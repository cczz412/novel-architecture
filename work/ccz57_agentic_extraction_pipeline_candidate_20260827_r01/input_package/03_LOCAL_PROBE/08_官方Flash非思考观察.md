## 和 Doubao 对照时能说什么

同一 Prompt、同一四题、都是非思考、温度都是 0。不是同一家通道：Doubao 走火山 Agent Plan，Flash 走官方 API。

- Doubao：Q1、Q2 Schema FAIL（空 `speaker`）；Q3、Q4 Schema PASS；Q4 没有把因果写成一条事实。
- 官方 Flash：Q1、Q3、Q4 Schema PASS；**只有 Q2 Schema FAIL**（9 个空 `speaker`）；Q4 同样没有把因果写成一条事实。
- 两边都没有明显乱编人物和事件。
- 空 `speaker` 不是 Doubao 独有。官方 Flash 在 Q2 上会犯同一类合同错；Q1 上它选择了省略字段，反而合法。

更准确的产品结论是：

> 在冻结四题、统一非思考的条件下，官方 `deepseek-v4-flash` 能拆出动作、状态和关系，但 Q2 仍会交出空 `speaker`，Q4 仍可能把因果链拆成互不关联的事件。小说辅助产品不能只看返回了 JSON，还必须在接收后执行正式 Schema 校验和因果缺失检查。

这不能证明 Flash 整体可用，也不能替代 CCZ-84。
