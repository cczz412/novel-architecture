# ChatGPT Pro 综合审查计划（材料已齐，准备独立咨询包）

## 目的

把外部研究证据和本地真实 API 行为放在一起，请 ChatGPT Pro 提出一套“可实现、可停止、可验证”的迭代抽取模块候选。Pro 的任务不是替模型打分，也不是直接宣布产品应该采用哪套模块。

## 进入条件

- 五份 Deep Research 都已取得完整回件；
- 每份回件的问题、时间、范围、限制和反例已经检查；下载 Markdown 缺可点击来源，必须把来源链部分缺失写进 Prompt；
- 当前 L1 API 探针所有已授权模型都完成收口，失败、未调用和中途停止也保留；
- 冻结 Prompt、Schema、合成输入、每次请求、原始响应、模型身份、思考档位、重试、耗时、Token 和错误均能对应；
- 本地包通过成员清单、哈希和敏感信息检查。

## 候选包包含

- 五份 Deep Research 原始回件及其来源索引；
- 本批 `01_已有问答卡与报告索引.md`、`02_增量问题与路由.md` 和验收后的增量结论；
- L1 探针冻结 Prompt、Schema、人工合成输入；
- 所有已授权调用的脱敏原始请求、原始响应和元数据；
- 每批运行回执、观察说明、Manifest 和已发现的不一致／纠正记录；
- 一张待 Pro 回答的问题卡：模块分层、每层输入输出、错误路由、循环停损、成本预算、人工停点、最小本地消融。

## 明确不包含

- API Key、Authorization Header、Cookie、登录材料和账号信息；
- 未授权小说正文、Gold、答案锁箱或其他敏感样本；
- 本地 dirty clone、其他窗口工作材料和与本题无关的聊天历史；
- 把 Deep Research 报告或 Pro 建议冒充产品合同、Gold 或施工许可的文字。

## Pro 之后还要做什么

Pro 给出的只能是模块候选。后续仍要在本地用冻结样本做单变量消融：一次抽取、补漏、独立验真、候选修复分别增加了什么、破坏了什么、花了多少。只有本地结果支持，才交给 CZ 决定是否进入正式产品和工程票。

当前状态：`READY_FOR_INDEPENDENT_ADVISORY_PACKAGE_WITH_SOURCE_CAVEAT`。允许准备一个明确标名的独立咨询材料包；不把它冒充项目正式 review route，不上传、不发送。
