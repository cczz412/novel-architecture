# 本批增量结论

## 旧材料已经回答

- `clean-output-can-still-miss`：输出格式干净仍可能漏抽，必须反看源文覆盖。
- `evaluation-needs-layers`：运输、结构、值、证据、覆盖和语义关系不能混成一个 PASS。
- `verifier-diagnoses-not-writes`：验真负责指出错误，修复不能无痕覆盖原始回件。
- `change-one-variable`：本地 A/B 每次只能打开一个变量。
- SI-008：工具权限、工作流游标、生成前守卫和有限缺料回取已经调查过，本批没有重复研究。

## 本批新增

- 五路报告共同把“多轮”拆成了不同机制：纯自我反思、确定性反馈后的局部修复、任务分解、独立验证和 durable workflow 不能混称为同一种 Agent 能力。
- 公开负结果不支持把“同一模型再想一次”设成统一默认；新增证据来自程序、测试、检索、明确错误信息或独立 verifier 时，修复才更可能有稳定价值。
- 成熟 Agent 工具最可迁移的部分是外部可观察循环：保存每次输入／输出／检查结果，按失败层局部重做，保留原件，限制预算，检测无进展并允许人工接管。
- 当前公开实现没有普遍解决 exactly-once 副作用，也没有统一的语义无进展检测；能恢复执行不等于恢复后仍然理解正确。
- 对小说抽取最有价值的候选拆分是：机械格式修复、证据定位、显式事实补漏、说话人专项、关系／因果专项、解释层分离。每条路由都必须从同一冻结 baseline 做单变量消融。
- 修复评价不能只看最终分数，应同时记录错误变正确、正确变错误、重复、矛盾、证据支持率、人工升级率、Token、耗时和调用次数。

## 与旧主张的关系

- 加强：已有“检查要分层、修复不能覆盖真值”的产品边界得到多类外部材料支持。
- 收窄：Coding Agent 的测试循环只能提供结构参考，不能把代码测试的确定性直接套到小说因果、人物动机和伏笔判断。
- 冲突：反驳“只要增加思考或让同一模型反省，多轮就会稳定变好”的宽泛假设。
- 新增：提出按错误信号路由、不可变原件＋Patch、进展检测和状态转移式修复评分候选。

## 未知、反例和冲突

- 五份下载报告没有可点击原始来源，尚不能完成逐条来源回读。
- 论文和代码 Agent 的净收益不能直接外推中文长篇小说抽取。
- 当前 L1 探针只有四段人工合成短材料，不是正式 Gold，也没有严格准确率和召回率。
- 最低思考在当前探针中经常增加成本、截断或破坏 JSON，也没有补出 Q4 因果；这只能描述本轮精确模型与精确配置，不能证明所有思考模式无效。
- 8192 补跑缓解了部分输出预算问题，但并不自动证明语义改善；仍需把可解析、合同合法、内容正确和关系正确分开读。
- 还不知道哪条修复路由在中文小说上能产生正的端到端净收益，也不知道合理的轮数、预算和人工升级阈值。

## 对小说辅助产品意味着什么

- 当前模块读取：一段小说文字、冻结 Prompt 和事实抽取 Schema。
- 当前模块能够输出：动作、状态、关系等事实候选、证据片段和结构化 JSON；在部分模型和题目上也能保留一条显式因果。
- 小说辅助产品还缺少的能力：把运输、格式、证据、覆盖、说话人、关系和解释错误分开诊断；保存不可变原件与每轮 Patch；按错误类型只调用必要的修复器；比较修复前后并判断是否停止。
- 会卡住作者的操作：作者把章节交给产品后，当前还不能稳定知道哪些事实漏了、哪些关系没连上、修复有没有毁掉原本正确内容，也不能确认结果何时值得保存进长期人物／剧情账。

## 不能据此下的结论

外部证据不等于 Gold、产品合同、施工授权或完成证明。
