# 当前问题、证据和边界

## 我们真正要解决什么

当前抽取模块读取一段小说文字、冻结 Prompt 和事实抽取 Schema，能够一次输出事实候选、证据片段和结构化 JSON。

本地探针说明，多家精确 API 模型并非完全拆不动：人物动作、状态变化和关系变化经常能抽到。但不同模型会出现空 speaker、坏 JSON、代码围栏、截断、把否定或说话人处理错、只抽出因果两端却不保留关系等问题。打开最低思考也没有稳定改善，反而经常增加 Token、耗时和格式失败。

小说辅助产品还缺少一套可测量的迭代纠错能力：

- 能判断失败发生在运输、格式、证据、覆盖、说话人、关系还是解释层；
- 能把原始回件长期保存为不可变证据，再生成局部 Patch；
- 能只把精确错误交给合适的处理器，不整包无差别重跑；
- 能比较修复前后，发现正确项被破坏、重复、矛盾或无进展；
- 能按轮数、Token、费用、耗时、错误重复和风险停下来；
- 能把需要人判断的争议保留下来，不自动写成事实。

这个缺失会卡住作者：章节抽完以后，作者仍不知道漏了什么、关系有没有连对、自动修复是否毁掉正确内容，也无法放心把结果保存进长期人物／剧情账。

## 本地证据能承重到哪里

- 合成题共有 Q1 动作、Q2 状态变化、Q3 关系变化、Q4 因果链四类。
- 多家模型完成了非思考运行；部分模型完成最低思考 4096 和补到 8192 的运行。
- 原始请求、回包、模型名、运行档位、耗时、Token、错误和零重试记录都在包内。
- Q4 的严格观察是“事件节点经常存在，但因果关系边经常缺失”；不能据此写出正式准确率。
- 4096 思考轮里，Mini／Lite 非思考时出现的第一条显式因果在开思考后消失；多家模型又出现截断或非法 JSON。
- 8192 只改变输出预算，用来观察截断和最终 JSON，不自动证明语义变好。

## 外部研究能承重到哪里

五份报告共同支持的候选方向是：纯同模型无证据自修没有稳定净收益；外部可观察反馈、任务分解、局部 Patch、不可变原件、错误分层、状态保存和有界停损更可信。

但五份下载报告没有可点击来源。ChatGPT Pro 应把它们当研究综合意见，不能把内部 turn... 引用编号当成已核实的一手来源。

## 本轮要的是候选设计，不是终局拍板

Pro 可以推翻当前模块设想，也可以判定某些层不该自动化。它应给出一个最小可运行版本和一个后续演进版本，并清楚标出哪些判断由本地材料直接支持、哪些只是研究候选、哪些必须再做冻结实验。
