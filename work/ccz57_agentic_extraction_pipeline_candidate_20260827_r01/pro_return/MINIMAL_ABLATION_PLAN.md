# 中文长篇小说事实抽取：下一轮最小冻结消融计划

> 文档状态：实验候选，不代表已授权执行。  
> 本文不发起新的 API 调用、训练、扩样、Gold 生成或产品施工。  
> 当前四题是合成探针，不是 Gold，不能用于正式准确率、排名或产品验收。依据：`03_LOCAL_PROBE/00_任务与边界.md`、`03_LOCAL_PROBE/01_合成题面.json`。  
> 目标：每个实验只改一个变量，判断某个模块是否带来**净改善**，不是只看“修复后看起来更好”。

## 结论

✅ 建议按下面的优先级做 8 个冻结 A/B：

1. **纯格式派生的不变量测试**：0 次 API，先证明不会改叶子值。
2. **4096 vs 8192**：分开判“截断缓解”和“语义改善”。
3. **Patch-only vs 整包 regenerate**：验证整个架构最关键的局部修复假设。
4. **已有因果两端时，关系专项 vs 整包再想一次**。
5. **说话人专项只在明确触发子集上是否净改善**。
6. **源文反向覆盖是否提高显式事实召回且不增加假项／重复**。
7. **独立 verifier 是否比同模型自审更可靠**。
8. **思考关闭 vs 最低思考**：确认现有坏格式和截断现象是否可复现，而不是继续凭四题推断。

🔥 每个语义实验都必须同时报告：`W→C`、`C→W`、正确项保留、重复、矛盾、Token、耗时、费用和人工升级率。**只看最终正确数会掩盖回归。**

## 统一冻结协议

所有 A/B 共用下面的冻结项；某项正是实验变量时才允许改变。

| 类别 | 必须冻结 |
|---|---|
| 输入 | 正文版本、背景卡版本、输入哈希、切片 ID、题目顺序 |
| 合同 | Prompt 文本／版本／哈希、Schema 文本／版本／哈希 |
| 模型 | 供应商、精确请求模型 ID、预期返回模型 ID、调用通道 |
| 采样 | 温度、思考开关／档位、最大输出 Token、输出格式、重试策略 |
| 执行 | 每题调用数、并发、超时、运行时段分块、调用身份 |
| 检查 | parser、JSON Schema validator、证据定位器、去重器、verifier 版本 |
| 评分 | Gold 版本、标注指南、裁决流程、盲评顺序、指标定义 |
| 预算 | 单题调用上限、总 Token、耗时、费用、人工分钟 |

### 一个变量的含义

- A/B 不得同时改 Prompt、模型、Token 和 verifier。
- “关系专项 vs 整包 regenerate”可以改变**输出形态／任务范围**，但两边模型、输入、Prompt 信息量和调用预算要尽量等价。
- “独立 verifier”实验只改变 verifier 身份；Patch、基线、验证提示和证据必须相同。
- 任何模型 ID 或供应商漂移都会让该配对失效，不能拿备用模型补齐。

### 运行顺序

为了降低时段和供应商负载干扰：

- 使用配对设计；同一 item 的 A/B 在同一运行块完成；
- A/B 顺序交替或随机；
- 记录调用开始时间、耗时和供应商请求 ID；
- 温度 0 也不假定完全确定。正式解释前至少用一小组重复样本估计同配置波动。

# 实验 1｜纯格式修复是否保持所有叶子值不变

## 要回答的问题

安全格式派生能不能只解决外壳问题，不偷改任何事实内容？

## 优先级

**P0。** 不需要 API，也不需要 Gold。这个不通过，后续不能自动修格式。

## 冻结什么

- 原始响应字节；
- parser 版本；
- Schema；
- 白名单变换规则；
- 叶子值定义、数组顺序定义和哈希算法。

## 只改变什么

- A：直接解析原始正文；
- B：应用白名单派生：BOM／首尾空白／单层完整代码围栏，再解析。

不允许修逗号、括号、引号、枚举、空值或任何字符串内容。

## 数据

- 包内 GLM-5.2 Q1／Q2 围栏样本：`03_LOCAL_PROBE/responses/raw/glm_5_2_Q1.stdout.bin`、`glm_5_2_Q2.stdout.bin`；
- 所有直接 JSON 样本作为负对照；
- 未来可加入程序生成的纯外壳变体，但不能混入语义变化。

## 指标

- 原始解析率与派生后解析率；
- `leaf_multiset_before == leaf_multiset_after`；
- 数组顺序是否一致；
- 键集合是否一致；
- 派生是否只触发白名单样本；
- Schema 结果是否可重放；
- 误剥围栏率。

## 支持继续的结果

- 所有成功派生样本叶子值、数组顺序、键值完全不变；
- 围栏样本解析成功；
- 直接 JSON 负对照不被改写；
- 任何非白名单损坏都被拒绝。

## 应停止该路线的结果

- 任意一个叶子值变化；
- 多剥／少剥导致内容丢失；
- 格式派生开始猜结构；
- 同样输入得出不可重复结果。

## 资源

- 新增 API 调用：0；
- Token：0；
- 耗时：毫秒级；
- 人工：一次性核对测试夹具，约 30～60 分钟。

# 实验 2｜4096 到 8192：只是缓解截断，还是产生语义改善

## 要回答的问题

更大输出预算是否只让模型有空间写完，还是在**原本不截断的样本**上也提高字段、证据、覆盖或关系质量？

## 为什么要单独测

包内 40 组 `tl_*` 与 `t8k_*` 请求对比中，冻结请求只把最大输出从 4096 改到 8192；Prompt、输入、模型和思考档保持不变。路径：`03_LOCAL_PROBE/requests/tl_*`、`03_LOCAL_PROBE/requests/t8k_*`。

已有一次性结果显示：

- Turbo、Mini、Ling 的部分 4096 截断在 8192 下得到完整 JSON；
- MiniMax 在 8192 仍有多题到顶或无合法 JSON；
- SenseNova、Qwen 的引号型坏 JSON没有因预算增加而消失；
- DeepSeek 8192 的个别题出现空 `speaker` Schema 回归；
- 8192 低思考样本的 Q4 仍未观察到稳定的明确因果边。

这些只能说明“现象存在”，不能给语义因果结论。机器回执：`03_LOCAL_PROBE/13_thinking_low_*_partial.json`、`03_LOCAL_PROBE/15_*_partial.json`、`03_LOCAL_PROBE/17_t8k_*_partial.json`。

## 优先级

**P1。** 先把运行可靠性问题和语义问题拆开。

## 冻结什么

模型、供应商、输入、Prompt、Schema、温度、思考档、输出格式、超时、重试、运行块。

## 只改变什么

- A：`max_output_tokens=4096`；
- B：`max_output_tokens=8192`。

## 数据

两类必须分层：

1. **截断高风险切片**：已有 4096 达上限、思考正文过长、最终 JSON 为空或不完整；
2. **非截断控制切片**：4096 下正常 `finish_reason=stop` 且有完整 JSON。

正式语义结论要用未来获批 Gold；当前四题只做运行和格式观察。

## 指标

### 截断层

- `finish_reason=length`；
- completion 是否达到上限；
- 最终 JSON 是否存在；
- JSON／Schema；
- reasoning 与最终正文 Token 占比；
- 耗时与费用增量。

### 语义层

只在 A、B 都完整的配对上看：

- 字段值、证据承托、显式覆盖、关系切片；
- W→C、C→W、正确项保留；
- 新增重复与矛盾。

## 支持继续的结果

- 截断高风险切片的截断率明显下降；
- 在非截断控制切片，B 没有增加 C→W、重复或矛盾；
- 若声称语义改善，必须在 A、B 都完整的 Gold 配对上出现关系／覆盖净增益，而不是只因为 B 能写完；
- Token、耗时和费用在批准预算内。

## 应停止或只保留为“截断兜底”的结果

- B 只降低截断，但非截断样本语义不变；此时只作为截断路由，不是默认质量档；
- B 仍大量到顶；
- B 引入更多 Schema／语义回归；
- 成本增加但 accepted fixes 为 0；
- 模型把新增预算主要用在 reasoning，不交最终正文。

## 最小试运行资源

以 24 个配对 item 为例：

- 调用：48 次；若 A 已有冻结回包，只新增 24 次 B；
- Token：B 每题上限多 4096，实际依供应商；高档；
- 耗时：中到高；包内部分低思考样本已到几十至一百多秒；
- 人工：机械层约 1 小时；若做 Gold 语义盲评，约 3～6 分钟／配对。

# 实验 3｜Patch-only 是否比整包 regenerate 更少破坏正确项

## 要回答的问题

出现一个局部错误时，只改目标路径，是否比让模型重写整包更稳？

## 优先级

**P1。** 这是是否值得建设 Patch／版本模块的核心证据。

## 冻结什么

- 同一基线结果；
- 同一诊断；
- 同一模型／供应商；
- 同一局部证据和可见上下文；
- 相同调用次数；
- 尽量等价的最大输出预算；
- 同一 verifier 和评分。

## 只改变什么

- A：模型输出完整新 JSON（整包 regenerate）；
- B：模型只输出受限 Patch，`allowed_paths` 由程序给定。

## 数据

未来获批 Gold 的混合错误切片：status 错、speaker 错、evidence 错、关系边缺失。每个基线应同时含：

- 至少 1 个明确错误项；
- 多个已确认正确项，用来测回归。

## 指标

- 目标错误 W→C；
- 正确项 C→W；
- `C→C` 保留率；
- 未触碰字段变化数；
- diff 字节／路径数量；
- Schema、证据、重复、矛盾；
- Token、耗时、费用；
- verifier／人工拒绝率。

## 支持继续的结果

- B 的目标 W→C 不低于 A；
- B 的 C→W、未触碰字段变化和重复／矛盾明显低于 A；
- Patch 前置条件和作用域能被程序稳定执行；
- 成本不高于整包重写。

## 应停止该路线的结果

- B 经常无法表达必要修复；
- Patch 越界率高；
- B 的 W→C 明显低于 A，且无法通过更合理作用域修正；
- Patch 应用后仍需整包重写才能一致；
- verifier 无法判断 Patch 局部影响。

## 最小试运行资源

以 24 个基线为例：

- 生成调用：A 24 + B 24 = 48；
- 可选独立验证：再 24～48 次；
- Token：A 高、B 低到中；
- 人工：每个配对约 4～8 分钟，重点标 C→W 和未触碰变化。

# 实验 4｜已有因果两端时，关系专项是否比整包再想一次更有效

## 要回答的问题

当原因和结果事件都已抽出，只缺因果边时，edge-only 专项能否用更小改动补对关系？

## 优先级

**P1。** 这是本地最重复出现的语义候选问题。

## 包内起点

Q4 中多个模型能抽出“温控器跳闸”和“荔枝渗水”，但没有明确因果命题；Mini／Lite 非思考曾写出因果，最低思考又丢失。路径：

- `03_LOCAL_PROBE/04_逐题观察表.md`
- `03_LOCAL_PROBE/08_官方Flash非思考观察.md`
- `03_LOCAL_PROBE/10_AgentPlan第二批观察.md`
- `03_LOCAL_PROBE/14_thinking_low_observe.md`

这不是正式准确率，只说明适合构造一个窄实验。

## 冻结什么

同一基线 nodes、同一正文窗口、同一模型、同一关系标签集、同一调用次数、同一最大输出预算、同一 verifier。

## 只改变什么

- A：给模型完整结果，让它“重新检查并输出整包”；
- B：只给已验证的两个端点和局部正文，要求输出 `CAUSES/NO_EDGE/AMBIGUOUS` edge Patch。

## 数据

未来 Gold 的“端点正确、边错误／缺失”切片，包含：

- 明示因果；
- “便／于是／因此”等弱连接；
- 只有时序没有因果的负例；
- 多原因／多结果；
- 方向易反的句子。

端点错误的样本不能混入这个实验，应另开实验。

## 指标

- 因果边 precision／recall／方向正确；
- `NO_EDGE` 负例正确率；
- 端点是否被改坏；
- 其他事实 C→W；
- relation Patch 大小；
- Token、耗时、费用；
- verifier 冲突和人工率。

## 支持继续的结果

- B 补边 W→C 高于或不低于 A；
- B 的端点／其他事实 C→W 为 0 或显著更低；
- 负例不会被过度连边；
- B 的 Token 和 diff 更小。

## 应停止该路线的结果

- 专项把紧邻事件普遍误判为因果；
- 关系方向不稳定；
- 端点正确仍无法补边；
- 与整包重写相比没有净改善；
- 需要读取整个章节才能判断，窄窗口反而伤害准确性。

## 最小试运行资源

以 24 个配对为例：

- 生成调用：48；
- 独立 relation verifier：可再加 24；
- Token：A 中到高，B 低；
- 人工：每个配对约 4～6 分钟，需确认端点和方向。

# 实验 5｜说话人专项是否只在明确触发子集上净改善

## 要回答的问题

speaker 缺失、空串、过填或来源冲突时，专项模型能否只修 speaker，不伤其他字段？

## 优先级

**P2。** 本地已有可观察问题，但四题不能证明专项路线有效。

## 包内起点

- 空 `speaker` 导致 Schema FAIL：`03_LOCAL_PROBE/06_派生纠正回执.md`、`03_LOCAL_PROBE/08_官方Flash非思考观察.md`；
- Q3／Q4 有说话事件却漏 speaker，Schema 仍合法：`03_LOCAL_PROBE/08_官方Flash非思考观察.md`；
- Ling 给大量纯叙述填“旁白”，说明非空也可能不合任务意图：`03_LOCAL_PROBE/12_sensenova68_ling30_observe.md`。

## 冻结什么

基线结果、触发规则、局部上下文窗口、角色表、模型、Prompt、预算、verifier。

## 只改变什么

- A：不调用说话人专项，保留基线并升级人工；
- B：命中触发器后调用一次说话人专项，输出 speaker-only Patch。

也可增加一个单独对照实验：B1 同模型专项、B2 独立模型专项；但不能和本实验同时解释。

## 数据

只选明确触发子集：

- 直接引语 speaker 缺失／空串；
- 转述来源缺失；
- 内心判断来源缺失；
- speaker 与证据主体冲突；
- 纯叙述被批量填“旁白”。

未触发事实作为回归监控，但不送入专项。

## 指标

- speaker W→C、C→W；
- 缺失、空串、过填、泛化值分型；
- evidence 是否足够支持来源；
- `touched_paths` 之外变化数；
- 模糊样本是否正确输出 `AMBIGUOUS`，而不是强猜；
- 调用、Token、耗时、人工率。

## 支持继续的结果

- 触发子集 speaker 明显净改善；
- 非触发项零变化；
- 歧义样本能停住；
- 人工升级率下降，且没有把“来源不明”滥用成默认值。

## 应停止该路线的结果

- 专项只是把空串换成“旁白／来源不明”；
- 频繁猜错角色；
- 修改 fact/status/evidence 等越界字段；
- C→W 不低于 W→C；
- 跨句／跨章依赖使局部窗口不够。

## 最小试运行资源

以 24 个触发样本为例：

- 新增调用：B 24；若再做独立验证，加 24；
- Token：低到中；
- 人工：每项约 3～5 分钟；歧义样本更高。

# 实验 6｜源文反向覆盖是否提高显式事实召回且不过度增加假项／重复

## 要回答的问题

从正文反查未覆盖锚点，能否补到主抽漏掉的**明说事实**，而不是生成更多复述、解释和假项？

## 优先级

**P2。** 这是覆盖完整性的核心候选，但当前没有正式 Gold。

## 冻结什么

主抽结果、模型、Prompt、Schema、正文、覆盖候选生成规则、调用预算、去重器、verifier。

## 只改变什么

- A：一次主抽取；
- B：同一主抽取 + 一次反向覆盖扫描，扫描器只输出 add-only Patch。

不能在 B 里同时改变主 Prompt、模型或最大 Token。

## 数据

未来 Gold 的长文显式事实切片，重点放：

- 中段／章尾；
- 配角动作；
- 台词事件；
- 数字、规则、时间；
- 否定、条件、计划、承诺；
- 同一句多动作；
- 低频实体。

动机、伏笔、暗示不进入这次 Gold。

## 指标

- 显式事实 recall 变化；
- 新增项 precision；
- duplicate／near-duplicate；
- contradiction；
- 新增项证据定位与承托；
- 主体覆盖、章节位置覆盖；
- 额外调用、Token、耗时、人工审阅。

## 支持继续的结果

- B 补到可验证的漏项；
- 新增项 precision 保持预设门槛；
- 重复和矛盾不明显增加；
- 主要收益来自原先未覆盖位置／类型，而不是同义复述；
- 成本和人工在预算内。

## 应停止该路线的结果

- 召回增益主要来自重复拆分；
- 新增项大量是推断或气氛描写；
- precision 明显下降；
- 两轮扫描仍重复同一缺口；
- 与等 Token 独立采样相比没有优势。

## 最小试运行资源

以 24 个长文 item 为例：

- A 可复用已有基线；
- B 覆盖调用：24；
- 若每个新增 Patch再独立验证，调用可能增加 24～48；
- Token：中到高，取决于长文长度；
- 人工：每章约 8～20 分钟，主要判新增项与漏项。

⚠️ 没有正式 Gold 时只能看“新增候选数量”和人工印象，不能判召回提升。因此这条路线应等 Gold 切片批准后再做语义结论。

# 实验 7｜独立 verifier 是否比同模型自审更可靠

## 要回答的问题

同一模型审自己的 Patch，与独立模型／独立人工 verifier 相比，谁更能拒绝错误 Patch、放行正确 Patch？

## 优先级

**P3。** 先有稳定 Patch 数据再做，不要让 verifier 实验和修复器实验混在一起。

## 冻结什么

- 同一批基线、诊断和 Patch；
- 同一验证 Prompt；
- 同一可见证据；
- 同一输出 Schema；
- 同一 Token 上限；
- 同一 Gold／人工裁决。

## 只改变什么

- A：Patch 生产模型作为 verifier；
- B：独立模型或不同供应商 verifier。

另设程序机械验证，但它不是本实验变量。

## 数据

平衡的 Patch 集：

- 明确正确 Patch；
- 明确错误 Patch；
- 部分正确但越界；
- 证据不足；
- 关系方向反；
- 会引入 C→W；
- 无变化 Patch。

## 指标

- 正确 Patch 接受率；
- 错误 Patch 拒绝率；
- false accept／false reject；
- 对越界、回归、证据不足的分型表现；
- 与人工争议率；
- Token、耗时、费用。

## 支持继续的结果

- B 明显降低错误放行，且不会把正确 Patch 大量拒绝；
- B 的优势在多个错误类型上存在，不是只对某一模板；
- 成本增量可接受。

## 应停止或不强制独立模型的结果

- B 与 A 无差异；
- 独立模型只是更保守，false reject 大增；
- 两者都无法稳定判断；
- 人工争议率没有下降；
- 成本超过修复收益。

## 最小试运行资源

以 24 个 Patch 为例：

- verifier 调用：A 24 + B 24 = 48；
- 生成 Patch 调用不计入本实验，必须预先冻结；
- Token：低到中；
- 人工：每个 Patch 2～5 分钟，用于盲裁决。

# 实验 8｜关闭思考 vs 最低思考

## 要回答的问题

最低思考是否在特定关系切片上有净收益，还是主要增加截断、坏 JSON、Token 和耗时？

## 优先级

**P3。** 当前探针已经给出负面警报，继续投入前需要可复现结果。

## 包内起点

同一 Prompt、四题、温度 0、4096 上限下，最低思考出现：

- 多个模型 reasoning 吃满预算、最终 JSON 为空；
- Qwen／SenseNova 引号导致坏 JSON；
- Mini／Lite 非思考曾有的 Q4 因果在低思考中消失；
- 个别空 speaker 变好；
- Token 和耗时明显增加。

路径：`03_LOCAL_PROBE/14_thinking_low_observe.md`、`03_LOCAL_PROBE/13_thinking_low_*_partial.json`、`03_LOCAL_PROBE/15_*_partial.json`。

这仍是一次性四题观察，不足以宣布“思考无效”。

## 冻结什么

模型、供应商、输入、Prompt、Schema、温度、最大输出 Token、输出格式、重试、运行块。

## 只改变什么

- A：思考关闭／none；
- B：该供应商允许的最低真实思考档。

若某模型强制思考，不能纳入同模型 on/off A/B；包内 GLM 5.3 Flash 就是这种情况：`03_LOCAL_PROBE/15_glm53flash_nonthinking_partial.json`。

## 数据

- 显式事实控制切片；
- 因果／时间／指代等复杂关系切片；
- 长输出截断风险切片；
- 引号与复杂 JSON 格式切片。

## 指标

- 运输、截断、JSON、Schema；
- 字段值、证据承托、关系切片；
- W→C／C→W；
- reasoning 与最终正文 Token；
- elapsed／cost；
- 关系收益是否集中在某一切片。

## 支持继续的结果

- B 在预先声明的复杂关系切片上有稳定 W→C；
- C→W、格式失败和截断不增加；
- 关系收益足以覆盖 Token／耗时；
- 不需要把输出上限同时增加才能成立。

## 应停止默认开启的结果

- B 只变慢、变贵；
- 关系没有改善；
- 格式／截断恶化；
- 显式事实被改坏；
- 收益只出现在极少数样本且无法被触发器识别。

即使 B 在复杂关系切片有效，也只应按触发开启，不能成为所有抽取的默认档。

## 最小试运行资源

以 24 个配对 item 为例：

- 调用：48；
- Token：中到高，reasoning 消耗不确定；
- 耗时：中到高；
- 人工：每配对约 3～6 分钟。

## 优先级、依赖和停止门

| 顺序 | 实验 | 前置条件 | 通过后才允许做什么 | 未通过时 |
|---|---|---|---|---|
| 1 | 纯格式不变量 | 现有原始回包 | 自动启用围栏／BOM 派生 | 所有格式问题保留失败或人工处理 |
| 2 | 4096/8192 | 冻结配对与运行账 | 只把 8192 用于被证明的场景 | 不把 8192 当默认质量档 |
| 3 | Patch-only vs regenerate | Patch 数据结构、diff、Gold 基线 | 建立局部修复主路径 | 暂不做自动语义修复 |
| 4 | 因果关系专项 | 端点 Gold、edge Schema | 接入因果触发式 Patch | Q4 类问题继续人工告警 |
| 5 | 说话人专项 | speaker Gold、角色表 | 接入 speaker-only Patch | 继续人工／规则处理 |
| 6 | 反向覆盖 | 显式事实 Gold | 接入 add-only 补漏 | 不做自动 gleaning |
| 7 | verifier 独立性 | 冻结 Patch 集 | 决定是否用独立模型 | 规则 + 人工验证 |
| 8 | 思考 on/off | 同模型可真实开关 | 只在有收益切片触发思考 | 默认关闭 |

### 硬停止门

任一实验出现下面情况，不应因为“平均分看起来提高”继续：

- 身份漂移或请求配置不一致；
- Gold／标注指南中途变化；
- A/B 同时改了两个以上关键变量；
- 高严重度 C→W；
- 未触碰字段被修改；
- 新增矛盾明显增加；
- 结果依赖手工挑样本；
- 只报告最终分，不报告状态迁移对照表；
- 成本／人工超过预先批准预算；
- 当前样本量不足，却宣称正式产品结论。

## 当前材料已经给出的实验警报

这些只是直接观察，不是正式结论：
