## 一、真正要验证什么

这一轮不考模型会不会写小说，只考一个更底层的问题：

> 写第 N+1 章之前，程序能不能只拿到此时应该知道的资料，排除未来、过期和认错人的资料，并说明每条为什么被拿进来。

如果这层做不稳，后面模型写得再漂亮，也会提前泄底、让死人复活、让角色知道不该知道的事。

## 二、故事应该有小说感，但不需要正文

### 要有的东西

- 人物各自有目标、秘密、误会和关系变化；
- 事件之间有前因后果，不是随机事实堆；
- 伏笔有埋设、触发条件和合理回收窗口；
- 承诺、债务、规则代价会影响后续选择；
- 章节出口会改变下一章的可用状态；
- 至少有两条需要跨 3 章以上才能连起来的因果链。

### 不需要的东西

- 不写几万字小说正文；
- 不追求文风、对白和描写质量；
- 不让模型补故事；
- 不用真实作者作品改写；
- 不为了凑数量随机生成互不相关的记录。

### 一条记录大概是什么样

下面只是帮助理解，不是冻结字段：

```text
第 8 章后：林砚持有“残缺门卡”
有效期：第 8～12 章
来源章：第 8 章
所属故事线：失踪案
第 13 章起为何失效：门卡被顾遥取走
```

真正编第 10 章执行包时可以拿它；编第 15 章时不能再把“林砚持有门卡”当现状。

## 四、数据必须分成三层

🔥 最重要的纪律：错误不能直接写进唯一真值。

### 1. 干净故事真值

这里保存“故事实际上发生了什么”。至少覆盖：

- 章节；
- 人物和别名；
- 状态及有效期；
- 知情、未知和误信；
- 因果边；
- Hook 的埋设、触发和回收窗口；
- 义务、承诺和期限；
- 世界规则、代价和例外；
- 章节出口；
- 故事线归属。

### 2. 被污染的检索库

从干净真值复制后，再人工注入：

- 已经过期但没被标失效的旧状态；
- 第 N+1 章之后才出现的未来事实；
- 两个相似别名被错误合并；
- 多跳因果链缺一个中间节点；
- 已失效的章节或故事线摘要。

每个坑都要有单独编号和正确答案，不能靠审查者临场猜。

### 3. 查询题与期望执行包

每个测试点明确：

- 当前要编哪一章；
- 时间截止章；
- 本章大纲需要什么；
- 哪些记录必须进入；
- 哪些记录绝不能进入；
- 哪条多跳链必须完整；
- 每条入包记录的理由。

这样才能算召回、未来泄漏、过期命中和链条完整率。

## 六、主编包器的最小职责

给定第 N+1 章大纲后：

1. 锁住时间截止章，任何来源章大于 N 的记录不得被看见；
2. 按人物、故事线、状态槽、知情、义务、Hook 和规则做结构查询；
3. 排除已经失效或被新状态覆盖的记录；
4. 在预算内装配执行包；
5. 每条入包记录保留来源章、有效期和入选原因；
6. 输出可重复计算的排序结果和包大小。

阶段 0 不需要生成正文，也不需要模型判断软冲突。

- 全库直接塞入；
- 只取最近章节；
- 只做关键词匹配；
- 主臂：时间截止＋结构查询＋失效过滤＋有界装包。

## 八、指标和停止线

| 读数 | 大白话 |
|---|---|
| 必需记录召回率 | 应该拿的资料拿回了多少 |
| `future_leak_rate` | 有没有偷看到未来章节 |
| `stale_hit_rate` | 有没有把过期资料当成当前资料 |
| 别名错并数 | 有没有把两个人错误认成一个人 |
| 多跳链完整率 | 跨几步的前因后果有没有断 |
| 包 token 数 | 给下游的资料包有多大 |

token 数必须钉住同一个本地分词器、版本和配置；如果只数汉字或字节，就必须叫“字符数”或“字节数”，不能冒充 token。

### 需要在正式运行前说清的一处

“全库 dump”天生可能含未来和过期记录。如果把 `future_leak > 0` 的停止线套在所有对照组上，这条对照会让整轮必然失败。

推荐口径：

- 主编包器：`future_leak_rate = 0` 且 `stale_hit_rate = 0`，不满足就失败；
- 对照组：允许暴露错误，错误本身就是对照读数；
- 整轮有效性：标准答案不可复算、坑位编号丢失、评测程序漏报已知坑时，整轮作废。

这只是施工前消歧，不替 CZ 改原工单；正式运行前要保留一张拍板记录。
