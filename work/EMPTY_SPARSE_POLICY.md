## 1. 目的

为小说事实抽取训练集补「空样本／稀薄窗」候选，凑空样本配额。
**不是写 facts、不是训练、不是改 Notion／Git。**

## 2. 空／稀薄定义（可收两档）

### A. 真空窗
责任区里，几乎钉不出「后续章节必须记住」的新硬钉子：
新身份／新关系／新资源／新出口（签约、拜师、系统面板落地、关键人物登场定锚等）。

### B. 稀薄窗（已放开，可计入空样本配额）
整窗大约只能抽出 1～2 条硬事实。
对照：正常密窗常能抽 8～12 条。稀薄＝信息密度明显掉一截，不是「完全没字」。

## 3. 优先找

- 正常类型小说的「中段章」（大约第 4～几十章，甚至更后）
- 赶路、写景、闲聊、过渡、候场、日常缝隙——但必须嵌在「正常剧情书」里

## 4. 少吃／不主吃

- 纯生活流开篇买菜煮饭（可作类型点缀 1～2 条，不当主粮）
- 吐槽说「水／慢／水文」但窗里其实拜师、系统、认亲、签约密布 → **假空，驳回**
- 关键词机筛整批标空 → **禁止直接当金标**

## 5. 类型必须摊开（禁止再堆成全玄幻）

都市、女频（现言／古言）、历史、奇幻／西幻、科幻、悬疑、游戏／诸天、玄幻。
**玄幻单批占比建议 ≤25%。**

## 6. 切窗硬要求

1. 先整章落盘 `raw/`，再手读切 `segments/`。
2. 切窗约 850～1000 tokens。
   - 仓内无 token 估计器时，按中文约 700～900 字核（1 字 ≈ 1.1 token 粗估），别差太离谱。
3. 责任区要「干净」：硬情节钉子若在附近，宁可缩短窗口，也别把拜师／系统／认亲切进来。
4. 每条手读判断：`PASS_SPARSE` / `BORDER_SPARSE` / `REJECT`。
   - `PASS_SPARSE` 才算主交付
   - `BORDER` 可交但单独记账，别跟 PASS 混报「已满」
5. 禁止：只写书名章节、不存原文；或只存切窗不存整章。

## 7. 验收自检（交件前必跑）

对每条候选：
- [ ] raw 整章文件存在且非空
- [ ] segment 存在且 == raw[char_start:char_end]
- [ ] sha256 写对
- [ ] 手读确认窗内硬事实大约 ≤2（或真真空）
- [ ] 类型标签诚实
- [ ] 同书不要灌太多（建议单书本批 ≤2 条）
- [ ] BATCH_REPORT 写清：PASS x 条、BORDER y 条、驳回典型、类型分布、还差多少
