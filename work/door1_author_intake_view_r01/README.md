把 ZIP 中的 `work/door1_author_intake_view_r01/` 放到仓库同名位置。命令都从仓库根目录执行。运行代码只用 Python 标准库与现有兄弟包；不新增 pip 依赖。

## 标记怎么真正写到文件

纯 HTML 不能悄悄拿到同目录文件的写权限。因此有一处额外操作：**第一次点击补漏／重新抽，或点击顶部“连接页面目录，保存标记”，选择这张 HTML 所在的目录，并允许读写。** 这走浏览器的文件授权，不是新增网络接口。

浏览器要支持原生目录选择与文件写入能力，接口名是 `showDirectoryPicker`、`FileSystemFileHandle.createWritable`。运行时会检查；不支持就明说“这个浏览器不能写同目录边车”，不把下载文件、缓存或内存冒充落盘。接口权限依据见 `SOURCE_INDEX.md`。

选目录时，页面只核对同名 HTML 页头里的本次生成标识，再读取 `door1.marks.json`。不枚举目录，不读其他文件里的正文。请选专用输出目录，不要给整份工作区授权。

重开页面时：

- 浏览器记住目录句柄，且读权限仍在：自动核对页头并重新读边车。
- 权限失效、句柄无法保存、清过浏览器数据：点击顶部按钮重连。边车仍在磁盘上，不因此清空。
- 尚未获得目录权限：会显示构建时读到的标记快照，并明确写“尚未核对”，不称它是最新边车。

IndexedDB 只记目录句柄，不记标记内容。标记只有在写入、关闭文件并读回核对后才显示“已落盘”。取消授权、写失败或损坏时，新标记暂留当前页，标明“尚未落盘”；离开页面会提示。重新连接可重试，不重复写同一个标记。强制关闭未保存的页面仍会丢失未落盘标记，不能把提示当成后台保存。

**坏边车不重置、不盖成空文件。** 构建时读坏了仍会出页面，标记区写“标记没读到”；浏览器重读坏了也如此。把文件留给人核对，修好后再重读。一个输出目录只用于这一份页面；另一份候选快照使用别的输出目录，避免共用固定边车名。

本刀只承诺单人、单份页面的标记流程。同源浏览器支持时会用 Web Locks，写前再次核对文件；文件 API 支持时请求独占写。它们不构成跨浏览器、Python 工具与任意外部编辑器之间的统一锁。不要同时在多处改同一份边车。

## 画面怎样对应

四格固定从左往右：正文大卡 → 事实句子大卡 → 10 本账简装 → 分镜占位。每栏独立滚动；窄屏横向滚动，不把四格改成上下四页。悬停和键盘聚焦都能看到对应与小工具栏。

来源采用旧读路已经给出的 `source_location` 与 `evidence`。有 `match_locations` 时，位置必须与它完全一致。这里的坐标是 **UTF-8 字节、责任段内、左闭右开**，不是“第几个汉字”。先加上责任段在整章的起始字节，再核对证据的逐字节内容。

夹具里同一句“甲走进北塔。”出现两次。候选既然带了两处来源，就亮两处；不调用字符串搜索去挑第一处。缺 `source_location`、坐标断在汉字中间、位置越界、证据不一致、同一候选的任一位置对不上，都在该条写“来源没对上”，不建立原文高亮关系。来源未对上的候选仍可显示自己的分账，不借账本关系猜原文。

原文按句号、问号、感叹号和换行切，句尾引号跟前句走，原字与顺序保持不变。这不是通用中文分句器，不为别的小说提供导入入口。

悬停事实时，原文与对应账条高亮；悬停原文时，已匹配候选与账条高亮。如果对应条目在另一栏屏幕外，只即时挪那一栏的内部滚动位置，不做平滑动画，不移动作者正在悬停的那条。同一原文对应多条候选时全部高亮，滚到其中第一条，不保证多条同时塞进一屏。

没有对应候选的原文用淡灰色提示“可能漏抽”。这是“没和当前候选连上”，不是已经核对整章抽全。旧读路当前指针的责任段是 1；第 2 段没有返回条目，不自动等于抽取质量差。

## 小工具栏与标记对象

原文上只给“＋ 补一条”；事实候选上只给“重新抽”。没有删除、拒绝、叉或减号控制。

“＋”在事实栏末尾放一条**没有事实正文**的本页空候选，写“新生成，待抽”，虚线从原文连过去。虚线与普通来源高亮分开显示，不把用户补漏意向当成抽取证据。空候选尚无可分账内容，不凭空塞入账本。补漏以后原文的“可能漏抽”仍保留，直到未来真的有抽取结果。

“重新抽”只增加标记，保留原候选、来源与分账。空候选也可打重新抽标记。本刀不调用任何抽取器，不替换候选，不给作者的标记补写理由或认可结论。

边车存定位字段，不存整章正文：

| 字段 | 意思 |
|---|---|
| `schema_version` | 本刀格式版本，固定 `1` |
| `view_id` | 这份正文、范围、指针与候选投影的指纹，防止旧标记套到另一版页面 |
| `marks` | 按追加顺序保存标记 |
| `mark_id` | 一次点击的唯一编号，用来避免重试重复落盘 |
| `mark_type` | `漏抽` 或 `重新抽` |
| `target_type` | 原文是 `sentence`，候选是 `candidate` |
| `target_id` | 原文句 ID 或候选 ID |
| `created_at` | UTC 时间，例如 `2026-09-06T10:00:00.000Z`；这里只是格式例子 |

原文 ID 由正文与字节区间确定；候选优先沿用旧读路的 `stable_item_id`。缺稳定 ID 时才生成“仅本页定位”的编号，不把它装成库内永久主键。空候选 ID 是 `new_` 加补漏标记 ID，因此读回边车就能重建同一条空候选与虚线。边车限制为 1 MiB、4096 条；未知字段、错目标、错版本、错页面、重复标记编号与不合法时间均不静默跳过。

## 最朴素的分账规则

本页的“进账”只是候选展示归类，**没有写入 10 本正式账本**。旧目录对已确认事实的要求仍是正式账的边界；当前门 1 默认摆出候选、供人打标记，不能因此改成已确认事实。

| 条目已有字段 | 这一刀的展示去向 | 不做的推断 |
|---|---|---|
| `status` 是 `计划` 或 `承诺` | 长线账候选 | 不当成下一章已经选定的规划，不改成已发生 |
| 其他状态，包括已发生、推测、误信、条件、否定 | 事实账候选，原状态照放 | 不把误信、推测、条件变成客观事实 |
| 夹具章号与修订身份 | 章节账的一条身份行 | 不伪造章节历史 |
| 没有明确实体或规则字段 | 对应专门账留空 | 不靠句子里出现“北塔”“铜钥匙”猜地点、物品条目，不把“旁白”猜成人物 |

10 本账按目录原名与顺序全部保留：章节账、事实账、人物账、地点账、物品账、势力账、体系账、世界规则账、长线账、规划账。当前冻结五条候选预期是：事实账 4 条、长线账 1 条，章节账另有 1 条身份；其余 7 本为空。空账会写“暂时没有分到这里的条目”，不是漏画了。

每条候选只放一个展示组。主键这里按口述指“条目命名”，用现有事实句，不伪造实体名称；内部关联仍用唯一 ID，重名不会串高亮。标签保留 `状态`、`类型`，有现成 `speaker` 才显示 `说话人`。标签组统一显示“只读”，因为来源是只读夹具投影；不凭空宣称“不可更改”“不可回退”。这刀不执行标签组权限逻辑。

这套分法刻意保守，不能拿来宣称正式 10 本账路由已经做好。未来要按人物、物品等分账，应等上游提供明确身份字段，或另开授权设计，不在此页猜实体。

| 缺口码 | 意思与处理 |
|---|---|
| `GAP_NOT_RELEASED` | 书名或章号超出本刀，只接受北塔夹具第 1 章 |
| `GAP_FIXTURE_MISSING` | 放行表、固定夹具或所需字段读不到 |

| `GAP_DEPENDENCY_MISSING` | 切片没有原读路所需的兄弟包；回完整仓库验证 |
| `GAP_STORE_MISSING` | 现成库不存在或原读路判定未初始化；新页不建库 |
| `GAP_SCOPE_MISMATCH` | 不是同一项目、章节、修订、责任段或夹具只读身份 |
| `GAP_POINTER_MISSING` / `GAP_POINTER_AMBIGUOUS` | 当前指针缺失或不唯一；本刀不猜、不另选一条 |
| `GAP_CANDIDATE_MISSING` / `GAP_NO_HUMAN_ITEMS` | 候选引用对不上或没有旧读路可展示的条目 |
| `GAP_CANDIDATE_SHAPE` | 必要的事实／状态／证据字段坏了，或稳定编号重复 |
| `GAP_CURRENT_CHANGED` | 同一路连续两次读取的页面指纹不同，停下来重跑 |
| `GAP_STORE_READ` | 原读路异常；不退回硬编码五条来冒充活库 |
| `GAP_OUTPUT_PATH` / `GAP_OUTPUT_WRITE` | 输出路径不合要求或写失败；旧页面、旧标记不主动清空 |
| `GAP_MARKS_READ` / `GAP_MARKS_SHAPE` | 边车读坏或字段不符，页面仍开，显示“标记没读到” |
| `GAP_MARKS_SCOPE` / `GAP_MARKS_TARGET` | 边车属于别的页面，或目标不是本页句子／候选 |
| `GAP_MARKS_TOO_LARGE` / `GAP_MARKS_PATH` | 边车超限、不是普通文件、软链接或不合路径要求 |
| `GAP_MARKS_BUSY` / `GAP_MARKS_CONFLICT` | Python 追加锁占用，或同一个标记编号内容冲突 |
| `GAP_DIRECTORY_MISMATCH` / `GAP_BROWSER_UNSUPPORTED` | 目录不是这张 HTML 的位置，或浏览器没有文件授权能力 |
| `GAP_MARKS_PERMISSION` / `GAP_MARKS_CHANGED` | 权限没获准，或写前／读回发现边车变了；新标记保持未落盘 |
| `GAP_HANDLE_MEMORY_BUSY` | 浏览器保存目录句柄的内部存储占用；仍可手动重连，不在里面保存标记正文 |

“来源没对上”是单条候选的提示，不是整页退出码。坏边车也是局部失败：命令可以成功生成页面，同时回执的 `marks_status` 为 `ERROR`、`marks_gap` 带具体码。旧读路自身返回的稳定 `GAP_*` 原样带出，不重写成正常条目。

成功生成只是“生成时的快照”，不是跟着后台候选变化的实时页面。两次读取检查能发现这两次之间的可见变化，不声称提供数据库全程事务快照。

按 CZ 批准的 [CCZ-188 / #358](https://github.com/cczz412/novel-architecture/issues/358)，其中精确九项上游测试、清单和治理说明归为历史交付证据，分类理由及变化来源见 `historical_input_evidence`。分类只接受点名九项，不按目录通配，也不自动放行有变化的文件。九条原始哈希还与自检代码中保存的原基线值逐项核对；即使误改历史值后重算包清单，也会以 `DOOR1_HISTORICAL_EVIDENCE_DRIFT` 失败。其余62项仍须与原哈希相同；变化时失败并报告路径。

报告中的 `protected_input_verified_files` 只计当前严格校验通过的62项。`historical_input_evidence` 逐项列出路径、原哈希、当前哈希及 `same`／`changed`／`missing`／`unreadable`；`historical_input_compared_files` 只计成功读取并完成对照的历史文件。九项哈希不同不导致自检失败；缺失或不可读时保留全部历史对照行，结果为 `FAIL`，命令退出1，不能算作验证通过。其余保护失败仍抛出原有错误并非零退出。

历史对照只说明与旧交付的差异，不能证明当前功能兼容，也不能称“71项当前验证通过”。页面功能、夹具放行、来源对齐、坏边车与不写候选库仍由现有功能和集成测试验证。要扩九项分类、改其余62项保护或改变产品行为，须停止并报告，不为了绿灯刷新原始指纹。
