# 小说101注意力结构｜翻译清单

## 结论

小说101真正值得迁到 Z 批的，不是九块字段名，也不是整套仓库，而是“把输出、证据权限和变量边界说清”的设计思路。

下面这套曾作为候选顺序实测，**整包没有通过停点，不是当前默认**：

```text
任务与证据权限
→ A/B/C/D 准入规则
→ 2～3 个微型正反例
→ 短章节卡
→ 当前章全文
→ 同章冻结证据目录
→ JSON 输出契约
→ 临交稿提醒
```

## 可以直接学的

| 能力 | 在 Z 批里怎么翻译 |
|---|---|
| 固定 JSON 契约 | 键名、空值和证据 ID 形状交给契约，模型少花力气排版；程序继续负责回填原文锚和机械校验。 |
| 证据权限分层 | 当前章全文负责理解，冻结目录负责选锚；例子和提醒只能教规则，不能成为事实证据。 |
| 正反例放在规则后、正文前 | 只放 Z 批已经复发的 2～3 种边界，不搬整套错例病种表。 |
| 契约位置固定 | JSON 壳放哪一层必须固定；是否贴近输出更好，本轮没有证据，后续只能单变量测。 |
| 提醒只作临时补丁 | 只针对已经复发的一种错误做候选测试，不常驻，不和全文、例子一起打包。 |

## 要改造后再学的

- 小说101有作品卡和浅前情；Z 批第一阶段先只用短章节卡，不塞长前情。要不要加前情，单独做变量测试。
- 小说101的“新 1～9”是它自己的产品字段；Z 批仍用 A/B/C/D，只借层位职责。
- 全文＋冻结目录会增加 token；先用第 10 章看能否补回已知漏抽，再决定是否扩到 20 章。
- A→B→C→D 是适合 Z 批的工作顺序，不冒充已经验证的唯一最优顺序。

## 坚决不迁的

- 不迁 G 号体系、金标树、NVM 路由、旧 runner 和兼容旧目录。
- 不迁人工经验包、完整前情、六件履历和交接单；G091 只把它们当人工上限，且成本更高、没有稳定总胜。
- 不迁小说101的九块字段和专用病种表。
- 不把正反例、提醒或前情当当前章证据。
- 不把“JSON 能解析”写成“语义正确”。
- 不新增顶层目录；现有 `config / intake / runs / reports / outbox / tests` 足够承接对照。

## 2026-07-17 本地实测结论

- A 基线：24 条，60,292 token。
- B 整包：50 条；原文级真增益约 5 条，但重复、错分、错误 D 更重；成功输出 83,811 token，算失败调用 104,294。
- C 只加全文：仍是 24 条，原文级净收益主估值约 -1；73,660 token。
- B、C 都不升默认，不铺 20 章。当前暂留 `extract_v1.3.md`，但它也只是相对基线，不是“最优格式”。

## 证据边界

G091 只证明 JSON 形状较稳，也出现过局部克制信号；A 与人工上限 B′ 没有稳定总胜，B′ 两章 token 还多约 61.3%。本仓 Z00i 又证明：更多上下文会改变选条方式，但不等于净收益。

三臂都用了 `response_format=json_object`，没有非 JSON 对照，也没有注意力测量。因此只保留“JSON 方便解析和程序验收”这条；不声称它已经让模型把更多注意力放在分析内容上。
