## 1. 结论：把钱花在模型判断上，把机械环节并行验清

**推荐从真书主抽开始取得第一批模型证据，同时跑原章身份、原章锚定、六账投影和 C9 的 0-API 检查。** 开跑前只补会导致乱花钱、错归版本或错误外发的最小前置，不再要求先过一轮合成章节。

当前代码不是“所有模块都等着调用模型”。在本次完整建立索引的 105 份 `mvp/*.py` 中，实际可追到同一模型通道的业务用途有六类：**主抽、补漏、验真、去噪、一致性体检、续写规划**。C9 组装、关键词取件、投影、存储、意图路由和分镜数据导出都不能按名字算收费调用。另一方面，旧入口能发请求，不等于新版工作区已经接上真实模型；多个新版工具明确只接冻结响应。[S008]、[S010]、[S013]、[S019]、[S021]、[S046]、[S025]、[S028]、[S029]

本计划展开了 **109 个拟调用单元、56 个 0-API 单元**。除可选接口烟测外，代表样本均做同输入、同配置的 **4 次独立重复**。所有拟调用单元含重试的合计上限为 **1,713 次模型请求**；建议总费用硬上限 **人民币 1,000 元**，其中单元已分配 **993 元**，余下 **7 元不自动动用**。这些是停止上限，不是价格预测，更不是要求把额度花完。实际单价、套餐、余额和可用模型都待本机无密钥读回。

**计划交齐，不等于测试已做。** 本轮没有小说原章、没有 #324 返回的候选样本，也没有运行环境的套餐和账单。因此不会填写测试通过率、把任何模块判成产品可用，或把暂缺材料的数量写成零。

### 3.1 六类模型用途，实际是哪条线

**主抽线。** 旧 CLI 的 `prepare_m3_segments` 从准入门取得字符串正文，再切段。它调用 `extract_segment`，但 CLI 这条 string 路线不会因此自动获得新版完整 C2-v1 revision 身份。函数层本身支持 C2-v1；测试端应喂正式 current C2-v1，再让宿主保留来源引用。模型只返回事实文字和引文，不让模型生成可信的 revision 或账本主键。[S003]、[S010]、[S063]、[S064]

旧 CLI 的另一个风险是：某些段调用失败时，它仍可把其他段结果送给 `store.add_fact_candidates`，并打印完成统计。计划里的完成判定不读这行打印，而读**逐段终态、原章覆盖和结果版本**。部分成功可以保留作诊断，不计入整章 COMPLETE。新工作区有完整回执与冻结响应持久化路径，但不是已接好的 live runner。[S003]、[S025]、[S027]

**质检线。** `refine.run_pipeline` 中只有 supplement、verify、denoise 花模型请求；anchor、dedup 是机械动作。主抽候选由 checker 验，补漏候选反过来由 extractor 验。因此一段完整质检的基础请求上限是 **1 补漏＋2 组验真＋1 去噪＝4 次**；两次尝试时可到 8 次，再另加主抽。不能按“质检一个模块，一段一次”计费。[S013]、[S014]、[S015]、[S016]

当前质检的 `calls` 并不逐一保存所有失败尝试：失败后重试成功时主要记成功行，连续失败也不等于留下两条含完整用量的请求回执。它还会回退到 extractor 作为 checker；“不同家族”目前是配置说明，不是这里的强校验。S3/S3P 在宿主侧固定模型家族与逐次请求账，不允许缺 checker 时静默同家自审。[S013]、[S002]

**体检线。** `check.py` 按事实组调用；最多 14 个组并不等于最多 14 次网络请求，因为 `_scan_group` 可重试。输入事实还可能被分组/裁剪；没有出现在任何同组里的冲突不会自动被比较。S4C 先单组隔离测模型判型，组装器另做 0-API 覆盖检查；它不是“全书一致性已验收”。`check_tool` 的 C6-v1 路线明确要求 `model_calls=0`，不能塞入真实生产者却继续返回零。[S019]、[S020]、[S028]、[S066]

**规划线。** `plan.py` 的真实分支一次调用，`stub` 分支不调用。该入口仍产 C7-v0，只取有限的已确认事实上下文。`plan_tool` 的 C7-v1 输出、稳定卡片引用与当前事实过滤更严格，但 provider usage 目前必须为零。S4P 可验证旧规划内容是否有用，不能替代新的 C7-v1 真实接线。[S021]、[S022]、[S067]、[S029]、[S030]

### 4.2 选段办法：先看原章定号，再看模型结果

每本书前三章先做无模型接纳、哈希和切窗；选型与诊断阶段的模型输入只取前两章。固定 S1 的两个责任段：**一个能独立核对主体/动作的清楚段，一个带代称、否定、回忆、条件或说话者限制的边界段**。选择依据只看原章，由准备人员记录；不看 Pro 输出或模型得分后挑“容易过”的段。若前两章没有某类边界，就记录“未覆盖该类型”，不伪造书里有此情节。

六本书的第 3 章作为**本次选型链的留出章**：S1、S2、S3、S4 的模型输入、人工义务清单和调参诊断不使用第 3 章，也不查看该章 Pro 候选来改提示词。配置冻结后，S5 才首次在本试验链中送出第 3 章并盲审；前两章结果标“回归/负载”，第 3 章结果单独标“留出观察”，不混成全是新材料的总分。#324 可能已经把第 3 章交给 Pro 抽取，因此“留出”只约束本次选型人员和运行链，**不声称该章从未外发、所有模型都没见过，或它是完全独立新书样本**。选型人员接收 #324 时只取前两章诊断侧车，第三章结果隔离到配置冻结后再审。若已提前看过第三章输出，就登记泄漏，取消它的留出身份，不另编无污染成绩。原件哈希和无模型结构检查不属于调参使用。

切窗兼容基线先用现有 620–923 字及 H180 逻辑，保完整自然段；不把大段强裁到 923。CCZ-142 提出的语义责任段目标 600–800、450–900 兜底属于后续对照口径，**不是同一套现行代码已经做到**。S2H 只改背景，责任段逐字固定；语义切窗算法另开版本后，再用配对试验比较。[S002]、[S036]、[S063]

H0 是不带背景；H180 是现有每侧最多 180 字；HS360 是本轮提出的**人工预先划好完整句/段边界、每侧最多 360 字的只读背景**。HS360 不请另一个模型临场选段，不混入新的生成成本。若 360 字无法容纳必要语义单位，就记类型不足，不悄悄扩大到整章。HS360 只是 S02 语义背景问题的有界候选，不冒充已冻结方案。

### 4.4 哪些确实等 #324，哪些不等

每本样本按 `total = single_usable + cross_deferred + unsupported` 对账，不要求三种结果数量彼此相等。跨段是真的有证据但当前锚定尚不接纳，还是事实内容本身不被原文支持，必须分开。当前 C4 严格锚定会拒绝不能映回原章连续片段的引文；**不能把这种机械拒绝都记成模型语义错误，也不能把它都算语义正确**。[S038]

S4C/S4P 的大事实组把单次输入上限明确提到 16,384 tokens；其他参数不偷改。完整逐格上限已写入 CSV。P-C 与 P-T 均只在提示词中要求 JSON，不切换 `response_format=json_object`，避免把结构化输出模式和思考模式两个变化混在一起。P-T 的 32,768 思考预算是本轮拟议档位，**是否可用、是否与可见输出共用总上限必须先核**，不能只因配置文件出现 thinking 字样就说已支持。

P-B 的请求模型 `glm-5-2-260601` 与仓内登记的响应模型 `glm-5-2-260617` 不相同，这是一个明确映射，不能简单按字符串不等就判换模，也不能一概接受任意 GLM 返回。开工只允许无密钥目录回读确认后的**精确映射**；其他响应全部停。[S004]

P-C/P-T 目前的模型名不提供本文已验证的不可变权重快照。要保存目录版本、响应模型、服务端提供的版本标记、时间和配置哈希；若服务端仍只回同一别名，则明确记录“权重级可复现性有限”，不要伪造快照 ID。P-N 的原生工具能力也只是待核假设，**未接好之前不占用实际调用配额**。

这批不扩成十几家模型大海选。P-A 是当前仓内主抽模型候选，P-B 给异家族对照，P-C 给第二通道对照；P-T 专门回答思考是否值得多花钱。模型 unavailable 时保留该格 `BLOCKED_MODEL`，不替换成近似型号补满表。

### 5.1 当日无密钥回读要留下什么

执行者应在批次开始前 24 小时内核：精确模型目录和请求/响应映射、端点/profile 身份、支持的思考与 JSON/tool 参数、上下文和输出限制、超时/重试行为、当前套餐是否允许这种开发批测、计费方式和剩余额度。价格有分档/缓存/批量折扣时保存实际适用档位与证据时间。

公开价格和用户账户权益是两回事。没有证据时价格、套餐名和余额仍为 `null`，批次不可发出。若套餐免费额度存在，也不把已消耗额度记成“0 成本”；同时记配额消耗和影子成本。**不购买、不升级套餐、不把这份计划当支付授权。**

### 5.2 密钥边界

默认优先复用本机安全存储或托管 profile。Ark 登记要求使用受管 profile 并清掉可能覆盖它的环境变量；不要为追求“临时环境”反而读出受管密钥。只有已经批准的直接 SDK 适配器需要环境变量时，才由本机安全工具注入短生命周期进程，退出即清理。[S004]

计划、票、仓库、CSV、控制台、shell 历史和错误报告只存 credential source 的**类型或引用名**，不存值。不向用户索要粘贴密钥，不把密钥放命令行参数。模型输入不能拼进全量环境、主目录、其他项目或系统秘密；stdout/stderr 中的原文与候选只落本机受控日志，入仓仅脱敏摘要和哈希。

### 6.2 语义分母从原章来，不从 Pro 候选来

准备人员在不看本轮模型输出的条件下，把选中原章中的可核命题列成“核查义务”：主体、动作/关系、否定/条件、说话者、叙述时点、证据段。它是**本次实验的人工参照**，不是正式 Gold。边界争议项单列 `UNRESOLVED`，既不强行判正确，也不删掉后假装没有争议。

- **支持精度**＝输出中被原章充分支持、限定条件未丢的候选数 ÷ 实际已判定的输出候选数；另报未审/争议数。输出是否漂亮不参与这个分数。
- **义务覆盖**＝被输出正确表达的原章义务数 ÷ 已独立核定的应抽义务数；把一句拆成五句不让分母膨胀，重复同一事实也不加覆盖。
- **锚定通过率**＝满足现行 C4 原章连续片段要求的候选数 ÷ 提交锚定的候选数；单列跨段暂缓、空/歧义/非连续引文。这个比率不是语义正确率。
- **核心错误**单独计数，不允许用很多普通细节的正确率冲掉一个主体、否定、时序或规则适用范围错误。

同一张义务清单还要分开两种范围。`legacy_in_scope` 表示当前旧抽取指令明确要抽的、已经发生的客观事实；`v21_target_in_scope` 表示 CCZ-142 八种状态和隐含依据的目标范围。主抽现状的义务覆盖以冻结的 `legacy_in_scope=true` 项为分母，同时另报 v2.1 目标覆盖和未接线缺口，不能静默把较难的目标项删出报告。旧指令范围外的计划、承诺等命题未被输出，不直接算旧入口漏抽；但把计划、角色猜测、误信或否定说成客观已发生，在两种口径下都算错误。完成旧入口分母不代表 v2.1 目标完成。该范围差异来自现行 `extract.py` 的指令 [S012] 与 CCZ-142 目标（附件第 300、317 行附近），不能由裁判看完得分后更改。

每个小格若少于 20 条可判输出或 10 个独立原章义务，只报初步观察，不用百分比直接拍“模型已定型”。S5 要达到总计至少 200 个独立义务且每书至少 30 个，仍只够这批材料上的 L3 候选判断；达不到就报分母不足，不额外捏造事实或自动扩书。

独立内容核查采用双看：一人按原章建清单，另一人盲看输出和原章；模型名与运行编号先隐藏。两人争议保留，裁决后才入确定分母。若只剩单人条件，记 `SINGLE_REVIEWER`，不升 L3 定型候选。这里是试验准备/审阅工作，不要求产品作者逐条替系统做日常 QA。

自动第二模型可以给诊断意见，却不是独立人审，更不是 Gold。主抽模型与质检模型不同家族只能降低一种自审偏差，不能把“两模型都这么说”当原文证据。

### 6.3 四次重复怎样真的独立

同一格的 repeat-01…04 使用同一原章、责任段、背景、模型请求 ID 配置、提示词、输出约束和温度。运行编号只放宿主元数据，不混进 prompt。每次发新请求，不复用上次响应、不把上次错误和答案塞回去，也不在第二次起改提示词。

四次都保留，包括失败；重试记在该次下面，不补成“只挑四次成功”。调用顺序按预先冻结的交错顺序安排，避免某一家总落在不同的服务时段；服务缓存命中允许发生，但用量与延迟要分别记。每格报四次明细、最差值、中位数、范围和是否出现核心错误，不只挑最好一次。

模型随机性与材料多样性是两种分母：同一段跑四次不能当四段独立新材料；同一书三章也不是三本书。没有数据和预设统计模型，不声称“95% 可靠”“显著更优”。

### 6.4 错误注入要有名字，不污染真书

补漏测试先从人工核过的候选副本中移走已知有据条目；验真测试在副本中只改一个主体/否定/数值/来源字段；去噪测试追加明确的重复项或非事实噪声；M7 用干净组与单字段损坏组配对。所有改动都标 `DERIVED_TEST`、保存父件哈希与改动清单，**绝不声称原书原本有这些错误**。

对照项数量随原章实际内容冻结，不为了某格必须“至少找到一个冲突”而把悬疑、回忆、角色误信捏成矛盾。缺一种错误类型就记测试未覆盖。原文中的提示、广告、读者评论或抓取残留另列输入疑点，不作为对模型的指令。

一个重要版本差别：CCZ-142 的 `fact/status/evidence/speaker`、八种状态和隐含依据，是语义目标/研究候选。现行 C3-v1 仍是 text/quote/seg/revision 形状。本轮能在候选文字及审阅侧车中检查说话者与限定词，却不能把未接线的语义字段硬塞进 C3，随后宣布“v2.1 已投产”。

### 7.3 一格的落地例子，不捏造具体原句

以 `S1-04` 为例：书 B02，P-A，前两章选定的两个完整责任段，每段发四次相同输入。基础请求 8 次，至多再有 2 次有理由的重试，总上限 10 次，费用上限 5 元。每次输入至多 8,192 tokens、可见输出至多 4,096 tokens；原章 SHA、C11 revision 与实际 seg 必须由本机清单提供，本文没有填假值。

这格可以从现存原章直接准备，不等 #324。若出现一次主体/否定/规则来源升级错误，停止该配置扩量；若只是该段涉及当前不接纳的跨段连续锚定，单列机械暂缓，不一刀切判模型内容错。任何一次 timeout、截断或无效 JSON 都保留在这四次中的原位置。

`S3P` 不把旧 `calls[]` 长度拿来当实际请求数。若第一段的补漏重试一次、主抽候选验真一次、补漏候选验真一次、去噪一次，实际就是 5 个请求；它仍在本格预留预算内，但“4 次基础上限”不能改写成只付了 4 次。

S4C 的“一组一次”专指固定事实组送入 `_scan_group`，或由只处理这一组的受控测试入口调用它，再做 0-API 的结果判型。**不能直接把完整 `run_check` 当成这个单请求格执行**：完整入口会拆组并重试，网络请求数可能不同。要测完整 M7 入口，就另建冻结单元，把实际组数 × 4 次重复及重试计入新预算；本文 S4C 不把该整链成本藏在单组上限里。

这 1,000 元只约束模型/通道的本轮调用费用，不含人工审阅劳动、外部工具另行计费或任何订阅采购。没有额外工具采购授权；若拟用通道存在不能按本轮调用归属的固定开支，先另行核定，不把它悄悄塞进“免费”。人审条件不足不妨碍记录接口证据，但会挡住 L3 质量定型候选。

基础请求总上限 1,371 次，重试预留 342 次，合计 1,713 次。重试余量通常是基础请求的 25%，但**每个逻辑请求仍最多重试一次**；不是每个请求都保证有重试预算。某格预算先用完，后面的可重试请求也必须停止。

全计划 token 数是保守占位，不能拿它当预测账单。P-T 以可见输出 4,096＋思考 32,768 预留；它们是否在供应商 usage 中分开，执行前要核。跨回合输入重新携带上下文时，每回合都算输入，不能只数首次原章。

### 8.2 费用公式：价格未知也能判断何时必须停

把每次请求的输入拆成未命中缓存 `Iu`、命中缓存 `Ic`，计费输出拆成不重叠的可见/普通输出 `O` 与单独计费思考 `R`。若官方口径已经把思考计入 output，则 `R=0`，按原 output 一次计费，**不重复加 reasoning_tokens**。

```text
request_cost_billing_currency =
    (Iu * price_input_uncached_per_1m
   + Ic * price_input_cached_per_1m
   + O  * price_output_per_1m
   + R  * price_reasoning_per_1m) / 1_000_000
   + fixed_request_fee_if_any

cost_cny = request_cost_billing_currency * verified_fx_to_cny
```

分档价格、最低消费、批量优惠、缓存写入费或套餐按请求扣额度不能硬塞成错误的单 token 单价。执行者把实际计费函数版本、来源链接、核对时间与适用账户档位写进 rate card；免费额度另记消耗。本文不提供任何当前供应商单价，因为本轮没有核官方现价或用户权益。

**每发一次前先预留最坏费用。** 用该请求已核输入上界、最大可计费输出/思考和适用价格，算 `reserved_cost_cny`。检查：

```text
已清算费用 + 未清算请求的预留额 + 本次最坏预留额
    <= 单格上限、分组上限、全局上限（三者都要满足）
```

同样先预留一次请求数和 token 上限，才能开始网络调用。并发两个请求必须原子占用同一计数器，不能各自看到同一笔余额。若 token 估算器没有适配该模型，使用经过目录证明的更保守上下文上界预留；没有可信上界就不发，不用“汉字×某个常数”假装精确成本。

timeout 或连接断开可能已经在服务端消费。拿不到 usage 时，状态记 `USAGE_UNKNOWN_RESERVED`，保留整笔预留费用直到账单/供应商证据对清，不填 0。同一逻辑请求重试会再占一笔请求数和费用。不能因报错就认为免费。

### 8.3 批量到底多大

第一批同一 profile 并发上限 1；只有连续 20 个有完整账的请求没有身份/费用/合同事故，S5/S6 才允许最多并发 2。每次调度小包最多 8 个逻辑任务，出包后先检查停止条件，再派下一包。小包不是供应商 Batch API；本文没有核批处理接口、折扣或异步任务能力，不用它们估价。

S5 的每章 10 段是事先的预算占位。真实章若 6 段，就只发 6×4 次基础请求；少花的钱不自动换新章。若 11 段，发网前就阻塞该章并提交新的完整章预算，不先跑 10 段再把剩余一句话标“以后补”。其他完整章可继续；最终覆盖表如实列该章未跑。

### 8.4 重试和新实验的分界

可重试的是已经识别的临时传输失败、429/5xx 或明确可恢复超时，单逻辑请求最多一次；重试保留完全相同的模型、端点、输入和输出上限。坏 JSON、字段错、拒绝回答、截断、语义差、无依据内容，都不能用自动改 prompt/增输出/换端点“救成成功”。

现有 refine/check 自带重试，拟议出口必须把它们纳入同一计数/分类控制，不能再叠外层两次，变成四次请求。若 arkcli/SDK 内部还会不透明重试，先证明已禁用或已可观测；做不到就不能宣称满足本计划请求上限，应换成获准的可观测适配器后重开配置。这里要求的是收费可控，不是要求先跑合成小说。

## 9. 停止条件、失败归因与续接

### 9.1 硬停与局部停分开

| 触发 | 数字或明确条件 | 停在哪里 | 留下什么 |
|---|---|---|---|
| 未批准收费范围 | 没有覆盖该批的 ready 施工票/明确支付与批次许可 | 不发第一个请求 | `BLOCKED_AUTHORIZATION`；GH#325 的设计 ready 不顶替它 |
| 原件/配置漂移 | 任一源 SHA、revision、prompt、endpoint、模型映射与批准清单不一致 | 整个受影响批次 | 漂移前后摘要；不覆盖旧清单 |
| 凭证/原文越界、越权写入 | 1 次 | 全部相关出口立即停 | 脱敏事故摘要、已发范围、凭证处置由本机持有人处理 |
| 模型偷换 | 1 次响应不在本格精确允许映射内 | 该 profile 全停 | requested/resolved model、response_id、目录证据 |
| 预算/token/次数不足 | 下一请求的最坏预留会超过任一上限 | 发网前停止 | 已清算/待清算/预留、未执行单元列表 |
| 账户/权限错误 | 1 次 401/403 或 provider 明确配额耗尽 | 该 provider 暂停 | 错误类别和安全响应摘要；不轮换密钥绕过 |
| 服务不稳 | 连续 2 次 timeout，或最近 10 次有 3 次 429/5xx | 暂停该 profile 后续派发 | 10 次窗口明细；等待重新核可用性，不现场换端点 |
| 合同/截断 | 1 次非法对象、来源绑定错或 `finish_reason=length`；即使表面 JSON 完整也检查 | 当前逻辑任务失败；同型错误连续 2 次暂停 profile | 原响应哈希、解析错误、既有完整结果仍保留；不自动内容重试 |
| 核心语义错误 | 1 次主体、否定、说话者、规则条件或关键因果被错误改写/升级 | 停该模块/profile 的扩量 | 原章证据、错误种类与该次输出；其他已隔离配置可继续比较 |
| 语义一般不达标 | 任一次独立重复不满足相应 G2/G3/G4/G5 | 不升候选、不进入该配置 S5 | 四次明细；不删失败后只看均分 |
| 下游写入/读取事故 | 1 次错误 confirmed/签字、越界写、旧新混读、错误幂等 | 停该写入链；模型原始试验与它隔离 | 操作回执、文件摘要与恢复点；不让更多真书进入坏链 |
| 费用未知 | 一次返回无可对清 usage 时先保留全额；连续 2 次无法对清 | 暂停该 profile | `USAGE_UNKNOWN_RESERVED`，不是 0 元 |

模型内容不足或不支持该小说语言/题材，记录为可判业务结果，不伪装服务不可用。服务超时也不能直接进入“模型语义差”统计。每格同时有 transport、contract、semantic、author、product 五列状态。

### 9.2 失败归哪一层

| 问题 | 主归因层 | 不该怎么记 |
|---|---|---|
| 原章身份/章号映射错、读者评论当正文 | 输入准备/接纳 | 不让模型背所有锅 |
| HTTP、profile、usage、请求模型漂移 | 通道与计费 | 不写成“事实抽错” |
| 主体错、漏否定、人物推测变客观事实 | 抽取/诊断语义 | 不因 quote 可以 find 就算对 |
| C3 合法但跨段 quote 当前不能映原章连续片段 | 锚定/合同能力，兼记语义待审 | 不直接归成模型错误或确认正确 |
| source_ref 丢失、错误升 confirmed、发号/绑定串书 | 落账/宿主权限 | 不靠换模型解决 |
| 有卡但消费者没拿到属性、C9 丢源/旧新混读 | 取件/组装/消费者 | 不把更强模型当补丁 |
| 自动生成内容在 writer 前被正确拒绝 | 安全门正确拒绝 | 不是“API 没跑通” |

### 9.3 续跑规则

每个逻辑任务至少有 `batch_id/cell_id/material_unit_id/repeat_id/attempt_no`，每个实际请求有独立 `attempt_id`。停止时按这些键写未开始、已成功、失败、待清算、来源暂缓清单。重开只补该批准批次仍允许的未完成逻辑任务，不重复发送已完成请求。

同一模型响应只有唯一消费位置；去重只能阻止重复提交，不能拿它顶替另一次独立重复。任何修改模型、思考档、输出上限、prompt、halo、材料或计费函数，都产生新配置哈希和新实验批次；此前的失败与费用仍保留，不“边跑边改”后合成一个通过率。

恢复“暂时服务故障”与修代码后重跑不同。前者在原批准清单、剩余预算和请求限制内续接；后者要新 SHA、差异说明和批次批准。合同不匹配时不从 main 换到 #235 或 #314 分支偷跑。

## 10. 五级判据：到哪一级，才能说哪句话

五级不是把一个 `pass=true` 不断往上复制。零模型环节的 L1 记 `N/A_ZERO_API`，同时要求观察到零外发；作者认可也不能替产品可靠性测试背书。

| 级别 | 实证要求 | 能说什么 | 不能说什么 |
|---|---|---|---|
| L1 API 跑通 | 实际 provider 请求/响应、精确模型映射、可核 request/response ID 或等效服务端证据、完成/拒绝/失败状态、用量/费用或明确待清算；至少一次成功响应 | “这个固定通道和配置有真实响应证据” | 不能因 HTTP 200 就说抽得准、合同过或可上线；若连用量都无法核，仍不允许扩量 |
| L2 机械合同 | 输入/输出按声明版本验证；合法/坏 shape/空/越权/旧版本/并发/重开反例；不可伪造源/主键/状态；零模型模块观察到零调用 | “这段组件在已测范围内遵守合同” | 不能把旧 C6/C7-v0、冻结响应或 mock 测试升为新版 live 链 |
| L3 语义质量候选 | 真书独立原章清单、盲审、完整分母、四次重复、无核心错误、对应阈值过；新书和旧书分账；至少达到第6节的分母要求 | “这个模块+固定配置是本批材料上的候选方案” | 不叫金标、不自动改默认、不写正式账、不说所有题材都可靠 |
| L4 作者确认 | 真实使用本产品的作者对本次用途、候选/目标卡/账本操作作出明确采纳或标记；有版本、动作、权限与回执 | “作者接受了这个结果/交互，范围是……” | CZ 批准实验、人工 QA 判对、隔离测试 confirmed 均不等于原著作者签字 |
| L5 产品可用 | 获准产品入口从真实材料到实际消费者完整走通；成功、失败、取消、限额、重开、并发、旧版本、权限、成本全可见；无手写绕路补库；至少两次独立产品会话复验 | “这个明确用例可投入使用”，注明材料/模型/版本边界 | 不能从静态源码、一次实调、好看的卡片或带消费者名字的探针推导出来 |

**产品定型的最低级别是相应用例的 L5。** L3 可以定一个待采用的模型候选，L2 可以定一个隔离实验可依赖的机械组件；这两种“定”都要带限定词，不能冒充对作者公开可用。

本轮材料是别人的小说。即使 CZ 对开发结果满意，也不替原著作者签 `AUTHOR_ATTESTATION`。以后做真实作者流程时，使用当次授权的作者工作区和作品；作者可以按当前产品口径成批认可/标记，不必逐条替测试人员评卷。

### 10.2 进入 L5 的最小产品用例

M3 的代表用例是：作者从正常入口导入一章真书/自己作品 → source/current 准入 → 真实请求 → 完整或明确部分/失败结果 → 事实句及薄结算条可查看 → 按原章逐字回取 → 作者标记/接受 → 重开后状态与来源一致。失败途中不得盖住上一份完整结果。

六账/C9 的代表用例是：同一作者项目内，已获准候选/确认事实按明确 binding 投影 → 正常产品准备发号基础 → 当前点读 → C9 按需要组装 → **实际消费者**能看见需要的性质和来源；同时测空账、权限不足、旧版、预算不足和中断恢复。仅造一个叫 `plugin` 的 caller_id 不算插件验收。

M7/M8 的代表用例要由真实作者打开报告或目的卡，看到来源和限制，作出处理/选择，并在重开后查到其记录。模型生产与 writer 权限必须拆开；计划与告警不能悄悄变成“故事已经发生”。这些用例是后续施工/验收要求，不是本轮已完成结果。

对“先测 M3”的独立判断：**同意它是第一批收费调用的优先业务，但不同意它占据全部优先级。** 理由不是“样本最齐”——#324 还没回来——而是原章已经有授权、主抽通道在代码中可追、所有后续语义质量都受它影响。与此同时，六账投影/C9 是当前能做且共同影响多消费者的 0-API 节点，应并行取得真书证据。

P1 不用一次派出全部 S1：可以先发 B02、B05 对应的已就绪 profile 单元，每格仍保留四次重复，再看错误类型；这是同一份批准表内的调度顺序，不是遇到坏结果就换输入。若一个 profile 第一格就发生核心错误，停它的扩量，其余 profile 仍可用同冻结材料作独立对照。

模型候选排序采用分层规则：先剔除身份/合同/核心错误不过的配置，再比较原章义务覆盖与不确定项处理，之后比较四次最差表现、费用和延迟。精度/覆盖都接近时优先低成本、低波动配置。没有达到阈值的配置就报“本轮没有候选”，不为了尽快定型硬选最高分。

## 13. 回执与机器可读交接

### 13.1 三份记录各管一件事

**批次清单**记“获准测什么”，发网前冻结：代码 SHA、合同版本、材料/原章/责任段、prompt、profile、模型映射、输出/思考/token限制、次数与钱、停止阈值、批准出处。模板见 `BATCH_MANIFEST_TEMPLATE.json`。它还没有执行许可，空字段不允许默认为有效。

**逐次请求账**记“真正发出了什么、花了多少”，每个实际请求一条。字段形状见 `CALL_RECEIPT.schema.json`；这是本计划拟议的回执 schema，不是修改了仓内正式合同。

**单元结论**记“到哪一级”，把四次重复、失败、语义分子分母、跨段暂缓、作者动作和消费者实证合起来。L1…L5分别取 `NOT_RUN/BLOCKED/PASS/FAIL/INCONCLUSIVE/N/A`，不只留一个混合pass。

### 13.2 逐次请求账必填组

| 字段组 | 要记什么 |
|---|---|
| 对得上这一格 | batch_id、cell_id、material_unit_id、repeat_id、logical_request_id、attempt_id、attempt_no、parent_attempt_id |
| 对得上来源与代码 | source_sha、原件哈希、实际chapter revision、责任段/背景/输入prompt/config哈希、声明合同版本 |
| 对得上模型 | provider、profile、endpoint摘要、请求模型、响应模型、目录证据、思考档/预算/JSON或native模式 |
| 对得上请求 | 发出时间、结束时间、持续秒数、供应商request_id/response_id、HTTP/传输状态、finish_reason、原响应哈希、错误类；未暴露ID时明确null与证据缺口 |
| 对得上费用 | 原始usage、归一化input/cache/output/reasoning、计费口径版本、rate_card、币种/汇率证据、estimated/reserved/reconciled cost、quota消耗 |

保存模型公开用量中的 reasoning_tokens 即可；**不要求模型吐出或保存内部思考正文**。模型输出的事实候选、必要原文证据和完整原响应只在本机受控目录；GitHub/Notion只收脱敏汇总、ID和哈希，不能把本附件无正文当成未来日志也无正文。

### 13.3 完成后应交怎样的结果

每书至少一张覆盖表：原章范围、段总数、未开始/成功/失败/预算暂停/来源暂缓、候选数及内容审阅分母。每模块/profile给四次明细、最差/中位数/范围、核心错误数、净新增/误删、来源/身份问题、费用和延迟，不拿别家某次最好结果比本家四次平均。

恢复点写到具体 book/chapter/segment/repeat，而不是“还剩一点”。原始文件、输入清单和响应版本不覆盖；新跑实验新ID。真实输出回放到冻结工作区时新建 replay run，并用 parent_live_run_id指回生成run，回放自身0-API与生成时的费用并存，不互相抹掉。

### 批次批准摘要的规范算法

下列算法定义摘要输入，不执行API。审批证据单独保存，明确批准计算所得的batch_manifest_sha256；execution_authorization.approval_hash是该证据原始字节的SHA-256。不能仅凭模板自报authorizer或ready_to_dispatch放行。状态和其他全部字段在送审批前填定，审批后不再改变；只有下列三个排除槽可填摘要、证据哈希和派发就绪标记。

```python
import copy
import hashlib
import json


def canonical_sha256(value):
    raw = json.dumps(value, ensure_ascii=False, sort_keys=True,
                     separators=(",", ":"), allow_nan=False).encode("utf-8")
    return hashlib.sha256(raw).hexdigest()


def config_manifest_digest(config_manifest):
    frozen = copy.deepcopy(config_manifest)
    frozen.pop("manifest_sha256", None)
    return canonical_sha256(frozen)


def batch_manifest_digest(manifest):
    frozen = copy.deepcopy(manifest)
    frozen.pop("batch_manifest_sha256", None)
    frozen.pop("ready_to_dispatch", None)
    frozen["execution_authorization"].pop("approval_hash", None)
    return canonical_sha256(frozen)
```

先给config_manifest.manifest_sha256填入config_manifest_digest，再计算batch_manifest_sha256。批准对象包含配置摘要、选中格、prompt清单、预算、供应商绑定及其余未排除字段；任一变化都会改变批次摘要。每次派发前重算并与外部审批证据核对；同时将实际加载停止策略的原始字节SHA-256与failure_policy_sha256比较，不能只认同名文件。每条请求回执携带batch_manifest_sha256，清算时按此摘要取得不可变清单和批准证据，不能仅按batch_id找当前文件。原始审批证据不是这份JSON本身，证据及摘要均不得用事后生成的自报批准替代。

usage为KNOWN时，原始usage对象、归一化规则和四项计费计数（未缓存输入、缓存输入、独立计费输出、独立计费思考）必须存在且非空。经供应商计费口径确认不适用的计数才可填0，不能用0补未知数。reasoning_observed只是公开观测项，供应商不单列时可为null，不参与费用或token上限对账；缺计费所需计数就保留PARTIAL／UNKNOWN_RESERVED及原预留额。
