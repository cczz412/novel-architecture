# B-01 r03.5 设计边界、兼容处理与未覆盖能力

## 先分清两种“事实句子”

这条 B 线保存的是正文已经存在以后，由 CCZ-142 从语义责任段抽出的候选事实。它不是画布工作卡提前规划的剧情方案，也不是本章目标、承接区增量或章节内核。

两种内容以后可能都使用 `fact/status/evidence/speaker` 这类近似字段，所以不能只靠字段长相判断来源。本次把来源门放在公开 root baseline 写入之前：普通 B-01 调用方不能直接传 `raw_items`，也拿不到凭证签发方法，只能提交由组装层另一侧的固定 CCZ-142 交接适配能力封存的临时凭证。下面四类输入即使能拼出合法字段，也不能从普通 B-01 调用面自行签发后落库：

- 画布计划事实；
- 章节内核或承接区对象；
- 旧 C3 预览；
- 普通 JSON。

凭证和工作区、章节修订、来源代次、写作资料、责任段、尝试引用及候选条目一起封存。普通字典、同类型伪造对象、复制出来的对象和另一服务实例签发的对象都打不开；凭证签发后修改适配端原数据也不会改变封存内容。`B01Service` 的普通构造会失败，只有组装层能把互相绑定的“适配端签发能力”和“B-01 打开能力”分开交给两侧。

这仍是离线候选合同里的进程内角色分发，不是远端不可伪造签名。它防普通公开调用面误接，不防能够直接调用 Python 私有组装函数的同进程恶意代码，也不能替 CCZ-142 宣布生产接线已经完成。CCZ-142 的真实输出身份以后必须单独冻结；本票不创建那个上游 writer，也不调用抽取模型。

## 事实条目和原文依据不能混在一起

用户要找的是事实候选或账本条目。正文只是粘在条目上的逐字依据，需要复核时才沿着绑定关系取回。

因此新版条目明确分成：

- `fact`：候选事实；
- `status`：候选状态；
- `evidence`：1～2 句逐字依据；
- `speaker`：确实需要时才填写；
- `evidence_binding`：B-01 算出的章节版本、证据哈希和全部匹配位置。

调用方不能提交任意字符范围，也不能把人物状态摘要冒充原文依据。B-01 只接受候选内容，再从精确合成章节中机械定位 evidence。

## 段坐标为什么改成 UTF-8 bytes

中文字符在 UTF-8 中常占多个 bytes。旧字段如果只写 `start/end`，调用方很容易把“第几个字”和“第几个 byte”混用。

r03.5 明写 `start_byte/end_byte`，并要求各段从 0 连续覆盖到整章 byte 长度。证据位置也用相同坐标；落在半个中文字符中间、跨段或不在 exact 章节都会在写入前失败。

## 写作资料必须和章节来自同一代

当前 B-01 读取已接纳章节版本和同代写作资料，能够生成带输入绑定的 root CandidateVersion。

小说辅助产品还缺少把模块一的真实来源代次和写作资料安全传给 M3 的正式接口。这里使用两种只读候选记录做机械适配；如果以后上游正式接口不同，必须另开接线票，不能把合成适配器说成产品能力。这个缺失会卡住作者用真实题材、人物和章节材料启动抽取。

本次新增的 CCZ-142 临时准入没有改变这个结论。它关掉的是 B-01 公开入口直接吞任意候选列表的漏洞，不替上游发明正式 RecordRef，也不把来源标签冒充平台证明。

## 旧对象不能原地升级

旧 `r03.3-candidate` 条目只有 `text/quote`，没有新版的事实、状态和证据绑定。如果直接补字段并重算哈希，历史 RecordRef 会全部失效。

因此旧对象保持原 bytes、原 hash 和原 ref，只允许兼容读取器返回标记清楚的历史摘要。新 writer 拒绝旧合同对象，也不会把旧 quote 自动升级成 evidence。

## A 的记录不能冒充新版对象

A 阶段记录继续保留自己的旧合同版本。B-01 只解析完整原件并核对类型、版本、hash、权限和来源模块，不改 A 文件，也不把 A 的 Python dataclass 当成新版 M3 RecordRef。

## root baseline 和后续版本仍然分开

B-01 只能发布某段的第一版候选。current pointer 只允许 `FIXTURE_ONLY`，只从不存在推进到 generation 1，并把 schema 和输入绑定纳入逻辑身份。

当前 B-01 读取合成章节、来源代次、写作资料和 A 尝试引用，能够输出段索引、root 候选版本、夹具 pointer 快照，以及临时的条目／证据定位和版本差异。

小说辅助产品还缺少创建真实 child 候选、判断应保留哪一版并安全推进或回退 current pointer 的能力。这部分归 B-06；没有它，作者修改候选后还不能把新版本正式设为当前版本。

## 后续票不能被这次修复顺手替代

- 当前模块能够保存候选条目和证据绑定，但小说辅助产品还缺少生成并长期保存诊断、覆盖度和当前版本判断的能力。这部分归 B-02；没有它，作者看不清哪些候选已经覆盖、哪些问题仍待处理。
- 当前模块能够让后续代码沿候选找到已绑定 evidence，但小说辅助产品还缺少按事实候选／账本条目读取相邻证据并执行授权与保留期限的能力。这部分归 B-03；没有它，作者复核一条候选时还不能安全取回所需上下文。
- 当前模块能够提供候选版本和 Coverage 的引用基础，但小说辅助产品还缺少生成完整 `fact/status/evidence/speaker` 修补候选并保存其版本的能力。这部分归 B-04；没有它，作者还不能看到一组可审阅的修补方案。
- 正式事实确认、真实模型调用、Gold、抽取评分、作者验收和支持包都不属于本票。

## 这份证据不能证明什么

- 不能证明真实模型 API 可用；真实调用次数是 0。
- 不能证明候选事实准确；没有 Gold，也没有语义评分。
- 不能证明真实正文读取接口已经存在；施工只用了合成章节。
- 不能证明调用者在进程外的真实身份；当前只验证服务实例内的交接凭证和完整请求绑定。
- 不能证明 B-02～B-12 的 r03.5 修复已经完成。
- 本地施工完成不等于允许提交、推送、建 PR、转 Ready 或合并。
