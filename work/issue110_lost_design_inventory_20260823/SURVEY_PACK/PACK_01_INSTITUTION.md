### 真值按问题分工

| 问什么 | 应看哪里 | 不能拿什么冒充 |
|---|---|---|
| 故事里已经发生了什么 | 已通过正式确认规则进入事实账的事实句；外来道还要能回到书稿证据 | 仅有交棒整包身份的章事实稿、未确认候选、计划、渲染书稿 |
| 以后准备怎样写 | 规划账与长线账 | 选择卡、规划文本不能自动变成事实 |
| 外来已发表书稿写了什么 | 冻结外来书稿及其位置、版本、SHA | 抽取摘要、AI 推断 |
| 作者最终看到或导出什么 | 渲染书稿或其他投影 | 投影修改不能绕过确认改写真源 |

## 不能混的边界
### 已发生事实和未来计划
未来事件只能发计划编号。角色已经说过“我明天去码头”，可以登记“角色作出承诺”这件已发生事实；“明天真的去了码头”仍要通过正式确认规则。外来道可由书稿证据承托；自产章事实稿的交棒只绑定整包身份，逐条／整包怎样进入事实账仍待冻结。计划态不能因选择或渲染静默转正。

R10 对账注记（R10 正式吸收，ADD-030，2026-08-13）：**「消化」与「实际发生」是两层状态轴**——选项消化清单只管「安排进了章计划」（规划层销账），「实际发生」态只能由六态对账边或作者签字推进。设计稿把「作者选中计划」写成「已兑现」是走样，机制本身（选定即消化，ADD-004 Q3 亲拍）不动。详见下方 R10 架构增补「真值状态轴与对账边」。
### 事实和 AI 推断
AI 可以提出解释、叙事作用或关系猜测，但必须显式标为推断。作者声明和书稿确认的世界规则可以做硬约束，AI 推断不能直接亮红灯。
### 查询回答和永久事实
查询回答只服务当前问题。它只有在持续影响后文、证据承托通过、与现有底账不冲突、类型和作用范围明确时，才可提名为永久记录。
### 长期底账和压缩视图
剧情原子伸缩压缩是读取视图，也是多粒度派生摘要的载体，不是第二套事实库。胶囊和章节摘要只是这套视图的不同形态。压缩句必须带覆盖的原子编号和过期状态；底账变化后可以重建。它能帮程序准备上下文，不能替代底账、冻结书稿或原始证据；远期视图只负责导航，检索通道仍要能按需回捞冻结原文。
### 作者锁定真相和读者可见历史（R07 修订；N17）
作者已定、书稿未揭示的真相，用统一剧情原子身份证登记，不另建模块：状态＝已发生，来源＝作者签字 `AUTHOR_ATTESTATION`，可见范围＝AUTHOR，约束强度＝硬。签字至少能回到签字人、签字时间、版本、作用范围、故事内生效时间和可见范围。四条边线：
1. 尚无书稿证据→不进成文正史、不进训练／抽取实验；但它住进作者 Canon 账，是 QC 与规划的硬约束；
2. 产生须作者显式签字，与 Bible 升级同一把刀；
3. 改判走修改传播，留痕；
4. 书稿揭示后＝同一条原子挂上书稿证据、升“读者已释放”，不新建第二条。
旧“暗稿层”设计（NVM 历史需求层：16 记录项／类型学／锚点学／安全摘要）＝吸收替代，不是改判：读取边界→可见范围过滤，必揭露 hook→Hook 表，依赖自动强锁→T3 收编。
### 作者确认背景和书稿证据
背景卡能帮助识别主角、别名、类型和已确认设定，不能替书稿补证据。只读前态也不能被抄进本次新事实。
## 外来道书稿怎样形成可回验证据（R13 及更早口径；自产道不适用）
外来手写或已发表书稿尚未确认时，不能给新事实签证。回收核对通过后，小说辅助产品把对应文本写成不能静默覆盖的新版本，至少登记章节／场景身份、版本、来源编号、SHA 和可回取位置。后续修改另发版本，旧版保留。自产章走章事实稿明确交棒，不走本节的整章书稿回抽。
只有完成这一步，回收核对确认的内容才能引用该版本，进入剧情原子、状态和长线账。章版本是正式不可变的权威书稿版本；场景与段落只作章版本内的稳定锚点和局部确认范围。可逐场确认，关章生成整章版本回执；改动另发新章版本，并维护旧锚点到新锚点的映射。“先有可回验书稿版本，再写真值”不能倒置。
回收核对三态（硬事实对得上就行，不逐句对稿）：
- **写了**→对应剧情原子挂书稿出处，知情可见性升“读者已释放”；
- **没写且不冲突**→合法：原子保持已发生／无书稿证据／未释放（作者 Canon 态）；只有章纲标“必写”的漏了才提示；
- **写错（与硬事实／作者锁定真相冲突）**→红灯，出“书稿修改指导单”；作者坚持书稿版＝一次改账，走修改传播留痕。
## 三序：故事序、叙述序与创作痕迹（R06 扩充，账序 21:05 条判 8）
- **故事序**：故事世界里真正发生的顺序，用于因果和状态审计；
- **叙述序**：读者看到的顺序，用于倒叙、悬念、误导和信息释放；
- **创作痕迹**：作者改主意、推羻、沙箱试写等过程记录；**不入正史**，定稿只落故事序＋叙述序。
故事序与叙述序引用同一批剧情原子或计划编号，不能让一个数组位置同时承担两种意思。
## 章、场景和卡
- **章**：关闭章纲、完成总对账和长期入账的边界；关章＝清账不清零，未完事项显式转下章挂账才能关；关章有硬门槛（ADD-058：字数达标、本章任务完成可见、剧情有进展、质检过、不跟前文冲突、符合章节规划），过了系统才建议到此为止；可回验硬冲突红灯是「不冲突」这一条，不是唯一门槛；
- **盒子约束三级下达**（账序 21:35 条③）：全书宏观大纲→卷纲→章盒子，另加作者本章临时约束；编译时必须吃约束，冲突亮灯；先剧情后切章为主；
- **场景**：组织、交付和局部重做的工作单位，不是真值容器；
- **卡＝通用工作单位**（账序 21:05 条判 7）：分创作卡／修复卡；大卡承载本章主管线问题，小卡处理遗留逻辑；卡／困境跨章合法；
- **触发满足后**（账序 21:35 条④）：默认只亮灯＋进执行包＋提升检索优先级，不自动开卡；开卡由作者决定。
一场可以承载多张卡；场景变化时可以拆成前后两场。场内临时待办用完即弃，不固化为新的长期容器。
## 两工件与章纲的最小内容（账序 21:05 条判 6）
章层面只有两个工件：**章节工作台**（作者处理选线、卡、待决定的工作面）和**可重编译的章纲**（装配单本体）。
章纲当前稳定结构包括：章节身份、本章目标、入口状态、计划事件、故事序与叙述序、长线约束（含三级盒子约束）、场景安排、出口条件、风险和材料不足；另设**写法指导栏**（账序 21:05 条判 9）承接技巧／爽点／氛围类旁挂物，用开放词表，不固化标签树。
作者前台默认只展示目标、必须／不能、场景和待决定，其余内容渐进展开。后台可以保留更完整合同，但不能让字段数量反过来绑住作者。
## 状态、知情和长线
长期记忆至少要能表达：
- 人物、地点、资源、能力、身份的当前值与变化；
- 角色知道、怀疑、相信、误信或不知道什么；
- 关键状态变化的直接原因；
- 故事线、义务、规则和接近触发的事项；
- 别名、同名疑似、离屏但受影响的对象；
- 已发表、作者锁定、因果强锁和可回滚历史；
- 修改后直接受影响的对象及作者豁免。
**读者知情机器账（CZ 2026-08-13 17:18 亲拍 ADD-037／A1，关题 15）**：硬的「读者已知道／不知道／被误导」带原文锚进真账；被误导要能记下「误解成什么」。还可能再多几态——网文写法会针对「希望读者产生什么反应」，账本要接得住。「读者大概猜到多少」做带模型版本、可重算的旁账，**不进真值**。字段级枚举仍留 T3。角色知情边照 D21 分层不变。
**故事线三件套**（R07 按 N19-B 软化开章工序）：故事线是轻量一等公民对象：成员（人物／地点／义务多对多挂线）＋线状态（活跃／搁置／收束／并线）＋上次现场指针。主线支线＝同一对象＋优先级标记。开章选线工序保留，但已有宏观大纲／卷纲安排时由规划槽位映射默认作答，前台只显示可改的当前故事线；作者改线或拉伸、压缩、插入等偏差无法自动消解时才询问。切线仍是重动作并出切线包。
当前已拍补充：关系默认先用轻量关系状态和关系变化事件；重要、不对称、需要独立历史的关系才升成长期对象。Hook 和故事内义务分开看（消费口）；v1 不开真值表（ADD-042）。

## 总家规（R07 扩成七问；N23）
每个核心对象必须回答：谁产生、凭什么产生、谁有权确认、谁消费、何时生效或失效、怎样修订或删除、如何回到来源。七问没答全的对象只能留在实验层或投影层，不能进入核心档。状态账同管，防止无人消费、无法回源或没有退出方式的状态膨胀。

## R07 真值与资产语义增补

以下八段状态均为 `APPROVED_DIRECTION`（依据账序 2026-08-12 21:18 条）；字段、表结构和接口仍留 T3 与施工合同。每段保留独立原子 ID。

### N05-A｜外部工具的读写权限边界

外部工具既不能任意写，也不能默认全读。写侧只能提交修改提案，不能直接改写真源；批准后才落账。读侧对作者私有 Canon 默认拒绝，每次授权按主体、对象、字段、动作、用途、项目和有效期判断，只给当前任务所需字段与短期权限，并支持撤销、审计和导出授权记录。MCP、CLI 和人工成员服从同一边界。细则见[用户数据权利与安全政策](USER_DATA_RIGHTS_AND_SECURITY_POLICY.md)。

### N06｜输入材料五轴分诊与外来书稿身份（历史术语已收窄）

入口按五个轴共同判断：材料类型（书稿／章纲细纲／梗概粗纲一句话／外部参考）、生命周期（工作态／冻结态）、权力来源（书稿证据／作者签字／无）、允许用途、可见范围。外来工作态书稿是作者原始资产，尚未成为证据但不可当缓存丢弃；冻结后另生成不可静默覆盖的证据版本。自产章事实稿不叫工作书稿，走作者明确交棒。内容入账只有书稿证据承托或作者显式签字两条路，分类名称不自动授予权力。混合材料按最小语义单元分诊，标签与内容识别冲突时询问作者。

### N07-A｜视频产物四分法

视频侧分四类：从故事真源编译的生产规格是可重建投影；用户提供的参考图、LoRA 和素材是源资产；随机生成但未批准的镜头是候选产物；人工批准交付的镜头是冻结生产资产。四类都不能反写真源，但保存、删除、版本、权限和导出规则各不相同。

### N15｜真源按问题分权

系统不设笼统“总优先级”。问文字写了什么，看对应冻结书稿；问当前故事 Canon 是什么，看最新确认、带出处与改史记录的 Canon；问作者私下决定了什么，看作者签字记录。剧情图、摘要和查询结果永远没有独立裁决权。底账与旧书稿冲突时只能登记为改史或纠错，不能静默覆盖。

### N16｜表述事件与世界命题拆分

剧情原子判断前区分表述事件、命题内容、世界真实性和判断来源。例如“张三说城主已死”的逐字证据只证明张三说过，不能自动把城主死亡写成世界事实。对话、谎言、梦境、假设、传闻和反事实可以有原文证据，但不因此自动改变世界状态。这一语义合同必须在 T3 建表前定清。

### N17｜作者签字、三种时间和 unknown 六分

作者签字本身就是来源，记作 `AUTHOR_ATTESTATION`；未来准备这样写仍是计划态，只有世界中已成立但尚未写出的内容才进作者 Canon，揭示后在同一原子补书稿出处。原子生命周期叫“状态戳”，人物或世界当前值的集合叫“状态账”。时间至少拆故事内有效区间、叙述释放位置、系统登记／修订时间。`unknown` 至少拆成未检索、覆盖内未找到、证据冲突、作者未决定、对读者隐藏、尚未发生。

### N21｜章版本、实体生命周期与影响传播

章版本是正式不可变的权威书稿版本；场景与段落只作章内稳定锚点和局部确认范围，不另立第二套正史。关章生成整章版本回执，后续改动出新章版本并维护锚点映射。实体支持候选合并、确认合并、撤销合并和拆分；别名带有效区间与证据，操作可回滚。影响传播默认只列直接依赖并显示理由，深层传播由用户展开。

### N23｜扩展字段合同与提案路径

垂直扩展字段要说明命名空间、字段所有者、消费者、校验规则、版本、迁移、保存期限和导出方式。投影上**可以改**（多半是当面纠错）；进真值必须作者确认（ADD-061）。批准前不改写真源。记下「产品做错账」，后期收集找薄弱点——后期收集安排，不当本版已实现能力。修改提案仍是进真值的一条合法路，不是投影上禁止改。

## R08 架构增补（CZ 2026-08-13 拍板，挂账本 ADD 系列）

以下各段是语义方向；字段与接口仍留施工合同。工程细节见各段指到的 novel-mvp 设计稿。

### 真值方向性：书稿与规划账谁是老大（ADD-010，2026-08-13；R11 按 ADD-041／055 收窄第 3 点）

同一套规划结构里，节点的**真值方向**分两种，且会随创作进程**移交**（拍板原话用“正文／大纲”，产品层对应书稿／规划账）：

1. **已发表并导入的书稿**：**书稿为真，规划为影**。规划是从书稿抽出来的投影——抽错了是产品的问题。逻辑检查必须拿书稿字面再对一遍，不能只跟抽取结果对。已发表导入**必须附带原文**（ADD-055）。
2. **产品里开始创作之后**：**规划／账为真**。模块之间沟通走这一层。没导入过书稿也没关系。先有计划后有文。
3. **产品里写完才发表、或从未导入的书稿**：真值已经在大纲里。这些书稿默认可选对照，设置里可关，用来省额度（ADD-055）。
4. **外写新稿交棒（收窄原第 3 点，ADD-041）**：外面写进来的新稿默认只存放、只对照。交棒只发生在作者显式选择「以这篇为准」的时候，不是文件落地的副作用。原计划保留为“当初的打算”。

不要：永远不看书稿字面；草稿一入库就当正史；没导入就假装没有真值。

工程含义：来源身份标签之上再加**真值方向**维度；抽取质量指标只对“影”节点有意义；偏差报告在作者显式交棒时有意义。

### 户口总则：安排 vs 定义 vs 变化（ADD-038，CZ 2026-08-14）

故事材料分三家，一条只存一处，别处用稳定 ID 指。界面仍显示人话名字。

1. **安排**住规划账：这一章／这场要发生什么。
2. **定义**住实体／设定：这个人是谁、这地方叫什么。章纲只引用，不复制设定全文。
3. **变化**住事实账或计划事件：受伤、投靠、宝物易手。人物页上的「现在怎样」是影子＋锚。

地点／势力／物品：一种登记、带类型（ADD-039）。五层篮子不换树（ADD-040）。义务 v1 不开真值表；规则拆条仍开口（ADD-042／043）。检查器／时间线／执行包是投影，不另开「当前状态」真值表。

### 交互模型：画布真身＋点哪问哪＋聊天框万能入口（ADD-006，2026-08-13）

两代设计都没正面回答“人怎么跟产品交互”，此缺口由 CZ 亲自指出并补拍。**混合范式三原则**：

1. **画布是真身**：规划篮子、故事概览、事实账永远可见地摆在工作区，每步生成的剧情落在画布上、可回溯。画布是工作台本体，不是聊天附属品。
2. **点哪里，哪里就是入口**：点任何对象（卡／事实／篮子）出该对象的局部动作（就这段出题、查证据、只体检这章）。
3. **聊天框是万能入口，产出必须落画布**：跨范围或模糊意图在聊天框说；AI 回答不留在气泡里，变成画布对象（选项卡落在题目下、风险进收件箱、答案带原文锚）。聊天框是说话的地方，不是装结果的地方。

**聊天框怎么变聪明（CZ 2026-08-13 15:54 亲拍 ADD-036／A14）**：先暴露 MCP 已经能做的事（问事实、查证据），跟内部接口同步开发。AI 聪明不靠另训一套，靠接口清楚：每个插件能查／改／增／删什么、东西放哪、从哪拿，都告诉它。作者可预测的行为走 SOP／Skill（例如「怕跟前文冲突」直接走质检模块，不要自己傻扫全库），做完再反馈。🔥 **意图识别必须有**：探讨 vs 真改 vs 查询——作者只是想跟你聊聊剧情，不能噼里啪啦直接生产出来。

**防乱三机制**：①聊天框与卡片是同一对象模型的两种输入法——点卡片时聊天框跟随焦点，聊天默认作用于当前焦点；②AI 产出固定落位，绝不随机弹窗；③出题频率受停点设置控制（小白少题自动走、高级处处可出题）。

**AI 存在感分层＋建议署名（ADD-012 F4）**：画布局部处理是纯工具型；主窗口 AI（聊天框）是对话式“我提醒你、我建议你”，但不过度。关键规格：**AI 的建议要署名到出处**——“我调用了 XX 理论，它建议你……”“你安装过的 XX 网文技巧建议……”。AI 的权威来自引用的理论／技巧库，不是自己装专家。

**画布概念澄清（ADD-008）**：从来没有过“写书稿的沙箱画布”——旧设计的画布也是演化故事（列出发生了哪些事实），永远以规划／事实层为真值，不生成书稿成文。词典按单一连续概念收词：对象可见、步步可追溯的工作台。

**旧概念取舍纪律（ADD-006 附）**：考古捞货不照单全收，每条旧概念按“与新设计相符性 × 实现复杂度 × 成本 × 产生价值 × 用户需求”衡量取舍；画布工作方式明确保留。

### 上下文负担纪律：账本可以细，执行包必须瘦（ADD-007，2026-08-13）

过度设计在 AI 产品里有特殊代价：概念、字段、账本每多一个，生成时模型要加载的上下文就多一分，堆太多会稀释重点。**两道门原则**：①一个概念进不进产品，按取舍纪律衡量；②进了产品之后，它默认进不进生成时的执行包，按运行时注意力负担单独衡量——很多概念的正确姿态是**存而不喂**（账本里记着，生成时不装）。每次生成只编译本次所需最小上下文，每项可回答“为什么加载”。对考古概念回捡的直接影响：会常驻执行包的概念门槛显著提高，只进账本按需查询的门槛放宽。

**D11 伸缩压缩确认回捡，且是必须好好设计的大难题（ADD-008，2026-08-13）**：D11 是遗漏不是放弃。核心场景——续写下一章时必须加载“共同前提”（历史事实、规划限制、与前文不冲突的禁做清单、人物状态），脱离前提“剧情立马走飞”；但几十上百章不可能全加载。两难：缩太密仍然太多、压太简丢关键；“不可逆”怎么判定、会不会积一大堆永久保留句，都是待设计问题。D11 就是执行包的核心技术，已派专项设计单：[CONTEXT_PACKER_DESIGN_R01](../../../novel-mvp/design/CONTEXT_PACKER_DESIGN_R01.md)。打包器三题按推荐暂定（ADD-009 附批次）：前提包预算用固定档位（映射积分预估）；卷／线摘要关章时增量生成；缺料回取先做半自动（停点 P9）；关系质变默认“重大但可逆、作者可升级为不可逆”。

R10 口径补丁（R10 正式吸收，ADD-022，2026-08-13）：**「瘦」＝最小充分＋可扩张，不是越小越好**。在模型上下文、成本和权限允许时，整卷／整书宽窗口可作为大书导入重建、全书体检、低置信兜底三类场景的候选路由。部分外部基准只提供“宽窗口可能有益”的先验，不证明本产品当前已经具备整书宽读能力，也不证明当前产品效果。缺料回取通道和预算回执的“覆盖不足提示”都属于 CONTEXT_PACKER 的设计／验收候选。

### 插件（Skill）系统：卡牌制＋分层规格＋渐进式披露（ADD-014，2026-08-13）

写法挂件系统升级为插件系统。先纠正两个误读：①理论／技巧没有“暗中参与”——**一切都是卡牌制**：一道待解的题＋这张卡声明用哪些插件内容→生成方案→作者四选一，不存在自动往上冒的指导；②不存在“写书稿时的提示”——产品不代写，所有指导都围绕规划、事实句、分镜的生成。

**分层规格（核心新设计）**：同一个插件按消费场景分层取用。以“打脸爽点”组件为例——剧情生成层（出题时注入，约 50 字以内）、段落写法层（点开“这段怎么写”时取，100–300 字含正反例）、分镜画面层（做分镜时取），还可有卷纲层、章纲层等，按消费场景划分篮子；各层**同源**（同一组件的不同层）。V0 首发内置面仍是 1 套件、8 个组件、前三层；20～32 个只作后续内容生产候选，不是首发承诺或现有能力。分层标准公开给用户自制插件是设计要求。

**渐进式披露（CZ 2026-08-13 06:17 补拍）**：索引层常驻——主 AI 只看到套件内全部组件的“名字＋触发行”（15–25 字，30 字硬上限；二三十个组件全加载也就四五百字），只负责“拿哪个用”；内容层按需取——挑中组件后各消费场景只读自己那一层。主 AI 可从索引建议更合适组件（`suggest_from_index`），但只渲染成待作者点头的一行，复挑权不豁免卡牌制。

三道机械锁的设计要求是闸口唯一、运行来源回执受验、界面无推送。V0 官方内置 1 套件、8 个组件、前三层；后续候选内容独立排期。设计稿：[PLUGIN_SKILL_SYSTEM_DESIGN_R01](../../../novel-mvp/design/PLUGIN_SKILL_SYSTEM_DESIGN_R01.md)（R02 修订稿：[PLUGIN_SKILL_SYSTEM_DESIGN_R02](../../../novel-mvp/design/PLUGIN_SKILL_SYSTEM_DESIGN_R02.md)）。

R09 修订（ADD-019 M7，2026-08-13）：**随时自拆 Skill＋社群愿景**——不只完本书可拆，任何时候“今天写得特别顺”都可以把手感固化成 Skill 复用；自制入口不只是“作者指南文档”，是产品内“固化手感”的动作；可发到社群／论坛给别人用（自己也用别人的，但自己最了解自己）；**创建规范公开告诉 AI**，用户的 AI 帮他把手感做成合规 Skill。另有 R09 新增的“思路插件族”（帮作者想剧情的方法插件，ADD-018 K6）与选线插件（切线频率等，K2），见 03 页 R09 管线增补。

R10 硬化五件（R10 正式吸收，ADD-023，2026-08-13）：外审认为插件设计骨架可以继续验证，并建议补下面的护栏；这不是运行通过或已经实现的证据。`plugin.lock`、能力声明、注入防线、公开流程和评测集都按设计要求／公开前门理解。

1. **版本锁定**：项目级 `plugin.lock`（锁套件／组件版本）；生成回执记 `suite_id＋component_key＋version＋content_hash＋layer`——插件升级后历史生成仍可复现，旧项目不静默升级。
2. **插件运行来源四段回执**：用户声明、系统加载回执、模型自报、作者采纳。它只记录一次运行中谁参与了什么，不判断著作权，不判断作者身份，也不代替内容归属；模型自报不当内容生效证据。社群插件的作者署名另按 ADD-036 的“原作者＋历次微改者”署名链登记。

4. **能力声明与注入防线**：组件带 `affects_prompt / affects_defaults / writes_truth(恒 false) / network(恒 false)` 能力声明；纯声明式内容包、禁代码禁联网；用户上传内容按提示注入防线处理；自拆 Skill 默认私人、去标识。
5. **自拆 Skill 公开流程**：先私人候选配方→补正反条件→多次独立成功→权利确认→沙盒→公开——M7 社群规范的具体门，方向不变细则落地。
   路由评测集原则收编但降档：MVP 期只埋数据收集口径，公开市场前再建带零组件负例的评测集。

## R09 架构增补（CZ 2026-08-13 第五、六轮拍板，第二册挂账本 ADD-018～020）

以下各段是语义方向；字段与接口仍留施工合同。

### 角色 ID 永不硬编码（ADD-018 K7，2026-08-13；数据层修订点）

- “主角”是变量（＝角色名＝我＝你＝他）；**所有引用永远指向唯一角色 ID**（主角 A／B、男配一二三、反派一二……），不硬编码名字。改名一键全换（角色不变）；互动叙事带入任何角色都能轻松切第一／二／三人称——因为指的是 ID，不是名字。
- 第一人称书：账本统一用 ID（机器查账不乱），**人称是渲染层的事，不是数据层的事**。数据层设计稿的“事实句—实体引用关系”按此核对升级（也见 04 页数据口径注）；与人物账 CH- 编号（ADD-016 H4）同族衔接。

### 部署形态：标准云服务＋前端缓存策略（ADD-020 N1，2026-08-13）

- 部署走标准云服务：账本存服务器、随时可导出；“私人空间感”靠产品姿态传达（J3 口径），不靠本地部署实现。
- **工程要点：SVG 图走编号制＋浏览器本地缓存**——生成过的图按编号在本地直接拿（作者重生成不满意时的旧图、常用图都不再请求服务器）。**画布工作流不做本地缓存会非常卡**（画布性能关键），同时减服务器压力。这是 02 页“画布是真身”交互模型的性能地基，具体缓存策略留施工合同。

## R10 架构增补（2026-08-13；ADD-021～035 正式吸收，ADD-036／ADD-037 亲拍身份单列）

以下各段已按 CZ 批准口径吸收。它们先说明语义原则，再列设计／施工候选；除非另有当前结果票，不表示代码已经具备。字段与接口仍留施工合同。

### 真值状态轴与对账边升级（R10 正式吸收，ADD-030，2026-08-13；五份设计稿返工主轴）

两份架构回包独立打中同一根病，独立消化员同样命中：**设计稿把「作者选中计划」写成「已发生／已兑现」**，违反我们自己已拍的「未写成不发已发生态编号」＋六态对账。确认机制没被推翻——是设计稿没把拍板落进字段。修法五条：

1. **「消化」只在规划层销账**：选项消化清单照旧管「安排进了章计划」；人物页／伏笔／灵感的「实际发生」态只能由**六态对账边**或作者签字推进——两层状态轴分开，人物页吃 OPT 锚的条目必须显示为计划态、不得冒充 evidenced。
2. **对账边升一等公民**：PE↔F 对账结果（六态）落成实体边（`reconciliation_edge`），派生结论带支持集（`support_set`）——改一条 F 自动撤回下游，从口号变机制（接修改传播三层的机器层）。
3. **`truth_bearing` 只挂真正参与计划↔成文对账的对象**，不做万能枚举伪造统一状态机。
4. **槽位移交支持 partial**：一槽拆两章写（篇章组 M1 的账面形态）用 `handover_parts[]`／对账边表达，单值移交撑不住已拍机制。
5. **伏笔／灵感补「实际兑现」第二轴**：伏笔完成度由 `payoff_contributions` 推导（支持部分兑现）；灵感 `placements[]` 多实例（一个灵感安放三处）。
   落点：M8_PLANNING／CHARACTER_LEDGER／IDEA_LEDGER／PLAN_LEDGER_STORAGE 四稿 R02 修订。

### 存储与账本工程硬化（R10 正式吸收，ADD-032，2026-08-13）

JSON 的跨文件一致性风险高，需要护栏和实测。当前路线统一为：JSON＋护栏；产品化终点 PostgreSQL；迁移时点未拍；SQLite 是否作为中转未拍。**JSON＋护栏可以先跑、终点仍是 PostgreSQL，是 CZ 亲拍（ADD-036／A7＋A13）**。以下九项都是存储施工输入，不表示已经全部落地。

1. **跨文件原子性护栏先行**：复合动作一个 `operation_id`＋跨文件 commit manifest＋启动恢复扫描；撤销以 `operation_id` 为组出补偿操作。护栏实测仍出脏账即提前切向 **PostgreSQL**（SQLite 不是终点；中转未拍）。
2. **版本链存真内容**：每修订存不可变内容 blob（内容寻址）。活跃项目内、未收到适用删除请求时，历史修订不得被静默改写或选择性删除；项目／账户删除按政策页清理整条链。v0 存量基线冻结时要把 text 存快照，否则 rev 1 无法回放。
3. **读一致性**：`story_commit_seq`＋投影 checkpoint＋新鲜度标——「模型当时看到了什么」可复现（与 D11「每项可回答为什么加载」同向）。
4. **改史影响扫描**：依赖边（`dependency_edge`）反向索引，遍历限边类型＋限深＋visited set；不上图数据库。
5. **ID 纪律**：内部永久 ID 与人类显示编号分离；人物引用第一天就用 CH ID（执行 K7 亲拍，设计稿「暂不加外键」的口子收掉）。
6. **人物状态多值 key＋故事时间轴**：`injury:left_arm` 级状态键＋故事内有效区间——断左臂与中毒不互顶（N17 三种时间落地）；as-of 故事时间查询记 v2。
7. **锚迁移判据补强**：逐字 quote 之外加证据句邻域指纹＋否定／模态检查；邻域变了转 `needs_recheck` 或挂「邻域改动」弱标记供体检优先扫。
8. **故障半径**：核心真值破损只读降级、非核心隔离修复（quarantine），不「一错全拒」。
9. 留位不实作：`parent_revision_id`／`event_schema_version`。
   CONFIRM 加固：**不上全量 Event Sourcing**（关系型真源＋不可变修订＋outbox＋可重建投影够用）——写成存储稿纪律，防过度设计。落点：PLAN_LEDGER_STORAGE_DESIGN R02＋novel-mvp store 层排期。
   暗稿与收工侧的同族补齐（高影响事件强制单签、检测器 unknown 档、进度分轨、废纸篓安全垫）见 03 页「写作与检测」R10 注（ADD-031）。

### 画布与前端选型（R10 正式吸收，ADD-025，2026-08-13；T7 主件）

- **当前设计基线**：React Flow＋TanStack Query（服务端数据）＋Zustand（临时 UI 态）＋CodeMirror 6。当前阶段存储＝JSON＋护栏；产品化终点＝托管 PostgreSQL；迁移时点尚未冻结。这些是设计基线，不是已经实现的能力。MVP 暂不上 Service Worker／CRDT／图数据库；tldraw 只在自由白板成为核心卖点时另评估。
- **画布＝领域数据的可重建投影**：事实／人物／章节存数据层，画布只渲染视口＋LOD＋筛选（与「剧情图＝派生视图」同构；「画布真身」指交互中心不是存储中心）。
- **性能验收口径**：100～300 张完整卡同屏流畅是待测验收目标，不是实测结果；压测维度候选为 1k/3k/5k 总对象×100/300/800 同屏×真实中文卡片，施工时再按模块合同冻结。
- **SVG 缓存施工细则**（N1 落地）：URL＝稳定编号＋revision+hash（编号≠固定文件名，防 CDN／浏览器拿旧图）；Cache API 存文件＋IndexedDB 存索引；**本地缓存只是加速层、真源必须在服务端**；缓存按租户隔离、退出登录同步清（政策页删除承诺的前端半边）。
- **编辑器设计**：CodeMirror 6 是当前设计基线；K3 的行内标注和中文输入法 composition 期间暂停检测是施工要求，不表示已经实现。
  落点：[WEB_CANVAS_MVP_DESIGN_R01](../../../novel-mvp/design/WEB_CANVAS_MVP_DESIGN_R01.md)（并行产出，以文件现状为准）＋novel-mvp 施工合同。

许可不能由一个 `MIT` 标签包办：React Flow 核心库、React Flow Pro 示例／支持／角标政策、tldraw 生产 key／商业许可、CodeMirror 6 分别登记官方来源、访问日期和适用范围。

**画布默认长什么样（CZ 2026-08-13 15:54 亲拍 ADD-036／A15）**：

- **按章一张工作流**：这一张要处理的事全列好——像 AI 漫剧那种连线卡牌。每张卡怎么处理、哪出问题亮红灯／黄灯，作者一眼能看清；主 AI 查看时也能看清依赖关系。两章一起创建＝两张图，一前一后，前后依赖可以紧，但基本按章列，因为每张有自己的任务。
- **接收区**：卡片跟卡片传递的产物落到本章接收区，接收区一张一张设计。
- **时间轴是分离的预览**：画布做着做着想看效果，再打开时间轴——第一帧、第二帧、第三帧画面怎么变。画布工作流**不是**线性去产这些插图（可能先写出约 2/3 的剧情，再补开头）；时间轴只表示**故事内**分镜先后。可在锚点事件前／后插入（例如 3/5 与 4/5 中间插入，变成 7/10 的位置）。锚点＝故事内锁定的固定事情。
- **反向拆卡（CZ 2026-08-13 17:18 亲拍 ADD-037／A9）**：作者先有结局／画面、中间缺过程时，把意图交给画布工作流／Agent：「要达成这个，前面得先达成什么？」向前生成前置卡片，把中间细节夹出来。工作流可以正向铺，也可以倒着找。目的本身挂在卡上（见 03 页），不是绕过 Agent 去改底层文件。

### SVG 视觉系统三件（R10 正式吸收，ADD-026，2026-08-13）

确定性 SVG 是 V0 在当前成本、可复现和身份锚约束下的首选可控路径，不是唯一可能路径。生成模型的 seed 或参考图不能保证精确复现，只能说明目前不能承诺稳定一致，不能推出 SVG 是唯一技术方案。以下三项都是设计要求：

1. **`visual_version` 字段**：角色视觉资产挂在角色 ID 下带版本（换装／受伤／成长开新版）；身份锚点（体型／脸型／标志物）跨章锁定；表情动作与身份分离。
2. **素材台账 `asset_manifest`**：逐项登记素材编号、原始网址、许可证快照、校验值和是否允许导出。DiceBear 按具体 style 登记许可、署名和导出条件；unDraw、Storyset 等按实际用途核对使用、署名、再分发和生成器集成权。未经许可，不复制素材库、不向用户再分发原素材、不嵌入面向用户的生成器。
3. **降级规则**：无法表达的画面降级为剪影＋道具＋字幕，不让 AI 猜人物事实；一图一节拍；用户上传 SVG 白名单清洗（去脚本／事件属性／foreignObject／外部引用）。

**V0 素材方向保持 CZ 亲拍（ADD-036／A5）**：先用 CZ 本机已下载的 SVG 动画和 Icon，能表达剧情、喜怒哀乐、背景和物品即可，不另建中式古风部件库。**本机素材入口待登记。**

## 管线总原则
小说辅助产品不把入料、抽取、事实确认、规划、章事实稿、检查和交棒揉成一次模型调用。每一步都留下能检查的工件；不生成书稿成文，没有一键成文后门（ADD-049）。
总家规同样管管线：每个中间结构必须说清由产品哪一部分生成、存在哪里、怎样读回、哪一部分使用；没有这些答案的只留原型层。
本页统一分三种身份：**语义原则**只说明产品应该怎样理解；**设计／施工候选**可以交给设计或开发验证，但不表示已经实现；**已实现并有结果票**必须能回到当前代码、测试或正式结果票。除非另有当前结果票，本版新增的字段、界面、流程、性能数字和计费说法都按设计／施工候选理解。
## 外来道：已有作品和外部手写书稿怎样接入
```plain text
1. 冻结书稿，登记版本、来源坐标和 SHA
2. 建立可检索入口，但不要求首次穷尽全书
3. 作者提出当前真正要解决的问题
4. 系统按问题回冻结书稿取证
5. 程序回填逐字证据和位置
6. 独立评分或人工判断回答是否完整、限定是否正确
7. 持续影响后文的变化进入永久事实提名
8. 作者或正式闸确认
9. 更新状态、知情、因果、义务和规则
10. 投影出可编辑的反向剧情图
```
回答不了时要返回“材料不足”和回取轨迹，不能补故事。旧作品接入的目标是尽快让作者继续工作，不是先做一场全书考古工程。

入口分叉仍有效：外来道负责不认识的正文，必须切段、抽取和确认；自产道负责产品内部产生的章事实稿，不重复认识一次。

## 自产道：下一章怎样从规划走到章事实稿
```plain text
M8 读取规划账、长线账与已确认事实，只规划下一章
→ M11 按任务从十本账取料
→ 按交代顺序形成章事实稿：高密度事实句＋独立写法批注
→ 章事实稿检查只报哪里、为什么、怎样修，不自动改
→ 作者明确交棒
→ 作者确认的 INITIAL 章标题随交棒动作提交，由正式 C11 长期持有
→ 目标写入 C11／章节账当前版
→ 按确认规则进入事实账
→ 立即开始下一章规划；M2／M3 调用为 0
```
章事实稿不是书稿正文：事实句和写法批注在显示和身份上分开。渲染书稿是可选出口；作者手改后若新增信息，只把差异升级成候选并请作者确认，不把整章送回 M2／M3。旧章修订由 M7 提供“最小回改／后文圆回”两套方案，M7 不直接改书。

### 模块在两条车道上的位置

- **M1～M4 入料区**：只对外合并称呼，内部仍分别负责入料、切段、抽取、事实候选。
- **M5 确认开关**：只有明确确认的候选才进入事实账；沉默不确认，作者也不必把整批点完才继续别的工作。
- **M7 优化工作台**：接作者指出的“不好”，给位置、原因、最小回改和后文圆回；只报告，不改书。
- **M8 下一章规划**：只规划下一章并维护规划账与长线账；旧章问题交给 M7。
- **M9 驾驶舱**：只读已确认账算进度、人物、故事线、抉择、爽点、钩子等指标，不编数字、不产事实。
- **M11 供料**：从账本目录指向的材料为章事实稿和章事实稿检查准备上下文；取不到就明说缺料。
- **章事实稿检查**：这是产品用名；`T14` 只作历史任务票号。
- **入料水印**：M1 只标疑似水印，不剥离或改原文；作者明确同意后才能另生派生清洁版。
## 场景执行包装什么
每个场景执行包默认只带当前任务需要的内容：
- 全章章纲与本场目标；
- 上一场结尾原文和当前接线原因；
- 当前故事线及相关入口状态（含切线包，如果本章切线）；
- 本场涉及人物的状态与知情；
- 到期义务、生效规则、接近触发事项和已亮灯触发项；
- 必要的直接原因和未决事项；
- 从冻结书稿按需回取的少量证据；
- 用户确认片段形成的风格锚；
- 版本、来源和过期状态。
它不默认塞进上一章全部事实，更不默认塞入整本书全文。执行包供作者导写使用；没有第二种「生成成文」消费者（ADD-049）。
## 记忆怎样加载
当前已拍方向是“剧情原子伸缩压缩”：
- 当前完整；
- 近期展开；
- 远期压成带覆盖编号和过期状态的一句话；
- 关键因果保留头尾；
- 不可逆变化长期保留；
- 切换故事线时优先接回同一故事线上次出现的材料。
**双密度制与沉降**（R07 按 N12 收窄）：章节原料层登记本章全部剧情原子，长期底账只升关键变化；关章“沉降”只收缩常驻／展示层，活跃项目内历史原子、证据和版本不能被静默删改；回捞重建必须可验证。用户删除项目或账户时按用户数据政策清理，这条审计纪律不等于平台永久保存。
压缩视图本身承载多粒度派生摘要，胶囊或章节摘要只是呈现形态，不另起摘要真值。远期常驻视图只做导航，原文始终留在冻结书稿并可按需回捞；这条回捞通道是刚需，不是可选增强。压缩不能顶替证据。
当前不把“向量检索书稿分片”写成产品真值表示的核心路线，但检索通道可以用实体／时间／故事线硬召回、BM25 或向量扩召回来找候选原文，再回到冻结文本核证。

## 外来道的计划—书稿回收核对（R13 及更早口径；自产道不整章回抽）
回收后至少要分开六种结果：
- 按计划写成；
- 变体写成；
- 漏写；
- 与计划冲突；
- 新增未计划内容；
- 延后处理。
对已登记硬事实和作者锁定真相，另按三态处理（硬事实对得上就行，不逐句对稿）：
- **写了**→原子挂书稿出处，可见性升“读者已释放”；
- **没写且不冲突**→合法的作者 Canon 态；只有章纲标“必写”的漏了才提示；
- **写错**→红灯，出书稿修改指导单；作者坚持书稿版＝一次改账，走修改传播留痕。
**确认粒度**（账序 21:35 条⑥）：默认批量确认；以下四类进**重签清单**单独勾选，不随大流：Bible 新增／改动、人物永久不可逆变化、作者锁定真相新增／改判、跨线大因果；清单可扩展。
**沙箱选一转正**（账序 21:35 条⑦）：沙箱只存差异；分支内产物带沙箱标、对主线零效力；选一转正＝对账（普通改动批量确认，重签类单独签），不是多支并回；未选分支作废留痕；更细规则 MVP 后再定。
只有作者确认的结果才更新真值。改台词和文风不自动改事实；改未来计划不冒充已发生；改事件结果要提名受影响项；改证据要重判承托，不重做无关投影。修改传播按三层处理（机器自动重算／计划态亮灯可豁免／冻结书稿只出指导单，见 02 页）。

## QC 和风险怎样出现
- 硬事实冲突亮红灯；
- 节奏、手法、情绪和模板偏离亮黄灯；
- 隐含、多跳、动机类或两端证据尚未闭合的矛盾只记为“待复核线索”，进入裁决队列；
- 卡位点所见即所得地报警；触发满足默认只亮灯，不自动开卡；
- 作者可以喊停、降灯或豁免软问题；
- 硬来源不能批量豁免（重签清单单独勾选）；
- 风险和待确认项集中进裁决队列，不塞满每一段书稿。
红灯只给两端都能回验的已确认硬冲突（含与作者签字 Canon 的冲突）。红灯是关章硬门槛里「不跟前文冲突」这一条，不是唯一门槛（ADD-058）。“阻塞关章”只表示不能静默关章：作者仍可修书稿、正式改史、标记故意矛盾，或带负责人和期限挂账，处置必须留痕。系统没有检查到问题时，统一写“当前覆盖范围内未检出”，不能写“确定无冲突”。
**关章硬门槛（ADD-058）**：不是作者空手说「这章完了」。要过的是：字数估计达标；本章任务完成可见（例如三四个主要任务，产品跟着作者辅助处理）；剧情真有进展；质检过；不跟前文冲突；符合章节规划。过了之后系统在画布工作流建议「这一章到此为止」，作者观察确认。正文对账是可选一站；游戏存档、分镜导出是衍生，认同一份大纲。关完、下一章还没依赖前仍可改。无书稿收工仍可存在（只涨规划进度、不涨已写章数），但收工 ≠ 关章，空手宣布也不算关章。

## R07 管线增补

以下三段状态均为 `APPROVED_DIRECTION`（依据账序 2026-08-12 21:18 条）。每段保留独立原子 ID。

### N07-B｜视频投影接口占位

视频投影接口先只占两个输出族：场景连续性包，承接人物、地点、道具、伤势、昼夜、知情和相邻场景接线约束；镜头／资产绑定包，承接镜头与参考图、场景图、LoRA、种子和上一镜头等生产资产的绑定。系统对外只能承诺“提供约束和生成前冲突检查”，不能承诺随机生成模型一定服从。详细字段、平台方言和导出格式留后续投影合同。

### N19-B｜规划槽位映射与偏差驱动询问

当全书宏观大纲或卷纲已经安排“哪些章写哪条故事线”时，开章不要求作者重复选线。开章第一问这道工序保留，但由规划映射默认自动作答；前台只显示可修改的“当前故事线”标签。作者主动改标签，或系统检测到规划偏差时，才真正询问。切线仍是重动作，仍要生成切线包。

底层保留两条序列，并维护显式映射：

- **规划槽位序列**：表达上层规划的逻辑节奏和故事线顺序；原计划相对位置不因实际章数变化而重排或丢失。
- **实际章节序列**：表达作者真正写出的物理章节顺序，包括新增、拆分、合并、提前完成和非叙事章节。
- **槽位映射**：说明每个实际章节承接哪个规划槽位，以及后续槽位怎样落到新的物理章号；变化要留痕，不能反过来篡改原始规划序列。

| 偏差类型 | 例子 | 映射处理 | 什么时候问作者 |
|---|---|---|---|
| 拉伸 | 原计划 3 章写完一条线，实际写了 5 章 | 新增实际章节继续承接当前组槽位；后续槽位顺延到新的物理章号，逻辑顺序不变 | 无法判断新增章仍属当前线，或会挤压下一条线硬约束时 |
| 压缩／提前收线 | 原计划 10 章，实际 3～4 章已经收掉 | 这 3～4 个实际章共同承接原 10 章槽位；后续按原逻辑接上，不为凑章数制造空章 | 不能确认本线是否收束，或会跳过必须承接事项时 |
| 插入支线／子线 | 作者临时开支线或线内子故事线 | 推荐放在本线与下一线的转线处，或本线内合适位置；插入占物理章位，其余槽位顺延 | 作者决定插入点和线归属；系统只给推荐与影响预览 |
| 插入非叙事章 | 上架感言、请假说明等 | 保留实际章身份，不强行绑定叙事槽位；后续叙事槽位顺延 | 材料识别冲突，或作者要把它计入规划节奏时 |

映射更新后，作者必须能看见当前故事线、承接的规划槽位、后续章号怎样顺延，以及哪些三级盒子约束可能受影响。系统只建议映射，不能借自动作答静默切线、改规划或绕过作者批准。

R08 注（ADD-016 H1，2026-08-13；R11 按 ADD-050 收口）：选线屏不是每章必经。上层已定故事线则不问、默认带过；没定好才问。本节的槽位映射继续负责给出默认线；判线口径＝“关注的内容变了就是新线”（视角切换、感情线、复仇线都算），详见下方 R08 管线增补。

### N20｜告警三轴、红灯处置和覆盖回执

告警同时显示证据强度、影响大小、处置状态三个轴。作者可选择修书稿、正式改史、标记故意矛盾，或带负责人和期限挂账；还可记录忽略理由、稍后提醒、同类误报抑制和全局开关，但这些动作不能删除硬冲突证据与处置历史。

每次查询或检查附覆盖回执，至少说明书稿版本、扫描章节范围、检查类型、使用的状态版本、未读取材料及原因、未决线索数、结果是否过期。前台可折叠但必须能展开。告警有效率、误报抑制使用情况和覆盖回执完整性进入双计分卡。

## R08 管线增补（CZ 2026-08-13 拍板，挂账本 ADD 系列）

以下各段是产品共同理解与拍板结论；字段、界面与工程细节留在各段指到的 novel-mvp 设计稿，背景板只挂指针。

### 导入侧：材料架与分拣（ADD-003＋ADD-009 第 1 题＋ADD-002 Q3）

- **导入器必须接收多格式**：TXT、MD、DOCX、ZIP、纯粘贴；一份材料里可能混着多种身份的内容。
- **六个材料架**（自动分拣的目标槽位）：书名卡；简介卡（详情页文案，可能与剧情毫无关系，单独放不混进事实）；类型标签；章节架（每章标题＋书稿逐章区分，**唯一流向抽取正线的架子**）；大纲原稿（作者粘贴的整段旧大纲；界面命名按词典命名⑦暂定，避免与用户词“大纲”混淆）；设定集（世界观／等级体系／金手指／系统／朝代／世界机制）。
- **分拣三铁规**：分拣结果永远是候选；把书稿静默丢掉或错拆是最严重事故，宁可标不确定；大纲原稿／设定集是“作者声明的参考材料”不是事实账，进真值层走各自确认流程。架子身份不自动授予真值权力，与 N06 五轴分诊口径一致。
- **分拣停点调和（ADD-009 第 1 题，关闭原冲突）**：小白档把分拣确认“后置”而非取消——自动分拣直接入架，但仍是候选身份、留痕、可撤销、一屏结果醒目可改；**疑似书稿丢失无视档位强制必停**（缺章、覆盖缺口、章序矛盾、乱码四类机械触发，`--yes` 也绕不过）；高级档可设每次必停。
- **普通导入上限 10 章书稿**（可另附全局大纲等辅助材料）是现行**候选门槛，不拍死**（ADD-053）。超过可走**整本工程**（命名按词典命名⑥暂定，拍板原话“大工程”）：黑盒批处理，不是流式刷新——先识别规模→向用户报预估时长和预估积分→后台跑；也可 10 章 10 章分批拆。普通小导入照旧边拆边生成。不得把主体用户 3～20 章写成 11 章起必须走整本工程；轻入口怎么覆盖后半段待设计。
- **拆解是基础动作，体检是可选项**（勾选）；“批量动画”＝整本拆解＋直接出分镜脚本、跳过体检。
- 单章追加导入：缺章审计以项目为域，不以包为域（ADD-011 GAP-09）。
- 设计稿：[INTAKE_SHELVES_DESIGN_R01](../../../novel-mvp/design/INTAKE_SHELVES_DESIGN_R01.md)。

### 教程与首次体验（ADD-001＋ADD-017 J7＋教程脚本三题）

- **总原则：有声动态分镜是“附带产物”，从教程进，不是首屏主承诺**——创作中每段剧情边生成边附带 SVG 画面，最后拼接成有声分镜。
- **路 A（零材料用户）**＝固定的、不消耗额度的演示教程：约 3 分钟预制放映厅，零调用、零写账、无书稿成文，胶卷条攒帧收 45 秒有声分镜；作用＝效果承诺的展示。
- **路 B（有材料用户：前三章或一个绝妙点子）**＝真数据速通：生成到规划／剧情层＋写作指导（按 J1 口径，不代写成文）；约 20 次调用记为免费获客成本。**熟手路**：有前三章→迅速生成第四章续写规划。教程可做多条（不同起点各一条）。
- **激活事件定义（ADD-057）**：作者看见系统在干活。投影像财报／PPT：表、列表、人物、箭头、故事走向有形状，看起来专业可信、有条理，不是炫酷特效。画布工作流和投影跟着动，作者不干等、不误以为卡死。90 秒只是挑模型的延迟预算，不是「确认一条事实才算激活」。分镜 SVG 尽快上时间轴（中间可插、删、去重）是「看得见在干活」的一种，不是唯一形态。看到分镜的情绪 aha ≠ 激活。取证／规划下一章仍可当首价值入口（ADD-056），但激活本身＝看见系统在工作。
- **演示书改用真书（ADD-017 J7）**：不自拟微书（《捡骨人》方案作废），从新书书库的前三章挑真书当示例；具体书目与题材配比待 CZ 拍（❓）。
- 失败兜底铁律：永不留死屏、最终兜底回路 A；制作纪律：预制帧精致度钉在产品真实能力天花板，不许效果吹牛。首屏“粘贴你的章节”主位、“看演示”角落。
- 设计稿：[TUTORIAL_SCRIPTS_DESIGN_R01](../../../novel-mvp/design/TUTORIAL_SCRIPTS_DESIGN_R01.md)。

### 审查体验：故事概览是默认视图（ADD-002 Q1＋ADD-012 F2／F8＋ADD-009 第 3／4 题）

- 审查的默认视图是**故事概览**，不是密密麻麻的文字清单：每章约半屏 SVG 配图＋简短事件梗概，让作者“像看一个作品一样”一眼判断满不满意；点击某段才展开细节层（事实句、先描写什么后描写什么、写作指导）；密大纲依然存在但不显眼，主要给专业作者。此形式是**通用展示原则**（“以后给用户展示的也都应该是这种”，代码审查不把全量 diff 拍脸的类比）。
- **概览的真正身份＝感官愉悦＋自我认知，不是效率工具（ADD-012 F2 基调纠偏）**：抽取侧把名场面解析成画面展示，可形成“投放抖音的解说材料”——让作者看到“我的故事是生动的”；创作侧让作者先读一遍自己刚创造的故事，写书稿时更顺畅。效率是副产品。“可发抖音的解说画面卡”与场景卡（给视频工作流）是两个出口，同源不同用。
- **批量放行章级封顶（ADD-009 第 3 题）**：不给“全书一键放行”，最大只到“本章其余全通过”——一章一屏读得完，签字才有含金量。
- **驳回带可选原因标签（ADD-009 第 4 题）**：抽错了／重复／不重要／是梦境或假设，四个一键标签可选不强制；标签数据喂抽取器迭代方向。
- **驳回＝思路级否定（ADD-012 F8）**：四选一后另外三个是“未选”（正常淘汰，不特别记）；**驳回全组**＝“你这几个思路全错了”——强负反馈，必须记录为弃用项，且后续生成**必须读到**（不许把驳回过的思路再推荐回来）；界面原地变灰（看得见但明确已废弃）。
- 设计稿：[REVIEW_OVERVIEW_DESIGN_R01](../../../novel-mvp/design/REVIEW_OVERVIEW_DESIGN_R01.md)。

### 规划账（界面词“大纲”）结构与全书引导（ADD-004＋ADD-016 H2＋按推荐暂定批次）

- **命名（Q1）**：产品界面照叫“大纲”，文档和代码内部叫“规划账”；术语纪律管内部，不让用户学新词。**卷层（Q2）**：默认折叠，章数超约 30 章或作者手动才开卷。
- **选项消化清单（Q3，重要新机制）**：创作流是卡片题目流——出题给推荐＋备选选项，**每个选项标注“消化清单”：选它会消化哪些计划事件、伏笔、必写承接**；作者选择的同时对应计划事件即标已消化（挂消化链接），不需要事后关章再勾选；只有删减／修改剧情时才重新核对。对账主要发生在剧情生成层；书稿写成后的事实入账是另一道独立工序。变体兑现＝消化时附变体说明（ADD-011 GAP-10，`variant_note`）。
- **字数预估驱动槽位映射（Q4）**：编辑规划账时每个故事段落就预估“写清楚大概需要多少字”；预估显示本章装不下（或没东西可写）时，系统提示做映射调整（如原第 18 章改由 18、19 两章完成，后续整体后挪）。字数预估是规划阶段的固有信息；默认值由模型给、作者可改、写完几章拿实际字数回修（ADD-011 GAP-13）。R09 注（ADD-019 历史题号 M8，不是现行模块 M8）：字数预估的真身＝节奏抑制器＋跨章连续性来源，见下方 R09 管线增补。
- **来源身份同篮（Q5）**：反向剧情图（旧稿反推）和作者手写规划进同一套篮子，节点带来源身份标签（作者声明／旧稿反推／模型建议），互不冒充。**语义拆分（Q6）**：计划事件不拆“表述—命题”两层，就是一句人话；语义拆分只发生在事实入账那侧。**挂点节奏（Q7）**：挂点机制（稳定 ID＋挂件表）随结构落地，第一个模板等续写规划开工时做。
- **全书大纲引导与分层深化（ADD-016 H2）**：导入完就引导定全局大方向（至少“前 50／100 章大概写什么”）；**内置理论拆解**（救猫咪十五拍、英雄之旅、起承转合）把模糊想法拆成可写的节奏；分层深化三档（简单卷级→中等→详细），每档有“先够用了”停点，默认只深化当前卷＋下一卷；**长线节奏监控台**＝规划画布拉到最远的档，纯视图零自有账本；聊天中跨位置创建内容走**创建单**（逐行标目标账本和身份、勾选确认才落账、设定类只落候选）。按推荐暂定：写一半换理论骨架可支持（已落节拍是这本书自己的账，骨架只是出生模具）；存量书等反推收口再亮引导卡；V0 固定三内置理论各出一案。**节拍（BEAT）是唯一新对象**：住卷篮 `beats[]`、带章窗口估、进要点汇聚、走选项消化销账。新停点 P18 引导卡、P19 偏离提醒。
- 数据层按推荐暂定：旧大纲按需反推（作者点“组织进大纲”才入账，账里只有作者看过一眼的东西）；场／线用独立永久号（SCN-／L-）；已写成章节 MVP 显示“计划卡＋已移交有偏差角标”；存储选型＝JSON Schema 合同→MVP 用 JSON 文件（plan.json＋plan_history.jsonl 流水留痕）→产品化 PostgreSQL。

### 停点系统（ADD-005＋停点注册表）

- 产品全流程里所有“可以停下来问作者”的位置（分拣确认、选项选择、对账、槽位调整、体检提醒等）预先设计成统一停点位，每个停点可配置：**自动通过／提醒不停／必停**。停点位先做好，后期按用户分层开放档位。
- **小白默认放行、高级作者才频繁停**（方向反直觉但拍死）；付费新手出厂档＝省心预设＋首次出题提示可改（ADD-011 GAP-08）。停点放行 ≠ AI 可写真值：**真值签字**（事实入账、来源身份认领、Bible 升级、改史）任何档位都要作者显式动作。
- 全局注册表已裁定 P1–P15，另新增 P16 灵感提醒、P17 影子重推、P18 引导卡、P19 偏离提醒、P20 选线、P21 转正（撞号裁定：章工作台原提 P18／P19 让位给全书大纲稿，改 P20／P21；打包器缺料回取＝P9，原“P6 候选”与审查稿撞号作废）。强制必停分两族：S 类护账本、F 类护钱包（积分大额消耗前必确认）。导出不进真值签字表（不改账本，属付费权利）；掌控模式不锁付费（收费冻结口径）。

### 开章选线与章工作台（ADD-016 H1／H3／H7＋章工作台三题；R11 按 ADD-050 收口）

- **开章选线以 N19-B 为准（ADD-050）**：上层已经安排好「这一章是哪条故事线」→ 不用问，默认带过去，前台只显示可改的当前线。没定好 → 才问。作者改线，或系统发现对不上规划 → 才问。切线仍是重动作，仍出切线包。不要做成每章必经选线屏。选不同线要准备的东西确实不同（续线导入线状态；切视角＝切镜头），所以没定好时才停下来问。判线口径：**关注的内容变了就是新线**（视角切换、感情线、前一困境已解新任务进来都算）。首选路径是全局安排提前设计好或导入；用户不设计则引导；实在不要就走系统建议式。选线屏＝零调用线级素材栏。
- **章级沙箱天然多开（H3）**：这一章本来就在沙箱里进行（生成的不直接进数据库），天然可以另开沙箱并行推演两条线、切换着看；两条不冲突的可以一先一后都用（新线往后挪几章引出）。按推荐暂定：归档沙箱永不自动清、界面折叠（点子价值常在几十章后显现）；沙箱不做真合并（选一转正＋点子搬家重出题，分叉记 v2）；沙箱内“选定即消化”与转正调和为**决定即时生效、转正批量落账**。
- **整章重写＝分层回退（H7）**：剧情＝大骨架→填细节→更细的细节，卡在哪层回哪层——骨架不认可回骨架；填细节时发现骨架要改，回骨架层改完再重填。系统要能调查为什么重写（全自动生成不满意 vs 手动一步步走崩，天差地别）；回退标签可跳过，机械归因恒记录。三层回退＝细节跟卡走、账务跟卡走。
- 设计稿：[CHAPTER_WORKBENCH_DESIGN_R01](../../../novel-mvp/design/CHAPTER_WORKBENCH_DESIGN_R01.md)。

### 计划 vs 已经发生（ADD-051，CZ 2026-08-14）

说白了就一件事：**打算写什么，和故事里已经发生了什么，不能当成同一堆东西。** 字段怎么拆，留给设计；这里只把身份说清楚。

- **已经发生**：作者确认过、故事世界里算数的事。抽出来写成那种句子，叫事实句。账上登记成一条，就是剧情原子。对人来说就是一句话和账上这一条，差得不多。
- **计划**：这一章还准备写什么。句子样子可以和事实句一样（抽取抽出来的那种形式，上游抽、下游大纲生成完也用），但必须标明这是计划、还没发生。
- **不要叫「事实句子层」**：章计划铺的是本章要发生的安排。写成「事实」，后面的模型会当成已经发生。

界面只说「事实」和「计划」。

### 章计划与出题（续写规划 M8；ADD-013 G1／G3／G8＋ADD-012 F1／F8＋ADD-017 J5）

- **章计划的完整画面（G3）：要点汇聚一屏→主架卡片编排**。铺满，但铺的是**本章计划**（同样句式，身份是计划、还没发生）；**一屏看全本章要解决的问题**，不许隐藏后突然冒出“这个也要写”。要点来源汇聚约十类：全书／卷级规划下传方向＋上一章存留问题＋本章目标＋预估字数＋该触发的剧情＋人物必须完成的转变＋出场对象要达到的状态＋必须揭开的秘密＋必须释放的压力＋金手指久未使用提醒。**必选 vs 可选**：必选＝本章主架必须解决；可选带**推荐星级**（5 星最合适、2 星以下也列但不推），像素材货架，进大纲编辑台后随时增删。根据必选＋已勾选要点**编排主架卡片**（一张卡可串联解决多个目标），主架之外顺着卡片衍生支线。一卡一题；出题节奏参数 pacing_cap 默认 2、作者可改。
- **选项折叠部分＝系统执行的变更清单（G1）**：选项除了给人看的简短回答，可折叠部分在生成时就写好“选它之后系统具体怎么改账”——增／改／删哪些计划事件、Bible 世界规则怎么改、人物状态怎么变。折叠区既给作者看细节，也是选定后的入账指令；变更清单只动计划层，真值和 Bible 只出待签提案。新设定入册（ADD-016 H5）也走这条：选定即入设定集候选，入账时一并确认。
- **规划姿态＝果断领航员＋两个新机制（ADD-012 F1）**：直接给建议＋备选；①**前文最小修**——已上架小说的前文可能有逻辑错误（卡文常因此），系统先分析前文、按最小修原则找问题（已发表不能大改）；②**欠账偿还节奏**——后续建议转向不能太大，不许一章把欠账全还了（“画风突变是不允许的”），要分期偿还；repair 类要点走欠账通道，不自动占场。“未写”桶改期欠账流进下章要点汇聚，循环闭合。
- **口味配置（G8）**：驳回快选标签（节奏快了／慢了／人物不像／动机不对／不好看）＋未选记录，积累成作者的个人口味配置，影响以后选项生成——产品越用越好用；这些资料很珍贵，系统要收集。口味配置 V0 跟书走。弃用重出题不设硬限（120% 预算闸门护钱包＋连弃 3 组提示换思路）。
- **选项＋手写混合输入＋落位核查（ADD-017 J5，兼产品交互通则）**：选项和手写不是二选一——“这个选项方向对但太简单，我补两点”是常态输入形态，所有选择界面都要支持。手写必然产生新东西→系统对“选项＋手写”**重新评估**，生成变更清单；**落位核查环节必须有**：检查是否真有位置可填、是否硬填冲突（本有值又填一值）、名字写错（主角叫王刚写成李刚），核查完回告用户。“事后核查”和“开头就带大量幻觉的生成”是完全不同的效果。
- M8 的产出是剧情层＋写作指导。**写作指导＝大纲／出题过程的副产品，不是额外 API（CZ 2026-08-13 15:54 亲拍 ADD-036／G5）**：生成选项时用户就已经能看到这些注解，收工只是把已有内容挑拣整理再给看一遍——不是大纲阶段不提供、最后突然冒出来。三层对应不同位置已有内容，不新增工作量：①**这段写什么**＝这张卡片要解决什么问题；②**对白该透露什么**＝选项里「某人声称／说／透露」的目的（给选项时这些目的本来就有）；③**该如何写**＝插件自带的写法层。J1 口径不变：给要求给信息点，不给示范成文。理论／技巧对出题与写作指导的注入一律走插件卡牌制与分层取用（ADD-014，系统本体见 02 页插件系统）。
- **目的挂卡，不改底层（CZ 2026-08-13 17:18 亲拍 ADD-037／A9）**：作者要达成的效果（先有画面／结局、或缺中间过程、或额外限制）加到卡牌上。人可以在卡上加人为注解，**一起影响这张卡生成选项的内容**——不是绕过 Agent 去改文件。两种用法：①附着在别的剧情生成上，「顺便把这个效果也处理了」；②单独开一张卡，专门处理这个目的。跟 Agent 说「我想达成什么」，让它思考或顺手改；跟已有内容／本章原意图打架时要爆出来，问作者改哪边。中间缺过程时交给画布反向拆前置卡（见 02 页）。出题屏「我已有画面」轻按钮只是入口之一，**不是这道题的答案**。
- R09 注（ADD-018 K1／K8＋ADD-019 历史题号 M1／M2／M3，均不是现行模块号，2026-08-13）：要点汇聚屏升级为**插件提醒的集散地**（分组折叠＋来源标注）；出题新增衍生点子卡；变体必带反馈；熟手可一键快速铺满；连续高潮区间可绑成篇章组创作——均见下方 R09 管线增补。

### 触发系统：绑事件不绑章节（ADD-013 G2）

- 伏笔／钩子／义务有**最佳触发期**，过早过晚都不合适，必须有承接相关理论技巧的位置。**触发条件绑定故事内的事件／时间，不绑章节号**——“第 15 章必须揭露”是奇怪的（来不及就硬塞）；正确形态是“XX 事件发生之后，提示该触发哪些剧情”；预估章节范围只作辅助。
- **触发期之前就开始预热提醒**，不是快过期才叫；进入最佳触发期时主动积极。**素材栏交互**：到期候选像素材栏一条条摆着——系统可以挑拣，作者也可以主动勾选“这章触发这条”或叉掉“这章不碰它”（叉掉后系统不主动读不主动用）。
- 按推荐暂定：触发条件＝人话必填＋结构化锚可选（有锚机械判／没锚模型判／素材栏标明谁判的）。与 R07 触发亮灯机制衔接：亮灯＋进执行包、不自动开卡仍有效；题 16 的机器判据字段级仍挂账（见 05 页）。

### 体检定位修正：体检仍主要服务导入侧；创作侧也要检查（ADD-013 G7＋ADD-052）＋矛盾＝剧情机会（G4）

- **创作侧也要检查**（ADD-052）：生成时约束（执行包带禁做清单＋选项消化机制＋程序校验）不是保证。产品内生成的事实句、计划、执行包都要检查。删掉旧句「按理不会冲突、不需要事后体检」。检查器只能说覆盖范围内未检出，不能说没有冲突。**体检仍主要服务导入侧**：存量书稿的内伤，加上新章书稿粘回入库时的增量核对（作者手写可能偏离或引入新矛盾——这也算“导入”）。**不存在“每三章自动跑全书”的定期体检**；旧稿有“定期体检”字样的按导入口岸读。
- **体检语气可切换（ADD-012 F3）**：默认书粉腔（“诶，第 2 章说左眼失明，第 5 章怎么用左眼瞄准了？”），专业编辑腔／质检报告腔是可选设置；真源同一份，语气是渲染层不是数据层。
- **矛盾＝剧情机会（G4）**：只说影响当前章的；逻辑问题往往可以通过后续精妙剧情解决——“因为有矛盾才会有剧情”，人物动机立不住→后续补动机找补反而产生新剧情。发现前文矛盾时不说“你写错了”，说“这里有一个剧情发生的机会”。与 R07“冲突也可转成剧情机会”互证；体检与前文分析的呈现按“问题＝机会”重框。
- 免费层含一次轻量体检（ADD-009 第 2 题；额度细节属冻结话题，见 08 页）。

### 人物账：完整画面（ADD-016 H4＋人物账三题；也见 04 页聚合成本注）

- **人物页＝事实账的自动聚合视图**（防第二真源，聚合零新增调用），字段分四种身份：原文有证据的／作者设定的／推测的／可变的。

### 角色视角模式（ADD-008 第 5 点＋ADD-017 J6＋角色视角三题）

- **新设计，替代旧“导演／玩家／旁观”三身份**：“导演模式”不用设计——编辑规划本身就是导演模式；“旁观”没什么可设计——就是第三人称读小说。模式的本质只有一个维度：剧情是**事先编排好的／自动跑的／边用边生成的**。
- **角色视角模式**＝扮演故事中任一角色（人称可设置），以该角色视角展开：他看到什么、到哪了、面临什么抉择。**三个用途**：①**防降智工具**——主要配角／反派不能做愚蠢决定，用该角色身份跑一遍“立马就知道这个角色降智了”；②**剧情创意来源**——跑角色视角时发现“这角色怎么一直不动？”，作者从中产生剧情创意；③**沉浸冒险**（消费向延伸）——以某角色在这个世界里冒险，依然生成规划、用同一套规划账。运行机制：跑完约一章到停点问要不要存；关键节点交用户选择，其余自动跑。
- **排期已拍（J6，关闭洞-36）**：V1 只进“防降智重放”；创意跑和沉浸冒险 v2。
- 按推荐暂定：报降智前先查伏笔账（有隐藏动机静默跳过）＋作者标“故意”时顺手把动机收进伏笔账（降智报告＝伏笔生产线）；沉浸冒险跑时自由、存时对账（禁做区只装世界规则和已发生不可逆，不装未来计划——撞车是剧情机会）；账薄 NPC 跑前提示补三字段（动机／困境／性格）不拦（跑视角＝人物卡补全引擎，硬线只有“没名字不给跑”）。知情差 V1＝出场推定＋公共信息＋作者例外表；**全程沙箱，永不写事实账**。设计稿：[ROLE_POV_MODE_DESIGN_R01](../../../novel-mvp/design/ROLE_POV_MODE_DESIGN_R01.md)。
- R10 修订接受（ADD-028，2026-08-13）：①**防降智五条判据**作为角色视角评估先验——legally_possible ∧ epistemically_available ∧ serves_active_goal ∧ causally_explainable ∧ not_obviously_dominated；「被骗不算蠢」（已有）＋「失败不算蠢」（补进说明）；②**12 条知情／传播检查清单**作为 M7 体检项与长程回归计划的施工候选，逐条标「已有机制／待建」；③**misbelief＝派生关系**作为知情账后续设计先验，不设第二真相，V1 例外表不动；④纯函数求值和「合法候选过滤→评分选择→原子提交」三段式属于未来触发系统的施工候选。五判据只作为评估先验；12 项检查、纯函数和三段式都属于施工候选，不冻结题 16 的字段名称、枚举、组合优先级、缺失值处理或机器触发方案。落点：ROLE_POV_MODE 稿＋M7 体检设计＋未来触发系统合同。

### 体裁节奏包与跨体裁映射（ADD-016 H6／H8＋节奏包三题）

## R09 管线增补：写作与检测＋出题新机制（CZ 2026-08-13 第五、六轮拍板，第二册挂账本 ADD-018～020）

以下各段是产品共同理解与拍板结论；字段、界面与工程细节留在各段指到的 novel-mvp 设计稿，背景板只挂指针。

### 写作与检测：内置写作区＋当场检测＋暗稿（ADD-018 K3／K4＋写作区稿三题暂定，2026-08-13）

- **内置纯净写作区**（推翻此前“指导复制出去写”的默认想象）：产品内给一张“左小抄右净桌”的写作台——左侧章计划当“小抄”对照（哪段对着哪部分写），右侧是干净的码字区，可手打可粘贴，**AI 零介入零补全**。这不动 J1 提示词工厂红线：系统仍只给指导、不生成书稿成文，写作区只是把“作者自己写”这件事请进产品里；把指导粘去外部写作 AI 依然合法。
- **当场检测（防吃书）**：只查“我引出的那些要写的句子你是不是都写了、写对了”——描写方式遵守不够不管，不查文笔；**没写是一回事，写错是另一回事**。机械项实时查、模型项手动查；写错标红**不自动改**，作者三选：改书稿／无视（我们只认大纲）／反向改大纲（未收工前大纲随时可反向修改）。检测是当场的，不是事后核对。场级自动检测默认关、设置可开（锚定下一场时自动查上一场——锚定动作免费长出的第二用途）。
- **暗稿（新概念；与旧“暗稿层”不同物，见 07 页）**：列了 130 条要写的句子只写出 100 条——没写的那些若不写也没大问题，**默认已经发生、只是没写出来**＝转“暗稿”（背地里发生、读者没看到、仍是事实）。理由：这些句子可能既引发本章也引发后续剧情，不承认会前后打架。落地＝那条已发生的事实挂 `prose_status` 字段（作者签字的“已发生未描写”态），只打标记不进第二本账、不进 F- 账新序列；后续捞不捞由将来的暗稿插件管。呈现克制：收工卡报本章增量＋书画布角落可查累计，只陈述不催办。**打标记哲学**：很多位置内容先打标签，后续想用随时抓。
- **书稿是可选项（K4）／三路收工**：**没有书稿也可以点收工**——书稿对照是防吃书的可选增值，不是流程必经。三路收工＝有书稿全检／跳检／无书稿直接收工；第三态不移交真值接力棒，大纲继续为真。收工是手动按钮。收工 ≠ 关章：无书稿收工只涨规划进度、不涨已写章数。关章是独立工序，且有硬门槛（ADD-058）：字数、任务、进展、质检、不冲突、符合规划过了，系统才在画布建议「到此为止」。作者空手宣布处理完不算关章。暗稿算不算签过字、能不能开下一章，仍开口。
- **书稿去向（ADD-055）**：已发表并导入的书稿必须附带原文，逻辑检查要对书稿字面，不能只对抽取。产品里开写之后，大纲／账是工作真值；产品里写完才发表、或从未导入的书稿，默认可选对照，设置里可关，用来省额度。外写新稿默认只对照，作者显式选择「以这篇为准」才交棒（ADD-041）。去向记住偏好；选“不存”的每章保留一行知情提示。
- **码字进度条按轻量做**（ADD-019 历史题号 M8 附，不是现行模块 M8）：实时字数＋对照预估的进度条，安静在角落。
- R10 修订接受（ADD-031，2026-08-13；K3／K4 亲拍机制不动，收护栏五件）：①**高影响事件强制单签**——死亡／秘密揭示／物品转手类暗稿**不随批量默认**，进重签清单单独勾选；②**检测器加“模型不知道”档**——当场检测从三态补未知档，并拆成「自报写了／验证写了」两级，读者知情、伏笔兑现只吃验证态；③**进度分轨**——无书稿收工只涨「规划进度」，不涨「已写章数／连续更新」；④**数据去向分三件事**——普通放弃／关闭可以进入有明确期限的临时恢复区；选择“不存”不得进入长期项目库，操作前确认导出，并说明是否存在短期安全副本及怎样删除；主动永久删除项目／账户绕过废纸篓，按政策页清理原文、索引、缓存、派生材料、训练候选、受控第三方和适用备份链。临时恢复区的保存期限是待正式数据政策冻结的候选范围，不是当前用户承诺；⑤**折中默认值已由 CZ 亲拍确认**（ADD-036／A6）——低影响项保留 K3「默认已发生」原话＋高影响强制单签＋收工卡显示「本次默认转暗稿 N 条」。小抄展示与收费见下方 ADD-036／A10 注。落点：WRITING_DESK_DESIGN R02＋检测器合同。
- 设计稿：[WRITING_DESK_DESIGN_R01](../../../novel-mvp/design/WRITING_DESK_DESIGN_R01.md)。
- **小抄＝整理已有注解，收费卖方便（CZ 2026-08-13 15:54 亲拍 ADD-036／A10）**：大纲编辑时每个位置都会遗留「这段写什么／对白透露什么／该如何写」。收工小抄只是把这些已经有的内容整理成一屏。免费档细写法发虚锁住、只露前几个字，升级才看全——刺激订阅的是「写到心坎里的细写法整理」，不是卡住已生成的内容不给看。不充钱可以回头在大纲里自己一点点看，不损失内容只麻烦。这是 J2 收费数字仍冻时唯一已开的收费缝（不解冻价格数字）。插件口／停点是功能档，不是新价格。
- 展示粒度仍按 R10 已接受口径：默认节拍级，可展开到事实句（不是 ADD-036 新拍的）。

### 要点汇聚屏＝插件提醒的集散地（ADD-018 K1，细化 G3）

- 本章开局要处理的核心内容其实很少，**大头来自各插件**：情绪插件（该上了）、金手指频率、固定配角（三四十章该露面）、压力追踪（独立统计独立曲线）、信息密度、爽点统计、文学理论（人物多久转变／弧光）——各管各摊、来源标注（与 F4 建议署名同一纪律）。
- 形态＝分组折叠：必选摆开；可选按来源分组收起、露条数角标；每条约 10 字一行（一行可容两三个选项），悬停／展开才见详情；插件装得不多时一屏装得下。

### 切线预告与提前量哲学（ADD-018 K2）

- 选线也有插件：切线频率（多少章切一次、缓急可调——**此前各处说的节奏都应可控可调**）、新线由主角跑还是他人视角、允不允许不同步时间线（10 年前故事蒙太奇对照）。
- **切线预告**：写这一章时就提醒“下一章要切线——这章必须把故事写到哪、留下大钩子”；**故事线模块读伏笔／欠账**：提前两章提示“伏笔快到期但你还在支线，尽快回主线”。**有效提醒＝提前量**，当章火烧眉毛的提醒是无效的（与触发系统的预热提醒同一哲学）。

### 篇章组：连续章节绑定创作（ADD-019 历史题号 M1，不是现行模块 M1）

- 卷级大纲会布置“连续高潮区间”（三四章的大场面，要完成什么是模糊的）；进大纲编辑阶段，系统**发起询问“这几章要不要绑定在一起创作”**。
- 绑定创作中按预估字数拆分：越写剧情越多，一章 2000 字的内容写到 4000＝两章的内容，映射回去变成几章（结构上跟一章没太大差距，规划槽位映射照旧负责）；支持**回推**——想到第三章的高潮，回推第二章、第一章该有什么，像日常创作，只是字数多了映射成几章。
- 连续篇章的**章末钩子不那么苛刻**（节奏包在篇章组内放宽）；**跨故事线的无关章节不支持绑定**（没有一次性做出来的必要）。

### 出题与选项的三个新机制（ADD-018 K8＋ADD-019 历史题号 M2／M3，均不是现行模块号）

- **衍生点子卡（K8）**：AI 出题时**偶尔**附带衍生点子（“这个谁已叛变——要不要让另一个也叛变？会更有意思”）——出题的衍生物，只在选项里冒（其他地方不冒），不硬生成；作者点加号→**跟在这张卡后面单开一张支线卡**处理（跟题跟选项强相关）。要的感受是“创作不完、太精彩了一浪接一浪”，不是“做任务点确定就下一题，很累”。主 AI 聊天仍可“帮我想几个点子”（另一个入口）。
- **变体必带反馈（ADD-019 历史题号 M2，不是现行模块 M2）**：“这个方向再出两个变体”按钮可以有，但**点之前必须输入想法**（差在哪／选项本身差在哪／更想要什么）——“掷骰子不是好方式，掷之前说清你要什么，不然 10 次不如一次说清楚”。变体＝带反馈的定向重生成，不进弃用记录。
- **快速铺满（ADD-019 历史题号 M3，不是现行模块 M3）**：熟手一键“快速铺满”——系统按主推荐一路铺到底，铺完一屏总览供改、改哪点哪；逐卡确认变铺完总确认（停点即设置的自然延伸）。

### 大书接入：分层快启＋思路插件＋拒绝无设计续写（ADD-018 K6）

- 80 章级存量书分层快启（V1 就要）：近 10 章精抽＋全书粗抽，**粗抽也要抽出故事线结构**（哪几章是什么线、人物突然出现／消失）；出来第一件事问作者“你有大纲可导入；你本来的规划是什么”，脱轨在卷级大纲里修复。
- **拒绝无整体设计的续写**：“81–100 章大概写什么都说不出来，后面很难续”——控制权一般作者不会让度，引导即可，不替作者资格下判词。
- **思路插件族**：从人物结局／性格／情绪发展／地图扩展／矛盾升级／误会升高／为超级名场面做铺垫——各种方法帮作者想；一个思路产生新剧情、新剧情再产生新思路，完善好后续再回头写，剧情不乱飘。（抽取侧口径另见 04 页。）

### 主屏、完本与任性权（ADD-019 历史题号 M4／M5／M6，均不是现行模块号）

- **战报式主屏，每章都有（ADD-019 历史题号 M4，不是现行模块 M4；修订首屏 F5 层 1）**：不做专门的“断更回归”功能——**主屏本来就该是战报／报纸式**：主线到哪、可见状态、挂着的钩子、人物状态、大事件、最近剧情的插画式概览；工作室接力场景同款（队友写完我扫一屏就知道写到哪、矛盾是什么、要发生什么），断更回归自然被覆盖。用现有管线拼（图文概览直接拼、零调用）。
- **完本三件套（ADD-019 历史题号 M5，不是现行模块 M5）**：全书体检（伏笔收没收全／义务兑没兑完）＋全书图文总览（从头到尾故事长卷，可导出纪念／发推文）＋完本庆祝——完本是最强情感时刻，也是自来水素材时刻。
- **作者任性权：让路＋顺手收伏笔（ADD-019 历史题号 M6，不是现行模块 M6）**：明知冲突坚持写→让路，追一句“要不要把复活的理由记成伏笔？（假死／重生／双胞胎……）”——任性权至上，顺手把隐藏设定收进账（与“降智报告变伏笔生产线”同款思路；与回收核对“写错红灯”衔接：作者坚持＝一次改账留痕，不拦）。

### 随时自拆 Skill（ADD-019 历史题号 M7，不是现行模块 M7；插件系统修订输入）

- 不只完本书可拆：**任何时候**“今天写得特别顺”就可以把手感固化成 Skill，后续复用——自制入口不只是“作者指南文档”，是产品内“固化手感”的动作。可发到社群／论坛给别人用；创建规范公开告诉 AI，用户的 AI 帮他把手感做成合规 Skill。插件系统本体与三道机械锁见 02 页。
- R10 修订接受（ADD-023，2026-08-13）：公开分享补五道门（私人候选→正反条件→多次独立成功→权利确认→沙盒→公开）；自拆 Skill 默认私人、去标识。项目级锁版、插件运行来源四段回执、索引行人机分离、能力声明和注入防线都属于设计要求／公开前门，不表示现有产品已经具备。ADD-024 的核心只保留 V0 首发内置面 1 套件、8 个组件、前三层；后续内容生产候选降到施工附录，见 02 页 R10 节。社群插件作者署名继续按 ADD-036 的“原作者＋历次微改者”署名链登记。

### 字数预估的真身：节奏抑制器＋留活下一章（ADD-019 历史题号 M8，不是现行模块 M8）

- 模型对字数敏感：一段剧情约 200–250 字讲清楚（含对白动作），预估由此而来。
- **没有字数预估会无限生成剧情**；有了预估，“快达标了→剧情生成得差不多→不再深化→没写完的交代下一章／后续找机会完成”——**很多内容自然留到下一章，下一章也有事情做**。字数预估不只是容量灯的原料，是**单章剧情密度的闸**和**跨章连续性的来源**（Q4 槽位映射与容量灯的机制底座）。

### 小说腔的唯一位置（ADD-018 K5）

- 全产品 AI 文字默认说明腔（只关注发生了什么）；**唯一小说腔位置＝章末图文概览**——大纲创作完成与对照写书稿**之间**的环节，一幅图接一幅图带故事梗概。
- 生成时机：落账时与 SVG 图**绑定一起生成**（同属创造性产物）；分镜脚本里也会有小说腔句子。这与 J1 红线并行不悖：小说腔只出现在概览梗概与分镜脚本，不是书稿成文。

### 体验与可观测性五件（ADD-027 修订接受，2026-08-13）

- **覆盖范围可视化**：把「本次读了哪些章／哪些账」做成界面元素（如「基于第 12–45 章的事实」角标），属于设计／验收目标；“可见覆盖有助于建立信任”是待验证的产品假设，不是已验证因果。落 CONTEXT_PACKER C9 回执的界面化候选。

- **体验原则不冒充计费机制**：“失败不收费、废稿不占预算”只是待计费合同定义适用范围的体验原则，不代表当前已有退款、免扣费或预算返还机制；收费冻结和定价数字仍不动。
- **卡文多入口**：写作区卡住时不只「问 AI」一个口——回看图文概览／回看本章要点／跳写下一节拍（跳过处留回填标记，收工审计列出）／换视角草写（进沙箱不进书稿）。出题屏「我已有画面／想法」可以当界面入口之一；真正的机制是 **ADD-037／A9：目的挂卡＋Agent 中介＋可反向拆卡**（见上方写作指导段与 02 页）。

## R08 术语增补：产品词典 v0.1 吸收（2026-08-13）

全量词条（225 条＋逐条出处）以[产品词典 v0.1](../../../TEMP/bgboard-audit-20260809-r01/21_PRODUCT_GLOSSARY_V0_20260813.md)为查询处；本节吸收它的命名规则、背景板此前没有的新词条（按主题压缩收录）、易混词对照和旧词搜索键。词条效力跟着各自出处走，词典与本节都不产生新拍板。

### 三圈命名空间与三条铁律

产品相关的词分三个圈子，圈子决定这个词能出现在哪：

| 圈 | 是什么 | 例子 | 铁律 |
|---|---|---|---|
| 用户 | 产品界面上给作者看的叫法 | 大纲、体检、故事概览、积分 | 不让用户学新词；能用人话就用人话 |
| 工程 | 产品文档、代码、合同、模块的内部正名 | 规划账、M4 事实账、C7、责任段 | 一个概念一个正名，旧名退休要留映射；产品内的 AI／管线词（prompt、抽取、切窗、编排、模型调用）全归这一圈 |
| 治理 | 研究仓的流程词 | 挂账、结果票、共同背景板 | 只活在仓库文档里，禁止进产品界面和产品代码 |

三条铁律（当年真实踩坑换来的）：①**英文字段名不回写产品正文**（`premise_baseline` 这类稳定英文名只出现在合同和代码）；②**迁移期允许旧词进搜索键附录，不允许双主办**（一个词只许一个立法文件，双主办比重名更毒）；③**没有包打天下的总状态机**（故事保护、体检灯、任务进度、处理结果各是各的枚举，禁止硬并）。另加：**治理字段（authority／freshness／canonical 等）永不进产品正文**；从旧设计捡词回来先过 ADD-006 取舍纪律；新词谁发明谁当天登记，登记前先查重，撞名的后来者改名让路。

跨圈互认（已拍定或已成形）：大纲↔规划账；体检↔M7 一致性体检；审查（台）↔M5 审查台；故事概览↔M9／C5 概览卡；事实↔事实句（管线句子形态）；书稿↔书稿（研究仓实验旧语境叫“正文”）。

### 易混词对照（词典第 3 节全表吸收）

| 这对词 | 差别一句话 |
|---|---|
| 事实（句）vs 计划事件 | 一个已经发生、有证据（F 号）；一个还没发生、是安排（PE 号）——两本账永不混编号 |
| 章纲 vs 规划槽位 | 章纲管这章写什么怎么写（内容工件）；槽位管这章在规划序列里占第几个坑（位置）；章篮把两者装一起 |
| 伏笔 vs 义务 | 伏笔是作者的工具，忘了最多黄灯；义务是角色立的债，到期没兑现又没后果就是红灯；分开记账 |
| 概览胶囊 vs 卡牌四层 | 胶囊管上下（同一东西粗看还是细看）；四层管里外（同一剧情点的四种身份面） |
| 停点放行 vs 真值签字 | 停点是过程中的选择停顿，可以配置放行；真值签字任何档位都要作者亲手来 |
| 状态戳 vs 状态账 | 状态戳是单条原子的生命周期位；状态账是全世界“现在什么样”的总账 |
| 大纲 vs 大纲原稿 vs 规划账 | 大纲＝界面上的规划账；大纲原稿＝材料架上装作者旧大纲的架子（命名⑦暂定）；规划账＝内部正名 |
| 章节架 vs 章篮 | 章节架在导入侧，装原文书稿；章篮在规划侧，装这一章的计划 |
| 分拣确认 vs 事实确认 | 前者是“材料放对架子没”的点头（停点 P5，可调档）；后者是“这条真不真”的点头（真值签字，不可放行） |
| 查询结果 vs 事实 | 查询结果是临时答案，默认不进账；要转正得过升格闸四关 |
| 书稿 vs 正文 | 书稿是现行词；正文已退休，只在研究仓实验语境保留 |
| 拆解 vs 抽取 | 拆解是用户视角的整条基础动作（从导入到事实账）；抽取是其中 M3 那一环 |
| 体检 vs 审查 | 体检主要服务导入／粘回，创作侧也要检查（ADD-052）；审查是对每条候选的日常点头（M5，必经） |
| 有声动态分镜 vs 批量动画 | 前者是教程的附带产物（拼创作中的 SVG）；后者是整本工程套餐（拆解直接出分镜脚本、跳过体检） |
| 概览卡（C5）vs 场景卡（C8） | 概览卡给审查台看章梗概；场景卡给外部视频工作流吃分镜 |
| “卡”字家族 | 书名卡／简介卡是材料架的架子；创作卡／修复卡是工作单位；概览卡／场景卡是数据快照；选项卡是出题产物——都叫卡，四种东西 |
| 剧情层（C7）vs 剧情图 | C7 是一个章篮的只读快照（传输合同）；剧情图是原子＋关系边的图谱（数据形态） |
| 设定集（材料架）vs 故事状态 | 设定集是作者导入的声明材料（参考）；故事状态是系统维护的当前值账（Bible 状态法管） |
| 反向剧情图 vs 作者手写大纲 | 一个是旧稿反推的“实际写成了什么”；一个是作者的意图；同一套篮子但来源身份标签互不冒充 |
| 事实账 vs 长期底账 | 事实账是 MVP 的真值库（M4）；长期底账是设计上的常驻关键变化层——同一脉，前者是后者的 v0 落地 |
| 停点三档 vs 自动化四档 | 三档是现行停点设置；四档是旧设计同族词，且旧思路“新手逐条确认”已被反转成“新手默认放行” |
| 挂账 vs 挂点 vs 入账 | 挂账是治理流程（增补案攒批）；挂点是规划账的扩展机制（挂件挂在稳定 ID 上）；入账是事实进真值账 |
| 责任段 vs 责任区 | 责任段是产品 C2 的输入单位；责任区（responsibility zone）是研究仓 P4 合同词——同源不同物 |
| 产品 C1–C8 vs 研究 C 系 | 前者是模块合同编号；后者是实验臂（C0–C5）和表示家族（C2_UNIT／C2_FULL）——撞号不撞义，跨仓写全名 |
| 产品 M0–M10 vs 研究 M1 | 前者是产品模块；后者是合成风洞实验名——跨仓讨论时写全名 |
| 停点位 P1–P21 vs 研究 P3／P4／P5 | 前者是产品停点编号；后者是研究线编号——跨仓讨论时写全名 |
| 三种回执 | 章版本回执记关章定版；覆盖回执记这次检查读了什么没读什么；AI 参与回执记谁写的——三张收据管三件事 |
| 执行包 vs 待消化清单 | 执行包是开写前的全部上下文行囊；待消化清单只是其中“本槽位欠的账”那一格 |
| 入架候选 vs 审查确认 vs 真值签字 | 三个点头是三道门：材料勾选上架 ≠ 作者审过这条 ≠ 已写入真值；一个“确认”字不许包三件事 |
| 候选池（禁止裸写） | 没有一个通用“候选池”：已选改动、新问题、素材候选各有各的筐，不倒进同一锅 |
| 展示分组 vs 写入分组 | 摆在一起看的一组，不等于写入时同进同退；分组只管眼睛，写入按条走各自闸门 |

R10 易混词补充：**对账边 vs 六态对账**——六态对账是“怎么对”的判定规则（完全／变体／未实现……），对账边是“对完的结果记在哪”的账本对象；前者是动作，后者是落地。**暗稿默认值 vs 高影响单签**——低影响项保留“默认已发生”，高影响事件（死亡／秘密揭示／物品转手）强制单签，是同一机制的两档不是两个机制（**折中已由 CZ 亲拍确认**，ADD-036／A6）。**插件运行来源四段回执 vs 作者署名链**——前者只记一次运行中谁参与了什么，不判断权利或作者身份；后者登记社群插件的原作者与历次微改者。**创作证明包 vs AI 参与回执**——回执是系统内部的参与分类记录（N22）；证明包是作者自愿准备、申诉时可提交的候选材料，不保证平台采信。**写作指导 vs 额外生成**——指导是出题副产品，不是另调一次 API。**画布工作流 vs 时间轴**——前者非线性创作图，后者是故事内先后的预览。**目的挂卡 vs 直接改文件**——跟 Agent 说要达成什么，注解影响生成；冲突爆出来问改哪边。**知情硬账 vs 旁账**——硬态进真值，猜度量永不进真值。

R09 易混词补充：**暗稿（新义）vs 作者锁定真相**——暗稿是“计划里有、书稿没写、默认已发生”的事实句标记（`prose_status`）；作者锁定真相是“作者私下已定、读者未知”的 Canon 原子（`AUTHOR_ATTESTATION`）——一个管“写没写出来”，一个管“读者知不知道”，两条轴不同。**计划 vs 已经发生**——句子样子可以一样，计划必须标明还没发生，不许叫事实（ADD-051）。**粗抽 vs 精抽**——覆盖范围与结构义务不同，不是价格档位。**写作区 vs 章节工作室（已废弃旧词）**——写作区只管码字与当场检测，不承担旧“章节工作室”的全流程语义。
