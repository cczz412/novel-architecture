# 题①｜角色知情边怎么销

## 推荐：B｜候选，待 CZ 拍

**不另开一本知情账，但必须新增一种真正的“边”结构。**

这里的 B 不是把“他知道了”随手塞进人物 `profile`，也不是在事实和人物两边各抄一份数组。建议只保留一个权威宿主，另一方向靠索引查询。

项目里的矛盾确实存在：R14 与既有方向要求硬知情记录，人物合同却拒绝 `knowledge_edges`；现行第 12、13 行因此没有合法取数来源。

### 为什么选 B

**证据｜外部参考，无产品或执行权威**

* `Character Beliefs in Story Generation` 指出，人物信念对叙事很重要，却常在故事规划系统中缺失，或只被临时处理；论文用动态认知逻辑分别更新世界状态和人物信念。([AAAI出版物][1])
* `HeadSpace` 专门跟踪人物对世界的误解，并允许人物因为误信而作出会失败的行动。也就是说，**误信不是“没查到真相”**，而是一条有内容的错误信念。([AAAI出版物][2])
* `Using Domain Compilation to Add Belief to Narrative Planners` 明确说，任意深度的“甲相信乙相信丙……”会迅速复杂化，因此它把模型限制在人物对世界简单命题的一阶信念上。([AAAI出版物][3])

**推断｜外部参考，无产品或执行权威**

百万字连载真正危险的不是“边存在哪个文件”，而是以下四种做法：

1. 给每个角色和每条事实生成全量笛卡尔积；
2. 把所有没记录的角色都自动写成“不知道”；
3. 同时在人物、事实两端保存可编辑副本；
4. 无限递归记录“谁认为谁知道什么”。

只要采用**稀疏边＋一阶信念＋变化记录**，B 与 A 需要维护的有效边数量其实相近。A 额外增加的是新 ID、writer、reader、失效扫描、跨账事务和取件入口；当前连既有账的 runtime reader 都没有全接通，再开物理新账会扩大接线面。

## B 能不能撑住误信和误信内容

✅ **能，但有条件。**

一个只包含：

```text
character_ref + fact_ref + state=misbelieved
```

的 B **撑不住**。因为它只能说“这个人物对某条真事实看错了”，不能说“他究竟误以为什么”。

### B 的最低形状｜候选，待 CZ 拍

| 人话 | 候选机器含义 | 规则 |
| --- | --- | --- |
| 谁的知情 | `observer_ref` | 指人物 ID |
| 当前是什么状态 | `epistemic_state` | 至少区分：知道／明确不知道／怀疑／误信 |
| 对应哪条真相 | `fact_ref` | 可空；有世界真相时指 confirmed fact |
| 他实际相信什么 | `belief_content` 或后续 `claim_ref` | 误信时必填；**不能写进世界事实账** |
| 何时开始／失效 | 故事时间区间 | 不能拿最新知情倒灌旧场景 |
| 为什么这样判 | `evidence_refs`／作者签字 | 硬检查必须能回源 |
| 当前还是历史 | 版本／状态 | 改稿或揭示后旧边保留审计，当前值可重算 |

🔥 最重要的一条：

> **没有知情边，只能表示“系统未追踪”，不能自动表示“人物不知道”。**

只有书稿证据或作者明确设定能证明人物“不知道”时，才登记显式“不知道”。

## A 的维护成本会不会爆

**推断｜候选，待 CZ 拍：A 不一定因数据量爆，但更容易因制度面爆。**

A 只有在下面场景才开始显出优势：

* 同一个秘密／传言被很多角色共享；
* 要追踪完整传播链；
* 同一个错误说法需要被多人引用，不能重复抄写；
* 需要经常做“这条信息现在谁知道、谁误信”的反向查询；
* 信息项本身有独立生命周期和多种说法版本。

这时可以升级成“信息项＋知情边”的 A。现在直接上 A，相当于先为未来复杂案建立一整套新账，而现行简单场景也要承担新 writer 和 runtime。

## 中文网文适不适合

**适合，但应按题材启用，不该全书全角色强制铺满。**

* 高适配：悬疑、宫斗、权谋、身份伪装、误会推进、多视角、读者比角色多知道的故事。
* 中适配：群像、升级流中有情报差与阵营欺骗的部分。
* 低适配：单视角、直线推进、人物得到信息后马上公开行动的简单段落。

World Anvil 的公开教程已经把“哪些角色知道哪条秘密”与面向读者／团队的资料访问并列展示，但这也反过来说明：**故事角色知情和资料权限必须分轴**，不能用一个 `visibility` 字段包办。([世界铸造炉][4])

> **若只许选一个，选 B，因为当前需要的是一套稀疏、可回源的知情关系，不是再开一本尚无 writer、reader 和 runtime 的账。**

# 题②｜`dark_draft` 身份

## 推荐：A｜候选，待 CZ 拍

项目当前两句话无法同时长期成立：

* `dark_draft` 表示“已发生、未描写、仍是事实”；
* 它却继续只住规划账、不发 F 号，规划账又明令不能证明已发生。

这个冲突已经在现役内审回包里被点明。

### 外部工具通常怎么分

**证据｜外部参考，无产品或执行权威**

* Final Draft 的 Beat Board 用于规划场景、序列、情节、幕结构和人物目标，再通过 Outline Editor 进入剧本页面。它清楚区分“规划卡”和“剧本内容”。([Final Draft][5])
* Scrivener 的同一张 synopsis 卡既可以总结“已经写了什么”，也可以写“下一步准备写什么”，并另有 `To Do` 等状态。也就是说，**容器相同不等于身份相同，必须靠状态判定。**([Literature and Latte][6])
* Plottr 的 Scene Essentials 同样可以用于事前计划，也可以在写完后回填“这场实际发生了什么”。([Plottr][7])
* Final Draft 还把从剧本中删掉的场景保存在 Beat Board 的“boneyard”。这些内容依然存在于工具里，但并不等于仍在成片或当前正史中。([Final Draft][8])
* World Anvil 的 Timeline 则明确把 Historical Event 定义为记录“世界中发生了什么、何时发生”。([世界铸造炉][9])

### 外面通常算哪一层

**推断｜外部参考，无产品或执行权威**

外部没有一个通用的 `dark_draft` 术语，但身份分界很稳定：

| 作者真正表达的意思 | 应算哪一层 |
| --- | --- |
| “我以后打算让这件事发生，但还没定” | 计划 |
| “这个场景被删了，可能以后再用” | 废稿／候选素材 |
| “故事世界里它已经发生，只是读者没看到” | 作者 Canon／历史事实 |
| “正文已经明确写出来” | 有书稿证据的事实 |
| “人物声称它发生了，但真假未定” | 表述事件＋命题候选，不能直接当世界事实 |

所以，**只要保留“已发生、仍是事实”这句话，A 是唯一与现行真值分层一致的选项。**

### A 怎么落才不膨胀｜候选，待 CZ 拍

不是每条没写出来的章计划都自动发 F 号。建议准入门至少满足一项：

* 后文会依赖它；
* 会改变人物、物品、地点、势力或世界状态；
* 后续查询／一致性检查必须知道；
* 属于死亡、秘密揭示、物品转手、身份变化等高影响事项；
* 作者明确签字说“这件事已经在故事世界中成立”。

正式准入后：

```text
事实／Canon 层：保存“已经发生什么”及 AUTHOR_ATTESTATION
规划层：只保留“有没有在书稿中描写”的状态或事实引用
```

⚠️ `prose_status` 可以继续回答“写没写出来”，但不能继续单独承担“发生没发生”的裁决权。

## 累赘风险

A 的主要风险是把 130 条没写出的计划句全部批量转正，形成大量作者自己也没认真确认的“幽灵历史”。

防线不是把事实留在规划账，而是：

* 低影响项可批量审；
* 高影响项单签；
* 不影响后文的装饰性遗漏不必入硬 Canon；
* 事实身份和书稿覆盖状态分轴；
* 作者撤销或改史必须留历史。

## 中文网文适不适合

**适合。** 长连载里常有离屏行动、时间跳跃、闭关、旅途、势力调动、配角在主角视角外完成的事。它们可以不直接写成场景，却会决定后面的人物状态和因果。

但“作者本来想写、后来没写”在网文里同样普遍，所以必须靠作者动作区分，不能由“计划卡还留在系统里”自动判成事实。

> **若只许选一个，选 A，因为“已发生”是事实身份，不是成文覆盖状态；继续放在规划账里只会让两个真值系统长期打架。**

# 题③｜读者承诺

## 推荐：A｜候选，待 CZ 拍

开一个**极薄 A-lite 对象**，但准入必须很窄：

> 删掉这条后，读者是否能拿出书名、简介、标签、作者公告或明确原文说：“你确实答应过。”

能，才配活。只是读者自行期待、题材常见套路、作者希望“写得好看”，都不升格。

项目内已明确：伏笔、章末钩、悬念、`must_carry` 与读者承诺不是同一个对象；NWM 只是 U 级研究原型，不能替产品决定。

## 中文网文里确实有“可追责来源”

**证据｜外部参考，无产品或执行权威**

* 中国作家网的男频综述直接使用“文类与读者的基本契约”这一表述，说明“作品卖的是什么体验”在中文网文讨论里确实被视为作者与读者之间的约定。([中国作家网][10])
* 晋江公开作品文案中，作者会在“食用指南”里明确写出“不换男主”“HE”、题材口味和雷点，并给文案标日期留档。单个作品不能证明行业采用率，但它能证明：**正文之外存在可以逐字回指的明确承诺来源。**([晋江文学城][11])
* 番茄官方标签教程把“标签是什么、如何吸引目标读者、标签与作品不匹配怎么办”单列成课程问题；书名课程也专门讲书名最重要的条件和编辑眼中的优质书名。这说明书名与标签是读者进入作品前的副文本入口，不只是后台分类。([番千小说][12])

## 作者纪律和数据对象要分开

| 说法 | 是否进 A-lite｜候选，待 CZ 拍 | 原因 |
| --- | ---: | --- |
| “本文 HE” | **可以** | 明确、可验证、有公开来源 |
| “不换男主／1v1” | **可以** | 明确排除了另一条走向 |
| “第三卷揭开身世” | **可以** | 有时间范围和具体兑现内容 |
| 书名直接承诺复仇、种田、经营某对象 | **视具体程度** | 需判断是否真能逐字追责，不能看到标签就全转承诺 |
| “人设不崩” | **通常不进** | 是作者纪律和质量要求，边界模糊 |
| “要爽、要好看、不能无聊” | **不进** | 读者体验评价，不是可验证事实 |
| “这个伏笔以后会回收” | **仍属伏笔／内部计划** | 除非作者对外明确承诺，否则不是读者承诺 |
| `must_carry` | **不等同** | 它表示后续计划必须承接，不说明读者从哪里获得了承诺 |

## A-lite 最薄可以薄到什么程度

**候选，待 CZ 拍：**

```text
承诺内容
明确来源
适用范围
建立时间／来源版本
状态：生效／已兑现／已改口／已撤回
```

不建议一开始加入复杂情绪预期、读者群画像、兑现强度评分或“爽度”。

## 累赘风险

最大的坑叫**承诺通胀**：

* 每个标签都变硬合同；
* 每句宣传文案都锁死后续；
* 读者评论里随口猜的东西也被记成作者欠债；
* 作者合理改线却被系统永久亮红灯。

所以必须保留三个门：

1. 有明确来源；
2. 含义足够具体；
3. 作者可以正式改口或撤回，但不能静默删除历史。

## 中文网文适不适合

**适合，而且比一般 story bible 更有理由做薄对象。**

中文连载常在书名、简介、标签、作者有话说、食用指南中提前筛选读者。它们的作用不是记录世界事实，而是记录作者对作品走向或阅读体验作出的明确表态。

泛化的“人设不崩”仍应留在软检查；具体的“不换男主”“HE”“某卷揭密”才可能进入 A-lite。

> **若只许选一个，选 A，因为副文本里确实存在可逐字回指的明确承诺，而伏笔和 `must_carry` 都回答不了“作者在哪里对读者说过这句话”。**

# 题④｜稀章家规

## 推荐：A｜候选，待 CZ 拍

A 是语义家规，B 是运行监控。两者不冲突：

```text
A：单章某类对象 0 条完全合法
↓
B：若连续异常为 0，检查抽取器是否失效
```

不能只选 B，因为没有 A 时，抽取器仍可能把“0 条”当失败，继而被逼着填满。

项目内现役回包已经把边界说得很清楚：允许空账，不等于允许造半空对象；定额不能作为正确性门槛或生成奖励，但可以做连续异常探针。

## 真实产品与标注规范怎么做

**证据｜外部参考，无产品或执行权威**

* Label Studio 把“允许提交空标注”和“跳过任务”设计成两个独立设置。也就是说，**认真看过后没有对象**，和**没有完成／无法处理**不是一回事。([Label Studio][13])
* TAC 事件标注论文的规范明确要求不要标注推断事件，哪怕边界判断很难，也不能为了丰富标注而把推断补成发生。([ACL 论文集][14])
* Plottr 的场景卡可以事前填写，也可以写完后回填，并没有要求每场必须含固定数量的 Hook、冲突或人物变化。([Plottr][7])
* Novelcrafter 明确说明，一章可以包含多个场景或 POV，因此一段统一章摘要未必有用；如果有多场，章摘要由各场摘要组成。结构密度天然不均。([novelcrafter][15])

## A 应写清的五种结果｜候选，待 CZ 拍

| 状态 | 人话 |
| --- | --- |
| `NOT_APPLICABLE` | 这类对象不适用于本章 |
| `NO_CHANGE` | 有相关对象，但本章没有发生变化 |
| `VALID_ZERO` | 已完成覆盖，确实没有合法条目 |
| `INSUFFICIENT_EVIDENCE` | 看过材料，但不能可靠判断 |
| `EXTRACTION_FAILED`／`NOT_RUN` | 抽取器失败或根本没跑完 |

名称可以另拍，语义不能再压成同一个空数组。

## B 怎样作为异常探针

**候选，待 CZ 拍：**

* 不设“每章至少 N 条”；
* 按材料类型和历史基线观察；
* 连续多章所有事实族都为 0，才检查管线；
* 只有某一类一直为 0，检查路由、Schema 或提示词；
* 报警只说“抽取行为异常”，不能补写事实；
* 阈值由本地带 Gold 的章节实验决定，不从外部课程抄一个数字。

## 累赘风险

A 只需要几条总家规，成本很低；它反而能减少：

* 重复事实；
* 把气氛描写硬拆成事件；
* 把计划、猜测写成已经发生；
* AI 为了填表主动制造剧情；
* 稀章被误判为抽取失败。

C 的软定额最危险，因为“软”只要进入评分、提示或奖励，模型就会把它当目标。

## 中文网文适不适合

**非常适合。**

过渡章、纯对话章、心理章、解释章和大战高潮章的数据密度本来就不同。番茄官方课程会教章末留钩、提前埋伏笔等写法，但课程把两者列成不同动作，也没有把它们变成每章必须出现的事实配额。([番千小说][16])

> **若只许选一个，选 A，因为只有 A 能从制度上保证“零条也是正确答案”；B 可以监控抽取器，却不能阻止模型为了达标造数据。**

# 第二部分｜中文网文是真缺结构，还是现有账能吸收

下面现行映射只按项目合同与内审回包：人物账没有知情、追求和困境；故事线缺节点／里程；规划账已经有书核、卷、章槽、场、计划事件、伏笔、`must_carry`、对账边等。

所有外部出处仍是：**外部参考，无产品或执行权威。**

| 业内常讲的东西 | 典型说法与出处 | 我们现行能接住吗 | 判定 |
| --- | --- | --- | --- |
| **读者知情 vs 人物知情 vs 叙述者知情** | 人物信念研究把世界状态与人物信念分开；World Anvil 还同时展示角色知情、读者防剧透和资料权限，说明三者不能混。([AAAI出版物][1]) | `scene.pov` 只能表示计划视角；事实账能承载世界真相；现行没有人物知情边，也没有可正式查询的读者释放边。叙述者知情通常应由 POV／叙述身份和释放记录派生。 | **真缺硬结构**：缺的是信息—观察者关系；不等于要开三本账。 |
| **人物有什么目标、欲望、动机、阻碍，达没达成** | Plottr GMC 拆内部／外部目标、内部／外部动机、内部／外部冲突；Scene Essentials 追问场景目标、输赢及是否达成。([Plottr][17]) | 章槽 `goal`、场 `goal`、PE `purpose` 都是作者计划用途，不是人物当前渴望。人物合同未收 `pursuit`／`motivation`。 | **真缺硬结构，但优先是人物字段＋具体目标结果关系，不一定新账。** |
| **打脸、兑现、期待管理** | 中文平台课程常讲爽感、悬念和追更；Plottr 场景模板则把 Hook、冲突、高潮、目标结果拆开。([番千小说][18]) | 可由 PE 的 `setup/reveal/payoff`、H 伏笔、`must_carry`、RE 的 actual 对账共同回答“安排了什么、实际兑没兑”；“打脸爽不爽”不能硬判。 | **可吸收进现有账；爽度不该进硬账。** |
| **人物弧、立场转变 vs 人物状态时间线** | 番茄人物课把主角、配角、反派的成长线分开，并要求给配角欲望、让其联动主线；Plottr 也把 Character Development 放在场景层。([番千小说][19]) | `state_timeline` 能记录受伤、地点、身份等变化；人物弧可由目标、选择、关系变化、故事线节点组合看出。当前缺少目标和里程，但不缺另一本“弧光真值账”。 | **可吸收；补目标／里程后做派生视图。** |
| **势力格局、地图、战力／体系边界** | 番茄“开书前六大筹备”把主线、世界观、体系、金手指、人设、卷纲分别列出；Plottr 也把魔法体系、文化、宗教、地点、军事组织作为 worldbuilding 内容。([番千小说][20]) | 势力账、地点账、体系账、世界规则账已有宿主；人物／物品当前位置或归属走状态变化。地图应是地点与关系的投影。 | **可吸收进现有账；地图不该再成第二真源。** |
| **长线伏笔本 vs 章末钩** | 番茄官方课程把“章末留钩”和“提前埋入伏笔”列为不同动作。([番千小说][16]) | 长线伏笔进 H；章末钩进 `chapter_slot.exit_hook`；实际兑现由 RE＋confirmed facts 推导。 | **已可吸收，方向正确；不要合并。** |
| **日更节奏、章末要不要留钩** | 平台课程会教章末钩，但中文作者也存在有纲、无纲两种稳定工作法；有人认为细纲可防写偏，有人认为会限制临场发展。([番千小说][16]) | 可以放 `exit_hook`、`craft_widget` 或节奏插件；按题材、篇章组和作者偏好提醒。 | **写法纪律，不该进事实硬账；也不应成为每章定额。** |
| **全书大纲、分卷大纲、细纲、章纲分层** | 情何以甚说每卷有大纲控总体方向，细纲是场景／台词／画面碎片；许墨城会写人物设定和章节大纲。([中国作家网][21]) | 书核→VOL→章槽→场→PE 已有分层形状。VOL runtime、长线读取面和部分 writer 没接。 | **主体可吸收；核心问题是 runtime，不是再发明一层。** |
| **“不换男主／HE／1v1／某卷揭密”读者契约** | 中国作家网有“文类与读者的基本契约”说法；晋江食用指南会明确列“不换男主”“HE”等。([中国作家网][10]) | `genre_promise` 只能放粗题材承诺；`must_carry` 和伏笔不是公开来源承诺。 | **真缺极薄结构候选**：仅收明确、可回指承诺；“人设不崩”仍是作者纪律。 |
| **故事线到底有没有推进** | Plottr 的 Plotline 可表示主线、支线、人物弧、结构和 beats；Novelcrafter 用场景挂接的 subplot additions 展示每场怎样影响支线。([Plottr知识库][22]) | L 已有成员、状态和上次现场；PE 有 `storyline_ref`，RE 能判 actual。现行缺节点／里程，因此无法稳定区分“露面”和“推进”。 | **有一个小而真实的结构缺口**：里程／节点引用；不必新开整本故事线账。 |

## 这一表压成一句话

中文网文不是要求再添一批“爽点账、情绪曲线账、打脸账”。

真正仍可能缺硬结构的主要是：

* 人物知情／误信；
* 人物当前追求、动机及具体目标结果；
* 读者可追责的极薄承诺；
* 故事线节点／里程。

势力、地图、体系、伏笔、章末钩、节奏、人物弧的大部分内容，现有账已经有宿主或可由现有真值派生。

# 第三部分｜长线账、全书大纲、卷纲的形态和边界

## 1. 中文长篇作者通常怎么分层

先说边界：中文作者没有一套人人相同的固定表格。中国作家网访谈里，有作者完全不写大纲以保留临场自由，也有作者写人物设定和章节大纲防止自相矛盾。所以下表是**反复出现的工作层次**，不是行业强制模板。([中国作家网][23])

| 层级 | 常写什么 | 直接出处 |
| --- | --- | --- |
| **全书大纲／书核** | 主线是什么；题材与核心卖点；主角大方向；世界与体系边界；结局或终极问题；大致分成哪些阶段／卷 | 番茄《开书前的六大硬核筹备要点》依次列主线、世界观、体系、金手指、人设、卷纲；爱潜水的乌贼提到搜材料、准备人物场景、电脑写大纲后才正式创作；卖报小郎君的新作把世界观、大纲、人物设定和双线结构做得更细。([番千小说][20]) |
| **卷纲** | 本卷要解决什么；主要冲突／问题；从什么状态进入；到什么状态结束；哪几条主线或人物矛盾在本卷承重；少量关键转折；怎样交给下一卷 | 情何以甚原话是“每一卷都有大纲，这是把控总体方向”，并强调路的起点与终点明确；番茄课程则直接说“卷纲的意义大过大纲”，理由是全书周期长、剧情会改。([中国作家网][21]) |
| **细纲** | 场景画面、关键台词、人物碰撞、高潮碎片、转折线索；可以是不连续素材，不一定机械铺满每章 | 情何以甚把自己的细纲描述为画面、台词和场景碎片，中间过程来自人物自然碰撞。([中国作家网][21]) |
| **章纲／场计划** | 本章当前目标、出场人物、地点、POV、冲突、场序、信息揭示、章末钩、不得违反事项、预计容量 | 许墨城公开表示会写人物设定和章节大纲；Plottr Scene Essentials 的公开字段包括 POV、时间、Hook、Purpose、Conflict、Climax、角色目标和人物变化。([中国作家网][23]) |

## 2. 哪些必须留在全书／卷层，哪些必须下沉

| 内容 | 全书／卷层 | 章／场层 |
| --- | ---: | ---: |
| 作品前提、题材核心承诺、结局锚 | ✅ | 只引用 |
| 一卷的目标、主冲突、入卷／出卷状态 | ✅ | 只承接 |
| 本卷承载的故事线、少量关键里程 | ✅，只存引用或短骨架 | 具体落场 |
| 人物命运大方向 | ✅，引用命运对象 | 本章只取相关部分 |
| 具体事件先后、场景地点、出场人、POV | ❌ | ✅ |
| 对白要透露什么、转折怎样呈现 | ❌ | ✅ |
| 每章钩子、预计字数、场序 | ❌ | ✅ |
| 人物当前伤势、物品归属、已发生事实 | ❌，不能复制 | 仍由事实／状态账裁决 |
| 实际兑现、实际写成与否 | ❌ | 由 RE、事实和章节版本判断 |

### 混在一起的后果

**维护爆炸**

Plottr 自己提醒，故事改变后要同步更新 Plottr；上层和下层若复制同一批细节，作者每次改线都要改多处。([Plottr][24])

**和正文打架**

同一个事件同时写在卷摘要、章纲、场卡和书稿中，只要改了一处，另外三处就可能过期。现行项目把计划、实际事实和书稿证据分权，正是为了避免这种情况。

**执行包被旧细节堵住**

Novelcrafter 明确说，原场景摘要可能过长、失准或与当前情节无关，过长摘要会堵塞 AI 上下文；它建议压到关键点。([novelcrafter][25])

**生成模型被细纲绑死**

这不是“一细就错”，而是创作权被提前消耗。中国作者访谈里已经出现两种相反体验：一方认为章节大纲让思路清楚，一方认为会陷进条条框框。([中国作家网][23])

所以合理边界是：

> 卷纲把方向和退出条件说清，章纲决定这次怎样走到那里；卷纲不提前把每个脚印写死。

## 3. 对照现行 VOL- 七字段＋故事线三件套

### 结论

✅ **VOL- 不缺“最小骨架字段”，主要缺 runtime 和 writer。**

现行七字段已经覆盖：

* 顺序；
* 卷名；
* 本卷目标；
* 主冲突；
* 入卷状态；
* 出卷状态；
* 摘要。

合同还明确规定卷纲只留节奏与骨架，过细内容下沉章计划或人物卡；但 runtime 仍只接受 `volumes=[]`，并硬停 `VOLUMES_NOT_SUPPORTED`。

| 对象 | 格子是否已有 | runtime 是否接通 | 判断 |
| --- | ---: | ---: | --- |
| `VOL-` 七字段 | **有** | **没有** | 不是“卷纲没设计”，是 writer／读取面没施工 |
| `DESTINY-` | **有内容合同** | **没有 writer** | 不是字段缺口 |
| `INS-` | **有内容合同** | **没有 writer** | 不是字段缺口 |
| 长线账读取面 | **概念已定** | **投影未施工** | 不是缺独立物理文件 |
| H 伏笔 | **有规划层结构** | 局部可读 | `paid` 只代表安排回收，实际兑现仍由 RE＋事实推导 |
| L 故事线 | 有成员／状态／上次现场 | 有限 | **真正的小缺口是节点／里程，不是再开一本长线账** |

长线对象 writer 和读取面的当前断点，内审已经明确列出。

### 可能缺的只有两个“引用格”｜候选，待 CZ 拍

1. **本卷主要承载哪些故事线**：只存 L-ID 引用；
2. **本卷少量关键里程**：只存高层里程引用，不复制章纲内容。

但第二项还要先拍“里程目标对象究竟是谁”：是后续 BEAT、故事线节点，还是某种高层计划事件。现在不能先造字段，再让字段反向逼出对象。

## 4. 卷纲最小够用集｜候选，待 CZ 拍

现行七字段不改名、不删。下面只分“沿用”“可选候选”“不要做”。

| 中文人话 | 建议机器名 | 级别 | 放什么 |
| --- | --- | ---: | --- |
| 卷序 | `order` | **必须｜现行** | 第几卷 |
| 卷名 | `title` | **必须｜现行** | 人读卷名 |
| 本卷目标 | `goal` | **必须｜现行** | 本卷结束时要完成的阶段性任务 |
| 主冲突 | `main_conflict` | **必须保留字段｜现行，可为 null** | 本卷最主要的对抗／问题 |
| 入卷状态 | `entry_state` | **必须保留字段｜现行，可为 null** | 开卷时的高层局面，不抄人物全状态 |
| 出卷状态 | `exit_state` | **必须保留字段｜现行，可为 null** | 收卷后局面发生了什么阶段变化 |
| 卷摘要 | `summary` | **必须｜现行** | 只写骨架，不逐章复述 |
| 承载故事线 | `storyline_refs` | **可选候选** | 只放 L-ID；不复制故事线正文 |
| 关键里程 | `milestone_refs` | **可选候选** | 少量稳定引用；不设机械条数定额 |
| 全部章标题与章摘要 | — | **不要做** | 会把章纲复制进卷纲 |
| 场景、完整对白、逐场人物表 | — | **不要做** | 必须下沉场／章 |
| 每章必须留什么钩子 | — | **不要做** | 这是章级安排和写法纪律 |
| 人物当前伤势、地点、物品归属 | — | **不要做** | 应查人物／地点／物品／事实账 |
| “本卷伏笔已实际兑现”裸布尔值 | — | **不要做** | 应由 RE＋confirmed facts 现算 |
| 固定章数、固定字数、固定高潮数量 | — | **不要做硬真值** | 最多作估计或容量提示 |

这个集合与中文长连载作者反复强调的“卷控方向、细节可变”较接近；也保留了当前合同“卷纲不要复制章纲”的边界。([中国作家网][21])

## 5. 长线账作为读取面，外面有没有同类做法

✅ **有同类形态。**

**证据｜外部参考，无产品或执行权威**

* Plottr 会从 Timeline 自动生成可查看、编辑和导出的 Outline，还能切到单书或 Series View；这就是同一批底层卡片的不同读取面。([Plottr][26])
* Novelcrafter 把 subplot 正文放在 Codex 条目里，把各场怎样推进支线做成 scene-linked additions，再在 Plan 的 Matrix View 中集中查看。它不是另抄一份“长线真值”。([novelcrafter][27])
* Scrivener 的 Outliner 能在章、部或整本层级查看同一文稿结构和 synopsis，也不是另建第二份文稿。([Literature and Latte][6])

### 对我们意味着什么

**推断｜候选，待 CZ 拍**

现行“长线真值住规划账，长线账只是读取面”的方向没有明显外部反证，反而很接近成熟写作工具的多视图方式。

真正的累赘点在这里：

* 读取面允许直接改复制文本，逐渐变成第二真源；
* 投影不带 source rev／currentness，长期显示旧状态；
* 摘要越写越长，直接灌进 AI；
* 伏笔、命运、故事线和灵感全部默认常驻执行包；
* 同一个对象在卷视图、人物视图、时间线视图各存一份可编辑副本；
* view 只画出来，却没有 writer、reader 和重新编译机制。

所以候选纪律应是：

```text
真值只写一次
→ 读取面按任务编译
→ 每项带来源 ID、版本和为什么加载
→ 来源变化即重算
→ 读取面不得反写真源
```

这与项目现有“长线不是独立物理文件”口径一致；当前缺的是接线，不是再设计一张长线 JSON。

# 仍要 CZ 拍的清单

1. **知情边选 B 还是 A**；本稿推荐 B。
2. 若选 B，权威宿主放人物侧、事实侧还是现有状态存储中的统一边集合。
3. B 的最小状态是否只收“知道／明确不知道／怀疑／误信”，以及误信内容采用内联文本还是后续 `claim_ref`。
4. 是否明确冻结：**无记录＝未追踪，不等于不知道**；v1 只做一阶信念。
5. 什么条件触发 B 升级为 A：多人共享信息项、传播链、重复误信内容，还是查询量达到阈值。
6. `dark_draft` 是否采用 A，进入 C4／作者 Canon 正式准入并获得 F 号或等价稳定身份。
7. 哪些暗稿可批量签，哪些必须单签；“影响后文”与“高影响”的具体门槛。
8. 规划侧是否只保留成文覆盖状态，并引用正式事实，而不再单独裁决“已发生”。
9. 读者承诺是否采用 A-lite；允许的来源是否限定为书名、简介、标签、作者公告、明确书稿陈述。
10. A-lite 的生命周期是否需要“生效／兑现／改口／撤回”，以及改口如何留历史。
11. 稀章是否把 A 写入总家规；B 的连续零异常探针用哪些本地 Gold 数据定阈值。
12. VOL 是否增加可选 `storyline_refs`。
13. 是否需要 `milestone_refs`；若需要，先拍里程对象的 owner、身份和 writer，不能先造空字段。
14. `VOL-` writer、长线读取面、`DESTINY-` writer、`INS-` writer 的施工先后顺序。

**本稿没有移动任何一行的 ✅🟡❌；B／A／A／A 只是候选建议，不是拍板或合同修订。**
