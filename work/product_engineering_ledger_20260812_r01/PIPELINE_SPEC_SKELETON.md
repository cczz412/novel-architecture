# 抽取管线规格骨架（v0.1，留白格子标了由谁来填）

这页回答「一章正文进来，到变成可信的事实账，中间经过哪几站、每站颗粒度多少」。骨架是当前实验设计里已经冻结的形状；打【待填】的格子不许现在编，等对应实验收口。

## 主流程：正文 → 事实账

```text
① 正文分块 → ② 主抽取 → ③ 验真 → ④ 补漏 → ⑤ 程序合并 → ⑥ 作者确认 → ⑦ 入账
        （③④⑤ 是否全要，由 P0/P1/P2 对照决定）
```

### ① 正文分块

- 输入：一章正文（冻结书稿版本）。
- 规则：完整自然责任段优先，单事件完整性 > 字数；每块 620–923 去空白字符（判别材料另一口径：硬 450–1000／推荐 600–800／目标 760）；章首尾允许自然短块；拟声词、短语气词并入相邻块。
- 输出：责任块序列，每块配每侧最多 H180 只读背景（halo）。halo 只帮理解，不得产出正分事实（E-07 教训）。
- 状态：**规则敲定**。

### ② 主抽取

- 输入：单个责任块＋halo＋Prompt（当前冠军结构：OUT2-IDLIST 输出、极简规则、不放示例）。
- 输出：该块的事实句候选列表（原子句，一句一命题）。
- 颗粒度锚点：整章约 100–150 个剧情原子（CZ 设计口径）；DEV 卷实测每章 Gold 30 条上下（REQUIRED 为主）——两个数不矛盾，前者是全量原子，后者是「不能安全遗忘」的必抽子集。分界怎么画＝【待填：N16 语义合同＋首个真实项目校准】。
- 用哪个模型：【待填：DISCRIM17 候选 → A/B/C → 管线关】。
- 状态：结构暂定，模型实验中。

### ③ 验真（是否保留待定）

- 设想：独立模型逐条核对主抽结果，只答「这条在正文里站得住吗」，不产新事实。
- 【待填：验真器设计=外调三题之一；P1/P2 预注册时冻结】。

### ④ 补漏（是否保留待定）

- 设想：高召回模型盲抽一遍（不看主抽结果），专捞主抽漏掉的；与主抽岗位可用不同强度模型。
- 【待填：P2 对照结果】。

### ⑤ 程序合并

- 设想：主抽＋补漏结果去重合并、冲突标记，纯程序不用模型。
- 【待填：合并规则随 P2 预注册冻结】。

### ⑥ 作者确认

- 口径（R07 已拍语义方向）：确认差异，不填 Wiki；批量确认＋重签清单；入账只有两条路——书稿证据承托或作者显式签字。
- 首版验收链（N19-A）：真实项目提问 → 系统回原文取证 → 作者确认 → 状态安全更新 → 下次继续用。
- 界面颗粒度：【待填：首版产品试验】。

### ⑦ 入账

- 表结构：【待填：N16 表述/命题四层拆分定案前不建表】。
- 已定语义约束（R07）：表述事件≠世界命题（「张三说城主死了」只证明张三说过）；作者签字带 `AUTHOR_ATTESTATION` 七要素；unknown 拆六种；章版本=不可变权威版本，场景/段落=章内锚点。

## 消费侧（账建好之后谁来用）

| 消费场景 | 形状 | 状态 |
|---|---|---|
| 续写辅助 | 按当前问题取证→带相关设定入上下文→提案 | 方向已批（R07），无施工票 |
| 一致性检查 | 告警三轴＋覆盖回执＋红灯=不能静默关章 | 语义方向已拍（N20） |
| 规划映射 | 规划槽位序列↔实际章节序列，偏差事件（拉伸/压缩/插入）才触发询问 | 语义方向已拍（N19-B） |
| 视频投影 | 场景连续性包＋镜头/资产绑定包；约束不保证服从 | 方向已批（N07-B），留投影合同 |
| 外部 agent（MCP/CLI） | 只能提交修改提案禁直写；AUTHOR Canon 默认拒读 | 方向已批（N05-A/B） |

## 全链质量与成本护栏

- 质量：候选须过 A 产品线（E-11）；每站单独记 task/attempt 双账；失败进端到端分不得吞掉。
- 成本形状：主抽用中强模型、验真补漏可用弱模型、合并零成本——全管线控制在 3~5 个模型（CZ 口径）。具体每站单价【待填：A/B/C 与管线关的费用账】。
