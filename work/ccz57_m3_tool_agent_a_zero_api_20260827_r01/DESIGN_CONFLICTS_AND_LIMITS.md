# 与回包设计的冲突和保留项

## 以 #176 和现行合同为准的地方

- 回包里更完整的诊断、Patch、版本树、停止控制器属于 B；本包没有提前实现。
- C3 `quote` 按现行合同保留为可选字段。非空时，本包只做责任段内逐字存在检查；这不等于语义证据已被证明。
- C3 不增加 `status`、`speaker`、客户端条目编号、诊断或因果提示。
- A 阶段不创建持久关系候选。正式因果边必须等 M4 分配 `f...` 事实编号后，再走现役 `FACT_CAUSAL_EDGE` writer。
- OpenRouter 和 Ark 的供应商字段只按合成夹具验证；没有真实端点预检，不能宣布供应商兼容。
- 运行身份必须把模型、上游、思考档、配置和实际供应商工具载荷 SHA 冻结下来；native 与旧 `content` 两条路线都要从已保存的请求 body 反查这些值。供应商是否如实执行思考档和配置，仍只能由 C 阶段真实回执证明。
- 原始请求 body、回包、运行身份和机械错误码属于小说辅助产品内部排障证据，不是作者工作台。A 不保存完整 HTTP headers、API key、Cookie 或授权值，也不设计用户支持包上传。
- 请求身份失败统一留下父级原因 `REQUEST_IDENTITY_MISMATCH`，供应商外壳失败统一留下父级原因 `PROVIDER_ENVELOPE_REJECTED`；精确错误继续放在 `code` 中供内部诊断和反例测试使用。A 只建立这层机械映射，不在这里设计作者界面的文案。

## 仍然保留的风险

- Ark Responses 的真实回包字段可能与合成形状存在差异，必须留给 C 阶段精确端点预检。
- OpenRouter 上游 provider 的精确身份字段是否总在响应内返回，尚未经过真实 API 证明。
- 当前 evidence 门只证明非空 quote 出现在责任段，不判断事实句是否被 quote 支持。
- 普通正文连续两次不选工具后的提醒与停止属于 Agent 循环，不在 A 阶段执行。
- 非思考／低思考／高思考的动态路由属于后续实验。A 只冻结单个 run 的思考档；任何升档都必须以新运行留下独立原件和身份回执，不能覆盖 baseline。
- 本包不接现役 runtime，不写 C3、不写 M4，也不验证真实恢复续接。
- A 还不是完整运行日志合同：没有真实延迟、费用、缓存、循环次数和恢复链。后续应把内部排障账、作者可见的简明状态、用户明确授权的支持包分开设计，不能把工程日志整包交给作者。
