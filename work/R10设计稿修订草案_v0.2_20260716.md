## 修订一：T2 九类对象表改行（依 D-T2-001）

原：

| future_obligations（Hook） | 编排 | 记上不抽 |

改为三行：

| 对象 | 产出方 | 提取时 |
| --- | --- | --- |
| hook_occurrence（已发生钩子事实：正文里已挂出的悬念/威胁/承诺/倒计时） | 提取 | 可抽，带证据锚 |
| candidate_obligation（候选读者债） | 提取 | 可抽**不排期**；未经作者/规则确认不进 active、不直接影响生成 |
| scheduled_obligation（排期义务） | 编排 | 只归编排侧，提取侧无权产生 |

配套硬闸（随行纪律，不另立对象）：

- 入账门槛：跨章存在＋不回应读者会明显失望 → 才进长期债；普通章末转场悬念只留体验合同（防 Hook 账爆炸）。
- 防上帝视角：候选债须标 observable_at_chapter_end / confirmed_later；后知信息不得倒灌成本章义务。
- 类型分层：hard_deadline ≠ risk_watch；overdue_unresolved 等异常态不得静默续写。

## 修订二：Hook 语义定稿（依 D-HOOK-002，写进 §三编排侧）

- **Hook＝故事内触发器**：锚定故事内事件/故事内时间/条件（例："有人携X进副本→必触发Y""故事内5天后发生Z"），**不锚章节号**。
- 触发后行为：系统记账＋提醒作者；**不强制本章落地，也不允许遗忘**——触发未处理＝挂账态，编排时必须能看到"这个触发器后面跟着什么"。
- 与章末悬念钩子（turn_hook，吊读者胃口）分账不混，维持已拍四分（promise/obligation/payoff/turn_hook）。
- 明确否决：外部方案"触发即强制写入下一章 intent、下游必须落地"不采纳。
- 备查候补（未拍，等 Hook 冲突七序必答题）：连续 3/5 个"有机会处理章"未触达 → 黄灯/红灯提醒。

## 修订三：T7 体验合同改制（依 D-T7-001）

- 七项原七项**降格为控制页**（总览用），不再是填表模板。
- 合同本体改**稀疏合同**：硬约束 / 软偏好 / 控制 三组；**空值合法**，只填本章真要卡死的三五件事，详情靠 ID 引用（beat_spine_ref / reveal_policy_ref / canonical_moments / forbidden_shortcuts 等）。
- **版本化留痕可回放**：每张合同存档带 contract_version＋read_set_revision（"当时读了哪版账、为何生成这份合同"可复现）；本体/Hook/规划/合同共用同一版本封套，防各层各自改版出"鬼合同"。
- 增设**弧线级附合同**（3～10 章滚动窗口）：管疲劳、套路重复、长线兑现节奏；章合同为子、弧线合同为父，**父子继承，改编重分配时 must_preserve 硬锁不得丢**。
- scope 支持 章 / 集 / 互动段。
- 工作方式：机器拟稿，作者只确认少量要点（目标：确认成本＜1 分钟）。
- 验收尺：留存/七日保留采纳/套路重复率/新鲜感，**不得只看结构完整率**。

## 修订四：T1 薄切片锚位（依 D-T1-002＋D-TIME-001）

中间层维持厚描三件套为唯一真账，但"薄切片全部派生不入账"改为：

- 本体增设**薄引用位**：canonical_moment（名场面/关键帧锚，每章高优先级 1～3 个，防变成压缩正文）、branch 锚（互动分支点）、end_frame_lock（章末画面锁）。
- 分寸：本体只存**锚点 ID＋位置＋一句语义**；画面细节、镜头语义、造型资产一律留适配层/改编分账，**不进固定核心**。
- 互动加硬：变化流/状态/Hook/合同凡涉互动，须带 branch_id，防分支串账。
- **故事内时间轴为一等公民**（CZ 口径）：大纲可按 story_time 排布/编辑；事件先后因果可视；视觉锚挂时间轴上，编辑锚点时可查前后剧情；支持按时间段搜索（一件事的连贯片段内找锚）。底层沿用 story_time＋narration_order 双时间戳，此条升格为工作台硬需求。

## 修订六：T1 三件套定权＋阅读节拍（依 D-T1-003，改判②，10:12 拍）

- **定权**：章内变化流＝唯一权威原始账；章末快照＝可重建缓存，只许从变化流重算、不许手改；章间交接只向前传递、不改历史。
- **有序 reading_beats**：章内变化流带节拍序列——本章读者依次经历了哪几拍（看到什么、什么时候知道的）。
- **揭露闸**：哪条信息要到第几拍才准露出，生成侧不得提前泄底。
- 施工分寸：canonical_moment 视觉锚挂在节拍上（"第三拍是高光"），不另立重复账；reading_beats（读者知晓顺序）与 story_time（故事内实际顺序）两轴分立，倒叙/回忆靠两轴对照表达。

## 修订七：T11 建议层双轴（依 D-T11-001，改判④，10:29 拍）

- 秤拆双轴：**故事推进轴**（剧情走了多少）＋**读者情绪轴**。
- 读者情绪轴＝**AI 模拟真实读者情绪**，不依赖真实平台数据（多数作者没有回头导数据的场景；真实评论少且抽象难判）。铺垫章、蓄压章在情绪轴上得分，防"零推进→建议删"误杀。
- 建议好坏的成绩单：看**七日保留采纳**（采纳的改动一周后还留在稿里才算数），防 AI 靠嘴甜刷即时采纳。
- 平台追读等真实数据＝**可选一次性导入**，作为长线节奏监控台的一项可读参考：有则读、无则照常；监控台不必每次都看；只作参考不作裁决。
- 反馈落点＝长线节奏规划：已发表部分动不了 → 调后面（如加快节奏）。不设常态化"精确读者分析台"。

## 修订八：坐标系两维（依 D-COORD-001，改判⑥，10:29 拍）

- 事件加 **context_ref**：这事发生在哪条线/哪层现实/哪个副本/第几世。重生文的"第一世/第二世"直接摆在时间轴上表达，系统识别题材即可分清。
- story_time 支持**文字＋数字任意纪年**（虚构朝代第 N 年、副本内第几天等），不强求真实历法。
- 事实加 **assertion 性质栏**＋**known_by 知情栏**，规格从 NVM《IAM》移植改造（按 D-ADAPT-001 只搬逻辑不搬名词）：
  - assertion＝这条事实是什么性质：读者所见 / 角色推测 / 系统宣告；**真相和谣言分条记**，假死案例＝"他死了"只能是某些人的误信，不能记成事实。
  - known_by＝知情名单，每人带状态：知道 / 怀疑 / 误信 / 部分知道 / 特意标注的不知道；可挂群体（某势力都知道），群体不自动展开到每个成员；**名单外只代表没追踪，不代表不知道**。
  - 知情变化（谁哪章从怀疑变成知道）记进章内变化流，不另立账本。

## 修订九：AI 出方案两条道（依 D-T12-001，改判⑤，10:41 拍）

- **作者在场（创作方向题）**：默认 3～4 个方案＋打星；星级帮比较不替选；主方案完整、次推荐一句故事化描述、轻方向一句话，作者选中才围绕它补齐；作者可多选/延后/拒绝/从某步纠偏；禁止把创作方向题压成单方案。执行题（唯一合法动作）例外可单选项。
- **作者不在场（后台提取/程序性活）**：按置信度三档省 token——高＝直接单方案；中＝单方案＋自查一遍；低且影响大＝内部出两版对打，赢者才交付。
- 交付前统一过一道"清检查"：幻觉/离谱选项直接删。

## 修订十：签名三态＋标签 CD（依 D-SIG-001＋D-ADAPT-001，改判⑦，10:41 拍）

- 剧情手法两级标签：大类（打脸/误会/翻案/觉醒/日常…）＋二级（打脸→当众打脸/以弱胜强打脸…）。
- **CD 冷却（单位＝章）**：滑动窗口内同一手法用得越密，冷却越长（递增：第 2 次翻倍再翻倍）；解决手法类（翻手机/录音找证据）管最严；换场景换角色减半、明显变体再减。
- **事前过滤**：AI 推荐剧情手法时，冷却中的直接不进推荐列表、同组的降权；作者硬要用只软提醒，不硬拦。
- **签名三态**（新加的豁免开关）：
  - avoid＝无意识重复的套路 → 进 CD 正常轮换；
  - repeat＝人物招牌（出场必响的铜铃、标志性狠话）→ **永久豁免 CD**，防重复机制不得碰；
  - evolve＝演化重复（口头禅每次说但逐次升级）→ 允许出现，要求变体。

## 移植总纪律（依 D-ADAPT-001）

NVM 回收件只搬逻辑不搬名词：**"故事块"弃用，新版最小单位＝章**（CD 窗口、统计窗口按章数计）；NVMdiff、ESV、SB 等旧术语不进新稿；一切移植件翻译成本稿已有词汇。

## 修订五：权利真账新章（依 D-RIGHTS-001，新设 §一.5）

- 大纲对象加**授权状态字段**（rights passport：来源、license 类型、可改编范围、可互动、AI 标识要求、平台约束）。
- 提取流水线**第一步**＝source_rights_gate：自有 / 授权 / 仅摘录 三分流；**无授权状态的大纲不准进生产下游**。
- 默认硬件：导入默认不进训练、不跨用户复用；语料授权单独、明示、可撤回。
- 落点对齐：运行侧 rights_and_labels（V04 方案）与对象级字段是一本账两视图，字段级设计时合并定稿，不做两本权利账。
- 产品三档（候选，随改判⑪细化）：私有分析档 / 作者草稿档 / 授权生产档。
