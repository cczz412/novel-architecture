# C 视角方法诊断
执行身份：Codex

能确定的主因是提示把“看不出固定人物”与“全知”混在一起，而且没有把第一人称的“我”落到名字的明确要求。输入只带本章正文，遇到叙述者在别章才报过名字的情况，模型确实缺材料。代码证据能说明这些风险，但不能据此分摊 24.5% 的错误，更不能证明换提示就会降到 5.5%。

本轮真源是起点提交 66e5232 的生产代码、纯文字 C 提示和请求构造函数。任务书的三类错是诊断线索，没有读取真书逐条结果。若不改，C 会继续把材料不足当成全知的候选，并把没有名字的第一人称标签交给作者核对。

## 1. 定义与取值

视角字段用来回答“叙述贴着谁的感知”，机器名是 `viewpoint`。当前生产提示要求人物名或全知，但校验程序没有检查这个字段的值、类型或是否缺失。因此“第一人称”“未定”、任意名字甚至缺值都可能穿过结构校验。依据：`tools/pipeline_records25.py:53` 到段级校验结束只检查段号、写法标签和逐字短引；`tools/pipeline_author25.py:193` 明确接纳全知、第一人称、未定等值。

人物视角和全知只靠一句话区分，没有写出“第三人称也可以始终贴着一个人物”，也没有要求证明叙述者知道某个人物不可能知道的事。没有明确要求第一人称必须回答“我是谁”，更没有说明找不到名字时怎么办。三类错都能由这些空白诱发；这是风险判断，不是逐例归因。

## 2. 生产提示

生产提示原文：

> viewpoint 是本段透过谁的感知来叙述，写人物名，没有固定人物写全知

位置：`tools/pipeline_text105.py:218`。请求构造位置：同文件 `225–229`。这里按段提问，却用“没有固定人物”作兜底。一个外景段没写人的心理，不代表整章或整本全知；前一句贴着某个人物，下一句写门窗，也不等于切换视角。

旧提示文件还有一句：

> 视角跟随感知者而不是说话人；不能每段重新默认为全知。没有切换依据时沿用当前镜头。

位置：`tools/pipeline_prompts25.py:64`。这句话没有进入当前纯文字 C 请求。不能把旧提示里的好约束当成生产已经在用。

## 3. 输入

生产 C 只收到段号和本章正文，机器结构是 `paragraphs: [[段号, 正文], ...]`。没有 B 事实、J2 人物账本、上一章原文、上章 C 判断或全书叙述方式。即使整线先做过 B、J2、A，C 仍只调用本章材料。依据：`tools/pipeline_text105.py:225–229`、`862–909`。

整章回包坏掉时，C 还会把本章一分为二，各自再问一次；这时同章另一半也看不到。依据：同文件 `245–256`。这会加重名字在另一段、镜头延续跨半章时的信息缺失。

如果“我”的名字就在本章清楚写出，模型有机会找到；如果只有别章报过名，本章只有“我”，当前请求确实拿不到。人物出现最多、台词最多都不能证明是叙述者。

当前 C 读取本章正文，能够输出段级写法、视角候选和场景卡。小说辅助产品还缺少跨章叙述者候选的生成和传递能力，也没有全书叙述方式的长期保存和版本判断能力。这会卡住作者按叙述者查看场景，以及判断换章后是否换了视角。

## 4. 单章判断的边界

单章有明确的感知限制、第一人称自述或跨人物内心信息时，人也有可用证据。只有动作和环境、全知叙述者暂时贴着一个人、名字只在前章出现、书中嵌套了信件或回忆自述时，单章未必能唯一判断。单段限制更大。

“换了感知人物”也不必然等于全知：多个人物轮流各占一章，可以仍是有限人物视角。反过来，只写一个人的一小段，也不能证明整本是有限视角。因此不建议把全书标签强压到每段；书级材料最多作可推翻的参考。

这部分是方法边界分析。未读真书，也未做真实模型实验，不能宣称已经证实单章方法必然失效。

## 5. 程序与作者视图

生产 C 对每个视角都挂待核黄卡，字段是 `viewpoint_status` 和 `viewpoint_card_color`。它不检查视角的语义，也不把这些视角算成程序已核。依据：`tools/pipeline_text105.py:281–287`。

作者视图的降级条件在 `tools/pipeline_author25.py:191–199`。纯文字 C 通过方法标记直接豁免人物账本依赖，所以目前不会因 J2 没完成而把生产 C 的正确人物名改成未定；也不会替生产 C 修正错的全知或错的人名。旧路径在名字不在本段叙述且 J2 未完成时，会降为“未定（人物账本未完成）”，可能遮住跨章才能确认的正确名字。它保留原名，并不把名字改成全知。

作者视图把黄卡带下去，因此“表里能看到”不代表“程序证明正确”。问题主要发生在模型判断和输入定义，不是作者视图把整本人物视角批量改成全知。

## 排序与候选做法

主因候选：生产提示的判断边界太粗，且按段问却没有镜头延续规则。代码证据充分，但真实错误占比未知。

次因候选：输入缺跨章叙述者信息，第一人称名字缺失最直接受影响。单章不可辨识是方法上限。校验不核视角语义使错误候选继续展示；黄卡本来就没有承担语义修正职责。

候选 A：每本先判断一次叙述方式，输出带原文依据、允许局部切换的书级参考。可以同时针对三类错。预计每本额外 1 次请求；若要复核则再加 1 次。风险是首次误判污染全书，前几章不代表全书，用旧 C 标签投票还会放大旧错。离线可手写书级回包，检查后章偏离不被覆盖。本轮不做这个请求路径，因为还没有可靠书级证据来源和版本约定。

候选 B（本轮选择）：明确区分人物视角、全知、第一人称和材料不足；从正文中提取窄范围的自报姓名证据，作为叙述者候选传给 C，由模型确认或否认。前章证据只作参考，不把出现频率、代词密度或上章 C 判断变成书级结论。模型必须给视角依据；缺名、候选冲突或证据无效就保留未定。人物视角和全知主要靠新提示改善边界，第一人称另有程序候选帮助。每本额外请求 0 次，仍用原来每章 C 的请求和拆包机会。

选择 B 是因为改动能限在新模块和开关分支，默认请求可逐字节比较。风险是自报姓名证据覆盖很窄，嵌套叙述仍可能误认，不能把找到候选当成程序证明了叙述者。人造自测只证明数据传递、保守降级和黄卡保留，不能证明模型更会判断。
