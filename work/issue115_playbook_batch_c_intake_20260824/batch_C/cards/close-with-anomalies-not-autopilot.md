# 收口只合并异常，不替作者改剧情

身份：已拍加固

## 遇到什么

实现收工流程时，事实审查、计划对账、字数偏差、暗稿和欠账各弹一次；容量估算一超线就自动把场景搬到下一章，延期几次的事项则被系统悄悄降级或强制执行。

## 对的做法

**已拍：**散落的收工项合成一张“本章异常单”，一屏看完、一次签；它是合并弹窗，不是新增审批层。字数预估显示柔性区间，预警阈值不能小于模型固有误差；若建议把剧情搬到下一章，必须由作者确认。欠账连续延期可以用 `defer_count` 提升提醒显著度，但仍只是提醒，不能自动执行、作废或改写剧情归属。R14 写下的是这些语义边界，不等于异常单字段和界面已经实现。

**加固：**SI-007 P01 在候选流程里看到两轮全量审计、过窄字数阈值和欠账滚雪球风险。它支持“例外审查、柔性容量、欠账不隐身”，但报告里的五分钟、约一分钟、5%／30%及容量比例都不是产品合同。

## 错的做法

把异常单做成第五道批准门。没有异常也强制逐项复核。按预测字数自动搬剧情、删场或关章。延期后降低欠账优先级，或达到计数就强制兑现。把 P01 的数字和交互次序写成已拍。把本卡升级成执行票，或自行扩写 `defer_count` 的字段合同。
