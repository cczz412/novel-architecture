# 画布是交互投影，缓存只是加速层

身份：已拍加固

## 遇到什么

做 Web 画布时，后续 Agent 准备把完整人物、事实和章节数据分别复制到 React Flow、Zustand、Query 缓存和浏览器本地库；或把本地 SVG／画布缓存当成唯一保存位置，认为“画布是真身”就是“画布节点是真源”。

## 对的做法

**已拍：**人物、事实和章节留在领域数据层，画布是可以从它们重建的交互投影；“画布是真身”指它是主要交互中心，不是存储中心。本地缓存只负责加速，真源仍在服务端，并要按租户隔离、退出时清理。React Flow、TanStack Query、Zustand、CodeMirror 6 是当前设计基线，不是已经实现的能力；100～300 张完整卡同屏只是待测目标。

**加固：**SI-007 P08 的技术走查提醒，多套前端状态各持一份完整节点数据会产生同步和性能问题，浏览器缓存也不该成为唯一副本。这个外部技术意见与 R14 同向，但具体版本、库组合、缓存实现和压测矩阵仍由施工合同决定。

## 错的做法

把画布节点 JSON 当第二真源。React Flow、Zustand、Query 和本地库各维护一套可写领域数据。只保存在浏览器缓存，退出或清缓存后无法恢复。把“设计基线”写成已经上线。拿 100～300 或 1k／3k／5k 当实测结论。把本卡升级成执行票，或把 P08 的版本号和技术组合写成永久合同。
