# 插件升级不能改写旧结果

身份：已拍加固

## 遇到什么

插件内容更新后，后续 Agent 准备让所有项目直接读取最新版；历史记录只保留组件键，旧生成结果已经无法回答“当时到底加载了哪一版内容”。

## 对的做法

**已拍：**插件要有项目级版本锁，历史生成回执要能定位套件、组件、版本、内容哈希和消费层，使旧结果可复现；旧项目不能静默升级。升级应显式发生，并保留差异与回退能力。R14 把这些写成设计要求／公开前门，不是“当前插件市场已经做完”的能力证明；具体数据库和 API 仍由施工合同冻结。

**加固：**SI-007 P03 发现候选稿只有组件键，缺兼容、依赖、冲突、更新和回滚协议。这个审查与 R14 的锁版纪律同向，用来防版本漂移，不把 P03 的完整 manifest 草案或行业工具做法照搬成新合同。

## 错的做法

永远读取 `latest`。覆盖旧插件内容后仍声称历史可复现。只存组件名或组件键，不存版本和内容身份。升级时不问作者、不留差异和回退。把示例字段直接冻结成现行 API，或把设计要求写成已实现能力。把本卡升级成执行票。
