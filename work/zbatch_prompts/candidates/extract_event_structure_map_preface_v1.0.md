# Z00l 中性事件提取 Prompt v1.0

你只看当前一章，不得使用本章之后的知识。

【C 臂前置块｜产品结构地图】

这条产品链分成四个组件：原文与冻结证据目录负责提供可引用材料；当前中性事件提取只负责找出本章可供后续读取的原子事件并绑定证据 ID；下一阶段主控负责判断 A／B／C／D 等结构类型；更后面的程序负责核锚、跨章拼接、因果与状态关系整理。各组件各守一段，不互相代做。

所以你在当前步骤只聚焦“本章发生了什么、说定了什么、留下了什么待回答事项、明确了什么可重复机制”。不要提前分类，不要推断跨章关系，不要写状态表、因果图或产品总览，也不要替后续步骤下结论。

下方“冻结证据目录”按原文顺序覆盖当前章全文，短引之间有少量重叠。你的工作只有一件事：找出以后可能被继续读取的**原子事件**，并为每条选择真正支持它的证据 ID。程序会把 ID 确定性展开成章号＋10～25 字连续原文短引。

不要判断事件属于哪一种结构类型，不要输出 A／B／C／D，不要输出状态、事实等级、关联编号或类型专属字段。分类由下一阶段主控统一处理。

找事件时依次检查：已经发生的变化、正文说出口的后续安排、正文公开留下的待回答事项、正文明确说明的可重复机制。这里只做清点，不贴标签。

每条必须满足：

- 一条只写一个事实头，不把同一场景的多件事捆成一句。
- `event` 只写正文在本章支持的中性事实，不写“这是承诺／规则／触发器”等分类判断。
- `anchors` 只交冻结目录里的 `anchor_id`；一条可选多个 ID，但每个都必须真正支持该事件。
- 宁可保留有锚的边界事件，也不能为了让结果干净而漏掉真实变化或明确安排。
- 普通动作、气氛描写、无后续读取价值的场景复述不凑数。
- 事件 ID 必须按原文顺序从 `EV-C{{CHAPTER_PADDED}}-01` 连续编号。

只输出一个 JSON 对象，不要代码围栏，不要解释：

```json
{
  "schema_version": "z-event-v1",
  "chapter": {{CHAPTER_NUMBER}},
  "events": [
    {
      "event_id": "EV-C{{CHAPTER_PADDED}}-01",
      "event": "本章明确发生或说出口的一件中性事实",
      "anchors": [{"anchor_id": "E0001"}]
    }
  ]
}
```

当前章号：`{{CHAPTER_NUMBER}}`

当前章文件名：`{{CHAPTER_FILENAME}}`

冻结证据目录：

```json
{{EVIDENCE_CATALOG_JSON}}
```
