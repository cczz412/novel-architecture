# 主控分类规则 v1.2

## 用途

本规则只处理 `z-event-v1` 中性事件。弱模型没有分类权；主控逐事件登记命中类型、唯一主类型、规则编号和简短依据，程序负责验收决定、编译记录、生成重复／冲突账并核锚。

程序**不自动理解小说语义**。它只能把主控已经作出的语义决定变成可重复验收的工件，不能把“合同通过”说成“自动分类正确”。

v1.2 相对 v1.1 只收四项拍板：四类兜底审计、延迟复发双收、查尼斯门 A 类后备、跨章立即执行归 B。其余分类边界沿用 v1.1。

## 四类最低边界

- `A-01` 已发生变化：人物、组织、物件、调查、认知或故事线已经从前态进入后态，后文可能读取。普通场景动作、没有变化结果的复述不算。
- `B-01` 待触发动作：故事内某事件、时间或条件尚未到达；到达后仍有明确动作需要执行。已经完成的动作不能算 B。
- `C-01` 公开期待：正文已经让读者等待一个答案、揭示或兑现。普通未知、人物私下猜测、没有公开吊起的背景空白不能算 C。
- `D-01` 可复用规律：正文明确支持一个跨个案可重复适用的“条件—结果”关系，并能说清适用范围。
- `D-02` D 类排除：人物宣言、政策预测、一次性警告、单次观察、传闻、猜测和只对当前场景成立的处置不得直接标 D。**本编号只排除 D，不能单凭它把整条事件擦掉。**同一中性事件若另有独立、可复用的规律主体，可以保留 D 并同时带 `D-02`，但 `conflict_reason` 必须明确写出被排除的句中成分；空写即拒绝。
- `D-03` 单次观察降级动作：单次测量或一次性样本若形成新认知，归 A／推；没有独立变化则不成记录。该编号只标单次观察，不替代 `D-02` 对句中其他错误成分的排除。

## v1.2 四项补强

### 1. 四类兜底审计

- `MC-08` 四类兜底审计：任何 `unclassified` 或 `discarded` 决定，都必须在 `type_audit` 里逐项写清为什么不收 A、B、C、D；四项缺一即整份决定拒绝。
- `D-02` 只回答“为什么不是 D”。含 `D-02` 的未分类项还必须另带 `EVIDENCE-BOUNDARY`；含 `D-02` 的丢弃项还必须另带 `MC-07`。不得用 `D-02` 代替 A／B／C 排查或最终处置依据。
- 已分类 D 若同时带 `D-02`，必须在 `conflict_reason` 写清“保留哪段规律、排除哪段传闻／宣言／外推”；程序不得只看规则编号就放行。
- `type_audit` 是程序可核验的审计账，不是新的语义分类器。程序只检查四项齐全和理由不为空，不替主控判断理由是否正确。

### 2. 延迟复发双收

- `D-04` 概率限定的述源规律：正文由角色明确讲述“事情看似结束后，有时仍可能再次降临”时，可收 D；`source_level` 必须标 `述`，`scope_mode` 必须标 `probabilistic`，范围说明必须保留“有时／可能”，不得升成必然铁律。
- `C-02` 本人风险未结：正文已让读者等待“克莱恩自身风险是否能彻底解除”的答案时，可另用独立事件收 C。不得把同一个 `event_id` 复制成 C＋D 两条决定。
- D 收世界层的概率规律，C 收人物层的未结风险；两者事实头不同才允许双收。

### 3. 查尼斯门 A 类后备

- `A-02` 局部禁忌获知：一次性警告不能直接升 D，但人物已经获知“靠近某处会触发何种风险”的局部禁忌时，可收 A，`source_level` 标 `述`。决定必须同时带 `D-02`，明确这是“排除 D、保留 A”，不是把警告改写成世界铁律。

### 4. 跨章立即执行归 B

- `B-02` 跨章立即承接：本章已经接受一项尚未执行的明确安排，下一章立即进入执行时，收 B。它不因章末位置被硬归 C，也不得当普通场景动作丢弃。

## 主类型归属

1. 先写 `matched_types`：记录这条事件按字面可能碰到哪些类型，不能为了结果好看删掉冲突。
2. 再选一个 `primary_type`：按事件的事实头归属，只生成一条主记录。
3. 已经发生的具体变化以 A 为主；句中附带的未来影响不能另复制一条 C。
4. 尚待执行的明确安排以 B 为主；同一安排带来的读者等待不另复制一条 C。
5. 只有“答案／揭示／兑现”本身是事实头，且没有更具体的待执行动作时，才以 C 为主。
6. 只有可复用关系本身是事实头时，才以 D 为主；单次发生的结果仍归 A。
7. 无法唯一归类时必须标 `unclassified`，并登记 `EVIDENCE-BOUNDARY`；无跨章读取价值的场景事件标 `discarded`，规则编号必须含 `MC-07`。两种都必须带 `MC-08` 和完整 `type_audit`，不能静默删除。

## 重复裁决

- 同一事实头被拆成多条时，全部成员必须写同一个 `duplicate_group`。每组只准保留一条 `classified` 代表，其余成员用 `MC-07` 丢弃；每条都保留不少于 8 个非空白字符的冲突说明。
- “已经识别出机制”与“当场承诺按该机制执行”若没有两份独立的跨章义务，保留已发生的认知／状态变化 A，丢弃重复的条件承诺。不能复制成 A＋B。
- “接受一个长期安排”与“给出同一安排的具体时间和动作”若指向同一未来事项，保留信息更具体、仍待执行的 B 排期，丢弃泛化的接受事件。不能复制成 A＋B。
- 共用短引、共用证据 ID 只触发诊断，不自动等于语义重复；仍须看事实头是否相同。

## 单次观察降级

- 单次测量、单次观察或一次性样本即使长得像“条件—结果”，也不得升 D。
- 它若让人物从“不知道”变成“形成暂时判断”，用 `D-03` 保留为 A，`assertion` 必须是 `推`，并在冲突说明里写清“仍待再次验证”。
- 它若没有形成独立变化，则标 `unclassified` 或 `discarded`，并完成四类兜底审计，不为了凑 A 留账。

## 冲突与关联

- `matched_types` 多于一个时，`conflict_reason` 必须说明为何只留当前主类型。
- 跨类型重复闸看原始事件、重复组和分类冲突账，不得只看编译后 A/B/C/D 是否互斥。
- `related_event_ids` 只允许引用同章且最终成记录的事件；程序换成正式记录 ID。

## 事实等级与来源等级

- `assertion=明`：短引直接支持主控写出的事实头和类型关系。
- `assertion=推`：事实发生有锚，但未来用途或类型关系需要有限推断。
- `assertion=存疑`：证据边界不足，仍保留供审查；不能写成明示事实。
- `source_level=述`：规则或局部禁忌来自角色明确讲述。它与 `assertion` 是两根轴，不能拿“述”替代“明／推／存疑”。
- `scope_mode=probabilistic`：只表示概率性适用，不得被下游改写成必然关系。

允许的规则编号只有：`A-01`、`A-02`、`B-01`、`B-02`、`C-01`、`C-02`、`D-01`、`D-02`、`D-03`、`D-04`、`MC-07`、`MC-08`、`EVIDENCE-BOUNDARY`、`主类型-3`、`主类型-4`。成记录的 A/B/C/D 必须分别带自己的基础编号；拼错或自造编号整条拒绝。

## 主控决定合同

每个中性事件必须恰有一条决定，字段固定如下：

```json
{
  "event_id": "EV-C0006-01",
  "disposition": "classified|unclassified|discarded",
  "matched_types": ["A"],
  "primary_type": "A",
  "rule_ids": ["A-01"],
  "basis": "短句说明事实头和归属理由",
  "assertion": "明|推|存疑",
  "source_level": null,
  "scope_mode": null,
  "type_audit": {},
  "fields": {},
  "related_event_ids": [],
  "duplicate_group": null,
  "conflict_reason": ""
}
```

分类成功时 `type_audit={}`。未分类或丢弃时：`matched_types=[]`、`primary_type=null`、`assertion=null`、`source_level=null`、`scope_mode=null`、`fields={}`、`related_event_ids=[]`，并且 `type_audit` 必须恰有 A／B／C／D 四个键，每个理由不少于 8 个非空白字符。任何重叠命中、重复组，或“主类型 D 且规则含 D-02”的决定，都必须写不少于 8 个非空白字符的冲突说明。
