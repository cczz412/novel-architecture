# 第37道 B 臂｜程序点名靶 Prompt v1.2

你只看当前一章，不得使用本章之后的知识。

下方“冻结证据目录”按原文顺序覆盖当前章全文，短引之间有少量重叠。你的工作只有一件事：找出以后可能被继续读取的**原子事件**，并为每条选择真正支持它的证据 ID。程序会把 ID 确定性展开成章号＋10～25 字连续原文短引。

不要判断事件属于哪一种结构类型，不要输出 A／B／C／D，不要输出状态、事实等级、关联编号或类型专属字段。分类由下一阶段主控统一处理。

找事件时依次检查：已经发生的变化、正文说出口的后续安排、正文公开留下的待回答事项、正文明确说明的可重复机制。这里只做清点，不贴标签。

【B 臂固定任务｜程序点名段】

- 程序会在冻结目录之后列出 Z00x4 机械诊断找到的候选段。候选段只是待复核清单，不代表已经确认存在独立事件。
- 你必须按候选段编号逐段检查：有以后会继续读取的原子事件就正常输出；没有就不要凑数。
- 输出仍只用原来的 `z-event-v1` 三字段合同，不增加候选段状态字段。程序会另外登记每段本次是否关联到输出事件，不把“模型未返回”冒充成语义裁决。
- 点名段不扩大证据权限；事件仍只能引用下方冻结目录里的 ID。

每条必须满足：

- 一条只写一个事实头，不把同一场景的多件事捆成一句。
- `event` 只写正文在本章支持的中性事实，不写“这是承诺／规则／触发器”等分类判断。
- `anchors` 只交冻结目录里的 `anchor_id`；一条可选多个 ID，但每个都必须真正支持该事件。
- 宁可保留有锚的边界事件，也不能为了让结果干净而漏掉真实变化或明确安排。
- 普通动作、气氛描写、无后续读取价值的场景复述不凑数。
- 事件 ID 必须按原文顺序从 `EV-C{{CHAPTER_PADDED}}-01` 连续编号。
