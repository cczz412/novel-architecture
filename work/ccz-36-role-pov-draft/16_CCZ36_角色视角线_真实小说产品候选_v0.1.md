# CCZ-36｜角色视角线真实小说产品候选 v0.1

这是一份等 CZ 验收的本地产品候选，状态是 `PRODUCT_CANDIDATE__NOT_RUNTIME__NOT_CONTRACT`。它把两份真实小说实样收成一条可做低保真演示的路线，不修改正式人物账、知情账、事实账或规划账。

## 结论

角色视角线可以直接理解成：**把作者已经写过或规划好的这一段，换到某个角色当时的位置重新看一遍。**

小说辅助产品不把“先填一张谁知道什么的表”当开工条件。它先读现有大纲、事实、人物状态、关系、抉择和证据，给出一句能听懂的判断：

> 他为什么会这么做，目前说得通；

或者：

> 这一步像是用了他还拿不到的信息，我把证据给你看；

或者：

> 现在材料不够，我只能看出这里可能有问题，不能替你判。

推荐下一轮先做的候选形状是：**个人时间线＋同场换人看＋分级提醒。** 这是两份真实小说材料共同支持的试验路线，不是已经冻结的界面合同。

## 推荐测试的作者动线

### 入口

作者在章纲、场景或已经写完的剧情段落上点“换到他的角度看”，再选一个角色。

聊天框也能直接说：

> 帮我站在墨兰这边看第 24～25 章，她听懂了什么，后面的做法有没有前后打架？

小说辅助产品不先弹人物表，也不要求作者补齐所有字段。材料薄就先按现有证据跑，缺的地方老实说看不出来。遇到材料空白、作者要纠正当前解释，或某个例外需要长期保留时，再请作者用一句话确认；怎样保存仍等正式知情接口拍定。

### 产品自己做的事

1. 锁定本次重放的章节、场景和当前版本；
2. 只读取这个角色在该时间点之前能回源的材料；
3. 按顺序还原他碰到了什么、理解成什么、正在保什么、实际怎么做；
4. 对照五个检查角度：是否合法可做、信息是否拿得到、是否服务当前目标、是否有因果解释、是否存在明显占优又同样可行的选择；
5. 把事实、候选解释和材料空白分开；
6. 用人话给作者结论、证据和推荐，不把内部字段甩给作者。

五个角度只用于检查，不在 CCZ-36 里冻结成机器字段、枚举或分数。

### 作者看到的内容

推荐先试一条按场景推进的个人时间线。每个节点按这个顺序说：

> 这里发生了什么 → 他当时理解成什么 → 他现在最想保住什么 → 他因此怎么做 → 有没有需要作者看的问题

作者点同一场戏，可以换另一个人物看。产品要展示的不是两张名字不同、内容相同的表，而是每个人实际的理解和选择差：

- 商人：听过规则，但仍相信是骗局，所以离开；
- 楚轩：亲手验证异常，再选择留下和搜集信息；
- 明兰：听懂拒亲信号，所以避嫌；
- 如兰：先没懂，后来被明确解释；
- 墨兰：收到隐蔽争取策略，完整门第理解仍未追踪；
- 王氏与林姨娘：知道障碍后，分别选择止损和冒险争取。

这套呈现是否比静态知识表更好、是否该做成默认首页，仍要让作者实际比较。

## 推荐测试的提醒方式

### 有充分证据时，主动拦一下

只有同时满足这些条件，才进入“硬提醒候选”：

- 相关事实或作者设定已经确认；
- 决策发生时间和信息取得时间能比较；
- 章节版本没有过期；
- 作者已经明确确认没有新的信息传递或例外，或者正式知情记录与完整检索覆盖能证明这一点；
- 行动确实依赖角色当时拿不到的信息，或撞上已确认规则。

只凭“当前材料没有查到传递记录”，还不能进入硬提醒。产品先说：

> 我能确认楚轩听过通用奖励机制，但当前这批材料没查到那段具体经历怎样传给他。这还不是硬冲突。要不要我继续往前回查？如果你能确认他确实没听过，我再按信息越界提醒。

只有作者确认“没有传过”，或正式记录与完整覆盖已经证明没有传递时，才可以说：

> 这里我得拦一下：他正在使用一条当时拿不到的具体信息。更推荐补一个传递动作；另一条路是把这句改成他的猜测。

### 有解释、但显得薄时，报剧情机会

行为有误信、目标或处境作解释时，不报“错”。产品可以给三个修法方向：

- 补动作：让角色做出符合其处境的反应；
- 补理由：把作者脑中的动机露一点；
- 补传递：让角色真的获得后面要使用的信息。

作者听到的应该是：

> 两名商人把现场当成电影骗局，所以离开至少说得通。现在看不出他们有没有注意到药品验证。如果看到了，可以补一句为什么仍不信；也可以补一句为什么他们觉得留下更危险。

### 材料不够时，直接说看不出来

不能把“没记录”改写成“明确不知道”，也不能把合理推测冒充角色内心。

作者听到的应该是：

> 我能确认墨兰知道被父亲发现会受罚，也收到“做得隐蔽”的策略；但现有材料看不出林姨娘有没有把完整门第判断告诉她。这里先别判她懂或不懂。

## 产品主动，但不抢作者的方向盘

产品可以主动读、主动发现、主动解释、主动给推荐。作者不需要先提出专业问题，也不用先填表；碰到材料空白、解释有误或需要长期保留的例外时，作者仍保留一句话确认、纠正和补充的权利。

只有会改变剧情方向的地方，才把选择交给作者。例如：

> 这一步有两种修法。我更推荐补一段信息传递，这样后面的行动不用改；另一条是把这句改成角色自己的怀疑，代价是确定性会下降。你想保留哪一种意图？

作者说“这是故意的”时，产品可以追问一句是否要留下候选解释，但不能自动把隐藏动机写成事实，也不能因为作者点过一次就永久压掉所有相似提醒。

## 版本和证据怎么守

- 每次重放都要绑定章节当前版本；正文或章纲改过以后，旧重放结果标成过期，重新计算。
- 每条判断都要能回到事实号、章节位置或作者设定来源。
- 较早大纲和本机 CCZ-103 落位只能做本地候选证据，不能冒充 GitHub 正式账本。
- 只有确认事实能承重；不确定、待入位和无处可放仍保持候选身份。
- 角色视角结果是只读报告，不是第二本人物账，也不能反写事实账。
- 如果后续验证确实需要复用，可以测试把带版本和证据的只读结果交给大纲体检、分镜或其他读取面；无论走哪种方式，下游都不能反过来改故事真值。当前还没有冻结统一中间报告或传递接口。

## 不能在 CCZ-36 里偷着拍的东西

- 不冻结知情边的正式字段、枚举、存放位置或写入方；
- 不给人物账增加 `knowledge_edges` 之类未批准字段；
- 不创建“角色视角账”或“跑动回放账”；
- 不把本地七本材料、CCZ-103 本机件或较早七类整理升级成正式真值；
- 不把创意自动跑和沉浸冒险提前并入 V1；
- 不把五个检查角度做成分数后自动判作者对错；
- 不把心理标签单独当成行为硬约束；
- 不写 runtime，不提交小说材料，不外发正文、Gold 或私人笔记。

当前 GitHub 正式人物账 v1.1 还没有冻结知情边对象；本地评测材料又有知情边候选形状。这个冲突不由 CCZ-36 选边。这里先把“产品怎样读、怎样解释、怎样提醒”做成只读候选，等正式知情接口拍定后再接。

## 验收条件候选

后续若进入产品验证，可以按下面几条验：

1. 至少完成两种不同题材的真实小说人工材料复盘，不只讲虚构例子；
2. 能按角色和时间点给出个人线，并回指证据；
3. 能区分听见、理解、相信、误信、作者补充和未追踪；
4. 不把失败、被骗、高风险选择或不同价值取向单独判成降智；
5. 能识别有证据的信息越界或知情倒退，并给补动作、补理由、补传递的推荐；
6. 材料不足时明确说看不出来，不补写事实；
7. 给作者的是正常中文解释，不是让作者填后台字段；
8. 结果绑定章节版本，旧版本失效后不能继续承重；
9. 全程只读，不写事实账、人物账或规划账；
10. 不把候选界面、提醒时机和知情字段冒充已拍合同。

### 已有的材料证据

- 已完成两种题材的人工材料复盘；
- 人工产物能展示按角色和时间排列的候选个人线、同场人物解释差，以及“不要把失败、误信和材料空白硬判成降智”的边界；
- 两份实样和一张低保真稿都带证据回指，并经过独立只读复核；
- 这次工作没有运行产品，也没有写正式账本。

### 还没有验证的产品能力

- 小说辅助产品能否自动生成并完整覆盖个人线；
- 能否稳定区分听见、理解、相信、误信、作者例外和未追踪；
- 能否真正识别信息越界，而不是把检索遗漏当越界；
- 作者是否觉得结果有用、好懂、不烦，也不觉得被审判或替写；
- 误报和漏报会有多大负担；
- 章节变更后，旧结果能否可靠失效；
- 后续模块是否真的需要复用这份结果，以及什么传递方式最安全。

## 小说辅助产品当前还缺什么

当前不是正式模块运行，而是人工读取较早的本地七类整理和 CCZ-103 候选落位。这次人工复盘实际读取的是：真实小说的大纲、带证据号的事实句、人物与关系整理、人物状态候选、抉择和因果材料。

这次人工复盘整理出的候选输出是：两部真实小说中选定角色的候选个人线、同场人物差异、证据充分与材料不足的分界，以及面向作者的提醒文案。这不等于小说辅助产品现在已经会自动产出这些内容。

小说辅助产品还缺：

- **生成能力**：不能稳定自动生成按角色、按时间点的个人线；
- **长期保存和版本判断能力**：不能把结果稳定挂到角色和章节版本，也不能在原文变化后自动判旧结果失效；
- **使用能力**：作者写下一场或改旧章时，产品还不会主动读取个人线做防降智重放；
- **传递能力**：如果后续模块确实需要复用，产品目前还没有获批的方法安全交付这份结果，也没有验证“统一报告”是不是正确形状；无论采用什么方式，都要保证下游不会反写真值。

这会卡住作者的操作是：让配角、反派或 NPC 做下一步行动时，作者仍要自己翻前文确认“他当时到底知道什么、怎么理解、为什么会这样选”。篇幅一长，作者知道的内容很容易错塞给角色。

## 下一步推荐

低保真演示已经落在 [`17_角色视角线_作者前台低保真演示_v0.1.md`](17_角色视角线_作者前台低保真演示_v0.1.md)，并完成独立只读复核。它包含：

- 一个场景；
- 三到五个角色切换；
- 每人一条个人时间线；
- 一条证据充分的提醒候选；
- 一条“行为有解释，只报剧情机会”的候选；
- 一条“材料看不出来”的候选。

下一步让 CZ 直接看这套解释是不是产品想要的方向。CZ 验收产品语气和判断边界后，再决定是否把它交给正式界面／合同施工。真实作者观察放在候选成形以后，验证作者是否看得懂、提醒是否烦、推荐是否有帮助；它不再是当前设计稿的开工前置。
