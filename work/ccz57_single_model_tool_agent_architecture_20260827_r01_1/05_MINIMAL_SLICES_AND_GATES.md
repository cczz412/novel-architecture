# 最小施工切片与阶段门

## 总纪律

每一阶段只证明自己的事情。A／B 通过不能冒充 API 通过，C 通过不能冒充抽取质量提高，D 的合成题通过也不能冒充真实小说产品验收。

## A 票｜0 API 最小硬外壳

### 读取什么

- current C2／C1 合成夹具；
- 已保存的旧 API 原始回包副本；
- OpenRouter／Ark 工具回合合成夹具；
- current C2、C3、FACT_CAUSAL_EDGE 合同只读副本；
- R01.1 的 ProviderTurn 与工具包候选。

### 输出什么

- 不可变 raw Attempt；
- `ProviderTurn` 标准回执；
- `baseline-r01.1` 四个模型可调用工具的独立完整 Schema；
- 固定机械服务：身份、截断、两层 JSON、tool arguments、Schema、evidence、current revision；
- 供应商工具 Schema 打包器与 SHA 回执；
- C3 预览纯函数；
- 离线重放报告。

### 不做什么

- API／模型调用为 0；
- 不做 Agent 循环；
- 不做语义 Patch、因果映射、缓存续接；
- 不修改 M4 返回值，也不假装已有 lineage→f-ID 映射；
- 不碰 `novel-mvp` 正式 runtime；
- 不读 `local/` 小说正文；
- 不把 32 项目录全部做成模型工具。

### 放行条件

- 合法 tool call＋空正文不会被误判；
- 正文伪造工具调用不会执行；
- 所有工具 Schema 独立、无悬空引用、字节可重放；
- raw hash、模型身份或 revision 改一项就失败；
- 旧抽取回包与 Agent 动作回包走不同解析路线；
- 网络调用机械证明为 0。

## B 票｜0 API Patch、版本与停止

### 输出什么

- Diagnostic、PatchProposal、Preview、CandidateVersion、MergeReceipt、Checkpoint；
- 新增事实和单字段 Patch；
- 未触碰字段证明；
- 同错、A→B→A、回归、预算和人工停止；
- 预制干净复核回件；
- 有期限的 causal hint 侧车，不写正式因果边。

### 放行条件

- 原始 Attempt 永不覆盖；
- Patch 只能创建子版本；
- 新 blocking 错误出现时不得用总错误数下降掩盖；
- 同一错误指纹没有新证据时停止；
- 语义 Patch 默认不能自动合并，除非另有获批政策。

## C 票｜两个精确端点的真实工具调用预检

两个端点分开运行、分开回执、不能在一个 run 中互换：

- Doubao：`doubao-seed-2-1-turbo-260628`，非思考；
- GLM：OpenRouter `z-ai/glm-5.3-flash`，低思考，固定一个上游 provider，禁 fallback。

每个端点只用一个合成 C2，开放 `baseline-r01.1` 四个工具。建议分两步验证：

1. 强制调用一个只读工具，证明原生工具协议、call ID 和回送能走通；
2. 改为 `tool_choice=auto`，验证模型会不会自己读取 C2、提交 baseline 或结构化认输。

每个端点最多 2 次模型往返、4 次工具执行，不做 Patch，不写 C3／M4。

### 放行条件

- 精确模型、思考档、上游 provider 与配置均匹配；
- 供应商接受冻结工具 Schema；
- 原生 tool call 和 arguments 可机械验证；
- 工具结果使用正确 call ID 回送；
- 本地账本重建后仍能继续当前状态；
- 费用、Token、延迟、缓存字段和错误都有原始回执；
- 任一端点失败只说明该精确端点预检未过，不外推模型整体。

## D 票｜自我修复有没有净收益

比较两条路线：

- 固定式：一次抽取＋同样的机械门，不给语义修补；
- 工具 Agent：一次 baseline＋按错误触发局部 Patch＋干净复核＋停止。

先用冻结合成题，再在单独授权后加入少量真实小说 C2 责任段。真实材料只从明确授权的段进入运行，不扫整章、整本或 `local/`。

并排记录：

- 错→对、对→错；
- 正确项保留；
- 漏项、错项、重复、矛盾；
- Schema、evidence 和因果提示；
- 工具调用数、模型往返数；
- Token、缓存、耗时、费用；
- 无进展、震荡、人工升级；
- 每个精确模型和思考档单独统计。

### 放行条件

不能只看最终多抽出几条。工具 Agent 至少要证明：修好的项多于改坏的项；正确项保留率不下降；成本和人工升级率在 CZ 可接受范围；停止机制真实触发；结果可以从原始 Attempt 完整重放。

## 产品通过还差什么

D 票只回答“小样本里工具 Agent 是否比单次抽取更有希望”。小说辅助产品要真正通过，还要在获批的真实作者操作里证明：作者能够查看候选、看懂修补差异、拒绝错误建议、恢复旧版本，并确认或退役因果边。没有这一步，不能写成产品已可用。
