# CHAPTER_CONTEXT_RETRIEVAL_TASK · 本章取件任务单

**版本：v1**

一句话用途：把 CCZ-137 已确认的本章范围、上一章正式交接、从已读来源中选出的事实稳定引用和按需盒子目录，收成一张可以交给 CCZ-140、也能逐项翻译成 C9 来源需求的不可变任务单。

实现状态：`CONTRACT_ONLY__NO_SEARCH_READER_C9_OR_UI_AUTHORIZED`。

## 1. 唯一范围输入

本合同只接受一张完整、结构有效、状态为 `CONFIRMED` 的 `CHAPTER_SCOPE_CONFIRMATION v1` 作为故事范围输入。

任务单只保存：

- `scope_confirmation_ref`：范围对象身份和 `scope_basis_sha256`；
- `scope_projection`：原对象 `ccz139_handoff` 的逐字段投影。

调用方不能另外填写故事线、切线意图、视角人物或出场人物。校验器会把任务单投影和完整范围对象逐项比较。范围对象已撤回、已替换、仍等待作者、已经停止，或不再匹配当前水位时，任务单只能 `STOPPED`，不能改用聊天记忆或旧卡继续。

这条边界保证 CCZ-139 不重做 CCZ-137，也不因为取件方便偷偷改线。

## 2. 前后章身份和上一章交接

`chapter_position` 不能由任务单自己声称。每张已确认范围的任务单还必须带一枚 `CHAPTER_PREDECESSOR_BINDING v1` 引用；完整绑定对象在校验时作为证据输入，只负责封住：

- 当前章槽、修订和来源规划水位必须与范围确认一致；
- 第一章没有前章槽位和结算 SHA；
- 延续章的前章槽位和结算 SHA 必须与实际读取的正式结算一致。

它不是第二个故事范围输入，也不能改故事线、视角或出场人物。当前合同只做离线结构校验；真实运行端必须从受信的章节顺序 owner 取得这枚绑定，拿不到时以 `PREDECESSOR_BINDING_UNAVAILABLE` 停住，不能从槽位名称或聊天记忆猜上一章。

延续章必须读取一张结构有效且 `claim_kind=OWNER_RESOLVED_SEALED` 的 `CHAPTER_SETTLEMENT_SEAL v1`。任务单只投影：

- 上一章槽位和 `settlement_sha256`；
- 实际完成、关键骨架和重要状态变化的 statement 引用；
- 未决故事项引用；
- 下一章交接的模式、范围引用、短摘要和来源封条；
- 十本账逐账提交或确认无变化的结果。

`OWNER_UNRESOLVED_CANDIDATE` 不能冒充正式交接。第一章可以合法使用 `previous_chapter_handoff=null`，但必须由前后章绑定明确为 `FIRST_CHAPTER`。

切线也不删除上一章已发生事实和未决义务；后续事实选择、盒子顺序和取件重点仍以 `scope_projection.transition_intent` 指定的新范围为准。

## 3. 任务相关事实子集

`selected_fact_refs` 是稳定引用集合，不是第二份事实账。每条只保存：

- 事实稳定编号、修订和内容 SHA；
- 对应章节及章节修订；
- 真正打开的读取回执来源；
- 为什么与当前故事线、人物、任务或上一章未决项相关；
- 一句受长度约束的任务摘要；
- 必取／参考／可选等级；
- 对应的 C9 need ID。

事实必须真的出现在状态为 `OK`、`truncated=false` 的 `LEDGER_READ_RESPONSE` 中，并能回到该回执的 `source_manifest`。`EMPTY` 只代表指定范围没有匹配，`REJECTED`／`ERROR` 代表没有拿到可用内容；三者都不能产出事实引用。

校验器只能证明“引用来自哪份已读回执、修订和 SHA 是否一致”，不能证明自然语言相关性真的选得好。语义准确率继续由 CCZ-158 的真实小说 50 题评测。

## 4. 按需盒子目录

`box_directory` 是本章任务级逻辑目录，不创建物理 BOX，也不是已经关闭的 longline BOX runtime。

每个盒子只保存：

- 盒子类型和与当前任务相关的范围引用；
- 预计能取得哪类材料；
- 当前是已打开、只看目录、尚未读取、能力未接或权限遮蔽；
- 继续读取使用的逻辑入口；
- 义务等级和对应的 C9 need。

`DIRECTORY_ONLY` 只说明入口可见，不能夹带内容；`NOT_READ` 不等于没有内容；`CAPABILITY_UNAVAILABLE` 不等于合法为空。权限遮蔽时不得返回标题、数量、水位、哈希差异或可推断对象存在的入口。

## 5. 来源清单和读取覆盖

`source_manifest` 逐项登记真正打开、只看目录、未读和能力不可用的来源。`read_coverage` 必须把来源 ID 精确分区，并写清：

- 选中了多少条事实；
- 必取材料是否已经具备可执行入口；
- 哪些必取盒子确实无法取得。

读取期间来源前进、结果超过上限、返回被截断、来源损坏或权限失败时，必须保留准确原因。不能把旧水位和新水位混成一张任务单。

## 6. 和 C9 的接缝

`c9_source_needs` 逐项使用现行 C9 v2 的 `source_need` 形状。它只表达“要取什么”，不创建完整 `C9_RETRIEVAL_REQUEST`，也不定义总 token 预算、总 gap policy、消费者、请求哈希或 packer 结果。

规则固定为：

- 上一章交接、每条事实、每个需要打开的盒子都必须有明确 need；
- `LEDGER_OBJECT → FORMATION_BASIS → ORIGINAL_EVIDENCE` 只能按父子链下钻；
- 子层义务不能高于父层；
- 子层必须带能回指父层决定的 `trigger_provenance`；
- need 的来源合同和版本必须属于 C9 v2 当前允许集合；
- 本合同不执行 C9，不调用 `packer.py`，不复制 C9 核心。

## 7. 三种结果

| 状态 | 含义 |
| --- | --- |
| `READY_FOR_THIN_CARD` | 唯一范围、上一章交接和全部必取入口成立，可以交给 CCZ-140 |
| `READY_WITH_GAPS` | 必取入口成立，但参考／可选来源仍有明确未接能力 |
| `STOPPED` | 范围、上一章正式交接或必取来源不成立，不可交给 CCZ-140 |

`READY_WITH_GAPS` 不能用来掩盖必取缺口。`STOPPED` 可以保留范围、前后章绑定、上一章封存和失败来源这些审计证据，但不得保留选中事实、可执行 C9 need、盒子打开入口，或 `DIRECTORY_ONLY`／`NOT_READ` 来源入口。

## 8. 不属于本合同

本合同不负责：

- 搜索全书、判断自然语言相关性或自动选择事实；
- reader、分页器、数据库、缓存、AuthorWorkspace owner／writer；
- C9 request、plan、执行、材料包、回执或 trace；
- 物理 BOX、完整薄卡、UI、CLI、MCP、主 AI、自动备料或返工；
- 写入十本账、事实句子、正文、规划或章节结算；
- 把合成夹具冒充真实小说已经接线。

## 9. 离线校验器能证明什么

`validate_chapter_context_retrieval_task.py` 接收一张任务单和一组显式证据对象。它会调用现行上游校验器，检查：

1. 范围确认是唯一输入，且投影精确；
2. 前后章绑定与当前范围水位一致，上一章交接来自绑定指定的已解析封存，第一章例外明确；
3. 事实引用来自真正打开的 `OK` 读取回执；
4. 来源身份、作者、项目、章槽、水位和 SHA 对齐；
5. 盒子只保存目录信息，不把未读当空值；
6. C9 need 形状、来源版本、映射和三层依赖正确；
7. `read_coverage` 是来源清单的精确分区；
8. `task_basis_sha256` 绑定整张任务单。

它不访问 AuthorWorkspace、文件路径、数据库、网络或模型，不执行权限 current 检查，不搜索事实，也不执行 C9。`STRUCTURAL_VALID` 不能冒充真实自动备料或语义取件准确率已经通过。

## 10. 合成夹具

夹具至少覆盖 12 条合法路径：四种切线意图、第一章、上一章合法空结果、current 事实点读、可选来源缺口、旧摘要只留目录、三级证据链、作者确认／托管确认等价，以及全部任务材料到 C9 need 的精确映射。

反例覆盖：非确认范围、第二套范围、前后章身份错绑、未解析封存、跨作用域、从空／拒绝／错误回执抽事实、截断和来源前进冒充完整、重复事实、未接能力冒充空、停止态入口泄露、错误 C9 版本、上一章或盒子义务降级、孤儿 need、义务升级、自然语言路径、未知字段和摘要错误。每条反例还要命中自己声明的错误码，不能只证明“总之红了”。

所有夹具只使用合成稳定引用，不含真实小说、人物名称、正文、事实句子或作者隐私。
