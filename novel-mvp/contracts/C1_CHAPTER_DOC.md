# C1 · 章节文档（CHAPTER_DOC）

**版本：v0**（描述现状；要加字段先升版本并同步收发两端）

读法：v0 描述当前代码，`kind` 仍可能是 `draft`／`outline`。**v1 方向**（未改代码）：`chapters.json` 只收章节书稿；大纲进材料架／规划侧，不得占用实际章节序列。黄金三章是上层工作台，不由 C1 的章数或额度定义。

一句话用途：v0 描述当前代码里「一份进系统的材料」的标准形态。v1 方向收窄为：只表示章节书稿，大纲不再占用「一章」这个说法。

| 方向 | 模块 |
|---|---|
| 发 | M1 导入器（[ingest.py](../mvp/ingest.py)，经 M4 `store.add_chapter` 分配 id 后回传） |
| 收 | M4 事实账（落盘 `data/<项目>/chapters.json`）；M2 切窗器（只吃 `text`）；M0 展示（status） |

## 字段表

| 字段 | 类型 | 含义 | 必填 |
|---|---|---|---|
| id | str | 章节号，`c01` 格式，入库时按导入顺序分配 | 是 |
| title | str | 章节标题（导入时指定，默认取文件名） | 是 |
| kind | str | `draft`＝正文（走抽取）；`outline`＝大纲条目（不走抽取） | 是 |
| text | str | 原文全文，原样保存、未清洗 | 是 |
| added_at | str | 导入时间，`YYYY-MM-DD HH:MM:SS` 本地时间 | 是 |

章节顺序＝`chapters.json` 数组顺序＝id 序号，没有独立的顺序字段。

## 真实示例

取自 `data/万鬼伏藏/chapters.json` 第 1 条（`text` 截断展示，实际 3928 字）：

```json
{
  "id": "c01",
  "title": "第1章 李星燃",
  "kind": "draft",
  "text": "“你叫李星燃对吧，说说看吧，你都有什么症状。”\n　　市医院精神科的陈医生，四十岁出头，戴着眼镜，穿着干净整洁的白大褂，脸…",
  "added_at": "2026-08-13 00:53:41"
}
```

## 附：导入损失报告（M1 返回值，v0 最小版，不落盘）

`ingest.ingest_files(...)` 每批导入返回一份：

| 字段 | 类型 | 含义 |
|---|---|---|
| count | int | 本次导入章数 |
| total_chars | int | 本次导入总字数 |
| warnings | list[str] | 空章警告（正文全空白时一条） |
| chapters | list | 本次导入的 C1 章节文档 |

## 已知缺口（v0 不含，升版本再加）

- 无来源文件名、无清洗损失明细；章序校验、缺章检测、水印剥离未做（台账 I-001／I-002／I-003／I-006）。
