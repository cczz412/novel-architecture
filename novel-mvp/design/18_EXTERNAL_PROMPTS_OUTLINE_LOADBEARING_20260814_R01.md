# 外发调查 Prompt｜大纲／账本承重、户口与单源（2026-08-14）

身份：**调查题，不是施工合同。** 给 ChatGPT（建议开深度调查）逐条复制。10 题互相独立，**不要带附件、不要同一窗连发**。回包只作证据与候选先验，不自动改 R10、不自动改设计稿、不自动改代码。

上一批 7 题（[17 号](17_EXTERNAL_PROMPTS_AGENT_TOOLS_PIPELINE_20260814_R01.md)）管「AI 怎么调工具、怎么不乱蹦」。这批管下一层：**东西到底住哪、章纲能不能把上下游和写法都接住、一张表还是多张表、多细才够。**

产品语义以本地背景板／大纲结构稿为准。下面每题里的「已拍」是约束，调查时不要推翻；缺的是：**业界和网文实践怎么分家、失败长什么样、我们现有五层篮子还缺哪一口、哪些不该扩。**

## 怎么用

1. 新开一个 ChatGPT 对话（深度调查更好）。
2. 只粘下面某一题从「请做独立深度调查」到该题结束。
3. 10 题分 10 窗。回来后对照现有大纲结构稿消化，不要边回边改正式稿。
4. 回包登记走小说架构仓 survey-inbox（新 SI 卡），不要把报告正文复制进 R10。

现在的 CLI 是检修口。这批调查要让以后「想拿一样东西，立刻知道从哪张账拿」。

## 题 1｜户口：大纲里放什么，角色／地点／势力／物品自己家里放什么

```
请做独立深度调查。不要假设你能读到我们的内部文件。下面「已拍」是约束，不要推翻或改写成另一种产品。

我们在做给网文作者用的「故事真源引擎」：导写＋核对，不代写正文。作者界面叫「大纲」，内部叫规划账。已经有：

- 规划账：五层篮子（书核→卷→章槽→场→拍／计划事件）＋三条横架（故事线、伏笔、写法挂点）。
- 事实账：已经发生的事，句子级，带原文锚。规划账只引用它，绝不反写。
- 人物页：可变状态（受伤、投靠、关系）是事实／计划的影子＋指针，不是第二本真值；静态人设是作者声明的参考材料。
- 一条内容尽量只存一个地方，别处用指针读。不要两处维护。

痛点：章纲场篮里现在直接写地点字符串、人物显示名。作者会问：门派、势力、宝物、金手指规则，是写进大纲，还是各自有家？两边会不会重复、打架？

已拍、不要推翻：
- 不代写正文。
- 计划 ≠ 已发生。PE 和 F 分编号、分账。
- 人物可变状态不复制事实句正文，只存属性＋锚。
- 插件／文学理论不自动改大纲，走卡牌；作者点了才用。

请调查并回答：
1. 长篇创作工具、叙事引擎、TRPG／世界观 wiki、游戏 quest 系统，怎样划分「情节安排」和「实体户口」（人物／地点／组织／物品／能力）？各放什么、绝不放什么？
2. 「当前在哪、现在归谁、此刻什么状态」这类会变的信息，通常住实体家、住事件账，还是两边都有一份？公开产品怎样用指针避免双写？失败案例（改一处另一处忘了）长什么样？
3. 关系（谁恨谁、谁结盟）是独立一张关系表，还是人物家的影子？组织成员是势力家的名单，还是人物家的「所属」字段？怎么避免第三人？
4. 给出一份建议的「只住大纲 / 只住实体家 / 只许指针」三分清单，覆盖：本章目标、场安排、谁出场、地点、门派规矩、宝物下落、金手指限制、人物外貌、人物此刻动机。
5. 哪些内容看起来两边都能放，业界用什么消歧规则（一句话能判）？

请给可核对来源。分不清已验证与推测时写明。不要写代码，不要发明我们的字段名去冒充已拍合同。
```

## 题 2｜纵向承接：事实句和作者设定，怎样流进章纲，再流到写法指导和分镜

```
请做独立深度调查。不要假设你能读到我们的内部文件。下面「已拍」是约束，不要推翻。

产品要让同一套管线服务三截：

上游：已确认事实句；作者注入的全书／卷大纲；作者写的角色设定、世界观、门派势力。
中游：给「这一章」安排任务的章纲（本章目标、场安排、必写承接、不能违反、字数预估）。
下游：不代写正文，但要能给出很细的写作指导（这段／这句该完成什么事实、情绪、信息），以及分镜需要的画面／人物／对白要点。

已有形状：计划事件和事实句同一种句法（谁做了什么／什么变了）。章纲用依据引脚只读指向事实。场篮已有目标、阻力、转折、POV、画面提示、对白要点、写法指导栏。分镜／场景卡从章纲快照读，不另编一套剧情。

已拍、不要推翻：
- 规划永不改写事实。
- 账本可以细，真正喂给模型的执行包必须瘦。
- 卷层默认折叠；主体用户常常只有 3～20 章。
- 作者在产品里创作时，以规划／账本为工作真值，不以他后来在外面写的正文为真值（正文可存放、可对照；要对齐就改大纲）。

请调查并回答：
1. 成熟大纲／节拍／场景卡产品，上游设定和已发生事实怎样「下传」到本章，而不把全书设定糊进每一章？常见漏项是什么（漏不可逆、漏谁在场、漏世界规则例外）？
2. 「章纲承接卷任务」通常在哪几个格子完成（章目标／必写／场序列／出口钩子）？怎样检查「这一章的结构装得下卷交给它的任务」？装不下时业界提示什么，而不是静默改规划？
3. 写作指导如果细到「每段完成哪几条事实句、信息按什么顺序透露」，它是章纲的投影，还是另张「指导单」？和分镜（镜头任务）如何共用同一批计划事件，避免三套故事？
4. 同样 5 条事实句，编排顺序会改变紧张度——这种「叙述顺序」应该标在计划事件的数组位置、单独的话语序，还是只出现在写作指导里？线性网文和倒叙／多线分别怎么做？
5. 给出一张「上游字段 → 章纲格子 → 下游（指导／分镜）读哪些」的建议对照表。标出：必须指针、允许摘要、禁止复制。

请给来源。不要建议我们开始代写正文。不要取消「计划≠事实」。
```

## 题 3｜写法承重：钩子、爽点、弧光、伏笔、对立、危机……该进结构，还是只做插件卡

```
请做独立深度调查。不要假设你能读到我们的内部文件。下面「已拍」是约束，不要推翻。

我们既要接住学院派文学理论（人物弧光、自我救赎、人物魅力、人物推动剧情、伏笔、对立、解决危机、引出新剧情／新人物），也要接住中文网文教程里更刻板的说法（开局金手指、开门见山、黄金三章、爽点、打脸）。后者不是文学理论，但作者天天用。

已有：写法挂点（挂在章／场上的标签，如 technique.*／theory.*／reader_effect.*）；插件走卡牌，不自动套理论；伏笔账只管 hook；爽点被明确说过「不是标签树，是知情差、义务、状态翻转等底层件组合出来的效果」。

已拍、不要推翻：
- 理论插件默认不冒出来；作者点「找一种方法」才选插件。
- 模板不硬性规定、不追旧账（说好 20 章高潮、15 章写完了，提醒一次就停）。
- 挂件只记可机械数的底层件＋作者自评，不把「写得有文气」当硬检查。

请调查并回答：
1. 把下列技法逐项判定：必须有数据槽才能运转 / 挂个标签就够 / 只配教法卡、不要进账本。
   钩子；悬念；读者期待；爽点／打脸；情绪释放；人物弧光；救赎；魅力展现；人物推动情节；伏笔埋收；对立／冲突升级；危机解决；引出新人物；开局金手指；开门见山。
2. 公开的网文教程把这些写成「章法口诀」时，常见把口诀误当成数据结构的失败（例如强制每章打脸、把救猫咪节拍写进每章必填字段）。有哪些可核对的产品或作者吐槽？
3. 「底层件」（谁知道什么、谁欠谁、状态翻转、不可逆损失）怎样组合出爽点和弧光？哪些底层件必须是一等账本对象，哪些可以是检查器临时算出来的？
4. 拆别人的爆款时，若只拆出「很普通的故事梗概」就失败了。要拆出「他怎么调动情绪、怎么介绍人物、怎么安排信息披露」，最少还要哪些结构槽？这些槽和自己的书的真值账必须怎样隔离？
5. 给出建议：现有「五层篮子＋伏笔账＋写法挂点＋插件卡」还缺哪 0～3 个一等对象才撑得住上面清单；哪些明确不要扩。

请给来源。不要发明一套新的万能「文学理论表」冒充已拍。不要建议理论自动改大纲。
```

## 题 4｜还没发生的事：命运、结局、灵感、伏笔、计划、未来触发，怎样分家

```
请做独立深度调查。不要假设你能读到我们的内部文件。下面「已拍」是约束，不要推翻。

作者会说：「给每个人物设一个最终命运」「故事要朝这个结局走」「我突然想到以后要加一个卖伞老头」「第 30 章再引爆这条线」。这些都必须有地方住，并且真能被取出来用，否则就是结构缺口。

已有分家（请当约束，不要合并）：
- 灵感：还没进故事的愿望。删了谁也不欠。默认不进执行包、不进问答。安放之后才变成计划／伏笔／人物草案。
- 伏笔：已经（或已计划）亮给读者的债。不收会赖账。
- 计划事件：已经排进某场某拍的安排。
- 书核结局锚点：允许空。
- 触发器（方向已拍）：默认只亮灯，不自动开卡；不能把计划写成已发生。

已拍、不要推翻：
- 灵感 → 规划对象单向转化，不退回。
- 计划不能冒充已发生。
- 人物命运如果还没写成，不能写进「当前状态」。

请调查并回答：
1. 结局锚、人物最终命运、尚未排期的剧情种子、已埋未收的伏笔、已排进章的计划、条件触发的未来事件——公开系统怎样分表或分状态机？一张「未来表」通吃的产品后来怎么翻车？
2. 「人物命运」和「人物当前状态」怎样共存？命运改变时，哪些引用必须跟着亮灯？
3. 「故事是否朝既定结局发展」是书核上的方向字段、检查器算的偏离度，还是一条独立的目的账？谁有权改结局？
4. 作者灵感、设计好但未触发的剧情、已经对读者欠下的伏笔，三者在「能不能进本章执行包」上通常怎么隔离，才能既不泄底、又不让种子烂在抽屉里？
5. 给出最小对象清单：每类一个身份判据（删掉之后欠不欠账）、谁能读、谁能写、怎样被章纲指针引用。

请给来源。不要建议灵感直接当事实。不要建议触发器自动关章或自动开卡。
```

## 题 5｜「放这也能、放那也能」：怎样消歧，避免两个篮子抢同一条内容

```
请做独立深度调查。不要假设你能读到我们的内部文件。下面「已拍」是约束，不要推翻。

我们最怕扩面之后出现：新内容不知道放全局还是放一章；这个篮子也行、那个篮子也行；两处都存了，改一处漏一处。原则已经拍：同样内容尽量只存一处，别处指针。

典型歧义（请逐条给判据，不要和稀泥）：
- 「爷爷会遗忘开棺者」是世界规则、伏笔、还是某章的不能违反？
- 「陈九棺断左臂」是人物状态、事实句、还是某场的出口状态？
- 「宏远集团」是势力户口、地点、还是反派线？
- 「第 4 章回家不认」是章目标、场目标、还是计划事件？
- 「开局三章见金手指」是书核承诺、卷节拍、写法模板，还是插件？
- 秘密「里面封的是他自己的名字」是秘密账、伏笔、知情，还是事实？

已拍、不要推翻：
- 一处存放、别处指针。
- 世界规则／设定集身份 ≠ 已发生事实。
- 伏笔 ≠ 义务（角色立的债）；义务尚未进规划账 v1，调查时可以建议要不要单开，但不要把 hook 和义务合成一张业务表。
- 章号最多做导航，不要当触发条件语义。

请调查并回答：
1. 知识库／叙事数据库／wiki 产品用什么「放入规则」（一句话测试）消灭双篮子？有没有公开的决策树或对象生命周期图可核对？
2. 全局对象和章级对象怎样分工？哪些全局事实允许在章纲里出现摘要？摘要过期怎么标？
3. 发现双写之后，合并策略通常是什么（谁赢、怎样留痕、指针怎么改）？
4. 给上面 6 条典型歧义各写一条「只准住这、指针去那」的建议判词，并说明若我们现在结构缺那一口家，是该新开表还是并进已有表。
5. 列出另外 8～12 个网文高频、同样容易放错篮子的内容类型（请你补我们没想到的），各给判据。

请给来源。不要建议「两边都存一份同步」。不要发明第三本真值。
```

## 题 6｜大纲该多细：轻 30 条和重 130 条，怎样分层而不是做成两种产品

```
请做独立深度调查。不要假设你能读到我们的内部文件。下面「已拍」是约束，不要推翻。

我们抽事实时已经体会到：抽得轻，一章三四十条；抽得重，一百三四十条。大纲也会有同样问题。太粗：写作指导和分镜没东西可抓，拆书只剩普通梗概。太细：作者填不动，模型也选错，篮子歧义爆炸。

已有：每个篮子强制一句话胶囊，概览只读胶囊、点开才进细节；场篮分 MVP 最小档和完整档（赌注／策略／新知三分等完整档先登记不实装）；计划事件到「拍」为止不再往下分。

已拍、不要推翻：
- 账本可以细，执行包必须瘦。
- 小白默认少打断；高级作者才看细档。
- 不要把作者主界面做成检修 CLI。

请调查并回答：
1. 大纲／节拍／场景工具怎样做「同一结构、多档密度」，而不是轻量版、专业版两套数据模型？有哪些公开做法（折叠层、必填／可选、按任务投影）？
2. 「一章的计划事件」经验上多少条开始有害？有没有写作软件、编剧软件、互动叙事工具的数量纪律或用户研究（没有就明确说没有，不要编百分比）？
3. 细到「每句怎么写」时，哪些必须仍是计划事件（真值／计划），哪些只是写作指导投影（可丢、可重算）？
4. 导入已写正文做反推时，密度怎样跟「作者从零写大纲」对齐，避免反推出来 130 条、作者手写只有 8 条，系统认为两边都是章纲？
5. 给出建议的密度阶梯：书核／卷／章／场／拍各档大概装什么、作者最低要填哪几格才能开写下章、高级档多出来的格子谁看。

请给来源。不要建议我们做两套互不兼容的大纲格式。不要把执行包的瘦当成可以把账本砍薄。
```

## 题 7｜建表：几层、几张表、谁引用谁；平级还是树

```
请做独立深度调查。不要假设你能读到我们的内部文件。下面「已拍」是约束，不要推翻。

我们最终存储终点是 PostgreSQL（已拍）。现在设计稿里规划账已有约十来类对象（书核、卷、章槽、场、计划事件、故事线、伏笔、挂件、选择记录、引脚、对账边等），另外还有事实账、人物账、灵感账、材料架设定集。还可能要地点、势力、物品、义务、知情、时间线。

怕两头：表太少，什么都塞进大纲 JSON，口子含糊；表太多，作者和新内容不知道进哪张，引用网变成毛线。

已拍、不要推翻：
- 上层模块按合同抓数，不关心底下是文件还是库。
- 计划与事实分表。
- 人物引用第一天用稳定 ID，显示名是投影。
- 改史用依赖边／反向索引，明确不上图数据库当主存储。
- 一处存放、别处指针（单向引用为主）。

请调查并回答：
1. 长篇故事／剧本／游戏叙事的数据模型，常见分成几层（例如：世界实体层／事件层／安排层／表达层）？每层典型几张表？有可以核对的开源引擎或产品文档吗（Ink、Yarn、articy、Twine、World Anvil、Novelcrafter Codex 等）？
2. 「树形包含」（场属于章）和「平级引用」（人物被许多场引用）怎样混用才不会把实体做成章的子行？
3. 哪些引用必须单向（计划→事实、影子→真源）？哪些可以双向（故事线↔成员）？双向时怎样避免循环更新？
4. 一张表用 type 字段装多种对象，对比「一种对象一张表」，在故事工具里各自的翻车方式是什么？

## 题 8｜两种真值：已发表正文进来求真，产品里创作以大纲／账本为准

```
请做独立深度调查。不要假设你能读到我们的内部文件。下面「已拍」是约束，不要推翻。

我们有两种进货，真值不能混：

A. 作者把自己已经发表的小说导进来。那份发表正文是真值。抽取得到的事实／大纲是投影。检查、求真时按句子位置回到发表正文对照。
B. 作者开始在我们产品里往下创作。我们不代写正文。工作真值改成这里的大纲和各本账。作者在外面写出来的后续正文只存放；默认不升真值。除非作者对照后说「大纲错了，要改到和正文一致」，那是改账，改完再检查一致。

已拍、不要推翻：
- 有正文则发表正文为证据真源（导入侧）。
- 产品不代写正文。
- 计划 ≠ 已发生；未写成不发已发生编号。

请调查并回答：

请给来源。不要建议用模型摘要代替原文锚。不要建议后续正文自动入事实账。
