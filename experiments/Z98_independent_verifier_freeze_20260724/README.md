# 第98道独立核验冻结候选件

这个主要解决一个问题：17 份修复请求已经冻结，但原实验预算还包含 34 次独立核验；在核验请求没有完整冻结前，不能发网。

本候选件只做 0 调用准备：

- 从第98道步一冻结包机械生成 17 份盲核验模板；
- 两个被测通道各复用同一套模板，排成 34 次修复＋34 次核验的固定顺序；
- P2 响应落盘后才机械渲染动态核验请求，并强绑定具体裁判节点、唯一前置修复节点、原始响应、调用票、usage 票和各自 SHA；跨臂错接直接拒收；
- 裁判只判不改；看不到被测平台、臂名和单条／批式合同名；
- 金标、答案、人工判词、历史成绩和修复日志不进入裁判窗口；
- 未知字段、重复 JSON 键、身份漂移、非法 P2、泄漏和裁判判词自相矛盾一律拒收。

裁判冻结为千问平台 `qwen3.7-max-2026-05-20`。本地只冻结文本指定的固定型号；供应商目录在线状态仍是发网前待验，不在本步骤联网。

预算按 CZ 当前直令改为裁判通道整轮 50 万 token，总金额仍不超过 10 元。旧预注册逐次小帽保留在差异账里，不再作发送阻断；正式消耗仍只认逐条 usage。静态模板投影只作规划，不能直接放行：每份 P2 结果落盘并插入动态请求后，程序必须按完整消息重新估算本次输入，加上 4k 输出上限，再走 50 万 token 与 10 元两道发送前闸。

盲判边界也单列说明：平台名、臂名和合同名都不进入模型窗口；但单条模板恒为 1 项，批式模板为 4 或 5 项，裁判可能从数量猜出分组规模。因此这里只称“显式身份标签已隐藏”，不冒充完全统计盲化。

构造方式：

```python
from pathlib import Path
from experiments.Z98_independent_verifier_freeze_20260724.pipeline import (
    build_bundle,
)

build_bundle(Path("/an/empty/output/directory"))
```

`build_bundle` 只读第98道步一冻结包和本地千问配置，不读取密钥值、不访问供应商、不调用模型。
