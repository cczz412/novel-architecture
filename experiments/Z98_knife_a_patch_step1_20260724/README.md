# 第98道步一｜刀A小额补丁实验备料

这套候选包只做一件事：把下一轮要考的三章、要修的少量事件、两种输出合同和预算上限先机械冻结。它不会访问网络，也不会调用模型。

你可以直接理解成：先把同一张卷子、同一组选题和两种答题纸装进密封袋，等统一审收后再决定是否真的发卷。

## 这次冻结了什么

- 只读输入固定为 retry03 第 3／13／19 章唯一有效事件样张和对应冻结锚目录。
- 章内目标由程序按同一条风险公式排序，修复上限分别为 5／4／5。
- 单条答题纸只收一个刀A补丁，不准模型重写整章。
- 批式答题纸 `atom-batch-v2` 每批只收同章 4～8 个程序预给位置。每项固定只有 `slot_id／status／atom／split_span_ids／missing_context_codes` 五格，返回位置必须一项不差；扩窗计数归程序管，同一位置最多一次。
- 第97道宽松的未知字段面在本目录另存严格候选版；第97道原文件不改。
- 旧严格尺只读；UCR 五层只加候选列，不冒充正式成绩，也不作为换尺依据。
- 授权时间、两页 Notion 真源、预算公式和两道分歧定义另存为本地冻结摘录；它的 SHA 只证明本地摘录没变，不冒充 Notion 页面原始字节。
- 14 个选择位逐条登记源事件文件、事件身份 SHA、实发请求 SHA、批次和两种合同臂，状态统一为“已冻结、未发送”。

## 目标怎么选

程序只看事件本身和它已经挂着的锚，不看金标、人工判词或历史答案。风险分由四部分相加：

`50×锚数量 + 20×限定/转折词命中 + 10×句内标点数量 + 事件长度（最多100）`

同分时按事件 ID 排序。候选锚只取现有锚在冻结目录里的前后各一格，规则固定，不准人工挑。

## 预算怎么卡

每章都拿 retry03 的真实总 token 当 T1：

- 刀A补丁不超过 T1 的 25%；
- 独立核验不超过 T1 的 10%；
- 整条链不超过 T1 的 135%；
- Flash 和 Pro 分开记未来调用与账单；步一不联网，所以不猜价格。

预算闸按「章 × 模型通道 × 合同模式」逐格独立判断。四格相加只是一张运输总包络，不能拿总和冒充任何单格已经过闸。步一的真实修复消耗保持空值，只表示上限已经写死，不表示实际预算成绩。

## 怎么复验

`build_bundle(目标目录)` 会生成请求蓝图、合同 SHA 票、同卷票、选择票、预算票、泄漏扫描票、对照设计票和预演票。用两个空目录各跑一次，两个 manifest SHA 应完全相同。

预演票固定写着 `step2_release_allowed=false`。这表示备料完成不等于可以发网；步二仍需统一审收后的明确放行。
