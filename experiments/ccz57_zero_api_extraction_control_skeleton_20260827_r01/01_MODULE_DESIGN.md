# 01｜模块设计

## 设计结论

0 API 骨架不重新调用模型。它读取已经保存的请求、回包和题面，把“模型交了一份东西”拆成六个可回查动作：

```text
导入原件
  → 运输与身份检查
  → 原始字节检查和两层 JSON 解析
  → v2.1 Schema 与 evidence 定位
  → 诊断路由
  → 安全派生／人工 Patch 测试／新版本／停止
```

🔥 原始 `Attempt` 永远不覆盖。程序每次改变内容，只能创建带父版本的新对象。

## 为什么要做两层解析

当前原始文件通常有两层：

1. 供应商回包外壳，里面有模型名、usage、状态等；
2. 外壳里的 `content` 字符串，才是模型交付的 `facts` JSON。

Doubao Mini Q2 的外壳能正常解析，但 `content` 里同一条事实出现两个 `status`。如果直接使用普通 JSON 解析器，前一个值可能被后一个值盖掉，错误就消失了。

因此顺序必须是：

```text
外壳字节保存与解析
  → 提取 content 原始字符串
  → 用保留键顺序和重复项的扫描器检查
  → 没有重复键才交普通 JSON 解析器
```

## 模块清单

| 模块 | 读取什么 | 输出什么 | 能修改什么 | 必须停在哪里 |
|---|---|---|---|---|
| `AttemptImporter` | 已保存的请求、stdout／stderr、meta、题面和冻结配置 | 不可变 Attempt 与输入引用 | 只能新建记录 | 缺文件、SHA 不符、引用越出仓内候选包 |
| `TransportIdentityGate` | Attempt 外壳和冻结模型身份 | 运输、截断、模型身份诊断 | 不改内容 | 身份不符、空回复、已截断、永久错误 |
| `RawJsonGate` | 原始外壳和原始 `content` 字节 | 外壳解析、重复键、任务 JSON 解析状态 | 不改内容 | 重复键、结构散坏、引号未转义 |
| `SchemaGate` | 已成功解析的任务 JSON 和冻结 v2.1 Schema | JSON Pointer 级 Schema 诊断 | 不改值 | 必填缺失、枚举错误、空可选字段等阻断项 |
| `SafeFormatDeriver` | 原始 `content` 和白名单规则 | 派生 JSON、前后哈希、叶子不变量报告 | 只去 BOM、首尾空白或一层完整围栏 | 多层围栏、内部仍坏、任意叶子或数组顺序改变 |
| `EvidenceLocator` | 题面正文和每条 `evidence` | 精确字符区间、命中次数和来源部分 | 不改事实 | 找不到、只命中背景卡、需要拼接、多个命中未消歧 |
| `DiagnosticRouter` | 前述检查结果 | 分轴 Diagnostic 和下一动作 | 只写诊断状态 | 没有获批处理器、同一错误没有新策略 |
| `PatchScopeGate` | 人工测试 Patch、稳定事实 ID、允许字段 | 作用域、基线和回归检查结果 | 不直接合并 | 基线过期、数组下标直改、越界、未触碰字段变化 |
| `MergeGate` | 父版本、通过检查的 Patch | 新 ResultVersion 和 diff | 只创建子版本 | 任一前置检查失败 |
| `StopController` | 错误指纹、版本哈希、进展向量和 0 API 预算 | 下一动作或机器停止原因 | 只改运行状态 | 无进展、震荡、回归、需要模型／人工、预算越界 |

## 第一版能机械判断什么

- 请求和响应文件有没有、SHA 是否一致；
- 请求模型与响应模型是否符合冻结身份；
- 是否超时、失败、空回复或截断；
- 两层 JSON 是否能解析、有没有重复键；
- 是否符合冻结 v2.1 Schema；
- `evidence` 是否是当前题面正文的连续逐字子串；
- 单层完整代码围栏能否在不改叶子值的前提下剥除；
- Patch 是否指向稳定事实 ID、有没有越过允许字段；
- 未触碰字段是否变化；
- 版本是否回到旧哈希、错误是否原地重复。

## 第一版不能机械判断什么

- 一条事实是不是小说语义上的真事；
- 说话人应该填谁；
- 是否漏掉显式事实；
- 两个事件是否一定构成因果；
- 因果、时间、指代和状态变化的方向是否正确；
- 一份结果是否整体可用于产品。

这些轴必须写成 `NOT_CHECKED` 或 `HUMAN_REQUIRED`，不能借结构绿灯一起放行。

## 因果关系怎么处理

现行 v2.1 只有 `facts`，没有正式 `relations`。第一版遇到 Q4 这类“题面有因果提示，结果里只有两端事件”的情况，只生成旁路 `RelationCandidate`：

- 保存候选端点、关系类型、原文证据和触发理由；
- 不改 `facts`；
- 不写进 M4 正式事实账；
- 状态固定为需要人工或未来专项验证。

## 与现行产品的边界

这不是 M3 或 M4 的替换实现。设计期只在 `experiments/` 里重放已经保存的证据。只有后续实现、离线验收和单独产品拍板都通过，才讨论怎样接进 M3→M4 的正式传递接口。
