# EVALUATOR_R02｜现有四组答卷重评分

✅ 新评分器已经跑完，旧成绩没有覆盖。

## 这次修了什么

- 每道题只和本题金标匹配，不能再跨题“串分”。
- 把原来的“语义 F1”拆成机器可证明的“事实句精确命中”和“事实＋状态＋说话人精确命中”。
- 状态、说话人只在事实句已经精确配对后计算。
- 非法 JSON 仍按正式失败处理，但另外恢复已完整闭合的对象，用来发现被截断答案里的复读。
- 顶层容器异常、行内字段异常和非法 JSON 分开计数，不再出现永远为零的异常指标。
- 语义近似不由程序冒充判断，只生成盲审队列，等待人工判 `same / partial / different`。

## 非法 JSON 的诊断账

非法 JSON 没有被洗成合格答案。程序只从 raw output 里恢复已经完整闭合的对象，另算诊断：

| 组 | 恢复完整对象 | 重复对象数 | 重复事实数 | 非法 JSON 中精确抽到金标事实的案例 |
|---|---:|---:|---:|---:|
| A stage1 | 1,340 | 1,180 | 1,190 | 1 |
| A final | 922 | 654 | 708 | 1 |
| C stage1 | 274 | 150 | 163 | 0 |
| C final | 290 | 151 | 178 | 0 |

这里的“抽到”只认事实句规范化后完全相等，不做语义猜测。两条 A 案例说明模型偶尔已经写出了正确事实，但 JSON 最终损坏；它们仍然是格式失败。

## 旧分与 R02 的关系

- 四组完整 Schema 数量与旧账完全一致，差值都是 0。
- 原始 A final 机器票只在合法 JSON 内看复读，因此记成 1 案；R02 从 raw 恢复后发现 23 案完整对象复读、28 案事实复读。
- 阶段 1 后续诊断早已记到 A final 23 案严重复读，所以这次是修正原始机器票的漏计，不推翻阶段 1 总判。
- A final 新发现 1 条事实句精确命中，但三元组命中仍为 0；这不足以把模型改判为可用。

阶段 1 的四个核心判断没有被 R02 推翻。1C 的历史机器标签继续保留，但人话说明仍应收窄成“只证明 `@start:end` 记法外观不是主因”。
