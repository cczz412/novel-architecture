# T5 R04 A/C 两版 LoRA 对照失败原因独立审查

**状态：`CANDIDATE_PENDING_LOCAL_VERIFICATION`**  
**材料边界：只认路由包的 `00_ROUTE_MAP.md`、`01_current_truth/`、`02_current_route/`、`03_upstream_evidence/` 与 `_route/ROUTE_SELECTION.json`。**  
**本报告是候选审查结论，不替 CZ 拍板。**

## 大白话总判

✅ **这次不是“A 的逐字证据太长，所以 A 被截断；C 把证据缩成编号，所以 C 更好”这么简单。**

真正发生的是四件事叠在一起：

1. **两臂都出现了生成失控，A 尤其严重。** A 的 22 个触及 2048 上限的案例，在触顶前全部已经进入完整对象复读；正确金标并没有长到必须触顶。C 也有大量复读，只是多数较早自行收尾，所以看起来更短、JSON 更容易闭合。
2. **C 的坐标任务比 A 的逐字复制难得多，而且题面存在强误导。** 模型大量复制题面标题中的“归属终点范围”，把它当成证据范围；再给这个范围配单元开头或整句锚字。编号格式学会了，精确证据切片没有学会。
3. **第二阶段没有证据证明把第一阶段语义整体忘光，但确实带来了格式近因污染。** 第二阶段 72 行中有 142/646 条记录把 evidence 字段放到 fact 前；A 的多个失败答案随后直接变成 evidence/status/speaker、漏掉 fact。这个对应关系很强。它叫“序列化/字段顺序污染”更准确，不能直接扩大成“全面灾难性遗忘”。
4. **评分器把严重失败和计分错杀混在了同一个 0 里。** 名为“semantic”的指标其实要求 `fact/status/speaker` 三个字符串逐字相等；非法 JSON 又整案置空；C 的“锚字 1～5 字”在实现中实际要求等于最长前 5 个非空白字符。于是两个 0 分都不能解释成“模型完全没有语义能力”，但也绝不表示模型只是被评分器冤枉。

🔥 **最关键的纠偏：C 的金标答案通常不比 A 短。** 398 行里，C 金标比 A 金标更长的有 355 行；助手答案字符数中位数 A 为 891.5，C 为 1065，C/A 中位比 1.213。实测 C 输出较短，是模型少答、复读后早停或格式模板更容易闭合，不是任务天然节省输出。

## A/C 教材是否真的语义等价

独立比对封版母集 398 行、3,537 条事实：

- `fact/status/speaker`：A/C **3,537/3,537 逐条一致**；
- A 逐字 evidence：3,537/3,537 可在题面定位，3,537/3,537 责任终点合法；
- C 指针和金标锚字：3,537/3,537 通过现行严格校验；
- 8 种 status 在 A/C 中逐条一致且均属合法枚举；speaker 的有无和值也逐条一致；
- 无行内完全相同的 fact 重复。

所以，**“A/C 偷偷用了两套事实语义”没有证据。** status 与 speaker 也不是 A/C 教材分叉；真正的问题出在模型生成和评分时，`speaker` 缺省、`来源不明`、`无` 没有统一口径。

但“语义等价”不等于“学习难度等价”：

- A 只需复制一段原文；
- C 要选可见编号、计算 Unicode 字符起止、保证长链连续、最后一段落入责任范围，再给每段范围配锚字；正向教材还有 16 条事实需要 4～9 段长链，而特殊教材最多 3 段，阶段间难度分布也不完全相同；
- C 题面中 `[CHxxxx-Eyyy｜归属终点范围 @start:end]` 与输出 `CHxxxx-Eyyy@start:end` 使用同一种 `@start:end` 外观，但前者只是**允许的证据终点区间**，不是当前事实的证据切片。

系统提示和 JSON 语法也并非完全恒定：A 第一阶段用“连续短段＋左侧字符数”，第二阶段改成显式“只读左重叠区／本段负责区”；C 两阶段的任务合同基本相同，只改来源说明。第一阶段答案均以 fact 开头，第二阶段却有 142/646 条以 evidence/evidence_ids 开头。这个变化没有改语义，却改变了模型刚开始生成一个事实对象时看到的局部语法。编号桥接区反而不是主故障：恢复输出中仅 1 个事实以桥接编号收尾，远少于 322 次锚字错位和 38 次范围越界。

当前考卷 C 金标有 449 个指针元素，其中只有 174 个（38.8%）恰好等于题面标题范围；训练母集 4,704 个指针元素中也只有 1,339 个（28.5%）相等。这个设计会奖励一个有时正确、更多时候错误的抄标题捷径。

## 82 案当前成绩重算

本轮只读取 `exam_rebalance_r03/sealed/` 的 41 题/355 条金标和 `results/` 的原始输出。`sealed/exams/` 旧 48 题没有进入当前成绩。

| 读数 | A | C |
|---|---:|---:|
| 当前案例 | 41 | 41 |
| 当前金标事实 | 355 | 355 |
| 机器判 JSON 有效 | 14 | 35 |
| 机器计入事实 | 164 | 212 |
| 独立从原始输出恢复完整对象 | **922** | **290** |
| 触及 2048 上限 | 22 | 3 |
| 原评分器报告复读案例 | 1 | 23 |

| 严格 `fact/status/speaker` 命中 | 0 | 0 |
| 诊断性改写相似配对 | 42（20 案） | 35（19 案） |

说明：A 的独立“复读≥3”含 22 个触顶循环和 1 个有效 JSON 循环。原评分器只检查成功解析的 JSON，因此 A 的大多数复读被当成“格式失败”而没有计入复读。

### A：长输出与截断到底怎么来的

- 22 个 A 触顶案例中，**22/22 在截断前已有完整对象复读**；
- 这些原始输出长度与对应正确金标长度之比，中位数 **5.03 倍**，范围 1.06～16.25 倍；
- 也就是说，正确答案通常本可在 2048 内结束，输出变长主要是复读把它撑爆；
- A 另有未触顶却缺 fact 的案例，证明上限不是字段丢失的必要条件。

结论：**直接机制是复读失控，2048 是终止器和表面截断原因。** 把上限调大，只会先让循环跑得更久，除非复读本身也被处理。

### C：为什么 JSON 成功率高，却几乎没有合法编号锚字

独立恢复的 290 个 C 事实对象共有 367 个指针元素：

- 所有 base ID 都是可见的合法编号；
- 329/367 范围在单元长度内；
- 322/367 终点责任合法；
- **237/367 直接复制题面标题中的归属范围**；
- 220/367 直接覆盖整个编号单元；
- 只有 77/367 个锚字长度在 1～5 字；290 个过长或空；
- 严格规则只认 7/367 个锚字；
- 按提示字面允许“最前面连续 1～5 字的任一非空前缀”后，恢复对象中的合法事实从 6/290 上升到 51/290，但新增主要集中在 4 个案例，而且大量仍是复读。

这说明 C 不是完全没学会格式：**它学会了编号长相、可见 ID 和大致责任终点，却没有稳定学会“事实语义 → 精确字符切片 → 与切片起点绑定的短锚字”。**

### “C 复读更多”要怎么改写

机器票是 A 1 案、C 23 案，看起来 C 复读远多于 A。原始输出恢复后，完整对象复读≥3 是 A 23 案、C 23 案。C 确实在有效 JSON 中更常见复读，A 则更常一路复读到 JSON 截断。

更准确的说法是：

- **A：复读更容易演变成超长输出和非法 JSON；**
- **C：复读更容易在较短、可解析的 JSON 内结束；**
- 不能用原评分器的 1 vs 23 断言“只有 C 会复读”。

## 两阶段顺序：有污染证据，没有全面遗忘证据

训练顺序确为每臂“正向 278 → 特殊 72”，第二阶段分别续接本臂第一阶段权重，不存在 A/C 串接错臂。

### 支持“阶段二造成局部输出偏置”的证据

- 第一阶段没有 evidence-first 记录；第二阶段有 142/646 条记录以 evidence/evidence_ids 开头；
- A 原始输出中出现 209 个 `evidence,fact,status,speaker`、104 个仅 `evidence,status,speaker` 的完整对象；
- `AC-008`、`AC-010`、`AC-016`、`AC-035`、`NB-008`、`NB-010`、`NB-014` 等案例直接漏掉 fact；
- 这是训练末段序列化顺序与失败形态之间的直接同向关系。

### 反对“阶段二把第一阶段语义整体忘了”的证据

按来源类别看，特殊 6 题并没有形成“特殊全好、正向全坏”的简单图景：

- A 特殊题：仅 1/6 JSON 有效，5/6 触顶；
- C 特殊题：5/6 JSON 有效，但 5/6 仍有完整对象复读；
- 正向和新未见题也都有相同复读、字段遗漏与指针错误；
- 当前包只有最终阶段答卷，没有用第一阶段 checkpoint 跑同一 41 题的对照。

所以当前只能下：**阶段二很可能污染了字段顺序和格式先验；是否发生广泛语义遗忘，证据不足。**

## 训练、配方与解码的作用

四阶段同基座、同 LoRA 配方：16 层、rank 32、scale 0.125、dropout 0、lr 1e-5、batch 2、梯度累积 4、max_seq_length 4608。训练日志显示可训练参数 29.36M/4.022B（0.730%），无报错、无训练截断警告，但四阶段都明确写着 **没有验证集**。

日志末值：

| 阶段 | 迭代 | 已训练 token | 末次 train loss |
|---|---:|---:|---:|
| A 正向 | 280 | 285,925 | 0.467 |
| A 特殊 | 72 | 79,474 | 0.360 |
| C 正向 | 280 | 306,068 | 0.575 |
| C 特殊 | 72 | 79,132 | 0.428 |

这些 loss 只能证明训练目标被拟合，不能证明 41 题泛化。没有验证集，也没有阶段一/阶段二同卷曲线，无法从现有材料判断是“步数太少”“步数太多”还是 LoRA 容量不合适。

解码固定为 greedy、temperature 0、2048 token、0 次重试。它的角色是：

- greedy 会把一次高概率重复继续锁死，属于复读放大器；
- 2048 会把已失控的 A 输出截成非法 JSON；
- 0 重试使格式失败没有修复机会；
- 但 C 的 211/212 个严格指针失败大多发生在未触顶、有效 JSON 中，因此不能归罪于上限。

## 病因排序

1. **直接输出机制：重复对象/模板陷阱。** A 的截断几乎由它直接造成；C 的短而重复输出也由它解释。
2. **C 任务的坐标—锚字耦合过难，且题面“归属范围”外观诱导错误捷径。** 这是 C 指针几乎全坏的主因。
3. **教材/阶段二的字段顺序与容器不统一。** 不是语义金标冲突，但会教出 evidence-first、漏 fact 等格式偏置。
4. **评分器口径错误或过严。** 它解释两个严格 F1 为 0、A 复读被漏报和 C 短锚字被错杀；不能解释真实复读、漏题和坐标错误。
5. **greedy＋2048＋零重试。** 都是放大因素，2048 不是根因。
6. **LoRA 步数/参数不合适。** 有可能，但现有包缺单变量消融与验证曲线，不能定性。
7. **4B 基座容量不足。** 对 C 精确坐标任务有可能，对一般事实抽取不能从本实验单独推出。

## 不能下的结论

❌ 不能说“A 因为逐字 evidence 天然更长，所以必然截断”。  
❌ 不能说“C 天然更短、更适合 4B”。金标恰好通常更长。  
❌ 不能说“C 的 JSON 成功率高，所以 C 事实抽取得更准”。  
❌ 不能说“两个 F1=0，所以两臂完全没有学到语义”。  
❌ 也不能反过来说“只是评分器错了，模型其实没问题”。大量复读、漏字段、过抽、少答和错坐标都是真失败。  
❌ 不能确认发生了全面灾难性遗忘；当前只确认末阶段格式先验污染。  
❌ 不能确认 4B 基座、rank 32 或两轮训练是最终瓶颈，必须做单变量证伪。
