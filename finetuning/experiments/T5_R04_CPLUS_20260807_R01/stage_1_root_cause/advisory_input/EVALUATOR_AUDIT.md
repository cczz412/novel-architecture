## 结论

评分器没有把 A/C 分数“算错到完全相反”，但它有三处会系统性放大失败：

1. 指标名写“semantic”，实现却是 `fact/status/speaker` 三个字符串逐字相等；
2. 只要整份 JSON 或任一必填字段非法，就把该案例的 predicted 设为空数组，完整生成到一半的事实全部丢弃；
3. C 提示说锚字可取连续 1～5 个非空白字符，代码却用正则一次取尽最多 5 字，再要求完全相等，实际不接受较短合法前缀。

因此，严格三元组 F1 同时为 0 的原因是：**真实输出确实没有任何一条在计入范围内同时满足 fact、status、speaker 三个字符串完全一致；再叠加非法 JSON 整案清零。** A 有 2 条 fact/status 逐字命中，但 speaker 不同；C 连逐字 fact 都没有。另一方面，人工复核能看到不少改写级部分命中，所以这个指标不应称为人工意义上的“语义 F1”。

严格实现：

- 机器计入 212 个事实，严格合法 1 个；
- 独立恢复 290 个事实，严格合法 6 个。

只把锚字规则改成“预期首个非空白词串的任意 1～5 字前缀”，其他坐标、链顺序和责任终点不变：

- 机器计入部分可合法 20/212，净增 19；
- 独立恢复部分可合法 51/290，净增 45；
- 新增主要集中在 `AC-032`、`AC-043`、`NB-003`、`NB-005` 四案，且其中多案仍是同一事实复读。

结论：**锚字实现确有错杀，但修完后 C 仍远未达到可用。**

## 哪些是真没命中，哪些是评分口径错杀

### 真没命中或主要是真失败

- 输出落在责任边界之外；
- 同一事实重复多次而漏掉大多数金标；
- 把整段叙事动作、对白碎片或证据原句直接当 fact；
- C 使用题面归属范围而非事实证据范围；
- status、speaker、指针终点或长链顺序确实错误。

### 评分口径错杀或明显低估

- 非法 JSON 中已经闭合的完整对象被整案丢弃；
- 同义改写被所谓 semantic 指标判 0；
- `speaker="无"`、多写 speaker 与金标缺省之间没有归一化；
- 1～4 字的合法锚字前缀被实现强制成 5 字；
- 复读统计只看有效 JSON，导致 A 的截断循环被漏报。

## 建议的评分分层

本轮不改正式评分器，但下一轮读数应至少分开：

- **合同层**：JSON、必填字段、status 枚举、逐字 evidence / C 坐标合法；
- **严格回归层**：原有 exact record，用来检测金标复现；
- **归一化层**：speaker 缺省/来源不明/无的明确规则，标点与全半角归一化；
- **人工语义层**：盲审事实是否同义、是否错主体、错状态、错因果；
- **生成病理层**：从原始流检测对象复读、键名循环、触顶前行为，不能依赖最终 JSON 成功解析。

当前 0 分只适合叫“严格文本三元组 F1=0”，不宜直接叫“语义能力为 0”。
