## 一、批复结论

✅ **有条件同意按“A 为唯一人工语义真源、C-2 为短输出生产候选”的路线推进。**

当前允许锁定的方向：

1. **A 继续保存人工真值**：`fact / status / speaker / 逐字 evidence / 原文字符位置`。
2. **C 不再由人工维护第二套答案**：C-1、C-2、C-3 都必须从同一份 A 机械派生。
3. **旧 C 退出现役候选**：旧 C 的字符坐标、归属范围和锚字耦合，不再作为“简短版 A”继续扩数。
4. **C-2 是推荐生产候选**：局部 `B01/T01` 编号，只输出 `evidence_ids`，不让模型生成锚字。
5. **C-1 只做最简基线**：纯 `01/02/03` 局部编号，用来判断角色前缀是否有实际价值。
6. **C-3 只做小探针**：`B01/T01 + 两字锚`，不得直接进入正式大规模教材。
7. **正式 LoRA 只比较 A 与探针胜出的 C**：不允许给 C-1、C-2、C-3 各完整训练一遍。
8. **新增数据必须分批建**：先约 200～300 个新窗口，完成成对 A/C 测试，再决定是否扩到 1,100～1,300。

🔥 当前仍有一个 **P0 合同问题**，冻结 C-2 前必须写清：

> 纯 `evidence_ids` 能精确定位“编号单元”，但不能天然还原 A 中任意起止位置的字符级短证据。

所以 C-2 不能再被描述成“逐字 A 的无损压缩”。它只能选择下面两种合同之一：

### 推荐：`C2_UNIT`

- 模型返回最小覆盖证据的编号单元；
- 后台返回这些单元的逐字原文；
- A 仍保留更细的字符级真值，用来审计和计算多带了多少文字；
- C-2 的证据评分改为单元级命中、字符覆盖率和额外带入量。

### 不推荐当前直接做：`C2_EXACT`

- 若产品必须返回与 A 完全一致的字符起止，就必须再让模型给偏移量、双锚或做第二阶段精确截取；
- 这会重新引入旧 C 的坐标难题，不能仍叫“纯编号方案”。

**本批复默认建议采用 `C2_UNIT`。** 在 active 合同明确前，不得宣称 A/C 证据“完全等价”。

## 二、不可越过的边界

Codex 在任何阶段都不得做下面这些事：

- 不得据现有候选报告宣布 A 或 C 胜出；
- 不得把当前 41 题、旧冻结 48 题或其来源书籍混入训练；
- 不得在格式还没冻结时启动 500 本大规模抽数；
- 不得同时改格式、训练轮数、学习率、rank、解码和评分器；
- 不得把评分器放宽后的分数解释为模型已经可用；
- 不得把解析失败整案直接等同于“零语义能力”；
- 不得让选择器、切段器或 C 渲染器偷看金标后再决定分段；
- 不得用外部简介、分类页、网络搜索、同名原著记忆补正文事实；
- 不得让 `RIGHTS_PENDING`、`REFERENCE_ONLY` 来源进入实际训练；
- 不得覆盖冻结批次，发现问题必须新建修订版；
- 不得把聊天里的临时决定当长期状态，所有决定必须落文件。

## 三、执行路线与阶段闸门

### 阶段 0｜材料身份、现状和基线冻结

Codex 开工前必须完成：

1. 确认附件或仓库可读；
2. 列出顶层目录和 3～5 个关键文件；
3. 阅读 `00_ROUTE_MAP`、当前 live `active/requirements/`、当前 run state、decision log、open issues；
4. 写出材料身份表：当前真源、候选报告、旧冻结卷、当前成绩卷、训练资产、只读证据分别是什么；
5. 记录当前 A/C 数据、评分器、adapter、解码锁和考试卷 SHA；
6. 检查是否仍保留第一阶段 checkpoint；
7. 不做修改，先回传 `PREFLIGHT_RECEIPT.md`。

**阶段 0 通过条件**：

- 训练、验证、测试身份没有混淆；
- 旧 48 与当前 41 的隔离关系写清；
- 当前 live active 与本文件没有未报告冲突；
- 所有后续对照所需输入都有 SHA 或稳定 ID。

### 阶段 1｜先跑根因包里的三个最小证伪

严格按 `MINIMAL_FALSIFICATION_PLAN.md` 执行，每次只改一个变量：

#### 1A. 只换 checkpoint

- 第一阶段 checkpoint 对最终第二阶段 checkpoint；
- 同一基座、同一 41 题、同一解码、同一评分器；
- 观察格式、复读、漏字段、语义、证据定位；
- 用来判断全面遗忘、局部格式污染或基本无差异。

#### 1B. 只改 A 输出上限

- 仅跑 A 当前 22 个触顶案例；
- `2048 → 4096`，其他完全不变；
- 记录首个复读点、独立事实数、重复次数和最终 JSON；
- 用来确认 2048 是根因还是终止器。

#### 1C. 只改旧 C 题面范围写法

- 仅把题面标题里的 `@start:end` 改成不与输出同形的自然语言；
- adapter、输出合同、金标、41 题、解码不变；
- 观察抄标题范围比例和严格指针合法率；
- 用来确认题面外观诱导的贡献。

**阶段 1 通过条件**：

- 每个实验只有一个差异变量；
- 原始输出全部保留；
- 评分器同时报告严格层、诊断层和原始流复读层；
- 报告不把“未证实”写成“已排除”。

**此阶段不需要新增小说，不得与大规模抽数并行混在同一批变更里。**

---

### 阶段 2｜冻结 C+ 的输入、切段、映射和评分合同

这一阶段先用 30～50 个高质量既有窗口做原型，不训练大模型。

必须冻结的内容：

- A 唯一真源 schema；
- C-2 输入模板；
- `B/T` 局部编号规则；
- `HEAD / MIDDLE / TAIL / WHOLE` 窗口位置枚举；
- 只读上下文、证据桥接区、本段负责区的权限；
- 切段器版本和参数；
- `sample_id + local_id → global source span` 映射；
- `C2_UNIT` 还是 `C2_EXACT`；
- JSON 字段顺序、空值、事实排序、EOS；
- 评分层级和决策指标。

推荐的 C-2 输入：

```text
【窗口位置】MIDDLE

【只读上文】
无编号，只帮助理解，不能取证。

【证据桥接区】
[B01] 他此前曾答应同行。

【本段负责区】
[T01] 陈川终于点了点头。
[T02] “明早出发。”他说。

【只读下文】
无编号，只帮助理解，不能取证。
```

推荐的唯一输出：

```json
{"facts":[{"fact":"陈川决定明早出发","status":"计划","evidence_ids":["B01","T01","T02"],"speaker":"陈川"}]}
```

固定规则：

- `B` 只表示紧邻负责区之前、机械选出的桥接单元；
- `T` 表示本段负责区；
- `evidence_ids` 的最后一个编号必须是 `T`；
- 只读上下文没有编号，模型无法把它作为证据；
- 每个窗口都从 `B01/T01` 重新编号；
- 不输出全局书号、章节号、字符偏移、锚字、省略号；
- 后台凭 `sample_id + local_id` 做唯一映射；
- 事实对象字段顺序永远是 `fact → status → evidence_ids → speaker`；
- `speaker` 缺省统一为 `null`；
- 事实列表按最早证据位置排序；
- 一个回答只含一个 JSON 对象，末尾写入 EOS；
- C-2 从 A 机械生成，不允许人工手填另一套 `fact/status/speaker`。

**桥接区不能按金标挑。** 推荐固定为负责区前最后 0～3 个完整单元，数量由窗口位置和切段规则机械决定。否则 B 区本身会泄露“哪句可能是证据”。

**阶段 2 通过条件**：

- 同一原文连跑两遍切段结果和 SHA 完全一致；
- 所有单元都能反向定位并逐字还原；
- C-2 可由 A 全量重建；
- A/C 的 `fact/status/speaker` 逐条一致；
- C 的编号全部可见、可映射、顺序合法；
- 已报告 C 单元覆盖 A 字符证据时的额外带入量；
- 评分器与训练 schema 使用同一个合同版本。

---

### 阶段 3｜C-1 / C-2 / C-3 小探针

只使用同一批 30～50 个窗口，A 真值完全相同。

| 探针 | 唯一变化 | 目的 |
|---|---|---|
| C-1 | `[01]` | 最简编号基线 |
| C-2 | `[B01]/[T01]` | 检查角色前缀是否减少边界混淆 |
| C-3 | C-2 外加固定两字锚 | 检查锚字是否提供真实增益 |

执行纪律：

- 不允许三套都完整训练；
- 优先做静态渲染、可学习性检查、受限解码探针和极小规模格式试验；
- C-1 对 C-2 时只有编号外观不同；
- C-2 对 C-3 时只有锚字字段不同；
- 题面、事实、顺序、基座、seed、训练量、解码、评分器保持一致；
- C-3 的锚字若测试，只能是程序定义的固定两字符前缀，不能“任选 1～2 字”。

**推荐淘汰规则**：

- C-3 若不能显著减少错选编号，或只增加锚字格式错，直接淘汰；
- C-1 若桥接/负责边界错误明显多于 C-2，淘汰；
- C-2 仍为默认候选，但必须凭结果进入下一阶段，不能凭偏好直接晋级。

### 阶段 4｜建立 500 本候选池并先锁作者级分割

推荐目标：

- 约 400 本训练；
- 约 50 本验证；
- 约 50 本最终封闭测试；
- 实际以作者组为单位接近 `80/10/10`，不得为了凑书数拆开同一作者。

硬规则：

- 同一作者的不同作品不能跨 train/dev/test；
- 当前 41 题、旧 48 题及其来源作者全部隔离；
- 先完成作者归一、来源登记、权利状态和 split lock，再开始挑窗口；
- 任何 split 调整必须生成新锁版本，不能原地改；
- 只允许用 dev 错误决定后续补什么，sealed test 不能参与选样。

采样量：

- 每本基础 2 个训练窗口；
- 第 3 个只补题材、status、speaker、文本形态或难度缺口；
- 第 4 个只在确有独特教学价值时加入；
- 同一章通常 1 个，特殊情况下最多 2 个；
- 同一作者全部作品合计默认不超过 4 个训练窗口；
- 超过上限必须有书面例外原因。

来源构成建议：

- 近年、目标业务相似网文：75%～85%；
- 旧教材中确有独特价值者：15%～25%；
- “近年”的具体年份由 active requirement 明确，Codex 不得自行猜一个年份；
- 单一题材达到 35% 时预警，接近 40% 时必须解释；
- 不追求题材机械平均，优先匹配真实产品分布并给稀有结构留底线。

---

### 阶段 5｜首批约 100 本、200～300 个新窗口

推荐做法：

- 100 本为一批；
- 每本先完成 2 个窗口；
- 先不补第 3 个；
- 每个窗口通常 2～6 条事实，通常不超过 8 条；
- 高密度窗口优先重切，不靠模型一次吐十几条；
- 若产品需要学会空答，单独安排少量 0～1 条事实样本，不与普通样本混淆统计；
- 每 25 本或 50 个窗口写一次可恢复 checkpoint。

选择槽位不能只写“第一段、第二段、最后一段”，至少要同时记录：

- 全书进度；
- 章节内部位置；
- 文本形态；
- 事实密度；
- status；
- speaker 难度；
- 指代难度；
- 证据跨度；
- 噪声类型；
- 被选原因。

第一、第二窗口负责覆盖文风和位置；第三、第四窗口只允许由 dev 缺口驱动。

**阶段 5 通过条件**：

- 每个窗口都有完整来源、原文 SHA、选择槽位、atomizer 版本；
- 所有 A 金标经过独立语义复审；
- C-2 全部机械生成；
- split、作者、近重复、权利、映射、schema 校验全部通过；
- 返修原因和被淘汰样本仍保留审计记录。

### 阶段 6｜首轮 A / C-2 成对 LoRA

只允许比较：

- A：逐字 evidence；
- C-2：局部 `B/T` 编号。

二者必须共享：

- 同一批小说和窗口；
- 同一 `fact/status/speaker`；
- 同一 train/dev/test split；
- 同一基座、chat template、LoRA 配方、seed、样本顺序和阶段策略；
- 同一评分器版本和同一推理参数。

唯一设计差异是 evidence 表示。

报告中必须同时给：

- 行数、事实数、输入 token、目标 token；
- 训练步数、实际消费 token、截断数；
- JSON 有效率；
- 完成率、复读率、触顶率；
- fact 召回、过抽、归一化匹配；
- status、speaker；
- A 逐字证据合法率；
- C 编号结构合法率；
- C 映射后的字符覆盖和额外带入量；
- 按题材、作者、文本形态、位置、status、speaker、证据跨度分层的结果。

⚠️ A/C 输出长度不同会造成目标 token 量不同。第一轮可以保持相同行、相同 epoch 和相同步骤，比较产品实际表现；但报告必须把 token 暴露差异写出来，不能把所有差异都归因于格式。需要研究纯格式学习难度时，再另开 token 归一化实验，不和首轮混做。

---

### 阶段 7｜每增加约 200 个窗口做一次扩数判断

循环：

```text
新增约 200 个窗口
→ 全量机械与语义验收
→ 同配方训练/验证
→ 只看 dev 错误清单
→ 决定哪些书补第 3 条
→ 更新覆盖缺口
```

扩数不是自动继续。满足下面任一情况应停：

- 新增数据没有改善主要错误；
- 复读或漏字段反而增加；
- 格式合同仍在变；
- 某一题材、作者或模板占比失控；
- 大量新增样本只重复已有简单模式；
- 错误主要来自训练/解码而不是覆盖不足；
- 权利状态或来源追踪不完整。

---

### 阶段 8｜最终冻结与一次性 sealed test

只有在下面条件满足后才允许打开最终封闭测试：

- C+ 合同和 evaluator 已冻结；
- 训练、验证结果稳定；
- 不再根据 sealed test 返补训练；
- 数据和训练 run 都有完整 SHA、manifest、日志和原始输出；
- CZ 明确同意进入封闭评测。

一次 sealed test 后若失败，只能进入下一版本项目，不能继续在同一 test 上反复调参并仍称“封闭”。

## 四、训练和格式必须提前修好的事项

### 1. 正向与特殊样本使用完全相同的容器

不得再出现：

- 第一阶段 `fact` 在前；
- 第二阶段 `evidence` 在前；
- system 提示、user 容器、JSON 键序不同；
- speaker 有时省略、有时写“无”、有时为 null。

推荐把正向与特殊样本混合打散训练。若仍保留两阶段，至少：

- 第二阶段保持同一 schema；
- 混入固定比例的正向回放；
- 保留第一阶段 checkpoint；
- 同卷比较 stage1 与 final；
- 不在未比较前宣称发生或未发生遗忘。

### 2. 检查训练 chat template 与停止学习

每个训练 run 必须记录：

- system/user/assistant 模板版本；
- loss mask 是否只覆盖 assistant；
- assistant 最后一个 `}` 是否未被截断；
- EOS 是否确实追加；
- padding、packing、truncation 策略；
- 最大序列长度下被截断的样本 ID；
- 是否存在重复拼接同一 assistant 回答；
- 训练和推理模板是否一致。

### 3. 解码不能与训练问题绑在一次实验里

- 调 `max_output_tokens` 时不同时加 repetition penalty；
- 加受限 JSON 时不同时换 adapter；
- 调 temperature 时不同时改 prompt；
- 重试策略属于产品修复，不得掩盖原始一次生成指标；
- 所有重试前原始输出必须保存。

## 五、评分器必须改成分层诊断

不得再只给一个“严格三元组 F1”。至少分成：

1. **传输层**：是否有输出、是否触顶、是否正常结束；
2. **JSON 层**：原始 JSON 是否有效、是否需恢复；
3. **schema 层**：字段、类型、顺序和枚举是否合法；
4. **复读层**：完整对象重复、字段模板重复、连续片段重复；
5. **语义层**：fact 精确匹配、归一化匹配、召回、过抽；
6. **status 层**：只在配对事实后判断；
7. **speaker 层**：只在配对事实后判断，null 口径统一；
8. **证据结构层**：可见 ID、顺序、重复、桥接终点、越界；
9. **证据内容层**：映射后是否支持事实、覆盖金标多少、额外带入多少；
10. **案例层**：整案是否达到可用标准。

严格分继续保留，但必须与诊断分并列。解析恢复后的对象只作为诊断，不得冒充正式一次生成成功。

所有胜负阈值必须在看结果前写入 `DECISION_THRESHOLDS.md`。不得跑完再挑有利指标。

## 六、立即停工条件

出现下面任一情况，Codex 必须停止扩数，写 `BLOCKER_REPORT.md`：

- active 规则与本批复冲突；
- A 与 C 派生后 `fact/status/speaker` 不一致；
- 切段两次运行 SHA 不一致；
- unit map 不能逐字反向还原；
- B 区是按金标选择，不是机械邻接；
- 训练或考试出现作者、书籍、章节泄漏；
- 当前 41 或旧 48 被混入训练；
- schema、field order 或 prompt 在同一冻结批中变化；
- 批次中存在来源或训练权利不明却进入 train；
- 高比例样本需要人工改 C，而不是程序重建；
- 评分器版本在同一对照中途更换；
- 一次实验改动超过一个变量；
- 原始输出、日志、manifest 或 SHA 缺失。

## 八、不能下的结论

- 不能因为旧 C JSON 成功率高，就说 C 语义更好；
- 不能因为 A 截断多，就说逐字证据天然不可行；
- 不能因为 C-2 输出更短，就说它与 A 字符证据无损等价；
- 不能因为 200 条 pilot 有改善，就直接推断 1,200 条一定继续线性改善；
- 不能因为新小说更多，就认为数据天然更高质量；
- 不能因为每本样本少，就自动排除作者风格过拟合；作者级 split、近重复和模板分布仍要检查；
- 不能在 sealed test 上反复返修后仍把它当一次性封闭评测；
- 不能把顾问报告直接当 CZ 的最终拍板。
