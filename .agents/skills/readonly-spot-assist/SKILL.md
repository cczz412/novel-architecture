# 只读点检协助

主窗口继续做重点活。下面三类杂活可以派子 Agent，回来只交短结论。

这不是第二施工窗口，也不是一直转的检查器。感觉哪儿容易踩坑，才查那一处。

## 什么时候用

同时成立才启用：

1. 主窗口已经有正事（领票、改写集、对口径、写回执）；
2. 要做的是探路、搜文档、或收尾点检之一；
3. 子 Agent 只需读，不需要改文件。

## 什么时候不用

- 主任务本身就是读两三个已知文件：主窗口自己读。
- 要改代码、改治理页、提交、开 PR、合并。
- 训练、模型 API、Gold、搬删、退出 Git、生产晋升。
- 想「全程挂着盯着别犯错」：不要开循环点检。
- 想用 Grok 4.6、Fast、或其他名单外型号顶这个位置。

## 子 Agent 固定配方

- 模型：Grok 4.5 非 Fast。Task 的 `model` 只填 `cursor-grok-4.5-high`。不要 `inherit`，不要 `cursor-grok-4.5-high-fast`。
- 权限：只读。禁止改工作区、禁止 `git` 写、禁止开 PR、禁止调会花钱的模型 API。
- 回报：几段人话 + 可点的仓内相对路径。不要把长日志糊回主窗口。

| 位置 | `subagent_type` | 派它干什么 |
|---|---|---|
| 探路摸仓库 | `explore` | 找入口、目录职责、某条线从哪读到哪。thoroughness 默认 `quick`，主窗口说要更全再用 `medium`。 |
| 搜文档 | `explore` | 按关键词或文件名找 README／治理页／合同，把现行入口和过期页分开。 |
| 收尾点检 | `generalPurpose` | 只核对主窗口点名的易错处，例如写集是否越界、禁区、真源是不是认错。 |

不要用 `computerUse`、`videoReview`、`best-of-n-runner` 干这三件事。

## 怎么派

主窗口写清：要查什么、已知路径、不要碰什么。子 Agent 找不到就报「没找到」，不要扩大成全仓扫描，也不要替主窗口拍板。

收尾点检只覆盖点名的风险。主窗口没说的条目，不要自己加一轮「更放心」的检查。

## 主窗口还管什么

子 Agent 的结论只是提醒。认不认、改不改、要不要再查一处，仍由主窗口按工单和 `governance/CURRENT_STATE.json` 决定。本 Skill 不能扩大业务授权。
