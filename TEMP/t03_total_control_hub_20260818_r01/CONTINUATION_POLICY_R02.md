# 五窗不停机续跑规则 R02

这个主要解决“大家做几分钟就一起停下，排队等一个共享页面”的问题。

## 总控收到阶段回执后的顺序

1. 只做目录、JSON、SHA、API/retry、正式写集和权限的最小检查。
2. 判断有没有一张前置齐、写集独立、不会碰红线、能产生新信息的长阶段票。
3. 有就先派，随后把上一阶段回执排进共享 ChatGPT。
4. 没有才把该窗记成有意空闲或真实决策停点。

## 不能拿来续跑的假任务

- 重跑刚过的同一批测试；
- 为了让窗口显示 ACTIVE 而扩字段、扩治理或写更多说明；
- 替其他 owner 做定义；
- 共享 ChatGPT 已明确判定新增信息耗尽的同类离线壳；
- 尚未得到 CZ 明字的新书、Gold、API、模型、R13、产品大范围施工、训练、生产、上传和作者真值；以及任何不满足 `CZ_AUTO_AUTHORIZATION_20260819_R01.md` 四条件的正式合同修改。

## 当前节奏

- 每窗尽量一次做完一个完整对象，再发回执；不追求固定分钟数。
- 普通共享复核在后台串行跑，不打断已派的安全工作。
- 新失败和真实政策选择优先审；普通 PASS 可以排队。
- 有意空闲不是故障。没有真实新增信息时，空闲比重复劳动更有效率。
