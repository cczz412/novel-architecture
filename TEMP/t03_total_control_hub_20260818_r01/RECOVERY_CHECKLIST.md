# 总控恢复清单

总控发生重载、崩溃或上下文压缩后，按这个顺序恢复：

- [ ] 确认当前 CZ 指令没有覆盖本工作台。
- [ ] 读取 `CONTROL_STATE.json`，不要先翻聊天历史。
- [ ] 用线程状态工具核对五个线程的 active／idle；状态不同就先更新工作台。
- [ ] 检查共享 ChatGPT 页面队列有没有 `SENT` 但未 `ROUTED` 的项目。
- [ ] 检查页面是否仍是线程 `6a8389d0-e72c-83ea-9154-c0b749614b3e`。
- [ ] 一次只恢复一个共享页面回合。
- [ ] 每份未路由的阶段完成 capsule 都进入共享页面队列；不要由总控先写完整替代判断。
- [ ] 检查 A／B 的主工作树写集是否冲突。
- [ ] 检查 Notion 队列是否已经有回包，避免重复上传。
- [ ] 检查 Pro 队列触发条件，没达到就不打包。
- [ ] 机器门正式修复先逐条核对 `CZ_AUTO_AUTHORIZATION_20260819_R01.md` 四个条件；其他正式合同修改和任何 Gold、R13、产品大范围施工、训练、生产、上传、作者真值动作，都回查 CZ 明字。

不能做的事：

- 不根据线程标题猜当前任务。
- 不把 ChatGPT／Notion 的建议直接当执行票。
- 不让工作窗口自己操作共享网页。
- 不同时向共享页面发送两窗内容。
- 不把总控变成第二个深审模型；总控只做身份、证据、红线和写集检查。
- 不为“保持五窗都忙”制造重复工作。
