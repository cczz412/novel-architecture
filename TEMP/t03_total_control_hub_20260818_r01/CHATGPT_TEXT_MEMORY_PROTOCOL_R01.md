# ChatGPT 纯文本记忆流 R01

这个主要解决两件事：让 ChatGPT 帮我们消化阶段回执，也让项目记得“已经迈过哪些大步”。

## 页面只分两类

1. **快速调度页**：现有“全局深审与分拆建议”。每次只处理一个窗口，主要给下一步思考草稿。
2. **里程碑编辑页**：攒够一小批已核回执后再发，负责把零散阶段整理成里程碑和工程背景候选。

ChatGPT Pro 不常驻。等多条管线积累到需要跨阶段总审时，另开一次临时 Pro 审查；完成后收口，不把它当第三个日常页面。

## 每次只收六个文本篮子

ChatGPT 必须按下面顺序返回六个独立代码框；没有内容就写 `NONE`。

1. `B1_NEXT_ACTION`：当前窗口下一段工作的草稿。
2. `B2_CONFIRMED_FACT_CANDIDATES`：它认为已经被材料证实的事实候选。
3. `B3_ENGINEERING_BACKGROUND_CANDIDATES`：以后多个窗口都可能复用的稳定结论候选。
4. `B4_MAJOR_MILESTONES`：真正改变路线、合同边界、消费者关系或验证结论的大步进展。
5. `B5_CZ_DECISIONS`：只有 CZ 能拍的事项；没有就写 `NONE`。
6. `B6_RESEARCH_BACKLOG`：适合以后交 Notion、Pro 或 Deep Research 的问题；日常不立刻外发。

## 本地怎么收

- 原回答完整保存并计算 SHA，属于原始回执层。
- B1 只在身份、轮次、权限和写集检查通过后，才能转成给窗口的执行草稿。
- B2、B3、B4 先当候选；总控用本地结果票和机器回执核对后，才能写进对应账。
- B5 进入 CZ 决策队列，沉默不算红线授权。
- B6 只积攒，达到批量触发条件再外发。

## 哪些内容才配进背景板

每条至少写清五件事：结论、适用范围、证据指针、什么情况会失效、最近核验时间。

下面这些不进：普通 PASS、临时文件名、单次格式错误、尚未裁决的模型意见、只对一张小票有用的施工细节。

## 哪些内容才算里程碑

- 一条路线被证明可行或被正式止损；
- 一个正式合同边界或真实消费者关系被重新确认；
- 一个跨窗接缝被发现并改变后续顺序；
- 一批外部证据被吸收并真正改变当前路线；
- 产品从设计候选进入可原型、可冻结或明确不就绪的新阶段。

## 省额度的边界

适合交给 ChatGPT：长回执归纳、跨窗差异、下一阶段任务草稿、里程碑抽取、查缺补漏。

不适合交给 ChatGPT：文件是否存在、SHA 是否匹配、Git 当前状态、API 是否真的调用、正式权限是否存在。这些仍由本地做最小机械检查。
