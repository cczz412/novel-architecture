## 总判断

✅ **R10 v0 的主体方向能用，但目前只够支撑“有人盯着的半自动工作台”，还不够支撑六条下游黑盒自动跑。**

五个场景里，分镜取数最好用，互动叙事最危险。真正会把系统带歪的，不是少几个业务字段，而是下面四个横切问题还没有进入核心格式：

1. **作用域不够**：缺 `世界实例／分支／角色身份层／谁知道这件事`。
2. **不确定性不够**：缺“观察事实、系统确认、人物猜测、人物证词、推断规则”的区分。
3. **连续状态不够细**：任务倒计时、弹药、装备当前状态、章末正在发生但尚未出结果的动作，都不能稳定回放。
4. **正文导入不会形成 Hook 候选**：这与“正文导入后续写”场景直接冲突。

按本次试装给一个直观分数：

| 场景 | 当前好用度 | 判断 |

| ① 第 21 章续写取数 | 6.5/10 | 能人工出单，不能放心直写 |
| ② Hook 到期巡检 | 5/10 | 生命周期方向对，导入与触发机制缺口大 |
| ③ 分镜具名视图 | 7/10 | 方向最稳，补揭示时机和视觉连续即可 |
| ④ 互动分支 | 4/10 | 缺分支作用域，容易串账、提前兑付 |
| ⑤ 作者建议层 | 6/10（局部）／3/10（偏航） | 局部诊断可用，全书偏航缺规划材料 |

🔥 **最该补的不是再加一类对象，而是给所有对象统一加四组坐标：**

```
knowledge：known_by / revealed_to_reader_at
```

## 取数别扭处

1. **同一个续写请求至少要联查四个账域**：本体变化流、Hook 账、体验账、作者规划账。
如果这些账不在同一版本封套里，同一个第20章可能生成不同合同。
2. **第20章末不是稳定状态，而是进行中的动作。**
常规“章末快照”无法表达“斧已出手、已接触还是尚未接触、结果必须由下一章开头回答”。
3. **战斗资源无法完整回放。**
第16章只给出模糊总量，第18、20章存在多次“持续射击／换弹”，无法得出准确余量。
4. **长线 Hook 需要按世界过滤。**
钱华路与官方调查属于现实殷市，不应在隐山村战斗最紧张时被到期器硬塞进来。

## 账写不进处

- 李昂＝真实玩家身份，冯铁锤＝剧本角色身份，目前只能勉强塞进实体别名或状态事实。
- 黑僵的“进化触发条件”并不确定，既不适合写成确定规则，也不只是普通事件。
- 面具抵抗是否与对方感知有关，是李昂猜测。
- 章末斧击是 `pending_event`，不是已完成 `event`，也不是稳定 `state_fact`。
- “读者知道、李昂不知道”的官方调查线，目前没有统一位置表达。

## 代价与风险

- 增加状态对账会多一个停点，小白作者可能嫌麻烦。

- 资源账做得太细会产生维护负担，尤其是普通网文并不需要每颗子弹都精确核算。

推荐只追踪**会改变剧情选项的资源**。例如：

- “霰弹至少还有一发”需要追踪。
- “准确还剩17颗钢珠”没有必要。
- 可以用 `exact／range／approximate／unknown`，而不是只允许一个数字。

# 三、场景②｜Hook 到期巡检

## 结论

⚠️ **T3 的生命周期方向能用，但 T2 规定“future_obligations 记上不抽”，会让正文导入场景直接丢失最重要的存量 Hook。**

正文导入不应把模型发现的 Hook 直接记成真账，但必须产出一层：

```
candidate_obligations
```

由程序或作者确认后，再进入正式 Hook 账。

否则本次导入后，系统很可能只知道“当前任务0/1”，不知道：

- 第11章官方说处理完钱华路后回来调查学校；
- 第16章任务有三小时限制；
- 第16章承诺稀有技能卷轴；
- 第12章钱华路异常仍在升级。

| `H-SHOP-ROADMAP` | 第9章商城后续功能 | 世界路线图 | `dormant_low` | 系统版本变化 |
| `H-ENDGAME` | 第7章最终任务失败会灭绝玩家物种 | 全书级宏观承诺 | `dormant_long` | 全球游戏进度进入终局 |

### B. 不建议登记成正式 Hook 的东西

| 线索 | 为什么不该进正式 Hook |
| --- | --- |
| 第15章李昂猜官方可能治疗钱建军 | 有“也许”，人物推测，读者兑现压力很低 |
| 第16章新来的年轻女班主任 | 只有出场事实，没有明确事件承诺 |
| 第16章面具可能受观察者感知影响 | 这是规则假说，不是未来事件 |
| 第9章附身鬼描述死后世界 | 人物证词，不是剧情义务 |
| 第10章李昂猜高等级玩家很多 | 世界压力推测，不是必须兑现的事件 |

### C. 模拟“剧情内时间到触发点”

假设外部故事时钟把任务推进到“剩余十分钟以内”。

查询条件应类似：

```
scope.world_instance = 隐山村剧本
scope.branch_id = main
change_keys =
  task:饥饿极限
  entity:黑僵
  story_clock
  combat_resources
```

巡检结果应该是：

1. `H-TASK-TIMER`
    - `scheduled → eligible`
    - 优先级：最高。
    - 给编排器的指令：不得新增长篇探索、回忆或新支线；必须推进任务终局。
2. `H-TASK-KILL`
    - 保持 `eligible`。
    - 与倒计时合并成一个执行包，不重复提醒作者两遍。
3. `H-TASK-REWARD`
    - 仍为 `scheduled`。
    - 只在击杀事件成立后进入 `eligible`，不能提前生成技能内容。
4. `H-ZOMBIE-EVOLVE`
    - 输出风险提示，不强迫兑现。
    - 提示：“若继续让目标进食或继续承受同类伤害，可能出现阶段变化；因果未确认。”
5. `H-QIANHUA`、`H-OFFICIAL-RETURN`
    - 因世界作用域不符，本轮不进入续写包。

如果任务时间已经超过三小时，但任务状态仍是0/1，应进入异常态：

```
overdue_unresolved
```

不能默默继续写。

---

## 取数别扭处

- 当前 Hook 账需要同时理解故事时间、任务系统、世界实例和读者期待，不只是查一个日期。
- 钱华路是“中线承诺”，官方回查是“条件义务”，商城更新是“世界路线图”，三者不能都用同一种到期算法。
- 黑僵进化是风险，不是作者向读者许下的必兑事件。

---

## 账写不进处

当前生命周期缺少清晰的 Hook 类型。建议至少区分：

```
hard_deadline
conditional_obligation
reader_promise
reward_obligation
risk_watch
world_roadmap
turn_hook
```

还需要异常态：

```
blocked_missing_clock
conflicted
orphaned
invalidated
branch_diverged
overdue_unresolved
```

---

## 合同缺字段处

Hook 条目建议补：

```

scope.branch_id
knowledge_scope

condition_expression

```

尤其要补 `reader_salience`。不然商城社交大厅和三小时抹杀压力可能被排到同一层。

---

## 程序钩子缺位处

- 正文导入后的 Hook 候选抽取。
- 候选 Hook 人工确认／批量拒绝。
- 故事时钟发出 `change_key`。
- 任务目标变更触发奖励 Hook。
- 世界和分支过滤。
- Hook 合并去重。
- 低显著度世界承诺降噪。
- 到期但缺关键状态时，转异常而不是自动脑补。

---

## 代价与风险

- 半抽取 Hook 会带来误报，尤其是人物猜测和普通伏笔。
- 如果每句话都登记，作者工作台会变成待办事项轰炸。
- 如果过度追求“章章清债”，又会把长线悬念提前兑现。

推荐做法是：

- 模型只产候选。
- 程序用证据强度、措辞、读者显著度筛一遍。
- 正式 Hook 账只收作者确认或高置信系统义务。

---

## 反面核查

巡检结果出现下面情况，说明 Hook 系统做歪：

- 正在隐山村决战，却建议推进钱华路。
- 商城后续功能压过三小时任务时限。
- 把黑僵“可能继续进化”强制安排成下一章必发生。
- 黑僵死亡后，任务奖励仍停在 `scheduled`。
- 互动分支 A 已击杀黑僵，分支 B 的任务也被全局标成已完成。
- 导入 20 章后完全找不到第11章官方回查承诺。

# 四、场景③｜分镜线具名视图合同

## 结论

✅ **T8 是十二条里当前最稳的一条。第20章可以顺利形成分镜取数单，但必须补“揭示时机、叙事呈现模式、镜头内状态变化”三个维度。**

我选择第20章，而不是虚构第21章。它包含：

- 对话回忆；
- 角色隐藏后再揭示；
- 道路转树林；
- 载具灯光变化；
- 怪物肢体状态在章内改变；
- 精准章末动作钩子。

这些正好能测出具名视图是否真的可用。

### 具名视图

```
source_unit：chapter_20
```

## A. 必填取数

### 1. 三个场景块

| 场景 | 主要内容 | 必须保住的体验 |
| --- | --- | --- |
| S20-01｜盘山公路复仇 | 黑僵逼近；冯铁根求饶并回忆母亲救活全家的往事；黑僵短暂停顿、拥抱、勒死、进食 | “似乎认出儿子”的假缓和，立刻反转成死亡 |
| S20-02｜李昂现身 | 李昂从树林出现，说明自己看了十几分钟；认定冤仇已清；黑僵只剩饥饿 | 主角道德立场与冷静感 |
| S20-03｜公路到树林战斗 | 车灯熄灭、黑僵突袭、霰弹击退、李昂退入树林、黑僵嗅闻、树上伏击、左臂骨碎、斩颈 | 现代战术＋面具规则＋近身破防的连续爽点 |

### 2. 角色视觉状态

| 实体 | 取数要求 |
| --- | --- |
| 李昂 | 17岁；全套战术装备；变脸面具；短管霰弹枪；野营斧；面具图案正文未指定 |
| 黑僵 | 瘦削女性尸体；黑毛；单眼；长指甲；嘴部残缺；已进食，皮肤和毛发更有光泽 |
| 冯铁根 | 额头流血、脸和手擦伤、左脚踝骨折、尘土鼻涕泪水；衣着正文未明确 |
| 张翠芳 | 第19章已死并被开膛，属于环境连续物，不应在第20章后半段突然消失得毫无痕迹 |
| 货车 | 撞在石质防护桩上，冒烟；车灯从闪烁到熄灭，是黑僵发动攻击的视听触发点 |

### 3. 章内状态变化

分镜视图不能只拿章末实体快照，还要拿逐拍变化：

```
黑僵左臂：
正常可战
→ 斧刃切入桡骨
→ 枪口贴近尺骨
→ 骨骼粉碎、手臂耷拉
→ 黑毛仍尝试缠住斧头
```

如果只读取“章末左臂受伤”，分镜很容易提前画成残臂，或错误画成完全不能动。

### 4. 揭示时机

第20章开头不能提前画出躲在树林里的李昂。

正确数据应是：

```
fact：李昂已在树林观察十几分钟
reader_reveal_at：S20-02
known_by：
  李昂 = true
  黑僵 = false
  冯铁根 = false
  读者 = 到S20-02才知道
```

这不是普通事实字段能解决的，是悬念控制字段。

### 5. 回忆／证词模式

冯铁根讲母亲在饥荒中吞豌豆、回家吐给家人吃，这段若漫剧决定画成回忆蒙太奇，必须标：

```
presentation_mode：visualized_testimony
story_time：过去
narration_order：当前对话中插入
claim_status：character_testimony
source_speaker：冯铁根
```

不然下游会把它当成当前场景，或者当成全知旁白确认过的历史事实。

### 6. 规则约束

- 黑毛可以阻滞子弹。
- 近距离霰弹仍可把骨骼打碎。
- 面具削弱存在感可骗过黑僵搜索。
- 黑僵速度极快，能跨越十余米。
- 黑僵左臂骨碎后，黑毛仍能活动。
- 不得把面具画成真正透明／隐形；正文表现是“难以注意”，不是光学隐身。

### 7. 高光三连挑

本章正好适合三连：

1. **拥抱反杀**：黑僵似乎恢复母性，下一秒将亲儿子勒死。
2. **车灯熄灭突袭**：灯光暗下的瞬间，黑僵跨越十余米近身。
3. **树梢伏击破臂斩颈**：面具隐藏→从天而降→贴臂开枪→斩向脖颈。

### 8. 章末画面锁

```
李昂右手斧头再次挥出
目标：黑僵脖颈
结果：未展示
画面截断点：斧击命中或即将命中的瞬间
禁止：提前显示头颅落地、任务完成、系统奖励
```

- 李昂早已在场，却必须延后给读者看。
- 冯铁根回忆既能画，又不能混成当前时空事实。
- 同一个黑僵左臂在一章内经历多次状态变化。

## 账写不进处

- 镜头资产编号、固定面具造型、场景布局属于改编连续，不应写回故事事实。
- 但这些改编决定又必须跨镜头、跨集保持一致，不能只存在一次性生成提示词里。
- 所以 T8 的适配层需要自己的**改编版本真账**，而不是临时缓存。

推荐层次：

```
故事真账：李昂戴着会随机变图案的变脸面具
改编真账：漫剧版本A，第20章面具采用某固定图案
镜头产物：具体构图、景别、光影
```

- 悬念揭示时机校验。

- 把冯铁根回忆直接标成客观历史闪回。
- 黑僵在左臂被击碎前就画成断臂。
- 斧击脖颈后继续展示任务完成，破坏原章钩子。
- 面具表现成透明隐身。
- 第20章前半段就让车灯完全熄灭。
- 为了固定“三个高光”删掉拥抱反杀，或硬加新怪物。

# 五、场景④｜第20章末互动叙事分支

## 结论

❌ **这是当前设计最不能直接上线的场景。**

`story_time＋narration_order` 不能承担互动分支。必须给所有变化流、状态、Hook、合同、暗稿增加：

```
branch_id
parent_branch_id
divergence_point
canon_status
branch_local_time
merge_policy
```

否则某条分支杀死黑僵后，其他分支也会把任务标成1/1；某条分支支付了稀有技能奖励，其他分支的奖励 Hook 也会被提前关闭。

---

## 可操作方案

### A. 第20章末给读者的三个选项

三个选项只使用包内已有状态和装备，不引入新人物、新能力、新地点。

| 选项 | 读者看到的文案 | 实际策略差异 |
| --- | --- | --- |
| A｜趁伤强斩 | “左臂已废，继续贴身斩颈，不给它恢复机会。” | 时间成本低，近战风险高，资源消耗低 |
| B｜再次消失 | “松开斧头，借面具退入黑暗，重新制造伏击。” | 受伤风险较低，时间成本高，可能触发任务倒计时压力 |
| C｜火力剥甲 | “拉开距离，用剩余爆炸物先撕开黑毛防层。” | 资源成本高，可能再次刺激进化；需确认爆炸物可用状态 |

这三个选项不是换三种说法，而是分别改动：

- 风险；
- 时间；
- 资源；
- 黑僵可能状态；
- 后续可用战术。

### B. 假设读者选择 A

下面是**本次模拟大纲增量，不代表原作第21章**。

```
branch_id：B20-A
parent_branch_id：main
divergence_point：ch20.end.pending_axe_strike
canon_status：interactive_candidate
world_instance：饥饿极限剧本
```

#### 新增 narrative unit：`NU-21A-01｜近身决断`

1. 第20章末的斧击结果立刻揭示：斧刃切入黑毛与脖颈，但未一击断首。
2. 黑僵依靠右臂、身体冲撞和仍能活动的黑毛反扑。
3. 李昂利用黑僵左臂骨碎造成的单侧空档继续贴身斩击，不调用新技能。
4. 第二次有效斩击破坏颈部结构，黑僵失去行动能力并被完成击杀。
5. 系统目标由 `0/1 → 1/1`。
6. 本增量只推进到“奖励结算开始”，不生成稀有技能卷轴的具体内容。

#### 新增事件

```
E-A01：章末斧击得到结果
E-A02：黑僵以右侧反扑
E-A03：李昂利用左侧防御空档完成终结
E-A04：任务目标计数更新
E-A05：奖励义务转为 eligible
```

#### 状态增量

```
黑僵：
  alive：true → false
  left_arm_bone：shattered（沿用）
  hair_activity：active → inactive_after_death
  mission_target：pending → completed

李昂：
  world_instance：不变
  role_binding：冯铁锤，不变
  new_skill：无
  new_item：无

任务：
  target_count：0/1 → 1/1
  settlement：not_started → started
```

#### 体验账增量

```
第20章即时钩子：paid
“现代武器＋规则利用”爽点：paid
任务完成期待：paid
稀有技能卷轴期待：eligible，尚未支付
章末钩子候选：任务评级／技能卷轴揭示
```

#### Provenance

```
origin_type：interactive_reader_choice
choice_id：A
source_refs：ch20末态＋ch18/20已验证战斗机制
fiction_status：simulation_only
```

### C. 分支如何挂回已有账

不能复制整本大纲，而应使用覆盖层：

```
main@ch20
└── B20-A
    ├── events_delta
    ├── state_delta
    ├── hook_delta
    ├── promise_payoff_delta
    └── branch_snapshot
```

读者下一次选择时，查询的是：

```
materialized_state(main@ch20 + B20-A)
```

而不是修改 `main@ch20`。

某条互动路线被作者选为正式版本时，再执行显式操作：

```
canonize(B20-A)
```

不能自动把分支合回主线。

---

## 取数别扭处

- 选项 C 需要知道爆炸物是否仍可用；正文只能确定“制造过多枚、用过一枚”，无法给准确数。
- 选项 B 要消耗时间，但任务剩余时间未知。

# 七、第五节必答题中，我有把握的建议

### 结论

✅ **必须保留。置信度：0.98。**

## 2. 新逻辑句条目格式

### 结论

✅ **不要再做一条自由文本“逻辑句”，改为“条件—变化—后果—义务”。置信度：0.91。**

### 可操作方案

```

scope：在哪个世界／分支
subject：谁或什么
change：发生什么状态变化
because：已确认原因；未知可留空

```

第11章官方回查可写成：

```
obligation：官方重新调查实验中学
certainty：character_declared_plan
```

### 代价与风险

### 反面核查

## 5. Hook 冲突裁决七序＋爽点账／钩子账

### 结论

✅ **“章末钩子、未来义务、爽点兑现”必须分开。置信度：0.96。**

第20章斩颈结果是章末钩子；第11章官方回查是未来义务；第16章稀有技能卷轴是奖励兑现义务。三者不能共用一个模糊的 Hook 类型。

### 可操作方案

建议分为：

```
turn_hook：翻下一章的即时问题
future_obligation：以后必须或可能发生的事件
reader_promise：读者在等待什么
payoff：哪件事兑现了什么期待
risk_watch：可能恶化的状态
```

冲突裁决建议顺序：

1. 已发表锁定事实与当前分支。
2. 作者明确硬意图。
3. 当前场景因果、生命危险、任务时限。
4. 已确认规则与资源限制。
5. 到期的读者承诺和奖励义务。
6. 当前故事线里程碑与全书规划。
7. 情绪疲劳、套路变化、长线可选点子。

同序冲突时：

- 选更少改动已发表事实的；
- 选更可逆的；
- 缺证据则降级为建议，不自动排期。

### 代价与风险

分类增加；旧 Hook 数据需要迁移。

### 反面核查

把第20章场景送入裁决器，看它是否会：

- 先回答斩颈结果；
- 优先处理三小时任务；
- 暂时过滤钱华路；
- 不提前生成技能卷轴；
- 不把黑僵进化风险当成必发事件。

- 作者界面可以展示成“第八本规则账”，但数据不能复制存两份。
- 规则条目必须带适用范围和可信度。

### 代价与风险

视图需要实时聚合；查询会多一步。

### 反面核查

修改古怪眼珠精神力消耗规则，看：

- 本体规则；
- 体验合同；
- 分镜；
- 作者规则界面

是否全部同步。如果需要人工改四处，说明形成了重复真账。

## 9. 偏航判定口径

### 结论

⚠️ **没有作者规划账时，系统只能判连续性偏航，不能判战略偏航。置信度：0.92。**

### 可操作方案

分三类：

```
hard_drift：
  违反已发表事实、规则、分支、世界作用域

schedule_drift：
  已声明里程碑超出作者给定窗口

exposure_drift：
  重要承诺长期不露出，但尚未错过硬窗口
```

没有 T6 目标时：

```
strategic_drift = unknown
```

不能自动写“作者偏航”。

### 代价与风险

系统会少给一些看似果断的建议。

### 反面核查

仅输入前20章、不输入全书计划，看系统是否敢断言“钱华路线已经偏航”。如果敢，判定口径仍在越权。
