# V02｜五书前五章试装压测

## ✅ 总结论

**ZIP 校验通过。**

- 实测 SHA256：`ce16b8172b4a507b2f3887c3c5dc69bfec28067c702d096c66f53a92ab806e10`
- 与任务给定值完全一致。
- 包内 25 个章节文件的大小与单文件 SHA256，也全部通过 `00_书单清单.json` 校验。
- 《一品世子妃》第 2 章原文件确实停在一句未完成的话上。它的单文件哈希仍与清单一致，因此不是解压损坏，而是**源文件自身不完整**。

**结构总判断：厚描三件套没有走歪，可以继续当唯一中枢。**

25 章都能用“章内变化流＋章末快照＋章间交接”抓住商业阅读所需的推进、爽点、规则与钩子。没有发现需要推翻 T1、改回多种中间格式的证据。

但当前 v0 有 **3 类 A 级缺口**。这里说的“装不进”，不是指不能把原文塞进 `narrative_units`，而是指塞进去以后，下游仍无法无歧义地知道：

1. 事情发生在哪条时间线、哪层现实、哪次副本；
2. 某句话是客观事实、人物猜测、系统宣告，还是后来已被推翻的解释；
3. 同名／同角色的对象究竟是同一个人、复制体、前世版本，还是疑似对应物。

🔥 **推荐不增加第十类叙事对象。**
在九类对象上统一增加两个共用头即可：

```yaml
context_ref:
timeline_id:        # 哪条时间线
iteration_id:       # 第几轮人生／重置前后
reality_layer_id:   # 现实、诡异空间、游戏世界、幻境等
instance_id:        # 哪一次副本／哪次重复事件
story_time:
narration_order:

assertion:
mode:               # 观察、人物陈述、推断、系统宣告、作者旁白
truth_status:       # 已确认、暂定、争议、已推翻、未知
knowledge_holders:  # 谁知道／谁相信
confidence:
supersedes_refs:    # 推翻或修正了哪条旧判断
```

这两个共用头不改变“大纲唯一中枢”，只是在真账上补足坐标和真假层级。

> 下文证据编号 `¶`，按 ZIP 中文件的非空段落顺序编号。所有判断只取包内前五章，不补书外剧情。
`【抽】`＝正文可直接抽取；`【半】`＝读者期待／兑现的解释性标注；`【编】`＝建议进入编排侧的 Hook 候选，不算正文事实抽取。

# 一、《大道朝天》｜玄幻／仙侠

## 结论

**五章都能装入厚描三件套，主卖点也能保住：顶级力量展示、身份谜团、重修起步、反差人设。**

最麻烦的地方不在仙侠设定，而在三件事：

- 第 2 章与第 3 章不是简单前后相接，而是**部分同时发生、随后切线**；
- 白衣少年、石床死者、飞升者之间存在强烈联系，但前五章没有给出可直接确认为同一人的证据；
- 第 4、5 章大量使用九日／一年蒙太奇，不能拆成九天或三百多天的假事件。

## 逐章试装

### 第 1 章｜三千里禁

**章内变化流**

阴三被赵腊月以剑索控制 → 阴三试图套话和反制 → 小剑将其击杀 → 青山弟子处理魂火 → 三千里禁的严重等级逐步揭开 → 章尾揭示大事是景阳师叔祖飞升。

**章末快照**

- 阴三死亡，尸体由赵腊月处理。
- 青山宗处于“三千里禁”状态。
- 各方高手正在赶来。
- 景阳即将飞升，整个修行界的注意力集中于青山。
- 阴三为何冒险留下、赵腊月为何在意其魂火，仍未解决。

**章间交接**

下一章继续同一天、同一场飞升事件；视野从镇上弟子扩到各宗强者和青山群峰。

**九类对象关键项**

- `entities【抽】`：赵腊月、阴三、孟师、景阳、青山宗。
- `events【抽】`：擒拿、击杀、魂火处理、颁禁、飞升消息揭示。
- `state_facts【抽】`：赵腊月是外门弟子但有极高威信；阴三是冥部弟子。
- `rules【抽】`：禁令范围越大，事件越严重；非请者进入禁区可被格杀。
- `reader_promises/payoffs【半】`：“三千里禁为了什么”在章尾兑现；新的期待转为“景阳如何飞升、能否成功”。
- `future_obligations【编】`：阴三滞留原因、赵腊月的疑惑。
- `provenance`：1¶20–35、¶61–83。

### 第 2 章｜斩天一剑

**章内变化流**

各派大人物抵达 → 孟师回顾景阳的地位与争议 → 青山掌门逼退窥探者 → 天雷降临第九峰 → 景阳不等天劫结束，直接出剑斩天 → 天穹裂口持续扩大。

**章末快照**

- 飞升正在进行，尚未给出明确结果。
- 景阳剑光已斩开天穹，力量标尺被推至全书开篇最高位。
- 所有强者被震住。
- 第九峰及景阳本人仍未正面出场。

**章间交接**

第 3 章开头仍处于飞升期间，先跟随赵腊月，再转入另一处山腹。交接关系应标为：

```yaml
handoff_relation:
temporal: parallel_then_advance
scene: switch_thread
effect: recontextualize_previous_event
```

**九类对象关键项**

- `events【抽】`：各宗观礼、掌门出剑、天雷降临、景阳斩天。
- `rules【抽】`：常规飞升者需承受天雷考验；景阳主动斩路属于异常做法。
- `reader_payoff【半】`：兑现“千年大事”的力量规模。
- `hook【半】`：剑光能否真正穿过天穹。
- `provenance`：2¶18–38、¶46–56、¶61–87。

### 第 3 章｜再次踏进那条河的白衣少年

**章内变化流**

赵腊月确认飞升似乎完成，却对阴三尸体产生疑惑 → 叙事切到山腹石室 → 白衣少年面对一具重伤死者 → 木牌消失，飞剑转移到少年手中 → 少年走出山腹 → 尝试踏水、剑火、修行均失败或遗忘 → 章尾连入门口诀都想不起来。

**章末快照**

- 白衣少年拥有飞剑与极强肉身力量。
- 他对这具身体、日常生活和低阶修行流程并不适应。
- 过去拥有的若干能力当前不可用。
- 他与石床死者、景阳飞升事件的关系只能记为**高可信关联假设**，不能直接合并实体。
- 赵腊月对阴三死亡产生了未解怀疑。

**章间交接**

下一章在“三刻后”继续白衣少年的行动，他离开山林进入村庄。

**九类对象关键项**

- `entities【抽】`：白衣少年、石床死者、赵腊月。
- `identity_relation【需固定核心】`：

```yaml
type: possible_same_as / inherited_from / unknown
status: unresolved
anti_merge:true
```

- `state_facts【抽】`：少年能搬动巨石、操纵飞剑；不能踏水、不能生剑火、忘记入门口诀。
- `reader_promise【半】`：他是谁、为什么能力丢失、为何要“再忙多年”。
- `provenance`：3¶18–21、¶24–49、¶52–71。

### 第 4 章｜九天

**章内变化流**

少年进入村庄并被认作仙师 → 提出住一年 → 选中柳宝根并改名柳十岁 → 要柳十岁教授日常生活 → 九天内从完全不会到全面精通 → 村民再次确认其“仙师”判断。

**章末快照**

- 少年入住柳家，计划停留一年。
- 柳宝根改名柳十岁，成为其生活助手。
- 少年已掌握做饭、砍柴、修屋、手工等生活技能。
- 村民对他身份的判断仍是人物信念，不是系统应确认的客观事实。

**章间交接**

第 5 章先承接九日后的生活，再一次性跨过一年。应标为“场景继续＋长时间概述”。

**九类对象关键项**

- `events【抽】`：入住、赐名、教学、九日学习蒙太奇。
- `event_pattern【需固定核心】`：`montage`，时间跨度九天，不应生成九条虚构日程。
- `state_fact【抽】`：柳十岁相信少年是仙师；少年本人否认。
- `reader_payoff【半】`：兑现“看似生活白痴、学习能力却异常恐怖”的反差爽点。
- `provenance`：4¶26–53、¶73–105。
- ¶108 是作者附言，不得进入故事快照。

### 第 5 章｜一年

**章内变化流**

少年宣布不再做农活 → 说明自己擅长“找到薄弱处并切断” → 给出姓名井九 → 时间跨过一年 → 柳十岁服侍井九并接受其呼吸纠正 → 井九以“稿子烧毁后重写”为比喻，透露自己要重做一件长期工程 → 推算时机已到 → 中年修行者降临。

**章末快照**

- 井九已在村中生活一年。
- 他的日常适应度提高，但核心状态仍是懒、擅长推演和切断。
- 柳十岁已在接受某种修行指导，但正文尚未明说完整功法。
- 井九决定结束蛰伏阶段。
- 一名携剑修行者来到面前。

**章间交接**

下一章应直接消费“来访者身份、来意、井九是否离村”。

**九类对象关键项**

- `rules【抽＋暂定】`：井九声称万物皆有薄弱处，他擅长找到并切断；这是人物陈述，暂不能写成无条件宇宙法则。
- `reader_promise【半】`：重写“三千年”的真实含义、井九身份、柳十岁的修行。
- `hook【半】`：携剑来访者。
- `provenance`：5¶14–30、¶47–64、¶89–110。
- ¶115 是作者附言，不进入故事账。

## 代价与风险

- 为身份关系加“不合并”状态，会让实体解析多保留几个候选对象，数据略增。
- 蒙太奇若抽得过粗，分镜缺少关键画面；抽得过细，又会编造正文没有写出的九天细节。
- 推荐保留“事件组＋少量代表性子事件”，例如做饭、修墙、制竹椅，而不是逐日补全。

## 反面核查

把第 2、3 章只靠 `story_time＋narration_order` 排序，可以知道先后，却不能明确表达“赵腊月线与飞升线部分同时、随后切到山腹并重释前文”。
把白衣少年直接认定为景阳，则属于用书外认知补洞。现有前五章只够记“强关联、未确认”。

# 二、《玩家凶猛》｜都市异能／玩家流

## 结论

**五章对现有结构的压力主要来自“错误解释后来翻案”和“系统信息是故事内界面，不是作者说明”。**

商业卖点非常清楚：

- 李昂的怪诞思维和冷幽默；
- 都市怪谈逐渐坐实；
- 以普通人身份反杀怪物；
- 击杀后取得玩家资格和首件装备；
- 日常校园与超凡暗线并行。

厚描三件套能承载，但 `state_facts` 和 `rules` 若没有真假状态，会在第 1、3 章直接记出互相冲突的“死因”。

## 逐章试装

### 第 1 章｜鲸落

**章内变化流**

警方勘验张翠莲残尸 → 李昂通过外观推测她患糖尿病 → 推演宠物因饥饿啃食主人 → 用“鲸落”解释死亡现场。

**章末快照**

- 张翠莲已死，面部和四肢部分组织缺失。
- 三猫四狗被当作重要生物物证。
- 李昂给出了“疾病倒地后被宠物啃食”的解释。
- 这一解释此时只能记为 `character_inference`，不能写成已确认死因。

**章间交接**

李昂离开现场进入自己居住的楼栋，并提到近来怪事增多。

**九类对象关键项**

- `entities【抽】`：李昂、张翠莲、王警官、宠物群。
- `state_fact【抽】`：尸体客观状态。
- `claim【需共用 assertion 头】`：糖尿病及宠物啃食是李昂推断。
- `reader_promise【半】`：李昂的判断到底对不对。
- `provenance`：1¶15–20、¶28–56。

### 第 2 章｜猫面

**章内变化流**

都市怪谈背景扩展 → 李昂爬楼 → 楼层出现八、九、八的循环 → 向下跑也被困住 → 未知声音逐层逼近 → 黑猫现身，脸上覆盖张翠莲的人皮，并吐出手指。

**章末快照**

- 李昂被困在异常楼梯空间。
- 人面猫已现身，与张翠莲死亡有直接关联。
- 李昂只有木筷等临时武器。
- 异常空间规则尚未摸清。

**章间交接**

下一章直接进入人与猫的试探和战斗。

**九类对象关键项**

- `events【抽】`：楼层循环、浓雾隔离、人面猫出现。
- `rules【抽＋未知】`：异常空间存在循环和隔离效果，但触发、边界、解除条件均未知。
- `payoff【半】`：推翻第 1 章单纯自然死亡的阅读预期。
- `hook【半】`：李昂如何在近身状态下活下来。
- `provenance`：2¶26–40、¶44–60、¶66–79。

### 第 3 章｜玩家

**章内变化流**

李昂假意接近 → 人面猫以叫声或能力定住其身体 → 猫开始啃食 → 李昂从猫身伤痕推知虐待经历 → 咬伤舌头解除束缚 → 用木筷和拳击杀人面猫 → 异常空间消散 → 系统将玩家资格转移给李昂。

**章末快照**

- 人面猫死亡。
- 第 1 章的自然死因推断已被正文明确推翻。
- 李昂成为 Lv1 玩家，经验为零，暂无装备和物品。
- 系统宣告幻想作品、其他世界与“地球杀场”的大规则。
- 系统陈述尚未经过外部验证，应记为“系统宣告”，不能自动等于作者真理。

**章间交接**

下一章处理战场、检查掉落物并测试新能力。

**九类对象关键项**

- `events【抽】`：定身、破控、击杀、资格转移。
- `state_fact【抽】`：李昂玩家资格激活。
- `rules【抽】`：非玩家击杀玩家可触发资格转移；系统给出世界观说明。
- `reader_payoff【半】`：普通人以知识和狠劲反杀超凡怪物；金手指正式到账。
- `provenance`：3¶16–25、¶41–56、¶57–68。

### 第 4 章｜幻术

**章内变化流**

李昂伪装环卫工清理现场 → 检查怪猫眼珠 → 获得装备说明 → 回顾个人经历和性格 → 分析可能存在的玩家与组织 → 将眼珠嵌入眼眶 → 测试夜视和幻术 → 成功制造简单幻象。

**章末快照**

- 李昂已装备“古怪的眼珠”。
- 左眼获得夜视和制造简单幻象的能力。
- 使用幻术会消耗精神力量。
- 复杂空间幻象暂时做不到。
- 李昂决定隐藏身份、观察局势。

**章间交接**

下一章回到校园日常，并让城市异常继续侵入普通生活。

**九类对象关键项**

- `entities【抽】`：古怪的眼珠应作为装备实体，而非普通状态字段。
- `rules【抽】`：幻象强度、范围和时长受精神力影响；需要眼眶才能佩戴。
- `reader_payoff【半】`：首件稀有装备展示与能力试用。
- `future_obligation【编】`：官方／第三方组织是否在搜捕玩家。
- `provenance`：4¶10–17、¶35–44、¶47–60。

### 第 5 章｜校园

**章内变化流**

李昂翻墙进校 → 以荒诞理由应付老师 → 青梅竹马与同学关系建立 → 同学谈论“尸体长在电线杆里”的异常案件 → 网络内容被迅速屏蔽 → 李昂判断是超凡事件并记下“钱华路”。

**章末快照**

- 李昂维持普通高中生身份。
- 王丛珊、班主任等日常关系建立。
- 钱华路成为明确调查线索。
- 城市异常案件与信息封锁正在扩大。
- 李昂主动从被动幸存者转为搜集线索者。

**章间交接**

下一章可直接调用钱华路线索，也可以先安排系统任务；两者在当前文本中都没有被确认。

**九类对象关键项**

- `events【抽】`：校园回归、异常案件传播、线索记录。
- `reader_promise【半】`：钱华路异象、官方封锁、李昂怎样利用玩家能力。
- `signature【半】`：李昂的荒诞类比和一本正经胡说是角色品牌，不应被套路去重器主动压掉。
- `provenance`：5¶9–30、¶31–53。

## 代价与风险

- 如果所有人物推理都只记成对白事件，不进入结构化认知层，下游会丢掉“读者先信、随后翻案”的爽感设计。
- 如果把系统文字视为作者说明，则任何诱导性系统、假系统、残缺规则都会污染世界真账。
- 套路去重若只看语义相似度，会误伤李昂持续输出怪话的角色卖点。

## 反面核查

一种省事做法是：第 1 章只记“李昂说了糖尿病”，第 3 章再记“猫杀人”。
这样虽然没有字段冲突，但正文生成、互动推理和作者诊断都无法知道：**第 1 章那套完整推断曾经被读者当成可信解释，第 3 章的翻案才有力度。**因此仍需认知／真值状态。

# 三、《怪谈游戏设计师》｜规则怪谈／都市怪谈

## 结论

**这是五本里对当前结构压力最大的一本。**

最强压力来自：

- 同一套公寓同时具有现实状态和“诡家副本”状态；
- 每晚回来的爸爸妈妈既像固定角色，又有多个实体实例；
- 高命设计的虚构人物正在现实出现，但同名不等于已确认同一对象；
- 黑白照片上的文字像规则说明，却可能是异常存在给出的诱导话术；
- 第 4 章一次性摆出大量潜在怪谈，属于明确读者承诺，却还不是已排期 Hook。

这些结构不能只靠地点和时间解决。

## 逐章试装

### 第 1 章｜一个平凡普通且温馨的夜晚

**章内变化流**

温馨生日场景建立 → 高命从隔音层、冰箱、保鲜袋等细节判断“父母”危险 → 发现蜡烛数量与实际年龄不符 → 给饭菜下药 → 打开卧室，揭示里面堆满多批爸爸妈妈 → 回溯三日前大巴与隧道事件 → 高命推断自己设计的家庭游戏变成现实 → 十八根蜡烛出现，通关临近 → 门外出现雨夜杀人魔 → 高命主动将其引进屋。

**章末快照**

- 高命处于现实公寓与异常“家”重叠的边界。
- 多批诡爸爸／诡妈妈被捆在卧室。
- 十八蜡烛条件已经达成，副本似乎接近结束。
- 高命仍缺失隧道中的关键记忆。
- 现实杀人犯齐淹已进入屋内。
- “二十六岁本人”与“游戏要求活到十八岁”属于两套年龄语义，不能互相覆盖。

**章间交接**

下一章直接让齐淹进入诡异空间的可见范围，高命借其做外部验证和反杀工具。

**九类对象关键项**

- `entities【抽】`：高命、现实父母、诡爸爸角色、诡妈妈角色、多个角色实例、齐淹。
- `context_ref【固定核心】`：现实层／诡家层／家庭游戏实例。
- `rules【抽＋暂定】`：每晚父母回来；蜡烛随轮次增长；十八根蜡烛可能代表通关。
- `reader_payoff【半】`：从“主角疑似杀父母”翻为“主角在处理一屋怪物”。
- `hook【半】`：把现实杀人魔引入怪谈副本。
- `provenance`：1¶16–30、¶40–55、¶56–80、¶85–94。

### 第 2 章｜太内向，不敢和爸妈说话

**章内变化流**

齐淹自认猎手 → 高命把他带到卧室门口 → 齐淹确认自己也能看到诡父母 → 高命击晕、灌药、捆绑齐淹 → 异常空间逐步退出现实 → 一名诡妈妈将齐淹意识拖走 → 公寓恢复正常 → 高命获得两张黑白照片及文字说明。

**章末快照**

- 家庭游戏实例已经关闭或暂时关闭。
- 卧室恢复现实状态，蛋糕、蜡烛和诡父母消失。
- 齐淹肉身仍在，但意识／灵魂状态异常。
- 高命获得“家长照片”和“家人照片”。
- 照片宣称高命能打开“家”、吸纳特定人群，并让更多人玩夜间游戏。
- 这些规则的来源是异常照片，可靠度未知。

**章间交接**

下一章由高命分析照片、报警，并通过外部新闻和调查人员扩大世界范围。

**九类对象关键项**

- `events【抽】`：外部见证、击倒齐淹、副本退出、奖励出现。
- `rules【抽＋未验证】`：照片背面所有“家长／家人”规则。
- `reader_payoff【半】`：高命反将现实杀人魔送入怪谈。
- `future_obligation【编】`：验证照片规则，调查“家”的性质。
- `provenance`：2¶14–35、¶36–42、¶43–55。

### 第 3 章｜文明城市江沪瀚

**章内变化流**

高命分析两张照片 → 发现齐淹照片持续破裂 → 报警并查询大巴记录 → 发现当晚班次理论上全部停运 → 汇总三城异常新闻 → 警察和神秘调查员进入公寓 → 调查员设备在卧室故障 → 警方离开后怀疑高命 → 揭示高命危险评分超出测试上限。

**章末快照**

- 高命确认世界记录与自身记忆冲突。
- 恨山监狱、乐园火灾、旧城案件形成并行异常线。
- 存在普通警察之外的调查部门。
- 高命已被警方列入隐性观察对象。
- 齐淹照片状态持续恶化。
- 高命本人危险性成为新的角色钩子。

**章间交接**

天亮后，高命暂时无法前往隧道，转而处理自己留下的大量游戏设计。

**九类对象关键项**

- `state_facts【抽】`：官网显示客车停运；高命记得自己乘车；两者冲突需并存。
- `entities【抽】`：厉林、毁容调查员、调查部门。
- `reader_promise【半】`：三城为何同时异常、高命为何危险评分超限。
- `provenance`：3¶2–20、¶22–41、¶46–54。
- ¶55–56 是作者的新书说明，不进入剧情账。

### 第 4 章｜不做恐怖游戏的恐怖游戏工作室

**章内变化流**

暴雨阻断隧道 → 高命决定去夜灯工作室销毁设计 → 工作室人物与经营困境建立 → 高命拿回多年设计方案 → 将作品按危险程度分为六档 → 统计出大量凶兆、诡语、怪谈及四个失控怪谈。

**章末快照**

- 高命已取得纸质设计方案，准备销毁。
- 工作室仍留有电子版及已开发项目。
- 共存在大量潜在怪谈设计，其中四个是失控级。
- “这些设计是否已经变为现实”仍未知。
- 夜灯工作室成为主角的现实团队入口。

**章间交接**

下一章执行焚烧和删除，并碰到无法直接删除的恋爱游戏项目。

**九类对象关键项**

- `entities【抽】`：夜灯工作室、游戏设计方案集合、六级危险分类。
- `rules【抽＋人物分类】`：危险分级是高命自己的设计体系，不等于世界自动遵守的法则。
- `reader_promise【半】`：四个失控怪谈以及大量游戏可能陆续兑现。
- `future_obligation【编】`：只应把已被作者／编排确认要回收的项目晋升 Hook；不能把 126 个设计全部排成待办。
- `provenance`：4¶5–12、¶32–47。

### 第 5 章｜致我们终将去世的爱情

**章内变化流**

高命焚毁纸稿 → 请求删除电子文件 → 恋爱游戏项目因商业压力无法整体删除 → 决定只删除自己参与的第九路线 → 真实女子宣雯来到工作室，姓名和气质均对应游戏角色 → 另一女主同名者已离奇死亡 → 高命催促删除全部设计 → 宣雯私下称高命为丈夫 → 表明三日前一切已开始，并声称其他女人已被她杀死。

**章末快照**

- 电子与纸面设计虽已删除，但现实化进程没有逆转。
- 现实中的宣雯与游戏角色高度对应，但身份关系尚未确认。
- 宣雯知道隧道事件和高命记忆缺失。
- 高命成为宣雯主动接近的对象。
- 多条游戏女主线可能已在现实出现。
- 今晚去宣雯家成为高危明确邀约。

**章间交接**

下一章应消费宣雯邀约、隧道记忆或其他女主死亡线，不能无故切回普通工作室日常。

**九类对象关键项**

- `entity_relation【固定核心】`：

```yaml
real_person: 宣雯-现实
fictional_entity: 宣雯-游戏设计
relation: possible_counterpart
status: highly_suspected
anti_merge:true
```

- `reader_payoff【半】`：游戏变现实从抽象危机变成具体人物贴脸。
- `hook【半】`：宣雯的“丈夫”称呼、今晚邀约、杀死其他女人。
- `provenance`：5¶8–23、¶24–42、¶45–57。

## 代价与风险

- 引入现实层／副本层后，所有事件和状态都要携带 `context_ref`，存储与抽取复杂度都会提高。
- 多批诡父母若每个都建独立实体，会产生实体爆炸。推荐采用“角色原型＋必要实例”，只为发生独立动作、承受独立结果的个体建实例。
- 同名现实人物与游戏角色若过早合并，分镜会直接把“游戏设定图”和“现实人物”当成一人；若永不关联，又会丢掉最关键的阅读期待。

## 反面核查

把“诡家”只建成一个地点实体不够。第 2 章里，同一卧室先装满诡父母，随后恢复正常，齐淹肉身留在现实、意识疑似进入另一处。这里变化的不是普通地点，而是**现实层和副本实例的有效范围**。

# 四、《秦吏》｜历史穿越

## 结论

**这本对厚描三件套最友好。**

它的商业驱动力主要是：

- 现代知识带来的认知领先；
- 秦律和爵位制度构成的明确规则；
- 从“会战死的普通士伍”向“靠规则改变命运”推进；
- 战斗能力与制度收益连续兑现；
- 赏金、爵位、官吏争功形成新的现实障碍。

问题集中在“角色知道的历史未来不等于本故事必然未来”，以及作者使用现代制度做类比时，不能误抽成秦代真实名词。

## 逐章试装

### 第 1 章｜士伍，请出示身份证！

**章内变化流**

黑夫雨夜投宿 → 店家检查验与传 → 回溯现代人穿越成秦代黑夫 → 得知历史上的黑夫可能战死 → 因成年登记而前往服役 → 介绍秦代身份、旅行和私斗规则 → 住进客舍 → 章尾听到荆轲刺秦消息。

**章末快照**

- 黑夫身份检查通过，正在前往安陆县服役。
- 他已接受当前身份，并把避免历史死亡作为长期目标。
- 当前役期只是短期更卒，不会立刻上大战场。
- 秦国验传、户籍、私斗规则已建立。
- 荆轲刺秦消息将触发他对历史进度的判断。

**章间交接**

下一章继续客舍谈话，黑夫从天下形势推算自己的死亡风险。

**九类对象关键项**

- `entities【抽】`：黑夫、舍人、季婴、家人。
- `rules【抽】`：验传制度、傅籍服役、私斗处罚。
- `reader_promise【半】`：黑夫怎样避开历史死亡。
- `provenance`：1¶14–31、¶34–48、¶54–57。

### 第 2 章｜天下事与眼前事

**章内变化流**

众人谈荆轲刺秦 → 黑夫用现代历史知识推演燕、魏、楚战争 → 判断两年后自己极可能被征召 → 否定逃亡路线 → 比较不同国家与阶层机会 → 观察客舍爵位待遇差异 → 决定通过取得爵位改变命运。

**章末快照**

- 黑夫的全书级生存目标落成：在战争来临前取得足够爵位和地位。
- 他认为逃亡会牵连家人且无长期出路。
- 爵位成为明确成长刻度。
- 当前仍没有快速获得爵位的方法。

**章间交接**

第 3 章直接拆解得爵渠道，并让“捕盗机会”落到眼前。

**九类对象关键项**

- `state_fact【抽】`：当前时间、已发生的战争。
- `prediction【需 assertion】`：黑夫对未来灭国和战争的历史推演；属于人物高可信知识，不是不可更改的故事事实。
- `rules【抽】`：爵位决定饮食、住宿和社会待遇。
- `reader_promise【半】`：升爵路线。
- `provenance`：2¶7–23、¶31–45。

### 第 3 章｜爵位难得

**章内变化流**

黑夫盘点战场斩首、农耕、告奸、捕盗、做吏等升爵方式 → 发现短期都很难 → 与季婴同行 → 得知云梦泽盗匪问题 → 遭遇商贾被四名贼人追杀 → 黑夫因责任、法律与奖励决定迎战。

- 商贾正在逃向二人。
- 黑夫已经拔剑并主动报号。
- “捕盗换收益”从抽象方案变成眼前机会。

**章间交接**

第 4 章从同一秒继续战斗，不需要任何时间跳转。

**九类对象关键项**

- `rules【抽】`：多种得爵方式；百步内见死不救可能受罚；捕盗可能有赏。
- `reader_promise【半】`：现代训练能否压制古代盗匪，能否借此取得第一笔资本。
- `hook【半】`：二对四开战。

商贾逃走，二人变成二对四 → 黑夫吸引三名敌人 → 用短剑和擒敌技术逐一击倒 → 空手夺刃制服首领 → 季婴牵制一人 → 三名盗贼被捆 → 解释秦律的救援义务与捕盗赏金 → 粗算三人可能带来两万四千余钱。

**章间交接**

- 三名盗匪仍由二人控制。
- 赏金和功劳归属尚未确认。
- 湖阳亭长拥有地方武装优势。
- 黑夫与亭长进入公开对峙。

**章间交接**

下一章应处理执法权限、证人、俘虏归属与赏金争夺。

**九类对象关键项**

- `state_change【抽】`：季婴由同行者升级为承诺互助的盟友。
- `reader_payoff【半】`：黑夫分钱收人心。
- `hook【半】`：亭长是否抢功、黑夫能否保住俘虏和赏金。
- `provenance`：5¶7–17、¶23–39、¶40–52。

## 代价与风险

- 历史知识若直接写进客观未来，系统会把“人物认为会发生”误当成“故事必须照历史发生”，从而压死穿越改史空间。
- 作者用“身份证、派出所、县局处级干部”等词解释秦制，这些是读者沟通层，不是秦代角色口中的正式概念。
- 包内存在一处潜在事实不一致：第 1 章说黑夫来自“某省警官学院”，第 4 章数次写成“武警学院”。不能静默改成同一学校，应保留证据并标记待核。

## 反面核查

如果把所有现代类比都当作世界事实，分镜或互动角色可能在秦代直接说“身份证”“派出所长”。
如果把黑夫的历史推演全部当成已确认未来，下游会阻止任何改史情节。两种错误都会破坏这本书最主要的爽点。

# 五、《一品世子妃》｜女频古言

## 结论

**重生前两章的惨烈铺垫、重生后的信息优势、打脸与拿捏，都能被厚描三件套抓住。**

但这本给出了最明确的 A 级缺口：

> `story_time＋narration_order` 无法单独区分“前世的十五岁”和“重生后重新来到的十五岁”。
> 

两段故事可能拥有相同年月、相同人物和相同地点，却属于不同人生轮次，状态不能互相覆盖。

## 逐章试装

### 第 1 章｜手刃

**章内变化流**

- 余妈妈和车夫死亡。
- 顾远趋完全认陆心儿为母，对陆玥梨抱有强烈敌意。
- 陆心儿控制了陆玥梨的丈夫和儿子。
- 亲生儿子即将执行处决。

**章间交接**

- `entities【抽】`：陆玥梨、陆心儿、顾远趋、余妈妈、车夫。
- `state_facts【抽】`：亲生关系是陆玥梨陈述和强情绪认知；顾远趋当前并不相信。
- `reader_promise【半】`：如此极端的压迫将怎样翻盘。
- `hook【半】`：亲生儿子手刃生母。

第 3 章直接切到二十年前的新人生轮次。交接关系不是普通倒叙，而是：

**章内变化流**

十五岁的陆玥梨在青州醒来 → 看到完好的双手和年轻千双 → 确认自己回到二十年前 → 发现余妈妈与千双为了她挨饿、洗衣换食 → 主动前往浆洗房。

- `memory_origin【固定核心】`：前世经历不能当成本轮已发生事件，但可以成为人物知识和动机。

**章内变化流**

**九类对象关键项**

- `reader_payoff【半】`：重生后的第一次公开反击。
- `hook【半】`：主角凭什么对抗掌握外宅实权的管事。

**章内变化流**

李管事以大夫人名义要打陆玥梨 → 陆玥梨说出桃荷包和暗语 → 李管事、陈桃暴露心虚 → 揭示二人私通把柄来自前世记忆 → 陆玥梨以家破人亡威胁 → 李管事驱散下人并改为讨好。

**章末快照**

- 陆玥梨成功控制李管事和陈桃。
- 前世知识第一次直接转化为现实优势。
- 余妈妈、千双见证主角能力突变，但尚不知道重生真相。
- 外宅的小范围权力局势开始倒向陆玥梨。
- 大夫人、陆心儿、顾倾尧等远期敌人仍未正式进入本轮行动线。

**章间交接**

下一章应消费陆玥梨对李管事提出的条件，或展示外宅待遇改变，完成这一小段打脸的可见结果。

**九类对象关键项**

- `knowledge_fact【抽】`：李管事与陈桃私通，信息来源是前世记忆。
- `reader_payoff【半】`：不流血拿捏恶仆；重生金手指完成首次小兑现。
- `future_obligation【编】`：忠仆生活改善、大夫人反制、复仇主线。
- `provenance`：5¶2–10、¶11–24。

## 代价与风险

- 时间线字段加入后，同一人物会有“跨轮次同一身份”和“每轮独立状态”两层关系，实体查询更复杂。
- 如果只保留陆玥梨当前十五岁的快照，前两章惨剧会变成普通背景摘要，后续打脸的情绪燃料会被削弱。
- 如果把前世私通事实直接写成本轮已发生事实，互动叙事可能允许主角引用本轮尚未发生的证据，造成规则漏洞。

## 反面核查

单纯把前两章排到“二十年后”，第 3 章排到“二十年前”，仍解决不了问题：本轮故事若再走到相同年份，就会与前世事件共享同一个 `story_time`。
所以这里必须有 `timeline_id／iteration_id`，不是题材装饰字段。

# 九、第五节必答题｜本轮有把握的推荐

## 1. 证据锚保留与否

### ✅ 结论

**保留，而且应是固定纪律，不能降为调试选项。置信度：99%。**

### 可操作方案

每条事实、规则、实体关系、读者承诺至少带一个证据锚：

```yaml
provenance:
source_id:
chapter_id:
paragraph_start:
paragraph_end:
source_hash:
source_integrity:
origin: extracted / inferred / author_declared / planner_created
extractor_version:
```

模型推断出来的内容要同时记录“推断所用的多个锚”，不能假装是正文原句。

### 代价与风险

- 存储增加。
- 源文重排后段落号可能变化，所以要同时保存源文件哈希和局部文本哈希。
- 不建议长篇复制原文，只保留位置和短摘要。

### 反面核查

本包已有三类必须追责的场景：

- 《一品世子妃》2 章源文残缺；
- 《玩家凶猛》错误死因后来被推翻；
- 《秦吏》“警官学院／武警学院”存在潜在冲突。

没有证据锚，下游修错时无法知道该改哪条、为何改。

---

## 2. 新逻辑句条目格式

### ✅ 结论

**逻辑句不要写成普通剧情摘要，要写成“状态变化句”。置信度：94%。**

### 可操作方案

人能读懂的一句话模板：

> 在【叙事上下文】中，【主体】因【触发事件】，在【规则／限制】下，从【前态】变为【后态】，直接造成【结果】，并留下【未决问题】；该判断属于【确认／推断／陈述】，证据见【锚】。
> 

结构字段：

```yaml
logic_entry:
context_ref:
subject_refs:
before_state_refs:
trigger_event_refs:
governing_rule_refs:
change:
after_state_refs:
immediate_consequence_refs:
open_question_refs:
assertion:
provenance:
must_preserve:
```

💡 《玩家凶猛》第 3 章可写成：

> 李昂在异常楼梯实例中，因咬伤舌头打破定身状态，用木筷和近身打击杀死人面猫，从非玩家变为 Lv1 玩家；同时取得超凡资格，并留下系统规则是否可信的问题。
> 

### 代价与风险

字段比旧式一句话更厚。解决办法不是删字段，而是作者界面只显示自然语言句，结构字段折叠在后面。

### 反面核查

如果逻辑句只写“李昂杀猫成为玩家”，会丢掉破控方法、规则触发和系统可信度；互动和分镜都无法安全调用。

## 3. 体验合同格式

### ✅ 结论

**保留每章合同，但必须从“填满七个槽”改成“明确本章承担什么、不承担什么”。置信度：93%。**

### 可操作方案

```yaml
experience_contract:
primary_promise_refs:
secondary_promise_refs:
progress_type: seed / escalate / reframe / payoff / breathe
setup_refs:
payoff_refs:
rule_showcase_refs:
desired_pattern:
signature_policy: avoid / repeat / evolve
emotion_curve:
end_hook:
level: hard / soft / none
question:
urgency:
target:
must_preserve:
forbidden_drift:
field_status:
```

`progress_type` 必须允许 `reframe`。
《玩家凶猛》第 3 章不只是打怪，它还重写了第 1 章死因；《怪谈游戏设计师》第 5 章把抽象的“游戏成真”改写成“游戏人物贴脸”。

### 代价与风险

合同太长会压住作者。作者工作台只需露出：

- 本章让读者期待什么；
- 本章给了什么；
- 章尾把人拉向哪里；
- 哪些东西绝不能改。

其余字段供 AI 使用。

### 反面核查

若合同强制每章都要有规则展示和强钩子，《大道朝天》第 4 章这种反差生活章会被硬改成突发战斗，反而破坏节奏。

## 4. 产出方标记字段

### ✅ 结论

**必须把“谁写入”与“内容从哪里来”拆成两个字段。置信度：97%。**

### 可操作方案

```yaml
producer:
actor: extractor_model / planner_model / program / author / adapter
tool_version:

origin:
type: extracted / inferred / author_declared / planner_created / program_derived / adapter_added
confidence:
review_status: unreviewed / accepted / rejected / revised
```

同一条记录可能是：

- `producer.actor=extractor_model`
- `origin.type=inferred`

不能因为是提取模型产出，就假装它来自正文原句。

### 代价与风险

字段看起来重复，但两者解决的问题不同：

- `producer` 用来追查哪个环节出错；
- `origin` 用来决定下游能否把它当作原著事实。

### 反面核查

《大道朝天》第 3 章若模型推断白衣少年身份，单写“提取产出”会让下游误以为正文已确认。

---

## 5. 规则是否单列

### ✅ 结论

**规则继续单列，不能并入普通 `state_facts`；但规则对象允许章节级为空。置信度：96%。**

### 可操作方案

```yaml
rule:
rule_id:
context_scope:
condition:
effect:
cost:
exception:
duration:
visibility:
known_by:
truth_status:
evidence_refs:
demonstration_event_refs:
```

说白了就是：

- 事实回答“现在是什么”；
- 规则回答“满足什么条件会发生什么”。

《秦吏》的捕盗赏金、《玩家凶猛》的资格转移、《怪谈》的十八蜡烛，都不是普通静态事实。

### 代价与风险

规则抽取容易把人物猜测抬成铁律，因此必须和 A3 的 `assertion` 配套上线。

### 反面核查

若并入状态事实，互动叙事无法拿规则做条件判断；若每章强制有规则，《一品世子妃》的宅斗章节又会制造伪规则。

---

## 6. 爽点账／钩子账细目

### ✅ 结论

**两本账必须分开：爽点记录“本章已经给到的满足”，钩子记录“读者还想知道什么”。置信度：92%。**

### 可操作方案

爽点条目：

```yaml
payoff:
desire_ref:
setup_refs:
trigger_event_refs:
beneficiary_refs:
target_or_opponent_refs:
visible_result:
witness_refs:
intensity:
novelty:
cost_or_backlash:
residual_effect:
```

钩子条目：

```yaml
hook:
question:
threat_or_opportunity:
target_refs:
urgency:
expected_payoff_type:
dependency_refs:
lifecycle_state:
source_promise_ref:
deadline_or_tolerance:
```

💡 《一品世子妃》第 5 章：

- 爽点：陆玥梨用前世把柄让李管事当场服软；
- 钩子：她接下来会要求什么，大夫人何时反击。

不能把两者合成一个“本章有爽有钩”。

### 代价与风险

一章可能有多个小爽点。建议设一个主爽点，其他记辅助，不然账会爆炸。

### 反面核查

只记章尾问题，会漏掉当章满足；只记打脸结果，又解释不了读者为什么继续点下一章。

---

## 7. 偏航判定口径

### ✅ 结论

**偏航要按“读者承诺是否被破坏”分级，不按文字是否与旧稿相似。置信度：90%。**

### 可操作方案

| 等级 | 判定 |
| --- | --- |
| **S3 结构偏航** | 时间线、现实层、身份、已确认规则发生矛盾 |
| **S2 承诺偏航** | `must_preserve` 丢失；已铺期待被错误兑现或提前剧透 |
| **S1 推进偏航** | 里程碑延误、铺垫连续隐身、章末牵引长期不足 |
| **S0 表达变化** | 措辞、场景装饰、非关键动作变化，不算偏航 |

《玩家凶猛》若把李昂改成严肃沉默型人物，可能属于 S2 人设承诺偏航；换一个迟到借口通常只是 S0。

### 代价与风险

等级边界需要金标。尤其“慢一章”究竟是必要蓄力还是推进不足，不能只靠固定字数判断。

### 反面核查

若只比较剧情事件是否一致，会放过角色卖点和爽感丢失；若比较句子相似度，又会阻止正常改写。

---

- **Hook 冲突裁决七序**
需补材料：现有七序候选、至少 20 个真实冲突案例、冲突时更看重保原著还是保作者新意。
- **暗稿可见性闸**
需补材料：小白作者、职业作者、工作室分别能看到什么的界面草图。
- **建议层工况分型、挂靠点／停点**
需补材料：实际工作台任务路径和作者干预频次。
- **R12 金标与四层秤重建**
需补材料：旧金标、错误样例、四层秤当前定义。

# 十、质疑清单

## Q1｜质疑 T1：`story_time＋narration_order` 被当成足够的时间结构

**质疑结论：不够。**

《一品世子妃》重生前后可能处在相同年月；《怪谈游戏设计师》同一时刻、同一公寓存在现实层和副本层。两根时间轴无法区分时间线轮次与现实层。

**建议**

保留 T1 厚描三件套，但补固定共用 `context_ref`。
“唯一真账”应解释为“唯一权威存储”，不能解释成“每件事只能有一个客观版本”。

**证伪证据**

拿以下章节做消费者合同测试：

- 《一品世子妃》1–3 章；
- 《怪谈游戏设计师》1–2 章；
- 《玩家凶猛》2–3 章。

若不增加时间线／现实层字段，仍能让正文、分镜、画面、互动、工作台无冲突地还原有效状态，这条质疑可撤。

---

## Q2｜质疑 T2：九类对象里缺少“认知与真假”的固定表达

**质疑结论：这是本批最危险的问题。**

`state_facts` 这个名字会诱导系统把人物推断当事实，`rules` 又会诱导系统把系统台词、照片文字当世界铁律。

正文反复依靠“先信后翻”制造爽感：

- 李昂先给出糖尿病死因，后被人面猫推翻；
- 高命收到的照片规则来自异常存在；
- 黑夫听到的赏金算法还受“是否构成群盗”制约；
- 白衣少年的身份仍未确认。

**建议**

不新增第十类对象，给事实、规则、实体关系加统一 `assertion` 头。

**证伪证据**

做一套至少 50 条真假混合金标。若当前结构能达到：

- 错误推断不进入客观快照；
- 已推翻内容仍可回看；
- 互动引擎不把未确认规则当强制判定；
- 生成正文不提前揭底；

则可撤销质疑。

---

## Q3｜质疑 T2／T7：signature 去重可能误杀作者品牌

**质疑结论：按“近期出现过就避开”的方向有明显风险。**

李昂连续五章都在一本正经说怪话，这不是低质重复，而是人物招牌。高命的冷静、反向恐怖和黑色幽默也有类似作用。

**建议**

体验合同加 `signature_policy=avoid/repeat/evolve`。
区分：

- 该避开的桥段模板；
- 该重复的人物品牌；
- 该升级变化的核心爽法。

**证伪证据**

让目标读者盲评两组生成稿：

- 自动去重版；
- 允许品牌重复但要求局部变化版。

若去重版在人设辨识度、笑点和追读意愿上不降反升，质疑可撤。

---

## Q4｜质疑 T3：“Hook 记上不抽”可能漏掉导入正文里的明确承诺

**质疑结论：若完全禁止从正文产生 Hook 候选，会漏账。**

《怪谈游戏设计师》第 4 章的四个失控怪谈、《秦吏》的升爵目标、《一品世子妃》的复仇目标，都是正文明确建立的未来期待。

**建议**

不要直接抽成 `scheduled Hook`，而是：

```
正文 → reader_promise → 编排审核 → promote_to_hook
```

这样既不让模型擅自排期，也不会忘掉已对读者说出口的承诺。

**证伪证据**

在完整导入作品中测“显式承诺召回率”。若现有期待账能达到高召回，并能在编排时稳定查到，无需增加晋升关系。

---

## Q5｜质疑 T4：新逻辑句若不带上下文、真假和证据，重造后仍会复刻旧问题

**质疑结论：退役旧格式是对的，但新格式不能只是更漂亮的一句话。**

重生、怪谈副本、错误推断、规则条件都要求逻辑句知道：

- 在哪个上下文；
- 谁认为这是真的；
- 状态从什么变成什么；
- 证据来自哪里。

**建议**

采用本报告给出的“状态变化句”结构。

**证伪证据**

用同一条逻辑句同时驱动：

- 正文续写；
- 动作分镜；
- 互动条件判断。

若不带上述字段仍不发生错层、错身份、错规则，则可简化。

---

## Q6｜T5 暗稿：本批无法给出结构性反对，但存在重复记账风险

Hook 账、读者期待账、暗稿三处都可能记录“未来会发生什么”。如果边界不清，会出现一个点子改了三处仍不同步。

**需补材料：**暗稿条目样例、它与 Hook 的一对一／一对多关系、作者可见状态。

**证伪证据**

展示一个点子从暗稿进入 Hook、再被改期或废弃的完整数据流。若始终只有一个权威状态，风险可消除。

---

## Q7｜T6 作者规划双层：本批无重大质疑

“故事线里程＋全书级目标”可以容纳五本开篇：

- 井九结束蛰伏；
- 李昂成为玩家；
- 高命处理游戏现实化；
- 黑夫争取爵位；
- 陆玥梨启动复仇。

暂未发现必须增加独立“卷目标”对象的证据。故事线里程若能分层嵌套，就够用。

**证伪方向**

需用 100 章以上作品检查：故事线里程是否会变成过长平铺列表。当前五章窗口不能下结论。

---

## Q8｜质疑 T7：每章合同若不允许“无强钩子／无新规则”，会倒逼 AI 乱加戏

**质疑结论：方向对，必填方式有风险。**

《大道朝天》第 4 章依靠反差和九日学习完成阅读满足，不需要硬塞一个敌袭；《秦吏》第 2 章主要完成目标确立和制度欲望建立。

**建议**

合同字段带 `field_status`，章末钩子允许 hard／soft／none。

**证伪证据**

用强制填满合同和允许空值合同各生成一版。若强制版没有额外事故、假规则、无关反派，且追读更高，可撤销质疑。

---

## Q9｜T8 具名视图合同：本批没有方向性反对

“下游不直读本体”是对的，尤其现实层、真假状态、作者附言过滤都需要统一视图处理。

本批无法评价必填、限额和视觉档案的具体数值。

**需补材料：**三份视图底稿、消费者合同测试样例、错误降级示例。

---

## Q10｜质疑 T9：多模型流水线容易把早期错误层层固化

**质疑结论：阶段数本身不是问题，真正风险是错误实体合并和错误真值一旦进入中间工件，后续模型会把它当已知前提。**

本批最典型的是：

- 白衣少年身份；
- 现实宣雯与游戏宣雯；
- 诡父母实例；
- 黑夫学院名称冲突。

**建议**

每个模型阶段都必须传：

- provenance；
- assertion；
- unresolved relations；
- source integrity。

不能只传“整理后的确定答案”。

**证伪证据**

需补材料：T9 各阶段真实工件。
若影子运行中，歧义在多个阶段后仍被完整保留，且不会自动变成确定事实，这条质疑可撤。

---

## Q11｜质疑 T10：黑盒自动流程必须给“歧义”一个明确挂靠点

**质疑结论：只提供普通错误提示不够。**

作者最需要干预的不是每条小字段，而是：

- 这两个人是不是同一个；
- 这是现实还是副本；
- 这条规则到底可信不可信；
- 源文是不是缺了一段。

**建议**

黑盒提取结束时固定给作者一个极短的“高风险歧义卡”，只展示会影响下游的 A 类问题。普通低置信字段仍由系统处理。

**证伪证据**

在 25 章金标上运行黑盒。如果不设歧义卡仍能做到：

- 关键实体误合并接近零；
- 作者修正次数极少；
- 六下游无连锁错误；

则可撤销质疑。

---

## Q12｜质疑 T11：推进力不能被窄化为“发生了多少动作”

**质疑结论：推进力当总秤没问题，但要把认知翻转、规则证明、关系升级算作真实推进。**

例如：

- 《玩家凶猛》第 3 章推翻死因，是认知推进；
- 《怪谈》第 3 章确认存在调查部门，是世界推进；
- 《秦吏》第 2 章确立爵位目标，是目标推进；
- 《一品世子妃》第 5 章控制李管事，是关系与资源推进。

**建议**

推进力至少拆成：

- 事件推进；
- 认知推进；
- 规则推进；
- 关系／资源推进；
- 期待兑现推进。

**证伪证据**

若现有四层秤已经覆盖这五类，并能把上述章节评为有效推进，则不必再加字段。

---

## Q13｜质疑 T12：AI 管道只给单方案，歧义章节可能被迫过早选边

**质疑结论：省 token 的方向可以保留，但单方案不能等于单假设。**

白衣少年身份、宣雯身份、照片规则可信度，都不适合当场选一个答案写死。

**建议**

仍只输出一份结构，但允许其中带一个很小的 `hypothesis_set`：

```yaml
hypothesis_set:
-interpretation:
confidence:
evidence_refs:
-interpretation:
confidence:
evidence_refs:
```

不是生成两套完整大纲，只是保留两个解释候选。

**证伪证据**

比较单确定答案与小型假设集在歧义金标上的准确率。若单答案同样能保持高召回且没有错误固化，可继续原方案。

# 十一、收口建议

✅ **继续保留：**

- T1 厚描三件套；
- 九类对象；
- 大纲唯一真账；
- 章间交接；
- 规则单列；
- 体验合同；
- 下游只读具名视图；
- Hook 编排账与正文事实分离。

🔥 **进入规格前必须补的固定核心：**

1. `context_ref`：时间线、轮次、现实层、副本实例；
2. `assertion`：陈述方式、真值状态、知道者、修正链；
3. 实体关系中的候选同一／实例／前世／虚构对应与禁止误合并；
4. 章间交接关系类型；
5. 变化流的层级、蒙太奇和习惯事件表达；
6. `narrative_unit.discourse_role`；
7. provenance 中的源文完整性。

👉 **应留在题材可选池：**

- 玩家等级、经验、装备品质；
- 秦代爵位、赏金、法律条文结构；
- 怪谈危险六级；
- 重生机制的具体触发方式；
- 仙侠境界、宗门职位、法宝细项。

👉 **应留在适配层：**

- 系统界面的视觉样式；
- 黑白照片如何表现；
- 战斗镜头数量；
- 蒙太奇具体画面选择；
- 古装、怪物、法宝的视觉评价数据。

**总体判断：不是十二道决策方向错了，而是“唯一真账”的坐标系还少两维——叙事发生在哪，以及这句话到底有多真。把这两处补上，五种题材的开篇都能稳定落账；不补，正文续写尚能勉强靠语言模型猜，分镜、互动叙事和作者工作台会连续踩错。**
