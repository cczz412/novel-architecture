# 二、打包格式（每包统一）

每包＝纯文本一件，拼接顺序：**公共头（第三节模板原样）→ 设计稿 v0 全文粘贴 → 窗口专属任务段（第四节对应 V0x）**。花括号占位符由你替换成实料。

# 三、公共头模板（每包开头原样带）

```
你是资深的叙事系统架构与产品顾问。我们在做一套以「大纲」为唯一中枢格式的商业网文创作系统——面向起点／番茄类连载网文及同源改编的 AI 漫剧／短剧，不是文学向长篇。读者要快节奏、强代入、金手指、规则感清晰、爽点密集、章章有钩子；一切结构化只是保住并放大读者爱看的点的手段。链路＝正文导入提取大纲／大纲生成正文／大纲生成分镜脚本／分镜生成剧情画面／AI 互动叙事／作者工作台，全部下游只认大纲一种格式。

硬性要求一（质疑令）：对已拍定的 T1～T12，你有任何怀疑，必须单列「质疑清单」一节点名指出——哪一条、为什么、用什么证据能证伪。不要客套附和；若无重大质疑也要写明并给理由。
```

# 四、五个窗口专属任务段

## V01｜结构承载复检

```
V01｜结构承载复检。请整体评审这套「大纲唯一中枢」设计：厚描三件套＋九类对象＋读者体验层接口（体验合同／具名视图合同）＋编排侧四件（Hook 账／暗稿／规划层／新逻辑句）＋流程工具（八阶段流水线／工具登记门槛／建议层／harness 分档）。逐块回答：①能否长期承载六个下游？②哪里过度设计（可删可缓）？③哪里缺件（不补会在 100 章／1000 章尺度上崩）？④块与块之间有没有互相打架的地方？
```

## V02｜五书试装压测

```
V02｜五书试装压测。请自选至少 5 本你熟知剧情的头部商业网文，覆盖至少四类题材（玄幻／都市／电竞／规则怪谈／女频向等），各取前五章。逐章用设计稿的结构试装：章末快照＋章内变化流＋章间交接＋九类对象（关键项填出即可，不必全量）。清点三类问题：A 完全装不进的奇怪结构（什么结构、为什么装不进）；B 装得进但别扭的（别扭在哪）；C 字段空转的（结构里有位置但这些书用不上）。对每个 A／B 给判别：该改结构固定核心，还是留给题材可选池／适配层？
```

## V03｜编排调用模拟

```
V03｜编排调用模拟。请模拟作者工作台的真实使用场景，各走一遍完整流程并评好用度：①已发表 20 章续写第 21 章（取哪些账、体验合同怎么出单）；②Hook 到期巡检（剧情内时间到 30 天，怎么查、怎么带出）；③分镜线按具名视图合同取数出一章分镜；④互动叙事分支（读者选剧情，边选边生成大纲增量）；⑤作者建议层出一次诊断（三档递进）。每个场景指出：取数别扭处、账写不进处、合同缺字段处、程序钩子缺位处。只模拟，不需要真实运行。
```

## V04｜外部创作者需求调查

```
V04｜外部创作者需求调查（请联网调研）。调研对象：起点作家助手／番茄作家后台／主流 AI 写作工具（彩云小梦、Sudowrite、NovelAI 等）的功能与用户吐槽，及网文作者社区（龙空、知乎网文话题等）的真实需求与痛点。输出：①按需求点逐条对表我们的设计稿——能承载／部分承载／接不住；②「用户强需求但我们结构接不住」清单（最重要）；③同类产品已踩过的坑。
```

## V05｜作者体验层与新形态调查（新增）

```
V05｜作者体验层与新形态调查（请联网调研＋产品判断）。四类画像逐个分析：小白作者／网文老作者／工作室（多人协作批量产出）／AI 漫剧创作者——各自：为什么要来用我们（来用的理由是否成立）？工作流哪一步最容易流失（丝滑度）？需要什么可视化（好产品要做到可视）？再评两个新造形态：①普通人有个想法扔进来→生成分镜式 SVG 火柴人定格动画，作为讲故事的方式（为新用户创造需求）；②AI 互动叙事＝定格画面一张张播放、养成／闯关游戏式选剧情，边选边生成大纲，把故事当成虚拟世界来闯。请调研相关同类产品与用户需求点，回答：这些需求在我们已定架构（大纲中枢＋具名视图合同＋画布工作流＋黑盒工作流／挂靠点）上是否都能实现？缺什么件？哪个画像最该先做？
```

## V06｜评测与金标体系调查ﾀ05:09 增补）

```jsx
V06｜评测与金标体系调查。我们要为新大纲格式重建评测体系：提取质量秤（内容秤／严格秤双秤）与作者建议层四层秤（诊断命中／建议可执行／作者认可含稍后撤销率／读者结果只校准）都需要金标。请回答：①新格式金标怎么制作最省人力（标注协议、样本选择、难章型覆盖、多标注人分歧裁决）？②LLM-as-judge 用于叙事提取／建议质量评审的可靠性边界与防漂移手段（judge 与被评模型同源怎么办）？③影子运行（旧单轮 vs 新流水线并行）的胜出判据怎么定才不被单一指标误导？④评测集多大够用、怎么防对评测集过拟合？给出可直接落地的评测体系设计。
```

## V07｜生成侧往返压测（信息充分性，05:09 增补）

```jsx
V07｜生成侧往返压测（信息充分性）。请做思想实验级压测：取一段你熟知的头部网文剧情（连续 3 章），按设计稿结构写出其厚描大纲＋体验合同，然后只凭这份大纲（不看原文）反向生成章节梗概，对照原文回答：①哪些读者爱看的东西丢了（爽点时机／情绪节拍／台词高光／悬念留白）？②这些丢失该补进大纲结构（哪个对象哪个字段），还是本就该留给生成侧自由发挥＋描写标签库／剧情引擎供给？③体验合同的七项字段够不够指挥一次合格的爽文章节生成，缺什么？④防刷量核查：如果生成模型学会「应付合同指标」，哪些指标最容易被刷、怎么设计不可刷的核查？
```

## V08｜平台政策与版权合规调查ﾀ05:09 增补）

```jsx
V08｜平台政策与版权合规调查（请联网调研）。调研：①起点／番茄／晋江等主流平台对 AI 辅助创作的最新政策（禁用／限制／标注要求），作者用 AI 工具的实际风险；②「正文导入提取大纲」的版权边界——用户导入自己作品 vs 他人作品做结构学习，法律与平台规则上各是什么性质；③小说改编 AI 漫剧／短剧／互动叙事的授权链条常见做法；④AI 生成内容的署名与商用规则（中国为主，兼看海外）；⑤同类 AI 创作产品的合规做法与已出过的事故。输出：对我们六个下游功能逐个标注合规风险等级＋规避设计建议。
```
