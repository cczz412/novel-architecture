# Agent 必读：建票、拆票与依赖规则

说白了就一件事：票怎么建、怎么拆、谁能拍板、什么时候才算真值。查依赖先读 [CCZ-77](https://linear.app/ccz/issue/CCZ-77)；路线图、Linear 关系和 GitHub 施工状态没有互相打架时，不要把全部 Todo 再扫一遍。

本文是 Git 里的必读入口。拍板出处：[CCZ-77](https://linear.app/ccz/issue/CCZ-77) 评论 `f804a645`（CZ 2026-08-25 15:45）。合并前若评论与本文冲突，以更新的 CZ 原话为准。

## 查依赖怎么读

1. 先读 [CCZ-77](https://linear.app/ccz/issue/CCZ-77) 票面「当前入口」和本文 R1–R5。
2. 再核对当前 Linear 关系（父票、blockedBy、relatedTo）和 GitHub Issue／PR 状态。
3. 三者打架再重做推导。没有冲突就不要重开全局审计。

R4 另加了一条：冻结快照引用的证据失效时，也要重开。见下。

## R1｜拍板权三要素

`needs-cz` 停点，Agent 不得自己拍。

拍板落账必须带三要素：**拍板人＋时间＋出处**（对话原话或评论 ID）。没有出处的「已拍定」一律视为未拍。

## R2｜候选默认条款

回包、证据、「待入位」标注**默认都是候选，进正式合同才算真值**。任何票不得把候选写成已批准；引用候选时必须标明候选身份。

## R3｜结构扩展路由

新账本／新格子／新对象类型不走普通 Triage→待办，必须走 [CCZ-102](https://linear.app/ccz/issue/CCZ-102) 两层协议（格子级／账本级）。Triage 只收未核实现象，不做结构决定。

## R4｜重开全量审计新增触发

冻结快照引用的证据失效（附件丢失／SHA 对不上／被覆盖）时，重开全局依赖治理。验收体系靠证据冻结，证据断了任务图就断了。

原先已有的重开条件仍然有效：依赖环、错父票、重复宿主、Done 父票仍挂活跃子票、关键输入没有证据、跨多线批量改关系，或 CZ 明确要求。

## R5｜状态联动后强制回读父票

子票 Done、PR 合并或自动化改状态后，必须回读父票。没有明确父票验收依据时，父票自动 Done 视为待校正，不能当作完成事实。

这条主要防止子票或 PR 的状态联动把父票提前关掉。它不要求关闭 Linear 自动化，也不改变原有父子关系和验收条件。

## 分工原则（软约束，不写死身份）

- **默认分工**：决策整理与拍板准备在 Notion 分析线；其他 Agent 主要建票／做票，票内自由度以停点为界。
- **不设硬身份认领**：欢迎任何 Agent 发现问题——发现好问题就写到票上（现象＋证据＋可回读入口）。这是鼓励的，不因越出默认分工而被拦。
- **底线只有三条**：不越 `needs-cz` 停点自拍（R1）；不把候选写成真值（R2）；结构扩展走 CCZ-102（R3）。守住这三条，其余不额外设限——目标是不乱，不是管死。

## 建票时还要守的机械纪律

这些是 CCZ-77 票面已有的执行口径，和 R1–R5 一起用：

- 写清真实父票或 root 原因。
- 每条硬前置写明缺少哪个输出。
- 写清领取后的连续推进范围和停点。
- 回读父票、状态、标签、阻塞、相关票、附件和文档。
- 对新票和一跳邻居做局部依赖环检查。
- 只有路线真的变化才更新 CCZ-77。
