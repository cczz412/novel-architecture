# 仓库寻路与卫生治理收口｜2026-07-25

✅ 结论：这轮已经把“入口难找、目录职责不清、换机器后断链、测试依赖本机大件、打包验得不够严”五类问题收紧。改动只覆盖仓库工程面，没有重判模型成绩，也没有动六本金标、现役 122 条、默认链或封存运行原件。

## 现在从哪里进

- 人看当前状态：`governance/INDEX.md`
- 程序读当前状态：`governance/CURRENT_STATE.json`
- 第一次进入仓库：根 `README.md`
- 找工具：`tools/README.md`
- 找测试及正式命令：`tests/README.md`
- 找实验：`experiments/README.md` 与 `experiments/INDEX.md`
- 找参考材料、旁路和工作区：各目录自己的 `README.md`

`governance/INDEX.md`、`governance/current_run.md` 和索引清单都由当前状态真源机械生成，不能手工各写一套“现在跑到哪”。

## 这轮实际改了什么

### 1. 一跳寻路

- 根 README 改成长期地图，不再复制会过期的模型、成绩和道次。
- 工具、测试、实验、参考区和支线区补齐职责说明。
- 停更的 `current.md` 只保留历史身份，不再被活跃说明页当入口。
- 归档 stub 明写“只读、不能继续收件”，避免新材料又写回旧目录。

### 2. 工具与实验有账可查

- `governance/tool_registry.json` 已覆盖工具根层 90 个 Python 工具；不再有“文件在，但没人知道是现役、兼容还是试验”的无身份工具。
- 实验索引只列正式登记件；未登记目录明确是候选，不再被静默当垃圾，也不能冒充现役。
- Z98 独立核验器的小型源码合同和 V02 四组纯结构夹具可以随 Git 走；真实运行件、请求正文和候选大池继续只留本机。

### 3. 换机器不再静默断路

- `corpus-downloads` 改为指向 `.local/corpus-downloads` 的仓内相对软链。正文仍不进 Git，新机器只需按 `references/corpus-pointers.md` 重建本地二级指针。
- Z88 外部回包由指向被忽略目录的软链改为自包含目录；历史 SHA 清单保留，另增当前实物清单和迁移勘误。
- V02 运输探针不再写死某个用户目录；支持环境变量覆盖，并以当前用户目录作为默认位置。

### 4. 打包和验包都收紧

- `simple_pack.py` 与审仓打包器的 dry-run 现在真正零写入。
- ZIP 包内固定带 manifest 与 SHA 清单，写完会回读 CRC、成员集合、字节数和逐件 SHA。
- 重名、绝对路径、反斜杠、`../` 越界、非规范路径和保留成员名都会拒收。
- 验包端也独立检查危险路径；即使外部 ZIP 的清单与 SHA 自洽，成员名含 `../` 仍判失败。
- 成品先写临时文件，完整验收通过后才原子替换目标。

### 5. 本地证据与干净克隆分开

`runs/`、`reports/`、`TEMP/`、`outbox/`、UCR 原始回包、Z99 大候选池，以及能拼回小说正文的 V02 锚目录和请求，全部继续不进 Git。

测试分两层：

- 本机有真实证据时，正式命令会跑全部回放测试。
- 干净克隆缺本地证据时，只跳过登记过的精确节点；同一文件里不依赖实物的纯工程测试仍会运行。

历史回放中有 28 个测试文件的全部用例都绑定本地实物，按整文件登记；另有 174 个混合文件内的精确节点登记。这个边界由 `tests/local_evidence_registry.json` 管，不能靠宽泛的 `test_*.py` 通配静默藏测试。

## 清理了什么，保留了什么

- 已清 Python／pytest／Ruff／Finder／Cursor 可重建缓存，至少约 63 MiB；最终测试重生的 13 个 Python 缓存目录也已再次清掉。
- 已移除 4 个没有 ZIP 成品的审仓半成品目录。
- 唯一可回读的旧审仓包保留，明确标作历史格式，不冒充当前完整包。
- `.venv` 保留；删它只会让本机命令失效，对 Git 体积没有帮助。
- 历史 runs、reports 和有效外发包未做手工去重或批量删除。
