## ✅ 总结论

ZIP 校验通过，SHA256 与指定值完全一致：

```
a3f472194f000cc9f4afd4bbf3d63f00eb7f620d3e95f8bdf0d833c1ba6db27b
```

三章文件各自的哈希也与包内清单一致。本次没有联网，也没有调用包外剧情。

这轮往返给出的判断很清楚：

> **现有“大纲唯一真账”能够保住主要事件、状态、因果和规则，足以反向生成一份剧情正确的章节梗概；但还不足以稳定生成一章读起来够爽、够惊、够像原作品的商业网文正文。**
> 

丢得最严重的不是“发生了什么”，而是：

- 爽点为什么在那个时刻爆；
- 恐怖信息按什么顺序露；
- 笑点怎样插进高压场景又不泄气；
- 主角能力靠什么具体动作证明；
- 哪句台词、哪个画面是这章的记忆点；
- 哪些解释只是角色推断，不能被生成模型写成客观真相。

🔥 **不建议另造第二套格式。**
建议仍以大纲为唯一格式，但在 `narrative_units` 内补一层有顺序的“阅读节拍”，再让体验合同引用它。

最小改动可以叫：

```
narrative_units[].reading_beats[]
```

每个节拍至少记：

```
顺序
前态
触发
角色行动／反应
事实变化
读者认知变化
目标情绪变化
兑现或Hook引用
强度与篇幅权重
信息揭露闸
高光锚
证据锚
```

这不是文学向的“精细分析”。它主要解决一个商业问题：**别让大纲反向生成时，只剩剧情摘要，没有追读体感。**

## 第一章《鲸落》

夏末夜里，警方在独居老人张翠莲家中勘验尸体。她已死去约两天，屋里的三猫四狗严重破坏了现场；尸体的脸、眼、手脚末端和部分四肢软组织都已缺失。王警官看过她生前与家人的合影，再回头面对残缺尸体，案件也多了一层独居老人无人及时发现死亡的冷意。

邻居提供不了多少线索时，背着书包、拿着韭菜盒子的高中生李昂突然插话，判断老人长期患有二型糖尿病，并用自己曾观察到的体征说明依据。他知识扎实，表达方式却十分荒诞，不断把王警官的严肃询问带偏。

李昂又提醒王警官，房间窗户关闭，主人死亡后两天无人投喂，宠物很可能先舔舐主人，尝到血后开始取食，最先遭殃的正是柔软面部和容易下口的指趾。尸体谜面因此获得一个现实、完整又令人不适的解释。李昂用“鲸落”类比生命死亡后被其他生物利用，在冷峻余味中结束这一章。

## 第二章《猫面》

离开警戒现场后，李昂想到近几个月越来越多的荒诞都市怪谈，以及它们传播后迅速被删除的现象，但仍觉得轮不到自己操心。回到所住楼栋，他发现电梯停用，只能爬上二十层。

楼道上方传来类似老人咳嗽的怪声。李昂起初仍边吃边走，直到数着台阶发现自己从八楼走到九楼后，又回到了八楼。向下狂奔也只在七、八楼之间循环，窗外则被浓雾完全吞没。他终于承认眼前是现实规则解释不了的异常。

怪声越来越近，声控灯也一层层亮起。李昂撬开八楼住户的门锁，门却像被封死一样无法拉开；混用经文、十字、手诀和步法也毫无作用。高压下，他突然冒充一个动画人物向黑暗挑衅，怪声反而停了。

短暂寂静后，一只穿黄色小马甲的黑猫缓缓走来，脸上严丝合缝地覆着张翠莲的脸皮，还吐出一根带肉手指。前章的现实解释被瞬间反转。李昂无处可逃，只在身后攥紧一根木筷，准备迎战。

## 第三章《玩家》

人面猫顶着僵硬人脸，却做出普通猫一样的可爱动作。李昂假装蹲下亲近它，袖中暗藏木筷，准备等它露出破绽便刺击。

怪猫只轻叫一声，他的四肢便迅速僵住，整个人保持半蹲姿势无法动弹；与此同时，怪猫自身也出现呼吸急促，说明这种能力并非毫无负担。它跳上李昂膝盖，缓慢舔破他的下巴，再开始撕咬吸血。

李昂由自己的处境反推出更残酷的死因：张翠莲很可能不是死亡后才被宠物啃食，而是先被定住，清醒地看着自己被吃。怪猫身上的黄色马甲随后脱落，露出淤青、针孔、刀痕和烫伤，显示张翠莲生前曾长期虐待它。这让整件事多了一层扭曲因果，却没有降低眼前的致命威胁。

李昂猛咬舌尖，以剧痛冲松束缚，抓住木筷刺入怪猫颈部要害，随后将它砸向墙面并连续重击，直到彻底失去反抗。怪物死去，浓雾和楼层循环随之消失。

紧接着，一个系统出现，判定原玩家被非玩家李昂杀死，将废弃的玩家资格转给他。李昂成为一级、零经验、没有装备和物品的新手玩家。系统又宣告神话、影视、游戏等幻想作品其实是其他世界的投影，众多文明正在竞争和渗透。一次楼道怪谈由此扩大成整个超凡世界的入口。

### 反面核查

用目标读者做三组盲测：

1. 只看现有七项合同生成；
2. 增加阅读节拍和揭露闸；
3. 再增加高光锚和兑现验收。

- 章读完率；
- 继续读下一章意愿；
- 能否说出主角性格；
- 能否复述本章最强画面；
- 恐怖／爽感峰值位置。

## ② 哪些该补进大纲，哪些留给生成侧

### ✅ 结论

不能简单按“重要／不重要”二分。建议分成三层：

### A. 必须进大纲本体

| 信息 | 为什么不能交给生成侧临场编 |
| --- | --- |
| **有顺序的关键节拍** | 第二章的黑猫→马甲→人脸皮→舌头→手指，换顺序就不是同一个悬念 |
| **信息揭露闸** | 必须知道什么暂时不能说、什么时候才能说 |
| **事实与推断身份** | “痛能破定身”只成功一次；“糖尿病死亡”只是李昂推断 |
| **爽点兑现证据** | 不能只写“李昂会撬锁、会医学”，要记这章靠什么动作证明 |
| **压制与释放顺序** | 第三章必须先让偷袭看似要成，再定身，再慢慢捕食，再反杀 |

| **Hook 的具体问题与切断点** | 不能只记“系统钩子”，要记读者此刻具体想知道什么 |

### B. 大纲记功能，生成侧写具体表达

| 信息 | 大纲怎么记 | 生成侧可自由处理 |
| --- | --- | --- |
| 法医专业感 | “需要可信专业流程＋宠物叫声形成荒诞对撞” | 具体术语、设备、动作 |

| 反杀暴力 | “精准刺击后过量补刀，体现冷静狠辣” | 拳击句式、血液和骨骼的描写 |

### C. 高价值表达采用“双层保存”

不要要求所有原句照抄，而是为少数高光加保存等级：

```yaml
canonical_moment:
kind: dialogue | image | action | reveal | proper_noun
semantic_payload:
exactness:
    function_only
    wording_preferred
    verbatim_required
position:
prerequisites:
forbidden_before:
downstream_priority:
    text
    comic
    short_drama
    interactive
```

本次建议列为高光锚的至少有：

- 第一章：“鲸落”收束；
- 第二章：胡图图式假身份挑衅；
- 第二章：人面猫分层揭露；
- 第三章：咬舌破局；
- 第三章：精准刺击＋过量补刀；
- 第三章：“猫饼”；
- 第三章：“地球杀场”。

### 代价与风险

- 高光锚太多，会让生成内容像照着原文复刻。
- 过多硬顺序会压低模型临场创造力。
- 同一句台词跨文字、漫剧、短剧不一定都适合原样使用。

推荐只对每章 **1～3 个真正决定追读的点**设为高优先级，其余只保语义功能。

### 反面核查

把某个高光锚从大纲中删掉，再生成三次：

- 三次都能稳定产出同等级替代品，说明它可留给生成侧；
- 三次都变成普通句、普通镜头或提前泄底，说明它必须进大纲。

---

## ③ 体验合同七项够不够

### ✅ 结论

**单独使用不够。**

七项适合做控制页，能告诉模型“这章要干什么”，但不能稳定告诉模型：

- 先干什么、后干什么；
- 信息要压到什么时候才说；
- 爽点怎样才算真的兑现；
- 中段要压多久；
- 哪个动作必须被演出来，不能一句总结；
- 哪些规则只是一次观察；
- 哪个画面或专名不能漏。

像第二章，现有合同已经写了“逐层逼近、人面猫揭面、木筷临战”，但仍然无法阻止模型把五个揭露动作压进一句话。

### 可操作方案

保留现有七项，不推翻 T7；增加六个引用或结构块：

```yaml
experience_contract:
promise_advances: ...
setup_uses: ...
rule_exposure: ...
desired_pattern: ...
avoid_signatures: ...
end_hook: ...
must_preserve: ...

beat_spine_ref: ...
reveal_policy_ref: ...
emotion_curve: ...
payoff_acceptance: ...
canonical_moments: ...
forbidden_shortcuts: ...
```

### 1. `beat_spine_ref`

指向有顺序的阅读节拍，不再靠一段 `desired_pattern` 自由理解。

### 2. `reveal_policy_ref`

至少包含：

```
谁知道
读者知道
角色误以为
客观事实
不能早于哪个节拍公开
公开后替换哪条旧解释
```

### 3. `emotion_curve`

不只写“惊悚→爽”，而是写关键点：

```
0%-15% 日常／好奇
20%-40% 认知异常
45%-70% 失去退路
75%-90% 压制和濒死
90%-96% 反杀释放
96%-100% 新世界钩子
```

百分比不必精确执行，主要用来防止模型过早打怪、过早发系统。

### 4. `payoff_acceptance`

每个爽点写清什么才算完成：

```yaml
payoff: 李昂撬锁能力
not_enough:
- 旁白说他会撬锁
- 一句话写门开了
required_evidence:
- 临场取材做工具
- 至少一个可信操作动作
- 锁确实打开
- 随后被异常规则压制
```

### 5. `canonical_moments`

保存本章少量台词、画面、动作或专名锚。

### 6. `forbidden_shortcuts`

例如第三章：

```
不得让怪猫第一次偷袭就死
不得让虐猫揭露直接促成和解
不得在战斗前出现玩家系统
不得把咬舌写成已知通用技能
不得用旁白一句“李昂爆发”代替破局动作
```

人物声音建议放在 `entities.voice_profile_ref`，不必把所有口癖塞入每章合同。

### 代价与风险

- 合同越来越长后，会和章内大纲重复。
- 作者工作台若把全部字段展示出来，小白作者会被吓退。
- 模型可能机械按节拍填格，形成千章一面的工业感。

解决办法是：**合同保持短，详细信息通过 ID 引用；作者界面只显示“这章必须守住的三五件事”。**

### 反面核查

做三档测试：

- 七项原合同；
- 七项＋阅读节拍＋揭露闸；
- 完整增强版。

若中档已经达到完整增强版九成以上效果，就不再增加字段。不要为了规格完整而把作者端做成数据录入系统。

---

## ④ 防刷量核查

### ✅ 结论

最容易被刷的是所有“出现过就算完成”的指标。

而且不存在永远不可刷的自动指标。能做的是：

1. 不让生成模型自己给自己打分；
2. 不只查有没有，还要查是否改变了状态和读者认知；
3. 用反事实删除、顺序扰动和重新提取交叉检查；
4. 把真实读者的继续阅读偏好放在高权重位置。

---

### 最容易被刷的指标与处理方式

| 指标 | 模型会怎么应付 | 不按表面计数的核查 |
| --- | --- | --- |
| 推进读者期待 | 在旁白里提一句“他离真相更近了” | 必须产生 `before→after` 状态变化，或明确增加／减少期待压力 |
| 使用铺垫 | 让木筷在场景里露个面 | 删除木筷后若反杀仍成立，说明只是摆设，不算使用 |
| 展示规则 | 用系统或旁白解释一遍 | 区分 `mention / observe / test / exploit / pay_cost`；合同要求哪级就验哪级 |
| 兑现爽点 | 写“众人震惊”“他赢了” | 检查前置阻力、角色行动、结果差、代价和不可逆变化 |
| 章末钩子 | 结尾突然出现黑影、敲门、提示音 | 必须形成具体问题、具体风险和继续阅读才能获得的答案 |
| `desired_pattern` | 每个词对应写一小段，机械打卡 | 检查节拍之间是否有因果，以及情绪是否真的发生变化 |
| 避免套路签名 | 换同义词，但仍走完全相同的桥段 | 用语义级事件序列查重，不按词面查重 |
| `must_preserve` | 把所有要求塞进一段说明文字 | 每项指定呈现方式、位置、前置条件和证据跨度 |
| 爽点密度 | 连续安排很多小胜利 | 检查每个爽点是否有铺垫成本、阻力差和释放间距 |
| 规则感清晰 | 角色连续讲规则 | 让独立提取器从行为结果反推规则；只能靠说明书读懂则降级 |
| 高光台词 | 强行写金句或网络梗 | 评估是否改变关系、情绪或人物辨识度，而不是句子是否像金句 |

---

### 推荐的不可轻易糊弄的核查链

#### 1. 独立回抽

生成正文后，由另一个提取步骤重新抽成标准大纲：

```
原大纲 → 生成正文 → 回抽大纲 → 对比原大纲
```

比较：

- 状态变化；
- 规则事实等级；
- 承诺推进；
- 揭露顺序；
- 章末未决问题；
- 专名和硬数据。

生成模型的自述不进入评分。

#### 2. 因果删除测试

删除某个被声明为“铺垫兑现”的节拍：

- 后续结果仍然完全成立：该铺垫可能是假使用；
- 人物胜利突然失去依据：说明它确实参与因果。

例如删掉木筷后，第三章仍能正常反杀，就说明模型另造了方便解法。

#### 3. 顺序扰动测试

把关键揭露提前或调换：

- 人脸皮先于普通黑猫出现；
- 虐猫伤痕提前到定身前；
- 系统提前到怪猫死亡前。

评价器若判断这些版本与正确版本差不多，说明评价器根本没有识别悬念结构。

#### 4. Hook 专项检查

一个合格 Hook 至少回答四问：

```
读者具体在问什么？
不继续读会缺哪份答案？
风险或收益是什么？
为什么必须在这里切断？
```

只有“突然发生新事”不算高质量 Hook。

#### 5. 最低门槛而非平均分

不能让“文笔不错”抵消“规则写错”，也不能让“爽点很多”抵消“主角突然降智”。

建议设硬门：

```
连续性
人物动机
规则边界
关键揭露顺序
must_preserve
```

任一硬门失败，章节不能因其他分数高而直接通过。

#### 6. 隐藏变体题

对同一合同随机改一个关键条件：

- 木筷改为钥匙；
- 怪猫不能定身，改为幻觉；
- 本章不得出现系统。

若输出几乎没变化，说明模型没有真正消费合同。

#### 7. 目标读者对打

自动核查只能防低级应付。高价值章节仍需让起点／番茄口径读者或经过校准的读者评价模型做二选一：

```
哪版更想继续读？
哪版主角更有辨识度？
哪版爽点更“挣来”而不是白送？
哪版章末切得更狠？
```

### 代价与风险

- 回抽、反事实改写、多个评价器会增加模型成本。
- 评价器也会学会偏好固定套路。
- 过度强调位置和强度，会让章节节奏模板化。

建议日常走“快速硬门＋单评价器”，只在以下情况启动深查：

- 规则置信度低；
- Hook 到期；
- 大爆点章；
- 新金手指出现；
- 已发表内容可能被改写；
- 多个评价器意见冲突。

### 反面核查

定期把明显作弊版本混进测试集：

- 全章多次写“爽”但没有状态变化；
- 章末随机敲门；
- 铺垫物只被提及一次；
- 规则全靠系统解释；
- 把所有 `must_preserve` 写成一段总结。

核查器若仍给高分，就说明指标已经被刷穿，应先修核查器，而不是继续调生成模型。

# 质疑清单

## 方法有效性质疑｜非 T 项

### 质疑

本次无法严格自证“模型级盲态”。

我确实按流程在写段 B 时没有重新打开原文，只读阶段 A；但同一模型此前已经读过原文，不能证明其内部记忆被清除。

### 为什么

流程隔离不等于认知隔离。段 B 可能无意识受先前阅读影响，因此它更接近“禁止回看条件下的回忆生成”，不是严格双盲重建。

### 用什么证据能证伪或解决

让一个全新隔离会话或独立模型只接收段 A，不接收 ZIP 和本轮历史，再生成段 B。将两份盲稿分别与原文对照。该结果才可作为强证据。

---

## T1｜厚描三件套是唯一真账

### 质疑等级：🟥 重大，但不要求推翻方向

### 质疑

“章末快照＋章内变化流＋章间交接”方向正确，但“章内变化流”若只记事实变化，会得到本轮盲稿这种结果：剧情正确，阅读效果明显掉档。

### 为什么

第二章最值钱的不是“人面猫出现”，而是普通黑猫、黄色马甲、人脸皮、舌头、手指按顺序揭露。第三章最值钱的也不只是“李昂反杀”，而是偷袭将成、突然定身、缓慢捕食、伤痕揭露、咬舌、精准刺击、过量补刀的顺序。

这些不属于纯描写，却也不是章末状态。

### 证伪方式

在至少五种商业题材中，比较：

- 只有状态变化流；
- 增加 `reading_beats＋reveal_gate`。

若目标读者对生成正文的追读意愿、爽点峰值和高光记忆没有稳定差异，该质疑被证伪。

---

## T2｜九类对象与 future_obligations 不抽

### 质疑等级：🟥 重大

### 质疑

“编排权不交给提取侧”是对的，但“future_obligations 记上不抽”过于绝对。

### 为什么

第三章已经明确向读者公开了玩家资格、新手引导和多世界竞争。提取侧若完全不登记候选义务，导入作品的章末承诺会丢失。编排侧甚至不知道读者已经被许诺过什么。

### 推荐修正

区分：

```
hook_occurrence：正文中已经发生的钩子事实，可抽
candidate_obligation：由钩子推导出的候选读者债，可抽但不排期
scheduled_obligation：正式排期，只能由编排侧决定
```

### 证伪方式

导入大量真实连载章末，不抽候选义务，再与“抽候选但不排期”方案比较续章 Hook 保真度。若无差异，该质疑被证伪。

---

## T3｜Hook 登记账

### 质疑等级：🟨 条件性质疑

生命周期设计合理。但若大纲本体只留下一个引用和状态，下游视图又只拿到 `scheduled/paid`，没有拿到：

- 读者具体问题；
- 风险；
- 兑现条件；
- 预计答复窗口；
- 当前压力；

下游仍然无法使用。

### 证伪方式

让正文生成、互动叙事和分镜三个消费者只读具名视图，分别完成续章。如果三者都能正确理解钩子而不直读 Hook 账，该质疑消失。

---

## T4｜旧逻辑句退役重造

### 质疑等级：⬜ 暂无重大质疑

退役旧格式而不是继续打补丁，方向合理。

**需补材料：新格式候选、旧逻辑句失败样例、主要消费者查询。**

目前能确认的是，新条目必须同时表达“事实变化”和“读者认知变化”，不能又退回只写因果句。

---

## T5｜暗稿挂编排侧

### 质疑等级：⬜ 暂无重大质疑

与 Hook 账配对合理。风险不在位置，而在暗稿是否被模型偷偷当成已经发生的正史。

### 证伪方式

让生成模型面对互相冲突的暗稿和已发表事实，检查是否稳定服从已发表事实；再测作者是否能区分候选、已采纳和已发生。

---

## T6｜故事线里程＋全书目标双层规划

### 质疑等级：⬜ 无重大质疑，但有一项边界

商业连载确实需要长期目标和实时路线分开。偏航系统必须允许“有效绕行”。

第二章大部分篇幅没有推进全书里程碑，却强力推进恐惧、规则认知和人物辨识度。若程序只按里程碑距离判定，会建议作者过早出怪、过早打赢。

### 证伪方式

比较“只看里程碑”与“同时看读者状态推进”的建议，交给网文作者和目标读者评价。

---

## T7｜体验合同七项

### 质疑等级：🟥 重大

### 质疑

七项作为章节控制页合适，作为一次合格爽文正文生成的全部指令不够。

### 为什么

本轮三个合同已经写明推进、铺垫、规则、模式、避重、Hook 和必保项，盲生成仍丢失：

- 揭露次序；
- 压制长度；
- 具体能力证明；
- 高光台词；
- 专名；
- 错误解释的事实等级。

### 证伪方式

使用同一模型和同一温度，分别按现合同与增强合同各生成多版，进行目标读者盲评。现合同若不弱于增强合同，该质疑被证伪。

---

## T8｜具名视图合同

### 质疑等级：⬜ 方向正确

下游不直读本体很重要，特别适合六类消费者分工。

风险在于消费者合同测试只查“字段有没有”，不查“语义有没有变”。例如字段里出现 `monster_reveal=true`，不代表人面猫的揭露顺序正确。

### 证伪方式

测试必须加入金标语义和变异样本：调换揭露顺序、提前系统、把推断写成事实，看消费者测试是否能拦住。

---

## T9｜八逻辑阶段混合提取流水线

### 质疑等级：🟨 中等

### 质疑

多模型、多阶段会放大前一阶段的合理误判。工件信封若只有值，没有“谁看到的、是什么性质、成功过几次”，后续模型会把推断逐级硬化。

### V07 证据

- “咬舌后束缚减弱”容易被写成通用解控规则；
- “猫死后鬼打墙消失”容易被写成猫必然是领域核心；
- “丢韭菜盒子”容易被明确解释成测试行为；
- “原玩家就是怪猫”虽然高度可信，仍应保留推断链。

### 证伪方式

测流水线的置信度校准、推断变事实比例和阶段间错误放大率。若多阶段方案稳定低于单模型且可校准，该质疑消失。

---

## T10｜黑盒自动型工作流

### 质疑等级：🟨 中等

黑盒对小白作者友好，但“提供挂靠点”还不够。真正进入唯一真账前，必须有：

- 人能看懂的变化摘要；
- 高风险项提示；
- 一键撤销；
- 原值与新值对照；
- 已发表事实保护。

否则提取器把“推断”改成“真相”，作者很难发现。

### 证伪方式

让小白作者在不看内部模块的情况下处理一批故意植入的误抽，看能否发现并撤销关键错误。

---

## T11｜建议层以推进力为评判标准

### 质疑等级：🟥 重大

### 质疑

“推进力”若主要指故事线里程和全书目标，会伤害悬疑、惊悚、喜剧和升级前的压制段。

### 推荐修正

把推进力改成两类并列：

```
故事状态推进
读者状态推进
```

读者状态推进包括：

- 更想知道答案；
- 对规则更确信或更疑惑；
- 风险感升高；
- 对主角更认可；
- 铺垫压力上升；
- 爽点释放前的压制有效累积。

第二章从听见咳嗽到人面猫出现，世界大状态变化并不多，但读者状态一直高速推进。

### 证伪方式

让“里程碑优先建议”和“双推进建议”分别修改惊悚章节，比较完读率和继续阅读意愿。若前者同样好或更好，该质疑被证伪。

---

## T12｜AI 管道单方案省 token

### 质疑等级：🟨 中等

高置信度任务给单方案合理；低置信度提取、Hook 冲突和大爆点修复仍强制单方案，容易把第一条错误路线直接写进真账。

### 推荐修正

按不确定度分流：

```
高置信度：单方案
中置信度：单方案＋反面核查
低置信度／高影响：两方案对打或生成方案＋批评方案
```

不必让作者看到所有 AI 分支，内部完成后只给推荐答案和差异原因。

### 证伪方式

比较全单方案与置信度分流方案在同等 token 成本下的关键错误率。若单方案恢复能力相同，该质疑消失。

---

# 建议本轮直接拍下的四项修正

🔥 **一，T1 不推翻，但明确“章内变化流”必须包含有顺序的阅读节拍，不得只做状态差。**

🔥 **二，T2 改成“提取侧可抽候选读者债，不得自行排期”。**

🔥 **三，T7 保留七项控制页，同时增加阅读节拍、揭露闸、兑现验收和高光锚引用。**

🔥 **四，T11 把推进力明确拆成故事状态推进和读者状态推进。**

其他几项更多是施工纪律：

- T9 补事实等级和置信度；
- T10 补提交前预览、差异和撤销；
- T12 按不确定度决定是否分支；
- T8 的消费者测试必须验语义，不只验字段存在。

这轮没有证据要求放弃“大纲作为唯一中枢”。相反，往返结果证明它能承载主干。真正危险的是把“大纲”误做成状态数据库，再指望生成模型自行补回商业网文最值钱的阅读节拍。那样能生成“讲对故事”的文字，却很难稳定生成让读者继续点下一章的文字。
