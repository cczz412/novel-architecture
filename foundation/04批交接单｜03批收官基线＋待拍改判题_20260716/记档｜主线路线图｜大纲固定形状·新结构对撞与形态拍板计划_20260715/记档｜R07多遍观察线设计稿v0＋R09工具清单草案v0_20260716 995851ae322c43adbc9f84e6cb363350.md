## 一、R07 多遍策略观察线设计稿 v0

- 目的＝把 ChatGPT（Pro 档）做提取／续写大纲／大纲改分镜时的思考过程拆成可移植的检查清单，给 DeepSeek 配 harness 用；G100 读数（0.220/0.165）＝改进前基线。
- 观察五项：
    1. 步骤序＝它先做什么后做什么、实际分几遍、每遍职责。
    2. 易错点＝哪里犹豫、哪里改口。
    3. 回头点＝什么触发它回头修正前面的结论。
    4. 自查法＝它用什么标准检查自己。
    5. 材料调取＝给足工具／接口信息摘要时，它主动调什么、嫌什么缺、哪里觉得会阻塞。
- 留痕规矩＝每次观察一个任务；要求 ChatGPT 边做边把思考步骤显式写出；全程原文存档不打断；任务后追三个固定问题＝「你哪一步最可能出错？」「只能调用一次你会砍掉什么？」「你希望工具／上下文补什么？」
- 比照法＝同一任务给 DeepSeek 现行默认跑一遍（走正常领号纪律），逐步骤对表：ChatGPT 有而 DeepSeek 没有的步骤＝候选钩子；差异逐条记入检查清单。
- 首批建议＝3 个任务（提取难章型一章／续写一章大纲／大纲改分镜一段），够出第一版检查清单即可，防过采。
- 纪律＝观察在 ChatGPT 端做不耗本地 API；产出只进候选池；多遍流水线落地另走 T9＋D02 改判申请；两遍法废同构禁复活。

## 二、R09 工具清单草案 v0（统一接口＝只认大纲格式；边界粒度＝T10 悬案待拍）

1. 正文→大纲提取（章）：输入一章正文 → 输出该章大纲账本。
2. 批量导入·正文：整本正文 → 逐章大纲。
3. 批量导入·外部大纲：外部大纲 → 拆成我们的大纲结构。
4. 批量导入·分镜：分镜脚本 → 反推大纲结构。
5. 大纲→正文生成（章）：大纲块＋描写标签＋剧情引擎 → 正文。
6. 大纲→分镜脚本：大纲块 → 分镜脚本段。
7. 分镜→画面生成挂钩：分镜段 → 画面生成任务单。
8. 剧情发生器：大纲现状＋引擎库 → 冲突／大势候选（解剧情平）。
9. 描写标签库调用：场景类型 → 写法标签包（爽点等）。
10. Hook 登记与巡检：登记未来事件（剧情内时间／节日／副本／宝物触发）；每章提取／生成后巡检到期 Hook。
11. 一致性校验：新章 vs 既有账本（知情差／实体状态） → 冲突清单。
12. 作者建议层：提取账本 → 「怎么改会更好」诊断建议。
13. 长线节奏台账：人物命运终局／感情线等长弧登记与进度对表。
14. 暗稿池：作者暗稿登记、按需调入生成上下文。
15. 往返一致性测验（测试用）：正文→大纲→正文对比出歪点。
- 备注＝每张卡名字守自描述起名规矩；输入输出都走大纲取数合同（T2 拍定后回填）。
