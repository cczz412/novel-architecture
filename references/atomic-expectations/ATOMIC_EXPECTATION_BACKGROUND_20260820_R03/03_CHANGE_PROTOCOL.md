# 原子需求背景板怎样升版

这块背景允许隔几天或隔一个月集中升版，但不跟着每次代码提交滚动修改。

## 可以原 ID 更新的情况

- 只把句子改得更像人话，用户目标和失败后果没有变化。
- 补充更清楚的测试材料、数据配方或评分解释。
- 修正仓库内相对来源，不改变预期含义。

## 必须新建 ID 或新版本的情况

- 用户使用时机变了。
- 希望系统替用户做的决定变了。
- 原来允许的失败变成必须拒绝，或相反。
- 核心与附加身份、权重或硬门发生实质调整。
- 原预期被拆成两个可独立验收的目标，或多个预期需要合并。

旧 ID 不能悄悄换意思。被替代的条目要保留旧版，并在新版本写清由谁替代。

## 新发现怎样进入

外部调查、Deep Research、用户访谈和本地失败案例先进入候选区。候选至少要写清：

- 真实使用时机；
- 用户想解决的问题；
- 系统预期行为；
- 不处理会怎样；
- 与现行条目是否重复；
- 需要什么材料才能验证。

有讨论热度不等于自动升核心。是否加入、放在哪组、属于核心还是附加，以及权重怎么调，仍由 CZ 和本地验证决定。

## 易变信息放哪里

- 当前完成度、基线分、本次分和回归结果放评测或运行区。
- 代码、合同、Schema 和接口放各自正式位置。
- 当前 owner、写集和任务状态放总控现场。
- 外部证据与来源强度放外部报告背景板。

这样升版时只更新真正改变的共同理解，不把运行噪声编进背景。
