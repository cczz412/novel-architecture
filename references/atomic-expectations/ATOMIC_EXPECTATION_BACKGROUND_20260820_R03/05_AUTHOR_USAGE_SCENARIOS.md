# 作者使用情境索引

同一条能力在不同使用时机里，正确行为可能不同。这张索引帮助 Agent 先理解作者正在做什么，再去查对应原子预期；它不规定页面和模块顺序。

## AS-01｜导入已有小说或材料

作者可能交来一章、很多章、ZIP、表格、设定、灵感或混合文件。外来正文要先认清材料身份、覆盖范围和损失，再走切段、抽取和作者确认。

## AS-02｜继续制作当前章事实稿

作者编辑的是有序事实句和写法批注，不是把正文当内部真源。材料、规划和检查结果要分层显示；普通建议不能自动变成事实。

## AS-03｜规划下一章、整卷或远期走向

作者可能没有规划、只有一句方向，也可能已有完整卷纲。M8 只规划下一章并维护长线；远期想法不能过早写成已发生事实。

## AS-04｜记录和调用灵感

作者可能只丢下一句话。灵感进入长线账并保留预计使用时机；到点可以提醒，但不能自动执行。

## AS-05｜审核外来正文抽出的事实

作者需要按章看到候选、原文证据和影响，再确认、驳回或修改。这里属于外来道；自产事实走作者签字身份，不能强求原文锚点。

## AS-06｜交棒自产章事实稿

作者明确交棒后，产品记录标题和章事实稿身份，不回 M2/M3 重抽。交棒、写入章节账和事实准入必须各自有可回验结果，不能提前宣称完成。

## AS-07｜同一本书混用外来旧章和自产新章

每章都要有可验证车道身份。外来章不能跳过抽取直接当事实，自产章不能误送回抽取。

## AS-08｜查询设定、前情和证据

作者问的是当前事实、未来计划还是某个角色知道什么，决定允许装入哪些材料。答案要带来源，并诚实说明被排除的范围。

## AS-09｜检查冲突和优化旧章

M7 可以定位问题并给最小回改／后文圆回两种方案，但只报告不改书。作者手改渲染正文出现新信息时，只报差异并升级候选，不整章重抽。

## AS-10｜打开十账户籍或给新设定找家

新项目先有章节、事实、人物、地点、物品、势力、体系、世界规则、长线、规划十账户籍。新忍术、新国家等设定应有唯一建议去处；没有合适账时提议开新账，不能只留在聊天里。

## AS-11｜断更后回来或跨设备继续

作者需要看到上次写到哪里、当时为什么这样决定、哪些计划仍有效。选择卡全文、版本和长期材料必须可重新读取。

## AS-12｜导出或交给其他工具

作者可能只需要一张场景卡、一份证据结果或一个上下文包。输出要自包含、身份清楚、可重复读取，同时不带出别的作者数据或未授权材料。

## AS-13｜多人协作或换平台

不同作者、编辑和 Agent 的材料来源与裁决权不能混成一种身份。换成网页、Notion、其他模型或云存储后，十账户籍、双车道和作者数据边界仍应保持。

这些情境来自现行产品背景和原子预期的稳定归纳。具体测试仍以预期 ID 和对应数据配方为准。
