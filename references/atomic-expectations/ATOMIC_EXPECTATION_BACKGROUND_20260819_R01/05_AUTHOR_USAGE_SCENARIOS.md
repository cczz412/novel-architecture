# 作者使用情境索引

同一条能力在不同使用时机里，正确行为可能不同。这张索引帮助 Agent 先理解作者正在做什么，再去查对应原子预期；它不规定页面和模块顺序。

## AS-01｜导入已有小说或材料

作者可能交来一章、很多章、ZIP、表格、设定、灵感或混合文件。系统要先认清材料身份、覆盖范围和损失，再决定交给哪个能力处理。

## AS-02｜继续写当前章

作者希望少填表、少被打断，同时需要事实、规划、人物状态和冲突提醒在合适时机出现。系统不能把普通建议变成强制流程。

## AS-03｜规划下一章、整卷或远期走向

作者可能没有规划、只有一句方向，也可能已经有完整卷纲。系统要帮助放置和细化，不能把远期想法过早写成当前章事实。

## AS-04｜记录和调用灵感

作者可能只丢下一句话。系统要能保存、找回并在相关时机提醒，但不能因为“像是能用”就自动执行。

## AS-05｜审核系统抽出的事实

作者需要按章看到候选、原文证据和影响，再确认、驳回或修改。高影响决定不能藏在大批默认动作里。

## AS-06｜查询设定、前情和证据

作者问的是当前事实、未来计划还是某个角色知道什么，决定了允许装入哪些材料。答案要带证据，并诚实说明被排除的范围。

## AS-07｜检查冲突和质量

系统可以发现矛盾、漏抽、断锚和规划偏离，但发现不等于自动改正文或替作者裁决。

## AS-08｜修改旧章或改变既定方向

旧事实、人物状态、未来计划和下游概览可能一起受影响。系统要沿真实依赖处理，不能全书盲重算，也不能继续使用已经过期的结果。

## AS-09｜断更后回来或跨设备继续

作者需要看到上次写到哪里、当时为什么这样决定、哪些计划仍有效。时间可以触发回看，但不能自动让旧决定失效。

## AS-10｜导出或交给其他工具

作者可能只需要一张场景卡、一份证据结果或一个上下文包。输出要自包含、身份清楚、可重复读取，同时不把别的作者数据或未授权材料带出去。

## AS-11｜多人协作或换平台

不同作者、编辑和 Agent 的材料来源与裁决权不能混成一种身份。换成网页、Notion、其他模型或云存储后，业务语义和作者数据边界仍应保持。

这些情境来自现行产品背景和原子预期的稳定归纳。具体测试仍以预期 ID 和对应数据配方为准。
