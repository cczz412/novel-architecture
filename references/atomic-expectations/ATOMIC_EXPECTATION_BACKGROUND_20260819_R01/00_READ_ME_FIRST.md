# 原子需求与验收背景板 R01｜先读本页

- 版本：`ATOMIC_EXPECTATION_BACKGROUND_20260819_R01`
- 收录：127 条原子预期；其中核心 78 条、附加 49 条，需要真实小说配料 44 条。
- 来源基线：2026-08-19 的现行原子能力预期本地快照；整理时删除了运行状态、本次分数、完成度、数据包进度和本机绝对路径。
- 身份：跨 Codex、ChatGPT、Notion、网页和其他 Agent 使用的共同需求背景。
- 权限边界：不是正式合同、施工票、权重修改授权、产品完成证明，也不产生 API、训练、Gold、上传、生产或 Git 权限。

## 这块背景解决什么

产品设计、模块边界和界面会不断调整，但用户真正想解决的问题不能跟着实现方案漂走。本板把这些问题拆成可单独阅读的预期：用户交进什么，系统应该做什么，应该产出什么，哪些失败必须明确拒绝，以及怎样用材料和分数检查结果。

你可以直接理解成：

- 产品共同背景板说明“为什么做、原则是什么”。
- 外部报告背景板说明“真实世界提供了什么证据和反例”。
- 本板说明“做到什么才算对用户有用”。

## 怎么读

- 人先看 [01_ATOMIC_EXPECTATIONS.md](01_ATOMIC_EXPECTATIONS.md)，按 M1～M11、作者工作区或跨模块组寻找相关预期。
- Agent 需要精确字段时读取 [02_ATOMIC_EXPECTATIONS.json](02_ATOMIC_EXPECTATIONS.json)。
- 需要升版或判断能不能改原预期时，看 [03_CHANGE_PROTOCOL.md](03_CHANGE_PROTOCOL.md)。
- 需要跨模块判断时，先看 [04_GLOBAL_ACCEPTANCE_RULES.md](04_GLOBAL_ACCEPTANCE_RULES.md) 的共同验收家规。
- 不知道作者此刻为什么需要某项能力时，看 [05_AUTHOR_USAGE_SCENARIOS.md](05_AUTHOR_USAGE_SCENARIOS.md)。
- 只读与当前任务直接相关的几条；不要因为文件存在就把 127 条全部塞进一次施工上下文。

## 哪些内容相对稳定

- 预期 ID 和它表达的用户目标。
- 用户在什么情况下需要这项能力。
- 系统应该给出的结果和必须避免的失败。
- 验收关键点、测试材料方向和评分维度。

## 哪些内容故意不放进来

- 某个窗口现在做到哪、谁正在施工。
- 当前完成度、本次分、回归结论和临时数据包状态。
- 某次测试的 SHA、运行回执和短期路线。
- 某个 Agent、平台或模型专用的操作步骤。

这些内容变化快，仍由当前状态、正式结果票和本地运行证据负责。背景板不能反过来证明代码已经做到某条预期。

## 使用顺序

1. 先确认这次任务服务哪条预期，以及它是核心还是附加。
2. 再看当前产品设计和合同怎样承接它。
3. 用对应测试材料和评分维度设计本地验证。
4. 新发现先记成候选；没有确认前不能偷换现有预期或权重。
