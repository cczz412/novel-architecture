# 产品北极星

状态：**项目级共同背景指导；长期骨架来自已拍产品方向，不替代上游拍板原页**

## 一句话

这是一个以**大纲中枢**为作者工作面、以**冻结正文和确认后的故事状态**为历史依据、能准备下一步创作、追溯证据并安全修改长篇故事的系统。

## 它主要解决什么

作者真正难的不是“让 AI 多抽几条事实”，而是写到几十章、几百章后还能做到：

- 看得清当前故事走到哪里，接下来几章准备往哪转；
- 人物状态、知情、承诺、规则、因果和故事线不崩；
- 缺前情时回冻结正文取证，不靠模型凭记忆补故事；
- 改一处时只复核真正受影响的部分；
- 大纲、正文、分镜和互动分支共享故事底座，但互不冒充真值。

## 默认服务谁

当前已拍口径不是优先服务“十万字以上才遇到长程问题”的作者。主体用户是已经写完黄金三章、正在 3～20 章之间继续推进、开始遇到结构和接续困难的网文作者。

入口是黄金三章工作台，作者可以边写边把故事状态和大纲逐步建起来。已有长篇作品仍可导入，但“先把全书深抽完才能开始工作”不是默认路线。

## 三个中心

| 中心 | 管什么 | 不管什么 |
|---|---|---|
| 前台以大纲为中心 | 作者安排未来、处理本章主管线问题、决定场景和待办 | 不把计划当已发生历史 |
| 后台以故事状态为中心 | 事实、状态、知情、因果、义务、规则和证据 | 不替作者安排未来剧情 |
| 生成以场景为中心 | 大纲关闭后，逐场生成、交付、对账和局部重做 | 场景不是新的真值容器 |

一章负责关闭和入账，场景负责生成和对账，卡片负责处理问题。大卡片承载本章主管线问题，小卡片修遗留逻辑；卡片数量不设固定门。

## 两条主流程

### 导入已有作品

```text
冻结正文
→ 建来源坐标与检索入口
→ 作者提问，系统按需回原文取证
→ 独立判断回答能不能用
→ 将持续影响后文的关键变化提名入账
→ 作者或正式闸确认
→ 更新状态、知情和长线账
→ 生成可编辑的反向剧情地图／成文剧情图
```

AI 从已有正文还原出的结构不能叫“作者大纲”。它是反向整理出的成文地图，叙事作用推断还要带置信度。

### 从大纲继续创作

```text
选择故事线
→ 编辑本章计划和场景安排
→ 处理大卡与必要小卡
→ 大纲关闭
→ 编译场景执行包
→ 逐场生成、逐场交付
→ 计划—成文对账
→ 作者确认差异
→ 将确认稿冻结为带版本、来源编号和 SHA 的正文证据
→ 登记真正写成的事实和状态变化
```

章节工作室在大纲阶段不产正式稿。正式正文等大纲设计完成后再生成；若某一场需要重做，只重做受影响场，并带上全章大纲、上一场结尾、本场义务包和风格锚。

## 产品长期纪律

- 已发生事实和未来计划分账；
- 查询回答默认是临时结果，不自动永久入账；
- AI 只能提议高影响变化，作者确认后才进入正史；
- 事实证据、计划、投影和推断不能互相冒充；
- 有两端可回验依据的已确认硬事实冲突亮红灯，节奏和手法建议亮黄灯，尚查不实的隐含／多跳矛盾只进“待复核线索”队列；系统只能说“当前覆盖范围内未检出”，不能宣称查尽；
- 冲突也可以转成剧情机会，不等于系统只负责把冲突消掉；
- 大纲阶段逐卡撤销，修稿阶段必须能回滚；
- 第一版不做高成本视觉生成，先把大纲、证据、下一章生产和文本分镜跑顺；
- 产品流程不绑定某一家模型。

## 上下文与记忆的长期方向

故事记忆不是“把所有正文分片塞进向量库”。当前已拍方向是围绕事实句做伸缩压缩：越远越压缩，关键因果保留头尾，不可逆变化长期保留；切换故事线时，优先接回同一故事线上一次出现的状态。压缩视图本身就是多粒度派生摘要载体，胶囊和章节摘要只是它的形态，不是另建一套摘要真值。

原文仍然保留在冻结正文中。远期常驻压缩只负责导航，按需回捞冻结原文是刚需。摘要和状态只负责帮助定位、准备和判断，不能取代证据；“不走正文分片向量检索主路线”约束的是真值表示，不禁止检索通道使用 BM25 或向量扩召回。

## 成功的最小读数

- 作者的关键问题能被回答，回答能回到原文；
- 下一场或下一章的执行包够用，不必重读整本书；
- 计划、历史、查询和投影不混账；
- 一处改动只重做清楚标出的受影响范围；
- 作者能看见风险和已通过部分，不被系统反复唠叨；
- 模型换掉以后，业务数据、证据和创作流程仍能继续工作。
