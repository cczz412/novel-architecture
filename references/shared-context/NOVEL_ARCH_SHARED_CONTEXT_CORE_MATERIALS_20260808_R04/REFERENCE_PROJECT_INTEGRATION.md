# 可选参考｜项目自动寻路怎样继续扩展

状态：**参考件；当前只启用 Agent 只读入口，其余接入层未启用**

## 这份参考保留什么

前一版方案不只做了八份核心材料，还设计了三层项目接入：

1. 在共同背景目录外放一份稳定 `README.md`，告诉人当前应该读哪一版；
2. 放一份机器可读的 `CURRENT.json`，登记当前目录、入口、核心 SHA、整包 SHA 和权力边界；
3. 在 `AGENTS.md` 增加阅读规则，让复杂任务、新窗口和跨环境交接开工前自动找到当前背景板。

这些设计没有作废。当前只启用了第 3 项的最小版本：仓库 Agent 通过 52 行根 `AGENTS.md` 找到 R04 的 `00_READ_ME_FIRST.md`。外层稳定入口和机器指针没有创建。

W06-D2 已把 repo-wide CURRENT、finetuning CURRENT 和 progress 的职责正式对齐；R04 只更新共同理解，不新增 shared-context CURRENT。R03 继续作为 immutable 历史版本保留。

## 当前怎样启用

CZ 要的是一个可以直接整目录交给 ChatGPT、Notion 协作者、Codex 或其他窗口的本地材料文件夹，同时要求仓库 Agent 开工时能找到它。当前做法保持两件事同时成立：

所以当前选择是：

- 八份核心材料是正式共读主体；
- 本目录整体是交付单元；
- `AGENTS.md` 只负责把 Agent 带到本目录入口；
- 本参考保存以后扩展自动接入的方案；
- 没有创建外层 `README.md` 或 `CURRENT.json`，也没有修改运行状态真源。

## 以后启用时怎样做

如果以后还需要外发工具自动找最新版，或需要长期切换 R04／R05，可以另开一张小工单：

- 建立一个稳定的人类入口，只指向一个当前背景板目录；
- 建立一个机器指针，登记版本、核心 SHA、整包 SHA 和验收回执；
- 保留当前“先读 00、复杂任务再读相关页”的规则，简单机械任务不强制通读八份；
- 明确共同背景板不是 Notion 拍板账、不是 `CURRENT_STATE.json`、不是训练或 Git 授权；
- 切到下一版时改入口，不原位改 R03。

## 本地与 Notion 的关系

本地已经比不少 Notion 普通页面新。自动接入继续扩展时，也应把 R04／后续版本当“当前共同产品说明”，把 Notion 账序当活裁定通道和拍板证据库；当前技术状态仍回本地正式合同、结果票和现役指针核对。
