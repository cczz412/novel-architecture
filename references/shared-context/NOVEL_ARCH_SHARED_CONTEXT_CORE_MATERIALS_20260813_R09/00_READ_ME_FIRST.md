## R08 → R09 主要变化（十分钟看懂这版变了什么）

按主题分组；每组给落点页。拍板日期均为 2026-08-13 上午，逐条原文见第二册挂账本。R08 吸收的 R07→R08 变化清单见[父版 R08 先读页](../NOVEL_ARCH_SHARED_CONTEXT_CORE_MATERIALS_20260813_R08/00_READ_ME_FIRST.md)。

### ① 写作与检测（01、03 页，本轮最大变化）

- **内置写作区**（K3，推翻“作者拿指导复制出去写”的旧假设）：作者在产品内对着指导直接写；**AI 零介入**（不补句、不改写、不续写），J1 红线一字不动。
- **当场检测**：写完一段当场对照章纲检测回收，不等全章写完；**三路收工**（K4）：写了正文／只关章纲不写正文／写了但先不检测，三条路都合法。
- **暗稿新义**（K3）：已发生但作者没写成正文的事实句标记 `prose_status`，留在账上不丢——注意与旧“暗稿层”模块不同物（旧义已被 N17 吸收）。
- **小说腔的唯一位置**（K5）：AI 文字全线保持工具腔，唯一允许小说腔的位置是描写要求里的信息点表述。
- 写作区工程细节见 [WRITING_DESK_DESIGN_R01](../../../../novel-mvp/design/WRITING_DESK_DESIGN_R01.md)（三题按推荐暂定，已按正式决定吸收）。

### ② 章工作台与出题机制（03 页）

- **篇章组**（M1）：连续几章绑成一组连续创作，组内切章不重新开章问线，收工统一对账。
- **要点汇聚屏**（K1）：G3 十类来源的架构细化——插件提醒等一切“这章该考虑什么”的要点先汇到一屏集散地，再进主架编排。
- **切线预告**（K2）：切故事线要有提前量，先预告后切，不搞突然袭击。
- **变体必带反馈**（M2）＋**快速铺满**（M3）：选项变体必须回答“跟上一版比变了什么”；作者可以一键让系统按推荐把本章铺满再挑着改。
- **衍生点子卡＋灵感区合并**（K8）：出题过程冒出来的点子落卡；系统灵感区并入灵感记事本，不另立第二个灵感容器。

### ③ 字数预估的真身（03、04 页）

- **字数预估＝节奏抑制器**（M8）：它的真实作用不是精确预测字数，而是压住“一章塞太多”的冲动＋给下一章留活；预估不准是常态，机制价值在约束不在精度。

### ④ 主屏、完本与任性权（03 页）

- **战报式主屏**（M4）：每章关章都出战报，不是断更回归专属功能。
- **完本三件套**（M5）：完本时点收尾核对、全书战报、下一本的经验包。
- **作者任性权**（M6）：作者要任性改，系统让路＋顺手收伏笔，不设卡。

### ⑤ 大书接入与角色 ID（02、03、04 页）

- **大书接入分层**（K6）：先粗抽建骨架（便宜、快），作者用到哪精抽到哪；配思路插件族辅助消化；**拒绝无设计续写**——没建立设计理解前不给续写指导。
- **角色 ID 永不硬编码**（K7）：正文之外所有账面引用一律用角色 ID 变量，改名、多马甲、视角切换都不用翻账重写。

### ⑥ 插件系统（02、03 页）

- **随时自拆 Skill**（M7）：作者可以随时把自己喜欢的写法拆成自用插件；远期社群共享愿景挂账不展开。

### ⑦ 部署与工程纪律（02、05、07 页）

- **标准云服务＋前端缓存策略**（N1）：部署不搞特殊，SVG 等重复素材按编号走浏览器缓存省流量。
- **MVP 开工工程纪律**（N3，CZ 原话要点全录进 05 页）：**模块 README 制**（每个模块配说明谁都能看懂）＋**可观测性前置**（日志、状态可见性一开始就做，不事后补）。

### ⑧ 研究线与流程（05、06 页）

- **研究线改定位校准器**（N2）：从“产品开工的阻塞前置”改为“给产品参数做校准”；数据资格、训练门、DISCRIM17／T-03 的实验身份都不变。
- **Notion 同步安排**（N4）：R08 不单独推；R09 建成后一次性同步最新版，由 Cursor 直接推。
- 05 页开放问题第二轮大扫除：写作区三题、篇章组、变体反馈、完本三件套、任性让路、演示书真书等已关闭移已决；新挂“暗稿的后续捞取”“思路插件族的具体内容工单”。
