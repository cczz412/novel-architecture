## 挂账本机制（R07→R08 实践确立，R08→R09 沿用）

版本包 SHA 冻结＋Notion 同步后，往包里塞文件会破坏完整性核验；而每来一点新内容就全量改版也受不了。因此：**小批语义新增先记挂账本**（TEMP 审计目录内的增补案文件，每条给来源＋按页码的落点＋正文），攒够一批或出现必须改版的大事时，由下一次组装一口吸收。挂账条目是候选，不改变现行版地位，也不产生执行权；吸收或驳回的处置结果回填挂账本状态列。第一册（ADD-001～017）已随 R08 封账；第二册（ADD-018～020）随本 R09 封账。

## 什么时候需要出新版本

出现以下任一情况，就建立新版本，不在已发布版本里静默改字：

- CZ 新拍或改拍会改变产品语义；
- 正式合同或结果票让现有描述失真；
- 现行版出现会误导执行的冲突；
- 新增或撤销背景板成员；
- 易变登记页的更新影响核心结论。

纯文字修复、不改语义时可以出补丁版，但仍要重算 SHA、登记差异；不得原位改写已发布父版。

## 更新与裁决规则

- 账序保存拍板原句，是裁定证据真源；背景板负责解释，不代替账序。
- 裁决按原子 ID 处理。`APPROVED_DIRECTION` 只进入语义方向；`DEFERRED` 留开放问题；`REJECTED` 从正文摘除并保留追源；未出现的原子维持原状态。
- 与父版冲突时，00 页用“旧句／旧读法 → 新句”登记原子 ID、裁决依据和影响页。
- 题 15、题 16 继续沿 R06 挂账，除非账序明确逐题改判。
- 语义方向不自动生成数据库、接口、工程任务、模型调用、训练或生产许可。
- 字段、表结构和接口细节由 T3 与后续施工合同另行冻结。

## 变更分级

| 级别 | 例子 | 处理 |
|---|---|---|
| 裁决变更 | 用户、真值边界、核心流程、权限边界改变 | 新版＋账序依据＋逐页影响表＋完整机械验收 |
| 合同对齐 | 正式字段或验收合同冻结后修正背景板描述 | 新版或补丁版，注明正式合同与影响范围 |
| 易变资料刷新 | 竞品、市场、价格和验证数字更新 | 只改 08 页；如改变核心结论再升版 |
| 文字修复 | 错别字、坏链接、不改语义 | 补丁版＋SHA 重算＋修复记录 |
