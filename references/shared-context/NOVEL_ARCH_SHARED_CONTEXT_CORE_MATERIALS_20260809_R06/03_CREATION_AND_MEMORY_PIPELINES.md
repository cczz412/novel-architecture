## 管线总原则
系统不把“抽取”“记忆”“章纲”“生成”揉成一次模型调用。每一步都留下能检查的工件：来源、查询结果、计划、执行包、场景稿、对账结果和长期入账彼此分开。
系统定位是导写＋核对，不代写：管线的产出是选线、约束、章纲、材料包和对账结果，不是替作者写成的书稿；“一键成文”只是后续可选模块。
总家规同样管管线：每个中间结构（切线包、执行包、重签清单……）都必须说清谁消费它，没有消费者的不进核心档。
## 已有作品怎样接入（修复模式入口）
```plain text
1. 冻结书稿，登记版本、来源坐标和 SHA
2. 建立可检索入口，但不要求首次穷尽全书
3. 作者提出当前真正要解决的问题
4. 系统按问题回冻结书稿取证
5. 程序回填逐字证据和位置
6. 独立评分或人工判断回答是否完整、限定是否正确
7. 持续影响后文的变化进入永久事实提名
8. 作者或正式闸确认
9. 更新状态、知情、因果、义务和规则
10. 投影出可编辑的反向剧情图
```
回答不了时要返回“材料不足”和回取轨迹，不能补故事。旧作品接入的目标是尽快让作者继续工作，不是先做一场全书考古工程。
入口分叉（账序 21:05 条判 11）：**修复模式**（已有作品接入、旧账补建、历史问题修理）与**续写模式**（下一章生产）是两个入口，共用同一套底账和真值分层，不各建一套。
## 从章纲继续写怎样跑（续写模式；R06 改写，账序 21:35 条②③⑤⑥）
```plain text
开章第一问：选故事线（保持或切线）
→ 切线＝重动作：出切线包（目标线上次现场恢复＋衔接设计作者选＋读者重认知提示）
→ 读取本线上一次接力点和上一章出口
→ 接收三级盒子约束：全书宏观大纲→卷纲→章盒子，另加作者本章临时约束
→ 编辑本章目标、计划事件和场景安排（章纲）
→ 处理本章主管线大卡与必要小卡（创作卡／修复卡）
→ 关闭章纲（编译吃约束：硬性承接、义务、结尾钩子、字数目标和 QC；冲突亮灯）
→ 按场景编译执行包
→ 作者写书稿（系统导写；一键成文＝后续可选模块，逐场交付、逐场回收）
→ 每场做计划—书稿回收核对（写了／没写／写错三态）
→ 作者确认差异（批量默认＋重签清单单独勾选）
→ 将确认文本冻结为带版本、来源编号、位置和 SHA 的书稿证据
→ 章末汇总真正写成的剧情原子和状态变化
→ 更新长期账并重建需要的投影
→ 关章＝清账不清零（未完事项显式转下章挂账才能关）
```
章纲阶段可以只编辑章纲，不产稿。书稿的重做半径默认限制在受影响场，不把整章和无关下游一起推倒。
这里的“逐场回收”不等于场景稿自动成为真值。未确认稿仍是可重建投影；确认稿要先形成不可静默覆盖的书稿版本，事实才能引用它。具体按场冻结、按章冻结，或两级都保留，仍要由施工合同锁定。
触发满足时（账序 21:35 条④）：默认只亮灯，亮灯项进执行包并提升相关材料检索优先级，不自动开卡；是否开卡由作者决定。
## 场景执行包装什么
每个场景执行包默认只带当前任务需要的内容：
- 全章章纲与本场目标；
- 上一场结尾原文和当前接线原因；
- 当前故事线及相关入口状态（含切线包，如果本章切线）；
- 本场涉及人物的状态与知情；
- 到期义务、生效规则、接近触发事项和已亮灯触发项；
- 必要的直接原因和未决事项；
- 从冻结书稿按需回取的少量证据；
- 用户确认片段形成的风格锚；
- 版本、来源和过期状态。
它不默认塞进上一章全部事实，更不默认塞入整本书全文。执行包供作者导写使用，也供后续可选生成模块使用；两种消费者同一份合同。
## 记忆怎样加载
当前已拍方向是“剧情原子伸缩压缩”：
- 当前完整；
- 近期展开；
- 远期压成带覆盖编号和过期状态的一句话；
- 关键因果保留头尾；
- 不可逆变化长期保留；
- 切换故事线时优先接回同一故事线上次出现的材料。
**双密度制与沉降**（账序 21:05 条判 2／3＋补丁二）：章节原料层登记本章全部剧情原子，长期底账只升关键变化；关章“沉降”只收缩常驻／展示层，底层剧情原子和证据永不删；回捞重建必须可验证。
压缩视图本身承载多粒度派生摘要，胶囊或章节摘要只是呈现形态，不另起摘要真值。远期常驻视图只做导航，原文始终留在冻结书稿并可按需回捞；这条回捞通道是刚需，不是可选增强。压缩不能顶替证据。
当前不把“向量检索书稿分片”写成产品真值表示的核心路线，但检索通道可以用实体／时间／故事线硬召回、BM25 或向量扩召回来找候选原文，再回到冻结文本核证。
因果读取也走派生路线：程序先从已登记事实中生成候选对，模型逐对受约束判断“有边／无边／待复核”，不开放式补边。长链只作较弱导航，需要更谨慎地回原文或进人工复核；具体链长门另由实验合同锁定。
## 事实抽取在管线里的位置
事实抽取只负责给查询、状态更新和长期记忆供料。它不独占产品主流程，也不追求首次把一章所有细节都抽尽。
本地已经建立“模型选目标区事实和证据编号、程序做合法性与逐字回填”的候选机制。更宽阅读材料和更窄责任区的组合很有研究价值，但具名的 `Wide Read / Narrow Write` 仍是研究假设，不是现役合同。
⚠️ 术语迁移保护（补丁一）：实验家族、CONSUME／EDGE、冻结合同里的“事实句”“正文”不改名、不返工；映射句：**实验语境的“事实句”＝已发生态剧情原子；实验语境的“正文”＝书稿**。改名只发生在产品背景板层。
## 计划—书稿回收核对（R06 扩充，账序 21:35 条⑤⑥⑦）
回收后至少要分开六种结果：
- 按计划写成；
- 变体写成；
- 漏写；
- 与计划冲突；
- 新增未计划内容；
- 延后处理。
对已登记硬事实和作者锁定真相，另按三态处理（硬事实对得上就行，不逐句对稿）：
- **写了**→原子挂书稿出处，可见性升“读者已释放”；
- **没写且不冲突**→合法的作者 Canon 态；只有章纲标“必写”的漏了才提示；
- **写错**→红灯，出书稿修改指导单；作者坚持书稿版＝一次改账，走修改传播留痕。
**确认粒度**（账序 21:35 条⑥）：默认批量确认；以下四类进**重签清单**单独勾选，不随大流：Bible 新增／改动、人物永久不可逆变化、作者锁定真相新增／改判、跨线大因果；清单可扩展。
**沙箱合并**（账序 21:35 条⑦）：沙箱只存差异；分支内产物带沙箱标、对主线零效力；合并＝对账（普通改动批量确认，重签类单独签）；未选分支作废留痕；更细规则 MVP 后再定。
只有作者确认的结果才更新真值。改台词和文风不自动改事实；改未来计划不冒充已发生；改事件结果要提名受影响项；改证据要重判承托，不重做无关投影。修改传播按三层处理（机器自动重算／计划态亮灯可豁免／冻结书稿只出指导单，见 02 页）。
## QC 和风险怎样出现
- 硬事实冲突亮红灯；
- 节奏、手法、情绪和模板偏离亮黄灯；
- 隐含、多跳、动机类或两端证据尚未闭合的矛盾只记为“待复核线索”，进入裁决队列；
- 卡位点所见即所得地报警；触发满足默认只亮灯，不自动开卡；
- 作者可以喊停、降灯或豁免软问题；
- 硬来源不能批量豁免（重签清单单独勾选）；
- 风险和待确认项集中进裁决队列，不塞满每一段书稿。
红灯只给两端都能回验的已确认硬冲突（含与作者锁定真相的冲突）；只有这类红灯可以阻塞关章。系统没有检查到问题时，统一写“当前覆盖范围内未检出”，不能写“确定无冲突”。
