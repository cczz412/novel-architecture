### ① 真值与账本（02、03 页，本轮最重）

- **两层状态轴分开**（ADD-030）：「消化」只在规划层销账；「实际发生」只能由六态对账边或作者签字推进——修掉设计稿把「作者选中计划」写成「已兑现」的走样，机制（选定即消化）本身是 CZ 亲拍、不动。
- **对账边升一等公民**：PE↔F 对账结果落成实体边＋派生结论带支持集（`support_set`）——「改一条事实自动撤回下游」从口号变机制。
- 伏笔／灵感补「实际兑现」第二轴；槽位移交支持 partial（一槽拆两章写）；`truth_bearing` 不做万能枚举。
- **存储工程硬化九件**（ADD-032）：跨文件原子性护栏（`operation_id`＋commit manifest＋恢复扫描）；**CZ 亲拍（ADD-036）**：JSON＋护栏可以先跑，**终点仍是 PostgreSQL**，SQLite 不是终点。版本链存真内容、读一致性（`story_commit_seq`）、改史反向索引、内部 ID 与显示编号分离、人物状态多值 key＋故事时间轴、锚迁移邻域指纹、故障半径分层降级。
- **暗稿与收工补齐**（ADD-031）：高影响事件（死亡／秘密揭示／物品转手）强制单签不随批量默认；检测器加 unknown 档；无正文收工只涨规划进度不涨已写章数。普通放弃／关闭、选择“不存”、主动永久删除是三个不同动作；临时恢复区的期限待正式数据政策冻结，任何具体天数都不是当前用户承诺。**低影响默认、高影响单签已由 CZ 亲拍确认**（ADD-036／A6），不重开。
- **读者知情机器账（ADD-037／A1，关题 15）**：硬账进真值——至少已知道／不知道／被误导（记下误解成什么），带原文锚；「读者大概猜到多少」做可重算旁账，不进真值。多态是为了接住针对读者反应的网文写法。字段级词表仍留 T3。

### ② 抽取与打包（04、03 页）

- **抽取管线四件**（ADD-021）：验真「诊断—修复」拆两步（三分类允许弃权）；源文反向覆盖账本（每个候选锚点必须 `covered_by_fact_id` 或 `excluded_reason`，漏抽从不可观测变可审计）＋分事实族补漏；原子粒度升级为 `fact_core＋qualifiers` 两层结构；跨家族纪律论证从「原理保证」降为「待验工程假设」（双 API 纪律本身保留）。
- **打包器口径补丁**（ADD-022）：「瘦」＝最小充分＋可扩张，不是越小越好。在模型上下文、成本和权限允许时，整卷／整书宽窗口可作为大书导入重建、全书体检、低置信兜底三类场景的候选路由。部分外部基准只提供“宽窗口可能有益”的先验，不证明本产品当前已经具备整书宽读能力，也不证明当前产品效果。预算回执增加“覆盖不足提示”是设计候选。

### ③ 插件系统与内容（02、03 页）

- **插件硬化五件**（ADD-023）：插件运行来源四段回执＝用户声明、系统加载回执、模型自报、作者采纳。它只记录一次运行中谁参与了什么，不判断著作权，不判断作者身份，也不代替内容归属。社群插件的作者署名另按 ADD-036 的“原作者＋历次微改者”署名链登记。项目版本锁、机器路由字段、能力声明、注入防线、公开流程和评测集都属于设计要求／公开前门，不是现有产品能力。
- **内容工单口径**（ADD-024）：V0 首发内置面仍是 1 套件、8 个组件、前三层。20～32 个是后续内容生产的候选批次，不是首发承诺，也不是当前已经具备的能力。内容工单已形成候选；真实交付状态以当前设计稿和本地回执为准。

### ④ 画布、前端与视觉（02 页）

- **技术选型**（ADD-025）：当前阶段存储＝JSON＋护栏；产品化终点＝托管 PostgreSQL；迁移时点尚未冻结。React Flow、TanStack Query、Zustand、CodeMirror 6 是当前设计基线，不是已经实现的能力。100～300 张完整卡同屏流畅是待测验收目标，不是实测结果。各依赖的许可、支持和生产使用条件分别登记，不用一个 MIT 标签包办。
- **SVG 视觉系统**（ADD-026）：确定性 SVG 是 V0 在当前成本、可复现和身份锚约束下的首选可控路径，不是唯一可能路径。生成模型的 seed 或参考图不能保证精确复现，只能说明目前不能承诺稳定一致，不能推出 SVG 是唯一技术方案。视觉版本字段、素材台账和降级规则都是设计要求；素材按具体来源、用途和许可逐项核对。
- **目的挂卡＋反向画布（ADD-037／A9）**：要达成的效果挂到卡上（附着或单独开卡），人加注解影响选项，不改底层；冲突爆给作者。画布可正向铺，也可倒着拆前置卡。不是出题屏打字入口。

### ⑤ 体验、角色与人物（03 页）

- **体验与可观测性五件**（ADD-027）：覆盖回执、确认负担和双路线修复属于设计／验收目标。“可见覆盖有助于建立信任”是待验证的产品假设，不是已验证因果。“失败不收费、废稿不占预算”只是待计费合同定义适用范围的体验原则，不代表当前已有退款、免扣费或预算返还机制。
- **防降智判据**（ADD-028）：五判据只作为评估先验；12 项检查、纯函数和三段式都属于施工候选，不冻结题 16 的字段名称、枚举、组合优先级、缺失值处理或机器触发方案。
- **人物账心理标签降级**（ADD-033）：心理标签只可作软先验和编辑索引，不能独立充当行为约束。长程行为判断依赖事实、当前目标、关系、情境签名和历史选择；单一标签永不独立触发硬告警。七层字段、检查器四档和 R02 落点都是人物账设计候选，不是当前已有能力。

### ⑥ 合规与市场（08、01 页＋政策页）

- **平台合规入册**（ADD-034）：晋江当前官方规则将 AI 生成细纲列为不允许范围；规则具有平台和时间边界。其他平台必须逐平台核对官方现行规则，未知就明确写未知，不能套用晋江结论。创作证明包是作者自愿开启的过程材料候选，可供申诉时提交，不保证平台采信或申诉成功；发布平台选择器和分平台提示是设计候选，不是当前能力或法律意见。产品红线仍是不做“降 AI 率”或“保证过检”。**不做晋江阉割档是 CZ 亲拍**（ADD-036／A8），不重开。
