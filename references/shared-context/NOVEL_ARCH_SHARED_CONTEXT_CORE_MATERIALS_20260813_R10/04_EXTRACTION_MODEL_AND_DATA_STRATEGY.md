## Production Canonical 的门
“Production Canonical”是可供正式训练和同源评测的唯一生产教材候选。生成它前，至少要同时满足：
1. 每个纳入来源的训练权能回到证据或明确裁定；
2. 作品、作者、来源身份清楚；
3. 每条证据的位置和 SHA 可回验，歧义不能由程序猜；
4. 普通分布与特殊分布都达到预先规定的覆盖；
5. 作者级、书级、来源级 TRAIN／DEV／blind 不交叉；
6. 五本真实候选的 DEV／blind 角色和污染边界已拍；
7. 正式 evaluator、人工复核规则和阈值与同一数据版本冻结；
8. 两次独立构建逐字节一致。
现在有计划、有部分资格修复，但没有 Production Canonical 数据集本体。

## R10 增补｜抽取管线四件护栏（ADD-021，CZ 于 2026-08-13 原文接受）

第三轮外调对六段管线的建议，经 CZ 本次转正确认后收为四件护栏。四件都落 EXTRACTION_PIPELINE_DESIGN R02，不改本页研究侧任何数据资格、训练门或模型顺位：

1. **验真「诊断—修复」拆两步**：跨家族验真只出三分类诊断（支持／不支持／不确定，允许弃权），修复另起一步——对齐已实锤的「修正建议一半误改→只挂建议待人审」教训，把"发现错"和"怎么改"的权责分开。
2. **源文反向覆盖账本**：每个候选锚点（对白／数字／专名／设定块）必须有 `covered_by_fact_id` 或 `excluded_reason` 之一——漏抽从"不可观测"变"可审计"；配套**分事实族补漏**（设定族／人物族／情节族分开扫），正对"设定密集块整段漏抽"两次复现的老痛点。
3. **原子粒度两层结构**：事实句升级为 `fact_core＋qualifiers`（核心断言＋限定词分层）——解决"原子句太碎丢语境、巨条太粗难判重"的两头翘。
4. **跨家族纪律论证降级**：「不同家族模型思路不同所以能互相拦错」从"原理保证"降为**待验工程假设**（外部指出家族间同错并非不可能）；双 API 纪律本身保留不动，加的是"别把它当万能保险"的清醒度。
