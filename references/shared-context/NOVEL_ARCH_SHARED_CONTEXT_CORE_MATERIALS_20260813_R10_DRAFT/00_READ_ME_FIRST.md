### ① 真值与账本（02、03 页，本轮最重）

- **两层状态轴分开**（ADD-030）：「消化」只在规划层销账；「实际发生」只能由六态对账边或作者签字推进——修掉设计稿把「作者选中计划」写成「已兑现」的走样，机制（选定即消化）本身是 CZ 亲拍、不动。
- **对账边升一等公民**：PE↔F 对账结果落成实体边＋派生结论带支持集（`support_set`）——「改一条事实自动撤回下游」从口号变机制。
- 伏笔／灵感补「实际兑现」第二轴；槽位移交支持 partial（一槽拆两章写）；`truth_bearing` 不做万能枚举。
- **存储工程硬化九件**（ADD-032）：跨文件原子性护栏（`operation_id`＋commit manifest＋恢复扫描）；**CZ 亲拍（ADD-036）**：JSON＋护栏可以先跑，**终点仍是 PostgreSQL**，SQLite 不是终点。版本链存真内容、读一致性（`story_commit_seq`）、改史反向索引、内部 ID 与显示编号分离、人物状态多值 key＋故事时间轴、锚迁移邻域指纹、故障半径分层降级。
- **暗稿与收工补齐**（ADD-031）：高影响事件（死亡／秘密揭示／物品转手）强制单签不随批量默认；检测器加 unknown 档；无正文收工只涨规划进度不涨已写章数；「不留正文」加 7–30 天废纸篓误删保护；**折中默认值已由 CZ 亲拍确认**（ADD-036／A6）。
- **读者知情机器账（ADD-037／A1，关题 15）**：硬账进真值——至少已知道／不知道／被误导（记下误解成什么），带原文锚；「读者大概猜到多少」做可重算旁账，不进真值。多态是为了接住针对读者反应的网文写法。字段级词表仍留 T3。

### ② 抽取与打包（04、03 页）

- **抽取管线四件**（ADD-021）：验真「诊断—修复」拆两步（三分类允许弃权）；源文反向覆盖账本（每个候选锚点必须 `covered_by_fact_id` 或 `excluded_reason`，漏抽从不可观测变可审计）＋分事实族补漏；原子粒度升级为 `fact_core＋qualifiers` 两层结构；跨家族纪律论证从「原理保证」降为「待验工程假设」（双 API 纪律本身保留）。
- **打包器口径补丁**（ADD-022）：「瘦」＝最小充分＋可扩张，不是越小越好；「整卷／整书宽窗口」明文列为三类场景的合法路由；预算回执加「覆盖不足提示」行。

### ③ 插件系统与内容（02、03 页）

- **插件硬化五件**（ADD-023）：项目级 `plugin.lock` 版本锁定；「程序署名」拆四段（用户声明／系统加载回执／模型自报／作者采纳）；索引行人机分离（机器路由另建 `when/when_not` 字段、允许 0 命中）；能力声明与注入防线；自拆 Skill 公开流程五道门。
- **内容工单开工包**（ADD-024）：以方法论地图为底本开工（首批四类各 5–8 个＝20–32 个组件）；插件卡 12 字段 schema；版权三色纪律；节奏包参数＝可调默认值＋来源等级（D 级口诀不得显示为规律）；reader_need 词表合并。

### ④ 画布、前端与视觉（02 页）

- **技术选型**（ADD-025）：React Flow（MIT）＋TanStack Query＋Zustand＋托管 Postgres；tldraw 避坑（SDK 4.0 起商用须买许可）；画布＝领域数据的可重建投影；性能验收「100–300 张完整卡同屏流畅」；SVG 缓存施工细则（编号＋revision hash、真源必须在服务端、按租户隔离）；写作区编辑器直接 CodeMirror 6 起步。
- **SVG 视觉系统**（ADD-026）：`visual_version` 字段（身份锚点跨章锁定）；素材台账 `asset_manifest`（免费下载≠允许嵌入 SaaS）；无法表达的画面降级为剪影＋道具＋字幕。「确定性 SVG 是角色一致性唯一确定解」获厂商官方佐证。
- **目的挂卡＋反向画布（ADD-037／A9）**：要达成的效果挂到卡上（附着或单独开卡），人加注解影响选项，不改底层；冲突爆给作者。画布可正向铺，也可倒着拆前置卡。不是出题屏打字入口。
