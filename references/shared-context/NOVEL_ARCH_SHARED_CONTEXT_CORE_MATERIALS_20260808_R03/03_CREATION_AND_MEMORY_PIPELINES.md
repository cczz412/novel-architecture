# 创作与记忆管线

状态：**项目级共同背景指导；主流程沿用已拍方向，具体 Schema、模型和调用次数不在本页冻结**

## 管线总原则

系统不把“抽取”“记忆”“大纲”“生成”揉成一次模型调用。每一步都留下能检查的工件：来源、查询结果、计划、执行包、场景稿、对账结果和长期入账彼此分开。

## 已有作品怎样接入

```text
1. 冻结正文，登记版本、来源坐标和 SHA
2. 建立可检索入口，但不要求首次穷尽全书
3. 作者提出当前真正要解决的问题
4. 系统按问题回冻结正文取证
5. 程序回填逐字证据和位置
6. 独立评分或人工判断回答是否完整、限定是否正确
7. 持续影响后文的变化进入永久事实提名
8. 作者或正式闸确认
9. 更新状态、知情、因果、义务和规则
10. 投影出可编辑的反向剧情地图／成文剧情图
```

回答不了时要返回“材料不足”和回取轨迹，不能补故事。旧作品接入的目标是尽快让作者继续工作，不是先做一场全书考古工程。

## 从大纲继续写怎样跑

```text
选择当前故事线
→ 读取本线上一次接力点和上一章出口
→ 编辑本章目标、计划事件和场景安排
→ 处理本章主管线大卡与必要小卡
→ 检查硬性承接、义务、结尾钩子、字数目标和 QC
→ 关闭大纲
→ 按场景编译执行包
→ 逐场生成、逐场交付、逐场落盘
→ 每场做计划—成文对账
→ 作者确认差异
→ 将确认文本冻结为带版本、来源编号、位置和 SHA 的正文证据
→ 章末汇总真正写成的事实和状态变化
→ 更新长期账并重建需要的投影
```

大纲阶段可以只编辑大纲，不生成正式稿。场景稿的重做半径默认限制在受影响场，不把整章和无关下游一起推倒。

这里的“逐场落盘”不等于场景稿自动成为真值。未确认稿仍是可重建投影；确认稿要先形成不可静默覆盖的正文版本，事实才能引用它。具体按场冻结、按章冻结，或两级都保留，仍要由施工合同锁定。

## 场景执行包装什么

每个场景执行包默认只带当前任务需要的内容：

- 全章大纲与本场目标；
- 上一场结尾原文和当前接线原因；
- 当前故事线及相关入口状态；
- 本场涉及人物的状态与知情；
- 到期义务、生效规则、接近触发事项；
- 必要的直接原因和未决事项；
- 从冻结正文按需回取的少量证据；
- 用户确认片段形成的风格锚；
- 版本、来源和过期状态。

它不默认塞进上一章全部事实，更不默认塞入整本书全文。

## 记忆怎样加载

当前已拍方向是“事实句伸缩压缩”：

- 当前完整；
- 近期展开；
- 远期压成带覆盖编号和过期状态的一句话；
- 关键因果保留头尾；
- 不可逆变化长期保留；
- 切换故事线时优先接回同一故事线上次出现的材料。

原文始终留在冻结正文。压缩只是准备材料，不能顶替证据。当前不把“向量检索正文分片”写成产品核心路线。

## 事实抽取在管线里的位置

事实抽取只负责给查询、状态更新和长期记忆供料。它不独占产品主流程，也不追求首次把一章所有细节都抽尽。

本地已经建立“模型选目标区事实和证据编号、程序做合法性与逐字回填”的候选机制。更宽阅读材料和更窄责任区的组合很有研究价值，但具名的 `Wide Read / Narrow Write` 仍是研究假设，不是现役合同。

## 计划—成文对账

生成后至少要分开六种结果：

- 按计划写成；
- 变体写成；
- 漏写；
- 与计划冲突；
- 新增未计划内容；
- 延后处理。

只有作者确认的结果才更新真值。改台词和文风不自动改事实；改未来计划不冒充已发生；改事件结果要提名受影响项；改证据要重判承托，不重做无关投影。

## QC 和风险怎样出现

- 硬事实冲突亮红灯；
- 节奏、手法、情绪和模板偏离亮黄灯；
- 卡片位点所见即所得地报警；
- 作者可以喊停、降灯或豁免软问题；
- 硬来源不能批量豁免；
- 风险和待确认项集中进裁决队列，不塞满每一段正文。

## 当前不能写成已定的部分

- 背景卡是默认、可选增强还是关闭；
- 整章宽阅读加局部窄责任是否优于局部上下文；
- 责任区最合适的粒度和跨边界事实归属；
- 真实章节／块元数据是否改善抽取；
- 查询回答升格的作者确认成本；
- 正式生产模型的调用编排和费用。
