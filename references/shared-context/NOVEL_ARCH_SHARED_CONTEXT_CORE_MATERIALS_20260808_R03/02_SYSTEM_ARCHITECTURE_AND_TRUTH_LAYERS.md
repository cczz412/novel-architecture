# 系统架构与真值分层

状态：**项目级共同背景指导；长期分层已有共识，字段和部分关系结构仍待正式冻结**

## 总结构

```text
故事项目／产品系统
├─ 证据与历史
│  ├─ 冻结正文（最终证据；带来源目录、原文坐标、版本和 SHA）
│  ├─ 事实底账（已发生、已确认、值得长期登记）
│  ├─ 状态与知情账（当前可消费状态）
│  └─ 长线账（故事线、因果、义务、规则、触发条件）
├─ 规划与创作
│  ├─ 计划事件（尚未发生）
│  ├─ 章节大纲（作者可编辑计划）
│  ├─ 场景执行包（程序编译的本次输入）
│  └─ 场景／情绪／风格旁挂（供创作，不冒充事实）
├─ 按需读取
│  ├─ 事实句压缩视图（从底账重建的读取材料）
│  └─ 查询结果（临时回答，默认不永久入账）
└─ 正文、分镜、互动和导出资产（可重建投影）
```

## 每层装什么、谁能改

| 层 | 装什么 | 真值地位 | 主要修改方式 |
|---|---|---|---|
| 冻结正文 | 原文、来源编号、位置、版本、SHA | 最终证据 | 新版本另存，不能静默覆盖 |
| 事实底账 | 已发生且确认、后续不能安全遗忘的关键变化 | 对已登记事项有权威，不宣称穷尽全文 | 改判、证伪或作者改史都留历史 |
| 状态／知情 | 人物、地点、资源、关系，以及谁知道、误信或尚不知道什么 | 当前可消费状态 | 由事实和作者确认的改动更新 |
| 长线账 | 故事线、因果、义务、规则、触发条件、锁定 | 长程一致性约束 | 引用事实编号，不复制第二份真值 |
| 查询结果 | 当前问题的回答、证据和回取轨迹 | 临时工作结果 | 默认不写底账，必要时提名 |
| 计划事件 | 脑洞、未来行动、候选转向 | 不是事实 | 作者可编辑；未写成不发事实编号 |
| 章节大纲 | 本章装配清单、场景和呈现安排 | 计划视图 | 作者和规划器编辑 |
| 场景执行包 | 当前场景所需的最小上下文 | 可重建缓存 | 程序按版本编译 |
| 旁挂资料 | 场景、情绪、风格、视觉线索 | 创作供料 | 有来源锚，不进事实质量门 |
| 事实句压缩视图 | 远近不同粒度的事实读取材料、覆盖编号和过期状态 | 非真值；可从底账重建 | 程序按任务和故事线重新编译 |
| 投影 | 未确认场景稿、工作正文、卡片、分镜、互动存档 | 非真值 | 出问题时回到计划或事实层修改 |

## 四条不能混的边界

### 已发生事实和未来计划

未来事件只能发计划编号。角色已经说过“我明天去码头”，可以登记“角色作出承诺”这件已发生事实；“明天真的去了码头”仍要等正文写成并确认。

### 事实和 AI 推断

AI 可以提出解释、叙事作用或关系猜测，但必须显式标为推断。作者声明和正文确认的世界规则可以做硬约束，AI 推断不能直接亮红灯。

### 查询回答和永久事实

查询回答只服务当前问题。它只有在持续影响后文、证据承托通过、与现有底账不冲突、类型和作用范围明确时，才可提名为永久记录。

### 事实底账和压缩事实句

事实句伸缩压缩是读取视图，不是第二套事实库。压缩句必须带覆盖的事实编号和过期状态；底账变化后可以重建。它能帮程序准备上下文，不能替代底账、冻结正文或原始证据。

### 作者确认背景和正文证据

背景卡能帮助识别主角、别名、类型和已确认设定，不能替正文补证据。只读前态也不能被抄进本次新事实。

## 工作正文怎样变成冻结正文

生成出来但尚未确认的场景稿仍是投影，不能给新事实签证。作者确认后，系统要把对应文本写成一个不能静默覆盖的新版本，至少登记章节／场景身份、版本、来源编号、SHA 和可回取位置。后续修改另发版本，旧版保留。

只有完成这一步，计划—成文对账确认的内容才能引用该版本，进入事实、状态和长线账。按场确认还是按章统一冻结仍待施工合同细化，但“先有可回验正文版本，再写真值”不能倒置。

## 故事序与叙述序

- **故事序**：故事世界里真正发生的顺序，用于因果和状态审计；
- **叙述序**：读者看到的顺序，用于倒叙、悬念、误导和信息释放。

两种顺序引用同一批事实或计划编号，不能让一个数组位置同时承担两种意思。

## 章、场景和卡片

- **章**：关闭大纲、完成总对账和长期入账的边界；
- **场景**：生成、交付和局部重做的工作单位，不是真值容器；
- **卡片**：问题处理单位。大卡承载本章主管线问题，小卡处理遗留逻辑。

一场可以承载多张卡；场景变化时可以拆成前后两场。场内临时待办用完即弃，不固化为新的长期容器。

## 大纲的最小内容

当前稳定结构包括：章节身份、本章目标、入口状态、计划事件、故事序与叙述序、长线约束、场景安排、出口条件、风险和材料不足。

作者前台默认只展示目标、必须／不能、场景和待决定，其余内容渐进展开。后台可以保留更完整合同，但不能让字段数量反过来绑住作者。

## 状态、知情和长线

长期记忆至少要能表达：

- 人物、地点、资源、能力、身份的当前值与变化；
- 角色知道、怀疑、相信、误信或不知道什么；
- 关键状态变化的直接原因；
- 故事线、义务、规则和接近触发的事项；
- 别名、同名疑似、离屏但受影响的对象；
- 已发表、作者锁定、因果强锁和可回滚历史；
- 修改后直接受影响的对象及作者豁免。

当前已拍补充：关系默认先用轻量关系状态和关系变化事件；重要、不对称、需要独立历史的关系才升成长期对象。Hook 和故事内义务分开管理。
