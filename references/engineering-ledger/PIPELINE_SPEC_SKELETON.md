# 抽取管线规格骨架（v0.1，核对版）

这页回答“一章书稿进来，到变成可供长期记忆使用的剧情原子账，中间可能经过哪几站”。它是已有实验路线和产品方向的导航图，不是已经部署的现役管线。打【待填】的格子不许现在编，必须等点名的正式票收口。

## 主流程候选：书稿 → 剧情原子账

```text
① 书稿分块 → ② 主抽取 → ③ 验真 → ④ 补漏 → ⑤ 程序合并 → ⑥ 作者确认 → ⑦ 入账
        （③④⑤ 是否保留，由 P0／P1／P2 对照决定）
```

### ① 书稿分块

- 输入：一章冻结版本的书稿。
- 已验证的两个局部口径不能混成一条永久规则：
  - 本地 4B DEV 顺序实验保留的完整目标责任段实测为 620–923 个 Unicode 字符；每侧最多 H180 是只读上下文。
  - DISCRIM4 判别材料使用去空白 Unicode 字符硬范围 450–1000、推荐 600–800、动态目标 760；语义门先保同一事件或连续动作／因果链完整，短拟声词和承接动作不单独切断。
- halo 只帮助理解；目标区外内容不能单独支撑正分 Gold（E-07）。
- 输出：【待填：新的正式管线对照票】。至少要带责任区文本、位置锚点、书稿版本和可复核身份，但精确字段尚未冻结。旧 T03 曾暴露材料身份、导入损失和证据承载问题，只算候选先验（E-14）。
- 状态：**局部实验口径已验证；产品通用切块合同未定。**

### ② 主抽取

- 输入：单个责任块＋允许的只读上下文＋冻结 Prompt。
- 输出候选：该块的原子化剧情信息，一句尽量只承载一个命题；实验家族旧词“事实句”按 R06 映射为已发生态剧情原子。
- 颗粒度有两个不同身份的锚点：
  - “整章约 100–150 个剧情原子”与“不能安全遗忘的必抽子集约 30 条”是 CZ 的设计口径，当前仓内没有找到可把这两个数升级成实测定值的正式票。
  - 当前 DISCRIM4 Gold 的实测是**三章主分合计 30 条，其中 REQUIRED 23 条**，不是“每章 30 条”。它只是一份强淘汰卷，不能反推真实项目整章密度。
- 全量原子与长期必抽子集怎样分界：【待填：新的正式语义合同票承接旧 T-08 的 N16 问题＋首个真实项目校准】。
- 用哪个模型、用哪版 Prompt：【待填：合法候选提案 → 新的 A/B/C 与管线对照票】。旧 T03 的岗位小样不能替代新对照（E-14）。
- 状态：结构和模型都未形成产品定版。

### ③ 验真（是否保留待定）

- 候选设想：独立于主抽的模型逐条核对“这条在责任区或允许证据里站不站得住”，不借验真阶段开放式补新事实。
- 【待填：验真输入、允许证据、输出枚举、失败处理、模型与 Prompt，由新的 P1/P2 预注册票冻结】。旧 T03 只证明过隔离配置可拆分，没有冻结产品合同（E-14）。
- 外调 ZIP 的回包即使回来，也只能当候选依据，不能直接填成本页正式合同。

### ④ 补漏（是否保留待定）

- 候选设想：偏高召回的模型在不看主抽结果的情况下独立再抽一遍，专门寻找主抽漏项；主抽和补漏可以用不同模型。
- 【待填：是否盲抽、输入范围、怎样防重复与污染、何时停止，由新的 P2 预注册和结果票决定】。

### ⑤ 程序合并

- 候选设想：对主抽与补漏结果做机械去重、身份绑定和冲突标记；不让模型直接覆盖另一条结果。
- 【待填：等价判定、冲突表示、保留策略和失败方式，随新的 P2 预注册冻结】。

### ⑥ 作者确认

- 已批方向：作者确认差异，不填 Wiki；日常项可批量确认，重签清单单独勾选。入账必须由书稿证据承托，或由作者明确签字。
- 首版验收链方向：真实项目提问 → 系统回到原文取证 → 作者确认 → 状态安全更新 → 下次能继续使用。
- 界面颗粒度、撤销与改判流程：【待填：首版产品试验和对应语义合同】。

### ⑦ 入账

- 表结构：【待填：新的正式语义合同票把旧 N15／N16／N17 问题转成可验收合同后再建表】。
- 当前只保留方向，不抢先发明字段：表述事件不能直接等同世界命题；判断来源、作者签字、时间和 unknown 分类要分开；章版本负责不可变书稿身份，章内位置负责回原文取证。
- 任何具体机器字段都要由正式 schema 或合同给出，本页不代填。

## 消费侧：账建好后准备服务谁

| 消费场景 | 当前方向 | 身份 |
|---|---|---|
| 续写辅助 | 围绕当前问题取证，把相关设定和原文证据带入上下文，再给提案 | R06 方向已批，无施工票 |
| 一致性检查 | 用告警与覆盖回执防止硬冲突被静默吞掉 | N20 语义方向已拍，字段和实现待定 |

| 视频投影 | 场景连续性包＋镜头／资产绑定包；向下游提供约束，不保证下游服从 | N07-B 方向已批，投影合同待定 |
| 外部 agent（MCP／CLI） | 只能提交修改提案，不直接改账；作者 Canon 默认拒读 | N05-A/B 方向已批，接入方案待定 |

## 全链质量与成本护栏

- 当前候选质量门：DISCRIM17 先按 A 产品线筛，A 不足 3 组才启用 B 筛选线；仅过 B 线不能成为最终产品通过者（E-11）。
- 每一站都要把逻辑任务与真实请求分开记；运输失败不能从端到端结果里消失；费用未对账不得写成 0（E-05）。
- 主抽、验真、补漏是否用不同强度模型只是待验证路线，不是“弱模型一定更便宜且够用”的结论。具体岗位、单价、Token、时延和是否值得多一步：【待填：新的正式候选与管线结果票】。旧 T03 记录只负责提醒哪些问题不要重踩（E-14）。
- 目标候选席位为 3–5 个，不等于最终管线一定同时调用 3–5 个模型；实际调用数由管线对照的质量、成本和时延共同决定。
