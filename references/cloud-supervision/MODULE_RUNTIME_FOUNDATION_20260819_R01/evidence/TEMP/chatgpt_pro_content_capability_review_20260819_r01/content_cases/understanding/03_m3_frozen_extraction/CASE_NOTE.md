# M3｜冻结合成抽取结果穿过现行 C2→C3 入口

## 这份结果怎么来的

- 数据身份：纯合成中文材料。
- API／模型调用／重试：0／0／0。
- 现行函数：extract_tool.offline_response_provider；extract_tool.execute。
- `current_output` 是运行上述现行函数得到的，不是人工仿写。

## 作者现在看到什么

- 结构化 C3 候选：事实句、逐字 quote、责任段号和章节版本。
- 本案例没有 M3 作者渲染器，因此只有 JSON 运输结果。
- provider 是人工编写的规范化合成映射，明确不是模型原始回包。

## 请重点审什么

- 候选是否漏掉关键动作、误把推断写成事实，或把一句事实拆得太碎？
- “哥哥生前约定”这一带背景的信息粒度是否适合进入事实层？
- 没有作者可读摘要时，普通作者如何发现漏抽和过度抽取？

## 这份案例不能证明什么

- 不能证明任何真实模型的抽取质量、稳定性或调用成本。
- 不能证明候选事实正确，只证明冻结规范化输出能安全运输并继承版本。
- 不能证明空 quote、坏 JSON、截断或实时 parser 风险已经解决。
