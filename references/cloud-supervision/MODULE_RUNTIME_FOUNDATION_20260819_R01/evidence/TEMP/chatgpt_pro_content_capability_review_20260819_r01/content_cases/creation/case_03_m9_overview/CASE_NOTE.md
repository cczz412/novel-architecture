# 案例 03｜M9 单章概览卡

这个合成快照故意同时放入 confirmed、extracted 和 rejected 三层事实。冻结 fixture 又故意把已驳回的“店主是寄件人”写进了梗概。现行 `overview.execute` 实际接受了这份输出，人读卡也展示了三种状态。

## 请 Pro 审的内容问题

- 作者概览的梗概主文是否应强制只使用 confirmed，还是可以把 extracted 作为显式候选附注。
- rejected 是否应完全不能进梗概，即使它仍然作为可追溯证据行存在。
- “顾川说”只是人物声称，概览是否把它过度改写成客观来历。
- 状态层级在人读文本里够不够醒目，能不能防止作者把候选当真值。

## 不能证明什么

这个恶意梗概是人工冻结 fixture，不能证明真实 provider 一定会犯同样的错。它只证明当前机械门会接受这种内容。API／模型／重试均为 0。
