# 案例 06｜M11 遇到作者未决事项时停下

这个合成案例把“沈遥到底改不改赴约决定”标成当前任务必须知道、但作者尚未决定的 HARD 未决项。现行工具实际返回 `STOP_UNRESOLVED`，并且没有装入半份上下文。

## 请 Pro 审的内容问题

- 这是否真的是必须询问作者的硬未决项，还是系统可以给出多个方案后继续。
- 停机文本有没有对作者说清“要决定什么”，还是只显示了内部 ID。
- 如果同时有多个未决项，应该一次全问，还是先问最影响当前章的一个。
- 未决项如何与“系统可以自己推断的低风险细节”区分。

## 不能证明什么

这个案例只证明调用方已经把事项标成 UNRESOLVED 之后，M11 会安全停下。它不证明系统能自己正确识别哪些事必须问作者。API／模型／重试均为 0。
