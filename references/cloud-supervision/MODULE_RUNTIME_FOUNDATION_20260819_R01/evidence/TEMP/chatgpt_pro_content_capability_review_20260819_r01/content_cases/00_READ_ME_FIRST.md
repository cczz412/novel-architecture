# 合成内容案例入口

这批材料专门补上一轮架构审查没有覆盖的“作者实际看到什么”。共有 13 组安全合成案例：

- `understanding/`：M1～M7，共 7 组；
- `creation/`：作者工作稿／T14 与 M8～M11，共 6 组。

每组通常包含：

- `input.json` 或合成输入文本；
- `current_output.json`：现行函数实际产生的机器结果；
- `current_output.md`：现行作者可读结果；
- `CASE_NOTE.md`：这例该审什么、不能证明什么。

M3、M4 当前没有对应作者渲染器，所以只提供结构化运输结果。冻结 provider 出现时，案例说明会明确标出；它只证明系统如何校验和展示给定结果，不能证明模型会自己做出正确判断。

## 身份与权限

- 所有故事、人物、句子、事实、规划和 provider fixture 都是本次专用合成内容。
- 真实小说、真实作者项目、Gold、盲审答案、raw response、reasoning：0。
- API／模型／重试：0／0／0。
- 用途：审当前合成内容体验，设计以后真实内容评测。
- 禁止宣称：真实小说泛化、抽取质量、规划质量、文学判断或产品上线能力已经通过。

先读本页，再读两个子目录的 `README.md`／`INDEX.md` 和各案例的 `CASE_NOTE.md`。
