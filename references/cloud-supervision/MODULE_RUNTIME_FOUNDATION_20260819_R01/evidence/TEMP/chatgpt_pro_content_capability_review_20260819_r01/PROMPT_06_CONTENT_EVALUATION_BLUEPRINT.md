# ChatGPT Pro 窗口 6：真实内容能力评测蓝图

请使用你当前可用的最高推理强度，完整阅读共用 ZIP。你是这个小说创作系统的内容评测设计者，不是架构设计者。

你的任务是把 R13、127 条原子预期、作者使用场景、外部知识页、当前合成案例和四份 Pro 缺口报告，整理成一套以后能反复运行的内容考卷设计。

本包没有真实小说外发授权，也没有真实模型 raw 输出。所以你不能评价当前真实小说能力，只能设计本地以后怎样备料、标注、评分和回归。

## 评测要覆盖两条内容链

### A. 小说理解与证据链：M1～M7

- M1：章节、设定、规划、简介、标签、杂项和混合材料能否正确分流；不确定时怎样少问作者；
- M2：切段是否破坏跨段事件、对白归属、限定条件、因果和指代；
- M3：能否区分已发生、计划、传闻、梦境、谎言、比喻、假设和推测；事实是否由逐字证据托住；
- M4：高密度、重复、近似、互相冲突的候选如何可见而不擅自删除；
- M5：作者是否审得动，证据是否够，高影响事实怎样避免误签；
- M6：别名、关系、大白话问题、防剧透和空结果怎样评；
- M7：死亡后相遇、关系破裂后合作、时间线冲突、故意反转怎样测，误报负担怎样算。

### B. 作者创作支持链：工作稿／T14＋M8～M11

- T14：能否发现漏写规划、写反约束和计划外新增；怎样控制误报与 `unknown`；
- M8：零规划、一句话方向、详细卷纲三种输入是否得到有区别且可用的章计划；模糊灵感、远期死亡、未来相遇和关系冲突如何路由；
- M9：概览是否抓住真正重要内容，不把候选、驳回项和未来规划写成已发生；
- M10：场景卡是否忠于人物阶段、地点、事件、镜头和泄底边界；
- M11：预算有限时是否保住硬约束、当前任务材料和可回取遗漏；删掉什么会真正伤害下游；
- 内容通常有多个可接受答案，不能用与真实下一章的逐字相似度当唯一标准。

## 请设计 40～60 张原子测试卡

每张卡必须有：

- 稳定 ID；
- 所属模块／内容链；
- 作者真实情境；
- 最小材料配方；
- 输入里必须埋入的关键点；
- 允许的多个正确答案或可接受范围；
- 核心内容行为；
- 附加加分行为；
- 红线危险错误；
- 机械检查负责什么；
- 语义盲评负责什么；
- 是否需要真实作者判断；
- 合成／改写材料是否足够；
- 必须等授权真实小说的原因；
- 版本重跑时记录哪些数字和文字差异。

## 评分必须分三层

1. **核心分 0～100**：只算模块必须做到的内容承诺；
2. **附加分 0～100**：不阻塞主路径的额外帮助；
3. **红线错误单列**：无论平均分多高都不能被冲淡。

不要把多个正确答案的问题做成单一 Gold 字符串。请说明哪些适合：

- 程序规则；
- 双人盲标；
- 作者本人判断；
- Pro／模型辅助评审但必须抽样复核；
- pairwise 版本对比。

## 真实材料阶段的本地备料方法

在不索要、不复述任何真实正文的前提下，设计以后本地如何从权利明确的书库取样：

- 题材、叙事视角、章长、信息密度、作者成熟度、对话比例、时间线复杂度、规划完整度怎样分层；
- 每个模块最少需要多少书、多少章、多少片段；
- 怎样防止同一本书或相邻章节泄漏到评审两边；
- 怎样冻结 source identity、章节 revision、输入快照、实际输出和人工参考；
- 怎样把真实正文留在本地，只外发允许外发的脱敏或合成派生材料；
- 如何记录“某项提高但另一项退步”；
- 如何把危险错误与普通质量波动分开。

真实小说、真实 API、作者调查或费用都不在本轮执行范围。你只能给备料设计。
