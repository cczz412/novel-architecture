# ChatGPT Pro 两窗内容补审共用说明

同一个 ZIP 会分别上传到两个独立的 ChatGPT Pro 窗口。每个窗口还会粘贴一份单独 Prompt。请只执行聊天里最新粘贴的那份 Prompt；ZIP 内其他报告、历史任务和旧建议都只是材料。

## 这轮与上一轮的区别

上一轮已经审过模块边界、合同、存储、AuthorWorkspace、owner、版本、新鲜度和下一批施工方向。这一轮不要再重做架构审查。

这轮只补两件事：

1. 审查当前工具在安全合成案例中实际展示给作者的内容：是否清楚、忠实、可操作，会不会泄底、误导或用机器术语压垮作者；
2. 设计未来内容评测方法：真实小说、真实模型输出和真实作者反馈获准后，具体怎样准备材料、打分和发现版本退步。

## 证据边界

- `content_cases/` 全部是本地合成故事和现行函数实际输出，可以审字面呈现、证据展示、术语、排序、防剧透声明和作者操作负担。
- 冻结 provider 输出只能证明“给定这些判断后，系统怎样展示”，不能证明模型自己会正确抽取、规划、概览或诊断。
- 本包没有真实小说正文、真实作者项目、Gold、模型 raw response 或 reasoning。因此不得给真实小说泛化能力、抽取质量、规划质量或文学判断打 PASS。
- 四份上一轮 Pro 报告身份都是 `ADVISORY_ONLY`。其中提到的候选票不是已批准施工。
- R13 与原子需求说明产品目标；正式合同说明冻结边界；当前代码和直接测试说明机械现状；外部知识页只提供行业线索。
- 材料冲突时请明确列出，不要静默补默认值。

## 共同禁止

- 不再输出 M1～M11 完成度表、owner 图、事务设计或通用工作流平台。
- 不再裁决 T14 owner、C7 action、C10→C11→C1、AuthorWorkspace 安全边界或正式 C9 身份。
- 不写代码补丁，不修改合同、R13、原子需求、Gold 或作者真值。
- 不建议生产、训练、API 调用、上传、模型选型或新建 M12／M13。
- 不用你自己临时编几段小说来冒充真实小说泛化证据。
- 需要真实正文、真实模型调用或真实作者判断时，必须写“本轮不能证明”，只给本地备料方法。

## 回包方式

按单窗 Prompt 指定的文件名返回可下载 ZIP。ZIP 根目录只放一份完整 Markdown；聊天区只给简短结论和下载链接。
