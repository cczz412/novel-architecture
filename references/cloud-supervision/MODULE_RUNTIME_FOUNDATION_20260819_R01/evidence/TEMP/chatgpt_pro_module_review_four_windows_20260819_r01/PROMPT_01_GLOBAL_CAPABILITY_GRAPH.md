请使用你当前可用的最高推理强度，完整阅读共用 ZIP 后再作答。

你是这个小说创作系统的高级产品架构审查员。这次不是逐文件挑错，也不是重新发明产品。你要把最新代码、合同、直接测试、原子需求和上一轮 Pro 建议放在一起，回答四件事：

1. M1～M11 当前真实能力图是什么；
2. 哪些只是独立工具能跑，哪些作者已经能用，哪些已经接入主循环；
3. 哪些是真阻断，哪些只是未来增强；
4. 下一波本地七窗口怎样并行施工，才能增加模块能力而不是增加治理。

## 已接受的高层判断

除非附件里有直接反证，不要重新花篇幅论证：

- M1～M11 暂时全部保留，不机械合并，也不机械续编 M12／M13；
- 这 11 个模块是一张能力图，不是强制串行链；
- M9 是核心读侧投影；
- M10 是可选跨媒介出口，不阻塞纯小说作者主循环；
- M11 是故事领域材料打包模块，不是通用基础设施；
- 作者工作稿与显式交棒已有正式合同和局部实现，不是从零新造一条 P-A；
- 上一轮“6 条独立管线＋8 个旁挂组件＋8 个共享服务”只是候选地图，不是 22 张施工票；
- 当前不建设统一工作流引擎或大一统平台。

你的新增价值是：用最新工作树判断上一轮哪些缺口已关闭、哪些仍真实存在，以及下一阶段怎样做。

## 必须回答

### 1. 画当前能力图

用人话说明 M1～M11、作者工作稿、AuthorWorkspace、C10／C11、T14 检测的真实关系。区分：

- 主循环；
- 事实读写支路；
- 规划支路；
- 可选导出；
- 共享存储底座；
- 仍缺 owner 的开放缝。

已有代码关系用实线，只有设计的关系用虚线，缺 owner 标 `OPEN`。不要画成从 M1 一路必跑到 M11 的单线。

### 2. 给 M1～M11 做三层判定

逐模块判断：

- 核心对象或文件工具是否能独立运行；
- 是否能通过 AuthorWorkspace 保存、重启读回并识别过期；
- 是否已有作者能看懂或能明确操作的出口；
- 是否有直接文件／对象交接；
- 是否只在合成或冻结数据上成立；
- 离“作者实际可用”最近还缺哪一个核心能力。

必须把“独立工具能跑”“作者实际能用”“跨模块主循环接得上”分开评分。不要把局部 PASS 写成模块完成，也不要因为没有 UI 就把能跑的工具写成零。

### 3. 检查作者真实旅程

至少检查这些旅程，分别写清能走到哪、最早断在哪里：

- 上传并安全保存材料；
- 当前章进入切段、候选抽取、事实保存和作者确认；
- 截至某章做防剧透查询并查看逐字证据；
- 查看体检、概览和规划卡；
- 保存工作稿、做检测、选择收工路线并显式交棒；
- 从章槽导出场景卡和可携带文本包；
- 为一个故事任务选择并打包上下文。

### 4. 重判当前公开缺口

重点核对：

- 工作稿显式交棒到 C11／C1 是否仍缺 C10 source、唯一章节号 owner、C11 runtime writer 和跨存储协调；
- T14 检测结果该内联复核还是必须进入 owner 存储；
- C7 局部 A／B／C／discard 选择能否生成正式 selection action；
- M11 的正式 C9 选材 owner、来源 revision、排序与消费者是否仍开放；
- M10 的人物锚、场景、事件补料能否从 current owner 自读；
- M3 当前是否只证明接口运输，尚未证明真实小说抽取质量。

最新代码若已关闭一部分，请引用具体代码与直接测试；没有关闭就不要用设计稿冒充完成。

### 5. 给出下一阶段排序

把候选分成：

- `SAFE_NOW`：语义唯一、单模块或窄接缝，可直接施工；
- `CALIBRATE_FIRST`：先做只读探针才知道能否施工；
- `CZ_DECISION`：存在真实产品二选一或 owner 扩张；
- `REAL_MATERIAL_LATER`：需要真实小说或作者材料验证；
- `DEFER`：现在做只会滑成平台或治理。

优先核心原子需求，不能用文件多、测试多或架构漂亮代替用户价值。

### 6. 给本地七窗口安排两波候选包

第一波给 5～7 个能真正并行的工作包；第二波给依赖解开后的候选包。不要为了凑满七窗制造任务。

每个工作包写清：

- 服务哪个模块或接缝；
- 对应哪些原子预期 ID；
- 作者交进什么；
- 工具产出什么；
- 当前已有基础；
- 这张票只补哪一个缺口；
- 建议触碰的文件族，不伪造现场精确写集；
- 一个最小正常例和失败例；
- 失败时必须保持什么不变；
- 与哪些包可并行、依赖什么；
- 完成后仍不能宣称什么。

### 7. 只留下真实 CZ 决策

只列会改变正式产品语义、owner／写域、费用、Gold、训练、生产、上传或作者真值的选择。机械答案唯一的实现细节不要推给 CZ。

### 8. 给出过度设计停损规则

最多 8 条，必须能阻止：重复复审、为了窗口常亮造票、把回执或 Notion 镜像当能力、把共享函数抬成平台、真实消费者出现前造统一编排器、用合成测试冒充真实小说能力。
