# 推荐总架构：从小说正文到逐章证据的生产线

## 1. 设计原则

目标不是让模型写一篇“看起来像总结”的文章，而是生产一套可追溯、可重放、可机械验收的事实数据库，再由程序渲染成 Markdown。

核心原则：

1. **当前章原文是唯一证据源**。
2. 前文只以精简状态账本提供，且只用于消歧。
3. 先追求高召回，再删错项；不要在第一步预测后文价值。
4. 模型负责语义判断，程序负责编码、切章、编号、排序、引用校验、去重和渲染。
5. 每一次 API 调用只承担一种可验收任务。
6. 所有中间产物落盘并带版本、哈希、模型参数和状态。
7. 失败重试只重跑有问题的章或条目，不重跑整本书。

## 2. 推荐流程总图

```text
A. 输入层
ZIP／TXT／MD
  └─ 安全解压、编码识别、Unicode 规范化、章节切分、哈希清单

B. 章节表示层
完整当前章
  └─ 按段落／句子添加 L0001、L0002…，保留原始文本映射

C. 高召回抽取层
  ├─ Extractor-A：动作、动机、计划、关系、状态、未决问题
  └─ Extractor-B：人物、身份、特征、地点、组织、物品、规则、体系、数字
       两个调用都只引用当前章行号和原文短引

D. 确定性合并层
  └─ JSON Schema → 原文短引子串校验 → 顺序定位 → 原子性初检 → 候选去重

E. 独立审校层
  ├─ Verifier：不支持、过度推断、模态错误、复合事实、重复
  └─ Gap Finder：逐段检查漏掉的可抽取事实
       只输出问题和缺口，不重写全部内容

F. 选择性修复层
  └─ 仅把问题条目＋相关原文段落送给 Repairer

G. 正式化层
  └─ 按原文位置排序，由程序生成 E-03-01 等正式 ID，渲染 Markdown

H. 跨章状态层
  └─ 用已验收证据更新人物别名、关系、地点、组织、未决线索账本

I. 全局验收层
  └─ 章节连续、ID 连续、引用存在、重复、跨章矛盾、密度异常、乱码、ZIP 标志
```

## 3. 为什么推荐双抽取器

一个 Prompt 同时追踪剧情动作、人物信息、地点、社会制度、数字、特殊体系和关系变化，容易产生注意力竞争。把第一步拆成两个互补视角，能够提高召回：

### Extractor-A：叙事变化

专门检查：

- 谁对谁做了什么；
- 动作结果；
- 决定、计划、命令、承诺；
- 动机与目标；
- 关系建立或变化；
- 状态变化；
- 公开提出但尚未回答的问题；
- 人物说法、猜测、判断。

### Extractor-B：世界与实体

专门检查：

- 人物首次出现候选、身份、年龄、外貌、职业、教育、能力；
- 地点性质与位置；
- 组织／势力；
- 特殊物品；
- 时间、数量、价格、制度；
- 规则、体系、能力机制、社会常识；
- 人物之间已有亲属／同事／师生等关系。

两个结果都必须有当前章原文短引。合并阶段不因类别不同而重复保留同一事实。

## 4. 三种运行档位

| 档位 | 每章主要调用 | 适用 | 风险 |
|---|---:|---|---|
| 高精度 | 双抽取＋独立审校＋选择性修复，通常3～4次 | 要做长期数据库、不同题材、要求“宁多勿漏” | 成本最高，但最接近人工多遍阅读 |
| 平衡 | 单次综合抽取＋独立补漏审校＋选择性修复，通常2～3次 | 大多数本地批处理 | 少量类别可能在首轮偏弱 |
| 单调用保底 | 综合抽取在同一响应中附覆盖自检，1次 | 调试、预算非常紧 | 同一模型自检相关性高，不能等同独立审校 |

高精度模式不是“把同一个 Prompt 调两次”。两个抽取器的覆盖职责不同，审校器也不能看到抽取器的内部推理，只看原文与候选结果。

## 5. 章节处理顺序

### 5.1 证据抽取阶段：顺序处理更稳

建议按第1章、第2章……顺序推进。完成第N章并验收后，更新状态账本，再处理第N+1章。

这样可以：

- 判断人物是否第一次出场；
- 解析跨章别名；
- 确认关系是新建、延续还是变化；
- 防止把未来身份倒灌到前章。

同一章的 Extractor-A 与 Extractor-B 可以并行，因为它们共享同一个 prior state。

### 5.2 不建议每章都发送所有前文

前文越长，越容易：

- 稀释当前章注意力；
- 把前文事实误当成本章事实；
- 增加费用；
- 遇到上下文截断；
- 让章节证据的来源边界不清。

只发送一个压缩、可追溯的 prior state，通常几百到两三千字即可。

### 5.3 全书整理阶段

等所有章节证据验收完毕，再把证据母集用于：

- 世界观；
- 人物档案；
- 地点；
- 人物关系；
- 每章大纲；
- 因→果→用；
- 写法分析。

这时输入应以证据数据库为主，按人物／地点／线索检索相关证据；必要时回读对应原文段落，而不是把整本正文反复塞入每个请求。

## 6. 输入预处理

### 6.1 保存两份文本

- `raw_text`：字节严格解码后的原文，只做换行统一，不删内容。
- `model_text`：去掉重复章标题、把作者 `ps` 标记为非正文、加行号；保留从 model_text 到 raw_text 的偏移映射。

不要直接在唯一副本上“清洗”，否则以后无法证明短引来自原文件。

### 6.2 按段落／句子加行号

推荐：

```text
[L0001] 第3章 梅丽莎
[L0002] 确定了计划，周明瑞顿时有了主心骨……
[L0003] 直到这个时候，他才有心情仔细审视……
```

长段落可按句号、问号、叹号和引号边界切分，但不能按固定字符数切断。若句子特别长，可保留一个段落 ID，再允许短引覆盖该段落。

### 6.3 超长章节分块

只有在“提示词＋状态账本＋章节＋预计输出”超过模型上下文的安全比例时才分块。分块规则：

- 只在段落边界切；
- 前后重叠1～2个完整段落；
- 每块带 `chunk_id` 和全章行号；
- 抽完后按原文位置合并；
- 再做一次全章补漏审校。

不要用固定23字滑窗代替分块。

## 7. 结构化中间数据

建议中间候选项使用：

```json
{
  "temp_id": "C-A-001",
  "fact": "梅丽莎拔起怀表按钮转动，使停住的秒针重新走动。",
  "category": "event_action",
  "assertion_mode": "narrator_fact",
  "entities": ["梅丽莎", "怀表"],
  "source_refs": [
    {
      "line_ids": ["L0038", "L0039"],
      "quote": "先将怀表顶端的按钮拔起，仅仅转动了几圈，便有哒哒哒的秒针走动声传出"
    }
  ]
}
```

正式 `E-03-01` 不在模型里生成。待候选去重、修复和排序后，由程序一次性编号。

## 8. 模态保护

事实错误常不是“凭空编造”，而是把原文的不确定性抹掉。必须让模型和审校器都检查：

| 原文形态 | 正确证据写法 |
|---|---|
| 叙述明确发生 | “X做了Y，结果Z。” |
| 人物说 | “X告诉／声称／回答……” |
| 人物猜测 | “X猜测／怀疑……” |
| 人物计划 | “X决定／计划……” |
| 人物未回答的问题 | “X提出……疑问，正文当章未给出答案。” |
| 传闻／报纸 | “报纸报道……”“A转述……” |
| 可能、似乎、也许 | 保留“可能／似乎／也许”，或改成“X认为可能……” |

不能把“克莱恩暂时把它算作自杀”变成“克莱恩自杀是既定事实”。

## 9. 合并与去重规则

1. 先按最早 `line_id` 和短引在行内的位置排序。
2. exact quote 完全相同且事实语义相同：合并。
3. 同一事实在多处重复：保留一条，附多个 `source_refs`。
4. 同一场景中不同动作：不合并。
5. 一句话含“身份＋动作＋结果”三个可独立事实：拆分。
6. 人物说法与客观事实即使内容相同，也不能无条件合并。
7. 只因实体相同而语义不同：不得去重。

语义相似度只能做候选提示，最终去重应由规则或审校器确认。

## 10. 失败恢复与幂等

每章建立作业键：

```text
novel_sha256 / chapter_no / prompt_version / model / mode
```

落盘：

- 输入章 SHA；
- prior state SHA；
- 请求体 SHA；
- 原始响应；
- 解析响应；
- 校验错误；
- 修复记录；
- 最终证据；
- 状态账本增量。

相同输入与版本再次运行时直接复用已通过产物。网络失败只重试请求；语义失败走修复 Prompt，不能把网络重试和内容纠错混在一起。

## 11. 为什么这套结构能适应其他题材

它不依赖《诡秘之主》的专有名词，而依赖通用事实类别和叙述模态：

- 恋爱文：关系变化、说法、内心判断；
- 悬疑文：未决问题、证词、推测、物证；
- 仙侠／系统文：规则、境界、技能、物品、代价；
- 历史文：组织、官职、地理、时间、制度；
- 科幻文：技术规则、实验结果、组织和地点；
- 群像文：实体账本和关系变化；
- 非线性叙事：只记录文本明示的故事时间，不自行重排。

通用管线稳定后，可以用 `genre_hint` 帮助审校器关注常见漏项，但 `genre_hint` 永远不能成为事实来源。
