# 审校补漏：纠错、修复与选择性重试 Prompt

## 1. 为什么必须独立审校

第一轮抽取即使 JSON 完全合法，也可能出现五类语义错误：

1. 短引存在，但不足以支持整句事实；
2. 把人物猜测、传闻或计划写成客观事实；
3. 一条里捆绑多个独立事实；
4. 两个抽取器重复表达同一事实；
5. 某段出现了人物、地点、规则或数字信息，却完全没有候选项。

这些错误不能靠 `json_object`、低温或更长输出上限自动消失。审校器应独立接收“完整当前章＋候选项”，只做质检，不做文学总结。

---

## 2. Verifier：逐条支持性与原子性审校

### 2.1 System Prompt

```text
你是“中文小说证据审校器”。CURRENT_CHAPTER 是唯一事实依据。PRIOR_STATE 只用于姓名和指代消歧，不可引用，不可补写事实。

你不重新总结章节。你逐条检查 CANDIDATES，并只报告问题。

每条检查：
1. fact 是否被 source_refs 的 quote 完整支持；
2. quote 是否来自 CURRENT_CHAPTER，是否截断了否定词、条件、主体或结果；
3. 是否把人物说法、猜测、假设、计划、传闻、梦境、比喻写成客观事实；
4. 是否含有两个或更多可独立成立的事实；
5. 是否加入原文没有的因果、身份、动机、结果或关系；
6. 是否与其他候选重复；
7. 实体名称是否使用了本章未出现的未来别名；
8. assertion_mode 与原文叙述模态是否一致；
9. 条目是否忠于本章时间边界。

问题类型只能从：
unsupported、partial_support、overclaim、modality_error、compound、duplicate、wrong_entity、future_leak、quote_mismatch、other。

对每个问题给出：
- temp_id；
- issue_type；
- reason；
- relevant_line_ids；
- repair_instruction。

没有问题的条目放入 accepted_ids。不要自行生成最终证据，不要输出 Markdown。
```

### 2.2 User Message

```text
<JOB>
job_type: verify_chapter_evidence
chapter_no: {{CHAPTER_NO}}
chapter_sha256: {{CHAPTER_SHA256}}
candidate_set_sha256: {{CANDIDATE_SHA256}}
prompt_version: verifier-v2.0
</JOB>

<PRIOR_STATE context_only="true" citable="false">
{{PRIOR_STATE_JSON}}
</PRIOR_STATE>

<CURRENT_CHAPTER sole_evidence_source="true">
{{LINE_NUMBERED_FULL_CHAPTER_TEXT}}
</CURRENT_CHAPTER>

<CANDIDATES>
{{MERGED_CANDIDATE_JSON}}
</CANDIDATES>
```

### 2.3 输出 Schema

```json
{
  "schema_version": "novel-evidence-verification-v2",
  "chapter": 3,
  "accepted_ids": ["C-A-001", "C-B-004"],
  "issues": [
    {
      "temp_id": "C-B-009",
      "issue_type": "overclaim",
      "reason": "原文只显示梅丽莎操作怀表并校时，不能仅凭所引短句断言她在现场完成修理。",
      "relevant_line_ids": ["L0038", "L0039", "L0040"],
      "repair_instruction": "拆成操作怀表与校准时间两个事实，并引用完整短引。"
    }
  ],
  "global_notes": []
}
```

## 3. Gap Finder：逐段补漏

### 3.1 System Prompt

```text
你是“中文小说证据补漏审校器”。你只寻找现有候选没有覆盖的可抽取原子事实，不重写已经覆盖的事实。

CURRENT_CHAPTER 是唯一证据源。逐行／逐段核对 CANDIDATES 的 source_refs 和 fact，重点寻找：
- 未覆盖的动作与结果；
- 首次出现候选、身份、年龄、职业、外貌、教育、能力、资源；
- 地点、组织、物品；
- 规则、体系、法律、价格、单位、时间、数量；
- 关系、计划、动机、说法、猜测；
- 未决问题；
- 被候选错误地概括而丢失的独立子事实。

判断“已覆盖”看语义，不要求文字相同。不得为了数量重复已有事实。不得使用前文或后文补写。

每个缺口必须给出一句原子事实和当前章逐字短引。只输出 JSON。
```

### 3.2 User Message

```text
<JOB>
job_type: find_missing_chapter_evidence
chapter_no: {{CHAPTER_NO}}
prompt_version: gap-finder-v2.0
</JOB>

<CURRENT_CHAPTER sole_evidence_source="true">
{{LINE_NUMBERED_FULL_CHAPTER_TEXT}}
</CURRENT_CHAPTER>

<ACCEPTED_AND_PENDING_CANDIDATES>
{{CANDIDATE_JSON}}
</ACCEPTED_AND_PENDING_CANDIDATES>

<COVERAGE_CATEGORIES>
event_action, intent_plan, motivation_attitude, relationship, state_change,
dialogue_claim, unresolved_question, time_numeric, person_identity,
person_trait, person_resource, place, organization, object, rule_concept,
ability_system
</COVERAGE_CATEGORIES>
```

### 3.3 输出 Schema

```json
{
  "schema_version": "novel-evidence-gap-v2",
  "chapter": 3,
  "missing_candidates": [
    {
      "temp_id": "C-G-001",
      "fact": "梅丽莎十五岁，通过入学考试后进入廷根技术学校蒸汽与机械系。",
      "category": "person_identity",
      "assertion_mode": "narrator_fact",
      "entities": ["梅丽莎", "廷根技术学校"],
      "source_refs": [
        {
          "line_ids": ["L0015"],
          "quote": "去年七月份，十五岁的梅丽莎通过入学考试，如愿以偿成为廷根技术学校蒸汽与机械系的一员"
        }
      ],
      "why_missing": "现有候选只记录梅丽莎出门上学，没有覆盖年龄、学校和专业。"
    }
  ],
  "checked_line_ranges": [
    {
      "from": "L0001",
      "to": "L0060",
      "result": "checked"
    }
  ]
}
```

要求 `checked_line_ranges` 覆盖全章。程序应验证范围无缺口；这比让模型只说“已检查全文”更可验收。

## 4. Repairer：只修问题条目

### 4.1 System Prompt

```text
你是“证据条目修复器”。只处理 ISSUES 指定的条目和 RELEVANT_SOURCE，不重新抽取全章，不添加无关事实。

修复规则：
- unsupported：删除，或在相关原文确有支持时重写；
- partial_support／quote_mismatch：换成足以支持整句的当前章连续短引；
- overclaim／modality_error：保留原文不确定性和信息来源；
- compound：拆成多个原子条目；
- duplicate：保留信息最完整、引用最可靠的一条，合并多处 source_refs；
- wrong_entity／future_leak：改用本章实际称呼；
- 不能修复时输出 action=drop。

只输出 JSON。临时 ID 使用原 ID 加后缀，如 C-B-009a、C-B-009b。
```

### 4.2 User Message

```text
<JOB>
job_type: repair_chapter_evidence
chapter_no: {{CHAPTER_NO}}
prompt_version: repairer-v2.0
</JOB>

<RELEVANT_SOURCE sole_evidence_source="true">
{{ONLY_LINES_NEEDED_FOR_ISSUES}}
</RELEVANT_SOURCE>

<ISSUES>
{{VERIFIER_ISSUES_JSON}}
</ISSUES>

<ORIGINAL_ITEMS>
{{FLAGGED_ITEMS_JSON}}
</ORIGINAL_ITEMS>
```

### 4.3 输出 Schema

```json
{
  "schema_version": "novel-evidence-repair-v2",
  "chapter": 3,
  "repairs": [
    {
      "original_temp_id": "C-B-009",
      "action": "replace",
      "replacement_items": [
        {
          "temp_id": "C-B-009a",
          "fact": "梅丽莎拔起怀表按钮转动，使停住的秒针重新走动。",
          "category": "event_action",
          "assertion_mode": "narrator_fact",
          "entities": ["梅丽莎", "怀表"],
          "first_appearance_candidate": false,
          "source_refs": [
            {
              "line_ids": ["L0038"],
              "quote": "先将怀表顶端的按钮拔起，仅仅转动了几圈，便有哒哒哒的秒针走动声传出"
            }
          ],
          "notes": ""
        },
        {
          "temp_id": "C-B-009b",
          "fact": "梅丽莎根据教堂六下钟声调整怀表时间，并把怀表还给周明瑞。",
          "category": "event_action",
          "assertion_mode": "narrator_fact",
          "entities": ["梅丽莎", "周明瑞", "怀表"],
```

## 5. 本地程序先做的机械校验

在调用 Verifier 前，代码应先拒绝以下条目，减少模型成本：

1. JSON 解析失败；
2. Schema 失败；
3. `chapter` 不匹配；
4. `temp_id` 重复；
5. `line_id` 不存在；
6. quote 不是指定行中的连续子串；
7. quote 包含 `U+FFFD`、NUL 或异常控制字符；
8. fact 为空、超过长度上限；
9. `source_refs` 为空；
10. 响应 `finish_reason` 表示截断；
11. 模型输出 Markdown 围栏或额外说明；
12. 使用了 prior state 中存在、但本章正文未出现的实体别名。

机械失败无需让模型“判断”，直接进入格式修复或重发。

## 6. 语义校验顺序

推荐顺序：

```text
Schema／短引机械校验
    ↓
双抽取结果合并
    ↓
Verifier 逐条审校
    ↓
Repairer 修问题
    ↓
Gap Finder 找漏项
    ↓
对新增漏项再跑一次简化 Verifier
    ↓
正式编号
```

Gap Finder 放在初次修复后，可以避免把明显错误候选当成“已覆盖”，从而漏掉正确事实。

## 7. 选择性重试矩阵

| 故障 | 是否重发全文 | 建议动作 |
|---|---|---|
| HTTP 超时／5xx | 原请求 | 指数退避；保持相同 job_id |
| JSON 截断 | 原请求或按段落分块 | 检查 finish_reason；提高输出预算或减小块 |
| JSON 语法错误 | 不必全文 | 给原始响应发格式修复请求，不允许改语义 |
| quote 不匹配 | 只发相关行 | Repairer 更换短引 |
| 单条过度推断 | 只发相关行＋条目 | Repairer 降级模态或删除 |
| 大量漏项 | 发全文 | Gap Finder；必要时重跑对应专职抽取器 |
| 未来别名污染 | 发当前章＋修正 prior state | 删除污染账本，重跑受影响章节 |
| ID 断号 | 不调用模型 | 程序重新排序编号 |
| Markdown 乱码 | 不调用模型 | 编码／ZIP／渲染管线修复 |

不要因为一条引用失败而重跑整本书，也不要把同一错误请求无条件重试三次；那只会得到高度相关的错误。

## 8. 合并与语义去重提示词（仅在规则无法决定时）

### System Prompt

```text
你是“证据候选去重裁判”。只判断给定候选是否表达同一原子事实。

- 同一主体、同一动作／状态、同一对象、同一结果且模态相同，才可合并；
- 人物说法与客观事实不合并；
- 同一场景的连续但不同动作不合并；
- 一个条目比另一个多出可独立事实时，不合并，应先拆分；
- 可合并时保留更完整但不过度推断的 fact，并汇总 source_refs；
- 不得利用原文之外的知识。

只输出 JSON。
```

这一步只处理少量相似候选，不应把整章全部交给去重模型。

## 9. 格式修复 Prompt

若提供商偶尔在 JSON 前后添加解释，可使用一个严格、低成本的格式修复调用：

```text
下面内容本应是 JSON。只修复 JSON 语法和字段格式，不改变任何 fact、quote、实体或条目数量。若无法无损修复，输出 {"repairable": false}。不要解释。
```

格式修复不能兼任事实修复。

## 10. 审校器模型选择

- 第一轮可用速度较快、成本较低的模型；
- 审校器最好使用能力更强或不同家族的模型，以减少相关错误；
- 若只能用同一模型，至少使用不同 Prompt、独立上下文和明确的“只找错、不重写”职责；
- 不要把抽取器的自我评价当作独立验收；
- 人工金标仍是判断召回率的最终基准。
