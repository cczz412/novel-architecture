# 中文网络小说逐章证据抽取：本地 API 高精度方案包

## 先给结论

你现在遇到的主要问题，不是简单的“模型不够强”或“温度没调好”，而是**输入形态、任务合同、上下文管理、校验机制和文件编码同时存在结构性问题**。

当前 ZIP 里的默认链把一章正文切成大量约 23 字的滑动短片，再要求模型判断“以后可能被继续读取的原子事件”。这会同时造成：

1. 主语、宾语、否定词、推测语气和结果常被切断，模型不得不自行拼接；
2. “以后是否有用”需要后文知识，但提示词又禁止后文知识，任务本身矛盾；
3. 提示词主动排除“普通动作、场景复述”，与目标要求的“宁多勿漏、人物／地点／组织／规则都算证据”相反；
4. 一次调用结束后没有独立补漏与逐条核验，漏掉的内容无法在后续大纲阶段恢复；
5. 默认链不见前文章节，实体表试验却混入了后文章节范围和别名，形成“无上下文”与“未来泄漏”两个极端；
6. Markdown 内嵌一整行超长 JSON，打印与渲染容易换行错乱；原 ZIP 的中文文件名还没有 UTF-8 标志，部分解压器会直接显示乱码。

要复现此前那种逐章证据效果，建议把“一次完整作业”设计成**程序编排的多次 API 调用**，而不是一条超长请求：

```text
原始 ZIP／正文
  ↓ 编码与章节机械校验
完整当前章＋前文状态账本（只用于消歧）
  ├─ 抽取 A：动作、动机、关系、状态变化
  └─ 抽取 B：人物身份、地点、组织、物品、规则、体系、数字
  ↓ 程序合并、原文短引校验、原子性检查
独立审校：错项、过度推断、复合事实、重复项、漏项
  ↓ 只修有问题的条目
程序排序并生成 E-章号-序号
  ↓
逐章 Markdown＋状态账本更新＋全局回归检查
```

## 关于“你之前是不是一次性全加载，再一次次吐出来”

不是“一次 API 把 50 章全塞进去再吐完”。此前工作具备以下几个特征：

- 五个正文包都可访问，因此可以先按章切分；
- 证据抽取按章节／章节批次反复读取和生成，不是一条请求完成；
- 当前章正文是该章事实的依据，前文主要帮助确认人物别名、既有关系和连续状态；
- 50章全部抽完后，才把完整证据母集用于跨章整理和机械校验；
- 编号、章节完整性、重复和文件汇总由程序再检查。

本地 API 应复现的是这套**外部编排＋显式状态＋多轮审校**，而不是依赖模型在一个超长对话里“自己记住一切”。

## 第3章或第4章要不要参考前文

要，但要严格区分两种材料：

- **当前章正文**：唯一可引用的证据源；所有短引必须来自这里。
- **前文状态账本**：只用于解析“他／她／队长／那本笔记”等指代、判断是否首次出场、识别既有关系；不能被当成本章证据，不能把前文事实重复写成本章新证据。

第3章应附带第1～2章的精简状态；第4章应附带第1～3章的精简状态。绝对不要给第3章注入第6章才成立的“愚者”别名，也不要给出“第1～20章出现范围／出现次数”这类未来统计。

## 文件阅读顺序

1. `01_ZIP审计_编码与请求体问题.md`：当前 ZIP 的具体故障定位。
2. `02_推荐总架构_逐章证据生产线.md`：完整作业流。
3. `03_单章抽取_API完整请求模板.md`：可直接改造成请求体的 Prompt 与 Schema。
4. `04_审校补漏_纠错与重试提示词.md`：第二、第三次调用怎么发。
5. `05_跨章上下文_实体账本与前文参考.md`：前文该给多少、怎样防止后文污染。
6. `06_本地实现蓝图_编码切章渲染与ZIP.md`：本地程序框架与编码修复代码。
7. `07_质量验收_指标回归集与故障告警.md`：怎样证明“抽得准”。
8. `08_第3章第4章_具体问题与改造示例.md`：用当前文件做实例说明。
9. `09_实施顺序_从最小改造到高精度.md`：按优先级落地。

## 最重要的十项改动

1. 改为发送**完整当前章**，不发送任意字符切断的短引目录。
2. 段落或句子加稳定行号，短引由模型从完整文本中选择，再由程序验证。
3. 把“以后可能有用”改成明确覆盖清单，先高召回抽取，再由下游决定用途。
4. 每条保留叙述模态：事实、人物说法、猜测、计划、未决问题不得混写。
5. 内部输出带类别，最终 Markdown 可以隐藏类别；类别用于防漏，不是为了文学解读。
6. 使用前文章节生成的**prior-only 状态账本**，禁止未来别名、未来范围和未来次数。
7. 至少增加一次独立“错项＋漏项”审校；高精度模式采用双抽取器。
8. 最终 `E-章-序` 由程序排序后分配，模型只生成临时 ID。
9. Markdown 由程序从通过校验的 JSON 确定性渲染，不让模型同时负责事实、编号和排版。
10. ZIP 用真实 Unicode 文件名写入、验证 UTF-8 标志，并排除 `__MACOSX`、`._*`、`.DS_Store`。
