# 质量验收：怎样证明证据“抽得准”

## 1. 不要用“JSON 成功率”替代事实质量

以下指标只能说明管线能跑，不能说明抽取正确：

- HTTP 200；
- JSON 可解析；
- ID 连续；
- 输出条数很多；
- 温度低；
- 模型自称已检查全文。

事实质量至少要同时评估**准确率、召回率、模态、原子性和引用完整性**。

## 2. 硬性机械指标

建议所有正式交付满足：

| 指标 | 目标 |
|---|---:|
| 章节连续性 | 100% |
| 每条 evidence ID 唯一 | 100% |
| 每章序号连续 | 100% |
| source chapter 与 ID 章号一致 | 100% |
| quote 为当前章原文连续子串 | 100% |
| line_id 存在且覆盖 quote | 100% |
| JSON Schema 通过 | 100% |
| `U+FFFD`、NUL、异常控制字符 | 0 |
| 未来章节证据注入 | 0 |
| ZIP 中文文件名 UTF-8 标志 | 100% |
| `__MACOSX`／`._*` | 0 |

任何一项失败，该章不得进入正式 Markdown。

## 3. 语义质量指标

### 3.1 事实准确率

人工抽样判断：输出条目中有多少被原文完整支持。

```text
Precision = 正确且完整支持的输出条目 / 全部输出条目
```

“短引包含几个相同词”不算支持；主体、动作、对象、条件、结果和模态都要对得上。

### 3.2 事实召回率

先为测试章节建立人工金标：

```text
Recall = 被系统抽出的金标事实 / 金标事实总数
```

召回必须按类别分开看。总体召回高，仍可能漏光所有地点或社会制度。

### 3.3 模态保持率

重点检查：

- 说法是否仍是“某人称”；
- 猜测是否仍是“某人怀疑／认为可能”；
- 计划是否被误写为已发生；
- 梦境／幻觉是否被写成现实；
- 报纸／传闻是否注明来源；
- “暂时、似乎、可能”是否被删掉。

```text
Modality Accuracy = 模态正确条目 / 含模态条目
```

### 3.4 原子性

人工判断一条能否自然拆成两个互不依赖的事实。若能，通常应拆。

例如：

> 梅丽莎修好怀表并还给周明瑞。

至少包含“使怀表走动”“校时”“归还”三个动作，而且“修好”本身还存在过度概括风险。

### 3.5 引用充分率

quote 是原文子串仍不够。引用必须覆盖完整支持范围。

```text
Citation Sufficiency = 引用足以支持整条事实的条目 / 全部条目
```

## 4. 建立跨题材回归集

不要只用一部小说调 Prompt。建议至少选择：

- 悬疑／推理：证词、猜测、未决问题多；
- 恋爱／都市：内心态度与关系变化多；
- 仙侠／玄幻：体系、境界、物品和规则多；
- 历史／权谋：官职、组织、制度、地理、时间多；
- 科幻／系统：技术机制、数字条件多；
- 群像：人物别名和跨章关系多；
- 第一人称或不可靠叙述：模态风险高。

每种题材挑若干章，人工标出全部目标证据。Prompt 升级后必须在整个回归集上比较，不能只看一个成功例子。

## 5. 金标制作规则

两名标注者独立抽取，再进行仲裁。金标条目至少含：

```json
{
  "gold_id": "G-C0003-001",
  "fact": "……",
  "category": "person_identity",
  "assertion_mode": "narrator_fact",
  "source_quote": "……",
  "line_ids": ["L0015"],
  "adjudication_notes": "为什么算一个原子事实"
}
```

先统一以下口径：

- “首次提及”与“首次场景出场”是否都收；
- 外貌多个并列特征是一个事实还是多条；
- 同一价格表如何拆；
- 反复说出的同一事实是否合并；
- 人物内心疑问是否收；
- 作者 `ps` 是否排除；
- 比喻和纯气氛是否排除。

没有统一金标口径，模型评测数字没有可比性。

## 6. 语义匹配方法

证据事实不是逐字摘要，不能只用字符串相等。推荐评测流程：

1. 先按 source line／quote 重叠生成候选匹配；
2. 再由人工或独立裁判判断语义是否对应；
3. 一对多／多对一时检查原子性；
4. 不允许仅凭实体相同判定命中。

可以用向量相似度筛候选，但不能作为最终金标判定。

## 7. 每章自动告警

告警只提示人工／审校器复查，不能直接判错。

### 7.1 条数密度异常

用同一本书已通过章节的中位数和 MAD，而不是固定“每章必须30条”。

```text
若 evidence_count / chapter_chars
显著低于全书中位数，触发 LOW_DENSITY。
```

当前第3章约3,366字符却只有10条中性事件，且类别极度集中，应触发低召回复查。

### 7.2 类别空缺

若一个数千字章节中人物、地点、数字、规则、关系等多个类别全部为空，触发 `CATEGORY_GAP`。但不能强制每章每类都有条目。

### 7.3 段落覆盖空洞

统计每个 narrative line 是否至少被一个候选引用。连续多段完全无引用时，送 Gap Finder 检查。

作者说明、纯章标题和明确排除的诗歌／广告等可标记为 exempt。

### 7.4 引用过短／过长

- 太短：容易缺主体或否定；
- 太长：模型可能用一大段掩盖事实不精确。

建议短引通常12～80汉字；超出只报警，不直接拒绝，因长句可能确实需要更长上下文。

### 7.5 模态关键词

若原文短引含以下词，而 fact 没有对应模态，触发复核：

```text
可能、也许、似乎、仿佛、猜、怀疑、认为、打算、计划、希望、据说、听说、报纸称、梦见
```

### 7.6 未来别名

当前章正文未出现的实体名若出现在 fact，且只存在于 prior state 或全书表，触发 `FUTURE_ALIAS_OR_CONTEXT_LEAK`。

## 8. A/B 测试不要只看条数

比较两个 Prompt 时至少记录：

| 指标 | 说明 |
|---|---|
| Precision | 多抽是否带来错项 |
| Recall | 是否真正补到金标事实 |
| Category Recall | 哪类事实改善／恶化 |
| Modality Accuracy | 是否更容易把猜测写实 |
| Atomicity | 是否捆绑事实 |
| Citation Sufficiency | 引用是否完整 |
| Token／成本 | 输入和输出实际消耗 |
| Truncation Rate | 是否被 max_tokens 截断 |
| Retry Rate | 需要多少修复 |
| Cross-genre Stability | 是否只对一部小说有效 |

“实体表注入后条数变多”不是胜利；若它泄漏未来身份或使不确定事实被写实，整体质量可能更差。

## 9. 模型版本升级的闸门

只有同时满足以下条件才替换现役 Prompt／模型：

1. 回归集总体 Precision 不下降；
2. 高风险模态错误不增加；
3. 主要类别 Recall 有可复现提升；
4. 不出现未来泄漏；
5. 成本与截断在可接受范围；
6. 至少两次独立运行结论一致；
7. 旧版本和新版本产物都可重放；
8. Prompt、Schema、模型和参数都有版本号与 SHA。

## 10. 人工抽检策略

即使全自动，也建议：

- 每本书至少人工验第1章、信息密集章、对话密集章、体系说明章、高潮章；
- 对所有 `manual_review`、未来别名、引用不充分、低密度章节进行人工复核；
- 随机抽取5%～10%条目做支持性检查；
- 新题材首次接入时扩大抽样；
- 一旦发现系统性错误，回溯受同一 Prompt／状态账本影响的所有章节。

## 11. 最终交付验收清单

```text
[ ] 章节数与源文件一致
[ ] 所有章节号连续
[ ] 所有 E 编号连续且唯一
[ ] 每条事实只有一个原子头
[ ] 每条有当前章短引
[ ] 每条短引能完整支持事实
[ ] 人物说法／猜测／计划保留模态
[ ] 无未来章节别名或事实
[ ] 无外部作品知识
[ ] 无作者日志元数据混入
[ ] Markdown 一条一行，无超长 JSON 单行
[ ] UTF-8 严格解码，无替换字符
[ ] ZIP 中文文件名标志正确
[ ] ZIP 无 __MACOSX／._*／.DS_Store
[ ] ZIP CRC 测试通过
[ ] 保存请求、响应、Prompt 版本和哈希
```
