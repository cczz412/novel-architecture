# 中文网文“中性原子事件”请求诊断包

## 核心结论

✅ 这次低命中不能简单归咎于模型。模型知道任务的大概名称，却不知道严格验收标准；更麻烦的是，模型没有看到连续可读的章节，只看到被拆成 175 个短锚的 JSON 目录。

附件里的短锚并未丢字：按顺序消除重叠后，可以逐字拼回第3章全文。问题出在阅读形态——原文 3366 字，被包装成 12078 字的目录，体积约为连续正文的 3.59 倍；目录中约 65.9% 是字段名、ID、章节号和 JSON 标点。只有 2.3% 的锚从句子边界开始，只有 2.9% 的锚在句子边界结束。模型必须一边拼句子，一边理解剧情，一边决定事件，一边选锚，错误会叠加。

🔥 收益最大的改法是：**同时给连续正文与锚目录**。连续正文负责理解，锚目录只负责挂证据。紧接着要把 `event` 改成“明确主体＋具体动作＋直接结果＋原文限定”的硬合同，并要求多个短锚共同覆盖整条事实。

⚠️ 单次 API 调用可以把首轮成功率做得很高，也可以把 JSON 语法和 anchor_id 合法性做成机械保证；但无法对“事件是否全、事实是否完全正确、是否与人工金标逐字一致”给出 100% 语义保证。生产系统仍要有确定性校验，语义失败时允许修复调用或人工复核。
