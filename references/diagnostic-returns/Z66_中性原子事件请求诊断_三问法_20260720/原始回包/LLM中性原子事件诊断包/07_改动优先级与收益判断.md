# 改动优先级与收益判断

## 直接排序

| 优先级 | 改动 | 预期收益 | 为什么排这里 |
|---|---|---|---|
| P0-1 | 连续正文＋冻结锚目录双视图 | 极高，主要提升剧情理解、召回、主语与因果正确性 | 现役最大负担是从175个句中碎片隐式重建全文。只改这一项，模型才真正“读到一章小说”。 |
| P0-2 | event 强制“姓名主体＋具体动作＋直接结果＋原文限定” | 极高，主要提升严格命中与可读性 | 当前坏句多数在合同内仍算合法；不改合同，换模型也会继续写标题式事实头。 |
| P0-3 | anchors 必须共同覆盖整条 event | 极高，主要提升证据可核验性 | 现役锚常只覆盖半句。下游只查 ID 是否存在，无法证明事实。 |
| P1-1 | 把稳定规则移入 system | 高，提升跨章一致性和抗正文干扰能力 | 最高优先级消息应固定资料边界与质量红线。 |
| P1-2 | 正反例＋原子拆分规则＋不确定性规则 | 高，降低“修好怀表”式过度解释和合并错误 | 边界只有示例才能让模型稳定学会。 |
| P1-3 | 严格 JSON Schema 或本地 Schema 校验 | 中高，保证结构、字段和 anchor_id 合法 | 能消灭机械错误，不能单独解决语义。 |
| P1-4 | 确定性后置校验与失败阻断 | 高，防止坏结果直接进入后续链 | 单次生成永远有残余错误，必须让系统能拒收。 |
| P2-1 | 更强模型／更高 reasoning 档 | 中高，在正确供料和合同后进一步补召回 | 现在先换模型会花更多钱去理解坏输入。 |
| P2-2 | 温度降到0、增加候选或共识 | 中，改善稳定性 | 不能修复合同缺失，也不能保证语义。 |
| P2-3 | 把锚改成句子级或40～80字语义块 | 很高，但涉及上游数据合同改造 | 若能改锚生成，这是比长期保留微碎片更好的终态。 |

## 只允许改一处时

改成“连续正文＋原锚目录”。这是对召回与事实正确性收益最大的单项改动。

## 只允许改两处时

再加四要素硬合同。一个负责让模型读懂，一个负责让模型写对。

## 不建议的顺序

❌ 先反复调温度、max_tokens 或换 Flash 型号，却继续只喂碎片。

❌ 只加实体表。实体表能统一名称，不能恢复被打碎的因果与场景。

❌ 只把示例写长，却不要求锚完整覆盖。句子会更漂亮，但证据仍可能挂错。

## 收益如何验证

保持模型与参数不变，用同一批20章做 A/B：旧请求对比“连续正文＋新合同”。分别统计事件级语义精确率、召回率、四要素完整率、原子性、锚蕴含率和 JSON 机械通过率。严格逐字命中可以保留，但不要把它当唯一指标，因为同一事实有多种正确表述。
