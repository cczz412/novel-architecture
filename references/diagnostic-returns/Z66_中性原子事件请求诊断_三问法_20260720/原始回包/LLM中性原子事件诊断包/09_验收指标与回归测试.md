# 验收指标与回归测试

## 不要只看“严格逐字命中”

严格逐字命中适合发现格式漂移，但会把同义正确句判错。推荐同时保留六组指标：

| 指标 | 建议上线门槛 | 说明 |
|---|---:|---|
| JSON 解析率 | 100% | 任何解析失败都阻断 |
| Schema 通过率 | 100% | 字段、类型、额外字段 |
| anchor_id 合法率 | 100% | ID 必须来自本章目录 |
| 明确主体率 | 100% | event 中出现姓名、组织或具体物品主体 |
| 四要素完整率 | ≥95% | 主体、动作、结果／对象、原文限定 |
| 原子性合格率 | ≥95% | 没有无关多事实捆绑 |
| 锚蕴含率 | ≥95% | 所有关键子句均被所挂锚支持 |
| 事件语义精确率 | ≥90% | 输出事件中有多少正确 |
| 事件语义召回率 | ≥90% | 金标事件中有多少被覆盖 |
| 严格命中率 | 作为回归参考 | 不作为唯一上线指标 |

门槛要按你们业务损失调整。事实库若会驱动后续剧情推理，锚蕴含率和精确率应比召回率更严。

## 金标格式建议

人工金标不要只有一句自然语言，建议每条同时标：

```json
{
  "gold_id": "G-C0003-01",
  "subject": "周明瑞",
  "action": "确认",
  "result": "头部伤口已经愈合",
  "qualifiers": ["按住太阳穴检查时"],
  "acceptable_anchor_ids": ["E0085", "E0086", "E0087", "E0088"],
  "canonical_event": "周明瑞按住太阳穴检查伤处后，确认原先的头部伤口已经愈合。",
  "acceptable_paraphrases": []
}
```

这样能区分“事实正确但措辞不同”“事实缺限定”“锚不全”“完全漏项”。

## A/B 试验设计

- 固定模型、温度、max_tokens、n 和 reasoning_effort。
- 使用相同20章金标，至少覆盖对话多、回忆多、世界设定多、动作多、开放疑问多的章节。
- A 组用现役碎片请求；B 组用连续正文＋新合同。
- 每章重复3次，观察方差，不只看单次最好成绩。
- 记录 token、耗时、事件数、错误标签和修复率。

## 错误标签

```text
MISSING_SUBJECT      缺明确主体
VAGUE_ACTION         动作空泛
MISSING_RESULT       缺对象或结果
MISSING_QUALIFIER    缺时间／条件／目的／数量／不确定性
COMPOUND_EVENT       多个独立事实捆绑
OVERCLAIM            把推测写成事实或增加原文没有的因果
ANCHOR_INVALID       anchor_id 不存在
ANCHOR_PARTIAL       锚只支持部分子句
ANCHOR_IRRELEVANT    挂了无关锚
DUPLICATE_EVENT      重复事实
MISSING_EVENT        漏金标事件
LOW_VALUE_ACTION     收入无后续价值的小动作
```

## 上线前回归闸门

- 新 Prompt 在固定金标集上全部机械指标通过。
- 语义精确率、召回率、四要素和锚蕴含率达到门槛。
- 不得只挑成功章节；失败章必须保留在回归集中。
- Prompt、模型、参数、锚生成器任一变化，都重新跑全套。
- 上线后按比例抽检，发现新型错误就补入金标与测试。
