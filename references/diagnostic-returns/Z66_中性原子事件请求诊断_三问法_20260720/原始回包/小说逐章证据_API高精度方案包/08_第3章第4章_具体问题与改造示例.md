# 第3章／第4章：当前请求的具体问题与改造示例

## 1. 为什么选择这两章做说明

当前 ZIP 有第3章和第4章的完整请求体；第3章还在后续试验请求中暴露了已落盘的10条中性事件，因此可以同时观察：

- 输入怎样切碎；
- Prompt 怎样过滤；
- 结果怎样漏项；
- 引用怎样不足；
- 实体表怎样泄漏未来；
- 为什么第4章也会受到相同结构影响。

本文件不是重新抽取整章，而是演示如何改造 API。

---

## 2. 第3章当前供料

完整第3章约3,366字符。默认请求没有发送连续正文，而是发送175个锚点：

- 平均短引23.5字符；
- 相邻片段通常只重叠4字符；
- 0%的短引从清晰句界开始；
- 仅3.4%的短引在标点边界结束；
- 序列化目录约12,078字符，是完整正文的3.59倍。

典型短引：

```json
{"anchor_id":"E0022","quote":"且对自身没有丝毫放松。\n　　“两天后，要参加廷根大"}
```

它只能看到“要参加廷根大……”的半句话。模型必须靠后续锚点拼接“学历史系的面试”，同时还要判断前一句是否属于同一事实。

再如：

```json
{"anchor_id":"E0161","quote":"克莱恩，羔羊肉和豌豆不要买多了，班森或许得周"}
```

“周日才能回来”的尾部被切到下一锚点。任何一个锚点单独看都不足以支持完整事实。

### 推荐供料

```text
[L0001] 第3章 梅丽莎
[L0002] 确定了计划，周明瑞顿时有了主心骨……
[L0003] 直到这个时候，他才有心情仔细审视克莱恩残留的记忆碎片。
[L0004] 或许受子弹穿过的影响，克莱恩的记忆就像摔碎的玻璃……
...
```

模型看到完整语句和段落；输出时自己选择能够完整支持事实的短引，程序再验证短引确实存在。

## 3. 第3章当前10条事件的结构性漏项

事件池为：

1. 周明瑞确定了计划；
2. 周明瑞审视记忆碎片；
3. 得知两天后参加面试；
4. 把左轮放进抽屉；
5. 发现伤口愈合；
6. 梅丽莎修好怀表并归还；
7. 梅丽莎嘱咐购物；
8. 周明瑞答应；
9. 梅丽莎离家上学；
10. 周明瑞转向转运仪式。

这10条并非全部错误，但明显不是“宁多勿漏”的逐章证据。至少漏掉以下类别：

| 类别 | 本章明确内容 | 当前事件池 |
|---|---|---|
| 未决问题 | 手枪来源、自杀或他杀、笔记句子含义、事发前两天经历缺失 | 未收 |
| 人物教育 | 梅丽莎的启蒙、公立初等学校、廷根技术学校 | 未收 |
| 人物身份 | 梅丽莎十五岁、蒸汽与机械系学生 | 未收 |
| 人物动机／特征 | 喜欢齿轮等，立志成为蒸汽机械师 | 未收 |
| 家庭／职业 | 班森所在公司受南大陆局势影响、裁员、加班与出差 | 未收 |
| 克莱恩经历 | 平民背景、古弗萨克语起步晚、靠熬夜追赶、以中等成绩毕业 | 未收 |
| 特殊物品 | 父亲遗留的怀表及其价值和故障史 | 未收 |
| 社会制度 | 《初等教育法》、公立学校宗教中立、学费 | 未收 |
| 交通／数字 | 步行约五十分钟、公共马车费率、为省钱步行 | 未收 |
| 历法／宗教 | 十二个月、365／366天、七天一周、七位正统神灵 | 未收 |
| 人物动机 | 周明瑞明确想回家 | 仅模糊写“转向仪式” |

根因不是模型“没看见”这些字，而是 Prompt 告诉它只找“以后可能被读取”的事件，且不凑普通动作和场景信息。

## 4. 第3章两条精度问题

### 4.1 “修好怀表”过度概括

当前：

> 梅丽莎修好怀表并还给周明瑞。

原文现场显示：

- 周明瑞尝试转动顶端，却没有让秒针走动；
- 梅丽莎拔起按钮再转动，秒针开始走；
- 她听教堂钟声后继续调整时间；
- 她把怀表归还。

此外，前文只说梅丽莎“最近更是宣称将它修好了”。因此更精确的拆法是：

```text
梅丽莎拔起怀表按钮转动，使停住的秒针重新走动。
梅丽莎根据教堂六下钟声调整怀表时间，并把怀表还给周明瑞。
```

是否由她“修好”是此前叙述提供的背景，不应和当前操作无差别捆绑。

### 4.2 “离开家去上学”的锚点不完整

当前引用只覆盖：

- 准备出门；
- 打开门后停下；
- 再次叮嘱购物。

真正“离开”的支持出现在更后面的“目送妹妹关门离开”。所以：

- 事实本身大体成立；
- 当前 `anchors` 不足以完整证明；
- 现有程序只检查 anchor_id 合法，没有检查语义支持是否完整。

正确做法是让 quote 直接包含“关门离开”，或附上完整的两个 source_refs。

## 6. 第4章当前供料的同类问题

第4章约4,182字符，却被序列化成215个短引、约14,918字符：

- 目录是正文的3.57倍；
- 只有0.9%的短引从清晰边界开始；
- 只有2.8%的短引在标点边界结束；
- 最长单行达到18,144字符。

第4章内容横跨多个类别：

- 穿着与唯一体面正装；
- 家庭积蓄与货币换算；
- 携枪与空弹巢防误击；
- 廷根气候和低收入街区环境；
- 市场、面包房、房租、工资、大学讲师收入；
- 《谷物法案》及进口粮食国家；
- 马戏团、塔罗占卜；
- 罗塞尔的发明、政治经历、教会关系、航路与死亡；
- 占卜师首次出现。

若 Prompt 只寻找“后续会读取的原子事件”，通常会偏向：

- 买菜；
- 发现塔罗；
- 进入占卜帐篷；
- 罗塞尔疑似穿越者。

而大量经济、制度、地点、人物身份和物品规则会被当作背景删掉。这正是其他题材小说也不稳定的原因：模型不知道你究竟想把“背景”保留到什么程度。

## 8. 对“实体表”的正确改造

当前实体表的问题不是“有实体表”，而是表的来源时间和权力层级错误。

### 当前做法

```text
system：当前章 only
system：全1～20章实体统计、未来别名、未来出现范围
user：当前章碎片
```

两个 system 消息发生冲突，未来表还是高优先级输入。

### 推荐做法

```text
system：稳定抽取规则
user：
  - prior-only state，明确 context_only / citable=false
  - 当前章完整正文，明确 sole_evidence_source=true
  - 输出合同
```

prior state 可以作为 user message 中的结构块，不必作为第二个 system；这样不会让动态数据与固定规则同级。

```text
  ↓
```


## 10. 最关键的变化

当前链是：

```text
正文 → 字符滑窗 → 单次事件筛选 → 下游只能使用漏损后的10条
```

建议改成：

```text
正文 → 完整行号文本 → 双视角高召回 → 全文对照补漏 → 逐条修复 → 正式证据
```

前者把“信息损失”放在第一步且不可逆；后者把删减和解释推迟到证据已经完整、可追溯之后。
