# 结构化记忆 vs 长上下文：长篇小说 AI 辅助创作的学术与工程前沿

查证日期：2026-08-13  
研究问题：事实账本＋按任务编译上下文，是否优于每次输入数十万字正文？

## 结论先行

**核心假设成立一半，而且最该改的是“最小”二字。**

现有研究支持：把人物状态、事件、时间、角色知情范围、情节承诺等显式化，再按任务缩小阅读范围，通常能降低费用和延迟，并在长历史、跨会话或远距离状态追踪中提高稳定性。长上下文的标称窗口也不等于有效推理长度；2025—2026 年模型的多针检索进步很快，但真实语义检索、跨段多跳推理和叙事状态维护仍会随长度、证据位置和干扰文本显著波动。

现有研究不支持：纯事实账本总能胜过全文，也不支持上下文越小越好。2026 年一项最直接的对照中，约 100K token 的完整历史配合 GPT-5-mini，在 LongMemEval 上为 82.4%，平面事实记忆仅 49.0%；在 LoCoMo 上为 92.85% 对 57.68%。账本大幅省钱，却因抽取和检索漏失而牺牲准确率。另一批研究又显示，长度到约 112K 后，设计更好的检索记忆可以反超全文。这意味着存在一个随模型、任务、历史长度和查询次数变化的**交叉点**，不存在固定赢家。

对长篇小说产品，证据最支持的技术表述是：

> **结构化账本负责可编辑状态、约束和导航；原文负责证据、语气与隐含意义；上下文编译器生成“最小充分包”，证据不足时自动扩张；全书长上下文作为低频复核与漏项发现器。**

这与现有项目的“冻结正文是最终证据、账本保存确认事实、压缩视图可重建、执行包按任务编译”高度一致。技术路线不应押注“模型永远读不动长文本”，而应押注“作者仍需要可验证、可编辑、可回滚的故事状态”。

### 一页判断

| 命题 | 判断 | 证据强度 |
|---|---|---|
| 标称 1M 窗口不等于能可靠综合 1M 内容 | 成立 | 强；多项同行评审基准＋2026 位置控制预印本 |
| 每次输入全文在高频创作中成本更高 | 成立 | 强；官方计价＋多项系统延迟实测 |
| 结构化状态适合时间、实体、关系、角色知识和版本更新 | 成立 | 中强；聊天记忆和 7K—8K 词故事实验 |
| 事实账本单独优于全文 | 不成立为一般规律 | 有直接反例 |
| 账本＋按需原文比纯账本更稳 | 成立 | 中强；LongMemEval、GraphRAG、KG²RAG、叙事研究方向一致 |
| “最小上下文”总优于较宽上下文 | 不成立 | 检索漏证据、多跳和心理叙事均有反例 |
| 已证明能支撑 20—50 万字小说持续改稿 | 尚未证明 | 关键空白；现有生成实验多为约 7K—10K 词 |
| 2—3 年后长上下文会让账本失去意义 | 压缩价值会下降，状态层价值不易消失 | 产品判断；不是论文统计结论 |

## 证据等级

- **[P] 同行评审**：正式会议或期刊论文。
- **[R] 预印本**：尚无同行评审确认，结论需要复现。
- **[V] 厂商材料**：模型发布、产品方论文、自测或官方定价；适合说明能力与工程量级，不应视为独立验证。
- **[E] 工程/独立报告**：技术博客或基准报告，方法透明度不一。

不同论文使用的模型、提示、裁判和数据不同，表中数字只宜在同一研究内部比较。厂商发布的 1M 指标与独立基准不可直接排名。

## 1. 长上下文模型的真实表现

### 1.1 “找得到”进步很快，“读懂并持续维护状态”仍未解决

| 研究 | 状态 | 测试与结果 | 对小说的解释 |
|---|---|---|---|
| [NoLiMa: Long-Context Evaluation Beyond Literal Matching](https://arxiv.org/html/2502.05167v3) | [P] ICML 2025 | 问题与证据没有直接词面重合。GPT-4.1 从短上下文 97.0 降至 79.8@32K、64.7@128K；按保留短基线 85% 计，其有效长度约 16K，虽标称可到 1M。GPT-4o 为 99.3→69.7@32K→56.0@128K。 | 小说旧事实常以改写、暗示和别名出现，比字面“针”更接近 NoLiMa。 |
| [HELMET: How to Evaluate Long-Context Language Models Effectively and Thoroughly](https://openreview.net/forum?id=293V3bJbmE) | [P] ICLR 2025 | 59 个模型、7 类应用任务、最长 128K。简单 NIAH 与真实下游任务相关性弱；针测试近满分的模型，在重排、引用、长文 QA 和复杂指令上仍会退化。 | 厂商针测试不能替代长篇续写评测。 |
| [LongBench v2](https://aclanthology.org/2025.acl-long.183/) | [P] ACL 2025 | 503 道现实长上下文题，材料为 8K—2M words；最佳直接回答 50.1%，o1-preview 增加推理后 57.7%。 | 深理解仍远未饱和；限时人类 53.7% 不等于模型已超过不受限专家。 |
| [LOFT: Long-Context Frontiers](https://aclanthology.org/2025.findings-naacl.374/) | [P] Findings NAACL 2025 | 35 个数据集、最长百万级。长上下文模型在部分检索任务可追平专用系统，但 SQL 式组合推理仍弱且对提示敏感。 | 这是“全文一定更差”的反证：封闭语料、简单查找时，全文可能足够好。 |
| [NOCHA: One Thousand and One Pairs](https://aclanthology.org/2024.emnlp-main.948.pdf) | [P] EMNLP 2024 | 67 本当代小说、49K—336K tokens。GPT-4o 完整输入的成对判断为 55.8%，人类 96.9%；句段检索题 59.8%，全局推理题 41.6%。BM25 取约 17% 原文为 49.7%。 | 全文胜过普通 BM25，但离可靠阅读很远；全局关系比局部证据更难。 |
| [NOVELHOPQA](https://aclanthology.org/2025.emnlp-main.1328.pdf) | [P] EMNLP 2025 | 83 本小说、4,000 题。论文表中跨模型均值在 128K 时由一跳 81.73 降至四跳 68.90；只取 top-7、约 2.5K token 的普通 RAG 总体约 48.86。 | 过度裁剪会漏掉链上任一证据；检索顺序也会破坏叙事关系。 |
| [Positional Failures in Long-Context LLMs](https://arxiv.org/abs/2605.23170) | [R] 2026 | 固定推理题，只改证据位置、填充内容和长度。部分新模型在一种填充下 64K 中部/末尾差异可压到 ±6 个百分点；换一种填充，中部仍可下降 16—56 个百分点，个别旧模型跌幅更大。 | “lost in the middle”已改善，但高度依赖干扰文本和模型，不能当作已消失。 |
| [FABLES](https://arxiv.org/abs/2404.01261) | [P] COLM 2024 | 26 本新小说、平均约 121K tokens。书长摘要错误主要落在人物/关系状态、事件和因果；约一半错误需要间接或多跳判断。声明核验中，小片段 BM25 对不忠实声明的 F1 为 0.249，Claude 全书输入为 0.476。 | “较小包必胜”有明确反例；隐含、多跳证据需要可扩张阅读范围。 |

这些结果共同说明：

- **窗口可容纳**、**局部可检索**、**能全局推理**、**能连续生成不矛盾的故事**是四种能力，不能互相代替。
- 2026 年的位置效应不再总呈经典 U 型；更准确的说法是“性能对位置、干扰类型和任务结构仍不稳定”。
- 小说比简单多针更难：同一事实可能用代词、隐喻、误导叙述或角色错误认知表达；答案还可能依赖叙事顺序而非事件时间。

### 1.2 2026 年厂商结果：不能低估追赶速度

### 1.3 成本曲线

API 账单通常随提交 token 近似线性增加，部分模型在超过阈值后单价跳档。内部注意力计算、稀疏结构和服务端缓存并不透明，不宜简单把理论复杂度直接换算成账单。

按 2026-08-13 官方公开价格，仅算一次请求的输入、不含输出与工具：

| 模型 | 公开输入价 | 100K | 500K | 1M |
|---|---:|---:|---:|---:|
| [GPT-5.6 Sol](https://developers.openai.com/api/docs/pricing) | 短上下文 $5/M；长上下文 $10/M | $0.50 | $5.00 | $10.00 |
| [Claude Sonnet 5](https://platform.claude.com/docs/en/about-claude/pricing) | $2/M；缓存命中 $0.20/M | $0.20 | $1.00 | $2.00 |
| [Gemini 3.1 Pro Preview](https://ai.google.dev/gemini-api/docs/pricing) | ≤200K $2/M；>200K $4/M | $0.20 | $2.00 | $4.00 |

价格会变，中文分词也会影响实际 token 数；表格用于说明斜率，不是预算报价。

若同一部 500K-token 小说每天调用 100 次：

- GPT-5.6 Sol 未缓存输入约 $500/天；理想 90% 缓存折扣约 $50/天；压缩到 10K/次约 $5/天。
- Sonnet 5 未缓存约 $100/天；全部命中缓存约 $10/天；10K/次未缓存约 $2/天。

缓存会削弱账本的成本优势，但不会消除：新章节、改稿、不同前缀、缓存过期和服务限流都会降低理想命中率。更关键的是高频创作的累计量：若手稿从零线性长到 (L)，每个阶段都重新输入全文，累计输入量与调用次数相乘；固定预算的任务包则更接近“调用次数 × 包大小”。

## 2. 结构化记忆路线的学术进展

### 2.1 代表性系统

| 系统 | 架构 | 结果 | 证据判断 |
|---|---|---|---|
| [MemGPT: Towards LLMs as Operating Systems](https://arxiv.org/abs/2310.08560) / [Letta](https://docs.letta.com/concepts/memgpt/) | 类操作系统分层：小型核心上下文、外部 recall/archival memory，模型用工具搜索、换页和写回。 | 原 DMR 中 MemGPT 93.4%，递归摘要 35.3%；但后续 Zep 重跑的 full-context GPT-4 Turbo 为 94.4%。 | [R/V] 主要证明外存优于有损递归摘要，不能证明优于今天的长上下文。 |
| [Zep: A Temporal Knowledge Graph Architecture for Agent Memory](https://arxiv.org/html/2501.13956v1) | episode、实体/事实边、community 摘要；事实带有效时间、写入时间和原消息链接；混合向量、BM25、图遍历与重排。 | LongMemEval-S：GPT-4o 全文 60.2%、约 115K tokens、28.9s；Zep 71.2%、约 1.6K tokens、2.58s。单-session assistant 题反而是全文 94.6%、Zep 80.4%。 | [R/V] 产品方自测且用 LLM 裁判；显示混合记忆的收益与局部漏失同时存在。 |
| [Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory](https://arxiv.org/html/2504.19413) | 抽取原子事实；相似记忆执行 ADD/UPDATE/DELETE/NOOP；图版加入实体关系和失效边。 | LoCoMo：全文 72.90，Mem0 66.88，Mem0g 68.44；输入约 26,031、1,764、3,616 tokens；p95 约 17.1s、1.44s、2.59s。图版提高时间题，却未提高多跳题。 | [R/V] 厂商作者预印本、仅 10 段对话；证明省钱省时，不证明普遍更准。 |
| [LongMemEval](https://openreview.net/forum?id=pZiyCaVuti) | 将长期记忆拆成 value、key、query、reading 四个控制点。 | 约 115K 历史中，GPT-4o oracle evidence 为 87.0%，完整历史 60.6%；使用 Chain-of-Note 后为 92.4% 对 64.0%。原子事实作为 value 会因信息损失伤害整体表现；作为检索 key，则可把召回提高约 4 个百分点、最终准确率提高约 5 个百分点。时间查询扩展提高时间题召回约 7—11 个百分点。 | [P] ICLR 2025。对“事实作索引、原文作载荷”最直接的同行评审支持。 |
| [RecMem](https://aclanthology.org/2026.findings-acl.1619/) | 保留原始交互潜层；重复出现后才合并 episodic/semantic memory，需要时恢复细节。 | 约 31.5K 的 LoCoMo：全文 76.43、RecMem 72.47；约 112K 的 LongMemEval-S：全文 45.60、RecMem 69.20，查询上下文约 5.63K。 | [P] Findings ACL 2026。显示交叉点：较短时全文胜，较长时选择性记忆胜。 |
| [Mnemis](https://aclanthology.org/2026.acl-long.1096/) | raw episode、实体、事实和来源链接组成底层图；上层层级记忆分别支持局部与全局检索。 | GPT-4.1-mini 在 LoCoMo 93.9、LongMemEval-S 91.6。 | [P] ACL 2026。高分仍依赖作者设置与 LLM judge；论文承认抽取幻觉和重建成本。 |
| [Beyond the Context Window](https://arxiv.org/html/2603.04814) | 直接比较 Mem0 平面事实库与全文 GPT-5-mini，并建模缓存后的累计费用。 | LoCoMo：57.68 vs 92.85；LongMemEval：49.00 vs 82.40；PersonaMem v2：62.48 vs 69.75。约 100K 历史时，事实记忆约 10 次查询后成本更低；20 次约省 26%。 | [R] 2026 公司作者预印本。是对“账本一定更准”的强反例，也是“高频查询更省钱”的直接支持。 |

### 2.2 有没有“事实数据库＋检索”对“全文塞入”的直接实验？

**有，但还没有与你们方案完全同构的实验。**

已有对照给出三种相反结论：

1. **全文胜**：上述 2026 直接实验中，GPT-5-mini 全文在两项记忆基准领先 33—35 个百分点；Mem0 自己的 LoCoMo 表中，全文也高于平面/图记忆。
2. **检索记忆胜**：Zep 在 115K LongMemEval-S 自报高于 GPT-4o 全文；RecMem 在约 112K 反超全文；LongMemEval 的 oracle evidence 大幅高于全文。
3. **二者互补**：[Long Context vs. RAG](https://arxiv.org/html/2501.01880v1) 在 13,628 个需上下文问题上，同一 GPT-4o 的全文正确率 56.3%，RAPTOR 49.0%；全文独占正确 2,287 题，RAG 独占 1,294 题。NovelQA 子集也是全文领先，但 RAG 有独占答案。[R]

差异主要来自：

- 事实抽取召回率与错误率；
- 问题是一跳、时间更新、多跳还是全局综合；
- 历史长度与无关噪声；
- 检索值是原子事实、摘要、原始 turn 还是完整 session；
- 检索数量、顺序和读取提示；
- 模型能力、裁判模型与 benchmark backfill 设置。

文献中尚无大规模实验同时满足：**人工确认账本、每条事实有版本化原文证据、同一 2026 前沿模型、100K—500K 小说、持续续写/改稿、全文/账本/混合四臂、人类叙事评审**。这正是你们必须自建的验证。

### 2.3 知识图谱：适合导航，不适合替代文学原文

- [Microsoft GraphRAG](https://arxiv.org/abs/2404.16130) 的图并不替代文本：实体、关系和 claims 保留 `text_unit_ids`；[Local Search](https://microsoft.github.io/graphrag/examples_notebooks/local_search/)把图信息与原始 text units 一起编入上下文。[R/V]
- [KG²RAG](https://aclanthology.org/2025.naacl-long.449/) 先用向量检索 seed chunks，再用知识图扩展相关 chunk，最终仍组织**原始文本块**供模型读取。[P] NAACL 2025。
- [Dissecting GraphRAG](https://aclanthology.org/2026.tacl-1.29/) 指出三元组抽取的准确率与覆盖率会成为硬瓶颈，图粒度和 community 粒度显著影响最终结果；确定性模板有时比 LLM 自动摘要更准、更省。[P] TACL 2026。
- [GraphRAG-Bench v3](https://arxiv.org/html/2506.05690v3) 的小说子集显示，图对复杂推理和全局总结较有帮助，对简单事实未必胜成熟文本 RAG；更多关系边不等于更好。[R]

对小说，图最适合表达时间、位置、物品归属、关系变化、角色知识、因果先决条件和未兑现承诺。语气、象征、暧昧、心理活动和不可靠叙述应保留原文与多种解释，不能被一个“确定三元组”覆盖。

## 3. 叙事一致性的专门研究

### 3.1 现在如何量化“一部长篇会不会崩”

| 研究/基准 | 状态 | 度量与发现 | 局限 |
|---|---|---|---|
| [Lost in Stories / ConStory-Bench](https://aclanthology.org/2026.findings-acl.410/) | [P] Findings ACL 2026 | 2,000 个提示、目标 8K—10K 词，覆盖生成、续写、扩写、补全；5 大类、19 子类错误。事实细节与时间/情节逻辑占主导，矛盾常在故事中段发生，人物记忆、绝对时间和地理错误跨越更远文本。 | checker 在 1,000 个注入错误上 precision 0.884、recall 0.550；绝对错误率明显低估，适合系统间比较。故事也远短于几十万字。 |
| [DOME](https://aclanthology.org/2025.naacl-long.63/) | [P] NAACL 2025 | 动态层级大纲＋时间 KG。20 篇故事、平均约 7,114 词；完整系统 conflict rate 0.56，移除 memory module 后 4.52，作者报告减少 87.61%；人工 plot/expression coherence 也改善。 | 小样本、旧模型；KG 同时参与生成和部分评估，可能共享盲区；每篇约 200 次调用、4 小时。 |
| [StoryWriter](https://dl.acm.org/doi/10.1145/3746252.3761616) | [P] CIKM 2025 | 事件图、章节级计划、按当前事件动态压缩历史。平均约 8,081 词；自动总分 4.3，去事件图 2.5，去规划或去历史压缩均约 3.9；人评优于 DOC、Agents’ Room 和直接 GPT-4o-mini。 | 仍是 8K 词量级；宽泛质量分大量依赖 LLM judge。 |
| [IS-CoT / IS-Writer](https://aclanthology.org/2026.acl-long.911.pdf) | [P] ACL 2026 | 目标长度从 500 增至 32K 时，多模型平均质量下降 5.83 分；论文把一次性计划的约束衰减称为 Length Collapse。Plan—Write—Reflect 的交错结构计划在 4K—20K 区间改善较大。 | 支持逐段重编译计划，不是事实账本与全文的直接对照；自动评测占比较高。 |
| [NARRABENCH](https://aclanthology.org/2026.eacl-long.176.pdf) | [P] EACL 2026 | 综述 78 个叙事 benchmark，现有任务只覆盖作者分类约 27%；事件、风格、视角、信息揭示等维度明显不足。 | 说明“事实一致”不能代表“小说写得好”。 |
| [CHIRON](https://aclanthology.org/2024.findings-emnlp.499/) | [P] Findings EMNLP 2024 | 结构化角色表分别记录对话、外貌/性格、知识和目标，并用蕴含推理清理假事实；STORIUM masked-character prediction 比摘要基线提高 11.6%。 | 支持角色状态结构化与抽取后验证，未直接测试长篇续写。 |
| [Guiding Generative Storytelling with Knowledge Graphs](https://doi.org/10.1080/10447318.2025.2603634) | [P] 期刊 2025 | 15 人、5 场景、8B 模型。总体 KG 与无 KG 综合分 3.51 vs 3.49，差异不显著；动作/空间型故事有改善，内省/心理型故事反而下降，参与者认为更重复、僵硬。 | 小样本，但它是“结构化越多越好”的重要反证。 |

### 3.2 学界对“长篇会崩”的原因分析

证据指向五类故障，而非单一“上下文不够长”：

1. **检索失败**：证据虽在窗口内，却因位置、干扰、别名或语义改写无法被找到。NoLiMa、HELMET、LongMemEval 都显示这一点。
2. **状态更新失败**：旧事实与新事实并存，模型没有显式有效期、版本或否定记录，容易使用过时状态。Zep、Mem0、ConStory 的时间错误都落在这里。
3. **多跳覆盖失败**：检索只命中因果链的一部分，或把片段按相似度而非时间/叙事顺序排列。NOVELHOPQA 和 FABLES 是直接证据。
4. **计划约束衰减**：一次性大纲在长生成中失去约束力，模型逐步转向局部流畅。IS-Writer、DOME、StoryWriter 都采用动态重规划。
5. **表示损失**：事实抽取把讽刺、隐含动机、角色误解、不可靠叙述和未决歧义压成确定事实。心理叙事 KG 研究与 LongMemEval 的 fact-as-value 消融都显示风险。

因此，“AI 写长篇会崩”不只是模型忘了前文，也可能是**读到了错误版本、只召回半条证据链、计划逐段漂移，或系统在压缩时已经删掉关键含义**。

## 4. 工程折中：混合路线已经是主流形态

已有产品/论文虽不都面向小说，却反复收敛到相同结构：

| 实践 | 结构化部分 | 原文部分 | 观察到的效果 |
|---|---|---|---|
| LongMemEval [P] | 事实增强 key、时间索引、结构化读取 | 原始 round/session 作为 value | fact key 提升召回与 QA；fact value 过度压缩反而伤害整体表现。 |
| Zep/Graphiti [R/V] | 时态事实图、community、有效期 | episode 节点与消息回链 | 115K 聊天自测更快、更准；单 session 局部题仍可能输全文。 |
| Microsoft GraphRAG [R/V] | 实体、关系、claims、community reports | text units 及其 ID | 图负责全局导航，local search 同时编入图与文本。 |
| KG²RAG [P] | KG 扩展 seed chunks | 原始 chunks 重排后交给 LLM | 多跳 QA 优于普通向量检索；不是纯图回答。 |
| RecMem [P] | 重复后形成 episodic/semantic memory | 原始交互潜层可恢复 | 约 112K 反超全文；31.5K 时全文仍占优。 |
| DOME / StoryWriter [P] | 时间 KG/事件图、动态大纲 | 近期历史或动态压缩的相关历史 | 7K—8K 词故事中有消融增益；尚未到书长规模。 |

### 4.1 推荐给该产品的上下文编译结构

不要追求不可知的“绝对最小”，追求**自适应的最小充分上下文**：

1. **硬任务层**：当前写作任务、场景目标、不可违反的计划、输出约束。
2. **近期原文层**：当前段落、上一个场景或章节的逐字文本，维持语气、指代和节奏。
3. **确认状态层**：与当前实体、地点、物品、时间和情节线相关的有效事实；保留否定、版本和有效区间。
4. **角色认知层**：谁知道、相信、误解或隐瞒什么；区分作者真值、叙述者陈述、角色说法和待确认推断。
5. **承诺层**：未兑现伏笔、禁止提前发生的事件、因果先决条件、关系与情绪轨迹。
6. **证据层**：每条硬事实的原文 span、证据 ID、版本和相邻片段；按故事时间或叙事顺序组织，而非只按向量相似度。
7. **不确定层**：检索覆盖不足、冲突事实、歧义和未解问题。出现低置信、多跳、全局主题或心理性任务时扩大窗口。

可采用两条并行通道：

- **状态通道**：账本、图路径、约束、版本和 delta，用于“不矛盾”。
- **纹理通道**：近期原文、相关证据段、人物声音样本，用于“像这部小说”。

生成后先输出候选正文与 state delta；冲突检查通过、作者确认后再写入正式账本。自动推断不得静默晋升为事实。

### 4.2 全书长上下文应该放在哪里

长上下文不应被排除，而应做三类低频工作：

- **导入/重建**：从原稿发现账本漏项、别名、关系和跨章伏笔。
- **全局复核**：整卷/整书的主题、人物弧、节奏、视角与信息揭示检查。
- **失败兜底**：检索覆盖低、证据冲突、问题需要大量分散证据时，升级到较宽窗口或全文 verifier。

这能把未来长上下文进步变成系统升级，而不是路线威胁。

## 5. 哪些是实证，哪些仍是赌注

### 有较强实证支撑

- 标称窗口远大于稳定有效的推理窗口；字面针测试会高估生产能力。
- 长度、证据位置、干扰文本和跳数都会影响准确率；100K—1M 不是统一质量区间。
- 高频反复输入全文会增加账单、首 token 延迟和吞吐压力；缓存只能部分缓解。
- 时间、实体、关系、角色知识和事实有效期适合显式表示。
- 动态计划和按任务选择相关状态，在 7K—8K 词故事生成中有直接消融收益。
- 把事实用作检索键、把原始片段用作证据值，比纯原子事实更稳。
- 结构化图对多跳/全局综合较有价值，对简单事实和心理叙事未必有增益。

### 仍是产品赌注

- 自动抽取能否在 20—50 万字和长期改稿中保持高召回、低错误。
- schema 能否表达角色私有知识、假信念、暧昧、不可靠叙述、象征和条件性世界规则。
- context compiler 能否稳定判断“充分”，避免把漏掉的硬事实从模型视野中彻底删除。
- 账本错误是否会被确定性编译放大为全局错误。
- 结构化约束是否会牺牲人物心理、语言多样性、悬念和作者风格。
- 人机共写、分支、回滚、持续改稿场景尚缺权威书长 benchmark。

### 已被证据否定或需要改写的表述

- **“全文塞入一定比检索差”**：不成立；LOFT、NOCHA、FABLES、Long Context vs RAG 和 2026 直接事实记忆实验都有全文胜例。
- **“事实越原子化越好”**：不成立；LongMemEval 显示原子事实替代原始 round 会丢信息。
- **“图比成熟文本检索更好”**：不成立；收益取决于任务，简单事实常无优势。
- **“上下文越小越好”**：不成立；正确目标是覆盖所有必要证据并控制无关噪声。

## 6. 2—3 年技术路线风险

| 风险命题 | 2026—2029 判断 | 产品含义 |
|---|---|---|
| 更强模型让全文阅读覆盖更多日常任务 | 高概率 | “因为模型找不到，所以必须建账本”的叙事会持续贬值。 |
| token 单价、缓存和长上下文延迟继续改善 | 高概率 | 纯成本节省不能成为长期壁垒，交叉点会向更长文本移动。 |
| 全文在一次性 QA/全局分析中经常胜检索 | 中高概率 | 全文应保留为可路由路径，不要硬性禁止。 |
| 长上下文消灭可编辑故事状态的需要 | 低概率 | 窗口不会自动提供作者可改的真值、版本、来源、分支、权限、diff 和变更传播。 |
| 账本因抽取污染、维护成本或 schema 僵化而失败 | 中高风险 | 这比模型窗口变长更危险；必须量化 extraction recall、provenance 和人工修正成本。 |
| 纯账本替代原文仍可长期成立 | 高风险 | 文学含义是有损投影；原文必须保留并可回取。 |

**路线风险结论：**长上下文在 2—3 年内很可能让“账本是压缩器/检索加速器”的价值下降，却不太可能让“账本是可验证故事状态层”的价值消失。真正可能过时的是“正文压成事实后只读账本”；较抗未来的方案是“账本导航与约束＋原文按需回取＋长上下文弹性兜底”。

长期壁垒应定义为：

- 作者可编辑的 canon 与角色认知状态；
- 每条事实的证据、版本、有效区间和变更传播；
- 能解释自己为何选入某段上下文的编译器；
- 对事实、计划、推断和叙述陈述的严格分层；
- 跨模型、跨窗口大小仍能复测的书长一致性基准。

不要把壁垒定义为“比模型厂商更会截断文本”。

## 7. 最关键的内部验证

用同一模型、同一生成提示、同一输出预算做四臂实验：

| 实验臂 | 输入 |
|---|---|
| A：Full context | 可用的完整正文＋当前任务 |
| B：Raw-text RAG | 向量/BM25/时间查询召回的原文块＋近期原文 |
| C：Ledger only | 事实账本、计划和状态，不含来源原句 |
| D：Hybrid | 账本＋相关图路径＋来源 span＋近期原文；不足时自适应扩张 |

再加一个 **Oracle Hybrid**：由人工给出完整必要事实和原文证据，用来区分“检索失败”与“模型拿到证据后仍推理失败”。

### 分层条件

- 长度：25K、100K、300K、可选 1M token。
- 证据位置：开头、中部、结尾；单点与分散位置。
- 推理深度：一跳、2—4 跳、全局综合。
- 任务：事实问答、矛盾检测、续写、场景改写、人物弧检查、改稿后的状态同步。
- 叙事现象：伏笔、误解、不可靠叙述、角色私有知识、倒叙、同名/别名、世界规则例外。

### 指标

- 每万字硬矛盾数，并按 ConStory 的 19 子类拆分；
- 必要事实覆盖率、检索漏失率、证据出处正确率；
- 角色知识泄漏、过时事实使用、伏笔提前/漏兑现；
- 计划遵循、因果先决条件、叙述视角与人物声音；
- 人类作者对连贯、悬念、心理连续性、语言质感的盲评；
- 输入/输出 token、缓存命中、p50/p95 延迟、单章成本；
- 账本抽取精确率/召回率、人工修正分钟数和错误传播半径。

产品决策不应只问“D 是否平均最高”，还要找出路由边界：在哪个长度、任务和风险等级下 A、B 或 D 最划算。每次前沿模型代际更新后，用固定金标准小说重跑整套测试。

## 最终建议

保留并加强现有路线，但把技术假设改写为：

> **我们不假设长上下文永远失败。我们维护一套有证据、可编辑、可版本化的故事状态，并为每个任务编译最小充分上下文；原文随时可回取，长上下文在复杂或低置信任务中自动接管。**

该表述与当前学术证据一致，也能承受未来 1M—10M 上下文继续变强。近期研发优先级应放在：账本抽取召回、事实/计划/推断分层、角色认知状态、证据覆盖检测、自适应扩张和四臂基准，而不是继续压低平均 context token 数。
