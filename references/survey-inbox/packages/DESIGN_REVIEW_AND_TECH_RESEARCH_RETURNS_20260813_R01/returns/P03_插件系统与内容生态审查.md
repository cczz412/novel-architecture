# 故事真源引擎：插件系统与内容生态审查

审查日期：2026-08-13  
审查对象：`PLUGIN_SKILL_SYSTEM_DESIGN_R01.md`、`GENRE_RHYTHM_PACK_DESIGN_R01.md`、`BOOK_DISSECT_MENU_DESIGN_R01.md`，并参考产品总纲、真值层、创作管线、用户数据权利与安全策略。

## 结论

结论是“封闭测试有条件通过，公开插件市场暂缓”。

“索引常驻、单层按需注入、卡牌声明后才加载、插件内容不写入真值账”这条主线是对的。它比把整套写作理论塞进每次提示更节省上下文，也比暗中自动套技巧更尊重作者控制权。

当前稿仍是“可跑的内容包机制”，还不是“可公开的插件生态”。公开前有五个 P0 缺口：

1. 版本、兼容、依赖、冲突、更新、回滚没有成为完整协议；历史记录只有组件键，无法复现旧结果。
2. 15–25 字触发行同时承担人读摘要和机器路由，缺少否定条件、前置状态、近邻边界和“一个也不用”。
3. `used_components` 是模型自报，程序只检查键是否合法；它不是内容确实生效的证据，也不是安全意义上的数字签名。
4. 用户 Markdown 会进入模型上下文，关键词黑名单挡不住提示注入；内容插件不执行本地代码，仍有“语义供应链”风险。
5. 格式校验和署名追溯没有覆盖版权链、抄袭、跨模型稳定性、组合冲突、效果回归、投诉下架和维护者退出。

官方首发建议为 **28±4 个组件**，分布在 6 个任务簇，不要用 20–30 个同属“爽点”的近义组件凑数量。现有 8 个爽点组件够做机制 Alpha，不够证明产品内容已可用。用户自制 Skill 先做“私人候选配方”，公开分享等治理能力齐全后再开放。

## 一、当前设计中应保留的部分

| 已有设计 | 价值 | 保留时的修正 |
|---|---|---|
| 卡牌声明后才进入生成 | 作者明确知道本次用了什么 | 声明记录要带组件版本、内容哈希、消费层和生成批次 |
| 索引行常驻、内容层按场景加载 | 降低上下文占用，减少无关理论干扰 | 15–25 字只做人读文案，另建机器路由资料 |
| 单次只加载一个消费层 | 避免剧情、段落、分镜指导互相污染 | 安装校验必须确认该组件真的具备当前层 |
| 插件不进入真值账 | 降低内容包篡改作者事实的风险 | 节奏包会改机械参数，应单列更高能力等级 |
| 第三方书籍拆解与作者项目隔离 | 已有较好的版权与风格模仿边界 | 复用这套“隔离、去标识、只导出抽象参数”的治理方式 |

设计稿中“未被圈定的组件不会注入内容层”可以保留；“因此零误用”应删除。关键词仍会圈错组件，模型也可能从预训练知识独立产生相似技巧。可承诺的是“系统没有加载该包的文本”，不是“输出不可能出现相似方法”。

## 二、业界踩过的坑，当前还没防住

### P0：公开前必须补

| 问题 | 当前风险 | 建议 | 业界实证 |
|---|---|---|---|
| 版本兼容与可复现 | `suite.json` 有 `version`，但没有引擎范围、模型范围、依赖、冲突、迁移；生成记录只存组件键。插件升级后，旧记录会指向新内容 | 每个项目生成 `plugin.lock`；每次生成记录 `suite_id + component_key + version + layer + content_hash`；旧项目不静默升级，升级前看差异，可回滚 | VS Code 把编辑器兼容写入 `engines.vscode`，依赖另有正式字段；Obsidian 用 `minAppVersion` 和 `versions.json` 找最近兼容版。[VS Code Manifest](https://code.visualstudio.com/api/references/extension-manifest)、[Obsidian Versions](https://docs.obsidian.md/Reference/Versions) |

| “程序署名”含义过度 | 模型输出 `used_components` 后，程序仅能确认它属于用户声明集合。模型可能没遵守内容，也可能没加载插件却独立给出同类方法 | 拆成四个标签：用户声明、系统加载回执、模型自报引用、作者最终采纳；“数字签名”只用于验证包来源和完整性；效果只能用对照测试评估 | VS Code 的包签名只证明来自市场且未被篡改，不证明扩展质量或行为安全。[VS Code extension signing](https://code.visualstudio.com/updates/v1_75) |
| 提示注入与数据泄露 | 用户插件是任意 Markdown，关键词黑名单易被改写、编码、分段或间接指令绕过；若路由或生成看到作者全文，恶意包可能诱导模型泄露或改写任务 | 保持纯声明式内容包；禁止代码、脚本、远程包含、动态正文和联网；不可信内容用低优先级边界包裹；路由只拿最小化故事状态；插件无工具权、无真值写权；输出继续做规则校验 | OWASP 把 Prompt Injection 列为 LLM01。Obsidian 用 Restricted Mode 整体禁用第三方代码，但明确无法可靠实施逐插件权限隔离；Figma 则通过 Manifest 限制网络域名并声明部分权限。[OWASP LLM01](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)、[Obsidian 安全](https://obsidian.md/help/plugin-security)、[Figma Manifest](https://developers.figma.com/docs/plugins/manifest/) |
| 权利链与内容来源 | `author` 和署名只能说明谁上传，不能证明他有改编、复制、传播和再许可权；“今天写得顺”可能固化了付费课程、平台签约稿或私密正文 | 增加来源与许可清单、AI 参与状态、人工审核者、合同或授权编号、相似度报告、投诉与反通知；私人提炼默认不公开、不训练 | 中国《著作权法》第十条区分复制、信息网络传播、改编、汇编等权利；第十九条规定委托作品未明确约定时著作权归受托人；第二十九条规定未明确许可或转让的权利不得行使。[国家版权局全文](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html) |
| 路由只有正向短句 | “打脸、当众验真、亮底牌、扮猪吃虎、憋屈蓄压”高度相似；否定句、多意图、前置状态会误命中或漏命中；固定 top 5 没有拒答 | 保留短句做人读摘要；机器侧另存 `when / when_not / prerequisites / aliases / confusable_with / positive_examples / negative_examples`；两阶段召回和重排，允许 0 个 | OpenAI 建议开局可见函数少于 20，并写明何时用、何时不用；Anthropic 也建议详细写用途、限制和边界。[OpenAI 函数调用指南](https://developers.openai.com/api/docs/guides/function-calling)、[Anthropic 工具定义](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools) |

## 三、官方内容冷启动

### 1. 数量：首发 28±4 个，不是越多越好

| 阶段 | 数量 | 用途 | 是否可对外称“内容生态” |
|---|---:|---|---|
| 机制 Alpha | 现有 8 个爽点组件 | 验证安装、声明、注入、回执和禁用链路 | 否 |
| 封闭 Beta / 官方首发 | 24–32 个官方组件 | 覆盖作者最常见的规划与一致性任务 | 可以称“官方组件库”，不开放公共市场 |
| 公共市场开门线 | 40–60 个官方或认证组件 | 覆盖至少 3 种体裁，并有投诉、回滚和排序治理 | 达标后再开放 |

建议首批 28 个的分布：

| 任务簇 | 数量 | 例子 |
|---|---:|---|
| 爽点、代价与回报 | 5 | 蓄压、兑现、反转、代价升级、胜利余波 |
| 伏笔、信息与揭示 | 5 | 埋设、提醒、误导、公平揭示、兑现 |
| 冲突、因果与选择 | 5 | 目标阻力、升级、两难、后果、支线并轨 |
| 人物动机与关系 | 4 | 动机校验、关系转折、承诺变化、人物弧节点 |
| 场景与表达要求 | 4 | 场景目标、信息顺序、段落任务、分镜可视化要求；只输出要求，不代写正文 |
| 连载节奏与章尾钩子 | 5 | 章内节拍、偿还窗口、支线切换、章尾出口、连续疲劳检查 |

三套体裁节奏包可以保留同一协议，但不建议同时以“成熟默认”发布。网文包先成为稳定默认；漫剧和互动叙事在各自消费管线跑通后标为 Beta。节奏数值在设计稿中仍是经验假设，应当被视为待验证参数，不是行业标准。

### 2. 内容来源路线与成本量级

推荐组合：**签约写手和编辑原创为主，AI 做格式整理与测试变体；版权课程只做少量联名包；UGC 先私人后公开。**

下面是 24–32 个组件、每个至少三层内容的产品预算，不是市场报价。不同路线的工时不同，统一用短约专家 1,000–3,000 元/人日做内部情景。国家统计局在 2026-05-15 发布的 2025 统计年度工资数据可作劳务底盘；短约网文专家因稀缺、返修与权利交付要加溢价。[国家统计局 2025 年工资数据](https://www.stats.gov.cn/sj/zxfb/202605/t20260515_1963707.html)

| 路线 | 24–32 个组件预算 | 周期 | 质量判断 | 主要法律风险 | 建议用途 |
|---|---:|---:|---|---|---|
| 签约网文写手＋统一编辑原创 | **4万–19万元** | 6–10 周 | 最稳；可按产品任务抽象 | 付钱不等于自动取得版权；委托合同若没写清，权利可能仍归作者 | 官方首发主线 |
| 取得明确内容许可后改编课程 | **5万–45万元/一个来源包** | 8–16 周 | 取决于课程结构与可拆分程度 | 单纯购买课程不当然取得插件制作和分发所需权利；讲师、机构、出版社可能分持权利 | 少量有品牌价值的联名包 |
| AI 初稿＋专家实质审改 | **2万–8万元** | 4–8 周 | 便宜的是模型调用，难点仍是专业验收 | 输入来源不清、输出近似他作、人类创作贡献不足、适用时的标识义务 | 扩写测试例、统一格式，不做官方权威来源 |
| 社区 UGC 有奖征集 | 内容现金 **2万–12万元**；公共市场治理另做工程估算 | 3 个月以上 | 供给多，但噪声和重复会快速上升 | 上传者无权授权、抄课程或签约稿、隐私泄露、投诉延迟 | 治理完成后扩展长尾 |

预算算式：签约原创按 0.75–1.5 人日/件，人工为 1.8万–14.4万元，再加总编、法务模板与评测 2万–4万元，取整为 4万–19万元。AI 路线按专家 0.2–0.4 日/件、编辑 0.15–0.25 日/件，人工约 0.84万–6.24万元，再加模型调用和统一复核，取整为 2万–8万元。UGC 假设验收奖 500–1,500 元/件，奖金为 1.2万–4.8万元；审核 0.35–0.75 日/件，人工约 0.84万–7.2万元，合计取整为 2万–12万元。公共市场的上传、审核、举报、下架、申诉和版本撤回，另按 20–60 个产品、工程、法务与运营人日做内部估算，不计入内容现金成本。

课程路线把许可费写成敏感性情景：`R = 3万 / 10万 / 30万元/来源包`，不是市场报价；改编、编辑、权利核查和固定评测约 2万–15万元，因此规划区间为 5万–45万元。知名作者、独家或长期权利另议。

国家版权局《使用文字作品支付报酬办法》于 2014-09-29 发布、2014-11-01 施行；在无约定或约定不明时，纸介质原创作品基本稿酬为 80–300 元/千字，数字和网络环境可以参照。它不是插件许可费的法定最低价，也不能代表含改编、升级、分发等权利的完整许可价格。[官方付酬办法](https://www.ncac.gov.cn/xxfb/tzgg/201409/t20140929_50352.html)

#### 合同和来源清单

签约写手至少写清：逐件交付、原创保证、现有平台合同冲突、财产权归属或许可范围、允许拆层与升级、商业分发、终端调用、署名方式、原始创作记录、侵权处理和下架配合。

课程联名包至少单列：数字复制、改编、整理、汇编、通过产品向公众提供、商业化、更新修改、终端安装所需再许可、地域、期限、独家性、课程名和讲师名宣传、第三方 AI 处理安排、上游素材保证、合同终止后的已安装副本。单纯购买课程、会员或课件载体，不当然取得复制、改编、汇编或通过产品向公众传播的权利；是否允许再许可及送入第三方 AI，还要分别看明确合同、AI 服务条款、保密和数据约定。只写“购买课程版权”不够。

《著作权法》于 2020 年修订、2021-06-01 施行，国家版权局页面发布于 2021-03-09。第十条、第十九条、第二十六条和第二十九条共同说明，权利种类、地域、期限和委托成果归属需要写进合同，未明确许可或转让的权利不能自行扩张。[国家版权局全文](https://www.ncac.gov.cn/xxfb/flfg/flfg_532/202103/t20210309_50530.html)

AI 参与内容要保存模型、版本、输入来源、原始输出、人工修改与审核者。《人工智能生成合成内容标识办法》于 2025-03-14 发布，自 2025-09-01 施行。对落入该办法及上位规则适用范围、并满足相应触发条件的生成服务和传播平台，分别规定显式标识、文件元数据标识、平台核验及用户声明义务；内部 AI 辅助制作的插件是否以及如何展示，要结合产品是否直接向公众提供生成服务、内容形态和传播方式判断。[国家网信办通知](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)

UGC 收到含初步证据和权利人真实身份的有效通知后，应按证据与服务类型及时采取删除、屏蔽、断开链接等必要措施，并向上传者转送；上传者可按规则提交不侵权书面说明。产品要把通知、转送、必要措施、书面说明、申诉和日志保全写成实际流程，而不是“收到任何举报就永久下架”。[北京市司法局对《民法典》第 1195、1197 条的释法](https://sfj.beijing.gov.cn/sfj/sfdt/jssp/436282513/index.html)、[《信息网络传播权保护条例》官方解读](https://www.mct.gov.cn/whzx/bnsj/zcfgs_bnsj/201111/t20111128_821526.html)

## 四、渐进披露与索引路由审查

### 1. 风险判断

没有可信的行业数字能直接回答“15–25 个汉字能有多少准确率”。公开研究的语言、候选规模、工具文档长度、任务难度和指标不同，不能把某个基准成绩平移到中文写作组件。

当前风险可这样判断：

- 8 个组件取 top 5，相当于每次暴露 62.5% 的库，只能证明链路跑通，不能证明圈定准确。
- 20–30 个高度相似的爽点组件全部靠短句区分，误命中和漏命中风险高。
- 关键词匹配会被否定、同义词、隐含前置状态和多意图击穿。
- 主模型复挑不是可靠兜底：已圈定组件拿到 50 字内容，漏掉的组件只有短索引行，信息不对称会继续偏向已圈定项。

例子：“这章先不要释放压力，继续让主角憋着。”关键词可能同时命中“释放压力”和“憋屈蓄压”；“主角当众拿出证据证明身份”可能同时命中当众验真、亮底牌、打脸和扮猪吃虎。正确答案取决于前文是否藏拙、当前目标是证明事实还是扭转群体态度、是否存在被反转的对手。

### 2. 可参考的业界数据

| 证据 | 数据 | 能说明什么 | 不能说明什么 |
|---|---|---|---|
| [OpenAI 函数调用指南](https://developers.openai.com/api/docs/guides/function-calling) | 建议一轮开始时可见函数少于 20；写清何时用、何时不用，并对大工具面用延迟搜索 | 20–30 个常驻候选已经需要实测；完整选择资料不能只有口号 | 这是软建议，不是准确率承诺 |
| [Anthropic Advanced Tool Use](https://www.anthropic.com/engineering/advanced-tool-use) | 58 个工具定义约占 55K tokens；该文配置按需发现 3–5 个。其内部 MCP 综合评测中，Opus 4 从 49% 到 74%，Opus 4.5 从 79.5% 到 88.1% | 大库中先检索再展开可节省上下文，并提高该内部综合评测成绩 | 数据集与指标未公开，也没有把选择、参数和执行拆开；不可平移到本产品 |
| [ToolRet，ACL 2025](https://aclanthology.org/2025.findings-acl.1258/) | 7.6k 任务、43k 工具；最佳通用检索模型平均 nDCG@10 仅 33.83 | 工具检索不是普通关键词检索，查询与目标文档词面重合低时尤其难 | 候选规模远大于 30，且是英文异构工具 |
| [When2Call，NAACL 2025](https://aclanthology.org/2025.naacl-long.174/) | 在论文的 LLM-as-judge 设置中，GPT-4o 的 When2Call macro-F1 为 61.3、无工具样本工具幻觉率为 26%；同表 BFCL v2 Live AST/Irrelevance 的 prompting 分数为 79.8%/83.8% | “会调用”与“知道何时不该调用”必须分开测；系统要允许零组件 | 每类取 100 个代表样本，且不是原生函数调用评测；目标也不是写作技巧相关性 |

业界数据支持架构方向，不给本产品现成准确率。你们自己的中文状态集才是发布依据。

### 3. 推荐的路由资料与流程

新 Schema 用 `display_trigger` 承接只供作者阅读的短句，并把旧 `trigger` 作为读取时的兼容别名。安装器生成新的规范化副本和新哈希，原始包及原哈希留在版本记录中；不能在字节发生变化后沿用旧哈希。另增不直接塞给主生成模型的机器资料：

```yaml
routing_profile:
  goals: [释放长期压抑, 公开扭转群体判断]
  when: [对头公开挑衅, 主角已有可展示的反证或实力]
  when_not: [本章目标是继续蓄压, 只有身份说明而无对抗对象]
  prerequisites: [此前存在误判或压制]
  aliases: [公开翻盘, 让质疑者改口]
  confusable_with:
    technique.爽点.当众验真: 验真重在证明事实，打脸重在让压制者付出认知或地位代价
    technique.爽点.亮底牌: 亮底牌可以无人受挫，打脸必须有被反转的对象
  positive_examples: [...]
  negative_examples: [...]
```

路由链建议：

1. 硬过滤：本书启用、当前消费层存在、版本兼容、题材适用、无硬冲突。
2. 意图整理：从题面和最小故事状态提取目标、否定、阶段和多意图。
3. 混合召回：中文字词/BM25 与中文向量并行，在隐藏路由资料上取 8–12 个。
4. 等信息重排：候选都用同规格字段；用独立 `none` 分类器或校准后的绝对拒答阈值输出 0–5 个，阈值在未参与调参的确认集上冻结。
5. 相似项去重、多意图保全：一个意图不让五张近义卡挤满；多意图保留每个子目标的候选。
6. 作者确认卡牌后，才加载对应内容层。
7. 记录声明、加载、模型自报与作者采纳四段数据。

### 4. 发布前评测合同

V0 建议做 **1,200–2,300 个中文“完整创作状态”**，而不是孤立关键词。内容包含题面、故事状态、题材、消费层、已启用组件及版本；正确答案允许多组件、等价组件和零组件。若同一状态标注多个组件，它只计一个唯一状态；同一故事状态及其改写必须按组进入同一数据分区，避免训练、调参和确认集之间泄漏。

样本应覆盖：每组件 30–50 个正例标注、10–15 个近邻硬负例标注、至少 300 个无组件/OOD 状态、至少 100 个多组件状态，以及否定句、口语、省略、隐含状态、新插件和同名 UGC。8、20、30、60 指同一批查询上的嵌套“本书启用池”规模，不能拿四套无关题目横比。

建议内部过门线，不是行业标准：

- 在所有“必须或明显有帮助”的组件—状态标注上计算 micro Recall@5，点估计 ≥95%；95% 置信区间用完整故事状态做 cluster bootstrap，下界 ≥90%；同时逐组件报告，不用小样本逐组件置信下界作硬闸门；
- 仅对金标“必须组件”数量不超过 5 的多组件状态计算 Complete@5，目标 ≥90%；超过 5 个时单独报告覆盖率；
- 无组件假激活定义为 `P(输出集合非空 | null/OOD 状态)`；点估计 ≤3%，并同时报告 95% 置信上界和按线上无组件基率计算的精确率；
- 有任一反向或硬冲突组件进入 top 5 的状态占比 ≤1%；
- 同一批查询、嵌套候选池从 8 扩到 30 时，配对 Recall@5 下降不超过 3 个百分点；
- 用经多人标注的 oracle 等价组件集合、路由组件和无组件分别生成要求，随机盲序、处理平局并跨多个随机种子复测；预注册非劣效界值，要求“路由减 oracle”的作者偏好差 95% 置信下界高于 −5 个百分点，并报告标注一致性。

线上监控看作者手动补加率、候选一键清空率、重出题率、声明到采纳的转化、立即回退、每组件异常曝光和低置信率。行为信号只做代理指标，每周仍需人工抽样复核。

## 五、用户自制插件的质量护栏

“格式机械校验＋署名可追溯”只够私人草稿，不够公开分发。建议分成四道门。

### 门 1：包和版本

- Schema、唯一 ID、语义版本、内容哈希、大小与层级限制；
- 引擎和模型兼容范围、最近验证时间；
- 依赖、冲突、替代、弃用、迁移；
- 禁止代码、脚本、远程正文、HTML 执行和联网；
- 包的发布者数字签名与撤销状态。

### 门 2：权利与安全

- `creator_type`：人类原创、AI 辅助、UGC、授权改编；
- 来源、许可证、合同编号、允许的使用范围、人工审核者；
- 相似度、独特例子和命名体系检查；
- 提示注入、隐私泄露、绕过真值账、诱导风格模仿测试；
- 举报、临时下架、通知上传者、反通知、申诉、重复侵权者处理。

### 门 3：语义质量

- 每组件交付正例、硬负例、零使用例和组合冲突例；
- 三层内容表达同一方法，不互相打架；
- 不新增故事事实，不代写正文，不把风格模仿包装成技巧；
- 在声明的模型和上下文结构上跑回归；
- 新模型或路由器上线时状态先变成“待复验”，不是默认兼容。

### 门 4：生态治理

- 发布通道：私人草稿 → 沙盒测试 → 已验证 → 公开 → 官方精选；
- 官方、认证、社区未审三档清晰标识；未审内容不自动进入本书候选；
- 排序权重看复用、保留、低回退、低投诉和维护，不以安装或五星为主；
- 限制低信誉作者批量提交近义卡，提供合并建议；
- 支持所有权转让、弃用、替代、锁版、撤回和项目影响清单。

### “今天写得顺”如何固化

不要一键变成公开 Skill。推荐流程：

1. 从本次写作行为提取“候选配方”，默认仅自己可见，并去除人物名、情节细节和正文片段。
2. 让作者回答“哪一步起作用、在什么条件下不该用”，补出正反条件。
3. 找到至少 3 次独立成功实例；再跑至少 6 个测试，其中包含近邻负例、不同题材和零使用场景。
4. 生成来源与 AI 参与清单，作者确认权利和隐私。
5. 先进入沙盒或邀请测试；数据合格后再申请公开。

这能保留“当场固化灵感”的轻快体验，同时避免把一次偶然顺手过拟合成公共规则。

## 七、90 天落地顺序与发布闸门

| 时间 | 工作 | 过门条件 |
|---|---|---|
| 0–30 天 | 补 Manifest、项目锁版、内容哈希、能力声明；重命名程序署名；建立隐藏路由资料；准备 1,200–2,300 个状态的数据框架 | 任一旧项目可复现；插件无代码、联网和真值写权；零组件可返回 |
| 31–60 天 | 2–4 名网文写手＋1 名统一编辑生产 24–32 个官方组件；跑关键词、BM25、向量、混合召回和重排对照 | 路由达到内部过门线；每组件通过权利、安全、语义和组合测试 |
| 61–90 天 | 20–50 名作者封闭 Beta；私有“候选 Skill”上线；组件和节奏包按版本灰度 | 手动补加、清空、回退和投诉在可接受区间；模型升级可回滚 |
| 公共市场前 | 上线举报、反通知、撤回、所有权转让、排序防刷、作者收益规则；累计 40–60 个已验证组件 | 审核与申诉能实际演练；被撤回版本的项目影响可列出；未审 UGC 不会自动生效 |

### 最终决策

- **现有 8 组件：**继续做机制 Alpha，标签写“实验内容”，不拿它证明路由质量。
- **官方首发：**24–32 个原创组件，预算优先给签约写手、统一编辑和评测，规划 **4万–19万元**内容预算较合理。
- **课程版权：**不做主供给，只谈一个非独家、限期、权项逐条明确的联名试点。
- **AI 内容：**做整理、正反例扩写和一致性检查，专家对最终规则实质改写并签字验收。
- **社区 UGC：**先私人保存，再邀请测试；公共市场治理齐全后开放。
- **节奏包：**官方或认证通道先行，版本锁定和能力确认比普通知识卡更严格。

这套系统最有价值的差异不是“插件很多”，而是作者能看见、能声明、能撤回、能复现每次外来写作知识如何进入任务。把这条审计链做实，比抢着开市场更重要。
