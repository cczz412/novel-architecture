# 调查结论（截至 2026 年 8 月 13 日）

最关键的发现是：职业网文作者的工作流不是“先写完整大纲—连续码字—统一修改”的流水线，而是一个滚动循环：

> 脑内构思/查资料 → 写当天正文 → 发布 → 看反馈 → 改后续方向 → 必要时补前文

公开资料可以支持工作流分型，却不能可靠回答三类问题：构思/码字/修改的行业平均比例、细纲/粗纲/无纲的总体占比、作者对 AI 工具的支付比例。下面凡出现数字，均注明它是代表性调查、定向样本，还是单个作者案例。

证据标记：

- **【多源印证】**：至少两个独立作者或不同类型来源方向一致；不等于统计占比。
- **【单一来源】**：一个作者、一本书或一篇社区帖，只能证明“这种做法存在”。
- **【平台规则】**：证明允许什么、工具能做什么，不证明作者实际采用率。
- **【数据空白】**：没有找到方法透明、可外推到起点/番茄签约作者的调查。

## 1. 一天怎么写

### 真实日程不是一种模板

| 工作流                       | 具名案例                                                     | 证据判断                         |
| ---------------------------- | ------------------------------------------------------------ | -------------------------------- |
| 清晨集中写，晚上另做次日规划 | 起点作者鹤守月满池凌晨约4点开始，4小时完成8000字，白天上班；晚饭后规划次日大纲。这种状态持续四个多月。[新民周刊/上观调查](https://www.jfdaily.com/wx/detail.do?id=1055014) | 【单一但非常具体】正文与规划分时 |
| 上午查资料，下午至晚间写     | 《玄鉴仙族》作者季越人上午查资料、构思，下午写到21点，目标约4000字，没有周末。[同一调查](https://www.jfdaily.com/wx/detail.do?id=1055014) | 【单一】考据型、全日工作         |
| 晚间一次写完                 | 爱潜水的乌贼早年兼职时19:30左右开始，一口气写约6000字，到凌晨1点多。[作者访谈](https://culture.cnjiwang.com/whrx/201706/2432995.html) | 【单一】约5个多小时              |
| 低字数也需要长时间心流       | 狐尾的笔每天写四五小时，产出四千多字；大情节预先想好，大量过渡和剧情点边写边想。[北大团队长访谈](https://www.jfdaily.com/wx/detail.do?id=936137) | 【单一但高质量一手材料】         |
| 极快熟手                     | 番茄作者沙漠里的雕称每小时约3000字，通常19—20点开始，4000字一个多小时写完。[番茄作者访谈转载](https://www.sohu.com/a/560619082_121119379) | 【单一异常快值】不能当平均       |
| 多段式写作                   | 千紫缤纷把一天拆成早、中、晚三段，每段约3000字；认为连续长时间写会让大脑超负荷。[中国作家网访谈](https://www.chinawriter.com.cn/n1/2018/0104/c405057-29744571.html) | 【单一】证明分段工作真实存在     |
| 整体工作时间远大于纯码字     | 《十日终焉》作者杀虫队队员称连载两年全年无休，每天坐在电脑前6—8小时。[2026年现场分享](https://m.mp.oeeee.com/a/BAAFRD0000202603151539105.html) | 【单一最新来源】未拆分具体环节   |

**【多源印证】** 日更同为4000—6000字，具名案例中的纯写作时间从一个多小时到五个多小时，若计入资料、构思和反馈处理，则可能占掉整个工作日。字数相近不代表劳动量相近。

**【多源印证】** 集中一次写完和分段完成都存在。兼职作者更容易把正文挤在清晨或深夜；考据型、严密世界观作者会把资料准备和正文拆开；出差时也会用手机写一段、回住处再续写。[爱潜水的乌贼谈移动写作](https://www.chinawriter.com.cn/n1/2020/0825/c405057-31835114.html)

**【数据空白】** 没有可信证据支持“构思20%—码字70%—修改10%”之类的行业比例。访谈往往也不单列修改时间，因为修改常发生在落字过程中，或变成后续章节的补洞。

产品上更适合记录“资料/构思、正文、校验、反馈处理”四种活动，而不是只显示码字时长和字数。

## 2. 大纲习惯的真实分布

### 不能给细纲派/粗纲派/无纲派百分比

没有找到以起点、番茄签约日更作者为抽样框的公开调查。

酒徒曾称，若询问写作十五年以上的作者，七成以上可能会说不需要大纲；他自己紧接着提醒，这是成功老作者的幸存者经验，新人不应照搬。[酒徒《如何写大纲》](https://www.chinawriter.com.cn/n1/2021/1015/c441011-32254266.html) 因此这个“七成”不能用作行业比例。

比较可靠的结论是：三类工作法都真实存在，且经常混合使用。

| 类型            | 实际颗粒度                                                   | 痛点                                                         |
| --------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 结构/细纲派     | 爱潜水的乌贼曾为《奥术神座》写三四万字大纲并纳入设定；番茄官方教程则把当天细纲解释为“今天写哪些剧情”，说明“细纲”可以从全书结构一直细到单日事件。[乌贼访谈](https://culture.cnjiwang.com/whrx/201706/2432995.html)、[番茄官方教程](https://notice.fanqienovel.com/docs/9476/gousi) | 维护成本高；太细会束缚灵感，提前消耗“已经写过一遍”的兴奋感   |
| 粗纲/滚动派     | 搬砖圣手写到约10万字时，会想好20—30万字方向；跳舞不写纸面纲，但脑内始终照亮前方约10万字；狐尾的笔预先固定大情节点，过渡边写边想。[搬砖圣手访谈](https://news.chenggua.com/detail/34724.html)、[跳舞访谈](https://www.jszjw.com/wap/online/20231009/1696841441313.shtml)、[狐尾的笔访谈](https://www.jfdaily.com/wx/detail.do?id=936137) | 中远期方向清楚，眼前章与章之间仍会卡；容易在过渡、人设和节奏处偏航 |
| 无书面纲/即兴派 | 三九音域偏自由发挥，并承认代价是思路卡壳；沙漠里的雕不开书面纲，但开书前会在脑内想一两周。[三九音域访谈](https://www.chinawriter.com.cn/n1/2024/0605/c404024-40250642.html)、[沙漠里的雕访谈](https://www.sohu.com/a/560619082_121119379) | 创作活力强，但卡文、重复情节和长程一致性风险更高             |

这里最容易误判的是“无纲派”：很多作者只是**没有纸面大纲**，并非没有前视计划。

### 正文偏离大纲后怎么做

**【多源印证】** 常见判断逻辑是：

1. 新方向是否比原纲更好；
2. 若更好，保留正文，重写后续纲；
3. 若只是写歪，尽量在后文拉回；
4. 已发布内容牵连过大时，不强行回滚。

狐尾的笔曾在写到一半后发现三四天前的情节不对，但已发布，只能尝试从配角入手修补；读者的好点子也曾让他重新框定整条后续大纲。[访谈原文](https://www.jfdaily.com/wx/detail.do?id=936137) 跳舞写到约20万字发现重复，于是临时加入新人物和新主线。[跳舞访谈](https://www.jszjw.com/wap/online/20231009/1696841441313.shtml) 起点社区版主流水给出的实务规则也是“好偏离就改后续纲，坏偏离才修正文”。[《再谈大纲设计》](https://www.qidianclub.com/threads/832/)

所以，大纲更像可更新导航，不是必须严格履约的合同。

## 3. 卡文时真实自救手段“排行”

没有全行业排行。我从12位具名作者、明确谈到卡文处理方式的访谈做了一个**定向样本计数**；一位作者可同时使用多种方法，采访问题也不统一，数字只能表示公开证据的出现次数。

| 样本内出现 | 做法                             | 作者实例                                                     |
| ---------- | -------------------------------- | ------------------------------------------------------------ |
| 5/12       | 暂停、睡觉、散步、换环境         | 季越人会洗澡、听音乐、喝咖啡或出门走走；叶非夜认为继续困在房间会越纠结越卡；天香瞳则明确主张实在写不出就停。[季越人访谈](https://www.chinawriter.com.cn/n1/2024/0801/c404024-40290360.html)、[叶非夜访谈](https://www.qidianclub.com/threads/488/)、[天香瞳访谈](https://www.sohu.com/a/522139076_121119379) |
| 5/12       | 原地硬想、先硬写、慢慢磨         | 季越人恢复后仍会硬着头皮交日更；宋象白先强迫自己写，实在不行才睡；打眼严重卡文时会在电脑前坐十几个小时死磕。[宋象白访谈](https://www.sohu.com/a/523249941_121119379)、[打眼访谈](https://www.wccdaily.com.cn/wapepaper/html/20220117/166509.html) |

| 4/12       | 找编辑、同行、作者伴侣或读者聊   | 出走八万里沿用编剧式集体讨论；宋象白会找同为作者的丈夫志鸟村逐章讨论；雪梨炖茶找责编定位问题。[出走八万里访谈](https://www.ifanr.com/1534112)、[宋象白访谈](https://www.sohu.com/a/523249941_121119379) |
| 2/12       | 跳过当前段，先写后面的高潮或情节 | 回到原初会慢慢磨过去或直接跳到下一段；小刀锋利主张已想清的第四段可以先写，不必被第二段卡死。[回到原初访谈](https://write.qq.com/portal/content/19065189901116801?feedType=1)、[小刀锋利访谈](https://www.qidianclub.com/threads/493/) |
| 1/12       | 回看自己前文，定位真正断点       | 胡说会回顾前文复盘；更早的两位作者访谈也出现“重读前文”和“读好书/看影视”两种策略。[胡说访谈](https://qnzj.cyol.com/html/2019-08/13/nw.D110000qnzjb_20190813_6-01.htm)、[中国作家网双人访谈](https://www.chinawriter.com.cn/n1/2016/0906/c404024-28695039.html) |

结论不是“哪招第一”，而是作者存在互相冲突的工作偏好：有人靠停，有人认为一停思路就断；同一作者也可能先散步，临近更新时间再硬写。

产品不宜只给“继续硬写”一个按钮。至少应并列：

- 暂停并保留现场；
- 回看前文，找出逻辑断点；
- 找人或 AI 生成多个方向供选择；
- 跳写后段，并自动留下回填标记。

## 4. 真实工具组合

2018年艾瑞对1781名阅文系签约作者的调查显示：Word/WPS 54.3%、作者助手42.17%、各类码字软件35.04%、其他4.44%。合计超过100%，说明是多选；也直接证明作者会混用工具。该数据较旧且只覆盖阅文系，只适合作历史参照。[《中国网络文学作者报告》PDF](https://s27.jiuye.net/p2/jiuye.net/List/Trade/Url/4b90f7ea38b5735ed8fbfb56e4cf7ecc.pdf)

公开的一手案例更能解释“为什么组合”：

- **平台助手＋专业资料**：季越人上午读祭祀、社会秩序典籍，正文再通过起点作家助手发布。资料真实性和发布管理是两套任务。[采访](https://www.chinawriter.com.cn/n1/2024/0801/c404024-40290360.html)
- **手机备忘录＋长大纲＋线下资料＋读者反馈**：胡说用手机建立素材库，另写几万字人物小传和故事纲，还去图书馆、博物馆查史料。[采访](https://qnzj.cyol.com/html/2019-08/13/nw.D110000qnzjb_20190813_6-01.htm)
- **文字大纲＋多张Excel**：管平潮分别管理世界观、人设、势力、技能、法宝、地理等，用来维持百万字长篇一致性。[作者自述](https://www.zjzx.gov.cn/wyfc/wyzf/content_71284)
- **电脑码字＋音乐＋作者伴侣互审＋编辑沟通**：宋象白与志鸟村逐章互看、卡文时讨论；音乐负责进入氛围，编辑负责职业判断。[访谈](https://www.sohu.com/a/523249941_121119379)
- **作家助手＋外部作品＋责编讨论**：雪梨炖茶用平台承载稿件，同时读外部理论和同类作品、深夜找责编拆问题。[播客](https://www.xiaoyuzhoufm.com/episode/68d68397522b40626c692bcf)

2026年的平台工具已经覆盖不少中枢能力：阅文作家助手含多端同步、大纲、全文检索、纠错、伏笔/设定查询、发布和数据；番茄助手含草稿同步、定时发布、错字检测、码字日历、收益与读者数据。[阅文官方产品页](https://www.yuewen.com/app/?type=appzj)、[番茄助手App Store](https://apps.apple.com/cn/app/番茄作家助手/id1560557075)

仍然无法由一个工具包办的原因是：

- 灵感发生在手机、聊天、视频和生活现场；
- 专业资料的可信度来自书籍、档案和实地调查；
- 表格更适合多维设定，正文编辑器更适合线性叙事；
- 编辑、同行和读者提供的是判断，不是存储功能；
- 发布、稿酬、流量数据天然锁在平台。

没有可靠证据表明Notion、Obsidian或XMind已成为起点/番茄职业作者主流，不能因为推荐文多就写进“真实工具链分布”。

## 5. 修改、回头看与“吃书”

**【数据空白】** 没有代表性“作者每周回改几次”的调查。多源材料显示，回改行为呈明显的成本分层：

### 小错：直接改原章

起点签约书《重生78，从知青返城开始》的作者称，读者指出的父亲名字和部分剧情疏漏已经在前文修改。[作者上架感言](https://www.qidian.com/chapter/1049871357/921434052/) 另一本起点作品也在读者提醒后修改并公开致谢。[章节说明](https://read.qidian.com/chapter/1049029006/904126844)

这是“评论区兼任QA”的真实用法，但两个案例不能推算频率。

### 设定矛盾：复核资料、发补丁、同步回改

《面壁者，但元婴期》的作者被读者质疑境界尺度后，重新查原文，发布带参考文献的设定补丁，并修改前文相关表述。[设定补丁](https://www.qidian.com/chapter/1044013306/862352676/)

### 结构性偏航：少回滚，更多向后修

狐尾的笔直言，几天前的情节已经发布后很难回头，只能从配角或后续剧情拉回。[长访谈](https://www.jfdaily.com/wx/detail.do?id=936137) 《诡秘：烈火与愚者之途》的作者也称，约70章时意识到问题，但剧情骨架已经形成，大改会造成整体崩塌，因此没有全面回滚。[作者上架感言](https://www.qidian.com/chapter/1042795616/845551607/)

《剑道余烬》则采取中间方案：重修部分前文，停约一周，重新准备剧情、细纲和存稿。[卷末复盘](https://www.qidian.com/chapter/1039487345/807830005/)

### 全文重置：存在，但属于极端值

《全民求生：我，光环缔造者》曾公告先改1—14章，之后每天整改3—5章，预计用一个月重置前文。[整改公告](https://www.qidian.com/chapter/1037396564/874198750/)

因此，“吃书被抓”后的真实处理链更接近：

> 读者指出 → 作者复核 → 小错直接改 → 设定冲突发补丁 → 结构冲突尽量后文圆 → 无法圆时停更重做细纲 → 全文重置仅作最后手段

产品需要的不只是“发现矛盾”，还应给出：

- 原句和读者评论的定位；
- 受影响章节/角色/伏笔清单；
- “改旧章”与“后文解释”两条修复路线；
- 对读者可见的修订说明；
- 修改前版本与回滚能力。

## 6. 2026年作者对AI的真实态度

### 使用率信号：已经广泛接触，但“使用AI”不等于“AI写正文”

2025年一项质性研究访谈了18名签约作者，涵盖起点、番茄、晋江等平台；样本通过目的性和滚雪球方式招募，不能外推。在这个小样本中，17/18至少偶尔使用过AI，9/18经常使用；约九成用过AI起名，多数用它查资料，也有人用于校对、大纲压缩和前文梳理。[论文PDF](https://xwcbpl.whu.edu.cn/e/public/DownFile/?classid=9&id=506)

媒体转述阅文数据称，2025年75%的作者已常态使用AI工具、AI功能周使用率接近70%；这是平台口径，未公开抽样和“使用”的任务定义，只能视为普及信号。[相关行业调查](https://m.thepaper.cn/newsDetail_forward_31989458)

### 多源出现的使用边界

| 相对接受                       | 主动回避或高度争议             |
| ------------------------------ | ------------------------------ |
| 查资料、生成检索词             | 让AI决定主题、核心人设与世界观 |
| 人名、地名、功法名备选         | 完整细纲、人物弧光和长程伏笔   |
| 错字、病句、事实检查           | 连续扩写叙事段落或整章         |
| 回顾配角经历、状态摘要         | 直接复制AI输出发布             |
| 压缩/整理作者已有的大纲        | 用AI模仿具体作者文风           |
| 卡文时给多个方向，但由作者选择 | 把情节判断权和最终决策交给AI   |

2026年采访中，大神作者毛志慧把AI限定在前文总结、检索和命名；世界架构、主线和逐章细纲由自己完成。他认为长文本超过约20万字后容易出现逻辑错误，战斗建议也偏旧套路。[《AI搅浑网文圈》](https://www.chinanews.com/cul/2026/03-09/10584016.shtml) 董江波的边界也类似：只做个别段落润色或校对，不让AI直接写作，理由是长文逻辑和作者风格不匹配。[中新经纬访谈](https://www.jwview.com/jingwei/html/m/03-24/664243.shtml)

这与18人访谈相互印证：作者并不只是担心“AI味”，更担心创作主体性、陈旧套路、长程一致性、版权和平台处罚。

### 平台规则正在反过来改变作者行为

- **晋江官方规则**允许校对级文字辅助、名称/人设等要素级辅助和粗纲级辅助；不允许描写、叙事或细纲由AI完成。作者还需保存AI使用前原稿、对话和输出，以备申诉。[晋江原创写作规范](https://bbs.jjwxc.net/showmsg.php?board=17&id=1575959)
- **番茄不是全面禁AI**，而是打击AI粗制滥造和批量占流量。2026年6月官方公布拒签低质书104,034本、处置低质违规书45,424本、处置账号6,627个；这些数字包含AI粗制滥造、格式混乱、结构失常、空洞水文等多类问题，不能全部算成AI账号。[番茄官方公示](https://fanqienovel.com/writer/zone/article/7657128820209631256)
- 2026年调查已经出现作者主动“去AI味”、保留写作记录、自测AI率，甚至因为怕误判而回避常见措辞的行为。[经济观察报调查](https://www.eeo.com.cn/2026/0704/942600.shtml)

这意味着产品除了AI能力，还必须提供“人类创作过程的可证明性”。

### 付费意愿：目前不可量化

没有找到2024—2026年针对起点/番茄签约作者、披露样本和方法的支付意愿调查。

能确认的只有：

- 一名作者在免费额度尚未耗尽时，因约2万字测试效果尚可转成付费用户；这是单例。[i黑马/字母榜报道](https://www.iheima.com/article-376272.html)
- 市场上已有月费、年费工具和真实订阅收入；厂商自报用户量、留存或收入，只能证明有人付费，不能推导作者群体的接受价格。
- 起点、番茄把不少检索、纠错、大纲和AI能力放进免费平台助手，也会压低通用功能的独立付费空间。

因此不能据现有材料声称“作者愿意支付49/99/199元”或“某比例愿付费”。更可靠的验证方式是让真实签约作者带正在连载的书试用2—4周，观察：

- 哪种任务反复使用；
- 免费转付费率；
- 第二个月续费率；
- 每次避免矛盾、找回伏笔或节省时间的可验证价值。

## 对产品设计的直接校准

1. **“AI不直接代写正文，主要做导航、检索和检查”方向得到较强支持。** 这恰好落在作者较能接受、平台风险较低的区域。
2. **大纲必须允许缺省、分层和滚动更新。** 不要强迫作者一次填写全书纲。更合适的是“全书方向—当前卷—未来10万字—下一章提示”四层均可选填。
3. **卡文入口应给多条互斥路线。** 暂停、硬写、补输入、找人聊、跳写都真实存在，不应让系统替作者选唯一正确答案。
4. **“计划了但尚未写进正文”的事实，不应默认已经发生。** 作者会在正文推进时频繁改路。建议至少分成“设想、计划、已写、已发布、后文确认”五种状态；只有后三类能进入硬事实检查。
5. **矛盾检查要显示修复半径。** 作者最怕的不是发现错误，而是不知道改旧章会牵连多少已发布内容。系统应同时提供“最小回改”和“后文圆回”方案。
6. **保留可导出的创作证据。** 版本历史、键入时间、AI调用记录、采用/拒绝的建议、发布前原稿，都可能成为作者应对平台误判的自证材料。
7. **收费不要押在普通续写上。** 更有差异化的候选付费价值是百万字跨章检索、人物状态回顾、伏笔追踪、修订影响分析和自证包；但这仍是从痛点推导的产品假设，不是已经得到支付数据验证的结论。
