# SI-009 消化｜现有结构要大改、中改还是微改

身份：**交叉消化，仍是候选先验。** 不改 R10、不改 schema、不改代码。对照对象：十份回包开头结论＋现有大纲 R02／存储 R02／人物账 R02／灵感账 R02。和 CZ 最新口令、已拍纪律冲突时，那些赢。

原包：[00_READ_ME_FIRST.md](00_READ_ME_FIRST.md)

## 一句话

**中改，不是大改。** 十份回包没有一份要推倒「五层篮子＋事实／计划分账＋人物影子＋灵感分家」。它们在给现有骨架当靠山，同时指出：场里还在手填人名地名、地点没有户口、知情／规则还没按已拍方向落成硬账。

说白了：章纲这棵树不用砍；要补的是「谁住哪」和「指针代替抄写」。

---

## 现有骨架：撑得住

这些已经对上十份里的公开做法，建议当继续有效：

- 书核→卷→章槽→场→拍
- 计划事件和事实句分账、分编号
- 人物可变状态是影子＋锚，不是第二本真值
- 灵感不欠账、安放前不进执行包
- 伏笔单独成账；义务先不开
- 写法挂点＋插件点卡，理论不自动改大纲
- 账本可以细，执行包必须瘦
- 卷默认折叠

回包还专门反对这些「假扩面」：一张未来表、轻大纲／重大纲两套格式、爽点账／弧光账／情绪曲线真值账、场内人名当地点户口。

## 要动的：按刀口，不是按热闹

### 第一刀（微改，现有对象上改字段）

场篮不要再把「陈九棺」「陈家老屋」当结构化数据存。界面仍显示名字，底下改成人物 ID、地点／实体 ID。人物侧这件事存储稿已经拍了（CH ID 第一天用），地点还停在字符串——这是稿自己承认的缺口。

章纲继续只引用上游，不复制设定全文。写作指导、分镜做成投影，不另存一套剧情。

已发表范围／未来创作范围打角色标记（证据真源 vs 工作真值）。外写新正文默认只是对照文本。这是政策＋几列状态，不是新故事户口。

### 第二刀（中改的主体：补户口，不改树）

缺的不是「第 6 层大纲」，是实体有没有家：

回包开表尺子（P10）给的优先真值补口是三组，加上实体门牌：

- 地点、势力、物品：要稳定 ID 和别名。优先做成**共享实体登记**（一种门牌、带类型），不要一上来就三本平级真值账。
- 人物知情硬账：方向早已拍，字段还没锁。
- 事件—时间—约束：倒计时／冷却／「现在什么样」不要另开状态表；事件上的时间、因果前置、期限要能查、能被引用。
- 规则—能力—例外：设定集现在整块入架、不拆条。回包建议升成硬账。这和已拍「Bible 两轴 v2 再上」同向，但是提前——**要你点头才进施工**，不能当成已经拍过。

### 第三刀（能后开就后开）

这些回包内部有打架，**先不要当施工清单**：

| 回包想要 | 另一份怎么说 | 建议 |
|---|---|---|
| P4 把命运／种子／条件剧情都开成对象 | P10 真值只准再加三组 | 命运先住人物自有件或书核结局锚；种子继续灵感账；条件剧情用触发器外壳，不新开未来表 |
| P3 读者承诺做成一等对象 | P10 只列三组硬账，没点名承诺 | 两份打架。先并进伏笔／期待挂点，还是现在就单开，要你拍 |
| P5 义务单开 | 大纲 R02 已写 v1 不开；P7／P10 后开 | 维持 v1 不开 |
| P2 叙述顺序另表 | 大纲已预留「故事内时间提示」升级条件 | 线性网文先用数组＝叙述序；真出现倒叙再升 |

拆书四件套（研究卡／写法发生／脱敏模板／话语计划）进**隔离研究项目**，不进正线数据库。

## 改完之后，表大概什么样

不是 80 张，也不是继续把一切塞进一份大纲 JSON。

回包建议的量级：**4 层叙事（实体／事实与时间／编排树／表达）＋大约 12 张首发核心表**。现有规划账十三类对象＋事实账＋人物＋灵感＋材料架，已经覆盖大半「编排层」和「事实层」。缺的是实体层门牌、知情、规则拆条。

检查器、人物页、时间线、执行包继续读投影，不另存第二套真值。

## 这轮明确不改

- 不砍五层篮子，不把拍改成章的子行冒充实体
- 不把计划和事实合成一张表
- 不把 CLI 现在的 JSON 文件当晚上下线成 Postgres（终点已拍是 Postgres，但换引擎是另一张施工单）
- 不按回包直接改 R10 或存储稿字段表
