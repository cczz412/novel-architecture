## 结论

✅ 不要做“轻大纲 / 重大纲”两份格式。应当是：

> 一套可追溯的细账本 + 一套书核→卷→章→场→拍的层级结构 + 按任务生成的瘦视图。

“30 条”和“130 条”可以继续留在事实账本里；它们不该直接等于 30 或 130 个章纲事件。反推正文后，130 条事实完全可能归入 8 个拍、3 个场，而作者手写的 8 条也对应这 8 个拍。两边到这一步才具有可比性。

章内平级计划事件，我建议：

- 6–12 条：默认可执行密度。
- 13–18 条：高级细档，必须按场折叠。
- 超过 18 条：不再允许平铺给作者或写作模型。
- 超过 24 条：触发“粒度审计”，检查是否把事实、动作细节、句法指导误当成计划事件。

⚠️ 这不是行业研究证明的临界值，而是建议拿来启动测试的产品阈值。公开资料中，我没有找到“小说一章超过多少计划事件就显著有害”的可靠用户研究。

## 1. 同一结构怎样容纳多档密度

密度不要做成一个“轻 / 重”开关，而要拆成三把互不干扰的旋钮：

| 旋钮     | 控制什么                 | 例子                                 |
| -------- | ------------------------ | ------------------------------------ |
| 结构层级 | 看书、卷、章、场还是拍   | 全书只看卷胶囊；写作时展开当前场     |
| 字段深度 | 看胶囊、核心格还是完整格 | 默认只看胶囊；连续性检查才看知识变化 |
| 执行窗口 | 一次装入多少相邻内容     | 写当前场只装当前拍和后续 2–4 拍      |

这比“专业版显示全部字段”更稳，因为高级作者也不需要每次同时看完全部数据。

公开工具已经在用类似做法：

- Scrivener 的同一条 synopsis 会同步出现在 Inspector、Outliner 和 Corkboard；自定义元数据可以随时增加，并按需显示成列，不必复制一份“专业大纲”。[Scrivener Inspector](https://www.literatureandlatte.com/blog/get-to-know-the-scrivener-inspector)、[Scrivener Metadata](https://www.literatureandlatte.com/blog/metadata-plus)
- Plottr 的空白场景卡只需简短标题，描述、人物、地点、标签、自定义字段逐步增加；场景卡还能堆叠、折叠和筛选。它允许无限场景卡，但不要求同时展示。[Plottr Scene Cards](https://docs.plottr.com/article/57-timeline-scene-cards)
- Arc Studio 的同一个 beat 会出现在 Plot Board、线性 Outline 和正文提示里；可按人物、故事线筛选，还能把 beats 组成 sequence 一起移动。[Arc Studio Plot Board](https://help.arcstudiopro.com/guides/the-plot-board)
- Final Draft 的 Beat Board 和 Outline Editor 共用同一 beat，修改会双向同步；不同 lane 可以表示幕、段落和场，并支持缩放。[Final Draft Outline Editor](https://kb.finaldraft.com/hc/en-us/articles/27613546469652-How-do-I-use-the-Outline-Editor)

这类设计符合“渐进披露”：常用信息直接展示，少用和高级选项点开再看。它通常能降低学习成本和误操作。[Nielsen Norman Group](https://www.nngroup.com/articles/progressive-disclosure/) 更早的信息可视化原则也是“概览→筛选→按需详情”。[Shneiderman 1996](https://www.mat.ucsb.edu/~g.legrady/academic/courses/11w259/schneiderman.pdf)

建议只存一套兼容对象：

| 内容                                 | 是否长期保留 | 默认谁看           |
| ------------------------------------ | ------------ | ------------------ |
| ID、层级、顺序、胶囊                 | 是           | 所有人             |
| 已确认的计划事件、状态变化、因果关系 | 是           | 当前任务需要时     |
| 事实、原文证据、来源、置信度         | 是           | 检查器和高级作者   |
| 赌注、策略、新知等可选侧面           | 是，填了才有 | 对应任务和细档     |
| 写法、对白、镜头、节奏建议           | 否，可重算   | 当前写作或分镜任务 |
| 执行包                               | 否，可重建   | 当前模型           |

执行包可以直接理解成“从账本临时切下来的一小片”。软件架构里叫“可重建视图”：它只装当前查询需要的数据，丢了可以从源数据重算，不应反向成为新的真值。[Microsoft Materialized View Pattern](https://learn.microsoft.com/en-us/azure/architecture/patterns/materialized-view)

字段还要区分四种状态：明确填写、继承上文、未知、不适用。空白不能同时代表后三种，否则篮子越多，模型越容易乱猜。

## 2. 一章多少计划事件开始有害

我找到的是“整部作品的工作纪律”，不是小说章节的有效阈值：

- Save the Cat 用 15 个结构 beat，再扩成约 40 张场景卡，范围是整部电影；其创始人的公开复盘还强调，要把每场的一段解释压成一两句。[Save the Cat Story Cards](https://savethecat.com/story-cards)、[The Board Says Yes](https://savethecat.com/tips-and-tactics/the-board-says-yes-or-not-quite-yet)
- 一份大学编剧教材建议长片约 45–60 张场景卡，20 分钟短片约 8–15 张，但这仍是全片尺度。[FADE IN: Scene Cards](https://una.pressbooks.pub/fade-in/chapter/chapter-4-scene-cards/)
- Plottr 明确允许无限场景卡；Final Draft 允许任意增加 outline lanes。商业软件大多给组织工具，不给数量上限。
- 一项 21 人的互动叙事工具研究发现，视觉化的节点连接更容易让非技术作者理解、重排和增加分支；但实验任务远短于完整创作，论文没有给出安全节点数。[Green、Hargood、Charles 2021](https://eprints.bournemouth.ac.uk/35353/10/jocch-submission-accepted.pdf)

工作记忆研究常说人一次只能稳定处理约 3–5 个有意义单元，但不能据此宣布“一章只能有 5 个事件”。分组、折叠、外部卡片都会改变任务。[Cowan 2001](https://pubmed.ncbi.nlm.nih.gov/11515286/)

所以真正容易出问题的是：

> 同屏平级数量 × 条目相似程度 × 当下需要做的选择量。

建议的起始纪律：

| 章内计划事件 | 产品解释                                                     |
| ------------ | ------------------------------------------------------------ |
| 1–5          | 骨架档；人可以开写，但不足以稳定驱动整章生成                 |
| 6–12         | 默认执行档                                                   |
| 13–18        | 高级细档；按场折叠，模型按场执行                             |
| 19–24        | 禁止章级平铺；只允许分场、滚动执行                           |
| 24 以上      | 检查是否误收了事实、连续动作或句子指导；真是有效拍就继续嵌套，不删除 |

这里的“有害起点”可以暂定为：超过 12 个平级条目开始增加整理成本；超过 18 个不再进入同一个执行包。验证时看“开写耗时、反复重排次数、模型违约率、作者删掉的指导比例”，不要只看表单完成率。

## 3. 细到每句时，什么还算计划，什么只是指导

拍应当是计划事件的最小可寻址单位。拍内可以有很多事实和写法建议，但不再建立“句子级计划子事件”。

用三个问题分类最省事：

1. 它有没有明确的前后状态变化？有，就是计划事件。
2. 后文必须引用或检查，但它本身没有状态变化？放进事实或硬约束，不新建事件。
3. 换一种写法仍不改变故事计划？它就是可丢、可重算的写作指导。

| 内容                                                     | 应放在哪里                         |
| -------------------------------------------------------- | ---------------------------------- |
| 人物作出决定、采取关键行动、获知秘密、失去物品、关系改变 | 计划事件／拍                       |
| 某事件必须先发生，后一个事件才成立                       | 计划事件及因果链接                 |
| 谁知道什么、谁误信什么发生变化                           | 拍上的知识状态变化                 |
| 分支选择、汇合点、不可逆承诺、伏笔兑现                   | 计划事件或计划链接                 |
| 密码原句、遗嘱措辞、关键道具颜色、必须保持的时间点       | 拍上的事实或硬约束，不新建句子事件 |
| 对白候选、比喻、感官细节、语气、段落长短、先景后人       | 写作指导投影                       |
| 推镜头、切特写、光影方案                                 | 分镜投影                           |
| “这里更紧张”“加一点误导”“对白短促”                       | 写作指导投影                       |

ink 的官方设计很有参考价值：普通 weave 内的局部内容默认没有地址，走完后也不会被系统记住；只有未来确实要测试或引用时才加 label。也就是说，“能写出来”不等于“必须升格成可寻址真值”。[inkle ink 文档](https://github.com/inkle/ink/blob/master/Documentation/WritingWithInk.md)

还有一个容易混淆的地方：正文里抽出的事实可以是真实记录，但不一定是计划事件。比如“桌上有一只红杯子”应留在事实账本；只有它造成线索、连续性或后续行动时，才进入拍的约束。

## 4. 反推正文怎样和作者手写大纲对齐

不要直接把抽取结果命名为“章纲”。反推流程应保留三个身份：

- `观察事实`：从正文抽到，带原文位置和置信度。
- `候选拍`：系统聚合后认为可能是计划事件。
- `已确认拍`：符合统一粒度契约，才进入大纲。

推荐流程：

1. 高召回抽取，30 条或 130 条都保存，绑定原文证据。
2. 按时间、地点、人物／物件、目标、因果和知识状态变化寻找边界。
3. 同一目标、连续时空、没有独立状态变化的微动作合并为一拍。
4. 决定、揭示、因果转折、不可逆状态变化必须保留为独立拍。
5. 每拍生成一句胶囊，事实仍挂在拍下面，不因压缩而删除。
6. 用与手写大纲完全相同的密度规则校准；只比较“已确认拍”的数量和覆盖，不比较原始事实数。
7. 若确有 20 多个有效拍，就分成多个场，并按场生成；不能为了凑 12 条删掉事件。

事件理解研究发现，读者会自然形成粗细嵌套的事件边界；时间、空间、人物、目标、因果等变化会推动分段，而且任务要求会影响人关注哪种边界。[Zacks 等人的事件分段综述](https://pmc.ncbi.nlm.nih.gov/articles/PMC3314399/)、[Bailey 等 2017](https://bpb-us-e2.wpmucdn.com/sites.wustl.edu/dist/e/952/files/2017/09/10.37582Fs13421-017-0707-2-zpeojd.pdf) 这说明“连续性检查版”和“分镜版”不该各抽一份章纲，而应从同一层级事件上投影不同侧面。

一个正常结果可以是：

> 130 条事实 → 10 个已确认拍 → 3 个场胶囊 → 当前执行包只装当前场、当前及后续 2–4 拍、相关硬约束。

较新的 WhatELSE 研究也发现：具体故事实例可能太细，高层提示又可能太虚；可调抽象层级，并让作者在 outline 与具体实例间来回查看，更利于掌控内容。其用户研究规模为 12 人，适合作为方向证据，不适合作为数量定标。[WhatELSE](https://arxiv.org/html/2502.18641v1)

## 5. 建议的密度阶梯

下面的数字指“该容器下默认可见的计划锚点”，不包括挂在账本里的事实和证据。

| 层级 | 胶囊档               | 默认执行档                                                   | 完整档及主要读者                                             |
| ---- | -------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 书核 | 一句话故事承诺       | 3–7 个全书承诺：核心欲望、主要冲突、结局方向、变化方向、类型承诺 | 8–15 个长期约束、主题问题、主副线承诺；高级作者、全书规划与编辑检查 |
| 卷   | 一句话卷功能         | 4–8 个宏观转折：进入状态、升级、逆转、高潮、退出状态         | 8–15 个里程碑、线索交会、卷间依赖；高级作者、结构与伏笔检查  |
| 章   | 一句话“本章改变什么” | 通常 6–12 个拍，场默认折叠                                   | 13–18 个拍及因果、知识、连续性侧面；高级作者和按任务调用的检查器 |
| 场   | 一句话场胶囊         | 2–5 个拍；继续使用现有 MVP 场篮                              | 约 4–8 个拍，加已登记的赌注／策略／新知等完整字段；高级作者、连续性和分镜任务按需读取 |
| 拍   | 一句话计划变化       | 一个占主导的行动／决定／揭示及直接结果                       | 前置条件、状态差、知识差、硬约束、证据；不再向下建计划事件   |

小白“开写下一章”的硬门槛只需三项：

- 本章胶囊：这一章要让什么发生变化。
- 第一场胶囊：谁在做什么；地点、时间、视角能继承就不再询问。
- 开头 1–3 个拍：眼前先发生什么。

章末落点可以允许选择“边写边定”，不要硬打断。

如果用户要求模型一次生成完整一章，才换用另一套“任务就绪检查”：需要章末状态、场胶囊，以及约 6–12 个有序拍。这个检查只决定当前任务能不能稳定运行，不改变数据格式。

高级字段的可见范围也应按任务切：

- 写作模型：当前场胶囊、当前和后续 2–4 拍、入口状态、硬约束。
- 分镜工具：人物、动作、地点、空间连续性、可视化锚点。
- 连续性检查：时间、物件、人物状态、知识状态和原文证据。
- 结构检查：赌注、策略、主副线、承诺与兑现。
- 高级作者：主动打开“完整细节”时才看全套。
- 小白主界面：胶囊、卡片、折叠场和“继续写”按钮，不暴露检修字段。

🔥 可以直接拍板成一句产品规则：

> 事实账本不限密度；章纲默认 6–12 个拍；超过 12 个开始分场折叠，超过 18 个退出章级执行包，超过 24 个审计分类；拍以下只存事实、约束和可重算指导，不再制造计划事件。
