# DR-LAW-02｜书稿、作者私设、第三方模型、插件内容与删除：创作助手的数据权利全链审计

**调查执行日：2026-08-14**  
**主要适用地区：中国大陆；第三方服务条款按各自全球/区域服务口径单列**  
**研究性质：上线决策证据调查，不是律师意见，也不判断当前产品已经合规。**

## 结论与调查边界

**一页人话结论**

✅ **已经比较确定的第一件事：未发表书稿不是“没发表所以没版权”。** 中国《著作权法》明确规定，中国自然人、法人或者非法人组织的作品“无论是否发表”均依法享有著作权；文字作品属于法定作品类型。作者还享有发表权、署名权、修改权、保护作品完整权、复制权、信息网络传播权、改编权、汇编权等不同权利。最高法公布的杨绛申请行为保全案、茅盾手稿案，也都说明了一个很关键的边界：**持有手稿、接触手稿或者获得文件，并不自动取得公开发表、复制和网络传播的权限。** citeturn3view0turn4view0turn1search0turn1search3

✅ **“用户上传了”不能写成一揽子授权。** 私下替作者存储和分析、把内容交给第三方模型、人工看稿、内部评测、拿去训练、公开分享、商业再利用、插件再分发，是法律性质不同的动作。著作权授权范围应与实际服务需要相匹配；个人信息层面又要分别判断处理目的、处理者角色、是否属于委托处理、是否向其他个人信息处理者提供、是否公开、是否出境。中国《个人信息保护法》还明确要求，处理目的、方式或个人信息种类变化时，应重新取得同意；委托处理、向其他处理者提供、公开披露分别有独立规则。citeturn3view4turn4view0

🔥 **对这个产品最重要的分界不是“有没有 AI”，而是“谁拿到了什么数据、拿去干什么”。** 第三方模型仅按你方指令完成推理，而且合同上不能自行训练、改善产品或另作他用时，更接近《个人信息保护法》第二十一条的“委托处理”；一旦供应商取得自己的用途，例如把输入输出用于自身模型改善，至少不能再简单地按纯粹受托处理理解。向另一独立个人信息处理者提供个人信息，法律要求告知接收方、处理目的、方式、信息种类，并取得单独同意。citeturn3view4turn18view1

⚠️ **“默认不训练”绝不能被用户理解成“不留存、不看、不出境、没有第三方”。** 2026 年的主流服务商条款清楚显示，这几个概念完全不同：OpenAI API 默认不把 API 数据用于模型训练，但默认滥用监测日志可含输入输出并保存最长 30 天；Google Gemini API 的免费档会使用提交内容和输出改进产品，而且可能由人工审核；Azure OpenAI 默认不训练，但特定滥用监测流程可能触发人工审核；AWS Bedrock 2026 年新增/强化了不同 retention mode，一些模型可要求最长 30 天保留，甚至在显式 `provider_data_share` 模式下向模型提供商共享；阿里云百炼按量付费 API/Token Plan 团队版承诺不训练，但 Coding Plan 明确是另一套数据用途。citeturn19view2turn20view0turn20view2turn20view4turn20view5

✅ **因此，“私人空间”承诺不能只靠一句“不训练”。** 更可靠的外部承诺至少要拆成：是否用于基础模型训练、是否用于产品改进、谁可以访问、有没有人工审查、默认留存多久、哪些功能另有持久化、是否出境、有没有子处理者、用户删除后多久清掉活跃副本、备份和法定日志怎么办。OpenAI、Anthropic、Google、Azure、AWS 当前文档都已经把这些问题拆成多个独立控制项，反过来证明把它们压成一句“不训练”会产生明显误解。citeturn18view3turn19view1turn20view0turn20view2turn20view4

✅ **删除也不是一个数据库 `DELETE` 就结束。** 中国个人信息规则要求，在处理目的实现、停止提供服务、保存期限届满、个人撤回同意等情形下删除个人信息；账户注销时应删除或者匿名化。确有法律规定保存期尚未届满或者技术上难以删除的，可以继续保存，但必须停止除存储和必要安全保护之外的其他处理。《网络安全法》又要求网络运营者按规定保存相关网络日志不少于六个月。因此，“注销后所有东西立即物理消失”通常是不合适的绝对承诺；更合理的是说明**活跃数据删除、派生物删除、第三方删除请求、不可立即擦除备份的隔离与到期清除、依法必须保留日志的用途限制**。citeturn3view6turn4view5turn17view0

✅ **删除范围不应只盯原文。** 搜索索引、向量索引、摘要、角色状态、世界设定抽取结果、检查结果、模型输入输出、缓存、评测样本等虽然法律名称不同，但只要仍能继续恢复、检索、分析该项目，就可能让“项目已删除”变成用户感受上的假删除。中国法律没有逐项写出“embedding 必须删除”，所以这部分不能冒充明确法条；但从目的终止、数据全流程管理和产品删除承诺看，**把可追溯的派生物随项目一起失效和清除，是证据较强的工程推论。** citeturn3view6turn17view1turn4view5

✅ **作者私设不能一股脑归到“个人隐私”。** 《个人信息保护法》保护的是与已识别或者可识别自然人有关的信息；纯虚构角色属性、世界规则、魔法体系本身不当然属于个人信息。但作者账号、联系方式、真实经历、聊天、人工客服记录，以及稿件里涉及现实人物的内容可能属于个人信息。另一方面，详细写下且具有独创性的设定文字可能构成受著作权保护的作品或作品组成部分；只有一个抽象点子、套路或概念，则不能因为作者叫它“私设”就自动获得对思想概念本身的版权垄断。citeturn3view3turn3view0

✅ **插件和社群素材最危险的误区是“网上公开＝可以拿来改、发、卖”。** 没有许可证时，默认版权规则仍然适用；GitHub 官方文档就明确提示，没有许可证并不意味着别人可以复制、分发或制作衍生作品。即使有许可证，也要逐个执行署名、变更标记、相同方式共享、非商业、禁止演绎等具体条件。Creative Commons BY 4.0 就要求适当署名、指向许可证并注明修改。citeturn21search0turn21search1turn21search5

✅ **“公版＝不用署名”在中国也不能这么写。** 中国《著作权法》规定署名权、修改权和保护作品完整权的保护期不受限制；所以财产权保护期届满和“作者名字可以抹掉”不是一回事。citeturn14search2

⚠️ **当前仍不能下死结论的几件事：**你们实际的“导写＋核对”输出究竟是否使产品本身构成面向境内公众的生成式人工智能服务，要看上线时究竟向作者输出什么、模型位于哪一层、产品承担怎样的生成服务角色；纯虚构私设在具体案件中能否同时落入隐私保护；向量 embedding 在著作权法上是否单独构成受控复制或改编；用户稿件里大量第三方自然人信息分别能否采用“履行合同所必需”等非同意基础；部分中国云厂商当前没有公开到足以回答“精确备份保存期/全部子处理者/每种 API 删除时限”的材料。这些应分别标为 **U 或需律师结合真实架构复核**，而不是用行业常识补齐。citeturn17view2turn3view3

**问题范围与调查方法**

本轮检索以中文和英文同时进行。法律层面以现行《著作权法》《个人信息保护法》《数据安全法》《网络安全法》《网络数据安全管理条例》《生成式人工智能服务管理暂行办法》《人工智能生成合成内容标识办法》及数据出境现行规则为主；司法层面优先最高人民法院及版权主管机关案例；供应商只采用当前官方服务条款、DPA、隐私/数据控制文档和官方技术文档作为“今天是什么规则”的证据。2026 年仍处于征求意见阶段的《著作权法实施条例》修订稿只作为未来更新触发器，不当作现行法。citeturn14search8turn15search0turn17view1turn17view2

供应商样本覆盖了 OpenAI API、Anthropic Claude API、Google Gemini API/Google Cloud、Microsoft Azure OpenAI、AWS Bedrock、阿里云百炼、百度千帆和腾讯云智能体开发平台，共八组，刻意保留不同账户档位、部署路径和地域条件，不把同一模型通过“模型厂商直连”和“云平台托管”视为同一套条款。Anthropic 官方自己也明确区分：Claude 直连 API 中 Anthropic 是数据处理者，而在 Amazon Bedrock 或 Google Cloud 上应看相应云厂商的数据处理规则。citeturn18view3

调查时主动寻找反例，包括“声称不训练但仍保存”“企业档不训练、免费档训练”“ZDR 仍存在例外”“云厂商总览页与最新模型级规则发生变化”“账户删除后仍需保存法定日志”等。AWS 2026 年最新 retention mode 就构成一个很有价值的反例：其 FAQ 仍概括说输入输出不共享给模型商，但更具体、更新的官方安全文档已经出现允许 `provider_data_share` 的明确模式，因此不能只截一张“Bedrock 不共享”的 FAQ 当永久结论。citeturn20view3turn20view4

明显偏差包括：供应商条款是供应商自己的声明，不等于独立审计；企业客户可能签有未公开附录；没有登录各家付费控制台验证每个开关；中国网文术语没有统一行业标准，公开平台文章和作者社区只能证明词语和使用方式存在，不能代表全部作者；本轮也没有读取你方任何内部实现，因此以下“产品启示”全部是假设上线前候选，不是现状认定。

**分歧与负结果**

**“没发表就不受保护”——反驳。** 法条和最高法案例方向都很清楚。citeturn3view0turn1search0

**“稿件是虚构的，所以没有个人信息问题”——反驳。** 小说本身的角色可能是虚构的，但作者账号、联系方式、支持工单、真实人物原型、作者自传性材料、聊天记录等仍可能涉及自然人个人信息。PIPL 是看信息和现实自然人的关系，不看文件是不是叫“小说”。citeturn3view3

**“只要第三方说不训练，就可以放心把私稿发过去”——反驳。** OpenAI 默认仍有最长 30 日滥用日志，Google 免费档会用于改善并有人审，Azure 有滥用审查流程，AWS 出现模型级 retention/data-sharing 模式。citeturn19view3turn20view0turn20view2turn20view4

**“企业版和免费版只是价格不同”——明确失败。** Google Gemini 和阿里百炼都给出了直接反例：账户/产品档位会改变训练和数据使用条款。citeturn20view0turn20view5

**“ZDR 就表示任何情况下服务器都不会留下一个字节”——不能成立。** OpenAI 明确有 endpoint 兼容性和安全例外；AWS 明确写明即使 `none` 模式，疑似 CSAM 仍可能保存并审核；Anthropic 某些功能根本不在 ZDR 覆盖内。citeturn19view2turn20view4turn18view3

**“删账号就能把所有日志同时删掉”——不能成立。** 中国现行《网络安全法》要求相关网络日志至少保留六个月；PI 删除规则本身也承认法律保存期和技术不可立即删除的例外，但这类数据不得继续拿去做普通业务处理。citeturn17view0turn3view6

**“所有稿件数据都是个人信息，所以只按 PIPL 做删除就够”——反驳。** 小说版权内容和个人信息是两个不同维度。纯虚构世界观可能根本不是 PI，但仍是有价值、可能受版权保护的用户内容。反过来，做了隐私匿名化也不意味着自动取得了作品的训练和商业再利用权。citeturn3view3turn4view0

**“开源、公开仓库、公开课程都能塞进插件市场”——反驳。** 无许可仓库保留默认版权；有许可也要执行具体许可证。CC BY、BY-SA、BY-NC-ND 的权限差别非常大。citeturn21search0turn21search17turn21search9

**“公版就是可以去作者名”——反驳。** 中国法规定署名权、修改权、保护作品完整权保护期不受限制。citeturn14search2

**“提示注入只是用户故意越狱”——反驳。** Microsoft 当前安全文档专门把**外部文档里隐藏的指令**列为 indirect prompt injection。也就是说，用户上传课程、插件说明、网页摘录甚至以后接入的 RAG 文档都应该视为“不可信数据”，不能因为它是知识资料就给它系统指令权限。citeturn21search6turn21search10

**“Prompt Shields 一开就解决了”——也不能成立。** 官方把 Prompt Shields、数据标记/spotlighting、规划漂移检测、工具链分析等作为多层防御组合，而不是宣称某一个过滤器能够证明完全安全。citeturn21search10

## 可复现记录、删除链与产品候选启示

**可复现性记录**

本题不是模型实验，复现对象主要是**法律状态和动态条款快照**。

| 复查对象 | 检索方式 | 应看到的预期结果 | 编码办法 |
|---|---|---|---|
| 未发表书稿版权 | 官方域检索“著作权法 无论是否发表 第二条”“发表权 手稿” | 国家版权局法条＋最高法手稿案 | `COPYRIGHT-UNPUBLISHED` |
| 个人信息第三方 | “个人信息保护法 第二十一条 委托处理 第二十三条 单独同意” | 委托和独立第三方提供被分别规定 | `PIPL-PROCESSOR/RECIPIENT` |
| 删除 | “个人信息保护法 第四十七条 删除”“网络数据安全管理条例 注销 删除” | 删除触发条件＋技术/法律例外 | `DELETE-LEGAL` |
| 法定日志 | “2025 修正 网络安全法 网络日志 六个月” | 2026 生效版本第二十三条 | `LOG-6M` |
| 跨境 | “促进和规范数据跨境流动规定 10万 100万 敏感个人信息” | 当前安全评估/SCC/认证阈值 | `XFER-CN` |
| OpenAI | “OpenAI API data controls 30 days ZDR application state” | endpoint 级留存矩阵 | `VENDOR-OAI-YYYYMMDD` |

| Azure | “Foundry models data privacy abuse monitoring deployment types” | 不训练＋审核＋部署区域 | `VENDOR-MSFT-*` |
| AWS | “Bedrock zero data retention provider_data_share” | `none/default/provider_data_share` | `VENDOR-AWS-*` |
| 中国云 | “百炼 数据训练 Token Plan”“千帆 用户协议 训练”“腾讯智能体 服务条款 180日” | 当前档位差异及删除条款 | `VENDOR-CN-*` |

| Prompt injection | “Microsoft Prompt Shields documents indirect injection” | 外部文档隐藏指令风险 | `PLUGIN-INJECTION` |

本轮**没有依赖视频作为关键证据**，因此视频时间戳为“不适用”。搜索到的 B 站用户抱怨等材料没有用来证明供应商实际处理行为，因为用户投诉只能证明“这种说法存在”，不能替代官方合同或技术日志。

推荐的供应商条款快照不是只存一张截图，而是保存一组字段：

`供应商 → 产品 → 账户档位 → 模型/endpoint → region → 页面标题 → 页面版本/生效日 → 抓取时间 → 关键条款原文 → 子处理者页面版本 → 数据保留 → 训练用途 → 人工审核 → 删除 → 跨境 → SHA-256 文件哈希`

其中“SHA-256”可以直接理解成**给这份快照算一个几乎不会撞号的数字指纹**。以后供应商悄悄改页面时，你能证明上线审批时看到的是哪一版。没有版本号的网页至少记录访问日期、网页 PDF/HTML 存档和哈希；条款变更后做逐段 diff。供应商条款、DPA、subprocessor list 应当是三个独立快照，不要只存隐私政策首页。OpenAI 的 DPA 和子处理者机制、Google Cloud 的 Service Specific Terms、AWS 模型级 retention 文档都说明了为什么只保存一个“隐私政策”远远不够。citeturn18view1turn20view1turn20view4

**删除链清单**

建议把“删除项目”在产品语义上定义为一场**有状态的删除任务**，不是前端立即隐藏后就算完成。下面的“应覆盖”属于产品候选目标；法律明确要求和工程推论分开标。

| 数据层 | 删除项目时建议动作 | 能否有例外 | 依据 / 证据 |
|---|---|---|---|
| 原始章节、上传文档、私设 | 从活跃存储移除，禁止继续查询/展示 | 法定保存极少见；如存在应单列 | PI 部分受 PIPL 删除规则约束；版权部分依用户删除承诺。citeturn3view6 |
| 对象存储历史版本 | 同步标 tombstone 并进入硬删除周期 | immutable backup 可延后物理清除 | **B**：由删除目的和技术例外推导 |
| 全文搜索索引 | 删除对应文档/索引项 | 不宜长期保留可检索副本 | **B** |
| 向量索引 / embedding | 删除向量和文档映射，不再参与召回 | “法律明确要求 embedding 必删”目前 **U** | **B/U** |
| 人物、世界状态、知情、伏笔等派生账 | 随来源项目一起失效/删除 | 用户主动导出后其本地副本不归平台控制 | **B** |
| 摘要、检查结果、AI 临时候选 | 删除可回指项目的结果 | 真正汇总且无法回溯个人/作品的运营统计另论 | **B** |
| 内部保存的模型 prompt/output | 清除正常业务副本 | 安全调查/法定日志例外 | PIPL 最小保存＋供应商条款差异。citeturn3view4turn19view2 |
| 缓存、队列、临时文件 | 设置短 TTL，删除任务阻止缓存重新写回 | 秒/分钟级自然过期可作为实现方式 | **B** 工程推论 |
| API gateway / 安全网络日志 | 内容字段尽可能减敏；按规定到期删除 | **有。网络日志法定至少六个月。**citeturn17view0 | **A** |
| 评测样本 | 若来自该项目且不是经单独授权的独立数据集，应删除/剔除 | 经合法、明确独立授权的训练/研究集另论 | **B** |
| 模型微调训练集 | 默认不应存在；若 opt-in 后存在，要按训练授权规定撤回后的效果及已完成模型处理规则 | 已训练模型能否“反训练删除”不是一般数据库删除，可形成重大承诺风险 | **U/B** |
| 主备数据库 / 灾备 | 活跃侧立即不可用；备份按轮换周期过期，并保留删除 tombstone 防止灾备恢复后“复活” | 可延迟物理擦除，但应停止其他处理 | PIPL 明确认可技术无法立即删除时仅存储和安全保护。citeturn3view6 |
| OpenAI/Anthropic/Google/Azure/AWS 等第三方 | 对有 delete API 的 stateful object 发删除；无删除 API 的按其约定 TTL 等待并留证 | 供应商的 abuse/safety/legal retention | 各厂商差异极大。citeturn19view1turn18view3turn20view4 |
| 人工审查工作台 | 清除审查副本、附件、导出和临时下载 | 违规案件/投诉证据按明确期限隔离保存 | **B** |
| 客服工单 | 内容最小化；项目稿件附件同步删除 | 财务/纠纷证据可有独立保存期 | **B** |
| 社群插件市场副本 | 私有草稿删除；已公开插件按撤回/下架规则处理 | 已由其他用户依法下载的副本无法保证远程销毁 | **A/B**：版权授权和技术控制边界 |
| 账单、交易、财务记录 | 不应因为删作品而全删 | 法定义务另有保存期 | 与稿件内容分库/分目的更清楚 |
| 账户标识 | 注销后删除或匿名化 | 法律保存期限未满或技术不可删时仅存储和安全保护 | 网络数据条例直接规定。citeturn4view5 |

🔥 这里最关键的外部措辞不是“永久删除”，而是能回答四个时间：

**什么时候用户在产品里看不到；什么时候活跃数据库/索引不可再使用；什么时候第三方供应商到期或确认删除；什么时候滚动备份中的残留自然过期。**

这四个时间如果不同，就应该让协议和内部删除账一致。否则非常容易出现“前端显示已删除、向量库仍能检索、第三方 stateful thread 还在、灾备恢复后又回来”的全链失配。

**对产品的候选启示**

**可以由本轮证据支持的方向**

| 候选方向 | 为什么有依据 | 证据强度 |
|---|---|---|
| 把“用户内容许可”限制在提供、维护、安全保障和用户主动启用功能所需范围，而不是总括永久授权 | 著作权权利分项；PIPL 目的限定 | **A** |
| 第三方模型形成独立的“数据路径账”：供应商、档位、模型、region、retention、training、human review、subprocessor | 多家服务商条款均显示这些变量会改变处理方式 | **A** |
| “默认不训练”做成技术门禁，而非只做协议文案 | Google 免费、阿里 Coding、AWS 特定模式构成直接反例 | **A** |
| 用户私有 Canon 默认不向插件暴露 | 最小必要＋prompt injection＋第三方处理风险 | **A/B** |
| 插件权限采用显式 scope，例如“读取当前选中文本”，而非“读取整个项目” | PIPL 最小必要原则和外部文档注入风险共同支持 | **A/B** |
| 插件市场要求原作者、来源、许可证、版本、微改者、修改说明 | 默认版权＋CC 署名/修改规则 | **A** |
| 删除任务有 machine-readable 状态，例如 active deletion / vendor pending / backup expiry | 法律允许不同删除阶段，供应商 TTL 也确实不同 | **B** |
| 导出不仅导正文，还尽量覆盖用户自己建立的设定、规划和派生工作成果 | PIPL 查阅复制/转移权＋产品可迁移性 | **A/B** |
| 人工审查按“谁、为什么、能看多少、看多久”单列，不埋进客服通用权限 | 当前供应商条款已经证明人审是独立重要变量 | **A** |
| 评测和训练分开开关、分开授权 | 两者目的和持续时间差异巨大 | **B** |

**本轮不能证明的东西**

本轮不能证明“你方只要采用某家供应商就一定合规”；不能证明所有作者都愿意用海外模型；不能证明“国内云一定比海外云更私密”；不能证明 embedding 在版权法上必然属于复制品；不能证明将所有稿件匿名化后即可自由训练；也不能证明一个 prompt 或短插件说明一定达到著作权作品门槛。供应商条款是必要证据，但不是对产品全部处理链的替代。

**建议上线前做的本地小实验**

最有价值的不是再做一轮问卷，而是跑一遍真实“数据旅程测试”：准备一个带唯一字符串的虚构项目，例如在正文、私设、人物表、模型请求中分别植入不同不可混淆的测试标记；创建项目、使用搜索/向量/AI 检查/插件/客服，再执行项目删除和账户删除。之后分别查活跃数据库、全文索引、向量库、日志、缓存、备份恢复环境、第三方 API state 和人工后台，看每个标记何时真正消失。这个实验不能证明法律合规，但能直接验证协议里最容易写假的“删除全链”。

作者访谈则更适合验证三个词有没有被用户理解错：**“私有”“不训练”“删除”。** 例如询问作者看到“私有空间”时是否默认认为工作人员也不能看、第三方模型也不会看到、删除后连备份都会立刻擦掉。供应商现实已经证明这些维度并不相同，因此用户理解测试很有价值。citeturn19view2turn20view0turn20view4
