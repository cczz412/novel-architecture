# EXPERIMENT_PLAN｜40章、3310条事实的上下文对照实验

> 状态：实验设计候选。**不执行训练，不修改种子金标，不解封训练授权。** 机械格式修复与语义方案实验分开记账。

## 0. 实验目的与最小单位

要回答的不是“哪个方案理论上更聪明”，而是：在同一模型、同一抽取合同、同一解码参数下，哪个上下文组装方式提高了章级事实质量，代价是什么，错误是否会传播。

- **独立统计单位：章/书。** 40章来自40本书，事实在章内相关，不能把3310条当3310个独立样本。
- **调参与最终验证隔离：** 32本训练书用于路由、提示、阈值和候选筛选；8本验证书封存到只剩最多2个最终候选时一次性开启。
- **事实真源不改：** 所有距离、人物密度、场景数等只做旁挂审计标签，不修改fact/status/evidence/speaker。
- **两套成本视角：** 一套按各方案自然成本；另一套按相同总输入token预算。两套结果不能混报。

## 1. Phase 0：不进入语义结论的机械前置

在任何模型实验前，单独修复并通过：

- 40个首段“无左侧重叠”占位符为空行；
- 7处构建收据字段层级错误；
- 源字节、SHA、段覆盖、重叠、3310条子集守恒、跨书隔离。

这一阶段只输出“机械PASS/FAIL”，不判上下文方案。

## 2. 旁挂审计标签

### 2.1 自动可生成标签

- `book_id/chapter_id/fact_id`；
- evidence字符起止offset；
- evidence所在段和负责区；
- evidence是否跨句/跨段；
- 章内相对位置（0～20%、20～40%、40～60%、60～80%、80～100%）；
- 显式人名、代词、指示词、引号和对话轮次；
- 当前段活跃人名数、场景切换标记候选；
- 重叠区事实与source offset去重键。

### 2.2 需要盲审的“前文依据距离”

给每条需要前文才能正确解释的事实标记“最早必要依据”的结束offset，与当前evidence起点求距离。桶：

- 0～250工程token；
- 251～500；
- 501～1000；
- >1000；
- 跨两个或更多短段。

建议先在32本训练书中盲标**至少480条高风险事实**，目标每个主距离桶≥120；不足的桶全量纳入并如实报告。高风险候选由代词、零代词、别名、对话、省略、计划/承诺/误信/条件触发，再随机加入20%无长依赖负例，防止只挑困难例。最终8本验证书在方案冻结后，对全部高风险事实盲标。

## 3. 最低成本、信息量最高的先导试验

### 3.1 样本

从32本训练书中选6章，不按结果挑：

- 最长2章；
- 人物/代词密度最高2章；
- 中位长度附近2章作为控制；
- 选取规则和名单在运行前写死。

### 3.2 八个条件

| 条件 | 输入组织 | 历史来源 | 输出范围 |
|---|---|---|---|
| A | 当前800～1200＋150～250左重叠＋P3 | 无 | 只交付当前负责区 |
| B800 | 当前段＋固定前800原文＋P3 | 原文 | 同A |
| C1 | 章级prefix多轮，累计此前user原文，不带answer | 原文 | 每轮只交付新增负责区 |
| C2-gold | C1＋此前正确金标assistant结果 | 金标 | 同上；仅测理论上限 |
| C2-self | C1＋模型此前实际输出 | 模型预测 | 同上；部署主估计 |
| C2-error | C2-self基础上，对5%历史事实注入平衡错误 | 人工受控错误 | 同上；测鲁棒性 |
| F | 整章单次＋P3 | 原文 | 整章全部事实 |
| G | A先提候选；第二遍看整章原文＋候选做去重/指代/冲突审计 | 原文＋候选（候选无证据权） | 最终整章；不得新增无逐字证据事实 |

请求量粗估：A/B/C1/C2三种约6.725次/章，F 1次/章，G约7.725次/章；6章×8条件约**294次模型请求**，不含失败重跑。工程token不是API token，运行时必须记录实际token。

### 3.3 固定项

- 同一个未微调或同一checkpoint；
- 完全相同的system、字段定义、事实口径、JSON schema；
- temperature=0或平台允许的最确定设置；top_p、max_output_tokens、stop、seed固定；
- 不在中途改提示；发现提示缺陷则整轮作废，另起版本；
- 失败重跑策略固定：格式失败最多1次，语义结果不因“看起来不好”而重跑；
- 输入块显式标记：`responsible_source`、`context_only_source`、`retrieved_source`、`untrusted_history`。

### 3.4 先导停止线

任何条件出现下列之一，立即停止该条件晋级：

- evidence逐字支持率<99%；
- 任何事实以assistant历史/状态卡文本而非正文offset作为evidence；
- source截断或输出截断>0；
- 跨书/跨章状态泄漏1次；
- C2-error在5%注错下，严格F1下降>1.0个百分点，或平均每1条注错引出>1条后续错误；
- 重复事实比A多>2条/1000条，且没有显著召回补偿。

这些阈值是**项目治理候选**，不是论文给出的行业标准。

## 4. 第一轮正式上下文实验

### 4.1 样本量

- 使用32本训练书中的12章做完整上下文比较，按章长四分位、事实密度、活跃人物、场景数分层抽样；
- 8条件共96个“章×条件”；按请求数约589次；
- 若API不完全确定，在25%章节上做2次重复；差距接近时再对全部候选重复；
- 不打开8本最终验证书。

### 4.2 为什么第一轮先不做D/E

D和E需要先定义状态字段、信任层级、检索单位和Recall@k；若一开始同时改窗口、检索器和记忆，就无法知道收益来自哪里。第一轮先回答三个高杠杆问题：

1. 原文从219扩大到800是否已有净收益；
2. 只累积原文的C1是否优于固定窗口/整章；
3. C2在gold/self/error三种历史下是否出现明显级联；
4. F与G是否分别解决边界与章级整合问题。

### 4.3 第二波加入D/E/B动态

仅对第一轮中“长距桶仍漏”或“C1/F成本过高”的6个困难章运行：

- **B-dynamic：** 触发未决指代/计划延续时，向左扩到最近完整场景或最大1200原文；
- **D-validated：** 只使用由已验收事实账生成的结构化状态；
- **D-model：** 使用前轮模型生成状态，单独测风险，不与validated混报；
- **E：** 按段落/对话块检索本章前文，k∈{2,4,8}；检索结果必须是原文offset。

## 5. E方案的检索实验合同

### 5.1 检索单位

并列比较：

1. 句子；
2. 2～4句段落；
3. 完整对话轮块；
4. 现有800～1200短段。

预计2～4句段落/对话块更有机会保留说话人和事件边界，但这是推断，必须实测。

### 5.2 Query组装

- 当前段人名、别名、地点、事件动词、计划/承诺词；
- 未决代词时，加入D中的活跃实体候选，但不得把候选当答案；
- BM25/字面检索与embedding检索分开记录；
- 不允许检索未来正文；只搜当前offset之前。

### 5.3 指标

- `Recall@k`：必要前文依据是否至少有一块被取回；
- `Precision@k`：取回块中相关块比例；
- MRR；
- 检索后指代正确率、事实召回和错误主体率；
- 检索文本evidence回贴率必须100%；
- 代词-only query单独分桶，不能被总体平均掩盖。

建议E晋级的最低门槛：高风险事实`Recall@4 ≥ 95%`，同时平均检索原文少于B800；这是项目候选门槛，不是公开标准。

## 6. D方案的状态合同与对照

### 6.1 最小字段

```json
{
  "entity_id": "book/chapter scoped",
  "canonical_name": "",
  "aliases": [],
  "current_location": {"value": "", "source_offsets": []},
  "event_state": [],
  "goal_plan_promise": [],
  "epistemic_holder": "",
  "status": "occurred|ongoing|plan|promise|condition|speculation|false_belief|negation",
  "open_events": [],
  "unresolved_references": [],
  "conflicts": [],
  "source_offsets": [],
  "trust_tier": "validated_fact|model_candidate",
  "created_turn": 0,
  "supersedes": [],
  "valid_until": null
}
```

### 6.2 三个来源必须分开

- `D-rule`：由原文规则生成的实体/位置/对话轮信息；
- `D-validated`：由已通过语义验收的事实账生成；
- `D-model`：模型前轮生成，仅作为untrusted candidate。

不能把三者汇总成一个D成绩。D-model的错误传播、过期率和正文纠正率必须单报。

## 7. F整章实验的专项检查

章长1,397～8,753工程token，从公开长窗口容量看通常可放入，但要同时满足：

- 实际豆包精调和推理端点不截断；
- 最大输出足以容纳整章事实JSON；
- 事实召回按章内位置五分位报告；
- 中位20%～80%位置不得比首尾平均低>2个百分点；
- 末20%召回不得比A低>1个百分点；
- evidence边界和重复不能恶化；
- 单次失败重跑成本单独计。

位置阈值为项目候选；没有论文能直接给中文小说事实抽取的安全阈值。

## 8. G两遍式实验合同

### 第一遍

A或B只生成候选事实，保留`fact_id候选、evidence offset、status、speaker、segment_id`。

### 第二遍

输入整章原文、候选及其offset；允许：

- 解决别名/主体；
- 去重；
- 标记冲突；
- 修正status/speaker；
- 补回第一遍漏项，**但新事实必须给出正文连续逐字evidence并通过substring/offset闸**。

禁止：

- 用候选文本作为evidence；
- 合并不同认知主体的误信/推测；
- 删除相互矛盾但各自有证据的事实；
- 依据“合理剧情”补事实。

## 10. 全指标表

### 10.1 事实质量

- 严格事实P/R/F1：标准化后的`fact+status+evidence+speaker`全部匹配；
- 语义事实P/R/F1：盲审同义表达和事实等价；
- evidence逐字支持率；
- evidence边界正确率；
- status、speaker、主体归属正确率；
- 时间、否定、条件、推测、误信正确率；
- 额外断言率。

### 10.2 长距离理解

按0～250、251～500、501～1000、>1000、跨≥2段报告：

- 指代正确率；
- 事实召回率；
- 错误主体率；
- 状态误判率。

### 10.3 边界与重复

- 跨段事实漏抽率；
- 重叠区重复率；
- 重复事实/1000条；
- 错误归属到当前负责区的比例；
- evidence无法回贴率。

### 10.4 章级一致性

- 人物状态冲突；时序冲突；目标/计划漂移；
- 同一实体别名归一错误；事实矛盾/1000条；
- 开放事件保持率；章节末整合召回率。

### 10.5 错误传播

- 后续错误数随轮次增长的斜率；
- 每条注入错历史影响的后续事实数；
- 状态卡过期率；
- 错误历史被正文纠正的比例；
- 模型把历史回答当正文证据的比例（目标必须为0）。

### 10.6 成本

- 请求/章；实际输入/输出/总token；
- P50/P95延迟；费用；上下文占用；截断率；
- `ΔF1 / 每增加1000输入token`；
- 缓存命中与未命中分别统计。

## 11. 统计方法

- 每章先算一个指标，再对方案做**章级配对差**；
- 95%置信区间：按章/书cluster bootstrap 10,000次；
- 主检验：paired permutation/randomization test；Wilcoxon signed-rank作稳健性检查；
- 同时报告均值、中位数、IQR、配对胜率；
- 3310事实的micro指标只作次要描述，不能代替章级CI；
- 距离桶用分层bootstrap；桶样本不足时只报区间，不下结论；
- 成本收益用章级回归，`F1 ~ input_tokens + chapter_length + fact_density + condition`，并做非线性敏感性分析，不预设每1000 token线性增益。

### 配对样本量解释

在双侧α=0.05、80% power的理想配对t检验下，标准化配对效应d=0.5约需34章，d=0.7约19章，d=1.0约10章。故：

- 32本训练书只足以稳定发现中等偏大的效应；
- 最终8本验证书只能验证很大的、方向一致的效应；
- 最终必须报效应量和CI，不能因p>0.05就说“相同”，也不能因全局micro F1很稳就忽略章间差异。

## 12. 晋级线与停止线

### 晋级候选（同时满足）

- 严格F1相对A提高≥1.5个百分点，章级bootstrap 95% CI下界≥0，或至少70%章节配对获胜；
- evidence逐字支持率≥99.5%，边界正确率不比A低>0.2个百分点；
- >1000 token依赖事实召回提高≥5个百分点，且错误主体不增加；
- 重复率不高于A+0.2条/1000事实；
- 成本≤2×A；若>2×，严格F1至少提高3个百分点；
- 无跨书/章污染、无截断。

### 立即停止

见3.4；另加：

- 方案收益只来自宽松语义F1，严格evidence/status持续下降；
- C2-self比C1差且注错后级联明显；
- D-model的过期率或错误覆盖正文比例>1%；
- E的Recall@4<95%且没有安全回退；
- F中段或尾段召回稳定低于A且G无法修复。

所有阈值均需预注册；若改变，必须新开实验版本，不能在同一结果上追调。

## 13. 正式SFT前的格式实验

只在上下文推理实验完成、金标训练获授权后做。最多训练两种格式模型：

1. **S-short：** 现有独立短段；
2. **S-mixed：** 短段＋一个经第一轮选出的长格式（F或C1；C2只有在self/error通过时才可入选）。

### 避免同一事实重复加权

- 每条事实有稳定`fact_id`；
- 同一fact出现在n种训练表示时，每个表示的loss weight为`1/n`，使总监督质量=1；若平台不支持样本权重，则按fact_id分层抽样，使各格式中的事实总量相等；
- 重叠区事实只作为input context，不进入assistant target；
- 同一章的短段和长样本必须在同一fold，禁止跨fold泄漏；
- 增加`input_mode=short|chapter|prefix`标签，防止角色结构含混。

### 4折书籍隔离交叉验证

在32本训练书内做4折，每折24本训练/8本内部开发；两种SFT格式使用相同优化器、学习率、epoch、总有效fact-weight和随机种子。候选选定后，在32本全量训练，只在最终8本验证书运行一次。

## 14. 豆包2.0 Lite相关的决策原则

没有公开证据能直接回答“豆包2.0 Lite在本任务上应优先多轮还是短段”。候选原则：

- **必须匹配的部分：** system合同、字段schema、evidence逐字规则、事实归属、角色顺序、输入块标签；
- **可以混合的部分：** 输入长度、原文窗口、单轮/章级格式，但必须显式标记并按fact_id归一权重；
- **禁止为了匹配生产而加入的噪声：** 未经语义验收的assistant历史、自由摘要、跨章状态；
- 正式训练前向平台确认：实际可精调基座名称、最大训练序列、最大输出、messages多轮支持、样本权重/重复策略、推理计费与缓存规则。

## 15. 失败后的下一步

| 失败结果 | 下一步 |
|---|---|
| B800不优于A | 不继续B1200；转B-dynamic或F，检查长距事实实际占比 |
| C1不优于B/F | 放弃章级多轮原文重传，保留单轮组装 |
| C2-gold高、C2-self低 | 明确teacher-forcing上限；禁止未验历史，测试D-validated或scheduled/noised history训练 |
| C2注错传播严重 | C2停止；历史只作候选提示，原文优先并加冲突闸 |
| F总体高但中段漏 | 进入G：短段候选＋章级整合；或位置分块两遍 |
| E Recall@k不足 | 扩query/检索单位；若代词-only仍差，回退B/F，不用检索强行作默认 |
| D-model过期/冲突 | 只保留D-rule/D-validated；增加supersedes和来源offset |
| G新增幻觉 | 禁止第二遍自由补项；改为只对候选做判定，漏项另开原文检索臂 |
