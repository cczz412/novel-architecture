# 深度研究：面向下游目标的事实抽取

我们在研究中文长篇小说事实抽取时，思考是否告知模型下游用途能提升效果。相关研究表明，**明确目的/意图**常能帮助模型聚焦关键内容，但也可能带来偏差和风险。以下结合文献和实验设计进行分析，并提出对不同模型的建议。

## 相关背景与研究

- 🧩 **查询/意图驱动摘要**：查询（query）或用户意图驱动的摘要任务早有研究。例如查询聚焦摘要（query-focused summarization）通过向模型提供特定提问，引导其提炼相关信息。精心设计的提示语（prompt）确保生成的摘要直指提问意图。类似地，有研究对教学文本进行“意图感知摘要”，通过显式的用户意图输入改进摘要质量。这些工作一致发现：**在摘要生成中**，向模型提供用户需求/意图可以显著提升摘要与用户期望的一致度，指标有ROUGE、BERTScore等大幅改善。这说明告诉模型“要干什么”确实能指导其聚焦相关信息。

- 🧩 **信息瓶颈与选择性提取**：信息瓶颈（Information Bottleneck）理论强调在压缩输入时保留尽可能多的关键信息。在文本解释领域，Paranjape等人利用信息瓶颈约束，学习从文本中提取**简洁且充分**的“理由（rationale）”片段。该方法在事实检验任务上效果显著：它以尽量少的信息支持分类预测，同时保证正确率。这提示我们，如果我们对模型设置过严（例如只抽取所谓“长远相关”），可能会牺牲对事实的全面覆盖，出现**漏抽**现象；反之若设置太松，又可能过多输出冗余内容。

- 🧩 **下游任务评估**：Iceberg基准和COSMIC等工作强调，**仅用表面指标（如检索召回）评估往往不能反映真正的效果**。Iceberg研究指出，在人脸识别和图像分类等场景中，优化距离度量的“synthetic recall”不一定带来任务精度提升。同理，我们抽取事实后的最终目标是支持后续检索、连贯性检查或文本生成，理论上应该用这些下游任务效果来验证抽取质量。COSMIC工作进一步提出可以计算摘要与源文档的互信息，以衡量是否保留了完成下游任务所需的信息。这意味着，我们可以用下游检索或问答任务作为第二指标，但**仍应以事实正确性为首要评价**。

- 🔥 **意图注入效果**：综合以上，“向模型说明目的/意图”往往能指导模型“为什么要抽这个、不抽那个”。例如，实验表明给模型定义摘要的受众、格式和目的后，生成结果质量和相关性明显提高。简言之，把任务放在语境中（如“给销售经理写报告”）往往比泛泛“总结”来的更有效。然而，在我们场景下也存在风险：若提示过多关注“长远使用”，模型可能忽略当前窗口内虽平凡但必要的细节（参考信息瓶颈下的「可解释稀疏性—准确率权衡」）。此外，让模型知道未来要“写小说”可能促使其生成未来剧情、填空或合理化，这与我们只需事实提取的初衷冲突。研究指出，当模型被要求回答超出训练时间范围的问题时（如未来预测），容易产生与现实不符的“编造”内容。

## 实验设计与对照方案

为了系统评估目的提示的影响，我们设计**四组对照实验**：  

- **P0（无目的说明）**：仅告诉模型抽取哪些字段和格式，类似当前提示。  
- **P1（一句简短目的）**：在原提示前加一句简述，如“这些事实将被存入小说长期状态库”或“用于故事连贯性回查”。  
- **P2（简要目的＋限制说明）**：在P1基础上，额外强调不允许总结剧情或凭空编造。例如“不是剧情总结，只抽取支持当前内容且对连续性有影响的事实”。  
- **P3（完整下游说明）**：给出详细背景和schema说明，如说明长期记忆的字段结构、消费模型等。  

评估指标包括：**语义精度P/召回R/F1**（对比抽取的事实与人工标注）；**长期重要事实切片**和**普通事实切片**的P/R；**过抽比例**（输出额外细节的频率）；**概要化倾向**（是否出现非文本证据或者总结句）；**未来导向倾向**（是否生成与当前无关的预测性内容）；**提示长度/Token数**等。根据Iceberg和COSMIC的思想，我们还可设计**下游任务辅助指标**（如用抽取结果构建知识库后检索问答准确率），但其结果只能作为参考，不能替代直接的事实正确率评测。

对于是否是真正影响“决策边界”而非仅改变措辞（F项），可以对比两种提示下**相同事实的抽取结果是否一致**：如果P1/P2下产生了新摘录或遗漏旧摘录，就表明提示改变了模型行为，而非仅表述差异。还可以用人为设置的难例（边界样本）测试：如果加入目的后模型在这些边界上有实质变化，即说明它的**判断机制**被调整。

## 本地Dense Qwen代理模型的建议

✅ **验证目的提示对模型精度的提升**：在本地Qwen3-4B实验平台上，先实施上述P0–P3对照，重点观察P/R/F1的变化以及事实粒度差异。如意图分化明显（例如P2召回提升但精度变化），即可确认“知道下游要啥”确实引导了模型提取倾向。

⚠️ **监控过抽和偏差风险**：实验中要注意，P1–P3增加信息后，模型可能输出更多内容，甚至构造未来剧情（hallucination）。可参考对话，及时检测是否出现不合理扩写。若发现明显的超提或“预言”，需要调整提示措辞或规则（如明令禁止）。

👉 **语料选择要谨慎**：只用经过权限审核的合成集进行实验，避免混淆模型行为；真实小说数据如果敏感或未经授权，不宜直接用于训练探索。

💡 **示例说明**：比如，一条P0提示可能是“请抽取事实、状态、说话人、证据ID”；P2提示可改为“这些事实会存入小说长期记忆库，用于连贯性检索。不要复述剧情，只保留当前文本明确支持、未来连贯性可能需要的事实”。通过对比，可看模型是否更多地剔除了无关细节。

## Sparse Ling Tiny的复验方案

Ling Tiny将作为轻量级代理，仅复查关键结论。建议：

- 🛠 **抽取结论验证**：将Qwen筛出的Top-2-3结论输入Ling Tiny，观察其是否再次选出相同事实。这里的验证类似于“交叉验证”，如果在P1/P2设置下结论更稳定，通过意义较大，说明目的提示提高了可靠性。  

- ⚠️ **注意架构差异**：Ling Tiny基于稀疏架构，理解能力可能弱于密集Qwen。提示中任务描述要简洁，避免过度说明导致模型混淆。可先做小规模测试：如在Ling Tiny上只运行P0和P2，对比其输出一致性。

- 🔄 **迭代优化提示**：根据Ling Tiny表现，调整文本顺序或简化说明。例如，如果发现“长期记忆”词汇效果不佳，可换用“后续检索”、“连贯性”等同义表述。持续调试，以确保同样的提示文本也适用于Sparse模型。

## Doubao Mini/Lite生产迁移建议

Doubao Mini/Lite作为未来生产候选，应基于上述发现谨慎迁移：

✅ **提示校准 vs 模型微调**：在生产部署时，一方面可以通过统一的系统提示（system prompt）或首段说明让模型“知晓目的”，这类似在推理时加入P2式指令。另一方面，也可以考虑在Fine-tuning阶段让模型熟悉此类指令，即“训练时就融入任务描述”。两者结合会让模型更稳健遵循目的。

⚠️ **提示长度控制**：生产环境限制提示长度，目的说明要简洁。不要在提示中列出完整的数据结构或消费流程细节（比如“对象存储+Kafka”之类）。长而细的说明容易泄漏产品逻辑，也可能导致模型偏离正事或试图填充未来场景。

👉 **分层验证**：可先在Doubao Mini的小批量微调中加入P2提示，观察效果。如果有效，再大规模应用。或对比在不同数据集上的结果，确保目的提示在所有测试场景下都不会损害基本的事实覆盖。

💡 **失败模式示例**：如果在一些测试中模型只提取重大事件，漏掉了普通对话事实，这说明提示太偏重“长期重要性”，需要补充“也要基本事实”之类的限定语。此时应重新设计提示，避免模型只抓*大纲*信息。

## 总结与指标建议

- ✅ **总结**：告诉模型“这些事实用于后续连贯性检索”**可以提升其对关键细节的关注度**，证实了这类策略在摘要任务中有效。然而，它也可能引发漏抽（忽略“眼下”事实）或过度推断（生成未来内容）的风险。设计提示时要平衡简洁性与准确性，避免指令冲突。

- 👉 **下游评估**：可通过构建长期记忆检索任务来辅助评估提取结果，如看抽取的事实能否帮助回答后续检索问题。但**事实正确性和覆盖度始终是优先考量**，下游表现只能作为附加参考。

- 🔍 **目的说明范例**（80–150字以内）：
  > “这些事实会被存入小说的长期记忆，用于检索人物状态、关系和事件，保证故事连贯。你的任务不是复述剧情，而是留下当前情节中确凿支持、未来连贯性可能需要的客观事实。背景信息只能帮助理解，不可代替正文证据。”  

- 🔄 **流程建议**：将此目的说明作为固定提示一部分。如果模型已通过对话指令或SFT/Fine-tune熟悉这类提示，可以在实际抽取时持续使用。对不同规模模型（Dense Qwen、Sparse Ling、Doubao Mini/Lite）分别验证效果再迁移，避免盲目放大未经测试的假设。
