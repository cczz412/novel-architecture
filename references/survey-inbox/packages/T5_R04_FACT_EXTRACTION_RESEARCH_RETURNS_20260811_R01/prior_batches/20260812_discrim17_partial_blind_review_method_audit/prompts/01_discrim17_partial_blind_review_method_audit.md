# 给 ChatGPT 的任务

请把附件 ZIP 当作一个**方法与决策审查包**，不是让你重做人工盲审，也不是让你猜真实模型赢家。

先读：

1. `01_current_truth/.../DECISION_BRIEF.md`
2. `01_current_truth/.../ANONYMIZED_MECHANICAL_FACTS.json`
3. `01_current_truth/.../METHOD_CONTRACT_EXCERPTS.json`
4. `01_current_truth/.../RETURN_CONTRACT.json`

`02_current_route` 里是当前准备票、盲审包机械回执、Wave01～05独立接收票和旧合同；`03_upstream_evidence` 是三份已登记的历史顾问材料，只能当先验，不能替代你这次独立判断。

我们的目标很具体：判断是否能在 225／916 条已审时停止默认全量盲审，用确定性最坏／最好边界安全地产生 3～5 个开发候选；如果还不能停止，找出最小且真正会改变候选结论的匿名盲行集合。

请重点挑战六件事：

- 上下界公式是否把必抽、可选、FP、Gold容量、重复预测、交付失败和零分母处理对了；
- 什么是“已经分得开”的充分条件，不能用区间中点或机器分填空；
- 四类角色候选怎样从区间产生，什么情况下可以强淘汰，什么情况下只能写证据不足；
- 如何计算未审盲行的信息价值，同时不向下一位盲审者泄露模型／臂身份；
- 控制端单向解盲、只公开组级聚合的流程是否还存在泄漏或选择性审查偏差；
- 费用全为待对账、资源字段不完整时，怎样保证缺账不会制造假优势。

请明确区分：

- 外部建议；
- 本地后续需要另签的执行票；
- 可以由机械测试证明的事实；
- 仍需人拍板的阈值。

不要要求我们补传小说正文、Gold事实文本、逐行预测／裁决、密封映射、原始模型回答、真实模型／平台／Endpoint身份、CONFIRM4或RESERVE8。它们被有意排除，而且不是这次方法审查所必需。

请严格按 `RETURN_CONTRACT.json` 的章节交回完整中文 Markdown。结论必须选 `PASS`、`CONDITIONAL PASS` 或 `BLOCK` 之一，并把修改建议写成能直接交给程序员执行的字段、公式、伪代码和反例测试；不要只讲原则。
