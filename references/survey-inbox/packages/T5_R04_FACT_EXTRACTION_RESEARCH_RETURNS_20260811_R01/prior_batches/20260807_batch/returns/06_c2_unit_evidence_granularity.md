# C2_UNIT 证据粒度研究：从“证据更干净”到“模型仍然看得懂”

## 结论摘要

✅ **现有数据还不足以证明“40 字一定过细”，但已经足以把 R02 判定为高风险方案。**

R01 到 R02 的变化并不是单纯把证据切得更准，而是同时改变了三件事：

| 维度 | R01 → R02 | 变化 |
|---|---:|---:|
| evidence 额外字符 p50 | 42 → 10 | 下降 76.2% |
| evidence 额外字符 p90 | 72 → 32 | 下降 55.6% |
| evidence 额外字符 p95 | 94.25 → 35 | 下降 62.9% |
| 平均 evidence IDs | 1.26 → 1.73 | 上升 37.3% |
| 每窗可见编号 | 11.65 → 21.875 | 上升 87.8% |
| 跨单元 evidence | 24.2% → 52.3% | 上升 28.1 个百分点，约翻倍 |

这里最强的危险信号不是“21.875 个编号”本身，而是：

> **超过一半的金标准证据被切断了。**

这说明 40 字已经经常短于你们任务中一个完整“证据语义动作”的长度。模型原本只需判断“一段文字能否支持事实”，现在还要额外完成：

1. 找到多个局部单元；
2. 记住各单元编号；
3. 判断这些单元应不应该合并；
4. 输出多个符号；
5. 避免漏掉相邻证据；
6. 在事实抽取和证据绑定两个任务间分配能力。

相关研究呈现出一个非常稳定的分化：

- 对**检索**来说，句子或命题级小单元经常能提高 Recall 和证据密度；
- 对**阅读、叙事理解和引用生成**来说，过细单元会破坏上下文、指代、时间连续性，并增加跨单元绑定和输出引用的负担；
- 对**小说等叙事文本**，极细命题切分可能明显差于保留叙事连续性的动态块；
- 对**未经引用训练的小模型**，要求它在同一次生成中既回答又精确引用，常常会降低答案正确性。citeturn5view1turn5view2turn13view2turn13view3turn7view0

🔥 **这意味着你们不应该继续把“阅读单元、证据单元、输出引用单元”强行做成同一种粒度。**

更合适的结构是：

- **阅读单元**：相对完整，保留句子、对白、指代和事件连续性；
- **证据单元**：允许较细，用来确定准确边界；
- **输出引用**：用区间、局部编号或锚点表达，不要求模型逐个枚举所有细单元。

在当前阶段，最推荐的主线不是在固定 `40/60/80 字` 中盲选一个，而是测试：

> **句子/分句感知的 55–80 字可变单元 + 层级局部 ID + 连续区间输出。**

这里的 55–80 字是建议搜索区间，不是文献给出的通用最优值。现有论文使用的语言、tokenizer、任务和证据定义差异太大，没有任何可靠研究可以直接把英文的 128 token、256 token 或一句话换算成“中文小说应切 60 字”。

## 文献能够回答什么，不能回答什么

### 粒度过粗与过细分别出了什么问题

**过粗单元的典型问题：**

- evidence 中混入大量无关字符，导致最低必要证据不清晰；
- 一个 ID 可能覆盖多个事件、人物或时间点，模型即使选对 ID，也不能证明它真的定位到了支持事实的文字；
- 训练信号变得宽松：模型只需学会“选附近段落”，不必学会精确 grounding；
- 检索 embedding 被无关语义稀释，相关事实在块中占比过低；
- 对否定、转折、条件和说话者归属，过宽 evidence 可能同时包含支持与反支持内容。

Dense X、PIC 和 RAG best-practice 实验都显示，适度减小块通常能提高检索精度和回答质量；但进一步缩小后，收益会变缓甚至逆转。citeturn5view1turn13view0turn1search2

**过细单元的典型问题：**

- 句法和语义成分被切断，例如主语在前一单元、行为在后一单元；
- 小说对白中的“说话者标记—引语—动作”被拆开；
- 人称代词、别名、省略主语和时间连接词失去先行上下文；
- 一个完整证据要由多个 ID 表示，证据召回从单选变成集合预测；
- 同一事实可能有多组“形式上不同但内容等价”的 ID 组合，标签熵增大；
- 模型需要同时理解文字和维护符号地址；
- 输出更长，更容易漏 ID、写错 ID、打乱顺序或选中相邻单元；
- 对未经专门训练的小模型，引用任务会挤占回答能力。

小说叙事实验中，平均仅 12 token 的命题块明显不如保留叙事连续性的动态块；LongCite 也发现未经训练的 8B、9B 模型难以一次完成回答和细粒度引用。citeturn12view3turn7view0

因此，你们的评价不能只看“额外带入字符”。一个 atomizer 至少要同时优化：

\[
\text{证据纯度} \quad+\quad \text{证据完整性} \quad+\quad \text{符号绑定难度}
\]

R02 只明确改善了第一项，却显著恶化了后两项的代理指标。

### 跨多个单元时性能怎样变化

需要区分两种“跨单元”：

**人为切断型跨单元**  
一个原本连续的最小证据，因为 40 字边界被拆成两个单元。这不需要真正的多跳推理，却增加了集合预测和编号绑定负担。

**真实组合型跨单元**  
事实确实要结合两处不相邻文字，例如人物身份在前文，行为结果在后文。这属于真正的多证据推理。

你们当前的 52.3% 把这两类混在一起了。这个指标必须拆成：

- 连续 gold span 被边界切断的比例；
- 同一证据覆盖几个连续单元；
- 证据由几个不连续区间组成；
- 区间间隔多少字、多少句、多少单元；
- 是否存在指代或时间链。

已有研究表明，多片段的**相对距离**会显著影响模型，即使总上下文长度不变；LongPiBench 中，约 10 个相关片段从密集变为分散时，代码任务可出现 20%–30% 的性能波动，而且模型增大并没有消除这一趋势。citeturn16view0turn16view1

但不能据此推断“1.73 个 ID 就会下降 20%”。你们更接近的是小范围符号绑定问题，必须通过配对实验测量。

### 大量编号、行号和 XML 标记是否会伤害小模型

现有证据支持一个更细的结论：

> **结构标记本身不一定有害；密集、无语义、需要精确计数和绑定的标记才更危险。**

Span Labeling 研究中：

- 不给模型显式位置，却要求输出字符索引，开放模型各任务表现普遍低于 24%；
- 给每个输入词插入索引后，NER 提高 21–45 个百分点；
- 但在语法错误和翻译错误识别中改善有限，作者推测插入的索引干扰了自然文本判断；
- XML tagging 是相对稳健的方案，但它要求复制整段输入，输出成本是 \(O(n)\)；
- 强制 JSON 等结构化输出会降低解析错误，却不保证任务正确率同步提高。citeturn20view0turn21view0turn21view1

LongCite 的结果进一步说明，即使句子 ID 格式清楚，未经引用训练的模型仍可能出现明显的答案正确率下降。GPT-4o、GLM-4-9B 和 Llama-3.1-8B 的下降约为 9、8.5 和 8.1 个百分点。citeturn7view0

不过，这些实验都没有单独证明“22 个编号一定比 12 个编号差”。编号数量、证据数量、引用任务和输出格式通常一起变化。因此，**21.875 是否形成认知负担，不能靠文献阈值判断，只能做保持正文完全相同的 ID-density 消融。**

### 哪些结论可以直接借，哪些不能类推

**可以直接借：**

- 不应只优化 evidence 多带了多少字符；
- 检索单元、阅读单元、引用单元可以分离；
- 小块定位、大块阅读是成熟架构；
- 连续证据应优先输出 range，而不是枚举每个 ID；
- 跨单元比例、gold ID 数量和证据间距必须成为分层指标；
- 对未专门训练的小模型，引用任务有真实的正确率成本；
- 小说比百科更依赖叙事连续性；
- 最优尺寸通常呈倒 U 或 Pareto trade-off，不是单调越小越好。citeturn8view1turn13view2turn1search2

**不能直接类推：**

- 命题检索优于 100-word passage，不代表 40 中文字 evidence 优于 80 字；
- RAG 的 Recall@20 提升不等于事实抽取或引用生成提升；
- 英文 token 数不能稳定换算为中文字符数；
- 跨文档多跳 QA 的下降不能直接等价于连续文字被人为切成两个 ID；
- 大模型的引用能力不能代表你们目标小模型；
- 训练后的 LongCite 表现不能代表 zero-shot C2；
- 框架中的 128、512、2048 token 是默认工程参数，不是经验最优标准。

## atomizer 候选设计与观测指标

### 句子与分句感知的可变单元

**建议规则**

- 句号、问号、感叹号、段落和完整引号优先作为强边界；
- 极长句再按分号、冒号、转折连词和部分逗号拆分；
- 小于约 20 字的片段默认与相邻片段合并；
- 软目标设为 55–70 字，硬上限先测 85–95 字；
- 说话者提示与对白尽量保留在同一单元；
- 不从人物全名、数字、日期、成对引号和否定短语中间切开；
- 含“他、她、其、这、那人、此事”等强指代而无先行词的片段，优先与前一单元合并。

**主要解决的问题**

它保留 C2 的逐字、确定性和可解析性，同时降低固定 40 字造成的随机语义断裂。叙事切分研究与动态 segmentation 实验都支持“自然边界优于极细命题块”的方向。citeturn13view0turn13view2

**重点指标**

- evidence 额外字符 p50/p90/p95；
- 跨单元 evidence 比例；
- 每条 gold evidence 的连续单元数；
- 单元内无主语、无先行词、引号不闭合比例；
- fact F1；
- evidence 字符级 precision、recall、F1；
- joint score：事实正确且 evidence 充分；
- 相对 R02 的 ID 数量变化。

### 层级父子单元与局部 ID

**建议结构**

```text
P03
  P03.C01
  P03.C02
  P03.C03
```

父单元可先测试约 160–240 字，child 使用 35–80 字的句子/分句感知单元。

输入不必把全窗所有 child ID 都同等暴露给模型。可以：

- 全局显示父 ID；
- 当前负责区域只显示 child ID；
- 非当前区域保留正文，但不插入密集 child marker；
- 输出 `parent_id + child_range`。

LangChain、LlamaIndex 和 Haystack 都已经采用“小块检索、大块返回”或层级自动合并模式；LlamaIndex 的 sentence-window 甚至直接以单句索引，在交给生成模型时替换为周边句窗。citeturn18search0turn18search1turn17search0

**重点指标**

- 全窗可见 marker 数；
- 当前局部可选 ID 数；
- 父块选择正确率；
- child evidence F1；
- 父块正确、child 错误的比例；
- ID hallucination 和不存在 ID 比例；
- 相同正文下，全量 ID 与局部 ID 的 fact F1 差；
- 两阶段延迟和 token 成本。

### 连续区间引用

对连续 evidence，不输出：

```json
{"evidence_ids": ["B03", "B04", "B05"]}
```

改为：

```json
{"evidence_range": {"start": "B03", "end": "B05"}}
```

或层级形式：

```json
{"evidence_range": "P03.C02-P03.C04"}
```

只有真正不连续的证据才输出多个 range：

```json
{
  "evidence_ranges": [
    "P03.C02-P03.C03",
    "P05.C01-P05.C01"
  ]
}
```

LongCite 的 coarse-to-fine 方法正是把邻接句子重新组织成连续引用范围，以避免 `[3][7][15]…` 这类离散 ID 序列。citeturn8view0turn8view3

**重点指标**

- 输出字段长度；
- 平均枚举 ID 数与平均 range 数；
- range 边界完全正确率；
- evidence 字符级 F1；
- 少选一个端点、扩大一个端点的错误比例；
- JSON/格式有效率；
- 同一证据在 list 与 range 表示下的 joint score。

### coarse-to-fine 两阶段证据

推理分两次：

**阶段一：事实抽取或父区域定位**

```json
{
  "fact": "...",
  "candidate_parent_ids": ["P03"]
}
```

**阶段二：只显示 P03 及相邻父区中的 6–10 个 child ID**

```json
{
  "evidence_range": "P03.C02-P03.C04"
}
```

这个方案把“理解整窗”和“精确选择证据”分开。LongCite 的实验表明，先回答再做 coarse-to-fine 引用，可以在 citation F1 65.8 的同时保留 100% 的原始答案正确性；直接句子检索虽然引用更准，却把答案正确性保留率降到 79%。citeturn8view1

**重点指标**

- 阶段一事实准确率；
- 父区域召回率；
- 在 gold parent 已知条件下的 child evidence F1；
- 实际检索 parent 条件下的端到端 F1；
- 阶段一正确但阶段二证据错误率；
- 两阶段成本；
- 与单次 C2 的事实准确率差。

### 较粗单元加局部 span 锚点

使用 80–140 字左右、语义完整的阅读单元，但 evidence 不要求覆盖整个单元。输出：

```json
{
  "unit_id": "P03.C02",
  "quote": "他直到次日清晨才回到城中"
}
```

系统在该单元内部做逐字匹配，得到真正的 start/end offset。若模型部署允许访问 logits，可以使用 trie 或 LogitMatch 一类受约束解码，确保 `quote` 必须是输入中的连续子串。

直接让模型输出字符数字 offset 不建议作为主方案。Span Labeling 实验中，模型凭空预测字符索引的表现很差；输入显式编号虽然能改善定位，却也可能干扰文本判断。相对而言，文本 span 更自然，但普通生成会出现改字、空格归一化和复述，受约束复制可以降低这类问题。citeturn20view0turn21view0turn21view2

**重点指标**

- quote 逐字匹配成功率；
- quote 多重出现的歧义率；
- constrained decoding 介入率；
- evidence 字符级 F1；
- 复制增删改字符率；
- 输出 token 数；
- 与纯 A 文本 evidence 的差异；
- 与纯 C2 ID 的 joint score 差异。

## 最小无训练实验矩阵

### 实验目标

实验不是简单比较 R01 和 R02，而是分别回答三个因果问题：

1. **40 字边界是否破坏语义完整性？**
2. **约 22 个可见 ID 是否干扰正文理解？**
3. **跨两个以上单元的输出绑定是否增加错误？**

R01 和 R02 同时改变了这些变量，直接比较无法知道是哪一项造成性能变化。

### 数据集抽样

建议从完全未参与 prompt 开发或训练的小说中抽取 **至少 200 个窗口做快速筛选**，随后用 500–1,000 个窗口确认。

200 个窗口应按以下属性分层抽样：

| 属性 | 建议分层 |
|---|---|
| 最小 evidence 长度 | ≤30、31–60、61–100、>100 字 |
| 证据结构 | 单句、连续多句、不连续多处 |
| 文本形式 | 叙述、对白、对白加说话者、书信/引用 |
| 指代 | 无指代、近距离指代、跨句指代 |
| 事实类型 | 人物属性、动作、关系、时间、地点、状态变化 |
| evidence 位置 | 窗口前部、中部、后部 |
| R02 gold ID 数 | 1、2、3 个及以上 |

不要只抽已有的“简单单 ID”样本，否则测不出 R02 的真正代价。

### 核心条件矩阵

用目标小模型、完全相同的正文和事实 schema，运行以下条件：

| 条件组 | 切分 | 输入 marker | evidence 输出 |
|---|---|---|---|
| 干净事实基线 | 不切或仅自然段 | 无 ID | 不输出 evidence |
| marker 负担控制 | 与 R02 相同 | 全量 ID，约 22 个 | 不输出 evidence |
| A 基线 | 原始正文 | 无 ID | 逐字 evidence 文本 |
| C2-R01-list | 固定约 80 字 | 全量 ID | ID 列表 |
| C2-R01-range | 固定约 80 字 | 全量 ID | start/end range |
| C2-R01-local | 固定约 80 字 | 局部 ID，上限约 12 个 | range |
| C2-R02-list | 固定约 40 字 | 全量 ID | ID 列表 |
| C2-R02-range | 固定约 40 字 | 全量 ID | start/end range |
| C2-R02-local | 固定约 40 字 | 局部 ID，上限约 12 个 | range |
| Boundary-list | 句子/分句感知，目标约 60 字 | 全量 ID | ID 列表 |
| Boundary-range | 句子/分句感知，目标约 60 字 | 全量 ID | range |
| Boundary-local | 句子/分句感知，目标约 60 字 | 局部 ID，上限约 12 个 | range |
| Span-hybrid | 80–120 字语义单元 | 较少 ID | unit ID + quote |

200 个样本 × 13 条件约为 **2,600 次调用/模型**。这是可以在不训练的情况下完成的规模。

为了判断效应是否只出现在小模型，再选一个能力明显更强的模型作为参考。若目标小模型随 ID 数和跨单元数明显下降，而强模型基本不变，就更能说明这是容量或训练不足导致的认知负担，而不是数据标签有问题。

### 专门隔离跨单元负担的配对实验

这是判断“52.3% 是否危险”的关键实验。

从 gold evidence 连续且长度约 45–80 字的样本中选 100 条，为每条生成两份**正文完全相同**的输入：

- **对齐版本**：移动切分起点，让完整 gold evidence 落在一个单元中；
- **切断版本**：保持近似相同的平均单元长度和可见 ID 数，但让边界从 gold evidence 中间穿过，使其必须输出两个 ID。

这是一种实验用的 gold-aware 切分，不用于上线。它只用来回答：

> 同样的文字、同样的证据、近似相同的 ID 数，仅仅因为证据需要输出两个 ID，模型会不会更容易失败？

比较以下结果：

- fact 正确率；
- evidence recall；
- joint score；
- 漏掉后一单元比例；
- 只选包含答案关键词单元的比例；
- 输出两个 ID 时的格式错误率。

如果切断版本显著更差，便可以确认跨单元本身是负担，而不只是 R02 样本碰巧更难。

### 专门隔离可见编号负担的实验

比较前两项：

```text
干净正文，无 ID，只输出事实
```

与：

```text
正文完全相同，插入约 22 个 ID，仍然只输出事实
```

两者都不要求 evidence，因此差异近似反映**输入 marker 对正文理解的影响**。

再加入：

```text
正文完全相同，只给约 12 个局部 ID，仍然只输出事实
```

可以直接判断：

- 22 个编号是否比 12 个编号更伤；
- 是编号本身伤，还是引用输出任务伤；
- 局部 ID 能否恢复性能。

Span Labeling 的结果已经说明显式编号可能一方面帮助定位，另一方面干扰自然文本任务，因此这个变量不能靠推测。citeturn21view1

### 统一评价指标

**事实质量**

- fact 字段 exact match；
- 实体、关系、时间、地点等字段级 F1；
- 允许同义表达时的规范化 F1；
- 事实幻觉率；
- 漏事实率。

**证据质量**

- evidence 字符级 precision；
- evidence 字符级 recall；
- evidence 字符级 F1；
- evidence 是否足以蕴含事实；
- 额外带入字符 p50/p90/p95；
- 漏掉否定、时间、说话者或限定语的比例；
- 事实正确且证据充分的 joint score。

**碎片化**

- gold evidence 平均覆盖 ID 数；
- 预测 evidence 平均 ID 数；
- 跨单元率；
- 连续区间数；
- 不连续 evidence 的最大间隔；
- 单 ID、双 ID、三 ID 以上各自的准确率；
- 每增加一个 gold ID，joint score 的下降斜率。

**符号和格式**

- 不存在 ID 的比例；
- 漏 ID 比例；
- 多选邻接 ID 比例；
- ID 顺序错误；
- range 起点正确率和终点正确率；
- JSON 可解析率；
- 平均输出 token；
- evidence 输出占全部输出的比例。

**认知负担代理指标**

最重要的是以下差值：

\[
\Delta_{\text{marker}}
=
F1(\text{有 ID、只抽事实})
-
F1(\text{无 ID、只抽事实})
\]

\[
\Delta_{\text{citation}}
=
F1(\text{有 ID、输出事实和 evidence})
-
F1(\text{有 ID、只抽事实})
\]

\[
\Delta_{\text{cross}}
=
F1(\text{gold evidence 被切断})
-
F1(\text{gold evidence 完整})
\]

这三个差值分别回答 marker、引用任务和跨单元绑定是否伤害模型。

统计上应使用样本配对 bootstrap 给出 95% 置信区间。还可以做一个简单的混合效应回归，把正确与否解释为：

```text
可见 ID 数
+ gold ID 数
+ 是否跨边界
+ evidence 字符长度
+ evidence 所在位置
+ 是否对白
+ 是否存在指代
```

这样可以防止“长证据本来就难”被误判成“ID 多导致难”。

### 判断四十字是否过细的工程标准

下面不是学术界统一阈值，而是适合你们当前决策的建议标准。

可以把 40 字判定为过细，只要满足以下任意两项：

- 相比 60–80 字或 boundary-aware 方案，joint score 下降至少 2–3 个百分点，且配对置信区间不跨零；
- 配对切断实验中，双 ID 版本的 evidence recall 下降至少 3 个百分点；
- 在事实内容完全相同的条件下，把可见 ID 从约 22 降到约 12，fact F1 或 joint score恢复至少 2 个百分点；
- gold evidence 需要三个及以上 ID 时，准确率出现明显断崖；
- R02 的 precision 收益主要来自减少无害邻接文字，而 evidence sufficiency 或 fact accuracy 同时下降；
- range 输出显著优于 ID 列表，说明问题主要来自枚举和绑定，而不是文字理解；
- 强模型基本不受影响、目标小模型显著下降，说明当前 C2 接口超过了目标模型的符号处理能力。

反过来，如果 R02：

- fact F1 不低于其他方案；
- evidence recall 不下降；
- joint score 最高；
- ID 错误率稳定；
- 双 ID、三 ID 曲线没有明显下降；
- 局部 ID 也不能进一步改善；

那么 40 字虽然跨单元率高，也未必已经形成实际负担。

## 推荐决策与经验搜索区间

### 当前最推荐的优先级

**主候选**

```text
句子/分句感知的可变单元
软目标 55–70 字
硬上限 85–95 字
最短片段约 20 字
层级局部 ID
连续 evidence 使用 start/end range
```

这个方案保留 R02 的证据精度，又避免把 40 字当作无条件硬刀。

**第二候选**

```text
80–120 字语义完整单元
输出 unit_id + 逐字 quote
由程序在单元内部解析真正 span
```

它适合 evidence 原本很短，但模型不擅长在 20 多个 ID 中做集合选择的情况。

**第三候选**

```text
父区定位
→ 只展开 6–10 个局部 child ID
→ 输出 child range
```

如果目标模型很小，或者事实抽取本身已经较难，这个两阶段方案最有机会保护事实正确性。LongCite 的结果表明，一次性生成答案和引用会消耗能力，而 coarse-to-fine 可以明显降低这种干扰。citeturn7view0turn8view1

### 如何寻找经验最优区间

不要用一个综合权重把所有指标硬加起来。更稳妥的方式是画 Pareto 前沿：

横轴：

```text
evidence 额外字符 p90 或 p95
```

纵轴：

```text
joint score
```

点的大小：

```text
平均 gold ID 数或平均输出 ID 数
```

点的颜色可以代表：

```text
可见 ID 数
```

候选粒度建议至少覆盖：

```text
固定 40
固定 60
固定 80
句子感知
分句感知目标 55
分句感知目标 70
80–120 字 + span
```

真正适合上线的点应同时满足：

- fact F1 接近所有方案最好值；
- evidence recall 不被精度优化牺牲；
- p95 额外字符在业务可接受范围；
- 平均 gold ID 尽量不超过 2；
- 三 ID 以上样本比例较低；
- 跨单元主要来自真实多证据，而不是任意字符边界；
- 可见局部 ID 数稳定；
- 格式错误和不存在 ID 很少。

可以把以下值作为第一轮工程警戒线，而不是永久标准：

| 指标 | 建议警戒线 |
|---|---:|
| 跨单元 evidence | 尽量低于 35%–40% |
| gold evidence 的 p90 ID 数 | 不超过 2 |
| 局部可见 ID 的 p90 | 约 12–16 |
| 三个及以上连续 ID 的样本 | 尽量少于 10%–15% |
| 相对最佳 fact F1 损失 | 不超过 1 个百分点 |
| evidence p95 额外字符 | 由业务确定，初步可用 40–60 字观察 |
| 不存在或非法 ID | 接近 0 |
| joint score | 作为最终主排序指标 |

R02 当前的 52.3% 跨单元率已经越过建议警戒区，但它只是**应当立即做因果消融的信号**，不是直接淘汰 40 字的充分条件。

最终判断不应是“C2 对不对”或“A 对不对”，而应比较四个可落地接口：

1. A：逐字 evidence；
2. C2：全量细 ID；
3. C2-range：局部或层级 ID + 区间；
4. Hybrid：较粗 unit ID + 单元内逐字 span。

如果 A 的复制错误可控，并且 joint score 明显高于 C2，就没有必要为了形式整洁强行使用 C2。反过来，如果 C2-range 在保持事实正确性的同时显著减少 evidence 过带字符，它会比纯文本 evidence 更适合作为稳定监督信号。

**当前证据支持的核心判断是：不要再把“更小的固定字符单元”当作唯一优化方向。R02 已经把证据纯度做得很好，下一步最有价值的实验不是继续切到 30 字，而是把语义边界、ID 密度和输出表示三个变量拆开。**
