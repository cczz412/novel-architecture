# SEMANTIC_CORE 辅助任务：帮助事实理解，还是污染结构化输出？

## 结论与建议

✅ **结论：SEMANTIC_CORE 有可能提升“从小说中找出事实”的能力，但把它设计成独立的第三种 JSON 容器，并不是风险最低的做法。**

现有研究支持这样一个基本判断：当辅助任务与主任务共享底层语义、比主任务更简单，而且辅助信号能让模型更直接地关注关键文本时，多任务学习经常能改善主任务；信息抽取中也有不少成功案例，例如用证据句识别辅助关系抽取、用低层语言任务辅助高层语义任务、用较简单的 NER/关系抽取任务迁移到更复杂的事件抽取。citeturn5search2turn5search3turn3search0turn10academia32

但这种收益并不自动成立。多任务目标可能产生相反方向的梯度，任务组合、采样比例、训练顺序和输出表示都会影响最终结果；有研究甚至发现，在中文多任务微调中，把生成任务加入原本较同质的分类任务后，生成和分类性能同时下降。citeturn1search0turn1search1turn6search7turn12view0

对你们这个约 4B 的模型，我的建议优先级是：

| 方案 | 事实语义监督 | 格式干扰风险 | 推荐程度 |
|---|---:|---:|---:|
| **正式 schema 不变，只提高 `fact` 部分的 loss 权重，或屏蔽其他字段的 loss** | 强 | 最低 | **最高** |
| **增加句子级事实分类、证据句选择等非生成辅助 loss** | 强 | 很低 | **很高** |
| **正式 schema 不变，辅助样本仍输出全部字段，但部分字段使用低权重** | 中到强 | 低 | **较高** |
| **同一根 JSON 容器，只允许简化对象或可选字段** | 中 | 中 | 可实验 |
| **单独的 `{"fact_sentences": [...]}` 第三种容器** | 中到强 | 最高 | 只适合做受控验证 |

🔥 **如果资源只够跑一轮，不建议直接做“0% / 5% / 10% 独立第三容器”然后据此决定上线。** 最少应增加一个 **5% 的同-schema 对照组**。否则即使 5% 组变好，也分不清是“语义监督有效”，还是“短答案、不同输出长度、不同格式习惯或正则化效应”造成的。

对比例的判断是：

> **5% 是合理的低剂量探索点，但不是有论文证明的最优比例。**

它足够小，适合观察是否已经出现格式泄漏；同时也可能因为 SEMANTIC_CORE 输出短，导致实际参与训练的辅助目标 token 占比远低于 5%。因此应把“样本比例”和“有效 loss 比例”分开报告。

综合判断：

- **支持立项测试：中等偏强。**
- **支持直接采用独立第三 JSON：偏弱。**
- **支持先测试同-schema 语义加权或非生成辅助目标：强。**
- **当前没有直接证据证明“4B 中文小说事实抽取模型，混入 5% `fact_sentences` JSON 一定提升或一定污染”。** 以下结论主要来自多任务学习、指令微调、统一信息抽取和结构化生成研究的交叉证据。

## 支持证据与主要风险

### 为什么 SEMANTIC_CORE 可能有效

你们的假设并不牵强。正式任务同时要求模型完成至少四件事：识别事实、区分事实状态、识别说话者或认知主体、定位证据并生成合法结构。对于 4B 模型，这些目标可能竞争有限容量。

SEMANTIC_CORE 去掉 evidence、speaker、status 和位置编号后，模型每个辅助样本上的大部分目标 token 都直接描述事实内容。这可能产生三个收益。

**更直接的语义监督。** 正式输出中的大量 token 是 key、括号、编号和重复字段。SEMANTIC_CORE 的内容 token 比例更高，可以更直接地强化“哪些命题应当被抽出来”。信息抽取研究中，证据提取等较直接的中间任务确实能帮助最终关系预测。citeturn5search2turn5search24

**降低单个样本的任务难度。** 低层任务支持高层任务、简单任务向复杂任务迁移，在层级多任务模型和 JsonTuning 中都出现过。citeturn5search3turn3search4

**形成语义正则化。** 多任务学习有时通过迫使共享表示同时支持两个相关目标，减少模型只记正式模板的倾向；Flan 和 Super-NaturalInstructions 也表明，多样任务训练可以改善跨任务泛化。citeturn6search4turn6search6

这种正面效果更可能出现在以下条件同时满足时：

- SEMANTIC_CORE 的每条事实都能从正式标注机械推导，不能引入新的事实定义。
- 辅助任务与正式任务对“什么算事实”完全一致。
- 错误信念、计划、否定、传闻、假设和未发生事件保留清楚的认知或模态表达。
- 正式任务拥有明确的任务标记或 schema 提示。
- 辅助比例较小，且不会长期占据训练尾部。

尤其要检查你们示例中的第二句：

```json
"赵明误以为钥匙在抽屉里。"
```

这句话可以作为事实，因为事实是“赵明持有某种错误信念”，而不是“钥匙在抽屉里”。辅助数据生成时必须保留“误以为、声称、计划、怀疑、否认”等谓词。否则模型可能学到一个错误的语义压缩规则：把角色相信的内容直接升级为叙事世界事实。

### 为什么它可能污染主任务

**根容器竞争。** 在正式 prompt 和 SEMANTIC_CORE prompt 相似时，模型需要根据少量任务提示，在：

```json
{"facts": [...]}
```

和：

```json
{"fact_sentences": [...]}
```

之间选择。对于小模型，根 key 本身可能成为高频、低难度的模式。输出格式研究显示，相同语义换一种表示就可能显著改变抽取效果，小模型整体上比大模型更受格式影响。citeturn8view0turn8view1

**目标存在语义缺失，而不只是格式简化。** SEMANTIC_CORE 不要求 status、speaker、evidence，因此它不仅是短版正式答案，也是一个不同的条件分布。对于错误信念、引语、计划等样本，辅助任务可能奖励“抽到命题就结束”，正式任务却要求继续判断命题属于谁、是否成立、是否已经发生。这个梯度未必完全一致。

**正式监督被替换。** 5% SEMANTIC_CORE 意味着正式 schema 的训练机会减少 5%。如果主任务格式变差，原因可能只是少看了 5% 正式答案，而不是第三格式产生了主动污染。

**短答案偏好。** SEMANTIC_CORE 的结束位置更早，可能提高模型在抽出事实后尽快结束的概率。正式任务中，这可能表现为缺字段、少事实、提前闭合数组或遗漏 evidence。

**任务提示依赖。** 多任务指令训练能处理多种格式，通常依赖明确且多样的任务指令。若两个任务的输入几乎相同，只有一句较弱的输出要求不同，模型可能学到“混合答案先验”，而不是可靠的任务路由。Flan 的成功也依赖任务平衡、prompt 设计和 mixture 消融。citeturn6search4turn9view2

**梯度冲突。** 即便两个任务概念相关，只要对同一 token 概率提出不同要求，也可能出现负迁移。多任务学习研究已经反复观察到这种冲突。citeturn1search0turn1search1

## 比例判断与 schema 选择

### 五个百分点是否合理

✅ **5% 适合作为安全性探针，不适合作为未经验证的最终配方。**

目前没有可靠经验能证明“相关辅助任务占 5%”是通用甜点位。Flan 使用的子 mixture 往往达到两位数百分比，不同数据源的权重也差异很大；DoReMi 则说明数据比例应当随任务和模型实测。citeturn8view2turn6search7

你们还要区分两个比例：

\[
r_{\text{example}}
=
\frac{\text{SEMANTIC\_CORE 样本数}}
{\text{总样本数}}
\]

和：

\[
r_{\text{target-token}}
=
\frac{r_{\text{example}}L_s}
{(1-r_{\text{example}})L_f+r_{\text{example}}L_s}
\]

其中 \(L_s\) 是 SEMANTIC_CORE 平均参与 loss 的目标 token 数，\(L_f\) 是正式答案的平均目标 token 数。

例如，假设简化答案平均只有正式答案的三分之一：

- 5% 样本比例，对应约 **1.7% 的目标 token 比例**；
- 10% 样本比例，对应约 **3.6% 的目标 token 比例**。

因此，“5% 样本”对共享参数的总体梯度影响可能很弱；但它对根 key、开始符号和结束模式的影响未必同样弱，因为这些 token 在每个辅助样本中都会稳定出现。

实验中至少应同时记录：

- 辅助样本比例；
- 辅助目标 token 比例；
- 辅助 loss 在总 loss 中的比例；
- 主辅任务梯度范数；
- 主辅梯度余弦相似度。

对 0% / 5% / 10% 的预期，比较合理的是：

| 比例 | 合理预期 | 决策含义 |
|---|---|---|
| **0%** | 格式最稳定，语义能力完全依赖正式标签 | 基线 |
| **5%** | 可能提供轻量语义正则化；也可能因有效 token 占比太低而无明显变化 | 最适合先测 |
| **10%** | 更容易看到语义剂量效应，但正式 schema 暴露量下降更多，格式泄漏风险更高 | 只有 5% 信号不明确或明显正向时再测 |
| **高于 10%** | 可能开始把辅助任务学成重要输出模式 | 当前不建议 |

### 单独第三 JSON 和保持正式 schema 的比较

✅ **保持正式 schema、只减少部分字段的学习压力，风险更低。**

推荐的同-schema 辅助目标不是简单把缺失字段写成 `null`，也不是让模型输出不完整对象。更干净的做法是：

1. 目标序列仍然是完整正式 JSON；
2. `fact` 字段使用正常或更高权重；
3. `status`、`speaker`、`evidence` 在这部分样本上的 loss 设为零或较低；
4. JSON 结构 token 可以维持少量 loss，保证模型仍学习正式容器；
5. 普通正式样本仍对所有字段计算完整 loss。

可以直接理解成：**模型看到的答案还是生产环境答案，但这 5% 样本主要考它“事实有没有找对”，不强迫它在每个字段上都得到同样大的梯度。**

一种示意如下：

```text
正式目标：
{
  "fact": "赵明误以为钥匙在抽屉里。",
  "status": "mistaken_belief",
  "speaker": "赵明",
  "evidence_ids": [3]
}

辅助样本的 token loss：
结构 token        低权重或正常权重
fact 字段值        高权重
status 字段值      0 或低权重
speaker 字段值     0 或低权重
evidence_ids       0 或低权重
```

这种方案的优势是：

- 不增加新的根 key；
- 不增加新的闭合方式；
- 不训练“正式任务可以不输出字段”；
- 仍然减少了复杂字段对共享参数的梯度压力；
- 可以与独立第三 JSON 做一一对照。

⚠️ 不建议把辅助答案写成下面这样并对所有 token 正常训练：

```json
{
  "fact": "赵明误以为钥匙在抽屉里。",
  "status": null,
  "speaker": null,
  "evidence_ids": []
}
```

因为这可能把 `null` 和空数组学成新的默认习惯。相比之下，**保留真实完整 target、只调整 loss mask** 更干净。

现有统一信息抽取和 JsonTuning 的结果总体也更支持“统一表示、在同一表示内迁移”，而不是为每个难度层级发明独立输出语言。citeturn4search0turn3search0

## 更干净的辅助方法

如果目标只是加强“找事实”，不一定需要引入第三种生成格式。下面按格式污染风险从低到高排列。

### 句子级事实分类或排序

把片段切成句子或候选命题，让共享 Transformer 表示接一个轻量分类头，判断：

- 这是应抽取的事实；
- 这不是事实；
- 这是事实证据句；
- 这是干扰句。

训练时：

\[
L = L_{\text{formal-generation}} + \lambda L_{\text{fact-classification}}
\]

推理时可以丢掉辅助头，正式生成接口完全不变。

这与 EIDER 的证据提取辅助目标最接近，也是我认为最干净的方案之一。citeturn5search2

缺点是需要修改模型或训练代码；如果当前训练框架只支持 causal LM token loss，工程成本会比纯 SFT 高。

### 同 schema 的 token loss weighting

这是最容易落地的方案。对正式 JSON 中不同 token 区间设置权重：

\[
L =
\lambda_f L_{\text{fact}}
+
\lambda_s L_{\text{status}}
+
\lambda_p L_{\text{speaker}}
+
\lambda_e L_{\text{evidence}}
+
\lambda_j L_{\text{JSON}}
\]

例如普通样本全部为 1；辅助样本中可设：

```text
fact       1.0
status     0.1
speaker    0.1
evidence   0.0
JSON结构   0.2
```

具体值要调，不能直接视为推荐参数。多任务研究中，GradNorm、基于不确定性的 loss weighting 等方法都说明，不同目标不必静态等权。citeturn13search3turn13search4

### 事实候选的对比学习

对比学习可以让模型表示满足：

- 同一事实的不同措辞靠近；
- 事实与其支持证据靠近；
- 错误改写、否定翻转、主体替换、时态替换与原事实拉开。

例如：

```text
正样本：
“陈川打算明早离开。”
“陈川计划在第二天早上出发。”

困难负样本：
“陈川已经在今天早上离开。”
“赵明计划明早出发。”
“陈川没有打算离开。”
```

对比学习的关键是负样本必须真的在任务语义上不同；一般表示学习研究也表明，正负视图的选择直接影响学到的能力。citeturn13search1turn13search9

这个方案特别适合小说中的主体替换、信念归属、否定、计划与已发生事件等细粒度区别。

### 课程采样

可以先在少量步骤中提高简单语义样本的权重，随后逐渐过渡到完全正式任务：

```text
训练早期：20% SEMANTIC_CORE / 80% 正式
训练中期：5% SEMANTIC_CORE / 95% 正式
训练尾部：0% SEMANTIC_CORE / 100% 正式
```

总的 SEMANTIC_CORE 样本数仍保持与 5% interleaving 组相同，只改变出现顺序。

这种方式减少了第三格式对训练尾部输出策略的影响。课程式指令微调在一些研究中优于随机打乱，但效果依赖模型、任务难度定义和训练阶段。citeturn9view3

不建议一开始同时改变比例和顺序。应先确定辅助目标是否有效，再比较 interleaving 与 curriculum。

### 梯度冲突控制

可以定期在相同 batch 上分别计算：

\[
\cos(g_{\text{formal}},g_{\text{semantic}})
=
\frac{g_{\text{formal}}\cdot g_{\text{semantic}}}
{\|g_{\text{formal}}\|\|g_{\text{semantic}}\|}
\]

若长期为正，说明两者较一致；若在关键层或大量训练阶段为负，说明辅助任务正在与正式任务竞争。

PCGrad 可以作为后续缓解方案，但不建议首轮就启用，因为它会引入另一个实验变量。citeturn1search1

### 偏好学习

DPO 更适合学习“两个完整回答中哪个更好”，它直接优化偏好对，而不是提供一个独立、可解释的事实识别监督。citeturn13search2

在这个问题上，DPO 可以用于修正：

- 一个答案事实完整但格式错误；
- 一个答案格式正确但漏事实；
- 一个答案把错误信念写成世界事实；
- 一个答案多抽取幻觉事实。

但它不适合作为第一选择来替代 SEMANTIC_CORE。原因是事实抽取已有明确监督标签，用 SFT 辅助 loss、分类或对比目标更直接，也更容易判断改进来自哪里。

## 严格控制变量的实验设计

### 核心实验组

最小可行实验应包含以下组，而不只是三个比例点：

| 组别 | 正式样本 | 独立第三 JSON | 同-schema 事实加权 | 作用 |
|---|---:|---:|---:|---|
| **C0** | 100% | 0% | 0% | 主基线 |
| **J5** | 95% | 5% | 0% | 你们计划中的 5% |
| **J10** | 90% | 10% | 0% | 剂量测试 |
| **S5** | 95% 完整 loss + 5% 部分字段低/零 loss | 0% | 5% | 判断第三容器是否必要 |
| **S10** | 90% 完整 loss + 10% 部分字段低/零 loss | 0% | 10% | 资源允许时测试 |

这里的 S5、S10 中，总窗口数仍不增加。所谓“5% 同-schema 事实加权”，是从原正式样本中选 5%，保留完整目标，但改变字段 loss。

🔥 **S5 是不可省略的关键对照。**

若结果是：

```text
J5 提升，S5 同样提升或更好
```

说明有用的主要是“减轻非事实字段压力”，第三容器没有必要。

若：

```text
J5 提升，S5 不提升
```

才有理由进一步研究短目标、显式事实复述或不同 schema 是否提供了额外信息。

若：

```text
J5 格式变差，S5 语义提升且格式稳定
```

基本可以判定第三容器带来了 format interference。

### 样本配对

每个实验组必须从同一个“主样本池”开始。

例如共有一百万个训练窗口：

1. 固定随机种子，选出十万个候选辅助窗口，记为集合 \(S_{10}\)；
2. 从其中选出五万个，记为 \(S_5\)，保证 \(S_5 \subset S_{10}\)；
3. C0 中，这些窗口使用正式 target；
4. J5 中，\(S_5\) 使用第三 JSON；
5. J10 中，\(S_{10}\) 使用第三 JSON；
6. S5、S10 使用相同窗口，但 target 仍是正式 schema，只改变 loss mask。

这样可以避免 5% 和 10% 恰好选到了更简单文本、更多对话或更多短片段。

辅助集合应按以下维度分层抽样：

- 文本长度；
- 事实数量；
- 是否含对话；
- 是否含错误信念；
- 是否含计划或未发生事件；
- 是否含否定；
- 是否含多主体；
- evidence 数量；
- 小说来源或作者；
- 训练标签置信度。

### 必须保持不变的变量

所有组必须保持：

- 同一初始 checkpoint；
- 同一 tokenizer；
- 同一训练总窗口数；
- 同一 optimizer update 数；
- 同一 batch size 和 gradient accumulation；
- 同一最大序列长度；
- 同一 packing 策略；
- 同一学习率与 scheduler；
- 同一 warmup；
- 同一 weight decay；
- 同一精度设置；
- 同一数据来源分布；
- 同一 prompt 长度策略；
- 同一 checkpoint 选择规则；
- 同一推理参数；
- 同一 JSON parser；
- 同一评测 prompt。

每组至少三个随机种子。若 4B 全量训练成本太高，可以先用较短训练预算筛选，但最终候选至少要用三个完整种子复现。

⚠️ “训练步数相同”不等于“监督量相同”。因为 J5/J10 的答案更短，以下统计必须单独记录：

- 输入 token 总量；
- 正式目标 token 总量；
- SEMANTIC_CORE 目标 token 总量；
- 所有参与 loss 的 token 总量；
- 每种字段的 loss-token 数；
- 每种任务的平均 loss 和梯度范数。

### 调度方式

主实验先统一采用**确定性分层 interleaving**，不要把 J5 全堆在训练开头或结尾。

一种简单方式是每二十个窗口中固定一个 SEMANTIC_CORE，使局部比例稳定，而不是完全依赖随机采样。J10 则每十个窗口一个。

课程学习作为第二阶段实验：

| 调度 | SEMANTIC_CORE 总量 | 顺序 |
|---|---:|---|
| Interleave-5 | 5% | 全程均匀 |
| Early-5 | 5% | 前 25% 步骤高比例，后续逐渐归零 |
| Late-5 | 5% | 后期集中，用作风险对照 |
| Sandwich-5 | 5% | 早期少量、主体正式训练、尾部纯正式 |

如果 Early-5 优于 Interleave-5，而 Late-5 格式泄漏最严重，说明“辅助语义可用，但不应留在训练尾部”。

### 评测集设计

不能只看一个主任务总 F1。至少需要五类集合。

| 评测集 | 检查的问题 |
|---|---|
| **常规正式测试集** | 总体生产性能 |
| **未见小说或未见作者集** | 是否真有语义泛化 |
| **认知状态集** | 错误信念、猜测、声称、传闻、计划 |
| **格式压力集** | 长 JSON、多事实、空结果、字段较多 |
| **最小对照集** | 主体替换、否定翻转、时间变化、事实与未发生事件 |

最小对照例子可以是：

```text
陈川计划明早出发。
陈川明早已经出发。
赵明计划明早出发。
陈川没有计划明早出发。
王晓声称陈川计划明早出发。
```

模型必须分别处理计划、时态、主体、否定和信息来源。

### 指标拆分

正式任务至少拆成：

\[
\text{总表现}
=
\text{格式能力}
+
\text{事实识别}
+
\text{字段归因}
+
\text{证据定位}
\]

实际应分别报告：

| 指标 | 含义 |
|---|---|
| JSON parse rate | 能否解析 |
| Schema validity | key、类型、必填字段是否正确 |
| Wrong-container rate | 正式 prompt 下是否输出 `fact_sentences` |
| Premature-close rate | 是否提前结束、缺字段 |
| Canonical fact precision / recall / F1 | 忽略容器后，抽到的事实是否正确 |
| Status accuracy | 在匹配事实条件下，status 是否正确 |
| Speaker accuracy | 在匹配事实条件下，speaker 是否正确 |
| Evidence precision / recall / F1 | 证据定位 |
| Fact count error | 多抽或少抽多少事实 |
| Exact object match | 整体对象是否完全正确 |
| Hallucinated fact rate | 是否生成正文不存在的事实 |
| Epistemic collapse rate | 是否把角色信念当成世界事实 |

其中 canonical fact F1 的计算应先把不同输出映射到统一内部表示，避免仅因引号、标点或 key 顺序不同而误判。

## 判断是否真的提升事实理解

要声称：

> “SEMANTIC_CORE 提升了事实理解，而不是仅仅改变了输出习惯。”

至少应同时满足下面几条。

### 内容指标在去除格式因素后仍提升

用正式 schema 的 grammar-constrained decoding，强制模型输出合法 JSON。这样格式能力的影响被大幅削弱。

若 J5 在自由生成下提高，但在 constrained decoding 下与 C0 相同，说明收益主要来自输出策略或格式，而不是事实识别。

若 J5 在 constrained decoding 下 canonical fact recall、precision 或 F1 仍显著提高，才是语义提升证据。

结构约束本身不能保证内容正确，因此应同时报告语义指标和格式指标，而不能把合法 JSON 当作任务成功。结构化生成研究也强调语法有效性和内容正确性是不同维度。citeturn3search1turn0search20

### 非生成探针也提升

在冻结模型后，从隐藏状态训练一个很小的线性分类器，判断候选句或候选命题是不是应抽取事实。

探针训练数据和正式测试文本必须分离，并在所有模型上使用相同探针训练配置。

若 J5 或 S5 在非生成探针上也提升，说明内部表示更容易分离事实和非事实，这比“JSON 输出看起来更好”更接近事实理解。

### 提升出现在未见文本和困难语义上

若增益只出现在训练来源相同、短文本、单事实样本，而在未见作者、错误信念、否定、计划等集合上消失，更可能是模板或词汇习惯。

真正的语义收益应至少在以下两类中出现：

- 未见小说来源；
- 认知状态和模态困难集。

### 格式泄漏没有同步上升

正式 prompt 下需要监测模型是否开始：

- 输出 `fact_sentences`；
- 缺少 status、speaker 或 evidence；
- 把多个正式对象压成字符串列表；
- 过早关闭数组；
- 输出简短自然语言而非正式 JSON。

建议预注册一个格式安全阈值，例如：

```text
Wrong-container rate 不得上升超过 0.2 个百分点
Schema validity 不得下降超过 0.5 个百分点
字段缺失率不得显著上升
```

具体阈值应依据 C0 多种子方差和生产容错要求确定，不应照搬以上示例数字。

### 状态和说话者能力没有被事实召回率掩盖

SEMANTIC_CORE 很可能提高 fact recall，却降低 status 或 speaker accuracy。若只看事实 F1，会误判为整体提升。

应计算条件指标：

\[
P(\text{status correct}\mid \text{fact matched})
\]

\[
P(\text{speaker correct}\mid \text{fact matched})
\]

只有在事实识别提高，同时这些条件准确率没有实质下降时，才可认为辅助任务提升了主任务，而不是把复杂任务退化成“看到像事实的句子就抄出来”。

### 同-schema 对照能够解释收益

这是最关键的因果判断。

| 结果 | 解释 |
|---|---|
| J5 和 S5 都提升，幅度相近 | 简化语义监督有效；第三容器没有必要 |
| S5 提升，J5 不提升或格式下降 | 第三容器有污染，同-schema 更优 |
| J5 提升，S5 不提升，非生成探针也提升 | 独立事实复述可能提供了独特语义训练信号 |
| J5 只提高 JSON 或答案长度相关指标 | 输出习惯变化，不是事实理解 |
| J5 recall 升、status/speaker/evidence 降 | 学会了粗糙事实识别，但损害正式任务 |
| 5% 提升、10% 回落 | 存在轻量正则化和高比例负迁移，5% 附近可能是局部甜点位 |
| 5% 无变化、10% 提升且无格式风险 | 5% 有效 token 权重可能太低 |
| 5% 和 10% 都无变化 | 辅助任务信号冗余、比例太低，或正式任务已经能学到语义 |
| 5% 和 10% 都下降 | 任务定义不一致、格式冲突或正式监督减少造成负迁移 |

### 统计判据

每个核心指标都应报告：

- 至少三个种子的均值；
- 标准差；
- 配对 bootstrap 置信区间；
- 每个测试样本上的配对差异；
- 预注册的最小有意义提升幅度。

“显著”不应只等于 p 值小于某个阈值。推荐同时要求：

1. canonical fact F1 超过预注册的最小有意义增益；
2. 多个种子方向一致；
3. constrained decoding 下仍存在；
4. 未见来源集仍存在；
5. 非生成事实探针至少有同方向提升；
6. 格式泄漏、status、speaker、evidence 不超过预注册退化阈值。

✅ **最终推荐的决策路径是：**

先跑 **C0、J5、S5**。  
只有 J5 或 S5 显示稳定语义增益时，再跑对应的 10% 组。  
若 S5 不弱于 J5，采用同-schema loss weighting。  
若 J5 独有优势，再比较 interleaving 与 early curriculum，并确保训练尾部恢复为纯正式 schema。

就现有证据而言，最有希望、风险也最低的生产方案不是“再教模型一种更简单的 JSON”，而是：

> **继续只教一种正式输出语言，同时把 5% 左右的训练信号更集中地压在 `fact` 语义上。**
