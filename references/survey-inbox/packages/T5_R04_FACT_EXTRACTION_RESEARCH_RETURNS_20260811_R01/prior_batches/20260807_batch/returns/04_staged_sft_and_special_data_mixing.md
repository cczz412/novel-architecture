# 第二阶段“特殊教材”为什么可能把模型教偏：阶段式 SFT 与混合训练研究

## 核心结论

✅ **你们现在倾向的方向更稳：统一 schema，把普通样本与特殊样本分层打散，在训练全过程混合；特殊样本只做温和加权，而不是在末尾单独覆盖。**

你们看到的现象——合法 JSON 增多，但字段顺序污染、漏 fact、异常输出习惯同时出现——并不矛盾。SFT 的交叉熵损失不会区分“这是我想教的特殊处理能力”与“这只是教材附带的格式习惯”。一条特殊教材实际同时在教：

> 特殊情况判断 + 内容取舍 + 字段集合 + 字段顺序 + 输出长度 + 措辞风格 + 空值处理 + 结束方式。

当这些样本集中出现在训练末段时，模型接收的是一批方向高度一致、彼此相关的梯度更新。它可能学会目标能力，也会把特殊数据中的序列化习惯、遗漏模式和异常模板一起放大。持续微调研究通常把相关现象称为**灾难性遗忘**、**任务新近偏置**或**任务间干扰**；“last-stage domination”更像工程上的描述，并不是一个严格统一的学术术语。连续指令微调实验已经在知识、推理和阅读理解上普遍观察到旧能力退化。citeturn13academia26turn7view5

**对你们问题的判断如下：**

| 判断 | 结论 |
|---|---|
| 特殊数据是不是有害 | 不是。它确实能补足长尾能力，但可能把能力与坏习惯捆绑教学 |
| 风险来自特殊数据本身吗 | 一部分来自数据质量，更大的风险来自分布过窄、格式相关性过强和末段集中训练 |
| 小模型是否更危险 | 对格式模仿、窄分布行为和输出模板通常更敏感，但“参数越小，灾难性遗忘一定越严重”并不成立 |
| 默认训练方式 | 统一 schema 的分层混训 |
| 特殊样本的默认权重 | 按 token 计，从真实占比或 5% 左右起步，通常先搜索 5%–10%，谨慎超过 20% |
| staged curriculum 是否应完全放弃 | 不应。真正存在前置技能关系时，阶段式课程可能更省样本；但末段仍应保留普通数据 replay |
| LoRA 是否能消除覆盖 | 不能。它通常减少底座权重改写，但同一个 LoRA 连续训练仍会覆盖先前适配行为 |

研究里没有一个可直接搬用的“特殊数据黄金比例”。比例必须由特殊能力收益与主分布回退共同决定，而不能只盯着特殊集准确率。DoReMi、Skill-It 和近年的 SFT 数据混合优化工作都显示，数据权重本身是核心超参数，简单平均、全量堆入或按直觉设置并不稳定。citeturn7view1turn7view2turn9view4

## 与你们情况最接近的研究

### 格式专业化会压过任务语义

与“合法 JSON 变多，但输出习惯被改坏”最接近的是 Google 与 UCLA 团队的 **Two-stage LLM Fine-tuning with Less Specialization and More Generalization**。研究发现，单任务微调会迅速让模型对该任务的输出格式形成专业化，而且这种格式学习发生得非常早，早期梯度甚至可能先被格式而不是语义主导。citeturn9view0

论文中的案例非常直观：模型在 RTE 这类只输出 True/False 的数据上微调后，即便被问 TriviaQA 或翻译问题，也开始大量输出 True/False。约 300 个训练步骤后，TriviaQA 输出中约 90% 被污染成该格式；继续训练后，其他任务几乎都被这种输出空间支配。citeturn9view0

这与字段顺序污染属于同一类问题：模型并不是先抽象出“特殊情况的处理原则”，再独立决定格式，而是直接学习整条目标 token 序列的概率。只要特殊样本在某些位置稳定出现某个字段、模板或省略方式，这些特征就会得到重复且一致的梯度。

近期针对超小型函数调用模型的 STAR 研究也报告，标准 SFT 容易让小模型记住训练集中的 JSON 调用格式，在换成 Python 风格或其他工具调用表示时显著崩溃。研究者将原因归结为容量有限的模型在强监督下过度记忆具体输出格式。citeturn8search2turn9view2

另一项覆盖 15 种输出格式和多个任务的研究发现，语言模型在任务质量相同的情况下，也会对输出格式产生显著偏好；加入格式多样且受控的数据后，格式间性能差异才能下降。citeturn6academia28

**A. 与你们最接近的研究，不是传统的“知识遗忘”论文，而是“格式专业化 + 连续微调干扰”这两条研究线的交叉：**

1. 两阶段微调中的格式专业化，最像你们的字段顺序和异常模板污染。citeturn9view0
2. 小模型结构化输出过拟合，最像“合法 JSON 上升，但跨 schema 和异常场景变差”。citeturn9view2
3. 连续指令微调中的灾难性遗忘，解释为什么 stage2 的改善会伴随 stage1 能力回退。citeturn13academia26
4. Llama 3 公开报告中“短上下文 SFT 导致长上下文能力明显退化，向 SFT mixture 补回长上下文样本后恢复”，是工业实践里很接近的分布补偿案例。citeturn5view2

### 旧能力不一定被彻底删除，但输出接口可能先坏

一部分“遗忘”并不等于内部知识完全消失。有研究把它称为 **spurious forgetting**：知识可能仍在参数中，但模型无法在当前提示、任务格式或解码路径下正确调用。citeturn2search5

这对你们特别重要。漏 fact 可能有两种完全不同的原因：

- 模型对事实本身的预测能力下降；
- 模型仍知道事实，但新的 JSON 模板、字段预算、排序习惯或输出长度先验让它没有把事实写出来。

因此，不能只用“最终 JSON 是否完全正确”判断能力有没有丢。必须把**语义知道了没有**与**有没有按正确结构表达出来**拆开测。

近期结构化输出评测同样表明，schema 合法率与语义正确率不是一回事：一个结果可以完全通过 schema 校验，却依然存在字段内容错误、顺序任务错误或信息缺失。citeturn6academia26turn6search14

## 为什么特殊教材放在末尾特别危险

### 每个阶段都只优化当前看到的数据

设 stage1 结束时参数为 \(\theta_1\)，stage2 的更新近似为：

\[
\theta_{\text{final}}
=
\theta_1-\eta\sum_{t=1}^{T_2}
\nabla_\theta L_{\text{special}}(\theta_t)
\]

stage2 中没有普通样本，就没有任何直接梯度告诉模型：

> “在学习特殊情况时，请同时保持普通样本的 fact 完整率、字段顺序和输出风格。”

模型唯一接收到的信号，是降低特殊数据损失。只要改变普通行为能够进一步降低特殊数据损失，优化器就没有理由阻止它。

针对 LLM 微调遗忘的 scaling-law 研究发现，遗忘通常随更新步数增加；LoRA 和全参数微调都会出现。研究还专门展示了在小型目标数据上持续微调时，ARC、安全能力等旧指标会随训练推进而下降。citeturn7view5

所以“特殊数据量很小”并不天然安全。真正决定影响大小的是：

\[
\text{影响强度}
\approx
\text{重复次数}
\times
\text{学习率}
\times
\text{梯度一致性}
\times
\text{与原分布的偏离程度}
\]

特殊集虽然小，但如果反复训练多轮，且格式高度统一，它可能产生比大而多样的普通集更一致的更新方向。说白了就是：**一百条高度同质、重复十轮的数据，未必比一万条多样数据“声音小”。**

### 末段数据具有隐性的模型选择优势

实际训练通常直接把最后 checkpoint 当 final checkpoint。这样一来，stage2 不仅获得了最新一批梯度，还获得了“训练结束权”：

- stage1 造成的问题，stage2 还能修；
- stage2 造成的问题，没有后续普通数据修回来；
- stage2 过拟合，也可能因为没有密集评测而被忽略；
- 如果阶段切换时重置学习率或优化器，stage2 的影响会被进一步放大。

课程学习的大规模实验发现，严格 easy-to-hard 排序有时会提高中途表现，但后段困难或噪声数据可能让最终 checkpoint 下降；相对更稳定的做法，是把 curriculum 当作 warm-up，随后回到随机或混合采样。citeturn10view1turn10view3turn13search3

### 特殊样本的“好能力”和“坏习惯”是同一条监督信号

假设目标输出为：

```json
{
  "answer": "...",
  "facts": ["..."],
  "status": "special"
}
```

而特殊教材经常写成：

```json
{
  "status": "special",
  "answer": "..."
}
```

即使 `facts` 的缺失只是标注疏漏，训练损失仍会告诉模型：

- 特殊情况时 `status` 更早出现；
- 特殊情况时可以省略 `facts`；
- 特殊情况的输出通常更短；
- `answer` 后可能直接结束。

模型不知道哪些相关性是业务规则，哪些是数据管道留下的偶然模式。它只知道这些模式能够提高训练样本似然。

OpenAI 的微调指南明确建议训练示例尽量贴近实际生产输入与期望输出；Llama 3 团队也公开描述了对训练数据中多余道歉、表情符号等不良输出模式进行过滤和配比，因为这些表面习惯会直接进入模型行为。citeturn12search0turn5view2

### 小模型更容易被“窄行为模式”占据，但不是简单的参数越小越差

对小模型可以做两个区分。

**格式与行为模式方面，小模型通常风险更高。** 它的容量有限，较难同时保留“通用输出策略”和“特殊情况下的局部例外”，更容易学成一个简单但覆盖面过大的规则，例如“看到 A 类信号就切换到另一套 JSON 模板”。超小型函数调用模型的格式崩溃实验，以及 Llama 3 团队发现 8B 模型需要比 70B 更高比例的安全数据才能达到类似区分能力，都支持这种容量约束。citeturn9view2turn5view0

**灾难性遗忘与参数规模的关系却不是单调的。** 一项覆盖 1B–7B 模型的连续指令微调研究反而观察到，较大模型的绝对遗忘更严重，作者认为这可能与大模型初始能力更高、可下降空间更大有关。citeturn13academia26

因此，稳妥表述是：

> 小模型尤其容易出现格式记忆、输出模式窄化和规则过度泛化；但不能仅凭参数量预测旧能力下降幅度，数据差异、训练步数、学习率、初始能力和评测定义都会改变结果。

## 分阶段课程何时有优势，什么时候混训更稳

### 几种方案的研究经验

| 方案 | 可能优势 | 主要风险 | 对你们的适合度 |
|---|---|---|---|
| 普通 → 特殊，末段纯特殊 | 特殊集损失下降快，实施简单 | 新近偏置、主分布回退、格式污染、过拟合 | 不建议作为默认方案 |
| 普通与特殊全程混训 | 持续给模型保留主分布的梯度约束 | 特殊样本过少时可能学不充分 | 最稳的默认基线 |
| 混训 + 特殊样本轻度 oversample | 在保留普通能力的同时加强长尾 | 权重过高时仍会污染 | 最可能成为最终方案 |
| 逐步提高特殊权重的 annealing | 可让模型先稳定基础，再加强长尾 | 末尾接近纯特殊时仍有覆盖问题 | 可用，但必须保留普通数据下限 |
| sequential + replay buffer | 保留阶段式训练的清晰度，同时减轻遗忘 | replay 选择不好会增加成本或偏差 | 无法全程混训时的实用方案 |
| 独立 LoRA / expert | 隔离任务更新，方便回退 | 路由、合并与部署更复杂 | 特殊任务边界清晰时可考虑 |

### 混训为什么通常更稳

混合训练优化的是：

\[
L(\theta)
=
(1-p)L_{\text{ordinary}}(\theta)
+
pL_{\text{special}}(\theta)
\]

只要 \(p<1\)，每一段训练都同时存在两种信号：

- 特殊能力要提高；
- 普通能力不能随便破坏。

这不保证两者完全没有冲突，但模型至少能在训练过程中看到冲突，并寻找兼顾两者的参数区域。纯 stage2 则相当于把 \(p\) 突然变成 1。

DoReMi 的实验说明，不同领域的采样权重会显著改变模型性能，经过代理模型优化的 domain weights 能比默认混合获得更高的下游表现与更高训练效率。citeturn7view2 近年的 SFT 数据混合优化工作也把 mixture weight 直接作为优化变量，并报告经过优化的权重能接近昂贵网格搜索得到的各领域最优结果。citeturn9view4

Llama 3 的公开实践尤其有参考意义。团队在训练后段加入高质量新数据进行 annealing 时，并没有切换成 100% 新数据；评测小型候选数据集时，采用的是约 30% 新数据配 70% 默认 mixture。这个数字不能直接套用到你们的 SFT，但它体现了一个很明确的工程原则：**后段强化数据不等于后段完全替换原分布。** citeturn5view0

在 InstructGPT 中，OpenAI 观察到直接进行 PPO 对齐会在 SQuAD、DROP、HellaSwag、翻译等公开任务上产生所谓 alignment tax，也就是对齐收益伴随部分原有能力下降。加入预训练数据对应的语言模型损失后，回退得到缓解。citeturn14search2turn14search3

这些案例虽然分别来自预训练、RLHF 和 SFT，但共同指向一个模式：

> 窄目标训练容易造成能力回退；把原分布数据或原目标损失持续放回训练，可以形成保护约束。

### staged curriculum 什么时候反而有优势

**C. 阶段式 curriculum 并不是错方案。它在以下情况可能更好：**

**存在真正的前置技能关系。** 例如模型必须先掌握基本格式、工具定义或简单推理，才能理解复杂组合任务。Skill-It 研究发现，技能之间可能存在可利用的依赖关系，按技能前置关系安排数据和动态采样，可以比均匀采样更高效。citeturn7view1

**早期数据主要用于建立表示，后期任务没有改变输出契约。** 比如先学通用语言，再学领域术语；两阶段的 chat template、字段定义和序列化方式完全一致。此时后段更接近“内容域适配”，而不是“行为接口替换”。

**阶段切换不是硬切。** 更稳的做法是：

\[
100\%\ \text{普通}
\rightarrow
80/20
\rightarrow
60/40
\rightarrow
70/30
\]

而不是：

\[
100\%\ \text{普通}
\rightarrow
100\%\ \text{特殊}
\]

也就是可以逐步增加特殊数据，但始终给普通数据保留采样下限，并在结束前重新平衡。

**特殊能力与普通能力高度冲突。** 如果同一个输入在普通任务和特殊任务中确实要求不同输出规则，那么分阶段、独立 adapter、显式任务标签或路由 expert 可能比无条件混在一起更清楚。问题不在“阶段式”三个字，而在于模型有没有可靠信号判断当前应该使用哪套规则。

**课程只作为 warm-up。** 2025 年对 0.5B、1B 模型进行的 200 多组课程学习实验发现，某些 interleaved curriculum 可以提高收敛速度，但效果强烈依赖难度指标；更稳定的组合之一是先进行 curriculum warm-up，再回到随机混合训练。citeturn10view0turn10view1turn10view3

## 特殊数据的比例、重放与 schema 管理

### 推荐比例不是固定答案，而是一条搜索路径

**D. 对你们这类结构化 SFT，本报告建议按“输出 token 占比”而不是“样本条数”控制特殊数据。**

样本条数容易误导。例如特殊样本平均输出 600 tokens，普通样本平均只有 150 tokens，那么按样本 10% 混合，特殊目标 token 实际可能接近 31%。

设真实生产中特殊情况的 token 占比为 \(p_0\)。建议从下面的搜索点开始：

\[
p \in
\{
p_0,\ 
\max(5\%,1.5p_0),\
\max(10\%,2p_0),\
20\%
\}
\]

不必全部训练到终点，可以先用 10%–20% 的训练预算和代理模型筛选，再让优胜比例跑完整训练。

对多数“长尾但重要”的特殊情况，可采用以下起步规则：

| 情况 | 建议起始特殊 token 比例 |
|---|---:|
| 生产真实占比低于 1%，风险一般 | 2.5%–5% |
| 生产占比约 1%–5%，业务重要 | 5%–10% |
| 特殊能力明显不足，标注质量很高 | 10%–15% |
| 高风险异常处理、必须显著召回 | 可测试 15%–20% |
| 超过 20% | 只有 Pareto 结果证明安全后再使用 |

这不是论文给出的通用定律，而是结合遗忘、数据混合和工业实践得到的保守工程区间。Llama 3 的后段实验使用过 30% 新数据与 70% 默认 mixture，但其任务规模、模型容量和训练目标与小模型 SFT 不同，不能把 30% 当作通用答案。citeturn5view0

🔥 **“轻微 oversample”建议先定义为真实占比的 1.5–2 倍，并把特殊 token 总占比暂时封顶在 10%–20%。**

### 不要只按高 loss 挖困难样本

Hard example mining，也就是“多训练模型最容易错的样本”，对提升特殊能力很有用，但单纯按 loss 排序很危险。高 loss 的样本可能是：

- 真正困难；
- 标注错误；
- schema 不一致；
- 输入信息不足；
- 输出存在多个等价答案；
- 被截断；
- 特殊模板与普通模板冲突。

LESS 的做法不是简单重复高 loss 样本，而是用梯度相似性寻找对目标验证集最有帮助的数据；在其定向指令微调实验中，选取约 5% 数据就能超过使用全部数据的方案。citeturn11search0 DEITA 则同时考虑复杂度、质量和多样性，说明“困难”必须与可靠性、覆盖度一起筛选。citeturn11search13

更适合你们的特殊样本选择分数是：

\[
S(x)=
\text{特殊集收益}(x)
-\lambda_1\text{普通集伤害}(x)
-\lambda_2\text{格式污染风险}(x)
\]

实际不一定逐样本计算完整影响函数，可以用代理指标近似：

- 当前模型是否确实答错；
- 标注是否通过 schema 与业务规则双重校验；
- 与已有特殊样本是否重复；
- 是否包含新的特殊子类型；
- 单独加入小批训练后，普通验证集 loss 是否明显上升；
- 是否带有特殊集独有的字段顺序、话术、空值策略或结束模板。

### replay buffer 应该保留什么

无法改成全程混训时，可以在 stage2 中加入普通样本 replay。重放研究普遍显示，混入旧数据能减轻连续微调中的遗忘；更近期的研究还发现，预训练数据 replay 有时不只是保护旧能力，也能提高目标任务的数据效率。citeturn0search11turn3search1turn3search4

建议 replay buffer 不要纯随机抽取，而要覆盖：

- 高频普通场景；
- 曾被特殊训练污染过的普通场景；
- 字段齐全、fact 较多的样本；
- 与特殊场景表面相似，但应走普通路径的 hard negatives；
- 长输出与短输出；
- 各主要 schema 子类型。

如果必须采用“普通 → 特殊”流程，stage2 可以从下列配比起测：

\[
\text{普通 replay}:\text{特殊}
=
70:30,\ 50:50,\ 30:70
\]

纯特殊作为风险对照组，而不应默认直接上线。

### schema 稍有变化时会发生什么

**F 前的关键风险：特殊数据不仅内容难，而且 schema 或字段顺序也变化时，模型会同时学习“任务切换”和“接口切换”。**

这会产生几类问题。

**条件耦合。** 模型可能把某个特殊内容特征与另一套字段顺序绑定。之后只要普通样本里出现相似词，就切到特殊模板。

**多模态目标冲突。** 对自回归模型而言，下面两种 JSON 虽然语义相同：

```json
{"answer":"A","facts":["F1"],"status":"ok"}
```

```json
{"status":"ok","facts":["F1"],"answer":"A"}
```

但它们是两条不同的 token 序列。训练目标不会自动把它们视为等价。训练数据如果没有显式说明“顺序可变”，模型只能从频率学习哪种前缀更常见。

**早期字段影响后续生成。** 自回归生成是逐 token 展开的。第一个字段变了，后续每一步的条件上下文也随之变化。因此，字段顺序差异不只是外观差异，还会改变后续字段被生成、遗漏或提前终止的概率。

**有效 JSON 掩盖内容退化。** 特殊阶段可能让 `{`、引号、冒号、固定键名等局部 token 更稳定，JSON parse rate 因此上升；但事实选择和完整性没有同步提高，甚至下降。结构化输出研究已经表明，没有专门覆盖 schema 变化的数据时，模型对新 schema 的泛化并不可靠。citeturn6search9turn6search14

因此应明确区分两种产品需求：

- **字段顺序属于契约。** 那么全量教材必须 canonicalize，也就是统一成唯一顺序。
- **字段顺序不属于契约。** 那么评测不应把顺序当错误；训练中可以有受控的顺序增强，但普通与特殊样本必须使用同一套增强策略，不能让顺序成为特殊标签。

建议在数据进入训练前强制完成这些检查：

| 项目 | 必须统一的内容 |
|---|---|
| chat template | system、user、assistant 包装与角色 token |
| schema 版本 | 字段名、字段类型、required/optional |
| 字段顺序 | 固定顺序，或普通特殊共同随机化 |
| 缺失值 | 省略、`null`、空数组、空字符串只能选一套规则 |
| 转义 | 引号、换行、Unicode、反斜杠 |
| 数值格式 | 整数、浮点、小数位、字符串数字 |
| 结束方式 | EOS、stop token、代码块标记 |
| fact 规则 | 必填事实、最少数量、去重方式 |
| 错误输出 | 不得把历史模型的异常结果当黄金答案 |

## LoRA 与全参数微调的覆盖效应

LoRA 冻结原始权重，只学习低秩增量矩阵，因此它通常比全参数微调更限制参数改动范围，也更容易保留一个可随时卸载的底座。citeturn13search0

但这不能推导出“LoRA 不会覆盖”。

研究显示，LoRA 同样会发生灾难性遗忘，遗忘程度会随可训练参数规模、LoRA rank 和训练步数变化。近期多项工作之所以专门提出 LoRA-Null、OPLoRA、CURLoRA 等方法，正是因为普通 LoRA 没有显式机制保证更新方向不干扰旧知识。citeturn7view5turn13search2turn13search6turn13search17

对你们的情况，需要区分三种部署方式。

### 同一个 LoRA 连续训练

```text
base
  + LoRA 普通数据
  → 同一 LoRA 继续训练特殊数据
```

这种方式仍然存在明显的新近覆盖。底座虽然没变，但 adapter 内部的普通行为会被特殊阶段更新。

### stage1 全参数，stage2 LoRA

```text
base
  → 普通 SFT 得到 stage1
  → 在 stage1 上挂 LoRA 学特殊数据
```

这通常比 stage2 全参数微调更容易回退，因为可以卸载 LoRA。但开启 LoRA 后，生成行为仍可能被其增量强烈改变，合法 JSON、字段顺序和遗漏模式依然可能被 adapter 支配。

### 普通与特殊使用独立 LoRA

```text
base/stage1
  ├─ ordinary adapter
  └─ special adapter
```

隔离性最好，但需要可靠路由。若模型无法提前判断是否属于特殊场景，路由错误会成为新的主要问题。直接合并两个 adapter，也可能重新引入干扰。

**总体判断：**

| 对比项 | LoRA | Full fine-tuning |
|---|---|---|
| 底座权重改写 | 无或很少 | 全面改写 |
| 回退方便程度 | 高，可卸载 adapter | 低，需要保留 checkpoint |
| 末段输出行为覆盖 | 仍可能明显 | 通常更明显 |
| 学习复杂新能力的上限 | 可能受 rank 限制 | 通常更高 |
| 持续训练同一模块时的遗忘 | 会发生 | 会发生 |
| 适合的比较方式 | 在相同目标能力下比较旧能力回退 | 同左 |

⚠️ 不要用“相同学习率”直接比较 LoRA 与 full FT。两者有效更新规模不同。更合理的是让二者达到相近的特殊集语义能力，再比较谁的普通集回退、格式污染和 leakage 更少。

## 严格对照实验设计

**E. 建议做一个以 token 暴露量为核心的三组实验。**

设：

- 普通训练数据为 \(D_o\)；
- 特殊训练数据为 \(D_s\)；
- 合并数据中，特殊目标 token 的自然占比为 \(p\)；
- 总训练更新次数为 \(T\)；
- 每次更新的有效 token 数为 \(B\)。

三组都使用相同初始 checkpoint、总更新数 \(T\)、总训练 token 数 \(BT\)、最大长度、batch packing、优化器、学习率曲线和随机种子集合。

### 训练组定义

| 组别 | 训练安排 | 目的 |
|---|---|---|
| Sequential | 前 \((1-p)T\) 步只训练普通数据，后 \(pT\) 步只训练特殊数据 | 测试顺序与末段覆盖 |
| Mixture | 全程每个窗口按 \(1-p:p\) 分层混合 | 同数据、同暴露量，只改变顺序 |
| Mixture + mild oversample | 全程按 \(1-p':p'\) 混合，\(p'>p\) | 测试特殊数据加权是否值得 |

第三组建议先设：

\[
p'=\min(\max(1.5p,\ p+2.5\%),\ 20\%)
\]

如果自然占比很低，例如 \(p=1\%\)，可直接测试 5% 与 10%，否则“1.5 倍”仍然太少。

### 公平性控制

**按 assistant target tokens 计数。** 不要只保证样本条数相同。

**Sequential 和 Mixture 的普通、特殊 token 总暴露量必须相同。** 两组区别只能是顺序。为此应保存 exposure ledger，记录每个数据源、子类型、schema 和样本的实际训练次数。

**不在阶段切换时重置学习率或优化器。** 否则 Sequential 的 stage2 同时获得“数据顺序变化”和“学习率重启”两种优势，无法归因。

**全组使用相同全局学习率曲线。** 如果使用 cosine decay，特殊数据在 Sequential 中恰好落在低学习率区间，也会成为干扰因素。最干净的主实验可以采用共同 warm-up 后的恒定低学习率；再额外跑一组生产实际 scheduler 作为外部有效性验证。

**至少三个随机种子，最好五个。** 小数据阶段方差通常很大，只看一个 seed 很容易把偶然结果当结论。

**不只评估 final checkpoint。** 推荐在以下位置保存 checkpoint：

- 训练开始；
- 25%、50%、75% 总步数；
- Sequential 切换前；
- 切换后经过特殊阶段的 5%、10%、25%、50%、100%；
- Mixture 两组在对应全局 step 的 checkpoint。

这样可以看到普通能力是在切换后立刻掉，还是随着特殊重复次数逐步掉。

### 数据准备

三组使用同一份经过 canonicalization 的训练数据：

```text
同一 chat template
同一 schema 版本
同一字段顺序规则
同一 required/optional 规则
同一 null/省略规则
同一转义方式
同一 stop/EOS
```

训练前额外构造四类反事实样本，用于评测而不是训练：

| 评测类型 | 示例目的 |
|---|---|
| 普通内容 + 特殊关键词 | 看是否被表面关键词误触发特殊格式 |
| 特殊内容 + 普通表达方式 | 看模型是否真正理解特殊条件 |
| 相同内容 + 输入字段顺序变化 | 看是否依赖输入位置 |
| 相同语义 + 输出 schema 版本变化 | 看能力是否与固定序列绑死 |

### 建议增加的诊断组

预算允许时，可加一个不参与三组主结论的诊断组：

```text
Sequential + 30% ordinary replay
```

即 stage2 使用 70% 特殊、30% 普通 replay。

它能回答一个很实用的问题：

> Sequential 的问题来自“阶段顺序本身”，还是主要来自“stage2 完全看不到普通数据”？

如果加少量 replay 就大幅恢复普通能力，说明没有必要彻底否定 staged 流程，保留普通分布约束即可。

## 如何判断是在补能力，还是在改坏输出习惯

**F. 不能把所有指标压成一个 JSON exact match。至少要拆成语义、结构、习惯、迁移和保留五层。**

### 特殊语义能力

这一层只回答：模型是否更会处理特殊情况。

- 特殊子类型 macro accuracy；
- 特殊条件识别 precision、recall、F1；
- 关键事实 fact recall；
- 事实 precision；
- 数值、实体、日期等槽位准确率；
- 多事实完整率；
- 冲突信息处理准确率；
- 不确定条件下的校准；
- 每个特殊子类型的最差组表现。

这里应尽量把解析失败与语义失败分开。例如先用宽松解析器抽取字段，再评事实；否则一个逗号错误会被误判成“所有事实都错”。

### Schema 与序列化能力

这一层只看机器接口是否正确。

- JSON parse rate；
- JSON Schema pass rate；
- required-key recall；
- extra-key rate；
- 字段类型准确率；
- enum 合法率；
- 嵌套层级准确率；
- 转义错误率；
- 尾部多余文本率；
- 提前截断率；
- canonical key-order exact rate。

如果字段顺序属于硬契约，还应计算 key-order edit distance 或 Kendall 距离；如果不属于契约，则不应把等价顺序算作语义错误。

### 内容完整性

这一层用于识别“JSON 更合法，但 fact 更少”。

建议单独统计：

\[
\text{Fact Recall}
=
\frac{\text{正确输出的必需 facts}}
{\text{黄金答案中的必需 facts}}
\]

以及：

- 平均遗漏 fact 数；
- 至少漏一个 fact 的样本比例；
- valid JSON 条件下的 fact recall；
- schema-valid 但语义不完整的比例；
- 输出长度与 fact 数的关系；
- 多字段之间的逻辑一致性；
- 幻觉 fact 数。

🔥 最关键的交叉指标是：

\[
P(\text{fact complete}\mid \text{schema valid})
\]

它能直接揭示“合法 JSON 增加是否只是外壳改善”。

### 坏习惯与跨场景泄漏

这一层最能判断特殊教材是否把模型教偏。

- 普通样本误用特殊字段的比例；
- 普通样本切换到特殊字段顺序的比例；
- 没有触发条件时输出特殊模板的比例；
- 异常前缀、后缀、解释文本、代码块出现率；
- 多余道歉、拒绝、免责声明或固定话术出现率；
- 特殊样本中的省略习惯向普通样本扩散的比例；
- 输入只改变关键词时，输出格式突变率；
- 生成长度分布变化；
- EOS 提前率；
- 重复键、重复字段、重复 fact 比例。

可专门定义一个 **format leakage rate**：

\[
\text{Leakage}
=
P(
\text{出现特殊格式特征}
\mid
\text{普通场景}
)
\]

这通常比普通集整体 exact match 更敏感。

### 主分布能力保留

至少保留一个冻结的 ordinary holdout，且不能用于 ratio 调参。

需要比较：

- 普通集 exact match、F1；
- 普通集 fact recall；
- 普通集 schema pass rate；
- 普通长尾子集；
- 与特殊情况表面相似的 hard-negative 子集；
- stage1 与当前模型在普通集上的 NLL 差值；
- 输出分布 KL divergence；
- 相对 stage1 的最大下降和最终下降；
- 各普通子类型的 worst-group regression。

连续微调研究说明，平均分可能掩盖某些能力簇的大幅遗忘，因此不能只看一个总平均。citeturn13academia26turn7view5

### 鲁棒性与 schema 泛化

推荐至少做以下扰动：

- 改写提示但保持语义；
- 调换输入字段顺序；
- 添加无关字段；
- 删除可选字段；
- 更换实体、数值和文本长度；
- 使用未见过的特殊组合；
- 在普通与特殊边界附近构造对抗样本；
- 在允许的情况下更换等价 JSON 空白与转义；
- 对受约束解码和自由解码分别评测。

受约束解码能强制 JSON 合法，但不能补回漏 fact。如果 constrained decoding 后 schema pass 达到接近 100%，fact recall 仍然下降，说明问题在内容选择或训练分布，不在括号和引号。

### 用 Pareto 前沿而不是单一总分选模型

模型选择建议设置硬性护栏：

```text
特殊语义能力：必须显著提高
普通 fact recall：下降不超过 0.5–1.0 个百分点
普通 schema pass：不得下降
format leakage：不得高于 stage1 + 预设容忍值
漏 fact 率：不得恶化
```

具体容忍值要按业务成本确定。高风险结构化输出可以更严格。

然后画三条轴：

\[
\text{特殊能力提升}
\quad
\text{普通能力保留}
\quad
\text{坏习惯泄漏}
\]

一个模型只有在特殊能力提高，同时没有被另一模型在“普通保留”和“泄漏”上全面压过时，才进入 Pareto 前沿。

可以再定义一个用于排序、但不替代原始指标的效用：

\[
U =
G_{\text{special}}
-\lambda_g R_{\text{general}}
-\lambda_f D_{\text{fact}}
-\lambda_l D_{\text{leakage}}
-\lambda_s D_{\text{schema}}
\]

其中：

- \(G_{\text{special}}\)：特殊语义能力增益；
- \(R_{\text{general}}\)：普通能力回退；
- \(D_{\text{fact}}\)：fact 遗漏增加；
- \(D_{\text{leakage}}\)：特殊习惯向普通场景泄漏；
- \(D_{\text{schema}}\)：结构错误增加。

**最终判定可以直接用下面这张表：**

| 观察结果 | 更可能的解释 |
|---|---|
| 特殊语义上升，普通能力稳定，leakage 稳定 | 真正在补能力 |
| JSON pass 上升，但 fact recall 下降 | 主要学会了外壳格式 |
| 特殊集提高，普通相似场景大量切换格式 | 学会了过宽的触发规则 |
| 特殊集提高，普通所有类型都下降 | 灾难性遗忘或整体分布漂移 |
| 字段顺序改变，但语义不变 | schema 风格专业化 |
| 自由解码差、受约束解码好，fact 不受影响 | 主要是序列化问题 |
| 受约束解码后仍漏 fact | 内容选择或训练目标问题 |
| Sequential 差、同 token Mixture 好 | 顺序和新近效应是主要原因 |
| Mixture 与 Sequential 都差 | 数据本身、schema 冲突或学习率更可疑 |
| 轻度 oversample 最好，继续加权开始回退 | 已找到能力与污染之间的拐点 |

综合现有研究与工业公开经验，最合理的默认方案是：

> **统一 schema 的全程分层混训，以真实分布为基线，特殊 token 从 5%–10% 或自然占比的 1.5–2 倍起测；任何训练后段都不让普通数据占比降到零。用语义能力、fact 完整率、schema 合法率和跨场景格式泄漏四组指标共同选 checkpoint。**

这套方案不能保证特殊教材完全不产生副作用，但它能把“特殊能力学习”从一次末段覆盖，变成一个持续受到主分布约束的权衡过程。
