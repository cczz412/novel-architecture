✅ 结论：这组结果已经能说明“模型学到了一部分可迁移的任务行为”，但还不能证明它学会了普遍的语义规则，更不能证明获得了预训练阶段没有的新能力。

更准确的说法是：

> 24 条 SFT 很可能把 Qwen3 原来就有的阅读、指代消解、事实抽取能力，接到了你们定义的任务格式、证据表示和输出标准上。

当前最符合证据的解释顺序是：

1. 重新激活并组合已有的语义抽取能力；
2. 学会任务接口、输出格式和判断阈值，也就是 behavioral steering；
3. 在已有表征里学到一个窄任务决策规则；
4. 形成低维的权重变化，可描述为 task vector；
5. “产生了全新语义能力”——目前证据最弱。

## A. 当前 24 TRAIN + 24 DEV 能证明什么

如果 TRAIN、DEV 确实没有片段、事实或近似改写泄漏，那么它能支持这些结论：

| 说法                                   | 当前支持程度 |
| -------------------------------------- | ------------ |
| 不只是在逐字复述 TRAIN 答案            | 较强         |
| 能迁移到新人物、新场景、新措辞         | 中等偏强     |
| 学会了同一生成流程下的任务行为         | 较强         |
| 学会了跨风格、跨事实类型的通用抽取规则 | 证据不足     |
| 可以迁移到真实小说                     | 尚未证明     |
| SFT 创造了预训练阶段没有的能力         | 尚未证明     |
| 76.92% 是稳定、可复现的真实性能        | 尚未证明     |

🔥 目前缺少的最关键数字不是更多 checkpoint，而是：

- 关闭 LoRA 后，同一 DEV24 的 F1；
- 只有任务说明、没有 SFT 的 prompt-only F1；
- 4/8/24-shot ICL 的 F1；
- 至少 5 个训练随机种子的均值、标准差；
- A_FULL 是否根据 DEV24 选出来；
- 一共比较过多少 checkpoint、证据表示、学习率和提示词。

没有 adapter-off 基线，就不能判断 76.92% 中有多少来自 SFT。比如原模型已经有 70%，这说明 SFT 主要在修格式；如果原模型只有 20%，结论会强很多。

DEV 只有 24 个片段。哪怕把每个片段粗略看成一次独立成败，76.9% 的 95% 误差范围大约是 ±17 个百分点。48 条事实也不能简单当作 48 个独立样本，因为同一片段里的事实共享难度、文风和上下文。

C2_FULL、E_UNIT_QUOTE、D_RANGE 等如果都在同一个 DEV24 上比较，然后选最高分，它们不是多份独立证据，而是“对同一批样本看了很多次”。最高的 89.36% 会带有明显的优胜者偏差。

## B. 为什么 tiny SFT 能产生这么明显的迁移

其实核心就一件事：模型不是从 24 条数据开始学中文和小说理解，而是在一个已经读过海量文本的模型上，学习“这里究竟要我抽什么、按什么格式交出来”。

几项研究和你们的现象很接近：

- [LIMA](https://arxiv.org/abs/2305.11206) 用 1,000 条精心选择的数据训练 65B 模型，可以与用 52,000 条数据训练的 Alpaca 竞争。它还发现：
  - 增加 30 条多轮对话，优秀对话比例从 45.2% 升到 76.1%；
  - 某些复杂格式，6 条示例就可能决定模型会不会输出；
  - 同一来源的数据从 2,000 增到 32,000，效果趋于平台；
  - 输入多样性比重复增加同类输入更有用。
- [T-Few](https://arxiv.org/abs/2205.05638) 在每个真实任务只有 50 条训练数据、没有验证集的 RAFT 上达到 75.8%，超过当时 GPT-3 few-shot 和人类基线。它用的是另一种参数高效微调方式，但证明了“几十条适配强预训练模型”确实可能有效。
- [LM-BFF](https://aclanthology.org/2021.acl-long.295/) 报告，提示式微调只用 32 条数据，也能在多个二分类任务达到约 90% 准确率。
- [Intrinsic Dimensionality](https://aclanthology.org/2021.acl-long.568/) 发现，预训练模型适配某些 NLP 任务时，真正需要改变的有效方向可能很少；一个 RoBERTa 任务甚至只调整约 200 个投影参数，就能达到完整微调约 90% 的表现。
- [LoRA 原论文](https://arxiv.org/abs/2106.09685) 也观察到任务适配的权重变化存在明显低秩结构。你可以直接理解成：模型不用重新装修整栋楼，只要调整少数几个控制旋钮。

还有三个容易忽略的因素：

- 一条 SFT 样本不是只有一个训练信号。输出中的每个 token 都会产生损失，所以 24 条长答案可以提供大量相互关联的格式和内容信号。
- 72 次 update 可能让同一数据被重复看很多遍。update 数不等于独立样本数，但足以强烈改变输出概率。
- LoRA rank 32 并不代表只有 32 个参数。它是每个被适配权重的更新秩为 32，整个模型加起来仍可能有数百万个可训练参数，完全有能力同时记忆和迁移。

少量数据改变行为的极端例子也很多。[Qi 等人的研究](https://arxiv.org/abs/2310.03693)显示，仅 10 条精心构造的数据就能明显破坏模型的安全拒答行为。不过这只证明模型行为很容易被转向，不证明它学会了新规则。

### 这些概念该怎么归类

| 概念                               | 对 MICRO24 的适用程度                                        |
| ---------------------------------- | ------------------------------------------------------------ |
| in-context-like task specification | 可以当作类比。SFT 像把 few-shot 示例压进权重，但严格说不是 ICL，因为推理时没有示例、权重已经变化 |
| behavioral steering                | 最准确：改变了抽什么、怎么答、何时输出证据                   |
| task vector                        | 可以描述 LoRA 的权重差；但光有迁移分数不能证明 task vector 是因果机制 |
| 重新激活已有能力                   | 最可能：阅读、指代、关系理解和抽取早已存在                   |
| true capability learning           | 工程意义上任务能力确实提高；如果指“学出全新的语义算法”，证据不足 |
| model editing                      | 不太合适。ROME、MEMIT 一类方法主要写入或修改具体事实；你们 DEV 事实没参加训练，更像任务适配而不是事实编辑。[ROME](https://arxiv.org/abs/2202.05262)可作对照 |

ICL 和权重空间里都有人观察到 task vector：[In-Context Learning Creates Task Vectors](https://arxiv.org/abs/2310.15916)研究的是激活中的任务向量；[Editing Models with Task Arithmetic](https://arxiv.org/abs/2212.04089)研究的是微调前后的权重差。两者不是同一个东西。

要专门验证 task-vector 解释，可以把 LoRA 强度按 `0、0.25、0.5、1.0、1.5` 缩放。如果目标行为随强度平滑增强，而无关任务基本稳定，说明适配更像一个连贯的行为方向。不过这依然不能区分“新能力”和“激活旧能力”。

## C. 怎么判断是不是泄漏、模板或 evaluator 偏差

建议把当前 DEV24 全部人工复核。只有 24 条，做两位盲评员的 TP、FP、FN 标注，成本很低，价值比再跑几十个 checkpoint 高。

### 数据泄漏排查

- 检查原文、标准化文本和答案的精确重复。
- 做字符 n-gram、MinHash 或 embedding 最近邻检查，找近似改写。
- 检查人物名字替换后，故事骨架是否仍与 TRAIN 相同。
- 同一 seed、同一故事提纲、同一 minimal pair 的兄弟样本必须放在同一个 split。
- 如果生成 DEV 时把 TRAIN 示例放进了生成提示，检查生成器是否只是换名字重写。
- 确认训练 manifest 中只出现 TRAIN ID，DEV 没参与数据整理、早停、梯度计算或 prompt 搜索。
- 如果 evaluator 或 gold label 由同一个模型生成，人工检查它是否偏爱自己的措辞。

“原创合成”只能降低预训练时见过原文的概率，不能排除 TRAIN/DEV 共享生成模板。

### 最有诊断力的对照实验

| 实验                             | 如果仍然高分，说明什么                          |
| -------------------------------- | ----------------------------------------------- |
| adapter 关闭                     | 原模型已经具备大部分能力                        |
| 明确任务说明、无示例             | 主要缺的是任务说明                              |
| 4/8/24-shot ICL                  | SFT 可能只是把 ICL 固化进权重                   |
| 输出格式训练正确，但事实标签随机 | 若 DEV 仍明显提高，收益主要来自格式或 evaluator |
| TRAIN 的输入和答案随机错配       | 若仍提高，优先怀疑泄漏、模板或评分器            |
| 只改人物名字                     | 检验实体记忆                                    |
| 交换施事者和受事者               | 检验关系方向                                    |
| 把肯定改成否定                   | 检验真正的语义响应                              |
| 加入无关干扰句                   | 检验输出是否保持不变                            |
| 设置完全无事实的片段             | 检验假阳性和拒答能力                            |
| 同一故事只改一个事实             | 输出必须只跟着那一个事实变化                    |

这种“只改变一个关键因素、正确答案随之翻转”的样本叫 minimal pair。它比再生成几十条随机故事更能区分规则和模板。[Contrast Sets](https://aclanthology.org/2020.findings-emnlp.117/)和[CheckList](https://aclanthology.org/2020.acl-main.442/)都强调了这种行为测试思路。

如果 Semantic Fact F1 里用了 LLM judge，要额外检查长度、措辞、自家模型偏好等影响。LLM judge 已知存在位置、冗长和自我偏好问题，即使强 judge 与人类整体一致率不错，也会系统性误判部分样本。[MT-Bench/Chatbot Arena 的评估研究](https://papers.nips.cc/paper_files/paper/2023/hash/91f18a1287b398d378ef22505bf41832-Abstract-Datasets_and_Benchmarks.html)有详细分析。

建议固定 24 条输出，做：

- 当前 evaluator；
- 一个不同家族的 evaluator；
- 两位不知道模型版本的人类标注；
- 严格字符串/结构解析分；
- 去掉格式影响后的语义分。

如果不同 evaluator 相差超过 5～10 个百分点，先修评估，不要继续扩大训练。

### TRAIN F1 接近或低于 DEV F1，并不自动说明泛化特别好

常见原因有：

- 24 个 DEV 恰好更容易；
- TRAIN 标签更复杂、更含糊；
- checkpoint 或证据表示是在 DEV 上选的；
- 训练优化的是 teacher-forced token loss，测试用的是自由生成 F1，两者不是一个指标；
- 推理有温度、采样或非确定性；
- TRAIN 和 DEV 的事实数、答案长度、证据格式不同；
- evaluator 对 DEV 的表达更友好；
- 单次随机种子运气好。

小数据微调对初始化、样本顺序和随机种子可能很敏感。[Dodge 等人](https://arxiv.org/abs/2002.06305)在 2,100 次试验中观察到，同一配置只换随机种子也会出现明显性能差异。

## D. 下一批应该增加什么

🔥 优先顺序不是“文风还是数量”二选一，而是：

1. 标签正确性；
2. 语义与决策边界覆盖；
3. 输入多样性；
4. 当前模型会失败的难度；
5. minimal pairs；
6. negative/no-answer 样本；
7. 输出格式一致性。

输出格式应该保持统一，输入表达应该主动变化。LIMA 的经验也是“多样输入、统一高质量输出”。

下一批 24 条可以这样分：

- 8 条新语义类型：
  - 否定；
  - 不确定、传闻、猜测；
  - 时间变化；
  - 多人同名或复杂指代；
  - 关系方向；
  - 跨句事实；
  - 对话归属；
  - 旧事实被后文修正。
- 8 条决策边界样本：
  - 4 组 minimal pairs，共 8 条；
  - 每组只改一个人物、关系、否定词或时间点；
  - 加入“没有目标事实”“只有干扰事实”的例子。
- 8 条文风变化：
  - 第一人称；
  - 对话密集；
  - 自由间接引语；
  - 长句；
  - 倒叙；
  - 描写性文本；
  - 信息出现在段落尾部；
  - 不同生成器或人工改写。

❌ 不建议下一步直接生成 500 条同一提示模板的普通片段。

与“少而精”有关的研究很多，但没有一篇能直接证明“Qwen3-4B 上 24 条小说事实抽取一定等价于 500 条普通样本”。最接近的证据是：

- [AlpaGasus](https://arxiv.org/abs/2307.08701)：从 Alpaca 52K 里筛出 9K 高质量数据，反而表现更好；
- [LESS](https://arxiv.org/abs/2402.04333)：选择与目标任务梯度更相关的 5% 数据，常能超过全量训练；
- [DEITA](https://arxiv.org/abs/2312.15685)：用质量、复杂度和多样性选择 6K 数据，达到或超过使用十倍以上数据的模型；
- [Data Diversity Matters](https://arxiv.org/abs/2311.14736)：多样性主要改善平均和最差场景表现，也就是鲁棒性；
- 大规模场景的后续研究也发现，复杂数据选择方法并非总能胜过随机选择，所以 LESS 不是普遍定律。[Large-Scale Data Selection](https://arxiv.org/abs/2503.01807)

Phi、“textbook quality”说明高质量合成数据可以显著提高数据效率，但 [phi-1](https://arxiv.org/abs/2306.11644) 用的是数十亿 token 的预训练和约 1.8 亿 token 的练习微调，不能直接拿来证明 24-shot SFT。

对你们更有用的两点来自：

- [Distilling Step-by-Step](https://arxiv.org/abs/2305.02301)：增加高信息量的解释或推理监督，可以用更少数据超过普通微调；
- [Self-Instruct](https://arxiv.org/abs/2212.10560)：生成后必须过滤错误和过度相似样本，任务多样性是关键。

你们的 evidence 字段可能正起到额外监督作用。如果 quote/range 不只是格式，而是明确告诉模型“证据在哪里”，一条样本的信息量会高于只有最终答案的样本。

## E. 进入真实小说前，再增加多少合成样本

✅ 建议只再增加 24 条高信息量合成训练样本，把 TRAIN 从 24 扩到 48。

不要为了凑数直接去 96 或 500。训练时做嵌套对比：

- TRAIN 6；
- TRAIN 12；
- TRAIN 24；
- TRAIN 48。

每档至少跑 3 个种子，24 和 48 最好跑 5 个。

48 条实验还要分两种计算方式：

- 固定总 update 数，例如都跑 72 次，用来观察新增覆盖的效果；
- 固定 epoch 数，让 48 条获得更多 update，用来观察真实训练收益。

不这么分，就无法判断提升来自更多独立数据，还是单纯多算了一倍。

只有出现下面情况，才考虑把合成 TRAIN 增到 96：

- 48 条仍缺很多事实类型；
- minimal pair 仍系统性失败；
- 新增 24 条在困难语义上继续明显提高；
- 真实小说样本暂时无法标注。

否则 48 后就应该切到真实小说。合成数据可以继续保留，用来补罕见语义、构造反例和做回归测试，但不应继续作为主体。

## F. DEV 什么时候不再是真正 holdout，Set C 要多大

DEV 一旦影响了任何选择，它就是开发集，不再是无偏测试集。包括：

- 选 checkpoint；
- 选 LoRA rank、学习率、update 数；
- 选 evidence 表示；
- 改 prompt；
- 改生成数据的提示；
- 改 evaluator 或阈值；
- 根据错误类型决定下一批训练数据。

哪怕只看总分，没有看具体样本，也已经泄露了一些信息。[True Few-Shot Learning](https://arxiv.org/abs/2105.11447)专门指出，大量依赖验证集选择配置会高估 few-shot 能力；自适应反复使用 holdout 也很容易让方案逐渐过拟合该集合。[Reusable Holdout](https://proceedings.neurips.cc/paper/2015/hash/bad5f33780c42f2588878a9d07405083-Abstract.html)

### Set C 样本量

| 独立 case 数 | 76.9% 附近的粗略 95% 误差 |
| ------------ | ------------------------- |
| 24           | ±17 个百分点              |
| 68           | ±10 个百分点              |
| 96           | ±8～9 个百分点            |
| 144          | ±7 个百分点               |
| 272          | ±5 个百分点               |

F1 不是普通成功率，所以正式报告要按“片段”为单位做成组 bootstrap，而不是把每条事实当独立样本。建议做 10,000 次配对重采样，同时报告：

- 微平均 F1；
- 按片段平均；
- 按事实类型平均；
- precision、recall 和原始 TP/FP/FN；
- 相对 adapter-off 基线的 F1 差值及置信区间；
- 5 个训练种子的分布。

✅ 最节省成本但仍可信的选择：Set C 做 96 个 case。

推荐组成：

- 24 个新生成流程下的同分布合成样本；
- 24 个困难合成样本，包含 minimal pair、否定、干扰和 no-answer；
- 48 个真实小说片段，来自训练和 DEV 都没出现过的书、作者或章节来源。

真实片段应按“书或作者”分组，不要把同一本书相邻章节分进训练和 Set C。

如果你们准备发表“模型性能约为 77%”这样的精确数字，96 还不够，最好用 144；若希望误差接近 ±5 个百分点，需要约 272 个独立 case。

### Set C 什么时候打开

在下面这些都固定后才能打开：

- 唯一 checkpoint 和文件 hash；
- prompt、chat template、证据表示；
- tokenizer、截断长度、解码参数；
- evaluator 版本、提示和阈值；
- 指标计算代码；
- 成功标准；
- bootstrap 方法；
- 是否允许任何无效运行重试。

只打开一次。打开后如果根据结果继续修改模型，Set C 就变成新的 DEV；下一次确认必须再建 Set D。

## G. 最省成本的“24 → 48 → 真实小说”路线

### 阶段 1：把当前结果审计清楚

不新增训练数据，先完成：

- adapter-off、prompt-only、ICL 基线；
- DEV24 全量双人盲审；
- exact/near-duplicate 检查；
- 5 个训练种子；
- 成组 bootstrap；
- label-shuffle 和 4～8 组 minimal-pair 测试。

如果随机错配标签后仍有明显提升，暂停扩大训练，先查 evaluator 或流程。

### 阶段 2：TRAIN24 → TRAIN48

新增前面设计的 24 条高信息量样本。

通过标准建议预先写死，例如：

- 48 相对 24 在困难语义上有稳定提升；
- 至少 4/5 个种子优于 adapter-off；
- 配对 F1 差值的 95% 区间下界大于 0；
- 若你们要求“有实际价值”，可以把下界门槛设成 `+10pp`；
- 人工 F1 与自动 F1 相差不超过预定范围。

如果新增 24 条只提高格式正确率，对新事实类型和 minimal pair 没帮助，就不要再造合成数据。

### 阶段 3：尽快进入真实小说小试验

建议先标注：

- 24 个真实 TRAIN case；
- 24 个真实 DEV case；
- 按书或作者切分。

用 `48 synthetic + 24 real` 做混合训练，与以下版本对比：

- 48 synthetic；
- 24 real；
- 48 synthetic + 24 real。
