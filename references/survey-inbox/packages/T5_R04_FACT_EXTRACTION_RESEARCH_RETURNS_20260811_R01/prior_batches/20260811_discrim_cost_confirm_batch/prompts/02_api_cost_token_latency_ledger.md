背景（真实项目）：我们对多家中国商用 LLM API（火山方舟 Agent Plan 套餐、硅基流动按量计费等）做同题对照评测。上一轮的教训是：语义质量分都齐了，但每次调用的费用、Token、时延账没记全，导致最后无法做「质量×成本」的候选筛选——这个缺口再多审语义也补不上。下一轮开跑前要先把记账合同定死。

请调查并回答：

1. 公开基准（如 HELM、Artificial Analysis、各类 LLM leaderboard 的成本维度）对「每次调用记什么」的标准字段：输入/输出/思考(reasoning) Token 分账、缓存命中折扣、重试与失败调用怎么计入、限流等待算不算时延；
2. 跨平台价格归一化的通行做法：按百万 Token 单价换算的坑（阶梯价、思考 Token 单独计价、缓存价），「每任务成本 cost-per-task」和「达标质量下最低成本 cost@quality」哪个更适合选型；
3. 套餐制（额度包月）和按量计费混在同一张对照表里怎么处理才公平——套餐边际成本近零，但不能因此在表里记零成本；
4. 思考型模型（reasoning model）时延和 Token 的特殊坑：思考 Token 是否计费各家口径、同模型不同思考档要不要拆成不同条件；
5. 失败/空输出调用在成本账里的标准处理（记成本不记质量分？单列失败率？）。

期望产出：一张「每次调用最小必记字段清单」+ 归一化公式 + 失败处理规则，每条注明出处或行业惯例；能直接抄进我们的执行票。不需要评价任何具体模型好坏。
