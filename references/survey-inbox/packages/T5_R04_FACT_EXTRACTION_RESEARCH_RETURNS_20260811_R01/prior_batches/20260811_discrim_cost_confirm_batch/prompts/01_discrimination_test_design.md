背景（真实项目，中文网文事实抽取评测）：我们要从约 13~20 个商用 API 模型条件里筛出 3~5 个候选。已有两块旧材料的完整人工裁决（每块 225/337 个预测键全审），但按确定性区间支配判定，20 个模型组里 18 个仍分不开。我们准备了 4 章从未发给任何模型的新鲜章节做「判别卷」，任务形态是：给定章节正文+只读背景，模型按固定输出合同抽取事实句，与人工金标逐条比对，可算 Precision/Recall/F1、格式通过率、假事实率。预算级别：总调用数希望控制在一两百次以内。

请深度调查并回答：在「候选多、题目少、预算有限」的约束下，怎样设计一次小样本模型判别测试才能可靠分开头部模型？具体想要：

1. 学界/工业界在小样本模型排名上的成熟做法：配对比较（Bradley-Terry/Elo）、序贯淘汰、自适应选题（类似 IRT 的高判别力题目优先）各自适用条件；
2. 每个模型至少需要多少独立评测单元，排名才不至于被单章特性主导；bootstrap/置换检验给小样本排名置信区间的标准做法；
3. 题目难度不均衡的坑怎么防（比如某章天然事实密度高，会系统性抬高 Recall）；
4. 「先用少量题淘汰明显差的，再对头部加题加密」的两阶段设计有没有先例和标准停止规则；
5. 明确指出哪些结论只适用于人类偏好评测（如 Chatbot Arena 类），不能直接搬到我们这种「有金标的确定性打分」场景。

期望产出：一套能直接落到我们场景的设计规则（题目数、分配方式、置信判定、停止规则），每条附出处；以及「什么证据出现时应该放弃小样本判别、改为扩大题量」的红线。不要替我们选具体模型。
