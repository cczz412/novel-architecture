## 0. 依据、边界与推测说明

### 0.1 本文依据了哪些共同背景板文件

本文先读了 `00_READ_ME_FIRST.md`，再按本任务需要使用了以下背景板文件：`01_PRODUCT_NORTH_STAR.md`、`02_SYSTEM_ARCHITECTURE_AND_TRUTH_LAYERS.md`、`03_CREATION_AND_MEMORY_PIPELINES.md`。它们共同给出的对标尺子可以用大白话概括为：**产品帮作者导写和核对，不把代写书稿当主线；未来计划、已发生事实、临时查询结果和派生摘要不能混为一账；长期记忆要能回到冻结书稿中的证据；下一场只拿最小必要材料包。**

背景板还特别要求，长篇记忆不能退化为“把全书切块塞向量库”；远期压缩只能用来导航，遇到要紧结论仍须按需回捞冻结书稿。本文用这把尺子评价竞品，但**不把背景板当施工令，也不把它当任何训练、数据或正式结果的授权**。

### 0.2 事实、未找到与推测如何区分

本文只把公开官方页面或官方开源仓库明确写出的内容当作**已核验事实**；价格均按核验日页面显示，可能随地区、税费、促销和付费周期变化。某项机制没有在本轮官方公开材料中找到，就明确写 **“未找到”**，不由产品宣传语补全。

后文所有“对我们大纲中枢的启发”“应该偷师”“坚决不学”，均是**推测/产品判断**：它们由共同背景板的北极星与已核验竞品事实推导而来，不代表竞品官方主张，也不是已拍的实施方案。

### 0.3 研究范围

这里的“会动手”不是指普通问答聊天，而是指工具至少能直接操作一种叙事工件或上下文工件，例如：生成/改写场景，维护故事条目，编排大纲与时间线，或主动检索/注入长期记忆。为避免把产品混成一锅，下面分为三类：**写作 Agent/AI 写作工作台**、**大纲与世界观中枢**、**长程记忆机制/基础设施**。其中 Letta 与 SillyTavern 不是小说写作产品；它们入选只因为其公开记忆机制对长篇叙事系统有工程参考价值。

## 1. 先给结论：市场的空位在哪里

已核验的产品大多分别做好了一件事：NovelCrafter 和 Sudowrite 让 AI 更好地参与创作；Plottr、Campfire、World Anvil 让作者更好地维护大纲、条目和时间线；Letta、SillyTavern 则展示了常驻记忆、按需检索或动态注入的不同做法。[1] [3] [5] [7] [9] [12] [14]

但在本轮公开资料里，**没有看到哪一个产品同时把“未来计划—已发生事实—冻结原文证据—作者确认—受影响范围”做成一条可回验闭环**。多数“Story Bible/World/Lorebook”更接近有用的资料库或提示词上下文，而不是带证据、版本和确认闸的故事账本。这正是我们大纲中枢不应变成“又一个世界书”的原因。

| 类别 | 本轮代表 | 已经做得较好的部分 | 公开资料中未找到、也是我们的机会 |
|---|---|---|---|
| AI 写作工作台 | NovelCrafter、Sudowrite | 角色/地点等条目组织；从创意到大纲、场景、草稿的连续体验；AI 参与创作。 | 冻结书稿版本、逐条证据锚、已发生与计划硬分账、作者确认后才入正史的闭环。 |
| 大纲/世界观中枢 | Plottr、Campfire、World Anvil | 可视时间线、并行故事线、卡片/百科和多模块组织。 | 自动从书稿取证、状态/知情/因果账、变更影响传播与风险核对。 |
| 长程记忆机制 | Letta、SillyTavern | 常驻状态与按需检索分层；关键词触发与递归上下文加载。 | 叙事真值模型、证据等级、作者可见的确认与回滚流程。 |

## 3. 逐项拆解

### 3.1 NovelCrafter：最接近“小说工作台”，但 Codex 不是证据账

NovelCrafter 公开展示的核心是 Codex。它会给人物、地点、物品等建条目，并在写作时自动索引相关提及；名字、别名和昵称可被识别。作者还能查看一个元素在书稿、聊天、片段中的出现位置，并从书稿跳去相应 Codex 条目。[1] 这比“手填一堆人物卡”多了一层很重要的连接：**条目知道自己在文本里出现过哪里。**

它的 Progressions 值得特别看。官方说作者可以把某个细节绑定到时间线的不同位置，也可以用较新的 progression 覆盖过时的设定，让故事圣经维持在“当前时点”。[1] 对长篇连载而言，这正是“人物能力/身份/关系会随章节改变”的实际痛点。

但我们不能把它直接等同于背景板的长期底账。公开页能证明“出现位置”和“时间点更新”，不能证明每次改动都带版本、原文坐标、作者确认、来源强度，或能防止未来计划混入已发生事实。因此，值得偷师的是 **实体索引 + 状态演进 UI**；不能照搬的是“一个条目既存设定、又代表当前事实”的宽松语义。其月付方案从 US$4 到 US$20，AI 能力采用 BYOK，是“编辑器订阅与模型账单分开”的一个公开例子。[2]

### 3.2 Sudowrite Story Bible：创作漏斗顺，但“source of truth”必须降级理解

Sudowrite 的 Story Bible 是最典型的“由创意一路推到稿子”的产品设计。官方文档说明，Braindump 会影响 Synopsis，Synopsis 会影响人物、世界观、大纲和场景；大纲再影响场景，场景再影响 Draft。生成草稿时会参考风格、类型、人物、世界观和场景等资料。[3] 这种“上一步产物自然成为下一步输入”的体验很顺，尤其适合不知道如何起章的新作者。

同一份文档也称 Story Bible 是作者和 AI 都可回看的 “source of truth”，并会随用户在项目文档间切换而保持可见。[3] 这只能说明它是项目级的稳定资料面板；不能证明它有证据链、版本冻结或自动防止“计划写成事实”。因此，**我们可以学它的创作工作台顺序和字段依赖可视化，不可接受其将可生成、可改写的资料直接升格为故事真值。**

更重要的是，Sudowrite 明确把 Scene 与 Draft 的生成放进主工作流，最终目标是可继续打磨的场景初稿。[3] 这与“导写＋核对，不代写书稿”的北极星不同。产品可以从中学“怎样给作者一个下一步”，但不应为了看起来聪明而把一键成文放在主路径中心。公开价格是按订阅与 credits 组合，而非简单买断。[4]

### 3.3 Plottr：大纲前台的交互样板，不是记忆引擎

Plottr 的 Timeline 是很清楚的前台样板：章节标题可表示章节、节拍、场景或情节点；plotline 可表示主冲突、支线和人物弧；场景卡则收纳场景细节与主要事件。作者还能把人物、地点、标签和自定义属性关联到场景卡并筛选。[5] 这正好对应背景板里“作者面对章纲/剧情图，而不是面对数据库表”的要求。

它公开页还提到可用筛选来发现叙事流动问题、可给卡片上色标记待办、可拖拽调整顺序。[5] 这是作者真正愿意每天使用的东西：看得懂、移动得动、能从宏观缩到当前场。

这里的反面也很干净：其价格页直接写明 “No AI”。[6] 因而不能把 Plottr 的“时间线”误解为自动记忆，或把“能发现 plot holes”的宣传扩写为自动核验事实。它应当启发我们做强**可编辑的章纲/剧情图交互**，而不是承担后台真实状态、证据回取和变更传播。

### 3.4 Campfire：模块丰富有用，但核心档不能照着堆模块

Campfire 的做法是把书稿、人物、Timeline、Calendar、百科等拆成专门模块。官方写明 Timeline 可管理庞大的历史和多条时间线，Calendar 能追踪自定义月相、纪元、日期，并与 Timeline 相连。[7] 对世界观重、历史跨度大的作品，日历与时间线联动确实很实用。

但产品中枢不能简单复制成“每种资料一个模块”。背景板有一条很重要的纪律：每个结构要说清谁消费它，没有消费者不要进核心档。Campfire 的免费计划也体现出模块化商品的典型形态：每个模块各有配额上限；付费则通过月/年/终身来获得更完整访问。[8]

因此，可借鉴的是把资料用清楚的工作面呈现、让时间模块与事件模块联动；不应借鉴的是让人物、设定、规则、时间线、待办分别长成彼此孤立的“真值岛”。本轮官方资料中未找到 Campfire 的 AI 自动记忆或书稿证据回取能力，应按纯作者维护的资料中枢对待。

### 3.5 Letta：记忆架构最值得学，小说产品语义必须自己补

Letta 的价值不在小说写作，而在其记忆分层说得很清楚。Memory Blocks 是结构化、跨交互持续存在且始终在上下文中的部分；Archival Memory 则不常驻，必须由工具按需查询。[9] [10] 归档层还支持语义搜索与标签，Agent 可以用专门的插入和搜索工具操作它。[10]

这与背景板中的“当前完整、近期展开、远期压缩导航、需要时回捞”的方向高度同构，但不能直接照搬。Letta 的 Memory Block 可以由 Agent 通过工具更新，而我们的故事长期底账不能让模型单方面写入：必须有来源、类型、作者确认、证据承托和改动留痕。换句话说，**可学运行时分层和工具化读写，不可学无叙事治理的自动记忆写入。**

Letta 的公开个人计划为免费受限与 Pro US$20/月，并允许 BYOK/超额 credits；这是开发型 Agent 平台的计费例子，不能拿来直接推导作者端产品价格。[11]

### 3.6 SillyTavern World Info：轻量召回有效，但它不是“记住了”

SillyTavern 的 World Info（也叫 Lorebook/Memory Book）本质是一个动态提示词字典：消息出现关联关键词时，相关条目才被插入到上下文。条目还可以递归触发，并可限制递归层级。[12] 这是一种非常实用的低成本召回机制，尤其适合角色别名、地点名称、约定俗成的规则和某些必须带上的提示。

关键是，官方文档同时提醒：World Info 只是在引导 AI，不能保证被注入的内容一定会出现在输出里。[12] 因此它可作为我们检索准备阶段的一个“候选召回器”，不能作为事实判断器。若模型要回答“某人是否已知道某秘密”，必须回到状态/知情账和冻结书稿证据，而不是因为关键词触发了某条 lore 就判定为真。

SillyTavern 是本地安装的开源 LLM 前端，AGPL-3.0 授权。[13] 这不等于模型调用零成本；官方公开资料只支持“前端开源本地运行”，本轮未找到统一平台订阅价。它的可用价值是**触发策略**，不是作者向产品的完整交互范式。

### 3.7 World Anvil：宏观世界史/并行时间线很强，事件账仍需另建

World Anvil 将 wiki 式文章、地图、时间线与小说写作放在同一套世界观工具中。官方特别展示：可以用并行时间线分别跟踪一个国家或一个角色的事件，还可以把时间线按时代切开。[14] 这对多国、多角色、多时代并行的长篇很有启发。

不过，它更像一个供作者维护和展示的世界百科，而非“从书稿回收—核对—入账”的系统。公开页没有显示自动抽取、证据回链或冲突裁决，所以“世界文章存在”不等于“故事中已经发生”。我们可以学其多视角时间线与时代层次；不能把百科条目直接当作角色当前状态、读者已知信息或历史证据。

World Anvil 有免费账户和会员制，公开年付页面显示从 Master US$4.50/月至 Sage US$25/月的档位，并提供月付/年付/终身选项。[15] 这说明工具型价值可以有多档付费，但不说明应按同样结构定价。

## 4. 我们应该偷师什么

下面的建议均为**推测/产品判断**，不是背景板中已经拍定的施工项。

| 应偷师的东西 | 主要参照 | 为什么适合我们的北极星 | 建议落成什么，而不是什么 |
|---|---|---|---|
| **章纲/剧情图的视觉工作面** | Plottr、World Anvil、Campfire | 作者需要先看清“本章做什么、哪条线在推进、哪件事悬着”，不是先读数据库。 | 卷—章—场的可编辑看板、故事线筛选、故事序/叙述序双视图；**不是**把卡片本身当历史真值。 |
| **实体与原文提及的双向连接** | NovelCrafter | 人名、别名、地点和物品若能从条目跳回书稿，核对成本会显著下降。 | 剧情原子/实体页展示来源锚和出现位置；**不是**只做一个好看的百科。 |
| **时间点上的状态演进** | NovelCrafter Progressions、World Anvil 并行时间线 | 人物状态、关系、资源、规则都可能“曾经如此、现在不同”。 | 状态变化绑定故事序，视图可按章节/故事线回看；**不是**直接覆盖旧状态且没有变更史。 |
| **常驻状态 + 按需归档的上下文分层** | Letta | 执行包不该塞全书；但作者问关键问题时，又必须读得到历史。 | 当前场所需状态/义务/知情常驻，远期故事原子和冻结书稿按需取证；**不是**将整本书无差别塞进提示词。 |
| **轻量实体/别名触发召回** | SillyTavern | 别名、地点、规则、特定人物往往是明确硬线索，可给检索候选加速。 | 关键词/实体/故事线/时间硬过滤 + BM25 或向量扩召回；**不是**关键词命中即认定为事实。 |
| **从想法到下一场的连续工作流** | Sudowrite | 作者需要的不是空泛建议，而是可继续编辑的下一步。 | 把宏观大纲、卷纲、章盒子、本场目标和材料包连续呈现；**不是**用一键成文替代作者决策。 |
| **平台与模型能力解耦** | NovelCrafter 的 BYOK、Letta 的 BYOK | 背景板要求流程不绑定某一家模型，作者也应拥有可替换空间。 | 把业务真值、证据、章纲与模型调用分层；**不是**把供应商模型的输出格式埋成事实模型。 |

最值得优先借鉴的不是某个“AI 写得好”的功能，而是**让作者看得懂、改得动、能追责**的工作面：前台像 Plottr 那样直观，后台像 Letta 那样分层，证据连接像 NovelCrafter 那样可追溯，但真值治理要比它们都更严格。

## 5. 我们坚决不学什么

| 不学什么 | 典型反例/风险 | 为什么与北极星冲突 |
|---|---|---|
| **把“一键出场景/出草稿”设成主流程** | Sudowrite 明确把场景与 Draft 生成纳入主工作流。[3] | 我们的当前定位是导写＋核对，不代写书稿。生成若有，只能是章纲关闭后的可选模块，且必须受执行包约束。 |
| **把 Story Bible、Lorebook 或百科直接叫“真相”** | Sudowrite 的 Story Bible 被称为 source of truth；SillyTavern 的 Lorebook 是动态注入文本。[3] [12] | 可编辑资料、模型生成建议、未来计划和已发生历史不是一回事。真值必须有来源、确认和可见性边界。 |
| **让模型自己把记忆写成正史** | Letta 允许 Agent 工具化更新内存；World Info 条目可递归触发。[9] [12] | 模型可以提名，不能自动永久入账。高影响变化必须经作者/正式闸确认，且要留下改动史。 |
| **用摘要或向量命中替代原文证据** | Letta 的归档是语义搜索；SillyTavern 是提示词注入。[10] [12] | 检索和摘要只能导航。针对历史事实的回答要能回到冻结书稿的具体来源，而不是“模型说它记得”。 |
| **把时间线卡片当唯一数据模型** | Plottr、World Anvil、Campfire 都很擅长作者维护的卡片/时间线。[5] [7] [14] | 时间线是作者规划/浏览界面；还需要状态、知情、因果、义务、证据等后台账，且计划与已发生不可混用。 |
| **模块越多越好、字段越全越好** | Campfire 的多模块资料体系很强。[7] | 背景板要求每个结构说明消费者。没有下一步消费者的字段只会让作者维护成本上升。 |
| **把本地开源误说成“整体零成本”** | SillyTavern 是开源本地前端，但仍需连接模型后端。[13] | 产品的模型成本、存储成本和作者数据责任必须透明，不能靠“免费”掩盖后续成本。 |

## 6. 建议的差异化落点：不是更会写，而是更会管住故事

如果只做“AI 大纲 + 世界书 + 写作框”，我们会与 NovelCrafter、Sudowrite、Plottr、Campfire 等产品正面同质竞争。更有价值的路线是把它们各自做得好的局部能力拼到一个**有纪律的故事中枢**里：作者在可视章纲里安排未来；系统拿最小执行包协助下一场；书稿写成后回收核对；真正写进、且被确认的变化才带着来源进入长期状态账；所有关键回答都能回到冻结书稿。

这条路线的第一性指标不应是“单次生成看起来多精彩”，而应是以下三个更实在的问题：作者是否能在几秒内知道本章该处理哪条线；系统是否能说清某个判断来自哪段书稿、还是仅为计划/推测；作者改一处后，是否只看到真正受影响的章纲、卡和书稿修改指导，而不是整本书一起崩掉。这样的产品更符合共同背景板的北极星，也更难被普通聊天机器人替代。
