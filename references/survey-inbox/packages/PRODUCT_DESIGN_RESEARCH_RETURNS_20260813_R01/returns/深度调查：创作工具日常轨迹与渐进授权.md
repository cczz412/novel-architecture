# 深度调查：创作工具日常轨迹与渐进授权

**核心结论：这条路线成立，但只能成立为“逐步授权生成私有草稿”，不能直接推导为“信任后自动写入正史并自动发布”。**

跨产品和研究最一致的规律是：

- 用户会随着熟悉度提高而接受更多建议，但创作任务的放权速度显著慢于导航、预测、代码补全。
- **可编辑、可限定范围、可回看、可撤销**比“系统越来越懂你”更能提高采用。
- 作者的信任不是一个总分，而是分层的：可以信任它查设定，不代表信任它决定人物死亡；可以信任它写草稿，也不代表授权发布。
- AI 网文批量生产已经真实存在，但“提高字数”有证据，“提高完读、订阅和长期收入”没有可靠证据；2026 年平台风险正在上升。

证据标记：**强**＝因果实验、大规模行为数据或正式政策；**中**＝具名/多方访谈、厂商内部数据、小样本研究；**弱**＝社区自述、供应商营销或无法审计的收入案例。资料核验截至 **2026-08-13**。

## ① 日常轨迹画像

### 先说数据边界

没有找到可信研究能把作者每天的时间精确拆成“正文 55%、大纲 15%、设定 10%、AI 对话 10%、素材 10%”。公开资料能支持的是：

- 2019 年行业报告称，网文作者平均每日创作约 **4.5 小时**，签约作者约六成为兼职；但报告没有细分任务，而且数据已经较旧。[中国作家网转述行业报告](https://www.chinawriter.com.cn/n1/2020/0907/c404023-31851730.html)【中】
- 具名作者访谈能还原任务顺序和极端工时，不能外推总体比例。

因此，下面给的是**观测轨迹**，不是伪精确时间饼图。

| 活动          | 证据判断                                                     |
| ------------- | ------------------------------------------------------------ |

## ② 渐进信任先例与数据

### “N选一＋推荐”的真实先例

| 产品              | 交互                                           | 实际数据                                                     | 能证明什么                                                   |
| ----------------- | ---------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| Gmail Smart Reply | 给3条完整回复，选中后可直接发或编辑            | 2017年已占Inbox移动端回复的12%。原话：“Smart Reply suggests three responses”。[Google](https://blog.google/products-and-platforms/products/gmail/save-time-with-smart-reply-in-gmail/)【强行为数据】 | 三个差异化、可编辑候选可以高频使用；不能证明用户愿意自动发送 |
| GitHub Copilot    | 默认显示一个建议，也可看替代项、部分接受或拒绝 | 934,533名用户中，首年平均接受近30%；接受率随熟悉度“steadily increased”。[GitHub](https://github.blog/news-insights/research/the-economic-impact-of-the-ai-powered-developer-lifecycle-and-lessons-from-github-copilot/)【中强】 | 最接近“越用越接受”的纵向数据；仍只是局部补全，不是代理自治   |
| Google Maps       | 最佳路线高亮，其他路线弱化显示                 | 官方确认交互，没有公开的长期“从比较到无条件服从”数据。[Google Maps帮助](https://support.google.com/maps/answer/144339?co=GENIE.Platform%3DiOS&hl=en-GB)【中】 | 明确推荐适合可比较、结果较客观的任务                         |
| Midjourney        | 一次给4图，用户选图继续变体                    | 无公开选择率；四图也没有系统推荐徽标。[官方文档](https://docs.midjourney.com/hc/en-us/articles/33329261836941-Getting-Started-Guide)【中】 | 创意任务更偏向并列探索，而非宣称一个正确答案                 |
| AI故事点子实验    | 0、1或最多5个AI点子                            | 293名写作者中，单点子组82/100使用，五点子组93/98至少使用一个；五点子组新颖性约高8.1%、可用性约高9%，但故事彼此更相似。[Science Advances](https://pmc.ncbi.nlm.nih.gov/articles/PMC11244532/)【强因果实验】 | 作者愿意取用候选灵感；不能外推到整章自治                     |

严格意义的“3–4个方案＋其中一个标推荐＋长期转自动”公开先例很少。现有产品通常只有其中一半。

### 信任怎样演化

最强的因果证据来自算法预测实验：

- 不允许修改算法预测时，约 **32%** 选择使用算法；
- 能修改部分结果时上升到约 **73%**；
- 能逐项小幅修改时约 **76%**。

研究者的概括是：“giving people some control—even a slight amount”。[Management Science论文摘要](https://ideas.repec.org/a/inm/ormnsc/v64y2018i3p1155-1170.html)【强】

这支持“先挑、可改、再逐步放权”，但任务是客观预测。创作更难：超过5.7万人的主观/客观任务研究发现，算法在主观任务中会被“trusted and relied on less”。[Journal of Marketing Research](https://journals.sagepub.com/doi/10.1177/0022243719851788)【强】

信任也很脆弱。5项实验、约2,367人发现，人们看到算法犯错后，比看到人类犯同样错误更快失去信心，即使算法总体表现更好。[PubMed](https://pubmed.ncbi.nlm.nih.gov/25401381/)【强】

所以：

- 连续接受20次推荐，不等于已经授权第21次人物死亡。
- “推荐项点击率高”可能来自排序和视觉默认，不一定是学准口味。
- 学习偏好时应记录**编辑、拒绝、撤销和事后反悔**，不能只记录点击。

### 授权自动化与可撤销先例

- **Claude Code**公开采用Manual → Accept edits/Plan → Auto的权限梯度，并建议用户熟悉后再升级；但没有公开各级转化和留存。[官方文档](https://code.claude.com/docs/en/desktop)【中，产品先例】
- **GitHub Copilot云代理**在隔离分支工作，产出diff和PR，用户决定是否合并。[GitHub文档](https://docs.github.com/copilot/concepts/agents/cloud-agent/about-cloud-agent)【中】
- **Zapier Human in the Loop**会在指定步骤暂停，允许审核者批准、拒绝或修改数据后再继续。[Zapier文档](https://help.zapier.com/hc/en-us/articles/38731463206029-Request-approval-to-keep-your-workflow-running-with-Human-in-the-Loop)【中】
- **VS Code代理**提供diff、keep/undo、checkpoint和按会话/工作区授权。[官方说明](https://code.visualstudio.com/docs/agents/concepts/trust-and-safety)【中】

反面教训是Knight Capital：部署故障在45分钟内产生400多万笔异常订单、亏损超过4.6亿美元；盘前已有97封错误邮件，却没有形成有效熔断。[SEC](https://www.sec.gov/newsroom/press-releases/2013-222)【强事故证据】

这说明“红灯才叫人”成立的条件不是多发警告，而是：

- 红灯少且可行动；
- 触发前就有硬限额；
- 高风险动作默认阻断；
- 有总开关和回滚；
- 执行模型不能兼任唯一审批者。

### 谁兴奋，谁反感

没有代表性调查能给出各层比例，只能做行为分层：

- **产能/套利型工作室：高意愿。**关心开书量、成本和命中率；主要担忧封号、限流、同质化和工具成本。【中】
- **有点子但写不出的新人：中高意愿。**“一句话变全文”吸引力强，但后续审稿负担和低通过率会造成流失。【中】
- **成熟日更作者：条件式意愿。**欢迎查资料、总结、候选情节、过渡场景初稿；核心转折、读者服务感和人物声音仍要掌握。【中强】
- **AI-first“导演型作者”：高意愿但群体规模未知。**常让AI扩写场景，仍逐章检查。【弱】
- **文学作者与工艺导向爱好者：自动正文意愿低。**18名长期使用AI的创意写作者仍强调过程、声音和所有权；一位作者说：“my personal satisfaction is lower when the AI does the majority of the work.”[From Pen to Prompt](https://arxiv.org/html/2411.03137v1)【中强定性】
- **付费原创读者：对“人工开头、机器续写而不披露”尤其反感。**当前证据主要是投诉和媒体访谈，不能转成比例。【中弱】

## ④ 插手层级与支线需求

### 作者控制的不是同一层

109篇HCI论文综述加15名写作者访谈发现：

- 内容导向写作者更重视规划、观点和结构所有权；
- 小说等形式导向写作者更重视句子、节奏、声音和修订；
- AI建议越长，感知所有权通常越低；
- 可接受、拒绝、修改的“建议”模式被视为维持能动性的关键。[Co-Writing with AI](https://arxiv.org/html/2504.12488v1)【中强】

18名长期AI写作者的现场观察进一步显示，决策发生在单词、句子、段落、场景乃至整条情节线上；同一作者会随当前意图动态改变AI角色。[From Pen to Prompt](https://arxiv.org/html/2411.03137v1)【中强】

可以把插手层级整理成：

| 层级       | 典型用户               | 愿意交给AI的内容                    |
| ---------- | ---------------------- | ----------------------------------- |
| 支持层     | 几乎所有AI友好作者     | 检索、纠错、连续性检查、反馈        |
| 结构层     | 规划型/商业作者        | 人物、剧情、大纲候选，由作者拍板    |
| 场景层     | 类型作者、AI-first作者 | 作者定scene beats，AI扩写，逐段选择 |
| 整章层     | 高压日更、导演型作者   | AI出章，作者逐章通读和重写          |
| 批量告警层 | 工作室、少量产能型作者 | 系统连续生成，作者抽检或处理红灯    |

公开研究实际观察到前四层；**没有形成对第五层长期无人值守日更的留存证据**。

因此，不应给作者贴一个永久标签。更合适的是按“内容层级×当前场景重要性”授权：同一作者可能允许AI写旅途过场，却坚持亲自写表白、死亡和卷末高潮。

| Plottr       | 主线/支线分轨，插入和拖动场景、章节，自动重编号。[官方文档](https://docs.plottr.com/article/54-timeline-overview) | 机械重排，不评估人物状态、伏笔和主线影响                     |
| Novelcrafter | Plan视图增加并拖动场景/章节、版本历史                        | 截至官方FAQ，正文视图不能直接在上方插章，需“新建后到Plan移动”。[官方FAQ](https://www.novelcrafter.com/help/faq/plan/how-can-i-insert-scenes-or-chapters) |
| Sudowrite    | 章节连续性、前文上下文、手动断开/重连章节，顺序可改。[官方文档](https://docs.sudowrite.com/using-sudowrite/1ow1qkGqof9rtcyGnrWUBS/chapter-continuity/4KL8gFeLZQ6GSBjDWtSbV6) | 未见“自动找插入点＋评估影响＋重排全部未来计划”的公开能力     |

作者目前的土办法主要是：

- 顺着好偏离继续写，再手改后续大纲；
- 偏离不好就回改正文；
- 单独维护支线时间轴，再手工穿回主线；
- 复制项目、使用快照或“废稿箱”保留替代版本；
- 重写全书章摘要，逐章检查人物状态和伏笔。

资深作者“跳舞”甚至描述过写到20万字才临时增加角色和前世情缘主线，并称大纲是“双刃剑”。[江苏作家网](https://www.jszjw.com/salon/20231009/1696841426396.shtml)【中】

“改上层后自动重排下层”是合理痛点，但还没有大规模使用数据。现有产品大多只做到拖放、版本和上下文注入。更合适的产品流程是：

1. 在分支沙盒中添加支线；
2. 推荐2–3个插入点，分别解释节奏与因果影响；
3. 列出受影响的角色知识、状态、伏笔、时间线和未来章节；
4. 提供“补桥不改后文 / 改未来大纲 / 仅重生成所选草稿”三种方案；
5. 显示旧章节号到新章节号映射；
6. 作者确认后才合并；
7. 已冻结或已发布正文永不静默改写。

这与你们现有的N19-B方向高度一致，属于值得继续押注的差异点。

## ⑤ 概念判断与交互设计建议

### 这不是完成过的用户概念测试

公开资料中没有找到“每天自动更三章”概念的代表性意愿、留存或付费实验。因此下面是**桌面研究推断**，不能包装成已验证的“测试结果”。

| 人群                | 对原概念的预期                     | 最大担忧                           |
| ------------------- | ---------------------------------- | ---------------------------------- |
| 工作室/产能型       | 高意愿，尤其是私有批量草稿         | 封号、限流、重复、成本和质检规模   |
| 日更商业作者        | 对“每天出待审稿”中高；对自动发布低 | 人物崩坏、读者反应、声音、平台规则 |
| 新人/输出导向爱好者 | 初始兴奋高，实际留存不确定         | 不会审稿、生成债务、作品仍不签约   |
| 工艺/表达型爱好者   | 对自动正文低，对资料和连续性高     | “写作过程被拿走”、所有权和AI味     |
| 文学/专业作者       | 对自动正文最低                     | 句子、声音、伦理、披露和职业身份   |
| AI-first导演型      | 高，但预计是小众                   | 仍需要逐章审阅和上下文管理         |

### 建议改写概念

原表达：

> 前期你逐个拍板，系统学你的口味；你说放手后它每天自动更，红灯问题才叫你。

更稳妥也更可信的版本：

> 前期你逐个拍板，系统把你的选择整理成可编辑规则。等你主动授权后，它可以每天生成待审章节；正史、发布和高影响变化仍单独确认，发现红灯会自动停下。

“学你的口味”最好变成作者可见、可删、可修改的规则，例如：

- 本书避免误会拖延；
- 战斗场景允许快节奏扩写；
- 不自动新增核心设定；
- 感情转折必须给作者三个方向；
- 卷末高潮不得自动决定。

### 四级渐进授权

| 级别            | 行为                                                     | 默认边界           |
| --------------- | -------------------------------------------------------- | ------------------ |
| L0 逐个选择     | 1个主推荐＋2个真正不同的替代项；显示理由、代价和影响范围 | 无自动采用         |
| L1 推荐预填     | 低风险项预选推荐，作者确认、编辑或换项                   | 超时不视为批准     |
| L2 批量草稿     | 每天在沙盒中生成若干待审章节，提供章级摘要和diff         | 不写入正史、不发布 |
| L3 有界自动运行 | 限定本卷、场景类型、7/30天、每日章数和禁区；红灯暂停     | 高影响变化重新签署 |

**对外发布应是独立权限，不是L3自然附带的下一步。**部分平台甚至不应提供自动发布。

任何“以后都按推荐来”都应展开成授权卡，至少确认：

- 哪本书、哪一卷；
- 大纲、章纲、场景还是正文；
- 有效期；
- 每日章数/字数/成本上限；
- 只进草稿箱还是允许进入正史；
- 审核密度；
- 平台模式；
- 红灯与自动降级条件。

你们已经确定的四类高影响变化——**Bible新增/修改、不可逆人物变化、作者锁定事实、跨线重大因果**——不应被一句永久授权覆盖。

### 每日审阅页应让作者看什么

- 今天生成了哪些章节；
- 采用了哪些推荐；
- 新增或改变了哪些事实；
- 与卷纲的偏移；
- 哪些后续章节受影响；
- 重复、风格漂移、连续性和平台政策风险；
- 作者修改量与diff；
- 一键接受、退回、局部重写、整批回滚；
- AI参与类型与发布标识记录。

### 不要用“批准率”衡量信任

真正的渐进信任应同时看：

- 推荐接受率，并校正推荐徽标和排序偏差；
- 接受后的编辑距离；
- 24小时/7天撤销率；
- 作者主动扩大、缩小或关闭权限的行为；
- 自动草稿→批准→实际发布转化；
- 红灯准确率、漏报率和忽略率；
- 每万章连续性冲突与回滚次数；
- 出错后重新开启自动化所需时间；
- 4–8周留存、续费和付费升级；
- 平台拒签、限流、下架和申诉情况。

最有效的验证不是问“你愿不愿意”，而是做4–8周真实书稿试验：

- 随机化“可小幅修改/不可修改”；
- 随机化推荐徽标和排序；
- 一组展示系统学到的明确规则，一组只说“越来越懂你”；
- 观察作者是否主动授权下一卷、是否续费，以及出错后收回到哪一层。

### 最终产品判断

- **应继续做：** N选一推荐、作者选择学习、局部默认、沙盒批量草稿、影响预览、回滚、红灯暂停。
- **应延后验证：** “每天自动生成整章”在成熟日更作者中的长期留存。
- **不应作为核心承诺：** 自动发布、自动增收、系统学会口味后不再需要作者。
- **最有差异化的机会：** 上层变更后的依赖传播——找插入点、展示因果半径、选择性重排未来计划，同时保护已确认正文。

一句话概括：**用户可能愿意从“逐个拍板”走到“每天收一批待审稿”，但现有证据不支持他们会自然走到“我的书无人值守自动发布”。**
