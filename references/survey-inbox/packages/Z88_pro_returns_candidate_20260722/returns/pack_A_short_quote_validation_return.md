# 结论先行

- ✅ 建议拍板为：**路线 2 为主的混合方案**——锚 ID＋冻结目录版本是唯一权威，正式短引一律由程序回填。
- 取消的是“模型自由誊抄短引并以逐字匹配决定整轮生死”，**不是取消证据绑定校验**。
- 模型短引可删除；确有排障价值时，改名为 `diagnostic_quote`，只记日志，不得写入正式证据字段。
- 锚粒度过粗时，不要让模型抄文字，改让模型返回句子 ID 或起止位置，程序再切原文。
- 硬闸应转向：锚合法性、冻结版本、位置范围、语义支持、证据覆盖、路由与人物／时间／否定关系。
- retry04／05／06 已显示逐字闸主要在拦誊抄清洗；但目前**证据不足**以证明“合法锚一定绑定正确”，仍需离线审计错锚和部分支持。

## 对“三证同根”的拍板判词

**一句话：选路线 2 为主、保留语义绑定复核的混合方案；不再让模型短引承担生产硬闸职责。**

三条理由：

1. **更接近成熟系统的工程形态。** Anthropic 的引用接口用文档、页码、字符区间或内容块位置作引用指针，并由接口直接提取 `cited_text`；Google 的 grounding 元数据也是把答案片段连接到来源块索引；LongCite 则使用句子 ID 或句子区间。这些方案都把“指针”与“展示文本”分开。([Claude Platform Docs](https://docs.anthropic.com/en/docs/build-with-claude/citations))
2. **逐字命中与证据真正支持事实是两件事。** ALCE 展示过一种“作弊式”结果：直接复制检索段落能拿到接近满分的引用指标，但答案正确性明显下降。也就是说，短引完全逐字，照样可能选错证据、只支持一半或答非所问。([ar5iv](https://ar5iv.labs.arxiv.org/html/2305.14627))
3. **你们的故障信号高度集中在誊抄层。** retry06 中 64／64 锚合法，55 条完全一致、8 条只是修剪、1 条是 `。`→`.`；当前硬停没有揭示实体、数字、否定、人物或事件关系变化，却让整轮不可用。它对“绑定是否正确”的新增信息接近于零，但不能据此省掉语义支持审计。

## 两条路线在公开系统里的成熟做法

| 路线                       | 代表方案                                                   | 成熟做法是什么                                               | 对你们的含义                                                 |
| -------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 模型给逐字短引             | **GopherCite、WebGPT**                                     | GopherCite要求提供从检索来源抽出的原文证据，并允许无充分证据时拒答。WebGPT 的 `Quote` 动作只有在页面中找到文本才收录；它甚至会忽略大小写、空白，并允许“开头＋结尾”的缩写格式。不是简单地让模型在 JSON 里自由抄写后做字节级全等。 | 路线 1 成熟的前提是：短引就是最终用户要核验的对象，而且由工具抽取／约束，不是靠 Prompt 要求模型誊抄。 |
| ID／位置指针权威，系统渲染 | **Anthropic Citations、Gemini Grounding、LongCite**        | 模型或系统返回文档索引、页码、字符范围、句子 ID、来源块索引；展示层再读取来源并插入引用。Anthropic 明确称 `cited_text` 是直接提取的，并保证引用包含指向输入文档的有效指针。([Claude Platform Docs](https://docs.anthropic.com/en/docs/build-with-claude/citations)) | 这是与你们“锚 ID 权威＋冻结目录回填”最接近的工业形态。       |
| 开源 ID 引用               | **LlamaIndex CitationQueryEngine、Haystack AnswerBuilder** | LlamaIndex 给来源节点编号，默认可按句切分；Haystack 从模型回复里解析文档序号，并关联回输入文档。([GitHub](https://github.com/run-llama/llama_index/blob/main/llama-index-core/llama_index/core/query_engine/citation_query_engine.py)) | ID 选取可以由模型做，但原文和来源元数据应由系统掌管。        |
| 生成后再绑定／细化         | **LongCite CoF、P-Cite**                                   | LongCite 的 CoF 先生成答案，再检索相关块并细化成句子级引用；论文称这种流程可避免“答案和引用一次生成”对答案正确性的干扰。一篇 2025 年预印本也更倾向检索优先、生成后引用，但该结论还不是你们场景的直接实验。([arXiv](https://arxiv.org/html/2409.02897v3)) | 可以作为路线 2 的旁证，但不能代替你们自己的中文网文离线评测。 |

**证据不足处：**目前没有公开研究直接比较“中文长篇网文、冻结章级锚目录、第二模型检查员”场景下，逐字短引硬闸与程序回填的误杀率、错锚漏检率和总体成本。这里的推荐是公开系统形态、引用评测方法与你们三轮故障记录共同支持的工程判断。

| **5. 把短引差异变成分层诊断。** 分为完全一致、纯前后裁剪、空白差异、Unicode／标点差异、同义改写、内容字变化。 | WebGPT 在引文匹配中忽略大小写和空白；Unicode 标准也区分规范等价与兼容等价。([ar5iv](https://ar5iv.labs.arxiv.org/html/2112.09332)) | **适用。** retry06 的 `。`→`.` 应进入“表层替换”统计，不应让整轮作废。 |

## 誊抄层失败模式目录

🔥 **一个必须核实的口径问题：真正的“连续子串闸”不会拒绝纯剪前缀或纯截尾。**

假设闸的含义真的是：

```text
模型短引是否完整出现在原输入文本中
```

那么只要没有改字，源文 `"甲乙丙丁"` 的 `"乙丙"`、`"甲乙丙"` 都是连续子串，应该通过。retry05 的“8 条截短尾部仍不过闸”说明至少存在一种情况：

- 当时实际执行的是“完全相等闸”，不是连续子串闸；
- 截尾时加了省略号、改了句末标点或空白；
- 比较对象不是同一份输入短引；
- 日志把多种 mismatch 汇总成了同一个计数。

这一项应直接查代码和原始 reason，不要只看转记摘要。

| 变化类型                                     | 原样连续子串闸                   | 对“逐字直接引文”的判断 | 对“绑定是否正确”的判断                           | 推荐处置                                 |
| -------------------------------------------- | -------------------------------- | ---------------------- | ------------------------------------------------ | ---------------------------------------- |
| 纯剪前缀／纯截尾，不增删内部字符             | **应通过**                       | 仍是逐字片段，只是变短 | 通常不说明锚错；可能因过短而证据不足             | 设最小信息量或语义充分性检查，不用全等闸 |
| 去掉首尾空白／换行                           | 预处理后可通过；原样比较可能失败 | 表层格式差异           | 通常不说明锚错                                   | 仅告警                                   |
| 内部空白折叠、换行变空格                     | 原样比较失败                     | 不再字面完全一致       | 通常是排版清洗                                   | 记录规范化差异；正式短引仍回填原文       |
| `。`↔`.`、`，`↔`,`                           | 失败                             | 非逐字                 | 多数小说语境下不改变事实内容，但可能影响分句     | 表层替换；不作为绑定硬停                 |
| 全角／半角、NBSP、零宽字符、Unicode 组合形式 | 失败或结果不稳定                 | 非字节级一致           | 多数是编码或排版问题；编号、代码等场景可能有意义 | 原文不改；规范化结果只用于分类诊断       |
| 中文弯引号／英文直引号替换                   | 失败                             | 非逐字                 | 通常不说明锚错；涉及说话人边界时可能有风险       | 对话场景增加说话人检查                   |
| 同义改写、调整语序                           | 失败                             | **不能再称直接引文**   | 未必是锚错，也未必是事实幻觉                     | 不落正式短引；转交语义支持检查           |
| 删除中间成分、拼接两段、加省略号             | 通常失败                         | 非连续原文             | 可能省掉否定、条件、说话人或时间，风险较高       | 隔离该条，做完整支持检查                 |
| 改实体、数字、时间、否定词、程度词、人物关系 | 失败                             | 虚假引文               | 通常属于真实内容误写或证据误读                   | 硬失败或人工复核                         |
| 复制得一字不差，但选了另一个合法锚           | **通过**                         | 引文本身逐字           | **真实绑定错误**                                 | 必须依靠语义相关性／支持性闸发现         |
| 锚方向正确，但只支持事实的一半               | 可能通过                         | 引文本身逐字           | **部分支持**，仍不合格                           | 要求补锚、拆事实或标记信息不足           |

要点是：**“非逐字”不等于“锚错”；“逐字”也不等于“锚对”。**

## 只认锚 ID 后，必须保留的程序闸

| 程序闸                   | 主要解决什么问题                                             | 失败处置                       |
| ------------------------ | ------------------------------------------------------------ | ------------------------------ |
| **候选集与引用完整性闸** | 锚 ID 必须存在，而且必须是本条检查任务实际提供过的候选锚，不能跨章猜 ID | 单条硬失败；若大量出现则整批停 |
| **冻结目录版本闸**       | 防止模型检查的是 A 版文本，程序却从 B 版目录回填             | 整批硬停                       |
| **来源指纹闸**           | 给原文文件、章节、锚文本保存“文本指纹”，也就是哈希；回填前重新计算，确认文本未漂移 | 整批或该章硬停                 |
| **位置范围闸**           | 起止位置不能越界、倒置、跨文档或跨章；句子区间必须连续       | 单条硬失败                     |
| **确定性回填闸**         | 正式短引只能来自 `目录[锚ID]` 或 `目录[锚ID][起止位置]`，禁止读取模型短引字段 | 程序异常，整批停               |
| **语义支持闸**           | 判断锚是否完整支持原子事实，而不只是“主题相关”               | 部分支持／矛盾时隔离该条       |
| **覆盖与无关证据闸**     | 一个事实中的每个关键断言都要有证据；同时避免挂无关锚         | 补锚、拆句或隔离               |
| **叙事关系闸**           | 检查人物、说话人、时间、否定、假设、回忆、传闻与实际发生是否混淆 | 高风险条目复核                 |
| **审计日志闸**           | 保存模型版本、合同版本、目录版本、候选锚、返回锚、回填文本指纹和 reason code | 缺日志不得正式落账             |

其中前五项是**确定性检查**，可以直接硬判；后面几项涉及语义，可能仍由检查员、独立判别模型或人工抽检完成。ALCE 和 LongCite 的评测设计也说明，引用是否合法、是否相关、是否完整支持，应拆成不同指标。([ar5iv](https://ar5iv.labs.arxiv.org/html/2305.14627))

## 可执行决策树

```text
IF 冻结证据目录没有版本号、来源指纹或稳定锚映射
THEN 暂不下线旧闸；先修好目录完整性
     ——否则程序回填也可能悄悄回填错版本。

ELSE IF 一个锚已经对应可直接展示的完整证据段
THEN 采用路线2：
     模型输出 anchor_id
     程序按 anchor_id 回填正式短引
     模型短引删除或仅作诊断。

ELSE IF 锚包含多句话、多个人物或多个可选事实
THEN 采用“指针式混合”：
     模型输出 anchor_id + sentence_id_range / start_end
     程序验证位置并切出原文
     不允许模型自由填写正式短引。

IF anchor_id 非法、未出现在候选集、跨章、版本不符、位置越界
THEN 硬失败；
     单条问题隔离单条，系统性版本／目录问题停整批。

ELSE IF 锚合法但只能部分支持、与事实矛盾、人物／时间／否定关系不符
THEN 标记 needs_review 或重新检查；
     不得因为“程序成功回填了一段漂亮原文”而自动接受。

ELSE IF 只有 diagnostic_quote 出现裁剪、空白、标点或引号差异
THEN 记 surface_quote_diff；
     不阻止落账，不触发整轮重试。

ELSE IF diagnostic_quote 改了实体、数字、否定、人物关系
THEN 记录 inspector_content_mutation；
     可隔离该条并纳入模型质量评测，但正式短引仍以程序回填结果为准。
```

### 三种方案对照

| 项目                     | 路线 1                 | 路线 2          | 推荐混合方案               |
| ------------------------ | ---------------------- | --------------- | -------------------------- |
| 正式证据权威             | 模型短引＋源文匹配     | 锚 ID＋冻结目录 | **锚／位置指针＋冻结目录** |
| 模型需要誊抄原文         | 是                     | 否              | 否；最多诊断字段           |
| 能否发现非法 ID          | 能，前提是另做 ID 校验 | 能              | 能                         |
| 能否发现合法但选错的 ID  | 不一定                 | 不一定          | **靠语义支持闸发现**       |
| 对标点／空白清洗的敏感度 | 高                     | 无              | 只做非阻断诊断             |
| 正式短引是否保证原样     | 依赖模型是否抄准       | 程序可保证      | **程序可保证**             |
| 适合你们当前病例         | 较差                   | 较好            | **最好**                   |

## 路线 2 的最小改造清单

### 程序侧，5 条

1. 给冻结目录增加版本号和文本指纹；锚记录至少绑定章节、来源文件和稳定位置。
2. 增加统一回填器：只接收锚 ID／位置指针，输出原始短引；任何模型文本不得覆盖结果。
3. 校验返回锚是否存在、是否属于当前候选集、是否跨章、是否重复、数量是否符合合同。
4. 加入语义结果状态：`完全支持／部分支持／矛盾／信息不足`，并把部分支持与非法锚分开计数。
5. 把整批硬停缩到目录、版本、解析器等系统性故障；普通单条语义问题进入隔离队列。

### 合同侧，5 条

1. 明确写入：`anchor_id` 是绑定权威，`evidence_quote` 由程序生成。
2. 删除模型必填的正式短引；保留时改名 `diagnostic_quote`，注明“不落账、不作权威”。
3. 要求返回本次目录版本或任务版本，防止跨版本结果混用。
4. 锚较粗时允许返回 `span_ref`，也就是句子 ID 或起止位置；不允许返回自定义正式引文。
5. 增加 `verdict` 和稳定的 `reason_code`，并允许 `insufficient_evidence／needs_review`，不要逼模型乱选锚。

### 评测侧，5 条

1. 拆开统计：非法锚率、错锚率、证据覆盖率、无关锚率、路由错误率。
2. 短引指标降为诊断项，并分开记录裁剪、空白、Unicode／标点、改写、内容字变化。
3. 建立难负例：同章相似锚、重复原句、人物互换、数字变化、否定反转、传闻与事实、时间错位。
4. 做分层盲审：抽查短锚／长锚、单锚／多锚、对话／叙述、普通事实／否定与条件句。
5. 产品预先定义上线门槛和回退门槛，重点看“合法但错误的锚”与“部分支持”是否上升，而不是只看通过率。

## 路线 2 可能掩盖的错误，以及离线审计补法

| 隐藏风险                               | 为什么程序回填会把它“包装得很可信”                   | 离线审计                                                     |
| -------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------ |
| **合法但选错锚**                       | 程序能从错误锚中回填一段完全真实、格式完美的原文     | 同章内交换相似锚，统计检查员能否拒绝；人工盲审事实—锚对      |
| **锚只支持事实的一部分**               | 回填出来的段落看起来相关，但没有覆盖原子句全部断言   | 按“完全／部分／不支持”标注；多断言事实逐项核对               |
| **锚粒度过大**                         | 长段落里可能同时存在支持内容和反例，模型只看见“沾边” | 评测锚长度与错锚率；必要时加句子级位置                       |
| **重复原句或近似原句错位**             | 相同文字可能出现在不同章节、回忆、转述或不同人物口中 | 测试相同文本、不同来源 ID 的对照组；强查章节、人物和叙事层级 |
| **否定、假设、传闻、计划被当成已发生** | 程序只负责取原文，不理解叙事状态                     | 建立否定／条件／传闻／梦境／回忆专项集                       |
| **需要多锚，但只返回一个**             | 单个锚可能支持结论，却不支持前提或因果链             | 统计证据覆盖率；允许多锚并检查联合支持                       |
| **目录或位置映射程序自身出错**         | 同一个程序会稳定地产出“看似正确”的错误文本           | 固定金样例做回填单测；双重校验位置与文本指纹；目录升级时跑全量重建对照 |
| **语义判别模型误判**                   | 第二模型可能偏爱措辞相似，而忽略逻辑关系             | 用人工盲审校准；定期加入对抗负例；不要把单一模型评分当唯一硬真值 |

ALCE 明确把“完全支持、部分支持、不支持”分开讨论，并指出自动 NLI 判别仍会误判部分支持；LongCite 也通过人工样本检查自动引用评测与人的一致程度。因此，语义闸可以自动化，但必须有抽样人工校准。([ar5iv](https://ar5iv.labs.arxiv.org/html/2305.14627))

### 推荐的离线审计单元

不要把金标答案放进生产模型窗口。离线审计可单独维护：

- 输入：原子事实、检查员实际看到的候选锚、它最终选择的锚；
- 标注：`完全支持／部分支持／不支持／矛盾`；
- 对照负例：从同章替换一个“主题相似但关系错误”的合法锚；
- 核心指标：**错锚漏检率、部分支持漏检率、无关锚率、需多锚却漏锚率**；
- 分层维度：锚长度、候选数、人物数、是否含数字／否定／条件／对话。

这套审计测的是路线 2 真正容易漏掉的东西，而不是重复测程序已经能百分之百保证的“正式短引是否来自原文”。

## 开放问题

1. **正式落账或对外展示的短引，是否存在法规、版权审计或人工验收上的“必须由检查员亲自指出范围”要求？** 若没有，模型自由短引字段可直接取消。
2. **现有锚粒度是否足以独立支持一条原子事实？** 若一个锚经常覆盖多句、多人物、多事件，应增加句子区间，而不是恢复模型短引。
3. **产品能接受的“合法但错误锚”漏检率是多少？** 这个阈值应决定离线抽检规模和是否增加第三道语义判别。
4. **单条失败能否隔离，还是整章必须原子提交？** 这会决定语义失败是单条复核还是整章回滚，但不应再由标点差异决定。
5. **`diagnostic_quote` 是否还有明确使用者？** 若没有调试、质检或模型退化分析的固定消费方，建议直接删掉，避免它重新变成事实上的隐藏硬闸。
