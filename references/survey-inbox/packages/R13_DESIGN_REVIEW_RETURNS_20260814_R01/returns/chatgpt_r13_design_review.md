# A｜设计稿与 R13 打架

## A1｜索引仍把 R10 写成现行权威

**类型 / 严重度 / 证据性质**：A｜过时索引｜已验证
**位置**：`INDEX.md` 开头“权威关系”；对照 R13 `00_READ_ME_FIRST.md`、`06_SYNC_AND_CHANGE_PROTOCOL.md`。
**原文短引**：“产品语义以背景板现行版为准（本地正式 R10）。”
**为什么是问题**：这是整包总入口。后面的人很可能只看 INDEX，就把 R13 当成尚未进入设计层的补丁，继续按 R10／R12 旧句施工。
**不要做什么**：不要把 R13 解释成“在 R10 上再叠几条注记”，也不要拿设计稿反向修 R13。

## A2｜仍把 90 秒事实确认写成激活

**类型 / 严重度 / 证据性质**：A｜硬伤｜已验证
**位置**：`TUTORIAL_SCRIPTS_DESIGN_R01.md` §0、§1.2、屏 B3／B4；对照 R13 00、01、03、07 页 ADD-057。
**原文短引**：“90 秒内亮出第一条能点回原文的事实。”；“激活事件三要素在此屏集齐：导入自己的章节→90 秒内看到……→确认它。”
**为什么是问题**：R13 已把激活改成“作者看见系统持续在工作”。事实确认可以是首价值，但不能继续充当唯一激活定义，否则所有教程、埋点和模型选择都会按旧漏斗开工。
**不要做什么**：不要把旧单点激活换成另一个单点，例如“看到第一张 SVG 才算激活”。

## A3｜项目第一屏仍会直达光标或门厅

**类型 / 严重度 / 证据性质**：A｜硬伤｜已验证
**位置**：`DAILY_LOOP_WALKTHROUGH_R02.md` §3 屏 1、§6.1 节点②；`FIRST_SCREEN_SYSTEM_DESIGN_R01.md` §2.2、§4；对照 R13 01、03、05、07 页 ADD-059。
**原文短引**：“有活动草稿时跳过②③④直达⑤原光标位。”；“单书用户直接进层 1，不经过主页。”
**为什么是问题**：R13 要求点进小说项目先看到梗概＋概览＋战报，再根据是否关章进入上次处理处或下一章工作台。当前稿把“恢复工作”顶成了“第一屏”，会把项目状态说明整层绕掉。
**不要做什么**：不要删除回到光标的快捷能力；问题是它不能取代项目第一屏。

## A4｜黄金三章仍被当成教程／免费导入档

**类型 / 严重度 / 证据性质**：A｜硬伤｜已验证
**位置**：`TUTORIAL_SCRIPTS_DESIGN_R01.md` §0、§1.3；`INTAKE_SHELVES_DESIGN_R01.md` §1.7；对照 R13 01、03、05、07 页 ADD-059。
**原文短引**：“路 B＝免费层首次动线（导入前三章→抽取→看效果）。”；“免费项目……取最前 3 章入架。”
**为什么是问题**：R13 的黄金三章是另一张独立工作台，处理满意后才移交进小说项目。当前设计把它降成导入额度和获客教程，没有独立身份，也没有移交动作。
**不要做什么**：不要把“前三章免费”改几个字就冒充黄金三章工作台。

## A5｜投影仍被写成只读

**类型 / 严重度 / 证据性质**：A｜硬伤｜已验证
**位置**：`FIRST_SCREEN_SYSTEM_DESIGN_R01.md` §1、§4.1；`REVIEW_OVERVIEW_DESIGN_R01.md` §2.1；`REVERSE_PLOT_MAP_DESIGN_R01.md` §6；`WRITING_DESK_DESIGN_R02.md` §1.2；对照 R13 01、02、07 页 ADD-061。
**原文短引**：“一份不落盘的现算投影……纯投影、不可编辑。”；“禁止在卡上改出第二真源。”
**为什么是问题**：R13 已废掉 R12 的投影只读口径。作者应该能在投影上直接纠错，是否进入真值再走确认。当前稿要求作者跳回“本尊”，会把最自然的纠错入口封死。
**不要做什么**：不要把“投影可改”读成“改了就自动进真值”。

## A6｜选线仍是每章必经闸门

**类型 / 严重度 / 证据性质**：A｜高风险｜已验证
**位置**：`FIRST_SCREEN_SYSTEM_DESIGN_R01.md` §4.2；`CHAPTER_WORKBENCH_DESIGN_R01.md` §1、§6；`DAILY_LOOP_WALKTHROUGH_R02.md` §6.1 节点③；对照 R13 02、03、05 页 ADD-050。
**原文短引**：“选线是必经的闸，不是必答的题。”；“每次开新章工作台第一屏。”
**为什么是问题**：R13 已拍：上层规划已经定线就直接带过，没定好、作者改线或规划对不上时才问。当前设计依然为每章保留一个选线状态和画面。
**不要做什么**：不要删掉故事线，也不要把切线降成轻动作；只不能把选线屏做成每章必过。

## A7｜关章仍只有三条件，没有六道硬门

**类型 / 严重度 / 证据性质**：A｜硬伤｜已验证
**位置**：`FIRST_SCREEN_SYSTEM_DESIGN_R01.md` §5.1；`M8_PLANNING_DESIGN_R02.md` §6.6；`DAILY_LOOP_WALKTHROUGH_R02.md` §6.1 节点⑬；对照 R13 00、03、05、07 页 ADD-058。
**原文短引**：“三条件齐（移交✓审查清账✓对账无未处置✓）时，收工卡……长出。”
**为什么是问题**：缺了字数达标、任务完成可见、剧情真有进展、质检过、符合章节规划等硬条件。它会让工程把“账务处理完”误做成“这一章可以结束”。
**不要做什么**：不要把“不冲突红灯”扩成唯一大总闸；它只是六道门中的一项。

## A8｜收工卡一亮就翻下一章

**类型 / 严重度 / 证据性质**：A｜硬伤｜已验证
**位置**：`FIRST_SCREEN_SYSTEM_DESIGN_R01.md` §5.2；`DAILY_LOOP_WALKTHROUGH_R02.md` §3 屏 11、§6.1 节点⑬；`WRITING_DESK_DESIGN_R02.md` §4.1；对照 R13 03、05、07 页“收工 ≠ 关章”。
**原文短引**：“收工卡亮起那一刻，所有入口悄悄翻页。”；“槽位 `slot_status` 加新值 `closed`（已收工·无正文入库）。”
**为什么是问题**：无书稿收工只代表规划侧完成，不代表章已经关闭，更不能自动把入口切到下一章。当前稿仍把几个不同动作压成一个“翻页时刻”。
**不要做什么**：不要取消无书稿收工；它可以存在，但不能冒充关章。

## A9｜正文对账仍是必跑工序

**类型 / 严重度 / 证据性质**：A｜硬伤｜已验证
**位置**：`M8_PLANNING_DESIGN_R02.md` §6.7；`DAILY_LOOP_WALKTHROUGH_R02.md` §6.1 节点⑫；对照 R13 00、03、05、07 页 ADD-058。
**原文短引**：“对账跑不跑不分档——账必须对。”
**为什么是问题**：R13 明确正文对账是可选一站。当前设计把它写进每章主干和收工完成态，会让没有书稿、关闭书稿对照、只在规划账工作的作者无法自然结束一章。
**不要做什么**：不要读成“创作侧从此不检查”；可选的是书稿对账这一站，不是取消质检和一致性检查。

## A10｜书稿入库仍自动移交，默认正文赢

**类型 / 严重度 / 证据性质**：A｜硬伤｜已验证
**位置**：`M8_PLANNING_DESIGN_R02.md` §6.1／§6.2；`DAILY_LOOP_WALKTHROUGH_R02.md` 屏 8；`STOP_POINT_REGISTRY_R01.md` P13；`PLAN_LEDGER_STORAGE_DESIGN_R02.md` §3.2；对照 R13 02、03、05 页 ADD-041／055。
**原文短引**：“粘贴入库与移交同一下，不加确认。”；“默认正文赢自动更新＋偏差标注挂着。”
**为什么是问题**：R13 已收窄为：外写新稿默认只对照，只有作者显式选择“以这篇为准”才交棒；产品里开写后规划账仍是工作真值。当前稿仍把文件出现当成权力移交。
**不要做什么**：不要补一个新的自动判定规则替作者决定哪边是真。

## A11｜章计划仍被叫成“事实句层”

**类型 / 严重度 / 证据性质**：A｜硬伤｜已验证
**位置**：`M8_PLANNING_DESIGN_R02.md` §0、§4.1；`TUTORIAL_SCRIPTS_DESIGN_R01.md` 屏 C3；`WRITING_DESK_DESIGN_R02.md` §0；对照 R13 01、03、05、07 页 ADD-051。
**原文短引**：“铺成事实句层的章计划。”；“每场带：事实句层（这场过后账上多什么）。”
**为什么是问题**：R13 已拍：计划可以长得像事实句，但必须明确还没发生，不许叫事实。当前词会直接污染模型输入、UI 和账务身份。
**不要做什么**：不要借本条发明新的字段、枚举或账名；这里只报身份用词错了。

## A12｜系统直接产出完整小说对白

**类型 / 严重度 / 证据性质**：A｜硬伤｜已验证
**位置**：`DAILY_LOOP_WALKTHROUGH_R02.md` 屏 6；对照 R13 01、03、05 页“不生成书稿成文”。
**原文短引**：“白翁：『雪夜的记忆最出油——冷的东西，烧起来才旺。』”
**为什么是问题**：这不是“对白要透露什么”，而是一句完成度很高、可直接粘进小说的台词。它会把产品从提示词工厂滑向写作模型。
**不要做什么**：不要把它解释成“只是示意文案所以正式产品也能这么出”；示意稿同样会决定施工边界。

## A13｜冻结的收费边界仍写成正式路径

**类型 / 严重度 / 证据性质**：A｜高风险｜已验证
**位置**：`TUTORIAL_SCRIPTS_DESIGN_R01.md` §0、B9、C5；`INTAKE_SHELVES_DESIGN_R01.md` §1.7；`FIRST_SCREEN_SYSTEM_DESIGN_R01.md` §4.3；对照 R13 00、01、05、08 页收费冻结。
**原文短引**：“出口：继续写第 4 章（付费）。”；“付费解锁后直接入架。”
**为什么是问题**：R13 只保留“小抄整理收费”这一条已开的缝，价格数字、免费额度和其它付费墙仍冻结。当前设计却已经用付费决定教程出口、导入章数和续写权。
**不要做什么**：不要因设计稿里出现过就把这些收费分界当成已拍合同。

## A14｜27 个组件被重新写成首批

**类型 / 严重度 / 证据性质**：A｜高风险｜已验证
**位置**：`PLUGIN_CONTENT_WORKORDER_R01.md` §0／§1；对照 `PLUGIN_SKILL_SYSTEM_DESIGN_R02.md` §7，以及 R13 00、02、03、05、07 页 ADD-024。

**为什么是问题**：R13 已明确 20～32 个只是后续内容生产候选批次，不是首发面。当前内容工单把候选规模重新抬成“首批”，会把 MVP 内容量直接膨胀三倍。
**不要做什么**：不要删除 27 个候选内容；只不能把它们当 V0 首发承诺。

## A15｜暗稿开放题被设计稿提前钉死

**为什么是问题**：R13 明确这两件事仍开放。当前稿不但选了答案，还把它写进下游、体检和进度状态，后面很容易被误当已拍合同。
**不要做什么**：不要在本轮替 CZ 选择暗稿身份，也不要顺势开新真值表。

## A16｜仍宣称产品内创作靠生成约束保证质量

**不要做什么**：不要把两条都做成同权重主路径再让用户自己理解差别。

## B4｜同一个“章完成”有四套判定

**类型 / 严重度 / 证据性质**：B｜硬伤｜已验证

**不要做什么**：不要让这条技术冲突抢走入口／关章等主语义返工的优先级。

## C1｜“第一屏”没有说明是项目级还是模式级

**为什么是问题**：有人会把它们理解为模式内部第一页，有人会理解为点进项目后的第一眼，结果就是各页面都抢路由根节点。
**不要做什么**：不要因本条新增更多“第零屏／第 0.5 屏”术语。

## C2｜收工、关章、关闭、翻页、移交被混着用

**类型 / 严重度 / 证据性质**：C｜含糊｜已验证
**位置**：`FIRST_SCREEN_SYSTEM_DESIGN_R01.md` §5；`WRITING_DESK_DESIGN_R02.md` §3／§4；`M8_PLANNING_DESIGN_R02.md` §6；对照 R13 03、05、07 页。

**为什么是问题**：后面的人无法判断 `closed` 是“今天不写了”“规划做完了”“章节真正关闭”还是“已经切到下一章”。
**不要做什么**：不要在本扫描里替项目冻结字段名；这里只要求语义不能一词多义。

## C3｜“正文为准／正文赢”没有说明作用范围

**原文短引**：“实际写成师妹遗忘（正文赢，作者已阅）。”；“已移交·正文为准。”
**为什么是问题**：它可以被读成“这次偏差作者接受书稿版”，也可以被读成“一旦有书稿，整本规划失去真值权”。这两种施工完全不同。
**不要做什么**：不要再使用一个裸的“谁赢”覆盖所有导入、产品内写作和外写交棒场景。

**原文短引**：“现行”“待随 R10 小修”“R02 已返工”“新交付”并列。

**不要做什么**：不要把“文件最新”直接等同“语义可施工”。

## C5｜低影响暗稿“默认发生”，又被称为“作者签字”

**为什么是问题**：背景板明确要求只有当前代码、测试或正式结果票才能证明已具备。设计稿本身不能给七个模块发完成票。

**读得较浅**：拆书、体裁节奏、角色视角、场景卡等衍生稿。它们做了全文关键词和结构扫描，但没有逐个枚举内部字段，因为当前不会决定作者 MVP 第一屏和日常循环。

* 历史 R01 按约定没有读，也没有从现行 R02 的转述反猜历史原文。
* ADD-043／044、题 16 和暗稿后续仍按开放问题处理；本扫描没有替它们给答案。
