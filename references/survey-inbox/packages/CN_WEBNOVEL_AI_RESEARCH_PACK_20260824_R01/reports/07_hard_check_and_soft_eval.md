# 硬检查与软评价：优秀样本应该怎样使用

## 结论先说

故事工具必须把两类问题彻底拆开：

- **硬检查**回答“这段是否违反了已经明确成立的事实、时间、知识或规则”；
- **软评价**回答“这段是否可能无聊、套路、拖沓、情绪不足、披露过早或人物不够动人”。

前者可以在证据充分时强提醒；后者没有唯一答案，只能提供带依据的诊断、对比和候选。

“优秀小说中被读者称赞的片段”可以研究，但更适合抽取**可解释的结构模式**，不适合把原文喂给模型后要求照着写，也不能把销量、榜单或评论直接当成剧情质量真值。

## 1. 为什么不能给故事一个总分

### 1.1 创意写作没有统一正确答案

同一个章节可以：

- 在爽文里被嫌慢；
- 在悬疑里被认为有耐心；
- 在关系文里被赞细腻；
- 在升级文里被认为不推进。

评分必须知道作品承诺、题材、当前阶段和目标读者。

### 1.2 自动评委与专业判断仍有明显距离

Art or Artifice 让专业创作者评价人类和 LLM 故事，发现 LLM 作品在多项创意检查上明显落后，而且 LLM 自己当评委时与专家判断没有可靠正相关。

LitBench 使用 43,827 对训练故事和 2,480 对人类标注测试故事。最好的现成 LLM 评委与人类偏好约 73% 一致，专门训练的奖励模型约 78%。这个水平可以用于排序候选或触发复审，不能当真值。

### 1.3 一致不等于好看

Dramatron、Fabula 和 CritiCS 相关研究共同暴露一个风险：系统越努力消灭奇怪、不规则和不一致，故事越可能走向保守、公式化。创作有时需要意外、留白、错位和不完全解释。

## 2. 三层评价模型

### 2.1 硬检查层

有明确证据和规则，可以判断相容或不相容。

| 类别 | 例子 | 适合的输出 |
|---|---|---|
| 事实 | 已毁物品再次出现 | 冲突 + 两端证据 |
| 时间 | 同一时刻身处两地 | 时间区间冲突 |
| 地点/旅行 | 三日路程半日抵达 | 条件不足或冲突 |
| 人物知识 | 未得知秘密却直接使用 | 知识泄漏 |
| 世界规则 | 明确限制被无解释违反 | 规则冲突 |
| 状态 | 重伤未恢复却无代价战斗 | 状态疑点，视规则强度决定是否硬判 |
| 因果 | 原因被删除，后果仍发生 | 因果链断裂 |
| 计划/事实 | 未发生计划被当成回忆 | 计划与事实混淆 |

### 2.2 半硬诊断层

有结构证据，但没有唯一标准。

| 类别 | 可检查的证据 | 为什么不能硬判 |
|---|---|---|
| 人物动机 | 目标、行动、已知信息、代价 | 人可以冲动、自欺或临时改变 |
| OOC 风险 | 稳定特征与当前行为差异 | 重大成长或伪装可能合理 |
| 关系跳变 | 两次关系状态之间缺少事件 | 有些关系可因单一重大事件骤变 |
| 披露顺序 | 谁知道、读者何时知道 | 提前揭示也可能产生反讽 |
| 伏笔强弱 | 埋点频率、显著性、回收距离 | 题材和目标读者差异很大 |
| 重复信息 | 相似披露或解释多次出现 | 重复可能用于强调或照顾断更读者 |
| 节奏偏移 | 计划粒度与实际篇幅差异 | 慢节奏可能是作者有意选择 |

输出应该叫“风险”或“可能问题”，并给作者选择。

### 2.3 软评价层

包括：

- 有趣程度；
- 爽感或获得感；
- 情绪冲击；
- 原创性；
- 人物魅力；
- 文风；
- 对话质感；
- 主题深度；
- 读者满足；
- 节奏美感。

只能用多视角、比较和真实读者反馈来提高可信度，不能做自动真值。

## 3. 软评价怎样拆得更可用

不要问“这一章好不好”，要问更具体的问题。

### 3.1 目标是否清楚

- 读者能否知道当前人物想做什么；
- 阻力来自哪里；
- 本章结束时发生了什么变化。

### 3.2 信息流是否有效

- 新信息给了谁；
- 读者比人物知道得多还是少；
- 关键答案是否提前泄露；
- 是否缺少理解当前行动所需的前提；
- 是否反复解释已经清楚的内容。

### 3.3 期待如何建立和处理

- 本章开头让读者期待什么；
- 中途是否升级、转向或延迟；
- 章末兑现了什么；
- 新开了什么问题；
- 延迟是否有新的价值，而不是单纯拖延。

### 3.4 人物行动是否有代价和选择

- 人物是在被剧情推着走，还是做了选择；
- 选择是否改变局面；
- 代价是否真实；
- 不同人物是否有不同利益。

### 3.5 章节是否产生状态变化

变化可以是：

- 获得或失去资源；
- 关系变化；
- 目标变化；
- 知识变化；
- 风险变化；
- 地位变化；
- 决心变化；
- 读者理解变化。

没有明显变化不等于差，但如果连续多章没有变化，就值得调查。

## 4. “答非所问”算不算好对话

答案是：**有条件时可以很好，没有条件时只是故弄玄虚。**

### 可能有效的情况

- 人物在隐藏真实意图；
- 权力关系使其不能直接回答；
- 角色用另一个问题夺回控制权；
- 对话表层和潜台词不同；
- 回避本身暴露了情绪；
- 读者已经知道答案，重点是人物如何躲避。

### 容易失败的情况

- 作者不知道角色该怎么回答；
- 每个人都说谜语；
- 重要信息被机械拖延；
- 人物明明有共同目标，却无理由拒绝沟通；
- 回避没有产生新的压力、信息或关系变化。

### 可抽取的结构卡

```yaml
pattern: "答非所问制造潜台词"
preconditions:
  - "提问触及角色不愿公开的信息"
  - "双方存在权力、信任或利益张力"
observable_move:
  - "角色转移问题、反问或回答邻近话题"
reader_effect:
  - "读者从回避方式推断真实情绪或秘密"
required_payoff:
  - "回避必须改变关系、风险或读者判断"
failure_modes:
  - "纯拖延"
  - "所有角色同一种说话方式"
  - "没有后续回收"
```

这比给规则“优秀对话应该答非所问”可靠得多。

## 5. 优秀作品怎样转成可学习的模式

### 5.1 先确定材料权限

适合使用：

- 公版作品；
- 已获得许可的作品；
- 作者自己的作品；
- 平台与作者明确允许用于研究的语料；
- 只保存抽象结构、不保存可还原表达的人工标注。

不建议把大量在售作品原文作为可检索模板库，更不建议要求生成“像某位在世作者”。

### 5.2 不用“名著片段 = 正确答案”

受欢迎片段受很多因素影响：

- 前面几十万字积累；
- 角色已有感情基础；
- 平台和作者名气；
- 题材受众；
- 更新时间；
- 同期竞争；
- 读者社区传播。

脱离上下文复制结构，可能完全无效。

### 5.3 抽取模式卡，而不是句子模板

每个样本可以标：

- 作品与章节背景；
- 这一段要解决的问题；
- 读者此前知道什么；
- 人物各自知道什么；
- 期待是怎样建立的；
- 事件和状态怎样变化；
- 信息在哪一步披露；
- 张力怎样升降；
- 对话每一句承担什么功能；
- 为什么这段在此处有效；
- 换到什么条件下会失败；
- 读者或评论证据；
- 标注者分歧。

### 5.4 保存反例

只收优秀案例会产生幸存者偏差。还要收：

- 同类结构但效果差的片段；
- 被读者误解的片段；
- 作者后来承认失误的路线；
- 同一作品里成功与失败的对比；
- 不同题材使用同一结构的差异。

### 5.5 用匹配条件检索

作者当前要写“师徒决裂”时，不要按关键词找所有决裂片段。应该匹配：

- 关系阶段；
- 双方权力差；
- 是否存在误会；
- 谁掌握真相；
- 这一场要永久决裂还是假决裂；
- 读者是否知道内情；
- 本章希望产生什么后果。

检索结果是参考模式，不是模仿指令。

## 6. 节奏可以量化到什么程度

### 可以观察

- 事件密度；
- 状态变化频率；
- 新问题与回收比例；
- 同一故事线停更章数；
- 目标提出到行动的距离；
- 铺垫到回收的距离；
- 高强度事件之间的间隔；
- 场景切换频率；
- 对话、行动、解释的比例；
- 章节长度与留存变化。

### 不能直接判好坏

- 事件密度高不一定好；
- 每章都钩子可能疲劳；
- 慢章可能承担情感、世界观或后果；
- 留存变化不等于文学质量；
- 同一节奏模板不能跨题材通用。

CONCOCT 把 pacing 理解为语义粒度和具体程度，而不只是长度。这个方向可借鉴：系统可以指出“这部分比周围过于概括”或“这一小点展开异常长”，但仍由作者判断。

## 7. 评价器的推荐层级

### 层 1：确定性规则

结构完整、时间算术、状态冲突、知识边界、重复 ID、证据缺失。

### 层 2：证据化模型诊断

要求模型：

- 指出具体文本；
- 说明参考的作品约束；
- 提供反例解释；
- 标注置信度；
- 不输出总分。

### 层 3：成对比较

比较两个章节方案，更容易回答：

- 哪个更符合当前人物目标；
- 哪个更早泄露答案；
- 哪个更好承接上一章；
- 哪个对旧伏笔利用更多。

比“给方案打 8.6 分”更可解释。

### 层 4：模拟不同读者视角

可分别模拟：

- 新读者；
- 连续追更读者；
- 偏关系读者；
- 偏剧情读者；
- 已经猜到真相的读者。

这些输出只是候选反应，不是假装真实用户。

### 层 5：真实读者和编辑反馈

最终软评价仍需真实受众。产品可以帮助归纳，但不能替代。

## 8. 评价结果怎样呈现

不建议：

> 综合质量 82 分；节奏 76 分；人物 91 分。

建议按问题卡呈现：

> **信息披露风险：幕后主使可能过早暴露**  
> 依据：第 187 章新增加的账本印章，与第 139 章黑色军令上的印章完全一致；当前读者已经知道军令来自城主府。  
> 可能效果：熟悉前文的读者可能在本章中段直接锁定城主。  
> 这不一定是错误：若目标是让读者早于韩夜知道，能制造“看着人物走近危险”的戏剧反讽。  
> 候选处理：保持 / 遮掉印章全貌 / 让印章指向中间人 / 明确采用读者先知路线。

## 9. 优秀样本研究的实验设计

### 建立成对样本

- 同一作品中读者反应明显不同的两章；
- 作者原稿与修改稿；
- 同一结构在不同题材中的成功与失败例；
- 人类作品与 AI 仿写，但必须合法取得材料。

### 多人标注

让作者、编辑、目标读者分别标注。不要强行消除分歧，分歧本身就是软评价的证据。

### 验证模式迁移

把模式卡用于新的写作任务，观察：

- 作者是否觉得有启发；
- 是否降低思考成本；
- 是否产生套路化；
- 是否改变作品声音；
- 读者是否真的更喜欢；
- 适用条件是否被正确识别。

## 10. 产品边界

- 硬检查可以有挡关能力，但应允许作者强制通过并记录原因。
- 软评价默认不挡关。
- 评价器必须知道作品自己的目标，不能只套通用写作法。
- 不把平台数据、热度或评论数当作品质量真值。
- 不把模型解释写成“专业编辑结论”。
- 不把优秀样本变成特定作者风格复制器。
- 不因追求一致性删除作者故意的怪异和冒险。
