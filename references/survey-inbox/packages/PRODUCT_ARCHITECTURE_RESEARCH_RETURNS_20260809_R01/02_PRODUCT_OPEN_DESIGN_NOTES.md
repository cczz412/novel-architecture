# 产品大问题逐个过：已有什么、缺什么、我的判断

- 给 Codex 的提示：这里的「已有」都核对过 R04 背景板原文，引用格式「文件:行」，文件在 `references/shared-context/NOVEL_ARCH_SHARED_CONTEXT_CORE_MATERIALS_20260808_R04/`。

## 总的画面

CZ 的所有疑问其实指向同一件事：**事实句子是「建筑材料」，但现在整个项目只有「采石场」（抽取），还没有「施工图」（下游怎么用材料盖楼）。** 下面八个问题，前四个是「材料够不够好用」，后四个是「盖楼的规矩还缺哪些」。

## Q1 大纲阶段能不能高效承接事实句？（给多吸收少的错配）

**已有**：执行包概念清单——全章大纲、上一场结尾、人物状态知情、到期义务、直接原因、按需回取的证据等九类（`03:50-60`）；明确「不默认塞上一章全部事实」（`03:62`）。

**缺口**：没有容量合同。上游一章能抽 100 条，下游一次该吃几条、按什么优先级选、吃不下的放哪，全空白。也没有任何实验测过「多喂 vs 少喂事实句，续写质量差多少」。

**我的判断**：这是当前最值得先补的一块，因为它决定抽取侧该优化什么。建议把「下游承接」立成一个新实验家族（比如叫 CONSUME）：固定一批已抽好的事实句，只改「喂给大纲/续写的条数和选法」，看续写质量和吃书率。不用等豆包，4B 甚至现成 API 就能做零训练版本。⚠️ 立家族要走 R02 路线图的登记规矩，这是给 Codex 的工单活，不在本窗口直接干。

## Q2 光靠事实句子，撑得起「好看」吗？（钩子、爽点、期待、人物）

**已有**：架构上其实想过这层——Hook 与故事内义务分表（D23，`01:124`）；技巧和爽点可作「处理配方／读者效果」但不进正史（D25，`01:126`）；节奏、手法、情绪偏离亮黄灯（`03:99`）；知情分「角色知识／读者释放／作者私有」三层（D21，`01:122`），「读者释放」这层就是给读者期待留的钩子。

**缺口**：这些都是「留了位置」，位置上没有东西。铺垫、情绪曲线、人物弧光在 R04 里没出现过；「读者效果」层没有对象定义，没有任何抽取或分析任务往这层供料。

**我的判断**：事实句子单独撑不起「好看」，但架构没走错——正确分工是：**事实句管「真」（不吃书），效果层管「好看」，两层分开、后者引用前者**。缺的不是把爽点塞进事实句，而是给效果层立对象（钩子、悬念账、期待账、情绪标注），它们的载体可以就是「一组事实句 ID + 一个效果标签」。这样底座不用改，上面加层就行。这是设计题，不是背景板写偏。

## Q3 拆书包／创作方法论／文学理论，这套结构吃得下吗？

**已有**：只有 D25 一句「技巧和爽点可作处理配方」，以及「外部研究只提供先验」的口径（`04:62`）。没有任何接入机制。

**缺口**：从「拆一本别人的书」到「变成我这本书能加载的包」，中间缺一个**配方格式**：拆书产物长什么样、挂到大纲中枢的哪个环节（大卡建议？关章检查项？QC 黄灯规则？）、和作者自己的事实句怎么对上。

**我的判断**：可行路径是把拆书产物也表示成「结构化断言 + 证据坐标」——跟我们抽自己小说的事实句同构，只是对象是别人的书、断言类型是「手法/节奏/结构」而不是「剧情事实」。这样一套抽取能力两用，配方包天然和底座同格式。这个想法需要外部调查支撑（市面拆书方法论怎么结构化、有没有现成 rubric），已列入外发调查 BRIEF_03。

## Q4 「情绪不够、钩子强度不够」这种判定，标准从哪来？

**已有**：只有黄灯机制的壳（`03:98-103`），没有判定标准。

**缺口**：全部。怎么算高怎么算低，谁说了算，误报率能不能让作者忍受——都没有。

**我的判断**：这是八个问题里最难的，别指望一步到位出「客观标准」。现实的路是三级：① 先用可数的代理指标（本章结尾是否有未决问题、悬念账里未回收条目的年龄分布、情绪标注的转折密度）；② 用「同类型高分书的统计分布」当参照系，而不是绝对阈值；③ 判定只出黄灯和理由，永远让作者豁免。学界对 emotional arc、suspense 建模有不少现成工作，值得外发调查（BRIEF_04）再定方案，别自己闭门发明。

## Q5 写到 50 章，前 49 章怎么伸缩？（4700 条 → 200 条）

**已有**：方向拍得很清楚——当前完整、近期展开、远期压成带覆盖编号和过期状态的一句话、关键因果保留头尾、不可逆变化长期保留、切故事线优先接回同线材料（D11+D27，`03:66-73`）。

**缺口**：从方向到机制的全部：收缩比、丢弃优先级、覆盖编号生成规则、以及 CZ 说的「人讲故事原则」——大背景一句话带过，但**和本章要写的事有铺垫关系的旧细节要单独捞出来**。这个「按当前任务反向捞旧细节」的机制（本质是相关性检索，但检索对象是事实句不是正文分片）没人设计。

**我的判断**：伸缩要拆成两件事分开做：**默认压缩**（按远近和重要性，机械规则可算）和**按需捞回**（按本章大纲的实体/义务/故事线，反查相关旧事实句）。前者保证不超预算，后者保证铺垫不丢。覆盖编号+过期状态已经是对的设计（读到压缩句可以顺藤摸回原始事实句和原文）。量化尺度建议外发调查（BRIEF_01：分层记忆压缩在长文创作系统里的现成做法）+ 本地小实验定。

## Q6 事实句会不会淡化了因果和「可回退性」？（原来设想的逻辑句）

**已有**：D24 拍过——逻辑句不做一级长期对象，拆成因果边、前置条件或桥接方案（`01:125`）；伸缩压缩明确「关键因果保留头尾」（`03:71`）；长线账里有故事线、因果、义务、规则、触发条件（`02:13`）。

**缺口**：因果边的**抽取**没有任何实验。19 个家族全在抽「事实」，没有一个抽「因为 A 所以 B」的边。长线账要靠因果边撑，供料通道还没影子。

**我的判断**：CZ 的担心方向对但结论可以放宽：架构上因果没被丢掉，是被挪到「边」的位置了（事实句是节点，因果是节点之间的连线）。真正的坑是**边的抽取比节点难得多**（因果常常是隐含的、跨章的），当前抽取管线完全没碰。建议：先不另起炉灶，等事实句抽取稳定后，加一个「第二阶段在已有事实句之间连因果边」的家族——现有 COREF 家族（第二阶段解析指代）已经开了「两阶段后处理」的先例，因果边可以走同款结构。

## Q7 长程一致性、不吃书，机制够吗？

**已有**：概念层齐的——后台长线账当长程约束（`02:33`）、硬事实冲突红灯（`01:75`、`03:98`）、改事件结果要提名受影响项（`03:94`）、确认稿冻结带 SHA。

**缺口**：红灯的**检测器**不存在。新写的一场和 4700 条旧事实句之间怎么高效查冲突（不可能每场全量比对），没有设计。这和 Q5 的「按需捞回」其实是同一个检索问题的两面：写之前捞相关旧事实是「供料」，写之后拿新事实反查矛盾是「验收」。

**我的判断**：把 Q5 和 Q7 当一个问题做：同一套「按实体/故事线/义务索引事实句」的机制，既服务加载也服务查冲突。矛盾检测的现成方法（NLI、实体状态跟踪）值得外发调查（BRIEF_05）。

## Q8 底座还缺什么结构？（我补充的盲点）

CZ 让我想「还有没有没考虑到的」。抽查完全套材料后，我认为还缺这四样，按重要性排：

1. **世界规则/常识账的供料**：D26 把世界规则分了四类（作者声明、正文确认、导入设定、AI 推断），但和事实句抽取一样，只有分类没有抽取通道。吃书往往吃在「设定」而不是「事件」上（金手指规则前后不一致），这块比事件事实更该有硬约束。
2. **时间线对象**：事实句有先后，但「故事内时间」（三天后、同一夜）没有表示。长篇最常见的吃书之一是时间账算错。
3. **抽取质量的置信度分层**：下游消费时需要知道哪些事实句是高置信、哪些是模型猜的。现在的表示里有 status 字段（8 个中文值），但下游按置信度差别对待的规则没定。
4. **「效果层」对象**（接 Q2）：钩子账、悬念账、期待账，作为旁挂层引用事实句 ID。

## 和当前 4B 微调工作的关系

以上都不改变当前主线（4B 上找最优抽取格式）的正当性——材料还是要先抽好。但有一个排序建议：**Q1 的下游承接实验（零训练版）值得和抽取优化并行跑起来**，因为它的结论会反过来告诉抽取侧「什么才算够好」——比如下游如果证明 200 条压缩句就够用，那抽取侧的召回率目标就不用死磕到顶。
