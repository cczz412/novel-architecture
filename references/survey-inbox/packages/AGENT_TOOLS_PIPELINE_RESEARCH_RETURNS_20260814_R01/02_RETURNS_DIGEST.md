## 一句话

七份回包没有推翻已拍边界。它们把同一件事说清楚了：聊天、点选、外部 Agent、管理员口，必须走**同一张动作清单、同一道权限门、同一份进度**；模型只能申请，不能自己改真值、关章、开卡。

现在不该去做的：作者版 CLI、把后台每一站都暴露成工具、主屏上堆「候选 219」、给故事打健康分。

现在该先想清楚的三块（仍是设计，不是开工令）：工具菜单怎么按意图露出、管线游标放服务端、生成前检查器给覆盖回执而不是裸 `OK`。

## 对照已拍：采信 / 已有 / 驳回

### ✅ 采信（和已拍同向，值得当设计形状）

- **三张工具菜单，不是一张万能清单。** 作者主 Agent、外部 MCP、管理员检修，能力内核同一套，可见工具不同。外部永远没有写真史入口。
- **按意图露工具。** 「聊聊如果」看不到提案工具；「谁知道密道」只读；签字入账不经过模型。
- **一个会改状态的动作只有一个 action_id。** 不要 `chat_update_outline` 和 `card_update_outline` 两套。
- **拆两个旋钮：** `effect_ceiling`（这次最多影响到哪）和 `advance_policy`（走完这一步是自动续，还是等作者点）。小白少停、高级多停，对应的是第二个旋钮，不是另一套权利。
- **游标在服务端。** 聊天、卡片、以后的管理员命令都提交「带游标版本的命令」，服务端重检。模式从游标推导，不要模式一份、游标一份。
- **完成要拆开：** Agent 这轮说完 ≠ 工件好了 ≠ 卡片处理完 ≠ 作者确认了 ≠ 章节关了。关章只认作者关章事件。
- **编译器编铁律和当前状态；RAG 找模糊相关；多跳缺口才让检索 Agent 最多跑两轮。** 回取后整包重编，不要往旧包末尾堆。
- **检查分三条通道：** 硬规则可阻断；检索多捞、红灯要准；小模型超时写成未检查，不能偷偷当 OK。
- **触发器外壳统一、业务表分开。** Hook 和义务分表。计划可以让 Hook「相关」，不能让义务「已兑现」。章号不当触发条件语义。
- **指示器四种颜色就够。** 作者能处理的单位才显示数字。节奏诊断只说症状；插件不自动套理论。

### 🧩 已拍里本来就有（回包是在加固，不是新方向）

- 正史签字必须作者显式动作；聊天说「好的」「都确认」不算。
- 外部 MCP：只读 + 本地提案。
- 触发默认亮灯，不开卡。
- 停点三档：自动通过 / 提醒不停 / 必停。停点放行 ≠ AI 可写真值。
- 硬冲突才能挡住静默关章；没检到只能说覆盖范围内未检出。
- 执行包必须瘦；知情至少要能表达已知道 / 不知道 / 被误导。
- 插件／理论不自动冒出来。
- 现在的 CLI 是检修口，不是作者主界面。

### ❌ 驳回或不要照搬

- **不要做作者版 CLI。** 回包里「主屏最少显示什么」是给画布／聊天投影用的，不是让命令行当作者产品。
- **不要把后台每一站做成工具。** 内部站点由后端封装。
- **不要一个带 `mode` 的万能工具**把查询、建提案、签字塞在一起。
- **不要裸 `done` / 工作流 `completed` 直接接关章。**
- **不要把 VS Code / Cursor「改了就落盘」搬到故事真值。** 回包自己举了反例：适合有 Git 的代码区，不适合 Bible／来源认领。Replit、过度凭证删库，说明「提示词写着别动」不够。
- **不要用事实句关键字直接判冲突。** 它只能帮你找到可能相关的材料。
- **不要相信检查器只回一个 OK。** 没有覆盖范围、版本、未查项，那个 OK 是假的。
- **不要把 Hook、义务、世界规则、计划合成一张业务表。** 外壳可以统一。
- **不要小说健康分、主屏候选总数、token、工具调用次数、模型自报置信度。**
- **不要「检测到三章无兑现 → 自动启用救猫咪 → 建议改大纲」。**
- **不要章号当触发条件。** 最多以后做导航位置。
- **不要关闭聊天／关掉窗口变成改主数据。** 回包举了 Cursor 关聊天触发 Git 回滚的同类事故。

### ⚠️ 回包里像建议、但还不能当合同的

- 「每轮 5–9 个工具」是保守起点，回包自己写了待实测，不是行业定律。
- 工具名（`truth_search_confirmed_facts` 等）是命名草案，不是本仓字段合同。
- 「日常最频繁是召回噪音、后果最严重是丢不可逆」是工程判断，没有长篇章纲场景的统一频率研究。
- Unity Ask/Agent、Figma Apply、Power Automate Draft/Published 是可借形状；不能把它们的字段抄进账本。
- R10 草案里仍有替拍段；本包消化不把替拍升级成亲拍。

## 先做哪一层（仍不是开工令）

按「作者马上能感到控得住」排序，而不是按后台站点数：

1. **动作清单 + 意图门控。** 同一 `action_id`；画布按钮禁用时，聊天里对应工具消失；正史签字不进工具表。
2. **服务端管线游标。** 当前步骤、当前章／卡／版本、谁能改；非法动作回执写清「现在在哪、为什么拒绝」。
3. **生成前检查器的覆盖回执。** 查了哪些、缺哪些、用了哪个事实版本；主 Agent 只看压缩后的 OK / 缺料 / 有问题。
4. **指示器投影。** 红／黄／灰／进度四种；三张脸读同一张小票，各自决定说多长。
5. **触发器外壳。** 先统一匹配与投影，业务表继续分开。
6. **执行包编译器。** 铁律强制进包；RAG 只找候选；缺料最多两轮回取。

管理员 CLI 继续当检修口，去读这些对象，不要另做一套作者命令。
