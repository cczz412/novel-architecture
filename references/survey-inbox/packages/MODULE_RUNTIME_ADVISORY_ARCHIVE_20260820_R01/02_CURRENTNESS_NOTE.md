# 当前口径校正｜模块运行历史顾问设计

这份校正只解决一个问题：材料很多，但不能让旧结论冒充今天的小说辅助产品。

## 今天优先看什么

- 产品方向优先看 R14。外来正文走 M1～M5 入料车道；小说辅助产品自产的章事实稿不回 M2／M3 重抽，而是按 C11 方向登记当前版。
- 长期需求优先看 R03 的 142 条原子需求。旧报告只核过 127 条，少了双车道、十本账、M7 优化工作台、M9 驾驶舱等 15 条新需求。
- 当前能力优先看当前分支代码和直接测试。报告里的“还没有”“已经完成”“应当开票”都是当时快照，不能跳过现行代码核验。

## 每份材料今天怎样用

### 模块扩展候选架构

它保留 M1～M11、反对为了凑流水线而随意合并模块，这个观察仍有参考价值。它把作者自产内容写成“工作稿回 C1 后再进 M2”，已经被 R14 的双车道改判；“工作稿”也改成了“章事实稿”。里面按 R13、127 条需求做的映射只能当历史对照。

### 六报告组件设计与任务卡

它列出的 M3 严格解析、M9 已确认事实准入、M10 时间阶段、T14 保存读回、M8 选择写回、章节交棒和 M11 脱敏，后来有些已经做成窄切片，有些被重新定义。现在更适合拿它的输入例子、失败场景和验收边界做回归检查，不适合把 7 张卡原样重派。

### 首批内容试点与 0 API 材料清单

它们保留了合成材料怎么拆单变量、怎样先过身份门再做语义评分、哪些红线要直接停止等方法。20 个 0 API 场景后来已有一次本地重放，但那次结果也只是历史快照。当前需求已经从 127 增到 142；新的 15 条需求还要补自己的 6 例设计。

API 试验部分从来没有获得执行权。当前模块、路由、模型、费用和材料范围都可能已变化；若以后要跑，必须另拿 CZ 当次明确授权并重新冻结输入。

### 三个机械问题的候选实现

M3／M4 运行回执、完整批次门和 M11 取件码的部分思路后来已被本地吸收、收紧或改写。候选补丁仍值得云端 Agent 对照字段、测试和失败顺序，但不能直接套到当前代码，也不能拿候选补丁里的测试通过数替代当前测试。

M1 水印当时停在产品语义选择。CZ 后来已拍“保守版”：不能静默删除或改写正文。更细的重复判等、提示方式和阻断范围仍应回当前需求与代码核对，不能让旧补丁替产品拍板。

### 当时的本地吸收说明

它记录的是 2026-08-20 那次吸收后的判断，适合回答“当时为什么收或不收”。其中分支提交、测试数量、127 条需求和未决项都可能已经过时。当前代码、R14、R03 和最新进度记录优先。

## 云端 Agent 可以做什么

- 用原文找当前代码可能遗漏的异常场景。
- 比较旧候选和当前写法，提出更小、更干净的重构方案。
- 发现旧建议已经被代码覆盖时，给出可核验的文件和测试位置。
- 发现旧建议与 R14／R03 冲突时，明确指出冲突，不替 CZ 静默改产品语义。

不能从这包外推模块完成、真实内容质量、API 权限、训练权限、Gold 身份或生产可用。
