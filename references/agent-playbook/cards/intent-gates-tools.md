# 先分清要做什么，再开放对应工具

身份：当前权限纪律

## 遇到什么

用户只是讨论剧情或查询材料，Agent 却拿到全部写入工具；或者用户已经授予某项托管权限，系统仍把所有动作都当成只能逐条手签。

## 对的做法

先区分探讨、只读查询、生成候选和正式改动，再只开放当前任务需要的最小工具。真正的权限判断放在模型之外，要同时检查主体、对象、动作、用途、项目、有效期和当前授权范围。

作者可以授予、收回范围权限。受控接口可以生成候选，也可以在获准范围内执行规定动作；它不能因为提示词说“可以”就越权，也不能把一次授权扩成永久全权。重大剧情变化仍在章末集中回执。

## 错的做法

聊天里说过一次“都交给你”就永久开放所有项目。查询任务拿到写真值工具。把工具描述里的“只读”当成真实权限证明。为了安全而把每个普通选择都变成停点。
