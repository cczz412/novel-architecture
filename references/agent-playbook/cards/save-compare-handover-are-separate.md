# 保存、对照、交棒是三件事

身份：已拍加固

## 遇到什么

作者在产品内或外部写完一份新书稿并保存。后续 Agent 准备立即让“书稿赢”、改规划状态；或者反过来，认为没有交棒就不能做计划—书稿对照。

## 对的做法

**已拍：**R14 已把三件事分开：保存只保留作者资产；外写新稿默认只对照；只有作者显式选择“以这篇为准”才发生交棒。原计划仍保留为“当初的打算”。对账回答计划和书稿哪里一致、偏离或新增，不以交棒为前置；交棒决定后续工作真值由谁接管，不能替代对账。

**加固：**SI-016 在当时候选 M8／写作区深处仍看到“入库即移交”“正文赢默认”，又把对账限制为只读已移交对象。这个审查与 R14 同向，用来防保存副作用和流程焊死；`handover_parts`、`slot_status`、操作日志和写权限仍是候选合同细节。

## 错的做法

文件落盘就自动交棒。默认书稿赢并覆盖规划。作者只想保存也被迫改真值方向。没交棒就拒绝显示偏差。用对账结果反推已经交棒。直接照搬 SI-016 的字段和动作序列。把本卡升级成执行票，或把建议写成当前代码已经如此实现。
