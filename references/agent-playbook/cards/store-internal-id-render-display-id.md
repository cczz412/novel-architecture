# 跨账引用认稳定 ID，不认界面编号

身份：已拍加固

## 遇到什么

字段表写一种事实编号，JSON 示例又写另一种；界面显示 `F-0001`，旧合同里还有 `f001`。后续 Agent 准备挑一种顺眼的，直接当跨账外键。

## 对的做法

**已拍：**当前产品口径已把“内部稳定身份”和“给人看的编号”分开。跨账引用必须保存当前正式合同指定的稳定 ID；界面编号只是渲染结果，不能靠截取数字、大小写转换或前缀拼接反推外键。当前产品口径 术语页还保留了编号升版与旧格式迁移记录，所以本卡不裁定 `f001` 或 `F-0001` 哪个是当前存储格式，只要求跟随现行合同和迁移表。

**加固：**SI-016 在当时候选存储稿里发现“正式规则写内部 ID、示例却写显示号”的自撞，说明例子很容易带歪实现。这个审查加固的是身份分层和引用一致性，不是旧格式继续有效的证明。

## 错的做法

把界面文案当数据库外键。通过字符串格式化在两种编号间猜关系。规则和示例冲突时自行选一个。把 SI-016 的 `f001` 结论覆盖当前产品口径的编号迁移记录。把显示编号改名当作实体换号。把本卡升级成执行票，或自行冻结前缀格式。
