# 大纲原稿不能占章节序号

身份：已拍加固

## 遇到什么

导入器要同时保存章节书稿和作者旧大纲。后续 Agent 准备用一个章节数组承载两者，只靠 `kind=chapter／outline` 区分，再把数组顺序当实际章序。

## 对的做法

**已拍：**当前产品口径的材料架已经分开“章节架”和“大纲原稿”。章节架装实际书稿，也是导入侧唯一进入抽取正线的架子；大纲原稿是作者声明的参考材料，不能占用实际章节序列，也不会因为被分到某个架子就自动获得真值权。规划侧章篮与导入侧章节架同样不能混成一个对象。

**加固：**SI-016 在当时候选 C1 中看到“大纲条目和章节书稿一起进入章节序列”的写法，指出后续槽位映射会把计划材料误当成已经写出的章。这个审查加固了分架纪律，但没有冻结 C1 v1 字段、迁移脚本、大纲原稿落盘位置或旧数据处置。

## 错的做法

把大纲写成第 0 章或占用一个章节槽。用同一数组同时表示实际章序和规划顺序。把大纲原稿直接送入书稿抽取正线或当书稿证据。照搬回包里的 C1 补句当正式合同。把本卡升级成执行票，或自行发明迁移字段。
