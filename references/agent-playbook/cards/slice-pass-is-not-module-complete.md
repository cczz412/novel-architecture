# 一个切片通过，不等于整个模块完成

身份：设计审查风险

## 遇到什么

后续 Agent 在 TEMP 里看到 20/20 PASS、上千条回归通过，或 127×6 测试设计验收通过，准备把相关模块标成“已完成”“端到端可用”或“真实内容质量已证明”。

## 对的做法

这是对 2026-08-20 一组候选实现和验收材料的历史审查风险，**不是现行产品已经炸了**。引用时只写清当时真正通过的代码切片、测试范围和基线；把“测试设计被接受”与“测试已经执行”分开，把零 API 合成场景与真实模型、真实作者、真实小说和端到端旅程分开。

材料本身已经明确：若干切片补上，不等于整个 M3／M4／M11 完成；20 个场景通过也不等于 M1～M11 全部完成。当前状态仍要回现行代码、现行合同和当前结果票核对，不能拿历史 PASS 外推。

## 错的做法

用回归数量代替模块边界。把测试设计验收写成 762 个测试已跑。把零 API 合成夹具写成真实模型质量或作者可用性证明。把已经修掉的旧预计失败继续写成当前缺陷。把本卡升级成执行票，或把历史局部 PASS 写成已拍完成状态。
