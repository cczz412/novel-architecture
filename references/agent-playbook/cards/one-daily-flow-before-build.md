# 先统一一条日常状态流，再把稿发给开发

身份：已拍加固

## 遇到什么

“打开项目→继续创作→收工”在几份设计稿里入口、退出、写入时点和异常恢复不一致。后续 Agent 准备各照一份实现，或按文件更新时间自行挑一份当现行流程。

## 对的做法

**已拍：**R14 已把“唯一日常主流程状态表”写成开发硬前置。先把每个状态的入口、退出、允许写入什么、失败后回哪里，以及哪些旧稿作废统一清楚，再分发施工。未关章项目应回到上次处理处；这属于同一条主流程，不要另造“断更回归”状态机。这里写下的是设计纪律，不代表代码已经完成。

**加固：**SI-007 P01 对五份候选设计稿的走查发现，它们不是文案不同，而是主流程和数据移交条件互相打架。这个发现支持“先统一再开发”，但 P01 没做可用性测试；它提出的四步流程、分钟数和具体页面顺序不是新合同。

## 错的做法

让门厅、写作台、章工作台和收工页各维护一套状态。按“最新修改时间”决定哪份稿有权。为了兼容冲突稿再加一层状态映射。把 P01 的四动作方案或时间估算写成已拍。把本卡升级成执行票，或自行发明状态名和字段合同。
