# 未来调查报告进入知识库的标准

## 这套标准主要解决什么

它主要解决三个问题：报告有字但追不到来源、整份报告被一次性打分、以及新报告覆盖旧记录后丢失历史。以后新报告必须先成为可审计来源档案，再拆成原子结论；没有通过结论审查，不得直接写入主题背景页。

## 1. 收件包必须包含

- 原始 Prompt／调查问题，保留逐字版本；若只能重建，要标 `PROMPT_RECONSTRUCTED`，不能冒充原文。
- 原始 Markdown 回包，不改写、不补链接，带稳定报告编号、生成日期、提供者、字节数和 SHA-256。
- 可打开的网页、DOI、官方文档、代码仓库、数据集或视频地址。`turn…`、聊天内部引用、搜索结果编号不算来源。
- 调查范围：地区、语言、平台、账户档、时间窗口、纳入／排除、检索式、样本量和明显偏差。
- 完整来源清单与访问日期；时敏页面记录发布日期／更新时间、地区或登录条件。
- 反例、负结果、查不到的内容、证据冲突和研究者推断。
- 技术题附代码、数据、版本／commit、环境、步骤、期望结果和失败记录。

缺任一关键项不等于整份删除：先按准入状态隔离，并把补件动作写进队列。

## 2. 报告层准入

| 状态 | 进入条件 | 可做什么 | 不能做什么 |
|---|---|---|---|
| `ACCEPT_SOURCE` | 来源链完整，方法与边界清楚，关键来源可打开 | 拆结论，A/B 仍逐条审 | 不能整份自动进背景 |
| `PARTIAL_USE` | 一部分可追，一部分外推或缺链 | 只吸收可追部分，保留负结果 | 不能用好引用替坏结论背书 |
| `LEAD_ONLY` | 题目、结构或案例有价值，证据不足 | 进入选题、访谈题、反例池 | 不能成为已知事实 |
| `QUARANTINE_UNTRACEABLE` | 只有内部引用、二手转述或源页不可定位 | 保留原件与补链队列 | 不得建立 A/B 结论 |
| `SUPERSEDED_KEEP_SOURCE` | 新时间点或更强证据接替 | 保留历史快照和替代关系 | 不删除、不改写旧原件 |
| `PROJECT_HISTORY_ONLY` | 只审某个内部版本／设计稿 | 追溯项目历史 | 不进入通用外部背景 |
| `NEGATIVE_EVIDENCE` | 失败、反证、无结果有决策价值 | 进入负结果账和停止规则 | 不把失败原因脑补成确定结论 |
| `UNRESOLVED` | 对象、时间或冲突拆不清 | 保持未知并派发补查 | 不强行选边 |

一个报告可以同时有主要状态与次要状态，例如 `PARTIAL_USE + NEGATIVE_EVIDENCE`。

## 3. 原子结论卡最低字段

每张卡必须有：

- `claim_id`：稳定、不复用。
- 一句可单独判断的结论；避免“某报告整体表明”。
- 主题，以及对象、地区、时间、平台、账户档、任务范围。
- `evidence_grade`：A／B／C／D／U；附等级理由和降级原因。
- 支持报告编号、source ID、反例、冲突和不能外推之处。
- 时间敏感度、刷新触发器和旧知识关系：新增、补强、收窄、反驳、替代或重复。
- 技术可复现信息：代码／数据、版本、步骤、期望、实际结果和失败原因。
- 背景资格：`PRIOR`、`EXPERIENCE_OR_HYPOTHESIS_ONLY`、`GAP_ONLY` 或 `BLOCKED_UNTRACEABLE`。

A/B 级结论如果找不到报告编号或 source registry 里的可打开来源，自动降为 U 并隔离。

## 4. A／B／C／D／U 的人话尺子

- **A**：当前一手规则／官方技术文档；或同行评审研究、公开代码和数据能直接支持该结论。A 仍受对象和时间限制。
- **B**：至少两类相互独立来源同向，其中一类接近一手；或强一手证据迁移到本产品时存在领域限制。
- **C**：多个实践者、平台课程或社区样本同向，但没有代表性抽样或因果实验。只能证明经验常见或说法存在。
- **D**：单个案例、营销材料、未经独立核验的转述，或研究者从来源推导出的产品假设。
- **U**：当前查不到、来源不可追、数字口径不明，或证据冲突到无法给方向。

等级不是数引用。十篇转载同一个原始新闻，仍是一条来源族；单条当前法律原文可以是 A，但只说明该法条在明确范围内存在。

## 5. 来源登记与快照

每个 source ID 保存 URL、标题／上下文、来源类型、机构／作者、发布日期、访问日期、适用范围、报告引用关系和打开状态。打开状态至少区分：

- `LIVE_VERIFIED`：本轮人工或自动打开，记录状态和日期。
- `LOGIN_OR_REGION_RESTRICTED`：存在但需要登录／地区。
- `DEAD_OR_MOVED`：失效，保留旧 URL 与替代关系。
- `URL_PRESENT_NOT_LIVE_CHECKED`：只确认报告导出了地址，本轮未实时打开。
- `CHECK_FAILED_RETRY_REQUIRED`：已尝试打开但网络超时或传输失败；不能算实时通过，进入补查队列。

网页更新、撤回、404 或迁移时，不覆盖旧记录；新增 `updates`、`supersedes`、`retracts` 或 `mirror_of` 关系。

## 6. 新旧合并

- 同向独立证据：合并同一 claim，来源并列。
- 新报告只重复旧来源：标重复，不虚增置信度。
- 新时间点更新政策、价格、版本：新卡成为当前入口，旧卡保留历史日期。
- 新报告收窄旧外推：保留旧原话和纠正理由，当前卡按更窄范围写。
- 冲突能由平台、题材、时间、账户档或方法拆开：拆成多张卡。
- 拆不开：保持 U，进入冲突图和补查队列。
- 本地实验反证外部建议：外部来源保留，当前产品判断记录为“被本地实验否掉”，不得删负结果。

## 7. 背景页编译门

背景页中的每个外部判断必须带 claim ID。正向“外部先验”只使用 A/B；C/D 只能放经验、反例或候选假设；U 只放“不能证明”和研究缺口。背景页不复制长引文和来源清单，追证据走 `claim ID → source ID／report ID`。

产品决定与外部建议分开。R13 或 CZ 已拍边界优先；外部报告最多说明支持、风险或替代方案，不能宣称功能已实现、授权已取得或产品方向已改变。

## 8. 更新、退场与删除

报告退场前必须写清：被哪张卡吸收、保留什么、什么已过期、何时重查。日常入口可以接替，原文件、Prompt、SHA、source registry 和冲突历史不能删除。

只有以下情况可从“当前背景”退出：被更强当前证据替代、适用对象消失、来源撤回且无独立支持、或本地实验稳定反证。退出不等于抹除，状态改为历史、反证或不可验证。

## 9. 每次构建的机器验收

- 报告清单数量与 manifest 一致，文件存在且 SHA 对上。
- JSONL 每行可解析，claim ID 唯一。
- 所有 A/B claim 至少有一个已登记 source ID；所有 report ID／source ID 引用存在。
- 背景页出现的 claim ID 全部存在；无裸外部判断。
- 所有人读 Markdown 以 `来源：ChatGPT Pro` 收尾。
- 冲突、隔离、负结果和刷新队列不为空。
- ZIP 可完整解压，MANIFEST 记录每个交付文件的 SHA、字节数和记录数。

## 10. 在本仓库加在哪里

- 新报告原件、逐字 Prompt 或重建 Prompt、SHA 和收件说明进入 `references/survey-inbox/packages/<batch_id>/`，并登记一张 `SI-*` 卡。
- 编译后的版本进入 `references/external-knowledge-base/EXTERNAL_KNOWLEDGE_BASE_<date>_RNN/`。
- 日常入口只认 `references/external-knowledge-base/CURRENT.json` 指向的版本；旧版本原位保留。
- 产品共同背景板与外部报告知识库分开。R13 或后续产品版可以引用知识库当前入口，但不能把外部建议复制成已拍产品决定。
- 单次施工先在 `work/<work_id>` 或 `TEMP` 拼装；通过验收后再写入新版本目录。正式版本目录发布后不静默改写。

## 11. 怎样发布下一版

1. 收原始报告并完成 SI 登记，不改原字节。
2. 把新报告加入准入账，补 Prompt 状态、日期、字节数和 SHA。
3. 新增或更新结论卡、来源登记、冲突关系和研究缺口；没有真实链接的内容继续隔离。
4. 只重编受到影响的主题页，但交付时生成一个完整新版本，不能让日常入口同时拼读多个版本。
5. 对新进入背景的来源做打开核验；A／B 正向结论至少有一个本轮可打开来源，否则降级或退出正向背景。
6. 跑引用、编号、SHA、JSONL、CSV 和背景门验收，写明与上一版的变化。
7. 经 CZ 明确允许后更新 `CURRENT.json`；旧版本和旧来源不删除。

完整的本地操作次序、是否需要升版以及 ChatGPT Pro 与本地验收的分工，见 `08_LOCAL_RELEASE_AND_UPDATE_PROTOCOL.md`。
