# 产品形态、交互、Agent 工具与失败恢复

## 可以作为外部先验

提示词不能代替权限阻断。高影响动作必须在模型之外有能力边界、授权校验、审计和失败状态；工具元数据里的“只读、破坏性、幂等”提示也不能当安全证明。[CLM-DR-UX-03-K01] [CLM-DR-UX-03-K02]

游标和分页不是天然一致快照。MCP 当前分页语义允许 cursor 过期或跨页变化；失效后应重扫并记录覆盖范围，不能把“翻完几页”自动写成“全量已检查”。[CLM-DR-UX-03-K03]

断线重试与恢复要区分请求是否真正提交、动作是否幂等、外部副作用是否已经发生。LangGraph 等工作流恢复可能重跑节点前半段；补偿动作不是通用 Undo。[CLM-DR-UX-03-K04] [CLM-DR-UX-03-K07] [CLM-DR-UX-03-K08]

长任务可以有持久 task ID 和恢复机制，但 task ID 不是授权凭证。每次恢复、查询或取消仍要重新校验用户、范围和权限。[CLM-DR-UX-03-K05] [CLM-DR-UX-03-K06]

聊天、按钮和管理员工具共用同一 Action 内核，比三套逻辑各自改数据更安全；checker 应给出检查范围、未读范围、命中、弃权和版本，而不是只回一个裸 `OK`。[CLM-DR-UX-03-K12] [CLM-DR-UX-03-K13]

## 只能当经验或候选假设

IDE checkpoint、文件回退和工作流历史能覆盖一部分副作用。关于“它不能覆盖所有终端命令、外部 API、子 Agent 和管理员操作”的方向合理，但 `CLM-DR-UX-03-K10` 的两个官方地址本轮均超时，因此该卡已降为 U，当前只作待复核边界。[CLM-DR-UX-03-K10] [CLM-DR-UX-03-K11]

“所有动作都确认”与“全部自动执行”都可能失败。普通中文作者能否理解聊天、画布、卡片、账本和确认语义，哪种渐进授权最少打扰，目前没有目标人群测试。[CLM-DR-UX-01-U01] [CLM-DR-UX-02-U01]

## 分歧与反例

现有工具并没有统一 coverage receipt 标准，覆盖回执是从多种原语推导出的产品候选，不应包装成行业规范。[CLM-DR-UX-03-K14]

Claude、VS Code 等把权限放在 Agent 之外，说明模型层与执行层必须分开；但不同产品的权限粒度、默认策略和可撤销范围不同，不能照搬界面。[CLM-DR-UX-03-K09]

## 不能证明什么

公开文档不能证明普通作者看得懂这些机制，也不能证明某套 SDK 在本产品工作流中无故障。MCP、LangGraph、Temporal、IDE Agent 的版本变化快，所有能力结论都要带版本与最小复现。[CLM-DR-UX-01-U01] [CLM-DR-UX-03-K09] [CLM-DR-UX-03-K14]

## 对产品设计的候选启示

把探索、查询、提案、真改做成能力边界；高影响真改需要明确授权，不用聊天中的模糊“好”代替签字。进度要区分运行中、已提交、已落盘和已回执；失败恢复应回答“发生了什么、什么没发生、下一步是否安全”。[CLM-DR-UX-03-K01] [CLM-DR-UX-03-K02] [CLM-DR-UX-03-K05] [CLM-DR-UX-03-K10] [CLM-DR-UX-02-U01]
