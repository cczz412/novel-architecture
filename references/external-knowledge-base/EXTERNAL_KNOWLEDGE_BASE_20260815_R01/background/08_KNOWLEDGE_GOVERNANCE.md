# 外部知识库治理、更新与负结果

## 可以作为外部先验

知识库的中心应是一条尽量单一、可判断的 claim，而不是整篇报告。claim、证据、处理过程和责任主体应可分离；同一来源可以支持多条 claim，同一 claim 也可以同时保留支持与反驳。[CLM-DR-GOV-01-K01] [CLM-DR-GOV-01-K02] [CLM-DR-GOV-01-K04]

只有“结论＋出处”仍不够。平台、价格、版本和政策会变化，至少要保存适用范围、观察时间、当前 assessment、来源依赖和刷新条件。[CLM-DR-GOV-01-K03] [CLM-DR-GOV-01-K05]

A/B/C/D/U 应属于有范围、有时间点的结论判断，不属于整篇报告；等级理由、降级原因和什么证据会改变判断必须一起保存。[CLM-DR-GOV-01-K06] [CLM-DR-GOV-01-K07]

负结果、未复现、无法解释、链接失效、撤回和修订不能被抹掉。它们改变的是当前可验证性或结论状态，不是把历史记录删除。[CLM-DR-GOV-01-K08] [CLM-DR-GOV-01-K09]

处理流水、模型调用和人工审查应放在 Run／Provenance 记录中，知识卡只保留关联，避免把“怎么生成这张卡”塞进结论本身。[CLM-DR-GOV-01-K10]

## 只能当经验或候选假设

新旧报告共存不能只靠“新覆盖旧”。新报告可能只是更好的摘要，旧报告仍保存独特原始来源；新报告也可能收窄旧外推、更新时点或提供反例。具体合并规则要通过本包的冲突图和后续人工验收运行。[CLM-DR-GOV-01-K04] [CLM-DR-GOV-01-K09]

活知识库的自动监测方案仍待补链。法律、平台政策、价格、代码版本、论文与社区经验需要不同触发器，当前没有一套机制被证明能低成本覆盖全部对象。[CLM-DR-GOV-02-U01]

## 分歧与反例

引用很多不等于证据强，多份文章可能都复制同一原始出处；反过来，单一官方规则可以很强，但只适用于明确平台和时间。报告级评分会掩盖同一报告内 A 级规则、C 级案例和 U 级推断并存。[CLM-DR-GOV-01-K02] [CLM-DR-GOV-01-K06] [CLM-DR-GOV-01-K07]

本轮 17 份新报告只有内部 `turn…` 引用。它们可以保留问题结构、负检索和待核假设，却不能因为文字完整就进入背景正向结论。[CLM-DR-CN-06-DERIVED-U01]

## 不能证明什么

知识库不能宣称“已经覆盖全部外部知识”，也不能把未实时打开的 URL 写成当前有效。自动摘要不能直接改结论等级；网页新不等于证据强；旧报告被吸收不等于原件可删。[CLM-DR-GOV-02-U01] [CLM-DR-GOV-01-K07] [CLM-DR-GOV-01-K09]

## 对产品设计的候选启示

日常窗口只读主题背景页，追究时走“背景页 claim ID → 原子结论账 → source ID／report ID → 原文”。新报告先入档、再拆 claim、再做冲突与等级审查，通过后才进背景。任何更新都保留旧时间点、SHA 和替代关系。[CLM-DR-GOV-01-K01] [CLM-DR-GOV-01-K03] [CLM-DR-GOV-01-K04] [CLM-DR-GOV-01-K10]
