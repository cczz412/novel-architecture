# 审计员派发模板

所有模板共同要求：`model: cursor-grok-4.6-xhigh`（禁止 `-fast`）；只读；每条回报带 `文件:行` 或原文短摘；给行数上限。

## 1. 取证员（explore）

```text
你只负责取证，不做判断、不改文件。
范围：<目录或文件清单>
问题：<要查明的 2～5 个具体事实>
输出：每个事实一行，格式「事实 — 文件:行 — 原文短摘(≤30字)」；查不到就写「未找到」；总共 ≤20 行。
```

## 2. 穷举员（explore / generalPurpose）

```text
你只负责穷举，不评价好坏。
列出所有：<X，例如「引用了 CURRENT.json 的文件」「背景板 R04 各页的对外链接」>
范围：<搜索范围>
输出：清单，每项带路径；结尾一行写「共 N 项，搜索方式：…」；≤30 行。
```

## 3. 核对员（generalPurpose）

```text
你只负责逐条核对下面这份清单，不扩展新话题。
清单：<主 agent 给出的待验证条目，每条是可判真伪的陈述>
对每条输出：「#序号 ✓成立 / ✗不成立 / ?查不到 — 证据 文件:行」；≤清单条数×2 行。
```

## 4. 对照组跑腿（generalPurpose）

```text
你只负责收集数据，不下结论哪组好。
对照组：<各组名称与结果文件路径>
按下表收集：<指标清单>
输出：一张 markdown 表（行=组，列=指标），每个数字标来源 文件:行；缺数据写 N/A；表外 ≤5 行备注。
```



## 5. 红队（generalPurpose）

```text
你只负责挑刺。下面是一份草稿结论，请找反例和漏项。
草稿：<主 agent 的判断草稿，尽量短>
可查证材料：<路径>
输出：≤5 条攻击，每条「攻击一句 + 依据 文件:行（或“无依据，纯质疑”）」。不要写改进方案。
```



## 常见坑

- 把整份长文档粘进 prompt → 应改成给路径让它自己读
- 问「你觉得哪个好」→ 判断题收回主脑
- 子 agent 回报无引用 → 退回或当传闻，不进【结论】
- 一波派 6+ 个 → 主脑读不过来，综合质量反而掉
