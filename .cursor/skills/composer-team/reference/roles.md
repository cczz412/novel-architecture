# 子 Agent 角色定义

本文件定义 composer-team 的全部角色。主 SKILL.md 引用本文件，不在主文件中重复定义。

**架构约束**：子 agent 之间**不能互相通信**，所有信息只能通过主 agent 中转（星形拓扑）。因此：
- W1 子 agent 的输出只有主 agent 能看到
- W2 子 agent 要看 W1 的结果，必须由主 agent 在 prompt 里**粘贴原文摘录**（不是主 agent 自己的总结，是子 agent 的原话）
- 主 agent 在穿插阶段的核心工作是**搬运**而非综合

---

## W1 角色：C1～C6（角色库；满编只派前 4 个）

**窄化原则（硬规则）**：每个角色只做**一件事**。prompt 必须包含 `你只负责 X，不要发散到其它维度`。弱模型做一件事比做三件事靠谱得多。

W1 满编按 **C1→C2→C3→C4** 取前 4 个。C5/C6 仍保留在角色库，只作 W2 唯一补位的候选。某一波若用户指定 N 个，按同一顺序取前 N 个，且 **N 不得超过 4**。

| 编号 | 角色 | 窄化职责（只做这一件事） |
| --- | --- | --- |
| C1 | **正面论证者** | 只做一件事：论证用户方案/产物的合理性，列出支撑证据和成立条件。不要发散到风险或替代方案 |
| C2 | **反面攻击者**（red team） | 只做一件事：列最大 3 条致命风险/失败模式/隐藏假设。不提替代方案，不帮忙修 |
| C3 | **落地验证者** | 只做一件事：验证方案的可执行性——依赖是否就位、步骤是否可操作、前置条件是否满足。不评价方案好坏 |
| C4 | **盲区扫描者** | 只做一件事：找方案**没提到**的事——未覆盖的维度、被跳过的前提、默认但未声明的假设。不评价已有内容 |
| C5 | **上下文核验者** | 只做一件事：读被审产物关联的文件/上下文，核对方案引用的事实是否正确、引用是否存在。不做价值判断 |
| C6 | **约束检查者** | 只做一件事：对照用户已有的规则/约束/需求文档，逐条检查方案是否违反。只报违反项，不建议怎么改 |

> **注意**：当 `reference/task-presets.md` 中有匹配的任务预设时，C1～C6 的职责被预设覆盖。无匹配预设时回退到上表。

---

## W2 专用角色：S（综合者）+ D（对质者）

这两种角色**仅在 W2（及 W3 若启用）使用**，不在 W1 出现。

### S = 综合者（Synthesizer）

| 编号 | 角色 | 必须产出 |
| --- | --- | --- |
| S | **综合者** | 读主 agent 搬运来的 **W1 全部子 agent 原文摘录**，写出初步综合结论（按当前预设的输出格式）。主 agent 在 S 的基础上做最终裁决，不再从零综合 |

**S 的核心价值**：把主 agent 从"读 6 份输出 → 深度综合"降级为"读 1 份综合 → 裁决"，认知负荷降低 80%。

**S 的 Prompt 要求**：
- 主 agent 必须在 S 的 prompt 里粘贴 **W1 各子 agent 输出的原文关键段落**（不是主 agent 的二次加工），确保 S 看到的是一手信息
- S 必须按当前预设的「综合输出格式」组织结论
- S 必须在每个结论点后标注 `来源：C?`（标明依据哪个子 agent 的发现）
- S **不新增事实命题**，只综合已有发现

### D = 对质者（Devil's Advocate）

| 编号 | 角色 | 必须产出 |
| --- | --- | --- |
| D1 | **对质者-前半** | 专挑 W1 中 **C1+C2** 结论的矛盾、遗漏、逻辑跳跃。不提新方案，只挑洞 |
| D2 | **对质者-后半** | 专挑 W1 中 **C3+C4** 结论的矛盾、遗漏、逻辑跳跃。不提新方案，只挑洞 |

**D 的 Prompt 要求**：
- 主 agent 在 D1 prompt 里粘贴 **C1+C2 的原文输出**
- 主 agent 在 D2 prompt 里粘贴 **C3+C4 的原文输出**
- D 的产出格式：`矛盾/遗漏描述 → 涉及哪个 C? 的哪句结论 → 建议复验方式`
- **禁止**：提出新方案或替代路径，只挑现有结论的漏洞

---

## W2 编组规则

**W2 标准编组（4 子，硬顶）**：

```
W2 = S(综合) + D1(对质前半) + D2(对质后半) + C补位 x1
```

- **S、D1、D2** 固定必派（3 子）
- **C 补位 x1**：从角色库选 **W1 覆盖最薄的 1 个维度**（由主穿插指定）；优先补 W1 没出场的 C5 或 C6
- C 补位的 prompt 标注 `wave=2, 补位=true, 禁止与 W1 同题重写，只补 W1 该维度的缺漏`
- 审查任务若要派 H：H 占用这一补位槽，W2 = S+D1+D2+H，**不得**变成 5 或 7 子

---

## W3 专用角色：R（高风险深潜者）

R 仅在 W3 使用，专门对 W1+W2 发现的**高风险点做深度分析**。

| 编号 | 角色 | 必须产出 |
| --- | --- | --- |
| R1 | **深潜者-风险1** | 针对 S 结论中的 **Top 1 风险/问题** 做深度分析：根因链、影响范围、是否有化解方案、该风险是否改变最终结论 |
| R2 | **深潜者-风险2** | 同上，针对 **Top 2 风险/问题** |
| R3 | **深潜者-风险3**（可选） | 同上，针对 **Top 3 风险/问题**。仅当 S 结论中有 3 个以上值得深挖的点时派出 |

**R 的 Prompt 要求**：
- 只做一件事：**深挖一个具体风险/问题**，不要发散到其它维度
- prompt 必须包含：S 的该风险结论原文 + D1/D2 对该风险的质疑（若有）+ 相关 C 子 agent 的原文摘录
- 必须产出：`根因链 → 影响范围 → 化解方案（若有）→ 判定：该风险是否改变审批/评估结论`
- **禁止**：重复 S 已有的表面结论，必须比 S 的分析**更深一层**
- R 可以使用 Read/grep 工具自行读取相关文件做验证

### W3 编组规则

**W3 标准编组（2～3 子）**：

```
W3 = R1(深潜风险1) + R2(深潜风险2) [+ R3(深潜风险3，可选)]
```

- **R1、R2** 固定必派（2 子）
- **R3** 仅当 S 结论中有 ≥3 个值得深挖的高风险点时派出
- 主 agent 在 W2→W3 穿插时选定 Top 2-3 风险点，写进 R 的 prompt

## 专岗 H（幻觉核验）

H 不占 C1～C6 / S / D / R 编号，为可选附加角色。

| 编号 | 角色 | 必须产出 |
| --- | --- | --- |
| H | **幻觉核验** | 对照上轮子 agent 输出，列出疑似无证据断言、路径/行号不可核验、与 A 段矛盾处；只标风险与复验建议，**不新增事实命题** |

### H 的派发策略

| 任务类型 | H 默认策略 | 说明 |
| --- | --- | --- |
| **审查已有代码/产物**（有文件路径可验证） | **默认派**（占用 W2 唯一补位槽，总数仍为 4） | 核验路径、行号、引用准确性有价值 |
| **方案审批 / 效果评估**（观点碰撞型） | **默认不派** | 审批的是逻辑和方向，不是文件行号 |
| 用户明确要求「核验幻觉」「加 H」 | **派** | 用户覆盖 |
| 用户明确要求「不要 H / 免幻觉核验」 | **不派** | 用户覆盖 |

### H 的 Prompt 约束

- prompt 须嵌入主 agent 搬运的 **上轮子 agent 关键主张原文**
- 提示对照 **A 段已核验事实**（若有）与仓库原文
- **禁止**基于核验输出编造仓库内不存在的内容；只能标「疑似幻觉 / 待查证」并指向复验方式（Read / grep）

---

## 用户调整数量

- 用户说「来 N 个子 agent」→ W1 按 C1→C4 顺序取前 N 个（N>4 则封顶 4，声明写 `封顶：4`）；W2 的 S+D 固定不减；W3 的 R 固定不减
- 用户说「全开」→ W1 满编 4 子，W2 满编 4 子，W3 满编 3 子
- 用户说「两轮就够」「不要 W3」→ 跳过 W3，只走 W1+W2
- **不接受用户自定义角色名取代 S/D/R**，避免阵型崩坏（不另开自定义角色 skill，阵型只认本表 S/D/R）
