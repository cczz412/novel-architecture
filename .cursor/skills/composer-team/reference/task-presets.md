# 任务类型预设（Task Presets）

主 agent 在 Step 2（波次判定）时根据用户任务描述**自动匹配**下列预设之一。
匹配后声明行标注 `预设=<preset-id>`，C1～C6 职责被覆盖为对应表格。
用户也可在触发时直接说「审批模式」「效果评估模式」强制指定。

**无匹配时**回退到 `reference/roles.md` 中的通用 C1～C6。

**所有预设通用规则**：
- W1 = 4 子（取 C1～C4），每个只做一件事；C5/C6 仅作 W2 补位候选
- W2 = S + D1 + D2 + C补位×1 = 4 子（编组见 `reference/roles.md`）
- S 的综合按本文件的「综合输出格式」写

---

## 预设一：方案审批（plan-review）

**触发关键词**：审批、评审、可行性、该不该做、要不要上、方案评估、这个方案行不行

**H 策略**：默认不派（观点碰撞型，核验文件行号意义不大）

### W1 角色（满编取 C1～C4；C5/C6 为补位候选）

| 编号 | 角色 | 窄化职责 |
| --- | --- | --- |
| C1 | **假设审核** | 只做一件事：逐条列出方案的隐含假设，判定成立/不成立/需验证。不评价方案整体 |
| C2 | **风险猎手** | 只做一件事：最大 3 条失败路径 + 最坏情况推演，每条附「严重度 + 发生概率 + 缓解方式」。不提替代方案 |
| C3 | **资源/时间线审核** | 只做一件事：投入产出比、时间线是否合理、资源瓶颈。不评价技术方向 |
| C4 | **替代方案** | 只做一件事：有没有更简单/更安全/成本更低的替代路径达到同一目标。与原方案的对比表 |
| C5 | **依赖/前提验证** | 只做一件事：方案依赖的前提条件是否满足、外部依赖是否就位、接口是否存在。不做风险评估 |
| C6 | **与现有体系冲突检查** | 只做一件事：方案是否与已有规则/架构/流程/约束冲突。只报冲突项，不建议怎么改 |

### W2 编组

```
W2 = S(综合) + D1(对质 C1+C2) + D2(对质 C3+C4) + C补位 x1
```
C 补位由主穿插指定最薄的 1 个维度；优先补未出场的 C5 或 C6。

### 综合输出格式（S 按此格式写初步综合，主 agent 在此基础上裁决）

```
## 审批结论
通过 / 有条件通过 / 驳回 — 一句话核心理由（来源：C?+C?）

## 可行性判定
✅ 成立的假设（逐条，来源：C1）
❌ 不成立的假设（逐条 + 证据，来源：C1）
⚠️ 需验证的假设（逐条 + 验证方式，来源：C1）

## 核心风险 (Top 3)
1. <风险描述> — 严重度: 高/中/低 — 缓解方式: xxx（来源：C2）
2. ...
3. ...

## 依赖与前提状态
✅ 已就位 / ❌ 缺失 / ⚠️ 不确定（来源：C5）

## 体系冲突项
逐条列出（来源：C6）

## 替代路径
| 维度 | 原方案 | 替代方案 |
| --- | --- | --- |
| 成本 | ... | ... |
| 风险 | ... | ... |
| 时间 | ... | ... |
（来源：C4）

## 审批建议
- 通过：第一步做什么
- 有条件通过：需先解决什么
- 驳回：修改方向建议

## 对质发现（D1+D2 的矛盾/遗漏）
逐条列出，标注涉及哪个 C? 的哪句结论

## 深潜分析（W3 R1+R2+R3）
- R1 深潜风险点 1：根因链 → 影响范围 → 化解方案 → 是否改变审批结论
- R2 同上
- R3 同上（若派出）

## 子 agent 汇总
- C1～C6：各一句 采纳/部分采纳/不采纳 + 理由
- D1+D2：挑出的矛盾是否改变结论
- S：初步综合 vs 主 agent 最终裁决的差异（若有）
- R1～R3：深潜后是否改变结论 + 一句理由
```

## 预设二：效果评估（outcome-eval）

**触发关键词**：效果、做得怎么样、偏差、执行结果、复盘、做歪了吗、达标没

**H 策略**：默认不派（评估的是逻辑和方向）

### W1 角色（满编取 C1～C4；C5/C6 为补位候选）

| 编号 | 角色 | 窄化职责 |
| --- | --- | --- |
| C1 | **目标对照** | 只做一件事：原始目标 vs 实际产出的逐项对比表，标注「达标/部分达标/未达标」。不分析原因 |
| C2 | **偏差量化** | 只做一件事：哪里偏了、偏了多少、偏差是否在可接受范围内、偏差趋势。不归因 |
| C3 | **根因归因** | 只做一件事：偏差的因果链——是方案本身问题、执行问题、还是外部变量。不提建议 |
| C4 | **改进措施** | 只做一件事：下一步修正措施、优先级排序、预期改善幅度。不重复分析偏差 |
| C5 | **被遗漏的目标** | 只做一件事：原始需求中有没有被忽略的目标没评估、有没有隐性期望未被覆盖。不评判已评估项 |
| C6 | **二阶效应** | 只做一件事：执行结果对其他模块/流程/依赖方的连锁影响。不评判执行本身好坏 |

### W2 编组

```
W2 = S(综合) + D1(对质 C1+C2) + D2(对质 C3+C4) + C补位 x1
```

### 综合输出格式

```
## 总评
达标 / 部分达标 / 未达标 — 一句话（来源：C1+C2）

## 目标对照表
| 原始目标 | 实际结果 | 偏差 | 评级 |
| --- | --- | --- | --- |
| ... | ... | ... | ✅/⚠️/❌ |
（来源：C1）

## 关键偏差 (Top 3)
1. <偏差点> — 偏差幅度 — 影响范围（来源：C2）
2. ...

## 根因分析
| 偏差 | 根因类型 | 具体原因 |
| --- | --- | --- |
| ... | 方案/执行/外部 | ... |
（来源：C3）

## 被遗漏的评估维度
逐条列出（来源：C5）

## 二阶连锁影响
逐条列出（来源：C6）

## 改进路线
按优先级排序：
1. <措施> — 预期效果 — 实施难度（来源：C4）
2. ...

## 对质发现（D1+D2）
逐条列出矛盾/遗漏

## 深潜分析（W3 R1+R2+R3）
- R1 深潜偏差/风险点 1：根因链 → 影响 → 化解 → 是否改变总评
- R2 同上
- R3 同上（若派出）

## 子 agent 汇总
- C1～C6 + D1+D2 + S + R1～R3：各一句
```

## 预设三：通用（general）— 默认兜底

**无特定关键词匹配时**使用。角色定义见 `reference/roles.md` 中的基础 C1～C6。

**H 策略**：按 `reference/roles.md` 中的 H 派发策略表判定。

### W2 编组

```
W2 = S(综合) + D1(对质 C1+C2) + D2(对质 C3+C4) + C补位 x1
```

### 综合输出格式

```
## 结论
<2~3 句直接回答用户问题，给出明确建议>（来源：C?+C?）

## 推荐方案
<从 C1 正面论证者的支撑证据 + C4 盲区扫描结果中选最稳妥路径>

## 主要风险
<引用 C2 反面攻击者的关键 1~3 条，标注是否可缓解>

## 盲区与约束
<C4 盲区扫描 + C6 约束检查的合并发现>

## 下一步
<引用 C3 落地验证者，挑出今天能做的 1~3 步>

## 对质发现（D1+D2）
逐条列出矛盾/遗漏

## 深潜分析（W3 R1+R2+R3）
- R1 深潜风险/问题点 1：根因链 → 影响 → 化解 → 是否改变结论
- R2 同上
- R3 同上（若派出）

## 子 agent 汇总
- C1～C6 + D1+D2 + S + R1～R3：各 采纳/部分采纳/不采纳 — 一句话理由
- H 幻觉核验（若派出）：采纳几条 — 是否下调哪些断言
```
