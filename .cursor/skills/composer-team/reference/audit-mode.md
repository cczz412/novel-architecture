# 审查类任务硬约束（Audit Mode）

本文件在任务涉及「审查 / 复核 / 校验 / 审批**已有产物**」时由主 SKILL.md 引用加载。
关键词：审、核、复审、check、audit、是否做歪、是否合规、对照规则、审批（针对已有方案/文档）。

**需要加载本文件的场景**：审查已有代码/文档、复核已有方案是否合规、审批一份已写好的方案（有具体产物可核验）。
**不加载本文件的场景**：从零设计新方案、实现功能、探索技术选型、排错——这些没有「已有产物」可审查。

---

## A 段：事实核验先行（主 agent 自己做，不派子 agent）

1. 先打开被审产物 + 关联规则原文，做可机械重复的二值化核对（文件数 / 集合 / 必含 / 必不含 / 计数 / 字段）。
2. **结论必须带证据**：`文件路径 + 行号` 或 `grep 命中`，无证据不算结论。

## 与团队模式的交互

1. **已触发团队口令**：完成 A 段后进入波次判定，派发子阵。子 agent **不得**否定或篡改 A 段已核验事实。
2. **未触发团队口令**：完成 A 段后，主 agent 单线程给出三档结论。

## 三档输出（审查类任务必须分档，不混判）

| 档位 | 判据 | 处理 |
| --- | --- | --- |
| **字面违规** | 有原文判据 | BLOCK / REVISE |
| **解释张力** | 协议字面与执行精神有缝 | 标「需用户/批判者/CZ 拍板」，AI 不擅自判 |
| **风格瑕疵** | 不影响合规，仅可读性 / 可维护性 | 列建议，不进 review_result |

## 派发子阵时的额外约束

子 agent prompt 必须包含：
- **规则原文 / 关键判据原句**（贴原文，不复述）
- **指定证据形式**：每条意见必须带「文件名 + 行号」或 grep 模式，**无证据自动降级为 see-also，不进结论**
- **明确产出边界**：C2 只挑硬违规，不假设；C4 只列「裁决项 / 未知项」，不发散到无关治理

## 审查产物沉淀

- **默认**（未获用户明示授权写 `temp/` 以外路径时）：把结论写到 **`temp/_audit_findings_<日期>.md`** 或用户指定的仅位于 `temp/` 下的路径。
- 用户**明确允许**写非 `temp/` 路径时：仍可写到被审目录旁的 `_audit_findings_<日期>.md` 等。
- 新发现的判据 / 边界更新同理：默认只动 `temp/` 内草稿，除非用户授权改治理/需求正文。
