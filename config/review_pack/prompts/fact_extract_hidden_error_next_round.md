# 小说事实抽取｜隐蔽漏错、低成本修补与两档产品路线审查

你现在是独立技术审查员。ZIP 里有三种小说题材、五个模型渠道、两种思考预算、程序疑点筛选、盲关键事实清单和早期分波修补的完整实物。请只按包内证据判断，不要把模型自评、事件数量、HTTP 200 或格式通过当成准确率。

## 你要回答的核心问题

我们要找的是一条能落地的小说事实抽取路线：

- 便宜档可以有少量已知边界，但不能持续制造高危错；
- 高级档愿意多花一点钱，重点降低主体、来源、否定、条件、时间、因果和情态的隐蔽错误；
- 用户不能长时间看着卡死页面，产品应能按事件、人物、地点等逐条可视写入，但“看起来在动”不能冒充结果正确；
- 同一比较至少跨三种题材，不能只用一个章节偶然拍板。

## 请先核对这些事实

1. 区分“产品闸分”和“严格合同分”。千问 T0 的产品闸是 8/12，严格合同是 6/12；这两种分数用途不同，不得混成一张排行榜。
2. MiniMax M3 的第一次失败是请求模型名／凭据路由配置错误，不是模型质量失败；有效质量结果只认修正后的 r02。
3. 豆包 2.0 Lite 有两本格式不合格，2/12 不能和三个格式全通过的模型作纯语义等价比较。
4. 所有模型都没有达到“无误杀、无漏放、三书格式全过”的全绿门槛，因此本轮没有继续跑批处理对逐条调用。这是预注册止损，不是缺材料。
5. `score_lockbox.json` 和金标没有外发。包内离线分数与人工审查结果可以用来复核结论，但不要反推或补写被隔离的答案锁箱。
6. E01 最终四项小批合同只覆盖 B03 一书，结果 2/4。它与后面的三书合同形状不同，只能说明整套组合失败，不能把失败单独归因给“关闭思考”。

若这些事实和实物不一致，请点名文件、字段和具体冲突。

## 请完成的审查

### A. 判断现在最像哪条产品路线

请分别判断：

- 低成本基础档该用哪个模型、是否关闭思考、每章允许几次调用；
- 高准确高级档该用哪个模型或异源复核组合、强模型只该接什么疑点；
- MiniMax M3 10/12 但有 1 个误杀，和 V4 Pro High 9/12 但 0 误杀，分别更适合什么岗位；
- Qwen3.7 Flash 是否还适合做骨架、程序候选生成或短输出岗位，而不是终判；
- SenseNova V4 Flash High 和豆包 Lite 是否应砍掉当前岗位。

不要只说“组合使用多个模型”。请给明确的主模型、触发条件、调用次数上限和退出条件。

### B. 解决最难的“看似完美但其实漏了”

程序只看正文和旧事件账，前 4／8／12 个疑点只覆盖 1／3／5 个已知错；盲关键事实清单又会制造新的主体、来源、否定和条件错误。

请设计一条更靠谱的漏错发现链：

- 哪些疑点能靠程序直接找；
- 哪些只能让模型做短判别；
- 如何产生 4～6 个高价值疑点，而不是在 12 个候选里错过时间、情态等低表面信号；
- 是否需要“不看旧事件账”的异源盲扫；
- 如何避免盲扫自己创造新事实；
- BERT/ModernBERT 现在该不该上；若不上，积累什么判题数据后再上。

请给出可执行的特征、分数或规则，不要只写“增加语义特征”。

### C. 判断下一轮到底测什么

请给一个冻结实验表，满足：

- 每个关键比较至少三种题材；
- 一次只改一个主变量；
- 不修改测试迎合实现；
- 明确哪些格零调用、哪些格真实调用；
- 给每格的模型、渠道、思考设置、温度、输入、输出合同、调用次数、停止线；
- 预算用“最大物理调用数 + 最大等待时间 + 最大输入/输出 token”三项表达；
- 没过前置门时，后续格自动取消；
- 不要为了把额度用满而安排无价值调用。

重点判断下面几条是否值得试，以及顺序：

1. MiniMax M3 的 4 项小批判别对 4 次逐条判别；
2. V4 Pro High 只接 MiniMax/Qwen 不确定项或高危项；
3. Qwen T0 一次骨架后，由程序按锚点切窗，再让同一个 API 做短判别；
4. 异源模型盲列“关键事实义务”，但只输出缺口编号，不重写完整事件账；
5. 先扩大程序疑点召回，再谈 BERT 判别器。

### D. 给出产品可视化写入方案

说明怎么让页面逐条动起来，但后台仍可校验、重试和断点续跑。至少覆盖：

- 任务、阶段、事件或实体的稳定编号；
- 草稿、已校验、需复核、已入账四种可见状态；
- SSE 或 WebSocket 的事件格式；
- 幂等写入、断线续跑、完成合同；
- 模型流式 token 与“已确认业务对象”为什么要分开显示；
- 如何避免没做完却显示整章完成。
