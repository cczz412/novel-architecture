# T-03 多形态输入抽取管线｜方向总审 Prompt

请完整阅读随附 ZIP，再以这个项目的**首席外部架构与评测顾问**身份作答。

这次不是请你验证 Codex 已经设计好的路线，也不是请你从我们列出的几个选项里挑一个。你可以推翻当前问题定义、合同、模块划分、模型岗位和实验顺序。只要材料支持，你可以明确要求我们停下、回退、拆管线或调转方向。

## 我们真正想做什么

我们在做一个面向长篇小说创作的故事真源系统。输入可能是：

- 小说正文；
- 总纲、卷纲、章纲、情节点纲；
- 小说和大纲同时存在；
- 书名、简介、金手指说明和黄金三章；
- 前 100 章或更长的大纲。

系统不只在项目导入时抽内容。作者连载时每写完一章，也要把新内容回收到候选故事账。作者若先确认大纲、再扩写成正文，系统还要能拿正文和原计划对照，指出写到了什么、漏了什么、改了什么、新增了什么、与既有真源冲突了什么，并给出可复核的证据。

我们当前有输入／输出合同草案、一个可调的中间管线、若干模型和程序小实验，也有很多局部淘汰结论。但我们担心：也许我们只是在错误的管线设计上越调越细；也许现在抽出的只是大纲和产品真正需要内容的一小部分；也许“事实抽取、计划理解、正文对纲、连续性检查、质量审查”根本不该塞进同一条管线。

## 你拥有的判断权

- 不要默认当前 T-03 管线是正确起点。
- 不要因为我们已经做了很多实验，就为现有投入找理由。
- 不要把局部 12/12、零引文失败、某模型更稳之类的结果自动外推成产品质量。
- 可以指出材料不足，要求我们先建立新的 Gold、下游任务或错误账，再调模型。
- 可以提出一套更优架构，也可以提出两三种路线并说明在什么证据下选择。
- 如果你发现比下面提示更重要的问题，请打乱回答顺序，把它放在最前面。

## 请你完成的核心工作

请独立判断并给出可执行方向：

1. **方向判决**：当前问题定义与管线是大体正确、局部歪了，还是应该重构？请用大白话说明最关键的三到五个理由。
2. **产品工作重建**：从产品实际用途反推系统需要完成哪些不同工作。请判断“抽取”这个词下混进了多少种任务，哪些应共享底座，哪些应拆成专用管线。
3. **内容充分性**：按小说、大纲、混合材料、项目种子、长大纲，以及“正文对章纲挑刺”场景，说明真正需要得到哪些内容。指出当前抽多了什么、漏了什么、混错了什么。
4. **更优管线**：请给出你主张的整体结构。明确程序、模型、作者确认各自负责什么；哪些阶段共用，哪些按输入类型或下游任务分流；当前模块哪些保留、下放、旁路、推迟或删除。
5. **合同与数据结构**：审查当前输入／输出合同是否够用。请提出最低必要合同，特别处理来源、证据、状态、计划、否定、模态、人物知识、时间、关系、歧义、版本和大纲满足条件。不要为了“统一”制造一个什么都装、谁都难用的巨型记录。
6. **正文对大纲审查**：单独设计这项复用能力。它怎样分解章纲，怎样和正文语义对齐，怎样区分缺失、替代、提前、推迟、合理新增和冲突，怎样避免把作者合理发挥误报成错误。
7. **评测重建**：告诉我们怎样设立标准，才能知道抽取是否真的够大纲和产品使用。请区分机械交付、语义准确、覆盖、证据、状态、粒度、下游效用、作者审查成本和端到端收益。指出应该怎样做 DEV、盲测、未见题材、长序列和回归，防止被少量精选案例骗过。
8. **证据审计**：把包内结论分成“相对可靠”“只能算候选”“可能误导”。若某个结论无法判断，请写清缺哪一份最小证据。
9. **下一阶段指挥单**：如果由你接手，请告诉我们明天停掉什么、保留什么、先测哪一小批、每批看什么读数、出现什么就停损或转向。我们希望继续用“小批测试 → 外部复盘 → 再测试”的节奏，不做大网格，也不把轻量试验做成重治理工程。

这九项是帮助你理解我们关心什么，不是限制你的目录。你认为更重要的判断可以覆盖它们。

## 回答要求

- 开头先给一页大白话结论，让非技术产品负责人能直接拍下一步。
- 每个关键判断标成：**材料直接支持／由材料推断／你的建议／目前未知**。
- 引用 ZIP 内具体文件路径和能支撑判断的段落或数字，摘要与原报告冲突时以原报告为准。
- 不要只给原则。至少给一版你愿意负责的目标架构、下一批最小实验和停止条件。
- 不要把“继续调 Prompt”当默认答案，也不要把“换更强模型”当万能解。
- 不需要替我们写代码；方向、合同、评测和实验优先级更重要。
- 结尾请明确回答：**如果这是你的项目，你明天会做哪三件事，又会坚决不做哪三件事？**

请直说。我们会把你的回包当成下一阶段的方向输入，而不是礼貌性参考。
