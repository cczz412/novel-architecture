# 模型调用合同

这个目录只管“请求怎么发、成功响应长什么样、正文怎么解析”。它不执行调用，也不代表已经获准联网。

当前唯一合同包是：

`qianwen_qwen3_7_flash_json_object_no_thinking/bundle.json`

你可以直接理解成：`bundle.json` 是总目录，它单向钉住六份现役依据。

| 绑定对象 | 解决什么问题 |
|---|---|
| 调用档 | 钉住模型、温度、思考开关、流式开关和 JSON Object 模式 |
| 供应商配置 | 钉住平台、地址、接口和预期响应模型 |
| 供应商访问规则 | 保留“没有明确运行命令就不得调用”的边界 |
| 请求外壳 Schema | 只允许本合同明确列出的请求体字段 |
| 响应外壳 Schema | 只接受非流式成功响应，并要求 `choices` 恰好一项 |
| 归一化规则 | 只严格解析正文一次；失败就拒绝，不补救 |

每条文件引用都同时写仓库相对路径和文件 SHA-256。被引用文件只要改一个字节，旧 bundle 就会失配；源文件不反向引用 bundle，所以不会形成循环依赖。

请求 Schema 验的是发给 Chat Completions 的 JSON 请求体，不包含 HTTP 请求头或鉴权值。允许的顶层字段只有 `model`、`messages`、`temperature`、`stream`、`enable_thinking`、`response_format`。因为顶层用了 `additionalProperties=false`，所以 `n`、各类最大输出 token、思考预算、推理档位、请求头、鉴权对象和工具调用字段都会直接被拒绝。

响应 Schema 验的是 HTTP 200 后已经解码出的单个 JSON 对象。它不接受 SSE 分片，也不接受多候选；成功外壳必须带用量账，模型正文固定从 `choices[0].message.content` 读取。

归一化规则很窄：先核对响应模型、候选数、结束原因和助手角色，再要求原始响应保持不变并留 SHA-256。正文只交给严格 JSON 解码器一次，重复键和非有限数直接拒绝，结果还必须是对象。不会剥 Markdown 围栏，不会截取中间 JSON，不会删前后解释，不会修坏 JSON，不会重试，也不会换模型。

解析成功不等于任务合格。调用方还必须提供一份已绑定的任务输出 Schema 做本地验收；归一化规则只要求“必须有这道闸”，不会反向引用某个具体任务 Schema。

这个合同包故意不引用提示词、上下文配方或任务输出 Schema。那三类材料有各自的登记和哈希，不能借 API 合同把它们绑成一条暗线。

离线核对入口：

```bash
python3 tools/model_call_profiles.py validate
```

这条命令只读本地文件，不读取密钥，不发请求，也不改默认链。
